# scripts — 确定性脚本

> 第三组「脚本与扩展」的另一半：**技能是软的，脚本是硬的。**

## 什么该写成脚本

判据只有一条：**这件事能不能用规则判对错？**

| 能规则判 | 写脚本 |
|---|---|
| 命名对不对、格式合不合规、有没有漏字段、链接通不通 | ✅ 脚本，秒级、可重复、不看心情 |
| 写得好不好、这个方案合不合适 | ❌ 留给人，或留给技能 |

**能用规则判的，绝不留给人判。** 每次你手工重复第二遍的检查，都该问一句：能不能是一条命令？

## 怎么长出来

不要预先设计。**踩到一次坑，就把那次的检查固化成一个脚本**——
它的名字应该是那次坑的名字。

## 约定

- **只放这里，不放全局 `bin/`**——全局对整台电脑可见，容易过载，安全风险也高
- 一个脚本干一件事，名字说清干什么
- 能跑就能重复跑：**同样输入同样结果，跑几遍都一样**
- 报告问题，不擅自修改——要改也另出一个 `fix-*` 脚本，让人决定跑不跑

## check-taskbook-segments.py — 大包任务书必须切段

踩过的坑：**2026-11-05 夜 #1316** 跑满 7200 s 被 kill，16 个文件写完但 RESULT / 负控 / final.patch 全缺，只能靠 WIP 补丁续跑；同一晚 #1334 #1336 #1370 #1328 #1339 同类超时。
「每 30 分钟 WIP 提交」只防丢进度，**不防「一整段跑不完」**——所以要在大包派单前就按文件切段。

判据来自最近 10 个超时单与 10 个一次跑完的单：**手写改动文件 ≥ 8 或 手写 diff ≥ 1500 行**（召回 9/10，误报 3/10，且误报的三个分别是 95 min 逼近上限、478k 行生成金样、接续轮）。
派单前拿不到真实改动量，所以任务书写 `<!-- pdrs-scope: files=N lines=M est_min=K -->` 声明（键只认 `files` / `lines` / `est_min` / `modules`，键名大小写与 `-`/`_` 不敏感；**写错键名等于把阈值吞掉，按「读不了」rc 2**——`files=2 estmins=300` 不会静默当成小包；**同一行把同一个键写两遍也 rc 2**（`files=16 est_min=180 files=2` 后写覆盖先写））；没写才退回人日估算（约 / 大约 / 估计 / 预计 / 估算 / 工作量 / 共计 / 合计 / 总计 … 可带冒号逗号 … N 人日）与点名 `*.rs` 路径数。

```bash
python3 -I scripts/check-taskbook-segments.py <任务书>     # 0 通过（含小包）/ 1 大包缺分段表 / 2 读不了、为空、读取中被改写或 scope 写坏 / 3 用法错误
python3 -I scripts/check-taskbook-segments.py --print-skeleton
python3 -I scripts/check-taskbook-segments.py --recent 24 [--root .]   # 兜底递归扫 _build/wt-*/_tmp/**/task.md，没扫到也是 0
python3 -I scripts/test-check-taskbook-segments.py        # 173 条正控 / 负控（负控钉死具体报错文案）
```

命中大包的任务书必须含 `## 分段交付`（段名 / 涉及文件 / 交付物 / 预估时长 ≤90 min / 段间依赖，≥2 段；列序不限，按表头定位：先精确 `段名` 再退回 `段`，`段间依赖` 先认领依赖列，同一列不会被两列认领；GFM 分隔行只认紧贴表头的那一行，**后面的全 `-` 行是没填的段行**，照常查空值与估时）与 `## 续跑`（带目录的实例进度文件路径 + 第 N 段失败从哪继续）。
占位符按「像占位符」判：尖括号/花括号里含中文、是纯点号（`<...>` / `{…}`）或是 `N` / `日期` / `待填` 这类词，全角与中文括号（`＜待填＞` / `【待填】`）同样算，外加裸 `...` / `…` / `？？？` / `待填` / `待补` / `待定` / TBD / TODO（`【重要】` / `【策略】` / `【等待】` 这类正文不误伤：中文方括号里只认明确的占位词）；`Vec<u8>`、`Result<(), E>`、`<https://…>` 这类仓库常态不误伤。尖括号 / 花括号内容**不设长度上限**：限长会让超长的 `{请填写…}` 既不算占位符、又不被遮蔽 → 静默通过（假 PASS），同时让超长的 `<https://…/a...>` 里的 `…` 反过来被裸占位规则命中（假 FAIL）。估时区间 / 上限（`80–120 min`、`80/90 min`、`60 至 80 分钟`、`60 到 80 分钟`、`上限 90 min`）取最大值，并列或连写（`60 min + 40 min`、`1h40m`、`1h100min` = 160）求和；区间与加法同现时先按加法切段、每段取 max（`40–50 min + 20 min` = 70，不是 110；裸「增加 / 加班」不算加法；**括注里的裸 `+` 是列表不是加法**：`80 min（S1 + S2 各 40 min）` = 80，括注里的「另加 / 再加 / 再补」仍算加法）；括注里的数字按说明处理——`含` / `各` / `其中` / `包括` / `内含` / `外加` 之后的数字不计入（回看范围到括注开头 / 句读为止、不限距离：`90 min（含双段联调 10 min）` = 90），括注里单位不是时长的数字跳过（`80 min（2 个文件）` = 80），不把整格判成「读不出」。正文兜底的占位符扫描只看表格行：`## 分段交付` 里正文写「先做 A 再做 B……」不是占位符。单位只认 min/分钟/m/h/小时（`以内` / `之内` / `以下` / `左右` 这类限定词不算单位的一部分）；表头写 `(h)` / `(hrs)` / `工时` / `人时` 时裸数字按小时算，写 `(人日)` / `人天` / `工作日` 判「读不出」，**表头认不出单位且格子也没写单位时同样「读不出」**（`预估人天` 里的裸 `2` 曾被当 2 min 通过）。
代码围栏（``` / ~~~）里的**分段表与占位符**不算数：贴上一单的示例分段表不能顶替本包的，围栏里残留的 `<段名>` 也不会把合规任务书打回。**scope 声明只认围栏外正文**（围栏 ``` / ~~~、引用块 `> …`、空行之后的 4 空格缩进块、行内代码 `` `…` `` 里的示例 scope 都不算声明——这四种「贴示例」形态都曾把 9 个 `.rs` 的包短路成小包）；人日与 `.rs` 回退看原文（围栏里的证据也算，宁可判大）——围栏里贴一段示例 `<!-- pdrs-scope: files=2 -->` 不再把 9 个 `.rs` 的包短路成小包，围栏 / 行内代码里写坏的示例 scope 也不再假 ERROR。行内代码只对 scope 解析屏蔽：续跑路径、人日、`.rs` 仍看原文（`` `_tmp/…/progress.md` `` 是常态写法）。缩进块按 CommonMark 只认「前置空行」的块，列表续行（`1. 进度文件：` 下一行缩进 4 格的路径）是正文，不许抹。**围栏开了没收口** rc 2（半截围栏后面是正文还是示例判不准）；关闭围栏**必须同串围栏独占一行**，` ``` x ` 这种带尾随文本的不算闭合（否则围栏里的示例 scope 会变成真声明）。
`--recent` 递归扫 `_build/wt-*/_tmp/**/task.md`（修复 / 续跑 / 重生成轮次在 `fix-rN/`、`resume*/`、`regen*/` 下一层，只认一层会整类漏掉），但跳过 `_tmp` 之后路径段里叫 `remote-run` / `remote-run.*` / `.prev-*` 的派发副本与旧轮次备份，同一份任务书不重复判（只看 `_tmp` 之后：`--root` 前缀里叫 `remote-run` 不能把所有任务书跳光）。扫描是自己写的 `os.scandir` / `os.walk`，**不用 pathlib 的 glob**——后者对 `EACCES` 静默跳过（实测 `chmod 000` 的 `_tmp` 下任务书整类消失、rc 0）。
`--recent` 与显式任务书可以同用：单个扫描到的文件在扫描期间被回收仍静默跳过（那不是任务书的问题），但**遍历本身**抛 OSError 一律 rc 2；`--root` 只与 `--recent` 同用（单独给 `--root` 是用法错误，免得以为按 root 解析）；**显式点名的文件不见了一律 rc 2**；读后复核 size/mtime，只挡 stat→read→stat 这个毫秒窗口内的写入——**写方停顿超过 10 s 再续写的半截任务书挡不住**（要堵得靠写方原子落盘），别当成已解决。空扫描 `--json` 打 `[]`、`--quiet` 只留 stderr 提示；**递归扫描中断（目录级 OSError，如权限拒绝）→ rc 2**，不与「扫过但没扫到」（rc 0）同观感（上句的「单个文件被回收」不在此列：目录在遍历中被删按回收跳过，只有权限 / IO 错误才算中断）；mtime 比 `now - 10 s` 新的一律跳过（含未来时间戳，宁可漏一轮也不读半截）；非空 `--json` 只输出 JSON、`--explain` 只打每个文件的判定依据，两者都不打文本 SUMMARY。非普通文件（FIFO / 设备文件）一律 rc 2，不试着打开（会永久阻塞）；读到一半文件被删也 rc 2。
`~/ws/pdrs-ops` 的 `dispatch-issue` / `dispatch-fix` / `fix-assemble` 已强制：不合规不启动 worker；`dispatch-resume` 只告警；`round-start` 9d 段每轮兜底。模板见 `~/ws/pdrs-ops/templates/taskbook-segments.md`。
