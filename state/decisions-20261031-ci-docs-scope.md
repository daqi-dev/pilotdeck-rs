# 决策卡 · #1199 纯文档改动跳过重 CI job（2026-10-31）

- **卡在哪**：只改 `state/` 的 state PR（如 #1197）也要跑两遍完整 CI（PR 侧 24 min + merge_group 侧 16 min），还占合并队列位；重 job（rust / a51-coverage / metadata-observer）对纯文档改动没有增量价值，但 #904/#918 的守卫测试按「必需 job 无条件执行、skipped 一律拒绝」钉死了 ci.yml。
- **人批**（2026-10-31）：「同意改 ci.yml，最好立即改」。这是合并闸门语义变更，由人批而非 AI 代批。
- **放宽边界（唯一放行路径）**：新增无条件 job `scope` 先跑 `scripts/ci_scope.py` 的自测（`scripts/test-ci-scope.py` 正负例），再按事件算改动文件：pull_request 用 `base.sha..head.sha`、merge_group 用 `base_sha..head_sha`、push 到 main 恒为 full。分类器**确定**改动文件集合非空、且每个文件都正好等于 `state/board.md`（rename / delete 两侧都算，用 `--no-renames`）时输出 `docs_only=true`；任一路径不是它、diff 为空、git 出错、事件缺 SHA、分类器异常，一律输出 false（fail-closed，宁可全量）。
- **为什么不按目录放行（fix-r1 收窄，非作者评审 P0）**：初版白名单是 `state/`、`.42cog/`、`docs/` 三个前缀，但这三个目录里有重 job 尺子的输入：`gateway-coverage/check_ledger.py` / `check_coverage_manifest.py` 读 `docs/research/005、008`、`docs/plan/005`（按 sha 钉死）；`ui-server-parity/check_frozen.py` 与 `check-approval-provenance.py` 读 `state/decisions-*` 的批准记录；`product-coverage` 读 `docs/experiments/*`。纯文档 PR 跳过 a51-coverage 后这些尺子不跑，`check` 假 PASS，push 到 main 才变红。`state/board.md` 是目录里唯一没有任何尺子读取的文件（`scripts/test-pdrs-loop.sh` 用临时目录自造测试 board；`scripts/pdrs-loop.sh`、`scripts/next-task.sh` 读它但只在本地 worker 循环跑，不在 CI 任何 job 运行）。这条前提由机检看守：`ci_scope.board_literal_violations` 扫描 `scripts/` 与 `src/**/tests` 下的 `.py`/`.mjs`/`.sh`，引用 `state/board.md` 字面量而不在允许清单登记（或登记过期）即违例，`scripts/test-ci-scope.py` 在 scope job（无条件运行）里执行——以后有人让尺子读 board，白名单自动报警。
- **闸门新语义**：`check` 的 `needs` 加入 `scope`；scope 非 success 一律拒绝（含取消 / 跳过）；三个重 job 各自的拒绝条件放宽为「result != success 且**不是**（result == skipped 且 docs_only == true）」——即只有这一种 skipped 被接受，取消和其他跳过照旧拒绝（#904 的放宽）。三个重 job `needs: [scope]` + 精确 `if: needs.scope.outputs.docs_only != 'true'`，不加其他条件（#918「步骤 / job 无条件」在这三个 job 上放宽为「只经 scope 门控」）；守卫测试同步改为精确字符串断言 + 四类变异负控（去 docs_only 条件、白名单退回目录前缀 / 加宽、scope 失败仍通过、重 job 加 continue-on-error）。`gateway-schema-baseline` 不变照常跑。
- **能否撤回**：能。删 `scope` job、还原 `check` 的三个旧条件与三个重 job 的 needs/if、守卫测试回退即可，无数据迁移。
- **动不动尺子 / 意向**：动。#904「check 只认 success、skipped 一律拒绝」与 #918「必需 job 无条件执行」被有意放宽，但只放开上面一条精确路径；「job 不许 continue-on-error」不放宽。
- **待观察**：① 探针 PR（只改 `state/`）实测 rust / a51-coverage / metadata-observer 被跳过且 `check` 在 PR 与 merge_group 两侧都通过；② GitHub 对 merge_group 上 skipped 必需检查（本仓必需检查只有 check / gateway-schema-baseline，均无条件跑，理论上不受影响）与 job outputs 在 skipped 前发布的语义，以探针 PR 实测为准。
