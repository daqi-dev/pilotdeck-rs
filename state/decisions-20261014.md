## 1 · 尺子：`cancel_during_tool` 原版不稳定（#35）

**卡在哪**：这个场景在 TS 和 Rust 两侧都会偶发出现 ACK=36（常态是 34），频率各约 5–7%（TS 1/20、Rust 1/15）。冻结口径要求 10 遍全部正常才 PASS，所以**每次 k=5 回归约有 50% 概率被它挡住**。
**不决定的代价**：每个改动的回归都可能随机挂掉（S1 #34 就是这样）；阶段 C 的分数会在 50 和 51 之间随机跳。

| 选项 | 后果 |
|---|---|
| A 登记为「原版不稳定」，移出 S（分母 53 → 52） | 立刻解开 S1；但「工具执行中取消」这条路径失去对拍守护，只剩单元测试 |
| B 只对这个场景改判法：先用 TS 跑约 20 遍摸清它会出现哪些结果，Rust 的结果只要落在这个集合里就算 PASS | 守护还在；但改了尺子的语义，要两家评审加你批准，约 1.5 小时 |
| C 整体加大 k（例如 k=10） | 不稳定还在，而且更容易撞上；不推荐 |
| D 不动 | 每次回归都有一半概率卡住 |

**AI 建议：B；B 做完之前，先按 A 临时登记（标「临时」），让 S1 可以合并。**

## 2 · deadline 竞态（#19，阶段 C 最后 2 个场景）

**卡在哪**：轮次超时（deadline）时，Rust 和 TS 的收尾不一样：
- Rust 的终态序号少 1，推断是缺一条 aborted 的 `turn_completed`；
- 部分轮次里，TS 宿主还会多写一条 `gateway_submit_failed` 状态。真实 TS 流程 0/10，Rust 3/5，唯一变量是 sidecar。

codex 修了三轮没修好。第 3 轮推断的根因是：Rust 的 deadline waiter 返回 `AcceptedUnknown`，让模型路径（`turn.rs:765-782`）和工具路径（`:1720-1722`）提前退出。这个推断**没验证过**。改动留档在 `_tmp/20261014-c4/r3-worktree.patch`。
**对你可见的影响**：只在轮次超时时出现，UI 可能多一条「提交失败」类状态（要实效层亲手确认）。

| 选项 | 后果 |
|---|---|
| A 按那条推断再修一轮（在 r3 补丁上补 aborted `turn_completed`），限时 1.5 小时 | 成功则阶段 C 满分；这块是并发收尾，之前一版就让 `cancel_during_tool` 蒙过冤，风险中等 |
| B 判为「原版缺陷」豁免（推翻代拍 #22、回到 #17） | 分数立刻 51/51；但一个已证实由 Rust 引起的差异被免检，破了「没登记的差异都算 Rust 的错」这条原则；不推荐 |
| C 先留 FAIL，推进 A/B 阶段，等阶段 A 用 Rust gateway 换掉 TS 宿主时再整体看 | 零成本；阶段 C 停在 51/53，挂「已知差异：超时收尾」 |

**AI 建议：A 试一次；不成就转 C。**
