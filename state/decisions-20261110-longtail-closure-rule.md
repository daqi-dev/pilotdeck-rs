## 新增判据（本卡确立）

**术语**：轮数 = 已开的**修复轮**（fix-rN 的 N），非评审轮数。**洞归属 = 发现该洞的评审所对应的下一修复轮**（如复核 fix-r25 的评审发现的新洞由 fix-r26 修，归 r26；评审轮无编号时以「发现于 head sha + 其后首个 fix-rN」锚定）。「逃逸族」= 同类句法/词汇/边界形状的洞族（与钉族规则的「同形状族」同概念，本卡内统一用「逃逸族」，不改别卡用词）。

**停修升级（任一命中即停手上报，不再开下一轮补丁；停修升级优先于允许收口）**：
1. **同族复现**：同一逃逸族的新 P0/P1（按洞归属）**累计第 2 次（隔轮不清零）** → 判「该修法不收敛」，续开必须换**结构性方案**（一处改动灭多洞）；结构性轮 = 以「一处改动灭多洞」为验收目标的修复轮，其存在期间本条与「修复轮上限 3」的计数继续累加但**不触发本条停修**。结构性方案动冻结/判读语义的须人批（#2245 ② 同口径），不动语义的可 AI 代批。
2. **评审分歧**：两家评审**都出了有效结论**（状态 PASS）且对「继续修 vs 停」相反 → 实测仲裁，取严。非 PASS 状态（PARTIAL/TIMEOUT/ERROR/TOOLS_VIOLATION）不算结论，复跑；只有一家评审在飞时**本条不适用**（不构成停修升级）。
3. **结构性方案失败**：结构性轮之后再出同族新洞，或结构性轮验收不达标（开单时登记的同族洞未清零）→ 停手转人拍板。
4. **轮数轴兜底**：第 3 轮修复后仍出现须当轮修的 P0（P0 跨轮存活）→ 停手转人拍板。

**允许收口（放行入队）的前置，缺一无效**：
- 末轮 P0=0、P1=0（尺子/冻结装置链按沿用节：P1 本就不放行）；
- 到点 P2 处置齐（沿用节 #2063 B 口径；P3 不要求）；
- **末轮评审覆盖齐**，按 CLAUDE.md 合并闸门 ④ 分轮次口径：修 P0/P1 的轮次 = 两家谱系、只修 P2 的轮次 = 一家非作者复核；并按 `state/decisions-20261107-review-block-whitelist.md`（PR #2108 已合）允许「一家真块 + 一家叙述」路径；纯文档轮可走 `<!-- pr-gate:waiver 理由 -->`（理由 ≥ 8 字）。真块要求（两件齐）：① `<角色>.md` 非空、含覆盖行、末行 VERDICT；② `summary.md` 的 `pr-gate:v1` 标记 head= 最终 head 且 roles 全 PASS（`check-pr-gate.py` 只认 PASS）。双谱系齐块由收货/协调者判定（pr-gate 逐块校验，不代查谱系）；
- 停修升级各条均未命中或已被结构性方案消化。

**收口证明义务**：
- 末轮评审块盖最终 head + 按改动类别给验证：行为/尺子改动 → 行为负控 + 真实数据复算；纯文档/流程 → 免行为负控但写明改动类别与为何不可复算。
- **修法类型声明**（fix-rN 任务书与 PR 必填，**只接受字面三值**）：`枚举式`（附边界论证：词表封闭性论证，或反向负例清单证明修饰窗/边界不吞真发现）｜`结构性`（须核到**测试真实遍历的词表**，#2245 r5 漏网根因；「结构派生/自动派生」等子类字样一律写 `结构性` 并附词表核验）｜`不适用`（**仅当 diff 只触及文档类路径**——`state/`、`docs/`、`.md`；触及 `src/`、`scripts/`、`specs/`、`tests/`、`.github/` 任一即不许写，尺子与装置主栖 `scripts/`）。缺失/空白/子类字样/未知值 → 退回。

## 每次拍板抽一条原则

第 4 轮及以后**每一轮**（fix-rN，N ≥ 4）修复开单前必须先答「上一轮的洞是边界暴露还是修法本身缺陷」——判不出即停修转结构性或转人。答案写进该轮任务书与 PR 的「上轮残差判读」（无上一轮时允许字面值「无上一轮」，空答不算答）。
