# 2026-11-08 · CLI 实现中的可撤回判断

## cron 命令终态后释放连接

- 卡在哪：固定 TS 基线的 `cron list` 已输出成功 JSON，仍因远端 WebSocket 存活而不退出；mbp2 隔离实测等 4 秒后仍无退出事件，需要 SIGTERM 清理。
- 谁受影响：四个旧 cron 子命令及使用它们的脚本；参数、请求、输出和业务副作用维持原约定。
- 能否撤回：可以，改动局限 CLI 连接生命周期，不改变持久数据格式。
- 是否动尺子或意向：不改既有冻结装置、分母或归一化；新增精确差异与产品测试。依现有人定“挂起属于默认修复的 bug”，不复制这项挂起。
- 选项与后果：保留连接会让一次性管理命令无终止；终态后释放连接使其按输出对应的退出码完成。
- 建议与决定：**AI 代批，待人复核**。选择终态后释放；仅在收到成功/失败响应或完成参数错误输出后结束，不给仍在执行的 RPC 新增超时，也不改变服务端任务生命周期。
- 原则与断言：一次性 CLI 已取得最终结果后不得因其自身的空闲管理连接继续挂起；子进程测试必须同时观察真实 WS 关闭及进程退出，不能只断言结果 JSON。
