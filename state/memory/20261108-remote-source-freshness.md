2026-11-08 CLI TUI r11：远端 runner 的 SHA 已是新内容，但真实 PTY 仍打印 r10 的 `history cleared` 文案；`cargo build --bins` 仅0.12秒，bin 时间晚于通过 `rsync -a` 保留的源码时间。新的库单测通过，实际运行入口却复用了旧产物。并行在本地编辑、等上一轮远端构建完再同步，就可能出现这种次序；仅凭时间差不能归因于两机时钟漂移。原始失败、源码快照和后续重编证据保留在主仓 `_tmp/20261108-cli-tui/`。

每轮先冻结写入、保存源码哈希，等待同步命令实际退出0；随后在专属远端镜像刷新本轮同步的 Rust 源码/manifest 时间戳，再按槽位编译。字节不能因此变化，保留刷新前后指纹和构建日志。真实进程测试绑定本轮二进制SHA，并用本轮新增行为确认当前入口；库测试、镜像Git HEAD和一次 `cargo build` 退出0都不能单独证明bin来自当前源码。不必清整个target或删除缓存；发现旧bin时该轮PTY结果按旧产物记录，重编后重跑受影响入口，不覆盖旧证据。
