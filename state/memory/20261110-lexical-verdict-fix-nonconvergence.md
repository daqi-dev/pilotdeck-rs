**为什么**：#2245 尺子（`check_ruler.independent_review`）r2–r6 连续五轮走「评审报一个词 → 加白名单/黑名单一个词」的路线，每轮双谱系评审都在**同一批词法位置**报出新的 P0/P1：r6 一轮同时开出六族新洞（双列 join any() 假 PASS、`<动词>中` 子串假 FAIL、单字「新」漏折叠、裸 需/会 假 FAIL、弯撇号假 PASS、缺 ASCII `.` 分隔假 FAIL）。词表枚举对无分词的中文天然不完备：每个词的左右邻接（需求方/会议/中间件）和写法变体（U+2019）都是独立开口，逐词补丁只会把洞搬到隔壁。r7 起改结构派生：逐格判定（每列 AND，不 join）、归一化前置（NFKC + 撇号折叠）、词边界守卫、子句分隔完备、级别否定走语法（否定词 + 排除动词首字的有界间隔 + 级别 token）、fail-closed 兜底，一次过 32 形状 + 真实数据复算 + 10 变异负控全灭。

**怎么用**：再遇到「评审结论的中文短句/单元格要机器判定」类装置，第一版就走结构规则，不要先写词表再等评审补词；评审再报词表型建议时，把建议指向的**形状**收进回归语料，方案本体仍走语法/边界/派生（单一词源真派生，如闭环/失败/进行中三族共享同一动词表）。每条残余词表项（显式 pending、右扩展例外）必须单独配负控。相关：[[ruler-real-data]]（判定改动必须真实数据复算）。
