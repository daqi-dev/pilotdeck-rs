## 卡 · JsValue 深度上限与 V8 实测阈值的差（A6.5-pr11 闸门 B1，2026-10-19 19:20，人批选 B）
- **卡在哪**：A6.5-pr11 gate1 B1——TS `structuredClone` 在约 1965 层嵌套抛 RangeError；Rust 新服务器名完全不查深度（3000 层也收下），已有名字走共享上限 2000，于是 1965–1998 层 Rust 收、TS 拒（gate2 实测：Rust 自 1999 层起拒）。
- **谁受影响**：只有构造上千层嵌套 MCP 配置的输入；正常配置不涉及。不影响 53 场景对拍（无此类场景）。
- **能否撤回**：能，常量与检查点都在 `js_value.rs`。
- **动不动尺子/意向**：不动。
- **选项**：A 追 V8 精确阈值（每个调用点各测一个数，且随调用栈深度变化，脆弱）；B 所有对 wire 侧 JsValue 的克隆/序列化入口都过 `js_value::MAX_ARRAY_DEPTH`（2000）检查，超限报 TS 同形 RangeError，1965–1998 这一段登记为已知差异。
- **建议/执行**：B。「完全不查」按 P1 修；「阈值差 35 层」降为 P3 已知差异（理由：V8 阈值依赖调用栈，无确定值；共享常量已在 js_value.rs:12-19 写明是保守值）。
- **原则**：对 wire 侧 JsValue 的每个克隆/序列化入口都必须过共享深度上限；与 V8 实测阈值的小差不追。
- **断言**：闸门评审任务书问「本 PR 有无绕过 js_value 深度上限的克隆/序列化入口」。

## 卡 · 写工具对硬链接的口径（A6.5-pr5 闸门，2026-10-19 19:35，人批选 B）
- **卡在哪**：A6.5-pr5 把「拒绝硬链接」用到了用户工作区文件（edit_notebook 生产路径必拒，报错还误用拒写目录文案）；TS 允许编辑硬链接文件。
- **谁受影响**：用户工作区里的合法硬链接，典型如 pnpm 的 node_modules（全是硬链接到全局 store）；Rust 下这些文件无法编辑，TS 可以。
- **能否撤回**：能。
- **动不动尺子/意向**：不动。
- **选项**：A 维持拒绝（比 TS 严，破坏正常操作）；B 用户工作区文件按 TS 允许硬链接，越界防护只靠真实路径（realpath）落在根内 + 符号链接解析；**我们自己私有的状态目录**（spill 目录、file history 备份目录等，进程自建）仍拒硬链接（A6.6-pr6 口径不变）。
- **建议/执行**：B。
- **原则**：越界防护以「解析后的真实路径是否在根内」为准；「拒绝硬链接」只用于进程自建的私有目录，不用于用户文件。
- **断言**：write_tools 夹具含「编辑工作区内硬链接文件成功、与 TS 同结果」用例。
