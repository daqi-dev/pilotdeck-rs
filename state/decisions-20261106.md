### 1.2 三条反例与归因（原文见 `raw/B/attribution.txt`）

| 脚本 | mutant | A | B |
|---|---|---|---|
| network-timing | `error-name-body` | INVALID | KILLED |
| runtime-spawn-panic | `tail-duplicate` | INVALID | KILLED |
| background-subtick-gate | `finish-on-cancel` | INVALID | KILLED |

三条 A 侧原文均为 `TimeoutExpired: Command '['bash', '.../scripts/cargo-slots.sh']' timed out after 900 / 900 / 300 seconds`；
B 侧同三条都给出真实判定（如 `KILLED: bound ... assertion failed`）。
**方向只有 A(INVALID)→B(KILLED)，`B − A = ∅`：因并行产生的 INVALID = 0 项；两臂 SURVIVED 均为 0；无假红、无假绿。**
其余 19 条 INVALID 两臂完全一致，属脚本自身已知失效（background-output 17 条 `#994 compilation failed`、background-panic `wake-disposed`、network-timing `error-name-invalid-url-upgrade`）。
剔除这 3 条「A 未取得判定」后，**266/266 逐 mutant 三态完全相等**。

### 1.3 超时的机制与根因（不是推断，是代码 + 同期记录）

- `scripts/cargo-slots.sh` 是**轮询检查**（`ps` 数 cargo 进程，空位 exit 0、满 exit 1），**不提供预留**。
- `negative_process.py:771 wait_for_slot()` 每 15/30 s 重跑该脚本，累计等待超过 300/900 s 即抛 `TimeoutExpired`——正是日志里的报错形态。
- **A 臂是串行运行、没有任何兄弟车道**，仍三次拿不到槽位 → 争用来自车道之外。
- 同期证据：`state/decisions-20261101-host-throughput.md` 记录 11-01 20:1x（落在 A 臂窗口内）cb8 名额仍写死 4、「十几条链排队拿名额」、cb8 上「大量 cargo-slots 180/300/600 s 超时 INVALID」。该卡据此提出按主机配置名额（cb8 10），经小工具 PR 合入后生效；11-05 人定口径又改为每台：本机 2 / cb8 4 / macmini-01 2 / mbp2 2（见 issue #1569）。
- 结论：**A 的 3 条 INVALID 是外部宿主争用（cap=4 + 十几条链）造成的「没取得判定」，与本实验的并行与否无关。**

### 1.4 混杂因子已量化（别把 27.1% 当纯并行收益）

- A/B 相隔 4 天，A 臂当时机器更忙：同脚本 B 普遍更快且输出逐字节相同（background-panic 96.8→44.4、persist-restart 62.4→10.6、runtime-spawn 115.6→73.4 min）。
- **同日归一化**：B 的 12 条脚本实测耗时之和 = **276.2 min**（同机同批的串行工作量）；B 墙钟 126.7 / 276.2 = **45.9%（2.18×）**，即「并行本身」的收益是 2.18 倍，**距 50% 线只剩 4.1 个百分点**。
- **车道数灵敏度**（`raw/k-sweep-B.txt`，按同批实测重排）：K=2 → 138.7 min（50%，刚过线无余量）；**K=3 → 92.8 min（占 276.2 的 33.6%、占 A 墙钟 19.9%）**；K=4 → 92.0 min（只少 0.8 min）；**K≥5 零收益**，被 `network-timing` 的 92.0 min 地板卡住。本单实际车道 126.7 / 94.5 / 55.0 min（按 A 旧耗时装箱，不均衡，比理想 92.8 多花 34 min）。
- **车道数写 K=3，不写「越多越好」**；且 cb8 名额 4，K=3 + 1 个 worker 正好占满（AB.md §6 尾）。

## 二、选项

### 选项 A — 维持原判：并行负控弃用，继续串行

- **判据怎么改**：不改。判据 2 按原文执行，结论「并行不可用」。
- **前置**：无。
- **代价**：串行一趟 467.4 min vs 并行 126.7 min（并行省 72.9%，等价地说串行是同工作量的 3.7 倍）；按同日归一化也有 2.18 倍差距。宿主链是当前合并关键路径，这一项直接落在每轮周转上。
- **判断错了会怎样（假 PASS 风险）**：**无**。这是保守方向，不会因并行引入任何未验证的等价性假设。风险只在效率侧：长期用 3.7 倍墙钟换一个「本可用装置消除的」环境噪声。

### 选项 B — 改判据 2（**尺子口径变更，需人批**）

- **判据怎么改**：把「INVALID 集合相等」改为
  **「SURVIVED 集合相等 + 非 INVALID 三态相等，且新增 INVALID 必须逐条归因到环境（槽位超时 / 编译失败）而非判据改变」**。
  改后本实验 266/266 相等 → 并行可用。
- **前置**：① 每条新增 INVALID 必须贴原始报错串（`TimeoutExpired` / `compilation failed` 原文），不许只写「环境原因」；② 新增 INVALID 条数不得超过串行臂基线，超出即整轮作废重跑；③ 被归因为环境的 mutant 必须**单条重跑一次**确认能取得判定。三条缺一即不得引用该轮结论。
- **判断错了会怎样（假 PASS 风险）**：**这是本卡风险最高的选项**。归因条款本身是文字判断，执行松一点就能把「并行导致的判定丢失」写成「环境噪声」，而判据看不见差别——负控覆盖率会静默下降，正是项目最怕的「尺子变松」。且它是**事后改预注册标准**，与「定阈值时不看 Rust 结果、不为变绿改标准」直接冲突。风险大小取决于执行纪律，不取决于判据文本；给不出机械闸门前，不建议走这条。

### 选项 C — 折中（**推荐**）：同宿主多车道启用，但每车道**对全宿主工作**独占 cargo 名额（名额分区，不是车道间互斥）

- **判据怎么改**：**不改**。判据 2 仍按原文「三态完全相等 + INVALID 集合相等」；C 是**用装置把 A 侧那类环境 INVALID 从源头消掉**，让判据 2 能被真正满足，而不是把判据放宽。
- **前置依赖（未满足则 C 不成立）**：
  1. **「独占」必须定义为「对全宿主工作的名额分区」**，不是仅车道之间互斥。依据见 §1.3：A 臂串行、无兄弟车道仍三次超时，争用来自车道之外；只做车道互斥、车道仍与外部链一起排队，A 那三次超时照样复现，**C 等于没做**。
  2. **(a) 真正的槽位租约装置**：现有 `scripts/cargo-slots.sh` 只是轮询检查（数进程，有位置 exit 0 / 满 exit 1），**没有预留能力**；`negative_process.py:771 wait_for_slot()` 每 15 / 30 s 重跑一次，累计等待超过 300 / 900 s 才抛 `TimeoutExpired`。C 要实现名额分区，须先做真租约（建议 `fcntl.flock`，见 memory「lock-use-flock」）。这属**装置变更**，**已单独开单 #1581**，须两家非作者评审，不在本卡内直接改。
  3. **(b) A 臂必须同条件重跑**：同宿主、同日、同 cap（cb8 4）、分区生效下 A/B 各跑一次，再判。当前 A/B 相隔 4 天、外部负载不同，266/266 相等只能证明「B 当天环境干净」，不能证明「并行在争用条件下仍等价」。
- **执行口径**：车道数 **K=3**（§1.4 实测：K=4 只省 0.8 min，K≥5 零收益）。先小样本（一单、A/B 各一次）→ 过判据 1、2 后才全量。
- **判断错了会怎样（假 PASS 风险）**：比 B 小，但不为零。残余风险是「两臂同等错」——3 条车道并发 cargo 可能把 20 核机器压满，时序类负控（network-timing 单条就 92 min，含时序断言）可能因负载出现**两臂都 KILLED 的假红**；三态相等，判据 2 察觉不到。缓解：KILLED 必须附真实绑定断言（本次 3 条 B 侧 KILLED 均为 `bound ... assertion failed`，非超时）；小样本阶段若出现无断言的 KILLED 即整轮作废。
- **额外代价（调度侧，非正确性）**：cb8 名额 4，K=3 时只剩 1 个给其他链；并行负控期间 cb8 基本被该单占用。属「名额计法、排队口径在 CLAUDE.md 上限内自己判断」范围（memory「self-decide-resource-gating」），记卡后简报。

## 三、建议

**人已拍板选项 C**（2026-11-05 16:20，见文首结论块）；下列理由与前置仍按 C 执行——把上面三条前置写死，否则 C 只是换了个名字的 A。

对被要求复核的「倾向 C」的结论：**方向成立，但不是无条件成立——要修正一处归因、补两条前置**。具体说，若「每车道独占槽位」被理解成「仅车道之间互斥」，则这个倾向**站不住**（理由见第三条）；只有理解成「对全宿主工作的名额分区」，才站得住。

- **同意**「不修改判定等价这条硬判据」：预注册判据 2 是这次唯一的一票否决项，事后放宽它等于自己给自己发通行证；C 保住了尺子，这是它优于 B 的根本理由。
- **同意**「墙钟收益在 C 下应该还在」：§1.4 同日归一化 2.18×、K=3 重排 92.8 min（占 A 19.9%）都说明收益来自「同批脚本分车道」，与是否隔离槽位无关；隔离只影响等待时间，不影响并行度。
- **修正归因**：「每车道独占槽位名额 → 消除 A 侧超时根因」这句，**只在「独占是对全宿主工作独占」时成立**。实测 A 臂是串行、没有兄弟车道仍三次超时（§1.3），根因是 cap=4 下十几条外部链的争用；如果 C 实现成「仅车道互斥、车道仍和外部链一起排队」，A 那三次超时照样会复现，C 就等于没做。所以卡里把「独占」明确定义为名额分区。
- **补前置**：**(a)** 现有 `cargo-slots.sh` 没有预留能力，C 需要先做槽位租约装置（已单独开单 **#1581**，两家非作者评审）；**(b)** 必须同条件重跑 A 臂，否则拿 4 天前、不同负载下的 A 当基线，C 的小样本也证明不了等价性。这两条不做则 C 不成立；做了，C 是三个选项里唯一既不动尺子又能拿到并行收益的路径。
