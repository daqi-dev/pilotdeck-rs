# 决策卡 · pr-gate 结果块的两个硬约束（白名单通道 + 第二家叙述）

- **状态**：**AI 代批，待人复核**（可撤回、在意向范围内、属判断题按「自决 · 待复核」）
- **卡型**：规则补登记（不新增标准语义，只把既有实测事实写成可执行约束）
- **发现于**：2026-11-07 09:0x，PR #2037 车道（代理 `a46b9c1f`）实测撞墙后提出
- **适用范围**：所有走 `python3 scripts/check-pr-gate.py` 的 PR 正文

## 卡在哪

`check-pr-gate.py` 对结果块的 `runner` 有硬编码白名单：

```
prefix = {"zai", "anthropic", "minimax", "deepseek"}
```

而 **Codex 通道（官方 ChatGPT 订阅 / GPT 谱系）产不出合规块**，实测报文：

```
结果块 runner=codex model=gpt-5.1-codex 不是已知组合
```

于是每一种「用 Codex 当第二家」的 PR 都卡在同一个岔路口：

- **歪路**（诱人且被明确禁止）：把 Codex 的结论原样贴成 `runner=zai` / `runner=anthropic` 的块
  —— 这是**伪装成别家谱系**，等于伪造评审出处。
- **正路**（#2037 车道实际走通）：一家白名单谱系出**真块**满足闸门，
  另一家（Codex）只出**叙述**，正文里写明「为什么它不是块」。

问题在于：**这条正路没有被写下来**。它现在只存在于我的判断和单个代理的临时决定里，
换个人/换个代理就会重演分歧，或者干脆走歪路。

## 谁受影响

- 每个需要两家非作者评审的 PR（几乎全部）。
- 评审执行器（`run-review-roles.py`）与闸门（`check-pr-gate.py`）的语义边界。
- 作者谱系是 GLM / DeepSeek / Claude 的单，第二家选择面被白名单削掉一块。

## 能否撤回

**能**，且成本很低：删掉这条登记即可回到「每个代理自行判断」的现状。不改任何代码、不改任何闸门。

## 动不动尺子 / 意向

- **不动尺子**：`check-pr-gate.py` 的白名单**一个字节都不改**，冻结装置与差异账本不碰。
- **不扩张意向**：本条只规定「怎么诚实地满足既有闸门」，不改变「两家非作者」这一语义。

## 具体约束（两条硬约束 + 一条补充）

**① 块只能来自白名单谱系。**
`pr-gate:v1` 结果块的 `runner` 只能是 `zai` / `anthropic` / `minimax` / `deepseek` 之一。
**任何情况下不得把非白名单通道（codex / grok / 其它）的结论套上白名单 runner 标签。** 这视为伪造评审出处。

**② 第二家可以只出叙述，但必须自证「为什么不能出块」。**
第二家**只要求是不同谱系的非作者**，不要求它产块。允许走「一家真块 + 一家叙述」，前提是：
  - （i）叙述方**用可核验的实测证据**说明自己为什么产不出块（例：贴出 `check-pr-gate.py` 的
    白名单拒绝原文，或该通道根本没有 `run-review-roles.py` 的 runner 实现）；
  - （ii）叙述方的 P0/P1/P2 结论**逐条原样抄进 PR 正文**，并给出**原始输出文件路径**，
    不许转述成结论句了事（memory `review-raw-output`）。

**③ 不为白名单缺口本身开单** —— 直到它**第二次**挡住产品开发为止（11-05 人令「只做产品代码」：
协作工具类不新开单）。第一次挡住时用 ①② 绕过去并登记在本卡。

## 选项与后果

| 选项 | 后果 |
|---|---|
| **① 采纳本卡（登记两条硬约束）** | 正路被固化，代理不再各自发明；歪路被明文禁止；闸门零改动；代价是多一段 PR 正文说明 |
| ② 改 `check-pr-gate.py` 白名单加上 codex | 要动闸门与评审执行器，属工具类改动，11-05 人令下**不该开单**；且 codex 通道没有四角色 runner，加了也只能收一块"伪四角色" |
| ③ 维持现状（不登记） | 每个代理重复做一次同样的岔路判断；已有一次差点走歪路，迟早有人真走 |

## 建议

**①**。理由：它把「已经跑通且诚实的那条路」写成了可执行约束，**零代码改动、零冻结影响**，
成本只有一段 PR 正文；而 ③ 的代价是评审出处可信度，那正是闸门存在的理由。

2. 不改 `scripts/check-pr-gate.py`。
3. 若第二次有产品单被白名单挡住 → 那时再开单，本卡转「已触发复查」。
