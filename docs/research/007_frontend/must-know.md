# 前端重构 · 三条不可妥协

> 2026-10-14。对象：浏览器端 `ui/src` → Rust。基线 `resources/PilotDeck` @ `cc7c4e6`。
> 这三条是本阶段所有取舍的硬边界，任何一条守不住就停下交人，不许用「先合了再说」绕过。

## 1. 用户可见行为一致

「一致」判的是**用户看得见的东西**，不是代码对应关系：URL 与路由、中英文文案、快捷键、中文输入法、明暗主题、滚动与焦点行为（`ui/e2e/streaming-*.spec.mjs` 整组测的就是这些）。

- 什么算 bug 沿用 `.42cog/intent.md` 不做什么表第一行的定义（崩溃/自相矛盾/安全问题 → 可修，进「已接受差异」清单；三条都不沾的是行为偏好，记 issue、不改）。
- 视觉像素不要求逐像素相同；**语义选择器可见的行为**（角色、文案、aria 属性）必须相同——这正是黑盒 e2e 用例的判法（例：`e2e/real-auth-native.spec.mjs:20-38` 全部用 `getByRole` / `getAttribute('aria-checked')` 断言）。

## 2. 对拍能机器判

新旧前端必须能被**同一组 Playwright 用例、同一个 mock 后端**分别跑一遍，结论是机器输出的 PASS/FAIL，不是「看起来差不多」。

- 判不了机器的用例（纯视觉偏好、无断言的截图）不算进验收，另列人工清单。
- 尺子不许为变绿而改：沿用 `CLAUDE.md` §五「尺子不许自己改」的规矩——要改用例先另开 issue、写明理由、过评审。
- 环境隔离沿用对拍老规矩：临时 `PILOT_HOME` / `TMPDIR`，不碰 `~/.pilotdeck` 与用户在跑的 PilotDeck 进程（计划 001 风险 R6）。

## 3. 能渐进替换，不必一次切换

任意合并点上产品必须**可用、可回退**；不存在「切换日」。

- 按页面切：每一页迁移完成的标志是「该页的黑盒 e2e 子集在新前端全绿」，然后才动下一页；任何时刻未迁移页面必须继续由旧前端原样提供服务。
- 重依赖（终端、编辑器、Office 预览）按「JS 岛」保留，不要求一步到位 Rust 化；岛与 Rust 壳之间的桥接协议要类型化、要进文档。
- 每一步都可独立回退：旧前端的构建与托管在全部页面迁完之前不删（`CLAUDE.md` 铁律 4：经人手的产物不可弃）。
