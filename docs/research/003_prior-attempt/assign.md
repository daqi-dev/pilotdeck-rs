# 派活模板 · 之前那次 PilotDeck Rust 迁移里，哪些可以照搬、教训是什么

> 2026-10-14。**每次把一份材料交给 AI 去读，照这个填。四件事缺一不可。**
> 不是「研究一下 X」，是一份结构完整的问卷。

## 先定角色，再定读多深

同一批材料，读的深度**由你显式决定**，不是默认全读。

| 角色 | 怎么读 |
|---|---|
| **要比的**（竞品 / 候选方案） | 逐条核查，每条带文件行号 |
| **要学的**（架构值得借鉴） | 只读架构，不读实现 |
| **零件**（用得上的构件） | 一两行说清它是什么、能接在哪 |

> **取舍不只发生在结论上，先发生在读什么、读多深上。**

也可以一句话把用法定死：**它对我是反面教材，还是简化范本？**

## 派活四件事

复制下面这段，填好发出去。

```
【要读什么】
<绝对路径或 URL>

【角色】
这份材料对我是：要比的 / 要学的 / 零件。（据此决定读多深）

【逐条核查】
1. …… 原生支持吗？在哪个文件、哪一行？
2. ……
3. ……
（每条都要能被「原生 / 部分 / 没有」回答）

【我的预判 —— 请推翻我】
我怀疑它 ……。请回源码确认，不要顺着我说。

【证据格式】
逐条给「原生 ✅ / 部分 / 没有 ❌ + 文件:行号 + 一句话」。
只报事实。引用文件名作为证据。说不出出处的不要写。

【字数上限】
800 字以内。

【必须给判断】
直接用 / 在它基础上改造 / 只借鉴架构 / 不适合——四选一。
给一个首选、一个备选，各附理由，再加三个风险。

【找不到怎么办】
如果没有，就明确说「没有」。
不许拿「部分相关」的东西把版面填满。
```

### 四件事，各自为什么

| 要件 | 它防住什么 |
|---|---|
| **逐条核查项** | 防它按 README 的亮点讲，避开你的命门 |
| **文件行号** | 防印象冒充依据 |
| **字数上限** | **逼取舍**——不限字数，它会把所有材料原样还给你，那等于没做分析 |
| **必须给判断** | 防「各有优劣」这种什么也没说的结论 |

## 读的时候，三道核查

**一、同名不等物。** 仓库里躺着一个名字对得上的文件，可能只是它开发时自己用的。
一路追到：谁加载它、什么时候加载、加载完改变了什么。
**关键词命中，正是 AI 最擅长给你、也最容易骗你的东西。**

**二、抽查两样。** 源头对不对（这份材料是真的吗）· 方法成不成立（这样比对，能得出这个结论吗）。
**真材料经过错方法，仍会稳定地产出错结论。**

**三、看提交历史。** 代码告诉你它现在是什么，**提交历史告诉你它放弃过什么**——
那是别人不会写进 README 的东西。要看历史，clone 时加深度：`clone.sh <url> -d 200`。

## 结论出来之后：换个谱系再审一遍

**同一个会话里再问一遍没用**——它只会再确认自己是对的。偏见有两个来源：
这次会话里积累的上下文，和模型自带的权重。新开会话只洗掉前一半。

**要换就换整套装置**：第三方的框架配第三方的模型。它拿到的既是一份干净的上下文，
又是一套不同风格训练出来的判断。

```bash
codex exec -m <模型> -c model_reasoning_effort=medium < 提示词文件
cat 提示词文件 | opencode run --model <厂商/模型>
```

装了哪些：`bash scripts/check-tools.sh`（初始化时就该装好）。

> ⚠️ **提示词绝不直接写进命令行，先落成文件再让命令读它。**
> 提示词里可能带危险命令，拼进 shell 有被执行的风险；各家对转义符处理也不一致，
> 特殊字符会被吃掉。**「读文件」要真的读**——用文件参数或标准输入。
>
> ⚠️ **发出去之前过一道**：有没有权限外发？密钥、个人信息、未公开的内容摘掉了吗？

派给它的活写清三件：**审什么**（给路径，别贴全文）· **只查什么**（事实 / 逻辑 / 合规——
**风格不归它管**）· **怎么报**（逐条给等级 + 文件行号 + 一句为什么）。

## 多路并行时

几份材料分给几个 AI，**每份都复用同一张核查表**。合并时不要再让一个 AI 写长篇综述，
**横向拼表，你自己裁**。

> **统一问题，比统一结论更重要。** 各人自选维度，每份都对，却没法比。
