## 这次不可妥协的几条

1. 前端一行不改就能接上，能逐条切过去
2. 「一致」能由机器判
3. 同一输入跑两次结果相同

## 我选择什么（草稿）

> **在 18789 gateway 帧协议这条边界上切**：Rust 替换 gateway 进程，`ui/`（含 `ui/server`）不动；对拍照 prime-agent 的样板搭——**同一份脚本、每侧各起一个 mock 模型服务实例（游标与请求日志各自独立）+ 每侧一个临时 `PILOT_HOME` + 比三样（帧与事件流、落盘目录、发给模型的请求体）+ 窄归一化 + 集中的已接受差异清单 + 阳性对照**。

## 我放弃什么（草稿）

> 放弃在 3001 浏览器 API 上切（这一阶段 `ui/server` 及它进程内调用的那部分 `src` 继续是 TS）；放弃函数级对拍、进程内 FFI；放弃 prime-agent 的终端帧 / ANSI 比对、单一巨型驱动脚本、把运行输出提交进仓。

## 支持它的最强依据

A 边界上**WS 客户端形态是现成的**：`tests/sdk/session-transcript-restore-e2e.spec.ts:116` 起真端口、用 `GatewayWsClient` 连。⚠️ 评审纠正：同一个测试的 gateway 是进程内构造、注入了假模型（`:96-105`），**不是现成的两进程黑盒用例**，成色以 exp001 为准。另：openai / anthropic 协议的模型请求经同一出口 `options.fetch`（`src/model/streaming/streamModel.ts:124, 206`），⚠️ **google 流式不经它**，走 `googleClientFactory`（`:172-181, 358`）；落盘根目录可整体替换（`src/pilot/paths.ts:21`）。

## 反对它的最强依据

A 边界**覆盖不到** `ui/server` 进程内调用的 `src` 逻辑（16 个文件 38 处）与对 `auth.db`、记忆库的直读——这一阶段结束时 TS 的 `src/` 仍然删不掉；而且单条 WS 上有连接级状态，「按 method 逐条切」可能根本不成立。

## 仍未补齐的缺口

**基线能不能在隔离环境里无头跑起来、并指向 mock 模型服务**（exp001）。这一条不成立，整套对拍方案要重想。

第 7 步还要跑的两个：exp002 盘点连接级状态（`interactionBinding` 进 `hello_ok` 且每次 `submit_turn` 都注入：`GatewayWsConnection.ts:126-135`；`inFlightSessions` 是连接内存态）；**exp003 让真的 `ui/server` 连一个站在 18789 的透明代理**——命门 1 期末要能举证「前端不改一行接上了」，而真客户端是带重连 / 重放的 `createRemoteGateway`（`ui/server/pilotdeck-bridge.js:60`），不是测试用的 `GatewayWsClient`。
