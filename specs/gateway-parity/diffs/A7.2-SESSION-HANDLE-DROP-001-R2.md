## 基线依据

v22.22.0 运行固定 cc7c4e6 的真实 AgentHandle / PluginRegistry，金样记录：
最后一个 lease 仍持有时 disposal 等待，release Promise 幂等；放开最后引用后
callback 恰好一次，丢弃 waiter 不取消释放；active run 未完成时 onDispose 不跑。

Tokio executor 取消、异步状态锁争用、Mutex poison 没有 JS 对应。

## Rust 行为

三类 plugin lease 的 Drop 和显式 release 共用 spawn 前创建的 RAII guard。
若任务在递减引用前丢失（未 poll、等状态锁时取消等），guard 不获取状态锁，
同步持久发布 `Plugin lease release stopped before releasing its references.`。
存活 runtime 的 dispose / release 等待者返回该明确失败，不继续等遗失的引用；
包括尚未取得状态锁，以及后台 disposal 正等待永不完成的 refresh 的情形。
失败后的 acquire / replace / refresh 拒绝准入，refresh 等锁后重新检查；重复
disposal 保持相同失败。已完成或已返回的 lease.release 结果保留，不被别的
lease 后来遗失改写；全局失败只终结尚未完成的等待者。
已递减计数后 guard 在同一无 await 临界段解除；callback 取消仍由原 completion
机制报错。没有引用的空 lease 不发布丢失错误。

这不是同步回收：遗失的 lease_counts 不伪造归零、callback 不强行执行，不宣称
资源释放成功或授予 Disposed 完成资格。错误是终态通知，资源完整回收仍需存活
executor 正常释放；进程退出回收 OS 资源不等于异步 callback 已完成。

handle drain 在真实 activity 等待中 shutdown，返回 cancelled、Disposed、
`disposal_completed=false`；取得 writer guard 一次，后续 Drop 不重启或覆盖结果。

## 范围

仅 #1010 三类 plugin lease 释放丢失的明确错误与 activity-wait shutdown 测试。
保留正常 lease 引用计数、退休 callback 排序、TS Promise 幂等及 writer fence。
原 -R1 构造前提、poison 与 panic/cancellation 契约继续有效；未扩展为任意第三方
callback 永不完成时自动超时或强制回收。该有意差异仍待人复核。
