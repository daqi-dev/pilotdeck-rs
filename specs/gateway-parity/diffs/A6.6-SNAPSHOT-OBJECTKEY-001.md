## 类别

有意改进（安全加固）：restore 拒绝解析到快照根之外的 `objectKey`，不照抄 TS 的越界读取。

## 基线依据

cc7c4e6 `src/storage/workspaceSnapshot.ts:128-131`：restore 对 `entry.path` 做了三重检查（unsafe relative path、绝对路径、Escape），但对 `entry.objectKey` 只做 `resolve(config.snapshotRoot, entry.objectKey)` 后 `readFile`，无任何校验。Node v22.22.0 实测（`resources/PilotDeck` 只读基线，探针写 /tmp）：`objectKey` 为 `../outside.txt` 与根外绝对路径时 restore 返回 `restored:true`，目标工作区出现根外文件内容。原始输出 `_tmp/20261026-issue-293/probe-a-objectkey.out`（probe 脚本 `/tmp/pdrs-293-a/probe-a-objectkey.mts`）。同一行为已被 snapshot-projection 夹具的 `escape` 快照钉住（oracle op 29/35，`tests/fixtures/snapshot-projection/oracle.json`）。

## Rust 行为

`src/pilotdeck-gateway/src/storage/workspace_snapshot.rs` 的 `restore_units`：`resolve_path_units` 与 NUL 校验之后，对解析结果做与目标侧同款的前缀校验（等于根或 `根 + '/'` 前缀），越界返回新错误变体 `WorkspaceSnapshotError::ObjectKeyEscape`（Display `Snapshot object key escapes the snapshot root.`，`runtime/snapshot.rs` 的 `project_error` 映射为普通 `Error`，无 code）。解析在校验之前，根内 `sub/../x` 仍正常恢复。快照根外文件不读、不写入目标工作区。

## 范围

仅 restore 读侧的 `objectKey`；manifest 中 `objectKey` 的 list/get 原样返回不变（投影仍可见原始 manifest）；`entry.path` 的三重检查与 NUL 语义不变；对快照根内经 `..` 折返回根内的 key 不拒绝（与 TS 可读路径一致）。TS 基线行为（越界恢复成功）在 snapshot-projection 回放中按本条偏离断言拒绝结果，不再与 oracle 的 ok 结果比较。

## 机器判据

`src/pilotdeck-gateway/tests/workspace_snapshot.rs`：`restore_refuses_object_keys_outside_the_snapshot_root`（根内正控 + `../`、绝对路径、`..` 折返越界三个负例，根外哨兵不被复制）。`src/pilotdeck-gateway/tests/snapshot_projection.rs`：`scenarios_match_real_ts_projection` 对 `projection` 场景 snapshotId `escape` 的 restore 断言 `ObjectKeyEscape` 拒绝、restore 目录 0700 且目标树为空。负控 `tests/fixtures/workspace-snapshot-gate/negative_controls.py` 的 `objectkey-escape-allowed` 变异（删前缀检查）要求 KILLED。复算：`cargo test -p pilotdeck-gateway --locked --offline --test workspace_snapshot --test snapshot_projection`。
