## 类别

bug 修复——差异消除（#681）。原条目「拒连 / 超时详情里主机名与 TS 的『解析后地址』不同」所登记的失败路径差异已按 TS 实测文案消除；原条目的机器判据（「暂无」）由本轮新增的金样单测补上。

## TS 依据

2026-10-25 实测（#681，Node v22.22.0、固定基线 cc7c4e6 的编译产物 `dist/src/mcp/client/McpClient.js` + 其锁定依赖 undici@8.3.0 / eventsource@3.0.7 / SDK@1.29.0，原始输出 `_tmp/20261025-issue-681/ts-probe.out`，只回环 127.0.0.1 端点、主机名 `localhost`）：

- legacy `sse` 连 `http://localhost:<closed>/sse`（拒连）：
  `MCP handshake failed: SSE error: TypeError: fetch failed: connect ECONNREFUSED ::1:60169, connect ECONNREFUSED 127.0.0.1:60169`——`localhost` 在本机解析为 `::1, 127.0.0.1`，Node v22 默认 `autoSelectFamily`（`net.getDefaultAutoSelectFamily() === true`，实测）的 happy-eyeballs `net.connect` 把每个尝试过的地址各报一条 `connect ECONNREFUSED <ip>:<port>`（`AggregateError`），eventsource@3 的 `flattenError`（`dist/index.js:48-49`）对 `errors` 数组用 `", "` 拼接。
- legacy `sse` 连 `https://localhost:<stall>/sse`（TCP 通、TLS 停滞，`handshakeTimeoutMs: 30000` 让 undici 的 10 s `connectTimeout` 先到）：
  `…SSE error: TypeError: fetch failed: Connect Timeout Error (attempted addresses: ::1:60217, 127.0.0.1:60217, timeout: 10000ms)`——复数 `attempted addresses`，列表来自 socket 的 `autoSelectFamilyAttemptedAddresses`（undici 8.3.0 `lib/core/util.js:904-920`）。
- `streamable_http` 两种失败都只报 `MCP handshake failed: fetch failed`（cause 不进 message），地址不外显，与 Rust 现状一致。
- `http:` 只 accept 不应答：两侧都由 10 s 握手超时先报 `MCP handshake timed out after 10000ms (server=…)`，无地址。

读码推断、未实测（本机没有只解析到单个 127.0.0.1 的主机名，无法在不改系统文件的前提下实测）：单地址主机名的超时仍显示 URL 主机名（node v22.22.0 `lib/net.js:1536-1547` 的 `toAttempt.length === 1` 分支不记录解析，undici `onConnectTimeout` 回退到连接器收到的 URL hostname）；单地址拒连则与多地址同形（`internalConnect` 的 net 错误本来就带解析地址）。另：Node 的 `dns.lookup` 带 `AI_ADDRCONFIG` hint（`lib/net.js:1373-1376`），Rust 的 getaddrinfo 不带，无 IPv6 的机器上解析集可能相差 `::1`，属未消除的边角。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/mcp/http.rs`：`failure_cause` 拆为 `classify_failure`（分类不变：Proxy / Refused / ConnectTimeout / Tls）+ 两个文案构造器；新增 `resolved_attempts`（失败路径上对主机名 URL 做 `tokio::net::lookup_host`，getaddrinfo 顺序与 Node `dns.lookup` 一致；IP 字面量跳过，Node 不解析）、`node_attempt_order`（Node 的去重 + 首地址地址族优先 + 两族交错，`lib/net.js:1470-1541`）、`node_address`（裸 IPv6 无方括号）。拒连文案按解析地址逐条 `connect ECONNREFUSED <ip>:<port>` 用 `", "` 拼接；超时文案在解析出多个地址时用复数 `attempted addresses` 列表，否则维持 URL 自身地址（IP 字面量 / 单地址主机名）。成功路径、streamable 的 cause 剥离（`strip_cause`）、proxy 分支、TLS 分支均不变。

## 范围

MCP `streamable_http` / `sse` 连接失败时 cause 文本里的地址部分，仅当 URL 用主机名时行为改变（`localhost:P` → 解析地址列表）；IP 字面量（含 IPv6 去方括号）文案不变。`https-sse-refused` / `https-sse-refused-ipv6` / `https-sse-handshake-stall` 回放金样不受影响（IP 字面量）。代理自身的 CONNECT 失败文案（`runtime/model/http.rs` `ProxyConfig::connect_error` 对主机名代理同样显示代理 URL 主机名而非解析地址）是同一模式的兄弟位置，本单不修，另开跟进。失败路径上多一次 getaddrinfo（仅拒连 / 连接超时两种分类触发），成功路径无额外开销。

## 机器判据

- `runtime::mcp::http::tests::hostname_refusals_list_every_resolved_address` / `hostname_connect_timeouts_list_attempted_addresses`（TS 金样，原文见 `_tmp/20261025-issue-681/ts-probe.out`）、`node_attempt_order_dedupes_and_interleaves_families`、`failure_addresses_use_the_scheme_default_and_node_form_for_ipv6`（删去无 TS 依据的 `example.com:8443` 断言）。
- 端到端 `tests/mcp_client.rs::hostname_refusal_reports_resolved_addresses_not_the_hostname`：真实拒连端口 + `http://localhost:<port>/sse`，断言文案不含 `localhost` 且逐个含 `connect ECONNREFUSED <解析地址>:<port>`（解析集按本机 getaddrinfo 现算）。
- 负控（2026-10-25 实跑）：把 `refused_cause` / `timeout_cause` 改回忽略解析、显示 URL 主机名（可编译的最小回退）后，上述两个金样单测与端到端用例全部失败（端到端实得 `connect ECONNREFUSED localhost:50394`），恢复后通过。
