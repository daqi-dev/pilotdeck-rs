## 类别

更正（Rust 行为随 #2257 / #2269 扩展 + 反事实缺口补齐 + 计数更新，非差异
变化）：014 登记的四条残差全部维持，本条补三件事：

1. **#2257 Err 分流**（新行为登记，属生产码变化）：014 的 Rust 形状只覆盖
   正常 `stop()`（`shutdown.send(true)` 走 Ok 路径）。两条 Err 触发路径——
   ① `stop()` async 块首行 `shared.log(...)` panic（unwind 时 `ServerEntry`
   连 watch sender 带 accept 循环 JoinHandle 一起 drop）；② handle 直接
   drop、未调 stop——此前与正常 stop 落入同一 drain 分支，「闭通道也
   drain」：无人观察的 drain 把监听端口占满 60 s 上限。#2257 把 select 臂改
   Err 分流：Err 路径跳过 drain（`JoinSet` 自然 drop = abort，端口即刻
   释放）；正常 Ok 路径的 drain 语义、两开关、warn 计数一字不动。
2. **#2269 永久负控**（方案 2，协调者拍板）：014「机器判据」里 #2247 r2
   更正的「截断 warn 计数」（timeout 返回 `Err` 后在分支内读
   `connections.len()`）此前只有用例断言 + r2 树的一次性实跑；#2269 把 r1
   的反事实形状（drain 前快照计数）做成永久编译开关
   `sms-stop-drain-predrain-count`，负控可复现击杀。
3. **计数更新**：014「范围」末行的「56 格金样」→ 57（#1913 加 `http10`
   格，`A8.3-CH-SMS-015`）。

## Rust 行为

`src/pilotdeck-gateway/src/channel/sms/mod.rs`（#2257 / #2269，基于
`648862527eb1`）：

- select 臂（`:653` 区域）：`changed = shutdown_rx.changed() => match changed
  { Ok(()) => break, Err(_) => { sender_dropped = true; break } }` —— watch
  的所有 sender 消失时 `changed()` 返回 `Err(RecvError)`：正常 stop 时
  `ServerEntry` 活到 `task.await` 结束（sender 存活）→ `Ok(_)`；两条 Err
  路径（stop 任务首行日志 panic 的 unwind、handle drop）都让 sender 提前
  消失。
- drain 分支：`if sender_dropped &&
  !crate::mutants::on("sms-stop-drain-on-sender-drop")` 时**跳过 drain**
  （`JoinSet` 自然 drop = abort 在途连接任务，监听 socket 随之关闭，端口
  即刻可重绑）；
- #2269：drain else 侧 `let pre_drain_count =
  crate::mutants::on("sms-stop-drain-predrain-count").then(|| connections.len());`
  ，截断 warn 的 `remaining` 读
  `pre_drain_count.unwrap_or_else(|| connections.len())` —— 开关开时恢复
  r1 形状（drain 前快照），关时维持 r2 形状（timeout 后现读）。
