## Rust 行为

条目 6（#2363 协调者授权，2026-11-09）三处：

- `src/pilotdeck-gateway/src/switch.rs`：`CronManagementGate`——每
  manager 一把 `tokio::sync::RwLock<()>`（`CRON_MANAGEMENT_GATES`
  注册表按 manager 身份 find-or-create：键是 `Weak<CronManager>`，
  查找前清扫死键——防串号（死键永不匹配活 manager、释放地址复用不
  串门）与既有 `CRON_MANAGEMENT_CLOSED` 同源论证，但生命周期相反：
  注册表不拥有 manager，不把 `CronRuntime::drop` 的清理推迟到进程
  退出；查找按 `Weak::ptr_eq` 指针比对、不升级弱键——升级会在查找
  窗内临时借出强引用，并行查找可让「已 drop 的 manager」短暂复活
  （fix-r4，codex concurrency/boundary P1 + DS concurrency P2 取高），
  先例 `runtime/memory/maintenance.rs` 同款 `Weak` 键形状）；dispatch 半
  `enter_dispatch()`（`blocking_read`，闭包体全程持读半），stop 半
  `drain_dispatches()`（async `write()`，取消安全——drop 排队中的取写
  即取消，closed 标记留置）。`stop_face` 顺序：close（落 A6 标记）→
  `drop(gate.drain_dispatches().await)`（排空）→ `stop_once()`。
- `src/pilotdeck-gateway/src/native_process/methods/cron.rs`：
  `dispatch_under_management_gate`（`cron_request` 的 `spawn_blocking`
  闭包体，即 WS 接缝真实执行体，`pub(crate)` 供测试直入同一函数）——
  先取读半，再查 closed（A6 / DC-5 拒绝），未关才 dispatch 六方法，
  体内完成才放读半。
- 锁序（dispatch 侧：gate registry → 读半 → closed registry → 方法体
  state；stop 侧：closed registry → 写半 → `stop_once` state）：两个
  registry 临界区内都不取 gate、也不嵌套互取，无环。
