## 类别

bug 修复（判据登记缺项）：A8.6 登记时把 always-on 三方法按金样逐行比对，但没登记
「Rust 侧暂缓实现、如实回 `CAPABILITY_UNAVAILABLE`」这一既知差异，导致真实 Rust
retirement 轮在这三个方法上被判 P3 + P4 + P5 共 9 条假 FAIL。本更正**不改阈值、不改
场景集、不改金样**，只给这三个方法补一格**逐方法显式延期**（延期，不是豁免）。

  error: {code: "cycle_not_found"}}`，同样包在成功信封里。

`Requests::always_on_request` 里**无条件**返回 `RequestError{code:
"CAPABILITY_UNAVAILABLE"}`（`:17-24` 的 `unavailable()`），文案照抄 TS；

## 范围

- 延期方法集（逐方法显式，无前缀/通配）：
  `always_on_apply`、`always_on_abort`、`always_on_rerun_plan`。
- **只容忍一格**：该方法 `outcome == 'error'` 且 `errorCode == 'CAPABILITY_UNAVAILABLE'`
  对应金样 `ok`（`errorCode: null`）。同一方法换成任何别的码（`not_configured`、
  `gateway_request_failed`、……）→ P3 + P4 照常 FAIL；Rust 将来改回 `ok` → 按金样
  正常 PASS，不需要这条登记。
- **不关判据**：P1（101 条覆盖）/ P2（shape）/ P6（线缆一致性）/ P7（跨轮稳定）/
  P8（fail-closed）对这三个方法**照常核**；P3 / P4 / P5 对**其余 98 个方法**逐字节不变。
  P5 的「集合外答 unavailable」集合减去这三个方法（它们的 unavailable 已登记为既知差异），
  6 个 gated 方法的双向集合判定不变。
- **不得静默**：每轮统计新增 `deferred` 计数与 `deferredMethods` 列表，报告顶层
  `deferred` 段给出登记集、理由与本文件名；命中在 stdout JSON 里可见。
- **fail-closed 前置**：金样里这三行必须是 `ok`（否则 rc2）、不得与 gated 集重叠
  （否则 rc2）、必须出现在 101 条里（否则 rc2）；`emit` 拒绝从「延期方法答错」的轮次
  派生金样（rc2），防止把 Rust 差异写进 TS 金样。
- 阈值仍为 **0 处不一致**；无百分比、无退化名额、无通用白名单。
