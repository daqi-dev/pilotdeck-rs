## 类别

更正（#1292 P2 跟进七项 + #1366 收敛，原条目与 R1 的批准状态不变；
fix-r1 按 r1 评审 P1×2/P2×1/P3×1 就地修订本文件）：

1. **headersTimeout 60 s 已复刻**（#1366，#1292 第 7 项；001-R1 登记的
   「未复刻，归 002 族处理」由此收口）：起算与重武装按请求——首头自
   连接开始、每个后续头自其首字节（`on_message_begin`），响应结束为下一
   头重设（fix-r1，探针 `fix-r1/probe-p11.out`：已 served 连接上滴字
   后续头在 +90.001 s 收 51 字节 408）；未 served 首头不完整——含零
   字节连接——写 Node 同形 51 字节
   `HTTP/1.1 408 Request Timeout\r\nConnection: close\r\n\r\n` 并关闭；
   已 parsed 的请求（含仍流式中的响应）永不被 408；停止 disarm
   （`server.close()` 清 connections checker，停止后的读段也不重设）。
   **落地**：408 落在 connections checker 30 s 网格（锚点 listen）的
   首个 ≥ deadline 的点，不是到期即裁（fix-r1，探针
   `fix-r1/probe-p12.out`）。
2. **requestTimeout 300 s 登记不复刻**：全部可探 TS 路径上不可达，复刻
   无对齐收益。
3. **残余清单同步**（#1292 第 1–2 项）：hyper 1.7.0 无 raw header span /
   原始 target / 按需 `max_headers` 分配 API，「出现后同步」不可执行；既有
   4 项预算边界残余维持；**新登记 1 项资源族残余**（`max_headers(16384)`
   每次解析的预分配峰值）；`uri().to_string()` 每请求重渲分配已修复（有
   路径的形态值恒等；无路径 + query 的绝对形分段求和恰为 Node 原始
   target span、比重渲少 1 字节，见 TS 依据第 7 点，负控 N1 由 fix-r1
   以 `native-http-uri-realloc` 恢复）。
4. **术语对照**（#1292 第 3 项）：A7.4 的 `max_headers(4096)` 与本条的
   16384 口径互引（见「范围」）。

6. `b4-U1.out`/`b4-U2.out`：17 020 B 超预算头在 `/ws` 升级路径与

7. `uri-probe.out`（http =1.5.0，与 lock 同版）+ fix-r1 `probe-p2.out`

8. 4 项预算边界残余的 TS 侧原证不重跑：R1（main，2026-11-01 #1304

## Rust 行为

`src/pilotdeck-gateway/src/http_proxy.rs`（native lane；代理 lane
`serve_connection_with` 照旧传无超时——其 TS 对应物不同、无探针，字节
不变）：

- 新增 `NODE_HEADERS_TIMEOUT` 60 s 与 `NODE_HEADERS_TIMEOUT_408`
  51 字节常量（与 `user_dialog` lane 各持一份罐装 Node 字节，同两个
  431 的先例）；fix-r1 增 `NODE_CONNECTIONS_CHECKING_INTERVAL` 30 s 与
  `headers_deadline_landing`（首个 ≥ deadline 的网格点）。
- `UpgradeReadGate` 增 deadline / 停止接收端 / 停泊 `Sleep`（在读
  waker 下轮询，静默首头也能在到期唤醒）：未 served 且未停止时到期即
  写 408、随后读侧 EOF、hyper 自身写拒绝 BrokenPipe。fix-r1 重写
  disarm/重设为按请求状态机：`served_heads` 计数 + `disarm_after`
  水位（已 parsed 超过武装时点即 disarm——served 或 in-flight 永不被
  408）、`awaiting_head`（后续头首字节重设其自己的 deadline，滴字节
  只续 idle）、响应结束（`IdleBody::release`）经 `rearm` watch 为下一
  头重设；停止仍 disarm，且停止后的读段不重设。连接 future 的本地
  形状：半头截断报 `IncompleteMessage`，零字节连接为干净关闭（线上
  字节与关闭时机一致，仅本地错误形状不同）。
- 落地网格：`native_ws.rs` 在 bind 时刻取 `grid_anchor`，经
  `serve_socket` → `serve_connection_configured` 传入（首头与重设的
  deadline 都过 `headers_deadline_landing` 量化）；代理 lane
  `serve_connection_with` 无锚点照旧（deadline 即真值——无监听器在
  socket 背后，与本条其余代理 lane 行为一致）。
- 停止分支增 test-only `stop_observed` 计数（替代 #1209 stop 测试的
  100/200 ms 固定 sleep，不观察生产行为）。

`src/pilotdeck-gateway/src/native_http.rs`：`tracked_header_bytes` 去
`to_string()` 每请求重渲，改分段求和；预算判定提为 `over_header_budget`
供两 lane 共用；`request_header_fields_too_large` 转 pub(crate)。
`src/pilotdeck-gateway/src/native_ws.rs`：升级分流前先判 span 预算
（`native-http-upgrade-budget-off` 变异口）；`ts_loopback_literal`
把 loopback 派生收紧为 TS 字面量（127.0.0.1/localhost 即
`Ipv4Addr::LOCALHOST`，先于 bind 策略放宽，属实现层对齐，无差异可登
记）。

## 范围

原生监听器（`NativeWsServer` 的非升级分支解析层 + 升级分流的预算
判定）；升级分支此前绕过 span 预算的缺口按 `b4-U1/U2` 修复；fix-r1
的 per-request 重武装与 408 网格落地同在原生监听器（bind 锚点由
`native_ws.rs` 提供）。不含：默认代理路由（字节不变）；requestTimeout
300 s（登记不复刻，见「类别」第 2 点）。**408 网格残余**（fix-r1 起
改写，r1 评审 P1-2 成立）：Rust 复刻 listen 锚定的 30 s 网格，取首个
≥ deadline 的点、从不提前；deadline 落在网格点 ±tick 执行抖动（毫秒
级）内时 Node 双峰（`probe-p12.out` p12b 在 5.002 s 落、与 5.500 s
网格点之间毫秒可辨），Rust 确定性取后继网格点——登记为实现细节残余。
**术语对照**（#1292 第 3 项）：A7.4-HTTPSTORE 族的
`max_headers(4096)` 是 `user_dialog/http_store.rs` 构建器的**头行数**
资源上限（该 lane 自身登记）；本条的 16384 是 Node TrackHeader 的
**span 字节**预算（handler 层复刻），构建器头数上限取同名值只为不先于
预算生效——同名旋钮、不同 lane、不同单位，两条登记以各自探针为准，
不改 A7.4 已收条目。分配峰值残余：hyper 1.7.0 `h1/role.rs:149–161`
每次解析按 `h1_max_headers` 预分配两支 SmallVec（`HeaderIndices` 与
`httparse::Header` 各 16384 槽、每槽 32 B，合计 ≈1 MiB 瞬时），对慢速
多连接放大 CPU/内存峰值；Node 无头行数上限、按需增长——登记为资源族
残余，数值不构成对拍豁免（响应字节与边界判定均一致）。
