## 类别与范围

运行时 API 映射差异，未批准；只涉及 complete I/O 挂起期间销毁整个 Rust LiveTurn。取消一个 next 借用不在此差异中：它必须继续同一 transition。未修改冻结判据，不据此增加判分豁免。

## 基线实测

固定 cc7c4e6，`tests/fixtures/turn-gates/generate.mts` 运行真实 AgentSession、TurnRunner、stdio sidecar；金样 `turn-gates/oracle.json` 的 drop-pending / drop-pending-once / drop-pending-always。原始输出在本次交付证据 `_tmp/20261026-issue-741g/node-final.log`，原始帧在 `ts-final/*-raw.json`。

JS `stream.return()` 排在仍然被持有的 pending.next 之后。complete 成功时该 next 得一个终态；首次 complete 失败时 catch 仍执行第二次 complete。一次失败得到一个持久错误结果、next 得 status，return 后不再交付 terminal；持续失败则两次尝试都失败并拒绝 pending.next。三格最后 active=0、closed=1。

## Rust 行为与判据

销毁整个 LiveTurn 会取消其 async transition，已经进入的 blocking append 仍持有真实 ActiveTurn 和 RuntimeLease，直到 I/O 退出。成功写入保留一次持久结果；失败写入不再启动 catch 重试；没有消费者，不产生可见终态。三个对应 `gates_drop_pending*` 用例均断言写入前 slot/lease 保留、写入后释放、child 已回收、complete 尝试一次；正常写入 durable=1，失败 durable=0。

JS return 与 Rust Drop 不是可取消能力相同的 API，因此不能宣称这些格逐字段对齐。若宿主将来要求 Drop 后仍补偿持久化，必须另行定义脱离消费者的终结任务、资源所有权及错误归属，本包不暗中引入后台续跑。
