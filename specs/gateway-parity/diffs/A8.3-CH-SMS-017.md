## 类别

本轮有意未对齐（#2499 对齐后剩余的两条有界残余 + `A8.3-CH-SMS-012` 残差
3 的重读落点 + fix-r1 增补、fix-r3 扩为同读通用形状的残差 3 + fix-r5 按
Node 实测增补的残差 4）：#2499
（#2026 决策 B）把 sms 车道
请求头读期限对齐到 Node `headersTimeout` 的三件事——到期写 Node 的 51 字节
`408 Request Timeout` + `Connection: close` 原始字节、锚点规则（有首字节
锚首字节、无字节锚连接建立，按每个请求头重锚）、落点由 30 s
connections-checker 网格裁断（首个**严格大于** deadline 的网格点，恰落
网格点取后继）。012 的残差 1（线上字节）与残差 2（触发时刻与起算点）
就此消除（`A8.3-CH-SMS-012-R5`），本条登记对齐后**仍存**的有界差异：

1. **网格落地的确定性**：Rust 按锚点整数倍确定性取后继网格点、从不提前；
   Node 的 checker tick 带毫秒级执行抖动，deadline 恰落在网格点 ±抖动内时
   Node 双峰（该 tick 的 `now - last_message_start_ > headersTimeout`
   比较可能在抖动内成立、也可能不成立）。同族登记见
   `A8.4-NATIVE-HTTP-002-R2` 的「408 网格残余」（native 车道同网格同措辞，
   其双峰证据 `probe-p12b`）；本车道金样只录应答三元组、不录时刻，格内
   无从分辨，登记为本车道自己的条目。
2. **空闲 keep-alive**：已 served 连接上的零字节后续头由本车道自己的
   60 s 头期限**静默**关（无 408、无 keep-alive 头）；Node 的
   `keepAliveTimeout` 5 s 关（5 s + 网格取整实测 5–6 s），且 served 响应
   带 `Connection: keep-alive` 与 `Keep-Alive: timeout=5` 两个头。这是 012
   残差 3 在 #2499 后的重读：修前头期限到期一律零字节关，修后**首个**零字节
   头与 Node 一样得 408，只剩 follow-up 空闲关的取值（60 s vs 5–6 s）与
   两个 keep-alive 头的缺失。
3. **同读吞掉后继头字节**（#2499 fix-r1 增补评审 concurrency#2 交错 A
   的 drain 孪生；fix-r3 按评审 r3 concurrency#1 扩为通用形状）：后继
   头的**首字节**若与前一请求的头/体落在同一次门读里，这些字节从此不再
   跨门的记账——该读时 `body_remaining` 还是旧值（service 尚未
   `store(L)`，或残存未扣完的 L），首字节重锚被跳过，后继头按上一响应
   完成时刻锚的 standby 窗关闭：比 Node 的自身重锚落点早恰好一个网格
   点、且因无锚记录而**字节静默**（与残差 2 同关路径），从不更早、也
   不悬挂。三个变体同一根因：
   - **drain 路（fix-r1 原登记）**：handler 不读 body 的请求（错路径
     404、`node_parser_admission` 拒绝）body 与头同读抵达，hyper 从自己
     的读缓冲 drain 掉这些字节——这条路不经过门的 `body_remaining`
     计数，且没有可观察的完成信号——响应完成后穿过门的 drain 读与头
     字节不可区分，提前置 0 恰好错锚「body 分段迟到」的形状（该形状
     现行按 Node 精确）。探针证据
     `_tmp/20261026-issue-2499/fix-r1/evidence/prefix-interleave-a-404-drain.log`，
     边界钉
     `a_follow_up_head_after_an_unread_request_body_closes_on_the_standby_landing`；
   - **整段同读**（fix-r3）：handler 读 body、但后继半截头与头+体
     **一次写出**（`POST … Content-Length: 96\r\n\r\n` + 96 字节 body +
     `POST /sms/incoming HTTP/1.1\r\nHost: x\r\n`，总长 < 8 KB）：门
     首读把全部字节一次交给 hyper（该读时 `body_remaining=0` →
     `consume(0)`），随后 service `store(96)`、handler 从 hyper 缓冲
     读掉 body——那 18 字节后继半截头此后不再跨门；
   - **read-ahead 变体**（fix-r3）：L=96、头带 40 字节 body 同读，第二
     次写 56 body + 20 后继头 → 门 `read=76 ≤ body_before=96` →
     `head_start=false`，同样静默早关。
   fix-r1 的读 body 收尾置 0（`route_request`）只覆盖 **store 之后**才
   到达的字节；同读吞掉的后继头字节已躺在 hyper 自己的读缓冲里、天生
   不再跨门，门拿不到 hyper 已读缓冲量，实现侧无法自愈，登记 + 边界钉
   是可行路径。两个同读变体的边界钉
   `a_follow_up_head_swallowed_in_the_same_read_as_the_previous_request_closes_on_the_standby_landing`
   / `a_follow_up_head_swallowed_with_a_read_ahead_body_segment_closes_on_the_standby_landing`
   （暂停时钟：standby 落点前 +29.46 s 仍开、+30.66 s EOF 零字节、
   永不 408；`_tmp/20261112-issue-2499/fix-r3/evidence/same-read-cells.out`）；
   击杀绑定与记账位变异的不可判别性见「机器判据」。
4. **停泊的已完整后续头在响应永不完成时被 408**（#2499 fix-r5 增补，按
   评审 boundary#3 先探 Node 后登记）：响应在飞时到达的已完整后续头被门
   扣留（`withheld_head`——cap 内同样扣留），各自首字节锚定的 deadline
   照常落地，`response_head_written` 为假时到期分支写 408 并关连接（钉
   `a_capped_withheld_head_behind_a_never_completing_response_gets_its_408_at_the_landing`：
   held 响应 + 512 头洪泛恰满 cap，+29.52 s 仍开、+30.12~+30.18 s 落点恰
   408）。
   Node 对**已解析**的请求永不被 408：已完整的停泊头连自身
   headersTimeout 都不裁（leg B：1.5 s 期限下 held 4 s，512 条停泊头
   零 408，释放后 513 条响应逐个送达 @4011 ms；leg E：单条已完整后续头
   + held 响应，+6 s 内无 408 无关闭，释放后两条全数送达）。**响应完成侧
   已对齐**——fix-r5 的 release 唤醒让停泊头在响应完成时立即逐个回喂
   服务（端到端 cell 钉 513 条响应，leg A/B 同形）；残差只在「响应永不
   完成」侧：Rust 在停泊头自身 deadline 落点 408 早关，Node 无限期持有
   （requestTimeout 只覆盖请求接收，已完整头不适用）。探针
   `_tmp/20261026-issue-2499/fix-r5/probe-node-pipeline-serve.out`（leg A/B/C）
   与 `probe-node-parse-state.out`（leg D/E），Node v22.22.0。native 车道
   同形状同登记（`A8.4-NATIVE-HTTP-002-R6`）。

78.2。TS 侧复用 012 已归档的实测，#2499 新增两格在基线上真录制：

  （`A8.4-NATIVE-HTTP-002-R2` 基线依据第 5 点；5 s 期限 + 0.5 s CCI、

## Rust 行为

`src/pilotdeck-gateway/src/channel/sms/mod.rs`（读侧由
`HeadersTimeoutGate` 自持，hyper builder 裸跑——#2499 摘掉了
`.timer(TokioTimer::new()).header_read_timeout(..)` 那对）：

- `DEFAULT_HEADERS_TIMEOUT = 60 s`（`:91`）与
  `NODE_CONNECTIONS_CHECKING_INTERVAL = 30 s`（`:105`，注释引
  `_http_server.js` 的 `setInterval(checkConnections, 30_000)` 与
  `ts-zero-and-delayed.out` 实测）；`headers_deadline_landing`（`:1096`）
  取首个严格大于 deadline 的网格点、恰落网格点取后继（变异
  `sms-headers-grid-off` 退化为 deadline 即裁）。
- `HeadersTimeoutGate<S>`（`:1147`）包连接 IO：锚点规则
  （`arm_started_head` `:1322`——任何一次读到字节且当前头未开始即锚定
  该头自身的 deadline，首头也不例外不锚连接建立；零字节首头保持
  连接建立锚；变异 `sms-headers-first-byte-anchor-off` 退回连接锚）、
  响应结束经 `RearmBody`（`:1653`）+ watch 为下一头重设待命窗口（已
  开始的头其 deadline 骑过前驱响应的流式）、`stop()` 解除武装
  （`:1449`，变异 `sms-headers-stop-no-disarm`）、在飞响应已写过
  response head 则静默 destroy（`response_head_written`）。
- 到期三分支（`:1460-1485`）：有字节的首头 / follow-up 头与零字节
  **首**头写 `user_dialog` 的 `NODE_408_RESPONSE` 原始字节直上 socket
  （不经 hyper 响应路径——无帧化、无 header 改写、无 `Date`；变异
  `sms-headers-408-bytes-off` 摘掉字节只关）；已 served 连接上的零字节
  follow-up 头是 Node `keepAliveTimeout` 的静默关——**不复刻**（本条
  残差 2 的登记面；变异 `sms-headers-idle-followup-408` 恢复写 408 供
  负控击杀）。
- 扣留停泊的唤醒（fix-r5，评审 boundary#1/concurrency#1）：停泊分支
  （`withholding_mid_stream()`，`WITHHELD_HEAD_CAP` 32 KiB `:1128`）在
  返回 `Poll::Pending` 前把本 poll 的 waker 存进 release 槽
  （`release_waker` 字段 `:1239`，注册位 `:1542`，`serve_sms_connection`
  创建 `:1788`），`RearmBody::release`（`:1681`）在响应完成后取槽唤醒
  ——替换 fix-r4 的空缓冲 `poll_read`（fix-r5 tokio 探针证明生产
  `TcpStream` 上零长读不注册 waker：内核仍有数据时 `read(fd, ptr, 0)`
  返回 `Ok(0)`，tokio 只在 `WouldBlock` 存 waker，恰排空形状下成立是
  内核依赖的偶然；cap 后循环不再读、连该形状也失去）。hyper 不自行
  重 poll 停泊读（响应结束的 `try_keep_alive` → `maybe_notify` 短路在
  io 层 `read_blocked` 标志上，而该 `Pending` 刚置位），所以唤醒必须
  来自响应完成——恰是 Node llhttp 逐个服务停泊头的时刻（残差 4 的
  leg A/B）。停泊头自身的 deadline 不需额外交出：上方三分支的 sleep
  在同一 waker 下每 poll 注册。变异
  `sms-headers-withheld-park-no-wake` 只摘唤醒供负控击杀。
- 网格锚点 = 监听器 bind 时刻（accept 循环 `grid_anchor =
  tokio::time::Instant::now()` `:669`，对应 Node checker 相位锚
  `'listening'` 事件）；`#[cfg(test)] SmsShared::test_grid_interval`
  （`:306`）是暂停时钟用例的注入点——不新增公开选项字段，生产路径
  恒 30 s。
- body 记账（fix-r1 补齐）：`request_content_length`（`:1726`）对
  `Transfer-Encoding` 返回 native 同形的 `i64::MAX` 哨兵（修前 −1 与
  `withholding_mid_stream` 的 `<= 0` 组合把 chunked body 当下一头扣留、
  handler 饿进 300 s body 408——fix-r1 评审 boundary#1/concurrency#1；
  变异 `sms-headers-chunked-body-withheld` 恢复 −1 供负控击杀）；扣留
  回喂路径与 fresh 读路径同读法（`consume_request_body` +
  `arm_started_head`）；handler 读 body 收尾把计数置 0（`route_request`，
  hyper 此时已消费完整个请求 body，残留正值按构造即 hyper 首读缓冲
  前推/回喂扣留留下的陈旧值）——置 0 同时让已读 body 请求的响应流式
  期间管线化下一头照常扣留。置 0 只覆盖 **store 之后**到达的字节：
  与前一请求头体同读吞进 hyper 读缓冲的后继头字节不再跨门（fix-r3，
  两个确定性交错见残差 3），handler 不读 body 的 404/准入拒绝路径又
  无可观察的 drain 完成信号——两形一并登记为本条残差 3。
- 头读期限与 body 读期限仍共用 `SmsChannelOptions::request_timeout`
  一个注入点（`#1955` 既有口径，012「Rust 行为」第 2 点不变）。

## 范围

仅 sms 车道请求**头**读期限的到期行为。不含：

- body 读超时的 408 字节形状与时刻（`A8.3-CH-SMS-010` / `-011`）；
- keep-alive 5 s 回收与两个 keep-alive 头的补写——本条残差 2 只登记
  「follow-up 空闲静默关发生在 60 s、Node 5–6 s、头缺失」，5 s 回收
  本身是跟进方向不是本条判分豁免；
- `stop()` drain 上限与 Err 分流（`A8.3-CH-SMS-014` / `-R1`，决策 C）；
  #2499 只把「drain 中连接的头期限被解除」对齐 Node 的
  `httpServerPreClose` 清 checker；
- 并发连接数上限、验签顺序（012「范围」原判不变）；
- 金样矩阵的量程：两新格覆盖 408 **字节**（三元组 + Rust 侧逐字节钉），
  锚点 / 网格 / 静默关时刻低于 oracle 的记录粒度（不录时刻），由
  `head_timeout_tests.rs` 的暂停时钟用例承担（见「机器判据」）。

本条不构成判分豁免：残差 1 是毫秒级确定性差（方向只可能晚 Node 的
双峰早支、从不提前于严格后继点），残差 2 是静默关时刻差，残差 3 只触达
「后继头与前一请求的头/体同读（handler 读或不读 body 皆可）」这一金样
矩阵不覆盖的客户端形状，残差 4 只触达「已完整后续头停泊在永不完成的
响应之后」这一金样矩阵不覆盖的客户端形状（fix-r5）——四者都不改变
任何金样格的期望字节或状态。
