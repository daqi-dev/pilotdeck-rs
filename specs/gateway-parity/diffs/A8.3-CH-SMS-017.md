## 类别

本轮有意未对齐（#2499 对齐后剩余的两条有界残余 + `A8.3-CH-SMS-012` 残差
3 的重读落点）：#2499（#2026 决策 B）把 sms 车道请求头读期限对齐到 Node
`headersTimeout` 的三件事——到期写 Node 的 51 字节
`408 Request Timeout` + `Connection: close` 原始字节、锚点规则（有首字节
锚首字节、无字节锚连接建立，按每个请求头重锚）、落点由 30 s
connections-checker 网格裁断（首个**严格大于** deadline 的网格点，恰落
网格点取后继）。012 的残差 1（线上字节）与残差 2（触发时刻与起算点）
就此消除（`A8.3-CH-SMS-012-R5`），本条登记对齐后**仍存**的两条有界差异：

1. **网格落地的确定性**：Rust 按锚点整数倍确定性取后继网格点、从不提前；
   Node 的 checker tick 带毫秒级执行抖动，deadline 恰落在网格点 ±抖动内时
   Node 双峰（该 tick 的 `now - last_message_start_ > headersTimeout`
   比较可能在抖动内成立、也可能不成立）。同族登记见
   `A8.4-NATIVE-HTTP-002-R2` 的「408 网格残余」（native 车道同网格同措辞，
   其双峰证据 `probe-p12b`）；本车道金样只录应答三元组、不录时刻，格内
   无从分辨，登记为本车道自己的条目。
2. **空闲 keep-alive**：已 served 连接上的零字节后续头由本车道自己的
   60 s 头期限**静默**关（无 408、无 keep-alive 头）；Node 的
   `keepAliveTimeout` 5 s 关（5 s + 网格取整实测 5–6 s），且 served 响应
   带 `Connection: keep-alive` 与 `Keep-Alive: timeout=5` 两个头。这是 012
   残差 3 在 #2499 后的重读：修前头期限到期一律零字节关，修后**首个**零字节
   头与 Node 一样得 408，只剩 follow-up 空闲关的取值（60 s vs 5–6 s）与
   两个 keep-alive 头的缺失。

## 基线依据

固定基线 `cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85`，Node v22.22.0 / ICU
78.2。TS 侧复用 012 已归档的实测，#2499 新增两格在基线上真录制：

- 012「基线依据」的 `ts-zero-and-delayed.out`（同一台机器、同一基线）：
  零字节首头与半截首头都 51 字节 408、`firstByteMs=90004`；延迟 35,002 ms
  的半截头 `firstByteMs=120008`（= 该头自身 95,002 ms 期限的后继网格点）
  ——首字节锚 + 严格后继网格两条规则的原证，本条不重跑。
- 双峰（本条残差 1）：native 车道 `probe-p12b`
  （`A8.4-NATIVE-HTTP-002-R2` 基线依据第 5 点；5 s 期限 + 0.5 s CCI、
  头起算晚 ~1 ms，408 落 listen+5.002 s——该抖动使恰网格点的比较成立）。
  本车道金样不录时刻，双峰在本车道不可格内观测，按同族先例登记。
- 空闲 keep-alive（本条残差 2）：`keepAliveTimeout=5000` 同 012 引
  `A8.3-WECOM-CALLBACK-KEEPALIVE-001`（同一无 options `createServer`
  家族、同一 connections-checker 路径，5 s 到期 + 网格取整 5–6 s、
  served 响应带两个 keep-alive 头）。
- #2499 金样两格 `headers-timeout-first-byte`（18859：连接后静默
  1,500 ms 再写半截头——首字节锚）与 `headers-timeout-connect-anchor`
  （18860：零字节——连接建立锚），由真生成器在基线上对真 `SmsChannel`
  实跑录制（cb8，Node v22.22.0 / ICU 78.2，与金样生成机同版本；双写
  一致后落盘），期望均为 `{"status":408,"contentType":null,"body":""}`
  ——`head-stall` 探针按 latin-1 原样收字节，51 字节原文与
  `user_dialog/http_store.rs` 的 `NODE_408_RESPONSE` 同一条 Node
  `requestTimeoutResponse` 常量。

## Rust 行为

`src/pilotdeck-gateway/src/channel/sms/mod.rs`（读侧由
`HeadersTimeoutGate` 自持，hyper builder 裸跑——#2499 摘掉了
`.timer(TokioTimer::new()).header_read_timeout(..)` 那对）：

- `DEFAULT_HEADERS_TIMEOUT = 60 s`（`:91`）与
  `NODE_CONNECTIONS_CHECKING_INTERVAL = 30 s`（`:105`，注释引
  `_http_server.js` 的 `setInterval(checkConnections, 30_000)` 与
  `ts-zero-and-delayed.out` 实测）；`headers_deadline_landing`（`:1096`）
  取首个严格大于 deadline 的网格点、恰落网格点取后继（变异
  `sms-headers-grid-off` 退化为 deadline 即裁）。
- `HeadersTimeoutGate<S>`（`:1140`）包连接 IO：锚点规则
  （`arm_started_head` `:1294`——任何一次读到字节且当前头未开始即锚定
  该头自身的 deadline，首头也不例外不锚连接建立；零字节首头保持
  连接建立锚；变异 `sms-headers-first-byte-anchor-off` 退回连接锚）、
  响应结束经 `RearmBody`（`:1598`）+ watch 为下一头重设待命窗口（已
  开始的头其 deadline 骑过前驱响应的流式）、`stop()` 解除武装
  （`:1421`，变异 `sms-headers-stop-no-disarm`）、在飞响应已写过
  response head 则静默 destroy（`response_head_written`）。
- 到期三分支（`:1431-1449`）：有字节的首头 / follow-up 头与零字节
  **首**头写 `user_dialog` 的 `NODE_408_RESPONSE` 原始字节直上 socket
  （不经 hyper 响应路径——无帧化、无 header 改写、无 `Date`；变异
  `sms-headers-408-bytes-off` 摘掉字节只关）；已 served 连接上的零字节
  follow-up 头是 Node `keepAliveTimeout` 的静默关——**不复刻**（本条
  残差 2 的登记面；变异 `sms-headers-idle-followup-408` 恢复写 408 供
  负控击杀）。
- 网格锚点 = 监听器 bind 时刻（accept 循环 `grid_anchor =
  tokio::time::Instant::now()` `:669`，对应 Node checker 相位锚
  `'listening'` 事件）；`#[cfg(test)] SmsShared::test_grid_interval`
  （`:306`）是暂停时钟用例的注入点——不新增公开选项字段，生产路径
  恒 30 s。
- 头读期限与 body 读期限仍共用 `SmsChannelOptions::request_timeout`
  一个注入点（`#1955` 既有口径，012「Rust 行为」第 2 点不变）。

## 范围

仅 sms 车道请求**头**读期限的到期行为。不含：

- body 读超时的 408 字节形状与时刻（`A8.3-CH-SMS-010` / `-011`）；
- keep-alive 5 s 回收与两个 keep-alive 头的补写——本条残差 2 只登记
  「follow-up 空闲静默关发生在 60 s、Node 5–6 s、头缺失」，5 s 回收
  本身是跟进方向不是本条判分豁免；
- `stop()` drain 上限与 Err 分流（`A8.3-CH-SMS-014` / `-R1`，决策 C）；
  #2499 只把「drain 中连接的头期限被解除」对齐 Node 的
  `httpServerPreClose` 清 checker；
- 并发连接数上限、验签顺序（012「范围」原判不变）；
- 金样矩阵的量程：两新格覆盖 408 **字节**（三元组 + Rust 侧逐字节钉），
  锚点 / 网格 / 静默关时刻低于 oracle 的记录粒度（不录时刻），由
  `head_timeout_tests.rs` 的暂停时钟用例承担（见「机器判据」）。

本条不构成判分豁免：残差 1 是毫秒级确定性差（方向只可能晚 Node 的
双峰早支、从不提前于严格后继点），残差 2 是静默关时刻差——两者都不改变
任何金样格的期望字节或状态。
