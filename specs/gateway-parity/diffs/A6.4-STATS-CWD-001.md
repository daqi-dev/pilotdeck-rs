## 类别

不可避免（既有 home 来源差异，非本次引入）：Rust 只从 `HOME` 环境变量展开 `~`，TS 的 `os.homedir()` 在 `HOME` 缺失时回退到 passwd 数据库。`HOME` 缺失且 `PILOT_HOME=~` 时，Rust 得到字面 `~`、不读 cwd，构造器相对 best-effort 成功；TS 用 passwd 绝对 home 成功（路径不同）。`HOME` 缺失且 `PILOT_HOME` 未设或为 `~/...` 时，Rust 得到相对展开，cwd 被删除即返回 ENOENT，TS 仍成功。本次不引入 passwd 回退。

## 基线依据

固定基线 cc7c4e6 的 `src/pilot/paths.ts:20` 调 `normalizeHomePath`，`:98-106` 对 `~` 与 `~/...` 使用 `homedir()`（`node:os`），其余用 `path.resolve`。Node v22.22.0 实跑原 `TokenStatsCollector` 构造器与 `createRouterRuntime`：HOME 设为隔离绝对路径时，未设 `PILOT_HOME`、绝对 `PILOT_HOME`、`~`、`~/nested/../home` 在 cwd 正常与删除两种状态下均成功且 `cwdReads=0`；`HOME=""` 时 `os.homedir()` 返回空串，`~` 原样返回、未设/`~/data` 仍经 cwd 解析（矩阵已覆盖）；相对/空 `PILOT_HOME` 删除 cwd 时抛出 `Error` / `ENOENT` / `ENOENT: no such file or directory, uv_cwd` / `uv_cwd`。原始输出见本任务 `_tmp/20261026-issue-879/node-stats-probe.log` 与 `_tmp/20261026-issue-879/stats-cwd-generate.log`；持久金样为 `src/pilotdeck-gateway/tests/fixtures/stats-cwd/oracle.json`。

`HOME` 缺失时的 `homedir()` 回退为**读码推断，未实测**：安全探针会读取真实用户 home 并可能写入 `<real-home>/router`，故未运行；本条不声称已与 TS 对齐。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/model/stats.rs::default_pilot_home` 先处理裸 `~`（原样返回、不读 cwd），其余用 `expand_pilot_home` 展开 `PILOT_HOME ?? "~/.pilotdeck"`。展开结果绝对时不读 cwd；相对/空时才读，并把失败按 `node_io::diagnostic_or_unknown(..., "uv_cwd")` 转成 Node 形状的 `io::Error` 返回，不再用 `/` 伪造 cwd。`TokenStatsCollector::{new,with_clock}` 因此返回 `io::Result<Self>`；直接调用点 `router.rs::RouterRuntime::with_deps` 按错误 kind 映射为 `RouterRuntimeError { code: "ENOENT" | "EACCES" | "UNKNOWN", message }` 传播。`HOME` 缺失时裸 `~` 原样返回且不读 cwd（`normalizeHomePath` 对 `~` 不调 `path.resolve`），`~/...` 与默认值保留字面相对展开，cwd 删除即返回 ENOENT；`missing_home_keeps_tilde_literal` 钉住字面行为。

## 范围

仅 `HOME` 缺失且 `PILOT_HOME` 为 `~` / `~/...`（或未设 `PILOT_HOME` 的默认 `~/.pilotdeck`）的分支；`HOME` 已设的所有矩阵格与 TS 对齐。不覆盖 passwd 查询、不同平台 home 来源、`filePath` 的生产配置（TS 配置解析不接受 `filePath`，本包仅测试直传）。不改变健康 cwd 的路径解析。

## 机器判据

TS 金样与生成器：`src/pilotdeck-gateway/tests/fixtures/stats-cwd/{oracle.json,generate.mts}`，含源码 SHA256 与 Node 版本。Rust 22 格：`runtime::model::stats::cwd_tests::{relative,empty,absolute,tilde,tilde_child,unset,empty_home_tilde,empty_home_unset,empty_home_child,file_path,disabled}_{normal,deleted}_cwd` 逐一比对 collector 与 runtime 两个入口；差异格没有 TS oracle 行，只由 `missing_home_keeps_tilde_literal` 钉住既有 `~` 字面行为。负控 `negative_controls.py` 的 `cwd-fallback` / `absolute-guard` 必须让对应矩阵断言转红，恢复后通过。脚本仅允许默认 HEAD 且调用者设置 `CARGO_TARGET_DIR`；新增文件提交后由协调者在宿主跑。
