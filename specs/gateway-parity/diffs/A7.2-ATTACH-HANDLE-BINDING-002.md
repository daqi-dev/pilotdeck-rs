## 类别

不可避免（安全加固）。本条目是 `A7.2-ATTACH-HANDLE-BINDING-001` 所列四条已登记残余中 (1)(2)(3)(4) 的收口记录：Rust 端「合法家」判定统一到逐段 lstat、写侧租约根也走同一守卫、租约身份补内容摘要项。TS 基线没有「家」概念、没有租约硬链接身份绑定，这些拒绝面本就无对应，不改变冻结判据。

## 基线依据

固定 cc7c4e6。TS 侧对应实现：`src/gateway/client/UploadStore.ts:370-392`（`readAt` 的 realpath → 前缀检查 → `readFile`）与 `GatewayAttachmentTurnComposer.ts:125-151`（附件 lease 路径 stat/open）；两者都不区分「叶」与「祖先」链接，也没有租约条目的身份绑定。前序实测见 `_tmp/20261106-issue-1468-1494/ts-probe/`（TS 同形竞态可读出项目外字节）与 `_tmp/20261107-issue-1887/inode-probe/`（`apfs-local.txt`、`ext4-cb8.txt`、`apfs-fields.txt`、`ext4-fields.txt`、`link-apfs.txt`、`link-ext4.txt`）。inode 复用实测的原始输出另见 issue #1889 评论（comment-6693632225）。

## Rust 行为

- #1887：`src/pilotdeck-gateway/src/upload/mod.rs:1378` 的 `canonical_home` 在 canonicalize 之前，对「工程根 → 家」之间的**每一段**做 `fs::symlink_metadata`，任一段是链接或非 `Component::Normal` 拼写即返回 `None`。叶与祖先同一答案。这样 composer/写侧与 `read_at` 的词法前缀检查（`upload/mod.rs` 读侧）对「`.tmp` 被换成指向工程内的链接」判同一条结论，不再一侧 forbidden、一侧放行。`src/pilotdeck-gateway/src/native_process/services.rs:566` 的 `canonical_upload_store` 与 `:710` 的 `lease_canon` 复用同一函数（原 `services.rs` 内的局部副本删除）。
- #1888：`upload/mod.rs:1419` 的 `prepare_lease_root` 先试 `canonical_home(<project>/.tmp/chat-upload-leases)`；不是家时再要求 `canonical_home(<project>/.tmp)` 是家（即租约根的父目录本身干净）才 `create_dir`，建完重新校验；否则 `upload/mod.rs:1443` 的 `lease_root_unavailable()` 返回 `PROJECT_PATH_FORBIDDEN` + `Attachment lease root is unavailable.`。写侧不再按 `record.projectKey` 裸拼路径建链。
- #1889：`upload/mod.rs:1481`（Unix）的 `lease_link_matches` 在原 `(dev, inode)` 项之外加 `lease_link_content_matches`（`upload/mod.rs:1522`）：重读**建出来的那个租约条目**并比对其 sha256 与 `verified()` 记下的摘要，摘要空或不等即 `ATTACHMENT_TAMPERED`。非 Unix 无跨平台文件身份，该分支只保留内容项（源码注释写明）。原有身份项不重构。

## 范围

只影响本地可写工程 `.tmp/chat-uploads` / `.tmp/chat-upload-leases` 的对抗性换链、rename、同路径 delete+create。正常路径、既有错误码与 TS 可观察形状不变。新增的两条拒绝文案（`Attachment lease root is unavailable.`、附件 lease 的摘要不符）在 TS 无对应。代价是每次租约获取多一次顺序读（摘要重算），只在拿租约时发生。

仍余的窗口（逐条列明，本条目不放宽也不宣称关闭）：

1. `canonical_home` 逐段 lstat 之后、`canonicalize` 之前，把某一段换成**指向工程内**的链接：包含性项通过，因此被接受（#1887 评审 concurrency#3）。换成**指向工程外**的链接会被包含性项拒绝，且该拒绝有确定性证明（`store_root_swapped_outside_after_the_walk_is_not_a_home`，见「机器判据」）。判定依据：残留的根是叶还是祖先不影响结论，因为逐段 lstat 已把「换链」这一动作统一成同一答案。
2. **`prepare_lease_root` 最后一次校验之后、调用方写入之前换祖先**（#1888 评审 boundary#1 / concurrency#1，两家同一条）：`prepare_lease_root` 返回的是普通路径，之后每次 syscall 都重新解析它。在这个窗口里把 `.tmp` 换成指向工程外的链接，调用方的 `make_dir`（`upload/mod.rs:600`）会逐段跟随中间链接，在工程外建出 `<random>` 目录，接着 `lease.json`（`:602`/`:622`）与附件的 `fs::hard_link`（`:632`）都落到工程外——写出的是**一条完整租约**，不是空目录。下游没有任何一项会拒：那个硬链接确实是已批准 inode 的硬链接、摘要也确实相符（`lease_link_matches` 恒真），读侧只让该 turn 失败、不回收已写出的内容，TTL 清扫只走工程内 `.tmp`，工程外副本永久滞留。窗口宽度不止两个相邻 syscall（中间还有 `random_id()` 读 `/dev/urandom`）。本函数内更窄的一段（`.tmp` 检查 → `create_dir` → 建后重校验）只会留下一个空目录，那一段确实无租约写出。关闭它需要从已校验的目录句柄出发的 dirfd/openat 链式创建，与读侧的 `O_NOFOLLOW` 同族；本轮只登记，不宣称关闭。
3. upload-store 的**写侧**（`upload/mod.rs` 的 `write`/`verified` 建条目路径）没有 `canonical_home` 守卫——它只覆盖租约根与读侧根。这是 #1887 范围外的同族缺口，登记待办而非本轮修复。
4. composer 消费侧按 `(dev, inode)` 复用同一工程内的旧条目：`(dev, inode)` 相同即视为同一对象，内容项只在租约**建立**时校验，消费时不复算（#1889 实测的直接后果）。
5. `read_at` 的 `record` 身份项与 #1889 实测的关系：读侧不建租约，不用 sha256 项，仍是词法前缀 + `(dev, inode)`；本轮未改。

`verified()` 打开句柄到 `hard_link` 之间换文件的窗口仍如 `A7.2-ATTACH-HANDLE-BINDING-001` 所述（该条目已登记，本条目叠加了摘要项但不宣称关闭它）。
