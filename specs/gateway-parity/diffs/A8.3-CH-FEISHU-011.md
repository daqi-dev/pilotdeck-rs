## 类别

输入收窄（Rust 更严，未批准）。`/feishu/webhook` 解析里 `chat_id` 若为
**非字符串的真值**（`123`、`{}`、`true`），TS 的真值门放行、按该值参与会话键
拼接；Rust 只接受字符串，取不到就让该形状的解析门不成立（是否最终丢弃还看
后续形状能否匹配，见「Rust 行为」）。

## 基线依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0。

- v2 事件 `src/adapters/channel/feishu/FeishuChannel.ts:1152`：
  `if (!chatId || content === undefined) return undefined;`
- v1 事件 `:1170`：`if (!event?.chat_id || event.text === undefined) return undefined;`

两处都是 JS 真值门（`!chatId`），只排除假值；`chat_id` 的数字/对象真值不被
类型检查拦下——TS 随后把它写进 `chatId` 字段（`feishu:chat=<值>:...` 模板
拼接会把它转成字符串），事件照常入站。

## Rust 行为

- v2：`src/pilotdeck-gateway/src/channel/feishu/parse.rs:195-198`
  `string_prop_value(message.get("chat_id"))` 只在 `JsValue` 是字符串时返回值，
  非字符串真值落到 `_ => return None`，即**这一形状不成立**；`parse` 随后继续
  尝试 v1（`parse.rs:112-121`），只有 v1 也不成立时才回落到 `ParsedEvent::Ignore`
  （HTTP 仍 `200 {"ok":true}`，不入站、不产生会话键、不写 state）。因此混合载荷
  （v2 `event.message.chat_id=123`，同时带 v1 的 `event.chat_id` / `event.text`）
  仍可能按 v1 入站，本条只声明「v2 形状被这个门拒绝」。
- v1：`parse.rs:220-223` 同形。

## 范围

只涵盖 v1 / v2 两个 `chat_id` 门的**非字符串真值**这一格。空字符串两侧一致
（TS 真值门返回 `undefined`，Rust 的 `!value.is_empty()` 同形，已有用例
`empty_chat_id_is_not_a_message_in_either_event_shape` 钉住）；direct 形状
（`parse.rs:156` `string_prop(raw, "chatId")?`）两侧同形——TS 也是
`typeof raw.chatId === "string"`，非字符串两侧都拒、空串两侧都保留，**无差异**，
不需登记。
**不声称** `event_id`（v2 `!header?.event_id` 真值门）与 v1 `uuid`
（TS `??`）这两格的类型门已核：它们形式上是同类收窄，但本单未逐格实测，
登记留给后续轮次。

## 机器判据
