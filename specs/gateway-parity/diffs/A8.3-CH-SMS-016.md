## 类别

缺口已修 + 传输层呈现差异（不可避免，继承已有条目）：原缺口是 sms 车道自有
监听器**没有接** `native_http::node_parser_admission`——与 `native_http.rs`
「每个此类监听器都必须调用它」的规则相反（该注释 #1683 r3 起列出实际调用
点并注明未接线车道，#2152 前包含 sms / user_dialog，fix-r1 已同步）。缺口
在位时 `FROB` 落到 sms 路由守卫的 404、无 Host 的 HTTP/1.1 请求被放行直达
handler（对拍上答 200 TWIML）。#2152 把调用点接到
`channel/sms/mod.rs::route_request` 的最前面，拒绝响应经同一 `finalize`
出线（HTTP/1.0 请求按 `A8.3-CH-SMS-015` 回显 1.0 状态行）。本条不增加判分
豁免：新增两格是**收紧**判据；呈现差异只把既有条目的适用范围扩到本车道
（见「范围」）。补登依据：该接线与两格此前只在代码注释 / fixture README /
`_tmp/` RESULT 中自我披露，账本无条目，仓内读者会得出「该区域无已知差异」
的假象（同 `accepted-diffs.md` A7.2-ZERO-RETENTION-TIMER-001 补登依据的
口径，评审 #2152 fix-r1 P1 点名）。

## Rust 行为

`src/pilotdeck-gateway/src/channel/sms/mod.rs:1074-1078`（`route_request`
入口，`handle_request` → `finalize` 的同一出线）：

```rust
if let Some(rejection) =
    crate::native_http::node_parser_admission(&request).map_err(|_| DestroyConnection)?
{
    return Ok(rejection);
}
```

- 调用点在路由守卫（404 分支）之前；拒绝响应与全部应答同过 `finalize`
  （1.0 请求回显 `HTTP/1.0` 状态行，015 家族）。
- `Err` 是 CONNECT 的零字节断连，经**调用点** `map_err(|_| DestroyConnection)`
  映射到 hyper 既有的连接中止（fix-r1 收窄：不设 blanket
  `From<io::Error>`，未来此处新增 io 错误不会被静默变成断连）。
- 与 webhook（`channel/webhook/mod.rs:565`）、api-server
  （`channel/api_server/server.rs:440`）共用同一份 `node_parser_admission`
  实现：方法允许表、target 字节 / 形态、请求头 span 预算 16384、HTTP/1.1
  缺 `Host`、CONNECT 零字节关闭。

## 范围

- 只涉及 sms 车道自有监听器的**解析层准入**：方法允许表、target 字节与
  形态、请求头 span 预算、HTTP/1.1 缺 `Host`、CONNECT 零字节关闭。不含
  路由 / 验签 / body 上限 / 408 / 401 / 413 等既有登记
  （`A8.3-CH-SMS-001..015` 各条不变）。
- 呈现差异只把既有条目扩到本车道，不新增豁免维度：裸 400 上 hyper 补
  `content-length: 0`（`A8.4-NATIVE-HTTP-001` 第 3 项，webhook / api-server
  车道同款）；本车道裸 `http1::Builder` 的头名小写与隐式 `date`
  （`A8.3-CH-SMS-002` / `-010` 已登记的车道级帧级呈现家族）在字节钉中按
  `normalize_wire` 折叠后比较。headless 400 的 `Date` + chunked 空体与 Node
  一致，无豁免。
- 两格只钉 bare 400 与 headless 400 两条路径；超预算 431、非 ASCII target
  等其余解析层形态无本车道专属格，由同一函数的 `native-http-basic` 金样
  与共用实现承担（同 `A8.3-API-SERVER-005` 的口径），本条不声称本车道逐格
  覆盖了它们。
