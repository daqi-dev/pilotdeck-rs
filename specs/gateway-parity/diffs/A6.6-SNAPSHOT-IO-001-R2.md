## 类别

对既有登记条目的更正（两处）：① Rust 侧 host boundary 覆盖面补全——`created_at()` 的时钟失败臂此前仍是 `io::Error::to_string()` 的 Rust Display；② R1 的「机器判据」段所写变异名 `IO_ERROR_ARM`/`TWO_PATH_ARM`/`UUID_DISPLAY` 与实发变异名不符，本条目给出正确映射。

## 基线依据

原条目 `A6.6-SNAPSHOT-IO-001` 与其 R1（原字节冻结）。TS 基线不变：`new Date()`（cc7c4e6 `src/storage/workspaceSnapshot.ts` 的 manifest `createdAt`）永不失败，故 Rust 时钟失败臂无 TS 对应物，属宿主边界（node_io.rs 既有约定：表外 errno 与不可映射失败走 `code: None` + 空消息，不把 Rust Display 写上协议线）。sibling#2 评审同时点名的 `resolve()` 与（已随结构删除的）`write_file_identified()` 的 `e`：二者为 `WorkspaceSnapshotError`，其 Display 即 node_io 文案或空串，非 Rust Display 泄漏，不属本条目范围（依据 `two_path_message_uses_the_shared_diagnostic` 的空串臂断言）。

## Rust 行为

`src/pilotdeck-gateway/src/storage/workspace_snapshot.rs`：`created_at()`（函数名锚点）的 `timestamp()` 失败臂改为 `host_boundary_io().to_string()`——`WorkspaceSnapshotError::Io { code: None, message: String::new() }`（与 R1 已登记的 `io_error`/`two_path_message` 表外回退、`random_uuid` 失败臂同形）。该文案只进 `_FAILED.json` 的 error 字段/捕获结果的 `error`，投影侧按 `NODE_IO_REQUIRED` 宿主边界呈现，与 R1 的回退形状一致。

## 范围

仅 `created_at()` 的失败臂文案形状；成功路径（ISO 毫秒字符串）、表内 errno 文案、JSON 语法错误行为不变。R1「机器判据」段的名称更正：实发变异为 `host-boundary-rust-display`（覆盖 R1 所称 `IO_ERROR_ARM` 与 `UUID_DISPLAY` 的空消息断言面——把 `host_boundary_io` 的空串换成 `"host io failure"`）与 `two-path-no-suffix`（R1 所称 `TWO_PATH_ARM`，去掉 `-> '<path>'` 后缀断言）。R1 所称 `UUID_DISPLAY` 无同名可绑变异：uuid v4 取自 OS 随机源，测试运行中该失败臂不可达（无法以运行时变异证伪），其 host-boundary 形状由 `host-boundary-rust-display` 对 `host_boundary_io` 本体的断言间接钉住；读 R1 段者应以本映射为准。`random_uuid` 失败臂本身（`capture` 派生 staging 时经 `host_boundary_io`）不变。

## 机器判据

`src/pilotdeck-gateway/src/storage/workspace_snapshot.rs` 内部测试 `two_path_message_uses_the_shared_diagnostic` 断言表外 errno 为 `code: None` + 空消息。`tests/fixtures/workspace-snapshot-gate/negative_controls.py` 的 `host-boundary-rust-display`、`two-path-no-suffix` 要求 KILLED（本轮 12 变异全部编译验证通过，全量负控归协调者提交后跑，见 `_tmp/20261026-issue-293/fix-r2/negative-check/`）。复算：`cargo test -p pilotdeck-gateway --locked --offline --lib snapshot`。
