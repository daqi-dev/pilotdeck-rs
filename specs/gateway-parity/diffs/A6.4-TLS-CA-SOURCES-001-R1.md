## Rust 行为

#1552 后 `runtime/model/http/tls.rs` 的模式来自 `NODE_OPTIONS` 分词：`--use-bundled-ca` 优先于 `--use-openssl-ca`，缺省 `Default`。`Default` 与 `Openssl` 读显式 `SSL_CERT_FILE` 与 OpenSSL hash 命名的 `SSL_CERT_DIR`（文件名须为八位小写十六进制 + 单索引位 `.0`..`.9`，排序后逐个加载；`SSL_CERT_DIR` 按路径列表逐个目录读）；`Bundled` 不读这两者；`NODE_EXTRA_CA_CERTS` 在所有模式追加。OnceLock 一次性快照不变。原文剩余差异第 4 条（bundled 根数据版本）仍保留。

按源码构建口径，`dir-unflagged` 上 Rust 会比 TS 多信任该目录（TS false / Rust true），属扩大信任集合而非对齐；按 Homebrew 口径则是对齐。处置随 #1640 的口径裁决，本条仍为未批准差异。

## 残余差异（本轮实测确认，未处理）

- `--use-openssl-ca` 下 Node 用 OpenSSL 库**替换** bundled Mozilla 根，Rust 因红线不读宿主原生信任库而**保留** bundled 根，故该模式信任集合是 Node 的超集。
- hash 目录只按文件名形状筛选（八位小写 hex + 单索引位 `.0`..`.9`），不校验文件名 hash 是否等于证书 subject hash；与 subject hash 不符的条目 Rust 会信任而 OpenSSL 不会打开。
- `SSL_CERT_FILE` 按单路径读取；OpenSSL 是否接受冒号分隔的文件列表未实测，故未实现。
- 冲突旗标（`--use-bundled-ca` 与 `--use-openssl-ca` 同给）取 bundled，Node 的真实语义未实测。
- `MAX_CA_FILE_BYTES = 8 MiB` 是本项目自定的上界，Node 无对应限制：超过上限的合法 CA bundle 被跳过，Rust 的信任集合**小于** Node。选这个值是为了避免在进程级 `OnceLock` 快照里无界读到 FIFO / 设备 / 增长中的文件。
- `SSL_CERT_DIR` 按路径列表读取是本项目的选择；OpenSSL 是否把 `SSL_CERT_DIR` 当列表而非单个目录，未在基线上实测。
- hash 命名要求 8 位小写十六进制（SHA-1 形态）；若某发行版的 `c rehash` 产出 64 位名（SHA-256），整个目录会被忽略。未实测。
- 「非普通文件跳过」分支与 `open_ca_file` 的 `O_NONBLOCK` 只有正控（hash 命名的目录条目会在读时失败），**没有可杀负控**：造一条能杀掉该守卫的用例需要 FIFO 加写者参与，时序不确定，本轮未做（P2-跟进 #1654，前置于 A6.4 差异族关闭节点）。

`NODE_OPTIONS` 作为载体已实测：本轮在基线 `cc7c4e65` 上以 `NODE_OPTIONS=--use-openssl-ca` 采 `openssl-dir` 得四客户端全 true，而同一基线默认模式下 `SSL_CERT_DIR` 不生效（见上文 `dir-unflagged` 全 false），说明 Node v22.22.0 接受该旗标经 `NODE_OPTIONS` 传入。
