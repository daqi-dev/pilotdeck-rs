## 类别

对既有登记条目的更正：R2 引入的两处缺陷按 r3 评审修复——① 非空目标的 fallback 发布先 rename `_COMMITTED` 再 rename manifest，第二步失败留下「有 marker 无 manifest」的半提交，早退只看 `exists(_COMMITTED)`，此后每轮永久误报 Committed（两家评审独立命中）；② 每轮收尾对共享 `<root>/.staging` 父目录的「尽力 remove_dir」与另一轮 `create_dir_all` 的两阶段（建父 → 子目录单次重试）竞态，ENOENT 被当作捕获失败落永久 `_FAILED.json`（两家评审独立命中）。

## 基线依据

原条目 `A6.6-SNAPSHOT-CLEANUP-OWNERSHIP-001` 与其 R1、R2（原字节冻结）。TS 基线不变（cc7c4e6 `src/storage/workspaceSnapshot.ts`）。既有实测继续有效：probe-c（Node v22.22.0，`_tmp/20261026-issue-293/fix-r2/probe-c.out`）c6 —— partition 预置 `keep.txt` + `manifest.json` 为目录时，真实 TS recorder 的发布顺序就是 manifest 先（其失败 rename 是 `.tmp-*/manifest.json -> partition/manifest.json` 的 EISDIR），落 `state: failed`、分区无 `_COMMITTED`、写 `_FAILED.json`；修后 Rust fallback 顺序（manifest 先、marker 最后）与该实测一致，R2 登记的偏离②（fallback marker 在先的残留）随之消除。`.staging` 父目录竞态：std 1.99 `DirBuilder::create_dir_all`（本机 rust-src `library/std/src/fs.rs`）沿 ancestors 自深向浅 mkdir 至成功，再对缺失目录逆序单次重试；父目录在两阶段之间被删则子目录重试 ENOENT——有界复现见机器判据。本轮无法运行新 TS 探针（基线 cc7c4e6 不在本机会话可达的任何工作树、`PDRS_BASELINE` 未设），涉及 TS 早退语义的结论均为读码推断或引用既有 probe 原始输出，未新增实测。

## Rust 行为

`src/pilotdeck-gateway/src/storage/workspace_snapshot.rs`：早退检查（`capture_once`）改为同时要求 `_COMMITTED` 存在且 `manifest.json` 为普通文件（`is_file()` 结构性可读，与 `list()`「有 manifest 才列出」同口径；不 parse——早退不因 manifest 内容失败）；`publish_staging`（函数名锚点）的 fallback 逐文件发布顺序改为 manifest 先、`_COMMITTED` 最后（marker 是提交点；其 rename 源本就是 staging 内同目录文件）。失败或中断的后果：manifest 已落而 marker 未落 → 下一轮按未提交处理并重发覆盖；marker 无 manifest（仅手工预置/外部写入可造，本轮自身顺序不再产生）→ 不早退，重采集重发布。`failure_cleanup` 与 `commit` 成功尾**不再删除 `.staging` 父目录**：只删本轮（已空的）staging 子目录；父目录常驻（根级 walk 已跳过，空置无害）。已知残留：进程在 staging 写入后、发布前被 kill 的 `.staging/<uuid>` 目录无回收（无活跃性判据，按目录年龄删除被 r3 评审明确排除），登记为已知泄漏（非不一致；见范围）。

## 范围

R2 偏离清单更新：②（fallback marker 在先的半提交残留）消除——顺序与 TS 实测（probe-c c6）一致；中断于两次 rename 之间残留无 marker 的 manifest，与 TS 中途态同形，下一轮覆盖。③ 改写为：`.staging` 父目录常驻不删（空置为设计而非泄漏）；崩溃遗留 `.staging/<uuid>` 仍无回收（r3 评审 P2，未修：安全的活跃/死亡轮判据需要租约或锁设计，超出本轮；按 mtime 清扫会误删慢轮）。新增偏离：早退的提交判定要求 manifest 同时在（TS 只看 marker，读码推断；TS 自身写序不留该残留，仅影响手工预置分区）。①（根级忽略 `.staging`）与④（占用目标 last-writer-wins）不变。

## 机器判据

`src/pilotdeck-gateway/tests/workspace_snapshot.rs`：`fallback_publish_writes_the_manifest_before_the_committed_marker`（原 M6 改写：预置 manifest 目录触发 EISDIR，断言无 `_COMMITTED` 落位、预置内容存活、第三轮经 `_FAILED.json` 早退为 Failed——修前该测试在其「marker 未发布」断言失败，即 r3 P1-A 有界复现）；`orphan_committed_marker_without_a_manifest_recaptures`（marker-only 残留重采集重发布 + manifest-only 残留被覆盖）；`staging_parent_survives_round_settlement`（成功与失败两种收尾后父目录在且空）。lib 内部：`removing_the_staging_parent_between_mkdirs_fails_the_round`（P1-B 有界复现：std create_dir_all 两阶段拆开，父目录被删则子目录重试 ENOENT 及 Node 消息形状）、`commit_publishes_the_staging_directory_atomically` 与 `failing_round_cleanup_removes_only_its_own_staging`（断言改为父目录在且空）。回放装置：`no_temporaries` 断言 `.staging` 无残留子目录（比旧「不存在」更强）；`record_tree` 在树根跳过 `.staging`（oracle 树是 TS 视角，与偏离①同口径）。负控 `tests/fixtures/workspace-snapshot-gate/negative_controls.py`：`fallback-order`（改绑「marker 是提交点」断言）、`fallback-drops-manifest`（只替换 manifest rename 一段）、新增 `early-exit-marker-only`、`cleanup-removes-staging-parent`、`commit-removes-staging-parent`，连同既有 `cleanup-unconditional-delete`、`staging-listed`、`staging-leak`、`publish-noop` 等要求 KILLED（变异表以本文件登记为准；全量由协调者提交后在宿主跑）。复算：`cargo test -p pilotdeck-gateway --locked --offline --test workspace_snapshot`、`--lib workspace_snapshot`（本会话已实跑通过；全仓 `--workspace` 由协调者跑）。
