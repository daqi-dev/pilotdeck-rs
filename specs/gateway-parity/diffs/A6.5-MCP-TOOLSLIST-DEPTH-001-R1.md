## 机器判据

同原条目（TS 金样、Rust 复算原件、「复算不覆写原件」通则均沿用），本更正新增 / 更正三点：

1. **复算硬判据（r2 补；r3 收紧内容校验与 rc 采集）**：复算命令用 `probe_1754` 过滤到单测试
   （`cargo test --offline -p pilotdeck-gateway --test mcp_client probe_1754 -- --nocapture
   --test-threads=1`）。该过滤器只在打过 `rust-probe.patch` 的树上存在，未打补丁时 0 命中且
   cargo 退出码 0（真空通过），故复算日志必须**同时**满足以下全部方可记「已复算」，任一不满足
   一律记「未复算」、不得记通过：
   - 含 `running 1 test`（`0 tests matched` 即未复算）；
   - `PROBE depth=` 行恰 6 条，depth 集合恰为 {255, 256, 257, 300, 399, 400}；
   - 逐条结论与写死的期望一致：`depth=255` 行为 `ok(2)`；depth 为 256 / 257 / 300 / 399 / 400
     的行各为 `err(` 且逐字含 `schema nesting is deeper than this port supports (256)`；
     各条均 `status=ready`。（`ok(2)` 证 `good` + `deep` 两工具都被返回；`supports (256)`
     钉住常量与 `>=` 比较符——改 257 / 改 `>` / 常量下调都会露馅；错误包络前缀与 `code=`
     形态不钉，理由见「Rust 行为」第 3 点。）
   - rc=0，且 rc 采集不经管道吞掉：`cargo … | tee <log>` 之后取 `$?` 是 tee 的退出码，不作数
     ——落盘用临时文件重定向，或 bash `PIPESTATUS[0]`（zsh 为 `${pipestatus[1]}`、1 起）。
   - 复算输出落 `_tmp/<本轮>/` 新目录、**独占创建**的文件名（`mktemp` / `set -C` 或等价的
     open(…, `O_EXCL`)：已存在即失败，绝不覆盖），不写回 `rust-probe.log`、不 `tee` 到任何
     已有路径；rc 与日志必须来自**同一次**调用，重跑 / 复盘一律换新文件名，先前 attempt 的
     原文不可被后续 attempt 覆盖（standing rule
     `state/memory/20261016-evidence-write-guard.md`，#589 三例；源：PR #2226 评审
     DS concurrency#2）。
2. **durable 钉子与负控仍缺**（跟进单 #2232，前置于 A6.5 批次复核）：边界档必须取
   **256 正控（整单拒绝，错误文案含 `supports (256)`）/ 255 负控（接受，断言 `ok(2)`）**，
   夹具须含至少一个合法工具（照 `rust-probe.patch` 的 `good` + `deep` 双工具构造，否则
   256 档的 `Err` 区分不了「整单拒绝」与「仅该工具失败」）；档位构造逐字照 patch 的
   `nested(depth)`（depth 层 `{type:"object",properties:{x:…}}` 包住**对象**叶子
   `{"type":"string"}`）。叶子类型影响：只有**布尔**叶子使 `check` 对该层 `Ok` 早退、
   边界整体移一格（`depth` 只在对象层 +1）；裸字符串 / 数字叶子在 properties 守卫处先被判
   `properties value must be ["object","boolean"]`——不是早退，也不是
   `schema must be object or boolean`（后者只在 `check` 直接收到非对象（根 / `$ref` 目标）
   时出现）。每档必须**新建 `McpClient`**（照 patch 每档 `race_client` 的做法）或断言前清空
   `list_tools_cache`（r4 补，源：PR #2226 评审 DS concurrency#1）：`list_tools` 命中 5 min
   TTL 缓存（`client.rs:1077-1080`）时直接返回旧成功列表、`check_schema`（`:426`）不执行——
   复用同一 client 的 255→256 顺序会观测到 stale `ok(2)`，256 正控落空。其余深度档只取
   冷进程实测点，不用 258–299 与 301–349 未测档、不拿暖梯档当冷进程上限，
   300 只作「远高于阈值仍整单拒绝」附加档。
3. 原条目「机器判据」末行「补端到端钉子 + 负控须另开跟进单，前置于本条从『待批』转
   『已接受』」的排序按本次人拍废止（人拍原文未含该条件）：本条登记即日生效，钉子转 #2232
   跟进（排序解读与「待人复核」标注见决策卡「状态」条）。
