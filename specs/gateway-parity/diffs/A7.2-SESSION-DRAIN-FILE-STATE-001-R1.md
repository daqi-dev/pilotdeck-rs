## 类别

#1022 fix-r1 bug 修复：更正原条目只覆盖成功 drain、排除全部已 disposed 前驱的范围；失败重试也不得丢失已保存的文件读状态。

## 基线依据

cc7c4e6 / Node v22.22.0：`session-factory/followups.mts` 新增真实 stdio `dispose-throw`，工具 gate 未释放时 snapshot 只有 seed.txt；drain 后包含 during.txt，配置 disposer 抛 DISPOSE_1022 后 handle 仍 Disposed、scope 释放。金样 `oracle.json.followups[2]`；原始证据 `_tmp/20261026-issue-1022/fix-r1/ts-generation/followups-raw.json`。TS 整个 ProjectSessionFactory + SessionRouter 重试组合仍为读码推断，未实测，不宣称端到端对齐。TS 无 Rust future 取消和 panic payload，对应格不适用。

## Rust 行为

`handle.rs::recreation_snapshot` 成功后登记 retained source 资格，owner 不再过滤这类已 disposed 前驱。`factory.rs::construct` 在本次快照之前采样已完成重建 drain，首次 dispose 错误仍返回；再次尝试从保留 source 读取最终 file_state，不重复返回已经报告的 dispose 错误。`owner.rs::create_active` 发布后同样不重复传播这条旧错误。只有 Disposed 且 activity 已归还才允许此重试；提前外部 dispose 或 cleanup panic 后 activity 仍在均不能放宽。

## 范围

仅仍缓存于同一 owner dirty record、已成功通过 recreate eligibility 的前驱。覆盖 dispose 错误、fence 超时后后台 drain 完成、最终 seed 读取失败；同一路径也保留后续 storage/setup 失败的前驱 source。显式 close、idle eviction、shutdown 移除缓存不在恢复承诺内。耐久 messages/sequence 仍只从 storage.restore 恢复。未获得资格的 disposed 快照继续拒绝。
