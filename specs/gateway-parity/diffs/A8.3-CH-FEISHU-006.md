## 类别

不可避免（A7 端口字段面与客户端看门狗未移植）。TS `submitTurn` 的下发
参数里除 `sessionKey`/`channelKey`/`message` 外还有 `allowPlanModeTools:
false`、`mode`/`basePermissionMode`（配置了 `permissionMode` 时）、
`timeoutMs`、`projectKey` 与 `attachments`；Rust 的 `TurnRequest` 只有前三个
字段，其余在端口层就不存在。此外 TS 在通道内自带 `turnTimeoutMs`
（默认 600 000 ms）看门狗，到期 `markTimedOut()` 并 `abortTurn(reason:
"system:timeout")`；Rust 侧没有这个看门狗。`explicitSend` 构造缝
（TS `options.send`）也未移植——它是测试/嵌入式替换发送实现的钩子，
`sendTextMessage` 首分支。

## 基线依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0。
`src/adapters/channel/feishu/FeishuChannel.ts:583-593`：

```ts
this.gateway.submitTurn({

  allowPlanModeTools: false,

  ...(turn.projectKey ? { projectKey: turn.projectKey } : {}),
})
```

`:568-581` 看门狗（`turnTimeoutMs = this.liveReplyOptions?.turnTimeoutMs ?? 600_000`，
`markTimedOut()` + `abortTurn({reason:"system:timeout"})`）；
`:137-138`、`:177`、`:824-832` `explicitSend` 字段、构造与首选发送分支。

## Rust 行为

- `src/pilotdeck-gateway/src/channel/protocol.rs:85-89` `TurnRequest` 只有
  `session_key`/`channel_key`/`message`；`mod.rs:856-862` 按此构造，
  `QueuedTurn.project_key`（`mod.rs:206`、`:737`）虽然保存了但不下发；
- 无 `turnTimeoutMs` 看门狗：`mod.rs:869-934` 的事件循环没有超时分支，
  也没有 `system:timeout` 的 abort（与 `A8.3-CH-FEISHU-004` 的 abort 缺失
  同源，但这里是**通道自己的**看门狗，TS 不依赖 gateway 端口提供超时）；
- `explicitSend`：`mod.rs:984-986` 注释写明「the TS `explicitSend` seam has
  no production caller, so the raw text send is the whole path here」，
  发送恒走 `ApiClient`；
- 因此 `permissionMode` 配置（`mod.rs:117` 附近的选项解析保留该字段）不会
  影响下发的 turn 参数，agent 侧收不到 `mode`/`basePermissionMode`。

## 范围

仅 feishu → gateway 的 turn 下发参数面与通道侧看门狗/发送钩子：
`allowPlanModeTools`、`mode`/`basePermissionMode`、`timeoutMs`、`projectKey`、
`attachments` 五个字段不透传；无 600 s 通道看门狗与 `system:timeout`
终态；无 `explicitSend`。不覆盖 `/new` 的 abort（另一条目）、不覆盖
gateway 侧自身的超时（若存在）。本条不构成判分豁免；**风险点**：
`timeoutMs` 缺失意味着 Rust 侧 turn 不因通道看门狗被终止，长跑 turn
可能比 TS 更久。

## 机器判据

- `src/pilotdeck-gateway/src/channel/feishu/tests.rs` 用假 `TurnGateway`
  捕获实际下发的 `TurnRequest`，钉死当前字段面（`session_key` 形状
  `feishu:chat=<id>:s_<uuid>`、`channel_key == "feishu"`、`message` 原文），
  防止悄悄多/少字段；
- 超时与 `explicitSend` 无判据；端口扩字段或补看门狗时须同步新增用例
  （含「到期后不再收事件、不发终态」）并改本条目。
