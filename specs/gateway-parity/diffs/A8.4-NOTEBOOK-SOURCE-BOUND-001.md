## 类别

有意改进：给Notebook JSON解码前的源读取设置64 MiB（67108864字节）上限，并让read_file、edit_notebook的实际输入和快照读取共用同一有界helper。AI判定依据：只限制展示文本或JSON解码后的数据无法避免先分配完整源；验证与执行分别重读有可能绕开单次检查，故所有实际读取点共用helper。64 MiB与媒体源保护保持一致，是已授权资源保护范围内可撤回判断，不是TS原限制，不保证JSON对象/渲染后总内存或CPU上限。

## 基线依据

固定 TS `cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85`，`resources/PilotDeck/src/tool/builtin/filesystem/readNotebook.ts:28` 全量UTF8读取再JSON.parse；`readFile.ts:447`调用它，`:461`再全量读取原文存write snapshot。`editNotebook.ts:346` 的readNotebookJson也全量读取，不设64 MiB限制。基线源码是该新增保护的直接依据；本轮未实跑TS >64 MiB有效Notebook，不声称已有对应TS金样或全生产Server对拍。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/tools/builtin/notebook_input.rs:6` 定义上限，`:22` helper：对合法普通alias解析后的目标检查大小，打开后再核普通文件、大小与Unix(dev,ino)一致性，以take(67108865)限制实际源字节；>67108864返回TooLarge。`read_file.rs:986`，`edit_notebook.rs:437`快照和`:466`JSON读取均调用它；TooLarge统一映射为 `result_too_large` / `Notebook source exceeds the 64 MiB input limit.`。已有缺失文件、JSON语法、未读不能编辑与二进制错误按各入口原顺序/映射保留。目录特意保留原生目录读取IO错误，不能把它写成新的invalid_tool_input保护差异。

## 范围

涵盖Notebook源字节读取，包括read_file渲染输入及edit_notebook验证、执行、快照路径，避免快照重读绕过64 MiB；输出快照/修改写入算法不改。合法普通文件symlink仍可读。已有非普通特殊输入由NotRegular映射invalid_tool_input，目录按原生IO路径处理；不增加任何文件权限。Unix前后(dev,ino)不一致检测只是已有局部检查，不宣称消除父目录或所有并发替换窗口；本轮不设计权限竞态测试。等于64 MiB不因源大小拒绝是代码条件，JSON语义及输出预算仍可能拒绝，运行时边界未覆盖不冒充通过。
