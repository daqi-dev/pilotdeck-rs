## 类别

不可避免（当前 Rust 存储错误类型边界）：复用原生 io::Error，不伪造 Node Error 的完整形状。

## 基线依据

cc7c4e6 `src/session/persistence/JsonlSessionPersistence.ts:20-37` 在父路径为普通文件时 reject Node Error；直接 import probe 实测 code=EEXIST，message 含 syscall mkdir 与路径。见 `src/pilotdeck-gateway/tests/fixtures/project-persistence/oracle.json` 的 appendError/appendMessage；原始输出 `_tmp/20261025-issue-587-pkg2/ts-probe-6.log`。

## Rust 行为

新资源入口复用 `storage/transcript_adapter.rs` JsonlTranscriptStore，向调用者返回 RecorderError::Store(LedgerError::Io)，Display 为 Rust OS 错误文本，不具有 Node 的 code/syscall/path 属性。错误不吞掉、不推进序列，路径修复后可重试。

## 范围

仅事件持久化 host IO 错误的表示，不改变 JSONL bytes、状态提交次序或 snapshot 已有 Node 错误映射。此错误不得直接标为完整 TS wire error 等价。

## 机器判据

`persistence_append_failure_does_not_commit_and_same_instance_retries` 使用真实阻塞路径检查错误类型、零序列、恢复与中途失败；`targeted-3.log` 保留 Rust Debug/Display。TS probe 同场景独立采集。
