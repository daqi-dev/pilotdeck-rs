## 类别

运行时容错差异（待批）：#1339 的 sms channel webhook 收到 JSON 参数
`Body` 为非字符串（数字等真值）时，TS 的 `body.trim()` 抛 `TypeError`，
真实进程无兜底会崩溃（200 TWIML 已先写出）；Rust 侧同一异常被连接任务
包含并经 `record_unhandled` 回调上报，进程继续服务。金样里的
`unhandled` 记录是生成器 harness 的进程级处理器产物，不等于 TS 生产
行为。

## TS 依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0 /
ICU 78.2。`_tmp/20261026-issue-1339/probes/sms-edges.out` 的
`--- json number body ---` 实测：应答 200 TWIML 字节完整写出后，异常以
进程级未捕获形式出现（`unhandled: ["TypeError: body.trim is not a
function"]`）；真实部署没有该处理器时 Node 以 uncaughtException 终止。
`SmsChannel.ts` 派发路径对 `body.trim` 无 try/catch。

## Rust 行为

`src/pilotdeck-gateway/src/channel/sms/mod.rs` `handle_request`：非字符串
`Body` 分支先取 `record_unhandled` 回调记录
`"TypeError: body.trim is not a function"`，再返回同一个 200 TWIML 应答；
进程与其余连接不受影响。回调和注入点由 `SmsChannelOptions` 提供，
生产挂载（`register`）当前为 `None`（静默丢弃，见 A8.3-CH-SMS-004）。

## 范围

仅 webhook 非字符串 `Body` 的派发异常路径；JSON 解析失败（400 `Bad
Request`）、表单解析、`From` 空 / body 空白的早退分支不在本条。
goldens 与 Rust 回放的 `unhandled` 内容逐字节一致，差异只在进程存活。

## 机器判据

`src/pilotdeck-gateway/src/channel/sms/tests.rs`：oracle 用例
`non-string-json-body` 重放断言 `unhandled == ["TypeError: body.trim is
not a function"]` 且 `responses` 为 200 `text/xml` TWIML；
`replay_cases!` 全表由 `negative_controls.py` 的 11 个编译期开关配对，
任一行为漂移被对应 KILLED 开关击落。
