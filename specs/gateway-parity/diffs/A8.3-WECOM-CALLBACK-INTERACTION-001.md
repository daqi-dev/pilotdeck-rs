## 类别

不可避免（共享交互 helper 未移植，生产装配传入 `NoInteraction`）。与
`A8.3-CH-FEISHU-008`（feishu）、`A8.3-CH-BLUEBUBBLES-002`（bluebubbles）同一缺口在
wecom-callback 车道的登记：TS 的企微回调通道把 gateway 的 elicitation /
permission 请求变成企微消息发给用户，把用户在同一 chat 的下一条文本当作答复交回
gateway；Rust 侧 `InteractionPort` 的编排（待答复期间的入站分流、答复记账）已移植，
但 #2301 的生产挂载传入 `no_interaction()`——提问不投递、答复不捕获。

## TS 依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85（只读），Node v22.22.0 / ICU 78.2。
`src/adapters/channel/wecom-callback/WeComCallbackChannel.ts:95-96`（`new
ImElicitationHelper()` / `new ImPermissionHelper()`）、`:216-247`（入站消息先查
`elicitation.hasPending` / `permissions.hasPending`，待答文本走 `answer` /
`answerWithState` 而非新 turn，含 `answerToken` 释放、多问题排队
`takeNextPrompt` / `confirmNextPrompt`）；helper 本体在
`src/adapters/channel/protocol/`（`ImElicitationHelper` / `ImPermissionHelper`），
由 wecom-callback 与 feishu 共用（`A8.3-CH-FEISHU-008` 同引）。

## Rust 行为

`src/pilotdeck-gateway/src/native_process/channels.rs:119-124`
`production_loader_mounts()` 的 wecomCallback 挂载：
`WeComCallbackChannel::constructor(crate::channel::wecom_callback::no_interaction())`
（`channel/wecom_callback/mod.rs` 的 `no_interaction()` 返回共享的 `NoInteraction`
实现——`elicitation_pending` / `permission_pending` 恒 `false`、capture 返回空 /
`None`）。通道侧编排（`WeComCallbackChannel` 的 `Runtime` 分支）已按 TS 接好，
但生产装配下永远走不到待答分支；缺 corpId / token / encodingAesKey 时的
`wecom_callback: corpId, token, and encodingAesKey are required` 可见失败形态
不受影响（经 `console_channel_log` 走 stderr）。

## 范围

仅 wecom-callback 生产装配的交互 helper：elicitation / permission 的提问投递、
答复捕获、确认与排队。行为后果：需要权限确认或 elicitation 的 turn 在企微侧
既无提示也无答复（该 turn 走 gateway 自身的超时 / 中止路径），与
`A8.3-CH-FEISHU-008` 描述的后果同构。不覆盖：通道侧编排（已移植、无生产判据）、
feishu / bluebubbles 的同名缺口（各自条目）、wecom-callback 的 HTTP 回调面与
#1941 body 上限（已接，PR #2033）。
