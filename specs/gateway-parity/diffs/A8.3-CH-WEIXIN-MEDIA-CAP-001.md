## 类别

有意改进（防资源放大 · 向严）。基线 `ImAttachmentStore.saveFromUrl` 先把整个
响应体 `arrayBuffer()` 进内存，再拿真实字节数比 50 MiB 上限；Rust 侧在读流的
每一帧上封顶，越过 50 MiB 立即停止。拒绝超限附件的**端到端可观察结果不变**，
变的只是「不声明 `content-length` 的超大响应」在拒绝前会占多少内存。

## 基线依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0（undici
fetch）。`src/adapters/channel/protocol/ImAttachmentStore.ts:62-73`：

1. `:62-65` 先读 `content-length` 头：`Number(...)` 且 `Number.isFinite` 后
   `> maxBytes` 直接抛 `Attachment is <n> bytes (limit <max>).`；
2. `:67` `Buffer.from(await response.arrayBuffer())` 全量缓冲；
3. `:71-73` 缓冲完再比 `buffer.byteLength > maxBytes`，同样报
   `Attachment is <n> bytes (limit <max>).`。

即：**声明**了超限长度的响应在读 body 前就被拒；**未声明**长度的响应，
基线要先把整个 body 读进内存才知道它超限。

金样格 `media-cdn-download-declared-too-large` 钉的是第 1 条（声明
52428801 → 读 body 前拒绝，错误串逐字一致），与 Rust 侧相同，不是本条目范围。

## Rust 行为

`src/pilotdeck-gateway/src/channel/weixin/media.rs` 的 `WeixinCdnClient::download`
用共享 `crate::fetch_redirect::read_body`（`media.rs:439` 起）逐帧读，累计
`buffer.len() + frame.len() > 50 MiB` 时立即 `BodyError::TooLong`，映射为
`Attachment is 52428801 bytes (limit 52428800).`——报的是**必然已到达的最小
超限字节数**（上限 + 1），而不是基线的真实总长度。声明长度检查
（`finite_js_number` + `> limit`）与基线第 1 条一致，先于读 body 执行。

## 范围

只影响「响应没有 `content-length`（或该头不可解析/非有限），且实际正文 >
50 MiB」这一种响应：

| 场景 | TS 表现 | Rust 表现 | 用户感知 |
|---|---|---|---|
| 声明长度 ≤ 50 MiB，正文也 ≤ 50 MiB | 成功落盘 | 成功落盘 | 无差别 |
| 声明长度 > 50 MiB | 读 body 前拒绝，错误串带声明的精确值 | 同左 | 无差别 |
| 无 `content-length`，正文 ≤ 50 MiB | 成功 | 成功 | 无差别 |
| 无 `content-length`，正文 > 50 MiB | 先吃下整个 body（内存无上界），再拒绝，错误串带真实字节数 | 到 50 MiB + 1 字节即停止并拒绝，错误串固定为 `52428801` | 都被拒；Rust 更快、内存有界，错误串里的字节数是下界而不是真实值 |

不改变：声明长度检查的判定（含 JS `Number` 的 hex/`Infinity` 语义）、
`response.ok` 检查、重定向策略、60 s 取头期限与正文的 undici 默认
`bodyTimeout`。附件落盘（路径、文件名、metadata）属 #1822，不在本单。

## 机器判据

`src/pilotdeck-gateway/src/channel/weixin/media/tests.rs` 的
`the_received_body_is_capped_at_the_limit`：脚本化 loopback 服务端不声明
`content-length`，直接推 50 MiB + 1 字节，`download` 必须返回
`Error: Attachment is 52428801 bytes (limit 52428800).`。

负控 `tests/fixtures/weixin-channel/negative_controls.py` 的
`media-download-received-cap-removed` 行把 `read_body` 的上限改成
`usize::MAX`，该用例必须红（会尝试读满 50 MiB + 1 字节并成功返回），
`KILLED` 原始输出见 `_tmp/20261107-issue-1823/`。
