## 类别

不可避免（运行时机制差异 + 传输层呈现差异）：sms 车道请求**头**读期限
（Node `headersTimeout` 等价，60 s）到期时的**线上字节、触发时刻与空闲
keep-alive 回收**。三个残差同源于一处机制——本单在连接上装了
`.timer(TokioTimer::new()).header_read_timeout(60 s)`——因此合并登记一条，
不拆成三条。四条具体残差：

1. **线上字节**：Node 到期写 51 字节 `HTTP/1.1 408 Request Timeout\r\n
   Connection: close\r\n\r\n`；hyper 的头读超时从 `serve_connection` 返回
   `Err(HeaderTimeout)`，**一个字节都不写**就关连接。hyper 1.7.0 没有「超时后
   由我写响应」的公开入口——超时发生时连接的所有权在读头路径里，handler 还没
   被调用，`http1::Builder` 也没有超时回调；兄弟车道
   `wecom_callback`（`A8.3-WECOM-CALLBACK-KEEPALIVE-001`）与
   `http_proxy` native 车道装的是同一副 timer，行为相同（`accepted-diffs.md`
   的 http_store 一条也只主张「被关闭」、不主张字节）。
2. **触发时刻**：Node 的 60 s 到期由 30 s 一次的 connections checker 裁断，
   实测落在 deadline + 30 s（90,004 ms 首字节与 EOF 同时到达）；Rust 的
   tokio 定时器到期即裁（实测 60.02 s 关闭）。起算点近似相同（Node 自请求首
   字节、hyper 自 accept 后首次 poll 读头），差异是裁剪方式：Rust 比 Node 早
   0–30 s 关闭。
3. **空闲 keep-alive**：Node `keepAliveTimeout` 5 s，且在 keep-alive 响应上写
   `Connection: keep-alive` 与 `Keep-Alive: timeout=5`；本车道空闲连接改由
   `header_read_timeout` 兜底（60 s，读下一个请求头），两个头都不生成。修前
   这条路径**没有任何期限**（连接可永久空闲），修后是有界的 60 s，方向朝
   Node 收敛但取值仍不等。
4. **`stop()` 期间的半截请求头**：`A8.3-CH-SMS-011` 的残差 2b 与 3 把「停在
   请求头阶段的连接能把任务与 fd 无限占住」归给 #1955，本条即其答复：现在
   60 s 内必然结束。但 `SmsHandle::stop()` 仍只 await accept 循环、不等 detach
   的连接任务（与 Node `server.close()` 相反：Node 的 `httpServerPreClose`
   会 `clearInterval` 掉 checker，半截头的连接反而**永不**到期、`close()`
   一直等到客户端自己断开）。所以 `stop()` 返回后进程仍可能持有该 socket 至多
   60 s，而 Node 会一直持有——两侧都是「stop() 不等它」，但关闭方向相反。

残差 1 的字节细节与 body 读超时 408 的字节细节（`A8.3-CH-SMS-010`）是
**两条不同的响应路径**：那条走 handler 里的 `node_request_timeout_response()`
（hyper 帧化，多 `date`/`transfer-encoding`），这条根本不进 handler。

## Rust 行为

`src/pilotdeck-gateway/src/channel/sms/mod.rs`：

- `DEFAULT_HEADERS_TIMEOUT = 60 s`（`:82`），与 `DEFAULT_REQUEST_TIMEOUT`
  （`:66`，300 s）并列；注释点明二者分别对应 Node `headersTimeout` 与
  `requestTimeout`，且**体读期限不能顺带当头读期限用**（那是
  `A8.3-CH-SMS-007` 的 TS null-body 挂起语义）。
- `SmsShared.headers_timeout`（`:239`）随 `SmsChannel::new` 定值（`:380`）：
  `request_timeout.unwrap_or(DEFAULT_HEADERS_TIMEOUT)`。复用
  `SmsChannelOptions::request_timeout` 这一个注入点同时缩短两条期限，是为
  不新增结构体字段（`channel/sms/tests.rs` 有 7 处逐字段字面量，且该文件
  正被 #1958 修改）；生产路径从不设该字段，实际取值就是 60 s / 300 s。字段
  文档已写明这层联动（`:104-118`）。
- accept 循环里每条连接一个 detach 任务，`http1::Builder::new()` 上装
  `.timer(TokioTimer::new()).header_read_timeout(headers_timeout)`
  （`:600-606`）；到期 `serve_connection` 返回 `Err(HeaderTimeout)`，任务结束
  （`:607-609`），socket 随 `TokioIo` 一起 drop。
- 依据 hyper 1.7.0：`common/time.rs` 未装 `Timer` 时把
  `Dur::Default(Some(30 s))` 折成 `None`（这就是修前「没有期限」的根因）；
  `proto/h1/conn.rs:256-265` 与 `proto/h1/role.rs:463-473` 显示头读超时只
  置错误、不写自动响应（`on_error` 仅对 Parse 类写）。
- 变异开关 `sms-header-read-no-timeout`（`:602`）摘掉这对 timer，用于负控。

## 范围

仅 sms 车道请求**头**读期限的到期行为，一条路径、一个场景（客户端发半个请求
头后停发并保持 socket）。不覆盖：

- body 读超时的 408 字节形状（`A8.3-CH-SMS-010`）与 body 超时的时刻/关闭
  路径（`A8.3-CH-SMS-011` 残差 1–3）；
- 验签顺序：本轮**不动**「头读 → 体读 → 验签」。把验签提前会改变
  401/403 与体读的先后，并与 `A8.3-CH-SMS-007` 的 TS null-body 挂起语义冲突；
  头读有期限后「半个头占连接」已不成立，提前验签没有额外收益；
- 并发连接数上限：本车道无先例（webhook 共享车道也没有），本轮不做；
- 金样：`src/pilotdeck-gateway/tests/fixtures/channel-sms/oracle.json` 的 56
  格里没有「半截请求头」格（最接近的 `body-truncated` 是体读阶段、
  `body-read-timeout` 是体读期限），因此本条**不影响任何金样判分**，也不会
  因为这里列出的任何残差转红。

本条不构成判分豁免：把「期限内有界关闭」放松（例如允许读超时充当关闭）仍会
让下面第一条测试报错。

## 机器判据

- `src/pilotdeck-gateway/src/channel/sms/head_timeout_tests.rs`
  `half_sent_head_is_closed_at_the_deadline_and_leaves_no_task`：8 条连接各写
  半个头后**保持 socket 不关**，注入 300 ms 期限，每条连接必须在 5 s 读期限
  **内读到 EOF**（`closed == true`）且**零字节**；随后 `SmsShared` 的
  `Arc::strong_count` 必须回到 `start()` 后的基线（detach 任务不得滞留）。
  `closed` 这个标志是必须的：删掉期限后客户端读超时同样零字节，读超时后客户端
  自行关 socket 又会让连接任务退出——只看字节或只看 `Arc` 计数都会假通过
  （本轮实测踩到过，见下面的变异结果）。
- 同文件 `a_complete_request_head_is_served_before_the_deadline`（正控）：同一
  300 ms 期限下完整请求头照常进 handler（错路径得 `HTTP/1.1 404` + `Not
  Found`），证明期限只退休停发，不误伤正常请求。
- 同文件 `the_default_head_deadline_is_nodes_sixty_seconds`（`#[ignore]`，
  60 s 墙钟）：未注入时默认期限就是 `DEFAULT_HEADERS_TIMEOUT`，实跑在
  60.02 s 读到 EOF、零字节。
- 回归：#1901 的 `channel::sms::tests::body_read_timeout` 与
  `channel::sms::` 全子集（177 passed / 2 ignored）保持绿。
- 变异负控：`crate::mutants::on("sms-header-read-no-timeout")` 摘掉 timer。
  三段实跑（`_tmp/20261107-issue-1955/smoke/mutation.out`，cb8，
  `--features pdrs-mutants`）：开关不设 → 通过；设为目标名 → **失败**
  （5.01 s 读期限内没有 EOF）；设为近邻名 `sms-header-read-timeout-other` →
  通过（证明是名字命中，不是「设了环境变量」）。缺口：该开关尚未登记进
  `src/pilotdeck-gateway/tests/fixtures/channel-sms/negative_controls.py` 的
  switches 表——该文件正被 #1958 修改，本轮不碰；登记待 #1958 合入后补。
