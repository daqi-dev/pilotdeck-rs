## 类别

**本轮有意未对齐**（传输层呈现差异 + 触发时刻差异 + 空闲连接回收差异）：sms
车道请求**头**读期限（Node `headersTimeout` 等价，60 s）到期时的线上字节、
触发时刻与空闲 keep-alive 回收。四条残差同源于一处选择——本单在连接上装了
`.timer(TokioTimer::new()).header_read_timeout(60 s)`，**没有**把车道迁到
仓内已有 Node 口径实现（见残差 1）——因此合并登记一条，不拆成四条。

**这不是「runtime 机制上不可能」**：仓内 `http_proxy` native 车道用自研读门
`UpgradeReadGate::poll_headers_timeout_408`（`http_proxy.rs:461-480`）在超时时
写出 Node 的 51 字节 408（`NODE_HEADERS_TIMEOUT_408`，`:853-854`），并带
`grid_anchor` 让 408 落在 Node 的 30 s connections-checker 网格上；零字节首头与
半截首头都覆盖（`:876-882`）；`user_dialog/http_store.rs` 的 store 车道同理
（`NODE_408_RESPONSE`）；webhook 车道已经整条跑在
`http_proxy::serve_connection_native_with_shutdown` 上。**本单没有迁移 sms
车道**：那是整条响应栈的替换（响应体类型、帧化、header 大小写与 `Date`、56 格
金样全部重验），远超「补一条头读期限」的范围，也不该由一个 P0 修复捎带。所以
下面四条按「本轮有意的范围取舍」登记，供人决定是否另开单对齐。

- 残差 2 的 30 s 网格：同族实测见 `A8.3-CH-WEBHOOK-002` 残差 1 与
  `A8.4-NATIVE-HTTP-002-R2` 的 fix-r2 探针；本条的直接证据是上面三个 408 的
  落点（`90004` / `90004` / `120008`，都在 30 s 网格上、且都严格晚于
  锚点+60 s 的第一个网格点）。

四条残差：

1. **线上字节**：Node 到期写 51 字节 408 + `Connection: close`；hyper 的头读
   超时从 `serve_connection` 返回 `Err(HeaderTimeout)`，**一个字节都不写**就关
   连接（hyper 1.7.0 `proto/h1/conn.rs:256-265`、`proto/h1/role.rs:463-473`；
   `on_error` 只对 Parse 类写自动响应，`http1::Builder` 也没有超时回调）。
   如上面「类别」所述，仓内 native 车道已用自研读门写出这 51 字节——本车道
   走的是裸 builder，所以这里零字节，属**未对齐**而非**不可对齐**。
2. **触发时刻与起算点**：两边锚点不同。
   - Node：有首字节锚首字节、无字节锚连接建立，再由 30 s 网格裁断，实测
     落在锚点 + 60 s 之后的那一个网格点（D=0 与零字节都是 +90 s，D=35 s 是
     +85 s 后取网格 = 该连接起算后 120 s）；
   - Rust：`header_read_timeout` 自 accept 后首次 poll 读头起算，tokio 定时器
     到期即裁，实测 60.02 s 关闭，与客户端何时发首字节无关。
   所以两侧关系不是固定的「Rust 早 0–30 s」：客户端越晚发首字节，Rust 相对
   Node 就越早（D=35 s 时 Rust 在 accept+60 s 关，Node 在 accept+95 s 之后；
   D≥60 s 时 Rust 会在客户端还一个字节都没发的时候就关掉，Node 则要等到
   首字节 + 60 s + 网格）。方向是「更严」，不会让本该被 Node 服务的慢客户端
   静默通过，但**会把 Node 会服务完的慢首头客户端提前关掉**——这是本条最值得
   人先看的一条。
3. **空闲 keep-alive**：Node `keepAliveTimeout` 5 s，且在 keep-alive 响应上写
   `Connection: keep-alive` 与 `Keep-Alive: timeout=5`；本车道空闲连接改由
   `header_read_timeout` 兜底（60 s，读下一个请求头），两个头都不生成。修前
   这条路径**没有任何期限**（连接可永久空闲），修后是有界的 60 s，方向朝
   Node 收敛但取值仍不等（native 车道是 6 s：5 s 到期 + 1 s 网格）。
4. **`stop()` 期间的半截请求头**：`A8.3-CH-SMS-011` 的残差 2b 与 3 把「停在
   请求头阶段的连接能把任务与 fd 无限占住」归给 #1955，本条即其答复：现在
   60 s 内必然结束。但 `SmsHandle::stop()` 只 await accept 循环、**不等**
   detach 的连接任务，而 Node 的 `server.close()` 会等——只是 Node 那边
   `httpServerPreClose` 会 `clearInterval` 掉 checker，半截头的连接反而
   **永不**到期，于是 `close()` 一直等到客户端自己断开。所以两侧都不在
   `stop()` 里等连接，但关闭方向相反：Rust 的 socket 在 `stop()` 返回后至多
   再活 60 s，Node 的会一直活到客户端离开。

残差 1 的字节细节与 body 读超时 408 的字节细节（`A8.3-CH-SMS-010`）是
**两条不同的响应路径**：那条走 handler 里的 `node_request_timeout_response()`
（hyper 帧化，多 `date`/`transfer-encoding`），这条根本不进 handler。

## Rust 行为

`src/pilotdeck-gateway/src/channel/sms/mod.rs`：

- `DEFAULT_HEADERS_TIMEOUT = 60 s`（`:86`），与 `DEFAULT_REQUEST_TIMEOUT`
  （`:66`，300 s）并列；注释点明二者分别对应 Node `headersTimeout` 与
  `requestTimeout`，且**体读期限不能顺带当头读期限用**（那是
  `A8.3-CH-SMS-007` 的 TS null-body 挂起语义），并点名残差 1/2 在仓内
  native 车道的对齐方案。
- `SmsShared.headers_timeout`（`:251`）随 `SmsChannel::new` 定值（`:392`）：
  `request_timeout.unwrap_or(DEFAULT_HEADERS_TIMEOUT)`。复用
  `SmsChannelOptions::request_timeout` 这一个注入点同时缩短两条期限，是为
  不新增结构体字段（`channel/sms/tests.rs` 有 **9** 处逐字段字面量、无
  `..Default::default()`，生产侧 `mod.rs::register()` 还有 1 处，且该文件
  正被 #1958 修改）；生产路径从不设该字段，实际取值就是 60 s / 300 s。字段
  文档写明了联动（含 `Some(Duration::ZERO)` 的语义，`:116-129`）。
- accept 循环里每条连接一个 detach 任务，`http1::Builder::new()` 上装
  `.timer(TokioTimer::new()).header_read_timeout(headers_timeout)`
  （`:615-619`）；到期 `serve_connection` 返回 `Err(HeaderTimeout)`，任务结束
  （`:621-623`），socket 随 `TokioIo` 一起 drop。
- 依据 hyper 1.7.0：`common/time.rs` 未装 `Timer` 时把
  `Dur::Default(Some(30 s))` 折成 `None`（这就是修前「没有期限」的根因）；
  `proto/h1/conn.rs:256-265` 与 `proto/h1/role.rs:463-473` 显示头读超时只
  置错误、不写自动响应（`on_error` 仅对 Parse 类写）。
- 变异开关 `sms-header-read-no-timeout`（`:616`）摘掉这对 timer，用于负控；
  旁边留了可 grep 的登记待办（`#1958` / `negative_controls.py`）。

## 范围

仅 sms 车道请求**头**读期限的到期行为，一条路径、三个场景（半截头、零字节
首头、延迟半截头；第三个只在 TS 侧实测，Rust 侧由「自 accept 起算」这一实现
事实覆盖，见残差 2）。不覆盖：

- body 读超时的 408 字节形状（`A8.3-CH-SMS-010`）与 body 超时的时刻/关闭
  路径（`A8.3-CH-SMS-011` 残差 1–3）；
- 验签顺序：本轮**不动**「头读 → 体读 → 验签」。把验签提前会改变
  401/403 与体读的先后，并与 `A8.3-CH-SMS-007` 的 TS null-body 挂起语义冲突；
  头读有期限后「半个头占连接」已不成立，提前验签没有额外收益；
- 并发连接数上限：本车道无先例（webhook 共享车道也没有），本轮不做；
- 金样：`src/pilotdeck-gateway/tests/fixtures/channel-sms/oracle.json` 的 56
  格里没有「半截请求头」格（最接近的 `body-truncated` 是体读阶段、
  `body-read-timeout` 是体读期限），因此本条**不影响任何金样判分**，也不会
  因为这里列出的任何残差转红。

两条既有条目的陈述已被本条取代，但**本轮不改它们**（冻结账本只追加，更正须走
`-R<n>` 条目，且这两份文件不在本单批准范围）：`A8.3-CH-SMS-010` 里「请求头读
没有期限（#1955）」一句已过时；`A8.3-CH-SMS-011` 的 `stop()` 残差描述需与本条
残差 4 一起读。本条即两者在本场景下的补正依据。

本条不构成判分豁免：把「期限内有界关闭」放松（例如允许读超时充当关闭）仍会
让下面第一条测试报错。

## 机器判据

- `src/pilotdeck-gateway/src/channel/sms/head_timeout_tests.rs`
  `half_sent_head_is_closed_at_the_deadline_and_leaves_no_task`：10 条连接——
  8 条各写半个头后**保持 socket 不关**，2 条**一个字节都不发**——注入 300 ms
  期限，每条连接必须在 5 s 读期限内**读到 EOF**（`closed == true`；客户端侧的
  reset 也算关闭）、**零字节**，且从该连接起算到关闭 **≥ 150 ms**（排出
  `Duration::ZERO` 之类的假期限）；随后 `SmsShared` 的 `Arc::strong_count` 必须
  回到 `start()` 后的基线（detach 任务不得滞留）。
  `closed` 这个标志是必须的：删掉期限后客户端读超时同样零字节，读超时后客户端
  自行关 socket 又会让连接任务退出——只看字节或只看 `Arc` 计数都会假通过
  （本轮实测踩到过，见下面的变异结果）。
- 同文件 `a_complete_request_head_is_served_before_the_deadline`（正控）：同一
  300 ms 期限下完整请求头照常进 handler（错路径得 `HTTP/1.1 404` + `Not
  Found`），证明期限只退休停发，不误伤正常请求。
- 同文件 `the_uninjected_head_deadline_is_nodes_sixty_seconds`（快，无墙钟）：
  常量与 `SmsChannel::new` 的默认接线都必须是 60 s，防止改成别的值时只有那条
  `#[ignore]` 用例才报错。
- 同文件 `the_default_head_deadline_is_nodes_sixty_seconds`（`#[ignore]`，
  60 s 墙钟）：未注入时默认期限就是 `DEFAULT_HEADERS_TIMEOUT`，实跑在 60.02 s
  读到 EOF、零字节。
- 测试模块的端口是固定的（`webhookPort` 不能为 0），所以 `start()` 先探一次
  端口占用、`connect()` 只连一次：别的 worktree 同时跑本套件时端口被别人占住，
  `SmsChannel::start` 只会 log + 返回 no-op handle，不探端口的话测试会去量
  别人的监听器而**假 PASS**。探端口与单次连接把这种情况变成具名失败。
- 回归：#1901 的 `channel::sms::tests::body_read_timeout` 与
  `channel::sms::` 全子集保持绿。
- 变异负控：`crate::mutants::on("sms-header-read-no-timeout")` 摘掉 timer。
  三段实跑（`_tmp/20261107-issue-1955/smoke/mutation.out`，cb8，
  `--features pdrs-mutants`）：开关不设 → 通过；设为目标名 → **失败**
  （读期限内没有 EOF）；设为近邻名 `sms-header-read-timeout-other` → 通过
  （证明是名字命中，不是「设了环境变量」）。缺口：该开关尚未登记进
  `src/pilotdeck-gateway/tests/fixtures/channel-sms/negative_controls.py` 的
  switches 表——该文件正被 #1958 修改，本轮不碰。补登记时要注意：那张表用的是
  单一 `PREFIX = 'channel::sms::tests::'`，而本套件在
  `channel::sms::head_timeout_tests::` 下，**只加一行 switch 不够**，还得让
  登记能指向另一个模块（或加一层转发用例），登记待 #1958 合入后补。
