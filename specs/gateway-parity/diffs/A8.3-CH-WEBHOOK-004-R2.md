## Rust 行为

默认代理车道（`src/pilotdeck-gateway/src/main.rs` 的监听器 →
`src/pilotdeck-gateway/src/http_proxy.rs` 的 `Proxy::serve_connection`，
`serve_connection_configured` 的非 native 分支：普通 `http1::Builder`，
无本地 1.0 版本钉）：转发侧与 TS 一致（版本透传、Host 重写，实测核过）；
应答侧相对 Node TS 默认代理三处呈现差异（上表加粗两项 + 状态行）：①
状态行 hyper 对 1.0 下行连接回写 `HTTP/1.0`（enforce_version，与
native 监听器同类）；②1.0-plain 应答无显式 `Connection: close`（Node
有）；③1.0-keepalive 请求下 hyper 因请求头回 `connection: keep-alive`
而连接实际仍关（Node 回 `Connection: close`）——限 **close 定界的成功
响应**：错误响应定长体下 1.0-keepalive 连接保持打开（见下）。**本批只
登记不修**（修复车道在飞，见「范围」）。错误响应是定长体例外（fix-r1
补登、fix-r2
换锚）：默认代理本地构造的 `http_proxy::plain()` 是 `Full<Bytes>` 定长体，
1.0 下 hyper 照写 `content-length`（实测 1.0 502 带 `content-length: 25`；
1.0-plain 即关、1.0-keepalive 连接保持打开且该车道无 idle 回收）——与本
批三车道「1.0 未知长度写出」（close 定界、无 `content-length`）不同；
`http_proxy::empty()` 在默认代理车道无调用点，属 native-http/api-server
车道（其 1.0 `content-length: 0` 见 A8.4-NATIVE-HTTP-001 第 3 项既有
登记）；Node 侧错误响应 1.0 字节未亲测。其余车道 Rust 行为不变；store 车道
#1947 起 1.0 应答按未知长度写（`KeepAliveBody` 的 `unknown_size`：close
定界、无 `content-length`，1.1 的 `content-length` 不动）。
