## 类别

更正（判据与范围措辞，非差异变化）：`A8.3-CH-SMS-008` 的「机器判据」节举的
正控不成立，「范围」节漏登一条已知误判分支；同一轮里 `bind_dual_stack` 的探测
方式也改了一次（见「Rust 行为」）。

1. 原文称正控含 `logger_panic_does_not_poison_boundaries` 的 `webhookPort: 0`
   路径——该测试不设 `webhookHost`，走 `DEFAULT_HOST = "127.0.0.1"`，
   **不经过** `bind_dual_stack`；且它不发起连接，改回 `port` 或 `0` 都不红。
   真正的判别测试是 `dual_stack_probe_uses_the_assigned_port`。
2. 原文只登记「探测成功 ⇒ 回退 IPv4」这一半。另一半没登：v6only 宿主上若第三方
   已占 `127.0.0.1:<port>`，我们的 `::` 仍能绑上，探测因**第三方**占用而失败，
   被当成双栈证据，于是保留只服务 v6 的 listener，IPv4 请求会打到第三方。

## 基线依据

## Rust 行为

探测方式改了一次（fix-r5）。原来的二次 bind 用 `TcpListener::bind(("127.0.0.1",
bound))`，但 Rust std 会给 listener 设 `SO_REUSEADDR`，而 macOS/BSD 上带该选项的
socket 可以在 `::` 已占端口时再绑一个具体地址——双栈宿主上探测**永远成功**，
`bind_dual_stack` 永远返回 `Err`，空 host 无条件退回 `0.0.0.0`，与「只在 v6only
宿主上回退」的登记不符。实测（本机，Rust 1.9x / macOS）：

```
$ python3 -I  # v6 :: 带 SO_REUSEADDR，再绑 127.0.0.1:<port>
v4 bind to ::-owned port 61433: ERR [Errno 48] Address already in use
$ python3 -I  # 同上，但 v4 也带 SO_REUSEADDR
v4 bind(127.0.0.1,<port>) reuse=True: OK      # 探测被它骗过
```

改为 `tokio::net::TcpSocket::new_v4()` + `bind`（不设任何 socket 选项），冲突即
真实占用。探测目标的更正在 fix-r4（用 `local_addr()` 的实际端口，而非配置端口），
fix-r5 只是换了建 socket 的方式。实现仍不区分「`::` 已占 v4」与「第三方占
v4」，后者即上面第 2 条。

## 范围

仅空 `webhookHost` 的监听地址族与探测判据。显式 `webhookHost` 不受影响；
55 个 oracle cell 的探针全走 `127.0.0.1`，看不见 v6 差异，故不改变任何 cell
的判定结论。

## 机器判据

- 判别正控：`cargo test -p pilotdeck-gateway --lib
  channel::sms::tests::dual_stack_probe_uses_the_assigned_port`。成功分支断言
  端口非 0、地址是 v6 通配，并实际连 `127.0.0.1:<port>` 与 `::1:<port>`；
  失败分支用 **connect**（不是 bind）判定宿主类型：先绑一个对照 `::`，再
  `TcpStream::connect(("127.0.0.1", control_port))`，连得上即双栈；
  双栈宿主上若实现返回 `Err` 即判红。
- 实测（本机为双栈）：

```
=== baseline ===
test result: ok. 1 passed; 0 failed; ... 3901 filtered out; finished in 0.00s
=== mutant A: std TcpListener bind probe (SO_REUSEADDR) ===
panicked ...: #1339 this host is dual-stack, yet bind_dual_stack(0) refused:
  #1339 `::` is IPv6-only on this host
test result: FAILED. 0 passed; 1 failed; ...
=== mutant B: probe the configured port, not the assigned one ===
panicked ...: #1339 this host is dual-stack, yet bind_dual_stack(0) refused:
  #1339 `::` is IPv6-only on this host
test result: FAILED. 0 passed; 1 failed; ...
```

- v6only 宿主上该测试走 `Err` 分支，只断言错误文案含 `IPv6-only`。
- 未覆盖：第三方占 `127.0.0.1:<port>` 的误判分支（需要可控的第三方监听器与
  v6only 宿主，本机不可复现）。

## 批准记录

未批准，非已接受差异。第 2 条误判分支登记为已知缺陷，前置于 #1386 的 A8.3
收尾（修法：探测失败时区分错误种类，或用 connect 判可达性，或直接
`setsockopt(IPV6_V6ONLY, 0)`）。来源为 #1339 fix-r4 增量评审：Codex P1 #2/#3、
minimax concurrency #1/#2，等级取高 P1；fix-r5 的探测方式更正由协调者做负控时
实测发现（同一处 P1 的第二次修，未超修复轮上限）。
