## 类别

描述更正，沿用原条目「有意的向保留偏离」分类；不改保留语义、不新增豁免。原条目（accepted-diffs.md，字节冻结）中「未验证别名（如 Node 按 UTC 解释的 `TZ=localtime`）继续保留」的括号把 Node 对 `TZ=localtime` 的解释写死为 UTC，实测宿主相关，r3 评审 P3-2 指出该前提若被照抄，会把 stats/provider 侧的别名放行成 UTC 解析、与真实 Node 差 8 小时。

## TS 依据

Node v22.22.0 实测：`TZ=localtime` 经 C 库 zone 搜索解析——存在 `/usr/share/zoneinfo/localtime`（符号链接到 `/etc/localtime`，Asia/Shanghai）的机器（cb8）按本地时区解析，`Date.parse("Sun Nov  6 08:49:37 2033")` = `2014850977000`；不存在该文件的机器（r2 评审宿主、fix-r3 在 macmini-01 以 Node v22.22.0 / ICU 78.2 重跑核实）回退 UTC，同输入 = `2014879777000`。原始输出见 `_tmp/20261026-issue-360/fix-r2/deliver/node-tz-probe-macmini-01.log`（另一类宿主的 cb8 实测转录见 r3 评审）。`TZ=unsupported-profile`、`TZ=:/nonexistent` 下与 `TZ=UTC` 同值（两机一致），与原条目结论无冲突。

## Rust 行为

不变。`stats.rs` 的 `admitted_local_to_utc` 对 `TZ=localtime` 等未验证别名仍按不可解析处理（三标识 allowlist 之外的字符串一律 Err），`parse_date_ms` 返回 `None`、`is_retained_record` 按保留处理；provider Retry-After 侧（A6.4-PROVIDER-RETRY-AFTER-TZ-001）同一门槛同理。本条只更正 Node 侧行为的描述。

## 范围

仅更正原条目中对 Node `TZ=localtime` 解释的括号描述：由「按 UTC 解释」更正为「经 C 库 zone 搜索、宿主相关（有 zoneinfo/localtime 走本地，没有则回退 UTC）」。stats 保留判定的方向（未验证别名一律保留、不误删）不受影响，原条目其余内容（含未验证 TZif / POSIX TZ / 自定义路径等子集）不变。

## 机器判据

`runtime::model::http::retry_after_dialect_tests::retry_after_dialects_production_wiring_matches_node_zone_children` 的 `TZ=localtime` 子进程断言该别名经生产门槛后本地方言为 `None`（无门槛共享解析器可解析宿主 profile 时）；`stats_dateparse_tests.rs` 的 `dateparse_zone_child` 同 zone 断言 `parse_date_ms` 为 `None` 且行保留。本条为描述更正，无新增机器检查。
