## 类别

有意偏离（#2285 poll driver 收口的注册件，两处）。其一（**无在途轮询时比
TS 严；有在途轮询时与 TS 泄漏同形**）：未 stop 丢弃——TS 侧丢弃一个已
`start` 的渠道实例（不调 `stop`）泄漏 `setInterval`，轮询永不停止；Rust
侧轮询 driver 任务只持 `Weak<Runtime>`，升级失败即退出，无在途轮询时轮询随
实例释放而停止。**收窄（r2，r3 措辞修正）**：响应时长超过 `POLL_MS`
（2.5 s）的服务器下，在途轮询任务持强 `Arc<Runtime>` 直到 `poll_messages`
返回，任务寿命 > 2.5 s 则每 tick 至少一条在途，下一次 tick 的升级仍成功、
driver 每 2.5 s 续派新任务，各请求各自受 300 s 单次总界
（`UNDICI_DEFAULT_TIMEOUT` 是每请求的界不是泄漏的界）——强引用不归零、
`Runtime` 永不释放（无界自续），与 TS 泄漏同形，非「比 TS 严」（已知缺口，
无专属判据，见「机器判据」）。
其二（**已知偏差，缺一条日志**）：
per-tick 轮询任务 panic 无 `poll error` 日志——TS 侧 `pollMessages` 的
try/catch 把每次轮询失败记成 `poll error` 日志后继续轮询；Rust 侧 per-tick
轮询任务是对 TS `void this.pollMessages()` 的逐字 fire-and-forget
`tokio::spawn`（句柄按 TS 形态不保留），任务内 panic 被 tokio 吞掉、无日志。
行为面（interval 继续轮询、`running` 闸门、`stop` 仍返回 `Ok(())`）两侧一致，
仅缺错误日志。

## Rust 行为

`src/pilotdeck-gateway/src/channel/bluebubbles/mod.rs:289-295`（start 的
即时轮询）与 `:302-323`（interval driver，per-tick 在 `:313-320`）：任务
只持 `Weak<Runtime>`，升级失败即 return/break——丢弃已 start 渠道后，
**无在途轮询时**下一次 tick 升级失败，driver 退出、轮询停止；**响应时长
超过 `POLL_MS` 的服务器**（请求已发出、各请求各自挂在 `request_unbounded`
的 300 s 单次总界上，`http_client.rs` 的 `UNDICI_DEFAULT_TIMEOUT`）下，
在途任务持强 `Arc<Runtime>` 直到 `poll_messages` 返回，任务寿命 > 2.5 s
则每 tick 至少一条在途，下一次 tick 的升级仍成功、driver 每 2.5 s 续派
新任务——强引用不归零、`Runtime` 永不释放（无界自续），与 TS `setInterval`
泄漏同形，非「比 TS 严」（#2285 ②，r2 收窄、r3 措辞修正）。
`:317-319`：per-tick `tokio::spawn(async move { runtime.poll_messages().await })`
——panic 落在轮询任务内被 tokio 吞掉、无日志（#2285 ③ 已知偏差）；该形态
为对 TS `:74` 的 `() => void this.pollMessages()` 的逐字移植，是本条登记的
偏差而非疏漏。`:876-890`（stop）：driver 任务的 abort + 有界 reaping 与
两条新 `error` 日志见 003-R1；panic 若发生在 driver 任务本身（非 per-tick
轮询任务），reaping 处会浮出为日志——本条只覆盖 per-tick 轮询任务的静默。

## 范围

仅 #2285 ②③ 的两处：drop-without-stop 的存活语义（TS 泄漏轮询 → Rust 无
在途轮询时停止，在途窗口同形）；per-tick 轮询任务 panic 的日志缺失（行为
面一致）。不覆盖 stop 对
在途回合的语义（003 / 003-R1）、不覆盖无信号轮询 GET 的 300 s 总界（006）、
不覆盖 `SEND_TIMEOUT`（进请求字节的常量，两侧同值）。

## 机器判据

- 行为 pin `channel/bluebubbles/tests.rs` 的
  `poll_driver_exits_when_runtime_is_dropped`（两个观察量：服务端轮询停增 +
  `Runtime` 释放）；负控 `driver-weak-reverted`（回退强引用 → 钉转红）。
  该钉用的是每请求都回包的 mock：**响应时长超过 `POLL_MS` 的服务器形状
  （在途轮询持强引用 → 升级仍成功 → driver 不退出）无专属判据**——可钉：
  响应延迟 > `POLL_MS` 的 mock + stop 后轮询停增断言（~5–10 s 实时窗口即可
  复现同一形状：driver 不退出、`Runtime` 不释放），超出本轮范围，登记为
  跟进（#2285 r2 评审 concurrency#1 提出，r3 修正预算结论）。
- 行为 pin `poll_task_panic_does_not_stop_the_driver`（毒化的 turn-index
  互斥量注入 panic：毒行后的下一 tick 仍到达、stop 仍返回 `Ok`；判据在
  第 3 次 poll 之后断言——`submit` 入口计数恰为 1 证明投毒路径确实走到
  `submit`，gateway 投影为空证明 panic 早于记录，r2 起不再以「断言时
  投影尚未写入」的竞态窗口作数）；负控 `poll-task-inlined-into-driver`
  （per-tick spawn 改 inline await → panic 落进 driver → 下一 tick 永不
  到达 → 钉转红）、`poison-turn-index-removed`（去掉投毒 → 派发正常完成
  → gateway 投影非空 → 钉转红）。
- 「无日志」本身无正向判据（不存在的东西无法断言）；行为面由上述两条钉
  覆盖。金样不覆盖 drop-without-stop（unsupported flow，oracle 无该用例）。
