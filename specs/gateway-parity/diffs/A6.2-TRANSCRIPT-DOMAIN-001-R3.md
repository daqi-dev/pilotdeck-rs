## 类别

bug 修复（#1985 第 1 块）。R2 收窄后的剩余范围里，「turn_result 的 usage/permissionDenials/errors」与
「session_metadata 的 title/aiTitle」两条恢复/列表投影切片已对齐：TS 成功的形状 Rust 成功，TS 抛
TypeError 的形状 Rust 抛同名同文案错误，跨多条记录的错误优先级也与 TS 一致。其余恢复投影差异维持 R1/R2
的「不可避免（暂未移植）、前置于 A7.5」定性，不新增豁免。

## 基线依据

cc7c4e6 的真实两条读面（固定 Node v22.22.0）：

- **restore**：`ProjectSessionStorage.ts:337-346` → `SessionEvents.restore` → `SessionProjectionDriver.hydrate`
  （`SessionProjectionDriver.ts:70-83,187-206` 逐条 reduce、无 try/catch、不跑 finalize）。实测顺序为
  注册序：`AgentTranscriptProjections.ts` turnSummary reduce（`mergeUsage` 读 `usage.inputTokens`，随后
  `permissionDenials` 展开）→ `WebHistoryProjections.ts:379-381` 读 `compactMetadata.postTokens` →
  metadata reduce（`mergeMetadata` 读 `second.title`）。`errors` 在 restore 侧从不读。
- **list**：`AsyncTranscriptStorageAdapter.ts:402,444-479` 的 `projectSessionInfo` =
  `replayTranscriptEntries`（conversation reduce+finalize → turnSummary → metadata → compactBoundary →
  subagentReferences，逐个投影器扫全日志）→ 全日志 `accepted_input` 的 prompt 摘要读取 →
  **合并后** metadata 的 `title?.trim()` / `aiTitle?.trim()`。conversation finalize
  （`AgentTranscriptProjections.ts:140-233`）的 `cloneTurnResult` 只对 `index >= lastCompactBoundaryIndex`
  的 turn_result 执行 `permissionDenials.map` 与 `errors?.map`（`usage` 只做 `{...}`，不抛）。
- 实测证据：`_tmp/20261107-issue-1985/ts-golden/cross-entry.json`（12 格跨记录真值表：restore 与 list
  各自的胜出错误）、`_tmp/20261107-issue-1985/ts-golden/before-boundary.json`（压缩边界前后各形状的
  放行/抛错）、transcript-adapter 金样 `oracle.json` 480 场景（新增 12 条 `restore-order-*`，两处计数精确
  断言）、session-factory `oracle.json` 16 行 hydrate 金样（新增 `denials-string-nonbmp`）。

## Rust 行为

`src/pilotdeck-gateway/src/storage/transcript_adapter.rs`：

- 恢复门按端口拆成三个投影器函数——`turn_summary_supported`（usage / permissionDenials 可迭代）、
  `control_boundary_supported(entry, true)`（含 `compactMetadata.postTokens`）、`metadata_reduce_supported`
  （`metadata.title` 读面）；`restore_entries` 按此顺序**逐投影器扫全日志**，不再逐条记录决定错误。
- 列表门拆成 `list_conversation_entry_supported(entry, before_boundary)` 与 `list_title_supported`：
  `last_compact_boundary_index` 先按 conversation reduce 复刻 `readCompactSnapshot(entry) ??
  replacementMessages` 的真值判定，finalize 只对边界及其后的 turn_result 读 denials/errors；标题 trim 在
  合并后的 metadata 上按 `title || aiTitle` 短路检查。`compactMetadata` 在列表端口不读。
- `runtime/session/projection_cache.rs` 的 checkpoint 后缀路径复用 `merge_permission_denials` 的 JS 展开
  语义（字符串按 code point、代理对合并、孤立代理保留），不再退回只收数组的 `array()`。
- `runtime/session/factory.rs` 的 `merge_permission_denials` 接受字符串（原只收数组且文案不同）。
- `ProjectionUnavailable` 只留给 TS 接受但 Rust 未建模的形状（本切片内已无）。

## 范围

已消除：`turn_result` 的 usage/permissionDenials/errors 与 `session_metadata` 的 title/aiTitle 在 restore
与 list 两条端口的显式拒绝与跨记录错误优先级差异（含压缩边界前的 turn_result 在 list 侧被丢弃、checkpoint
后缀的字符串展开）。仍未对齐、维持 R1/R2 定性：其余条目种类（`accepted_input.messages`、
assistant/tool_result/durable `message`）的未支持形状仍返回 `ProjectionUnavailable`（真 TS 对其中一部分
抛 TypeError，属 A7.5 未移植面；已另行登记 #2042/#2044）；子代理引用视图（#2042）、projection checkpoint
持久化（#2043）、暴露给宿主的视图/finalize API（#2044）不在本单。R2「顺序注记」所述「Rust 门逐条目检查，
多缺陷条目共存时先报哪条 message 可能不同」**对本切片失效**：门已按投影器顺序扫全日志，12 条
`restore-order-*` 金样逐格断言两侧同一错误。列表端口 prompt 摘要（`projectSessionInfo` 的全日志
`accepted_input` 读取）仍按既有宽松实现收集，不因本切片收紧。
