## 类别

更正件（#1791 / #1819 第 16 条）：只更正原条目 A6.3-CONFIG-POLL-001 的描述与判据文字，不改变其登记范围，不新增偏离条目，不增加任何判分豁免。原条目本身仍是「实现限制（宿主文件监视机制）」：`fs.watch` 被轮询采样替代。

## 基线依据

同原条目：`pilot/config/PilotConfigStore.ts:107-139` 对现存路径/缺失路径的 parent 使用 `fs.watch`，通知后 debounce（默认 250ms）；事件驱动，任何一次写入都产生事件。固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85。

## Rust 行为

更正原条目「默认每 20ms 采样 metadata 和至多 CONTENT_SAMPLE_LIMIT 的文件内容，再 debounce」一句：#1739 起每次采样**先取 metadata-only 指纹，与上次相同就不读内容**，只有 metadata 变化（或一次不完整采样，#1792）才走到内容读（被监视配置文件本体至多 1 MiB，其它目录项与超限文件始终只按 metadata）。该「内容变了、metadata 未变」的漏检格由 `A6.3-CONFIG-METADATA-SHORTCUT-001` 单列登记（其更正件 `A6.3-CONFIG-METADATA-SHORTCUT-001-R1.md`），本条不再覆盖。

另两句口径更正（#1736 / #1792 引入，不构成新的可观察差异）：

- 去抖上限 1 h（`effective_debounce`）已由 `A6.3-CONFIG-DEBOUNCE-CEILING-001` 登记，不属本条；`poll_interval` 的 10 ms – 60 s 夹取是纯实现细节，TS 侧没有对应旋钮，不构成新的可观察差异。
- #1792 修复后「读失败被当成内容未变」不再属于本条口径：一次 stat / `read_dir` / 内容读失败算**不完整采样**（`NotFound` 除外：它是完整观测，#1792 r1），不提交 metadata 指纹，下一 tick 重试直至完整样本落地；内容读恢复后无需 metadata 变化即可补报。

## 范围

同原条目：仅 watcher 触发的 reload 次数、时机、version/changedPaths；手动 reload 不受影响。净零遗漏的触发条件更正为「**采样间内容与采样 metadata 均相同**才不触发 identity reload」；「内容变了但 metadata 未变」的漏检格已由 `A6.3-CONFIG-METADATA-SHORTCUT-001` 单列，本条不再覆盖。另补一条（#1792 fix-r1，r2 按 D8/D9/D16 收敛）：启动探测（`WatchedPath::new` 的 stat）失败时，首个完整采样**必报一次**——探测失败期间配置可能已变，即使没变也是一次 identity reload（version+1、`changedPaths` 为空）；TS `fs.watch` 启动不读内容、不产生该事件。stat / `read_dir` 中途失败**不再额外补报**：遮蔽采样不提交任何指纹（含折叠指纹），只与上一遮蔽采样比较后上报可观测变更（持续遮蔽——如目录内某条目 stat 永久失败——期间，可观测条目的变更仍被上报），恢复后与最后一次完整采样比较、有差才报（含删除）。内容读失败的既有语义（失败期间报一次、恢复再报一次）不变。大文件超出内容样本、目录其它项只按 metadata，不保证所有文件系统均能发现瞬态变化（同原条目）。

## 机器判据

同原条目：`tests/config_store.rs::config_store_replays_real_typescript_oracle` 保障已覆盖 reload 行为；真实短突发验收须在同一文件系统记录 `fs.watch` 通知和 Rust 采样时间线，比较 version 和 changedPaths，尚未穷举 tick 相位 / ctime 粒度。补两点：

- 轮询上限与去抖上限的行为由 `config::store::tests` 的 `huge_poll_interval_is_clamped_and_keeps_sampling`（含 `MAX_POLL_INTERVAL == 60 s` 字面 pin）、`two_hour_debounce_is_clamped_to_the_one_hour_ceiling`、`overlong_debounce_is_clamped_and_reloads_within_the_bound`、`overflowing_debounce_does_not_kill_the_watcher` 钉住，负控绑定见 `tests/fixtures/config-store/negative_controls.py` 的 `poll-ceiling-removed` / `two-hour-debounce-ceiling-removed` / `debounce-ceiling-removed` / `overflowing-debounce-double-restore` 行。
- 不完整采样的重试语义由 `config::store::tests::transient_read_failure_is_retried_until_the_content_is_seen` 与 `startup_read_failure_is_retried_until_the_content_is_seen` 钉住（负控行 `incomplete-sample-committed` / `startup-incomplete-committed`）；stat / `read_dir` 失败的遮蔽语义（不提交任何指纹、只与上一遮蔽采样比较、恢复后有差才报）由 `stat_failure_leaves_the_metadata_fingerprint_uncommitted`、`stat_failure_during_change_is_seen_after_recovery`、`read_dir_failure_leaves_the_metadata_fingerprint_uncommitted` 钉住（负控行 `stat-failure-counted-complete` / `recovery-trusts-folded-fingerprint` / `read-dir-failure-counted-complete`，钉的都是**非 `NotFound`** 的 stat / `read_dir` 失败）；「`NotFound` 是完整观测」由 `missing_entry_is_a_complete_observation`（负控行 `not-found-counted-obscured`，钉 `hash_entry` 的 `NotFound` 分支）与 `a_removed_directory_is_a_complete_observation`（负控行 `read-dir-not-found-counted-obscured`，钉 `read_dir` 的 `NotFound` 分支）钉住；启动探测失败不丢路径且首拍必报由 `startup_stat_failure_keeps_the_path_watched` 钉住（负控行 `startup-probe-failure-dropped` / `startup-recovery-not-reported`）；未分类模式不被 `NotFound` 定死由 `probe_failure_then_directory_is_reclassified` 钉住（负控行 `probe-not-found-fixes-file-mode`）；目录被换成文件仍可检测由 `a_directory_replaced_by_a_file_is_seen` 钉住（负控行 `mode-change-not-detected`）；持续遮蔽仍上报可观测变更由 `a_persistent_obstruction_still_reports_observable_changes` 钉住（负控行 `obscured-change-not-reported`）；报变化拍不提交短路指纹由 `a_reported_change_does_not_commit_the_metadata_shortcut` 钉住（负控行 `report-commits-metadata-shortcut`）。
