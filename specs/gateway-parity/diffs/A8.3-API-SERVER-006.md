## 类别

已知差异，未修：请求带**存在但为空值**的 `Host:` 头时，TS 基线在 handler 里抛
`TypeError: Invalid URL` 并**整进程退出**，Rust 端口回落配置的 `host:port` 继续
服务并答 `200`。解析层准入本身两侧一致（都放行），差异发生在 handler 重建 URL
这一步，属 `A8.3-API-SERVER-001`（JSON `null` 体让 TS 崩进程、Rust 答 400）同一族。
**本条只讲「头存在但值为空」，与 HTTP 版本无关**：空值头在任何版本都不算「缺失」
——Rust 的闸门只在 `HTTP_11` 上拒绝**头缺席**，空值头通过闸门并落到
`host.is_empty()` 回落；TS 的 `new URL(path, 'http://')` 也不看版本。
（「头缺席」的拒绝则只在 HTTP/1.1 生效，那是另一条路径，不在本条。）本条按
HTTP/1.1 实测，HTTP/1.0 空值头同族。

## 基线依据

固定基线 `cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85`，Node v22.22.0 / ICU
78.2（探针自断言）。

裸 socket 探针（真 `ApiServerChannel`，`_tmp/20261107-issue-1683/probe/
probe-empty-host.mts`，原始输出 `probe-empty-host.out`）。**每格单独一个进程**：
空 `Host:` 会在 handler 里杀掉整个进程，单进程跑三格只能录到第一格（r2 边界
评审 P2 指出旧记录正是这样），所以探针接受格 id 参数、由 shell 逐格起进程：

```text
### cell=host-empty
GET /health HTTP/1.1\r\nHost:\r\n\r\n
  → node:internal/url TypeError: Invalid URL
    at ApiServerChannel.handleRequest (ApiServerChannel.ts:137:17)
    at Server.<anonymous> (ApiServerChannel.ts:63:19)
    code: 'ERR_INVALID_URL', input: '/health', base: 'http://'
    → exit=1（未拿到任何响应字节）

### cell=host-empty-space
GET /health HTTP/1.1\r\nHost: \r\n\r\n      （空值 + 一个空格）
  → 同上逐字相同（exit=1）

### cell=host-present-control
GET /health HTTP/1.1\r\nHost: 127.0.0.1\r\n\r\n
  → HTTP/1.1 200 OK … {"status":"ok","platform":"api-server"}（exit=0）
```

即 `_http_server.js` 用 `headers.host === undefined` 判缺，**空串不算缺**，
所以请求通过解析层进到 handler，然后 `new URL(request.url, \`http://${host}\`)`
以空 base 抛错。这条边界是 #1683 边界评审（GLM boundary P2）提出、本单实测的：
`node_parser_admission` 的 `contains_key(HOST)` 与 Node 的判定一致，**不需要**改成
「存在且非空」。

## Rust 行为

`channel/api_server/server.rs::handle` 里 `header_string(headers, "host")` 拿到空串，
`host.is_empty()` 为真 → `base_host` 回落 `shared.host:format_port(shared.port)`，
URL 解析成功，`/health` 答 `200 {"status":"ok","platform":"api-server"}`。

没有改成「空 Host 就 400」：TS 不是 400 而是崩溃，凭空造一个 400 会引入另一条
与基线不符的行为；要复刻崩溃需要让整个 api-server 进程退出，属产品级决定
（与 A8.3-API-SERVER-001 同类），不在 #1683 范围。

## 范围

- 只涉及 api-server 车道，且只限「`Host` 头存在、值为空」这一格。
- 不涉及解析层准入（方法表、target 字节/形态、16 KiB 预算、缺 Host）：两侧
  判定一致，`A8.3-API-SERVER-005` 已登记该闸门接入。
- 不影响其它车道（webhook / native-http / sms / wecom 各自的空 Host 行为未在
  本条声明，也未被本单改动）。

## 机器判据

- **不入金样**：这条格无法在生成器里记录 —— TS 在 handler 里崩进程，探针拿不到
  响应字节，`generate.mts` 会整轮退出。因此这条差异只能以「真实数据探针 + 本条
  登记」的形式存在，不设重放格。
- 探针可复算（**逐格起进程**：第一格会把整个进程杀掉，单进程跑三格只能录到
  第一格，驱动脚本 `_tmp/20261107-issue-1683/probe/run-empty-host.sh` 已归档）：

  ```sh
  PDRS_BASELINE=/abs/PilotDeck sh _tmp/20261107-issue-1683/probe/run-empty-host.sh
  # 等价于逐格执行（cell ∈ host-empty / host-empty-space / host-present-control）：
  #   LANG=en_US.UTF-8 PDRS_BASELINE=/abs/PilotDeck node \
  #     --import "file://$PDRS_BASELINE/node_modules/tsx/dist/loader.mjs" \
  #     probe-empty-host.mts <cell>
  # 前两格 exit=1（ERR_INVALID_URL 崩进程），对照格 exit=0 并打印 200 原始字节。
  ```

- Rust 侧现状由代码路径钉住（`host.is_empty()` 回落），不加断言以免把「TS 崩、
  Rust 服务」写成期望行为。
- 复算命令：

  ```sh
  python3 -I scripts/gateway-parity/check_frozen.py --base origin/main
  ```
