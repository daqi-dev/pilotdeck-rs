## 类别

登记（同源行为差异，#2312）。auth.test 失败路径的会话回收：TS 的 catch 保留
`this.app`（Socket 与已注册 handler 存活到进程 teardown），失败句柄的 `stop()` 为
空操作；Rust 侧在失败当刻回收已开启的会话。原条目「范围」item 6 与 R1 范围 3 的
「维持现状」决断（Rust 在 WS 连上后的失败路径保留 `runtime.app`）随之作废——
#2312 证明该状态在 Rust 侧有真实代价（reader 任务与 `Arc<SlackShared>` 永久驻留，
`NoopHandle::stop` 为空使回收无入口），不再是「无观测面」的中性差异。

## 基线依据

## Rust 行为

`src/pilotdeck-gateway/src/channel/slack/mod.rs` `abandon_session()`（#2312）：auth.test
失败的两侧路径（网络 Err 与 `ok:false`）取出 `runtime.app`、drop sink（裸 TCP FIN）、
abort reader 任务；随后 `start()` 照 TS 打 `slack: start failed: ...` 并返回空句柄。
`LiveApp` 增 `reader: Option<JoinHandle<()>>` 字段以持有任务句柄。回收对线上不可见：
FIN 不是 close 帧，mock 的 `ws` 记录维持 `[open]`，`start-auth-test-failed` 金样格
不动；真实句柄路径的 `stop()` 仍发记录内的 `close(1000)`。`NoopHandle::stop` 保持
空——失败句柄返回时已无可停之物。

## 范围

1. 本条只登记 auth.test 失败路径的同源差异；`connections.open` / 握手失败（WS 未开）
   无会话可回收，行为两侧本就一致。
2. 金样不判分本差异（`ws == [open]` 两侧同形）；Rust 侧资源态由专用测试钉住
   （见机器判据），TS 侧正控不可行（同原条目范围 5 的口径：基线只读）。
3. R1 范围 3 的「维持现状」决断作废；范围 6 的 failed-open 半区（`connections.open`
   失败时 `runtime.app` 为空）不受影响，继续按原条目登记。
4. 范围 1/2/3/5（真值来源降级、SDK 内部行为、「SDK 未装」状态）不变。
