## 类别

不可避免（A7 端口没有 abort 能力）。TS `/new` 在重置会话后调用
`gateway.abortTurn({ sessionKey, runId? })` 终止上一轮仍在跑的 turn；
Rust 的 `TurnGateway` 端口只有 `submit`，没有 `abortTurn`，因此 `/new`
只做本地重置（generation 自增、清队列、清待答交互、清批次定时器），
上一轮 turn 在 gateway 侧继续跑到底，只是它的事件不再投递给该 chat。

## 基线依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0。
`src/adapters/channel/feishu/FeishuChannel.ts:469-481`：

```ts
if (mapped.command === "new") {
  this.onStateChange?.(this.mapper.snapshot());
  const activeRun = this.chatState.activeRun(chatId);
  this.resetChatInteractionState(chatId);
  await this.gateway?.abortTurn({
    sessionKey: activeRun?.sessionKey ?? previousSessionKey,
    ...(activeRun?.runId ? { runId: activeRun.runId } : {}),
  }).catch(...);
  if (!mapped.message) { await this.send({ chatId, text: "已创建新会话。" }); return; }
}
```

`previousSessionKey` 在 `:467` 于 `resolve` 之前取；`around :576` 另有一处
`abortTurn(reason: "system:timeout")`，同属端口能力缺失，见
`A8.3-CH-FEISHU-006`。

## Rust 行为

`src/pilotdeck-gateway/src/channel/feishu/mod.rs:702-722`：先
`on_state_change(snapshot)`（顺序与 TS 一致，在 reset 之前）、再
`reset_chat_interaction_state`，最后按 `mapped.message` 是否为空决定是否
回 `已创建新会话。`；`/new <正文>` 在重置后带着**新**会话 key 继续走
提交路径（与 TS 相同：基线只在 `!mapped.message` 时返回），不做 abort；
注释 `:714-716` 明确「No `abortTurn` on the A7 port:
the previous run keeps going (registered diff), but the generation bump
below already stops its events from reaching this chat」。
`reset_chat_interaction_state`（`:763-779`）自增 `entry.generation`、
清空队列与 `active_run`、清 elicitation/permission 状态并 abort 批次定时器；
`process_turn` 的每个事件与收尾都过 `is_current(chat_id, generation)`
（`:848`、`:878`、`:936`），所以旧轮的事件与最终回复都被丢弃。

## 范围

仅 `/new` 触发时对**上一轮在跑 turn** 的终止语义：TS 会让 gateway 真正
停止该 run（省算力、停工具调用），Rust 任其跑完再丢弃输出。
**用户可见的会话切换、`已创建新会话。` 回复、持久化 state、后续消息
进入新会话均一致**；差异在于后台计算与副作用（工具调用、写文件）
不会因 `/new` 停止。不含 `system:timeout` 的 abort（另一条目）。
本条不构成判分豁免。

## 机器判据

- `src/pilotdeck-gateway/src/channel/feishu/tests.rs` 的重放用例钉死
  `/new` 的可见行为：`已创建新会话。` 回复、会话 key 形状
  `feishu:chat=<id>:s_<uuid>`、state 回调快照在 reset 前发出。
- generation 隔离有组件钉子：旧 generation 的事件不落到新会话
  （`process_turn`/`is_current` 路径），负控变异摘掉 generation 检查
  必须转红。
- `/new <正文>` 的提交路径由组件钉子
  `new_command_with_text_submits_on_the_new_session` 钉住：gateway 收到
  且只收到 `message: "请总结"`（会话 key 形如 `feishu:chat=c7:s_<uuid>`），
  出站没有任何 `已创建新会话。` 文案。
- `abortTurn` 本身无判据（端口无此方法）；补端口时须新增「`/new` 后旧
  run 收到 abort」用例并改本条目。
