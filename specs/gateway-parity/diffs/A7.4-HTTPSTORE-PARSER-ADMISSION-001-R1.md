## 类别

补登 #2774 的实测仲裁与 #2773 fix-r1 的更正：解析层准入早退的**连接生命周期
记账**。原条目（001）登记了接线与两格金样重放。r1 初稿据 worker 的 Node 实测 +
读码推断登记「不存在 Node FIN 而 Rust RST 的格 → 产品代码零改动」；三家评审
（anthropic + DS + MM）同撞推翻该结论的证据基础：worker 的 Rust 侧探针
（`rust-probe.out`）**没有任何 1 MiB 格**，「Rust FIN」与「不存在分歧格」两条
结论建立在没有实测的格上，且评审轮本机实测看到了相反格。fix-r1 以三组实测
（评审轮 macOS 探针、本车道 macOS 修前/修后矩阵、CI Linux 修前矩阵）重写本条：
修前 Rust 在「带未读体拒绝」格上的关闭类型**时序敏感、平台间不稳定**（同格在
两组 macOS 实测里互相翻转，Linux CI 未触发竞态但同样未接线保证）；fix-r1 补齐
准入早退与守卫 431 两条路径的排空接线（`mark_unread_body_close()`），并把尺子
（`exchange_until_eof`）从「EOF 即 closed」升级为 FIN / RST / StillOpen 三态，
使任何回归到 RST 的关闭在钉子上显式失败。fix-r2（同轮二家评审 anthropic
concurrency#1 P1 / DS sibling#1 P1 / DS boundary#1 P1 续修）继续增补：两条
绑定钉改为 dribble 构造（两钉写侧杀灭力以实测轮为正本、**采信需多轮重复
取证——macOS 写侧轴现仅一轮、整体为初证**，口径见「平台边界」；fix-r8
实测修正发送缓冲论证（评审 DS r8 boundary#1）、fix-r10 撤一切机制型单轮
采信（评审 DS r10 concurrency#1 / boundary#1））并加
`ServerClose` 尺子自检、负控改 N 跑协议、范围与平台边界逐线声明（见对应节）。
本条不新增判分豁免；未批准，非已接受差异。

## 基线依据

固定基线 `cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85`，Node v22.22.0（worker 复核
`node --version`）。真实 `http.createServer`（无 options，
`HttpGatewayUserDialogStore.ts:236` 同形）且不注册 `clientError` 监听——grep
全仓证实基线无任何 `clientError` 覆盖。Node 侧逐格（worker cb8 实测，裸
`net.Socket`，原始输出 `_tmp/20261026-issue-2773/r1/artifacts/round/
node-arbitration/probe-final.out`，仲裁回执已代贴 #2774 评论，存档副本
`_tmp/20261110-issue-2773-fix-r1/r1/2774-receipt-original.md`）：

- admitted 对照（POST + `Connection: close` + 10 B 体）：122 B `200` + FIN。
- llhttp 级拒绝（未知方法 `FROB`、非 ASCII target、无冒号头行、超预算头），小体
  （≤ 解析缓冲）：裸 `400`（47 B）/ 裸 `431`（67 B）+ **FIN**。
- 同族 + 1 MiB 未读体（与请求头一次写出）：响应字节先完整到达，然后 **RST**
  （frob-body-1m、header-no-colon-body-1m 两格）。
- HTTP/1.1 缺 `Host`，任意体量（含 1 MiB）：全量 `400`（117 B）后 **FIN**（Node
  在该路径排空了未读体）。
- CONNECT：**0 响应字节** + FIN。
- 客户端写完即 FIN / 体在拒绝后 dribble：响应 + FIN，迟到写 EPIPE。
- guard-431 格（超预算头 + 末行不完整，中途头内触发）：本车道补测 Node v22.22.0
  5/5 **FIN**（`r1/node-guard431-close.txt`，探针 `r1/node-guard431-close-probe.mjs`）。

Rust 侧修前实测三组（详见「Rust 行为」的矩阵对读）：评审轮 macOS 探针
（findings §四）与本车道 macOS 修前矩阵在 frob-1m / header-no-colon-1m 两格
**互相翻转**（RST ↔ FIN）；CI Linux 修前矩阵 16/16 FIN。即修前行为是
「close 时内核接收队列是否仍有未读字节」的竞态，不具确定性。

## Rust 行为

`src/pilotdeck-gateway/src/user_dialog/http_store.rs` 的三条关闭路径：

1. serve 路径（已接线）：`body_pending && Connection: close →
   mark_unread_body_close()`（`http_store.rs:3479` 一带）。
2. **准入早退（r1 初稿漏接线，fix-r1 补齐）**：`parser_admission` 早退
   `return Ok(rejection)` 发生在上述接线之前，是唯一「带未读体关闭却不排空」
   路径——fix-r1 在早退前按同条件补 `mark_unread_body_close()`
   （`http_store.rs:3410` 一带，评审 MM concurrency P1）。
3. **守卫 431 中途头内触发（fix-r1 新发现的第三条，同补齐）**：超预算头
   `header_guard.push` 触发点在头未读完时 break，同样带未读字节关闭——触发点
   补 `mark_unread_body_close()`（`http_store.rs:3099`）。Node 同格 5/5 FIN 实测
   见基线依据。该置位是**无条件的**：即使请求头是 `Connection: keep-alive`，
   超预算头的 431 关闭也走排空（Node 同格立即 FIN）。差异是 ≤100 ms 量级的
   排空等待时延——对齐需读内核接收队列，不可移植，登记为已知呈现差异
   （b 档台账路线，不改产品代码）。

修后：三条已接线路径「先排空再关」，对 `#702` `drain_after_early_close`
（100 ms 静默、1 s 上限）吸收能力以内的未读体（1 MiB dribble ≈ 35 ms，
实测远在内界）FIN 确定；**超出 1 s 排空上限的未读体不保证**——排空有界截断
后的关闭仍可能 RST，与 Node 排空缓冲超限后 RST 同族，未逐格登记。第四条关闭
路径——hyper 原生解析错误（如无冒号头行）触发的连接收尾——**未接线**：Node
同格实测本就是 RST（基线依据「响应字节先完整到达，然后 RST」），Rust 未接线
行为与之不构成 FIN/RST 分歧，不在本条登记。修前 Linux 全 FIN 只说明竞态在
CI 时序下未触发，不构成「不接线也安全」的证明。

**杀灭力边界（fix-r2 追加，评审 anthropic concurrency#1 P1；fix-r3 实测改写，
评审 MM boundary/concurrency P1）**：修后侧 FIN 确定，但拆线侧的关闭类型仍由
「close 时内核接收队列是否有未读字节」的时序决定——旧的一发写全构造下，
全套 KILLED 曾是一次性采样（计数见「N 跑协议」），同格在多轮实测里互翻（见
上矩阵三组对读）；修复轮
一轮杀灭不足以证明杀灭力稳定。fix-r2 把两条绑定钉改为 dribble 构造：客户端
先收全响应字节，再有界分拍写剩余体（见「机器判据」），意图使拆线侧吃 RST、
修后侧 FIN。**顺序边界（fix-r3 实测坐实）**：拆线侧的 RST 论证未覆盖客户端
接收队列里已排队的 FIN——拆线侧关闭时接收队列为空、先发 FIN，客户端首拍再
触发 RST，`read_to_end` 的分类取决于内核让已排队 FIN 与后到 RST 谁被消费。
实测（2026-11-10）：macOS RST 胜出，Linux（cb8）两行 drain 均 SURVIVED——
已排队 FIN 先被消费、拆线侧同判 `Fin`，**close-kind 断言对排空接线在 Linux
无判别力**（旧构造 16/16 FIN 同此；根因登记见「写侧判别轴」，逐轮明细见
「N 跑协议」）。修后侧 FIN 不受此边界影响（排空吸完 + 100 ms 静默是本侧
自身的时序预算）。
**平台边界（轴级取证口径，唯一正本；fix-r3 写侧轴后改写；fix-r6 数字收敛
到「N 跑协议」，本段只持轴级结论与两钉口径，轮次明细均见「N 跑协议」；评审
DS r6 simplify#1 / boundary#2、r7 simplify#4 / concurrency#1、r8 boundary#1）**：
**close-kind 轴**——Linux 在旧构造与 fix-r2 dribble 构造下都放走拆线侧
（SURVIVED），判别力证据只在 macOS 轮取得（原始输出已贴 #2842）；
close-kind 轴上「两侧都确定」仅对 macOS 成立，该轴的边界已被写侧轴取代
（下段）。**写侧轴**——两平台均取证；写侧断言不依赖读侧 FIN/RST 的消费
顺序。写侧杀灭力的登记依据是实测轮（逐轮明细与原始输出见「N 跑协议」），
不是机制演绎；机制侧只登记已测事实：两宿主 loopback 新建 TCP 连接的
`SO_SNDBUF` 默认初值实测（2026-11-10，`r1/sndbuf-probe.txt`）cb8 为
2,626,560 B（getsockopt 返回值含内核簿记翻倍，÷2 ≈1.31 MB = 1.25 MiB——
probe 原文的「1.31 MiB」系十进制口径）、macmini-01 为 146,988 B——FROB
拍量超 macOS 侧初值、装得进 cb8 侧（两钉拍量数值见「机器判据」的钉子
条目）。fix-r7 的「FROB 钉 1 MiB 阻塞写 ⇒ 写侧确定」已被实测推翻（Linux
侧装得进；评审 DS r8 boundary#1）；fix-r9 的「FROB 钉在 macOS 有阻塞写
机制 ⇒ 单轮可采信」同为容量推断未实测——真实吸收上界还含对端接收窗口与
栈侧缓冲抬升，均未测（评审 DS r10 concurrency#1），一并撤回。**采信规则
（本段正本，fix-r10，评审 DS r10 boundary#1 / concurrency#1）**：写侧轴不
采信任何单轮——全部钉 × 平台组合均按多轮重复取证采信；Linux 侧已有多轮
（见「N 跑协议」），**macOS 写侧轴取证仅第 10 轮一轮（第 3/4/5 轮的杀点落
已被取代的 close-kind 轴），整体为初证**，多轮补跑、拍量抬升与
拍间隔-vs-RST 往返的机制实测一并跟 #2852。负控纳入 CI 本身仍跟
#2842（CI 盲区未变）。
**写侧判别轴（fix-r3 续，评审 MM concurrency#1 / boundary#3 P1）**：close-kind
轴无平台判别力的根因是「已排队 FIN 先被消费」。判别轴改为排空的**写侧事实**：
拆线侧早关后，客户端后续 dribble 拍落在已关 socket 上，两平台都得
EPIPE/ECONNRESET（不依赖读侧 FIN/RST 的消费顺序；时序条件与缓冲实测见
「平台边界」）；排空侧吸收全部拍、每拍写全
成功。`exchange_dribbled_after_response` 为此返回第三值 `DribbleWrites`
（两枚举值与断言顺序见「机器判据」），两条绑定钉把写侧断言排在 close-kind
断言**之前**，杀点在两平台统一落在写侧锚 `every dribble beat is written,
none reset`。实测（2026-11-10，head `36ee65061`，逐轮明细与原始输出见
「N 跑协议」）：两条 drain-unwired 均死于写侧断言
（`r1/negctl8/parser-admission-drain-unwired-negative.log:9-10` panic 于
`http_store_tests.rs:1770`、`r1/negctl8/guard-431-drain-unwired-negative.log:9-10`
panic 于 `:1213`；后续轮同锚）——**写侧轴在 Linux 多轮恢复判别力；macOS
单轮为初证（采信口径见「平台边界」）**。
**计时与拍量边界（fix-r3 登记，评审 DS r4 concurrency#1 / boundary#5、r5
boundary#1 / concurrency#2；fix-r7 起点改为排空起表，评审 DS r7 concurrency#2 /
boundary#1）**：写侧断言使排空侧**正跑**多一条失败条件——排空静默窗与 1 s
硬上限都从**服务端写完响应（进入排空）**起表（`http_store.rs:3631-3643`），
故从服务端响应写出到末拍的任一点停顿——含客户端读响应前的调度延迟、读
响应本身、任意两拍之间的 sleep 调度点——超过排空静默窗（单次 read
100 ms），或整段 dribble 超出 1 s 硬上限时，服务端已关闭（100 ms 静默分支
通常 FIN；1 s 截断分支排空有界截断后仍可能 RST，见「Rust 行为」），后续拍
EPIPE/ECONNRESET ⇒ `Errored` ⇒ 未变异钉子假红（首拍可能先落本端发送缓冲
成功、错误在后续拍以 RST 返回；旧 close-kind 轴同交错在 Linux 仍绿；两平台
实测与 lib 回归全绿未观察到该交错，正跑偶发红按此排查——含「读响应前
>100 ms 调度延迟」这一臂；单拍写超时臂的定义见「机器判据」）。两钉采信
口径见「平台边界」（唯一正本），拍量数值见「机器判据」的 Rust 侧永久钉
条目。拍量抬升、拍间隔与 RST 往返的机制实测、`Errored` 臂的已提交直钉
自检、尺子零值护栏、Rust 侧确定性措辞注释（`http_store_tests.rs:450` /
`:1187-1189` 等多处，同文件全量随拍量抬升一起改）与正跑计时不确定性
（拍间延迟测量 / 该 cell 重跑）跟 #2852。

## 范围

- 只登记**准入早退与守卫 431 的连接结局**：解析层拒绝 × 体已读 / 未读（≤ 与 >
  解析缓冲）× 关闭类型。不涉 001 已登记的接线 / 金样 / 旋钮钉；431 的
  `force_node_response` 可达性（001 已知偏差②）与裸 400 字节形状（已知偏差①）
  不在本条，也不因本条实测扩大豁免面。
- **CONNECT 的覆盖边界（fix-r3 补，评审 DS boundary P2c）**：CONNECT 是
  `node_parser_admission` 唯一以 `Err(io::Error)` 返回的准入拒绝
  （`native_http.rs:250-256`），`http_store.rs:3392` 的 `?` 在排空接线块之前
  传播，故 fix-r2 的排空接线对它**不生效**；本条 CONNECT 格只覆盖**零体**
  （0 响应字节 + FIN），CONNECT+未读体不在三条路径与 16 格矩阵内、未实测。
- 分歧方向登记（Linux 实测）：llhttp 级拒绝 + 超缓冲未读体是 **Node RST /
  Rust FIN**——Rust 侧无「慢客户端未及读走 400 即被 RST 丢弃」竞态，按 Rust
  严格更优雅登记为传输层呈现差异，不对齐（向 RST 对齐既伤用户也无判分意义）。
  修前 macOS 曾实测到 Node FIN / Rust RST 的时序格（缺 Host + 1 MiB，评审轮），
  修后 Rust 排空接线使该格与 Node 一致 FIN，不再登记为分歧。
- sms 车道同族早退（`channel/sms/admission.rs`）的 CONNECT 零字节关闭由
  #2773 r2 追加的独立钉固定（`connect_pin_is_the_zero_byte_destroy`），本条
  范围只在 user_dialog HTTP store；sms 侧**关闭类型未测**——其两个孪生钉只
  断言零字节/裸 400 字节形状，不验 FIN/RST（跟进 #2835 条 2）。
- **姊妹车道未测声明（fix-r2 补，评审 DS sibling#1 P1；fix-r3 扩，评审 DS
  sibling#2 / MM boundary#2）**：同一个 `node_parser_admission` 闸在其余监听器

  `channel/api_server/server.rs:440`——**未测、未接线**，其关闭类型不在本条
  登记；这些车道的重放尺子仍是 `Ok(Err(_)) => closed = true` 布尔
  （`native_http/tests.rs:252`、`api_web/tests.rs:379`、`module_host/tests.rs:746`、
  `approvals/tests.rs:849`，以及 fix-r3 补登的第 5 处同款

## 机器判据

- **尺子（P1-a）**：`http_store_tests.rs` 的 `exchange_until_eof`
  （`:430`）返回 `(Vec<u8>, ServerClose)`，`ServerClose`（`:406`）分
  Fin / Reset / StillOpen 三态——`Ok(Err(ECONNRESET))` 不再计入 closed；调用点
  按 `early_response_raw` 逐格断言 FIN。姊妹车道的重放尺子仍把 RST 记作
  closed 的布尔（与本条三态口径的差异边界见「范围」的姊妹车道未测声明，
  接线与分型跟进 #2835）。
- **尺子自检（fix-r2 补，评审 DS sibling#4）**：
  `server_close_ruler_pins_reset_and_still_open` 用本地 listener 直钉两臂——
  `SO_LINGER 0` 关闭 ⇒ `Reset`（不判响应字节：RST 可刷队列，响应形状不是该
  关闭类型的确定性质）、永不关闭 ⇒ `StillOpen`——不依赖任何准入时序，退回旧
  布尔语义（`Ok(Err(_)) => Fin`）时该钉当轮红。
- **dribble 尺子（fix-r2 补，评审 anthropic concurrency#1 P1）**：
  `exchange_dribbled_after_response`——客户端写头 → 先收全响应（负控绑定的
  响应字节断言先过，拆线变异不会把响应字节 RST 刷掉而变成非锚定 panic）→
