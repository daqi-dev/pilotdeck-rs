## 类别

补登 #2774 的实测仲裁：解析层准入早退的**连接生命周期记账**。原条目（001）登记
了接线与两格金样重放；三家评审同撞指出早退 `return Ok(rejection)` 发生在 serve
路径的 `body_pending → mark_unread_body_close()` 排空接线之前，其连接结局（响应
是否送达、关闭是 RST 还是 FIN）无实测记账。本轮 Node v22.22.0 + 裸 socket 实测
（见「基线依据」）结论：**不存在「Node FIN 而 Rust RST」的格**，故不改
`mark_unread_body_close` / body_pending 排线（`http_store.rs` 产品代码零改动）；
唯一分歧格（llhttp 级拒绝 + 超出解析缓冲的未读体：Node 送达响应后 RST，Rust
FIN）按 Rust 严格更优雅一侧登记为传输层呈现差异。本条同时把 001 基线依据中
「读码 + 家族先例推断，本车道未另做裸 socket 探针」升级为本车道自有实测，并
以其 `connect` 格关掉 001 机器判据③（CONNECT 只有读码、无实跑格）。本条不
新增判分豁免；未批准，非已接受差异。

## 基线依据

固定基线 `cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85`，Node v22.22.0（本轮复核
`node --version` 为 v22.22.0）。真实 `http.createServer`（无 options，
`HttpGatewayUserDialogStore.ts:236` 同形）且**不注册 `clientError` 监听**——grep
全仓证实基线无任何 `clientError` 覆盖，Node 默认行为即基线行为。探针
`node-arbitration/probe.mjs` 与原始输出 `probe-final.out`（本轮会话证据目录
`_tmp/20261026-issue-2773/`，原始输出全文亦抄入该轮 RESULT.md，任务书指定由
协调者收货后代贴 #2774 评论）。逐格实测（客户端一律裸 `net.Socket`，记录响应
字节与关闭类型：`end(FIN)` 还是 `error ECONNRESET`）：

- admitted 对照（POST + `Connection: close` + 10 B 体）：122 B `200` + FIN——
  证探针能看见优雅 FIN 与 handler 是否被触达（handler 仅答 200，日志证明
  FROB / missing-host 格从未到达 handler）。
- llhttp 级拒绝（未知方法 `FROB`、非 ASCII target、无冒号头行、20 KB 超预算
  头），小体（≤ 解析缓冲）：裸 `400`（47 B：`HTTP/1.1 400 Bad Request\r\n
  Connection: close\r\n\r\n`，无 `Date`、无 `content-length`）/ 裸 `431`
  （67 B），随后 **FIN**。
- 同族 + 1 MiB 未读体（与请求头一次写出）：响应字节**先完整到达**，然后
  **RST**（`data 47B` → `error ECONNRESET`，无 FIN）。
- HTTP/1.1 缺 `Host`（`_http_server.js` 级拒绝），任意体量（含 1 MiB）：全量
  `400`（117 B：`Connection: close` + `Date` + chunked 空体 `0\r\n\r\n`）后
  **FIN**——Node 在该路径排空了未读体。
- CONNECT：**0 响应字节** + FIN（零字节关闭，与 #2152 读码口径一致；本格即
  001 机器判据③ 缺的实跑）。
- 客户端写完即 FIN：响应 + FIN；体在拒绝写回后才 dribble：响应 + FIN，迟到
  写 EPIPE。

## Rust 行为

`src/pilotdeck-gateway/src/user_dialog/http_store.rs` 的准入早退
（`parser_admission(&request, &timer)?` → `return Ok(rejection)`，3383-3387）
本轮以同一格实测（临时探针，交付时换成永久钉，见「机器判据」）：裸 `400`
103 B（hyper 归一化 `content-length: 0` + `date`——001 已登记的呈现残差，本条
不重登）、全量 `400` 117 B，**全部 FIN（EOF 之后再读一次亦无 RST）**；CONNECT
0 字节 FIN；withheld 体 / 客户端先 FIN / dribble 与 Node 同形。机理
（`~/.cargo/registry/src/*/hyper-1*/src/proto/h1/`，dispatch.rs / conn.rs）：
service 返回时 body receiver 被 drop，dispatcher 调
`poll_drain_or_close_read`（尽力排空读侧），`poll_shutdown` 只做
`shutdown(Write)` → FIN。因此早退路径虽不经 `mark_unread_body_close`，响应
字节也先于关闭送达、且关闭是 FIN——「Node FIN 而 Rust RST」需要修 drain 排线
的处置分支不成立，产品代码零改动。

## 范围

- 只登记**准入早退的连接结局**：解析层拒绝 × 体已读 / 未读（≤ 与 > 解析缓冲）
  × 关闭类型。不涉 001 已登记的接线 / 金样 / 旋钮钉；431 的
  `force_node_response` 可达性（001 已知偏差②）与裸 400 字节形状
  （已知偏差①）不在本条，也不因本条的实测扩大豁免面。
- 唯一分歧格（llhttp 级拒绝 + 超缓冲未读体：Node RST / Rust FIN）登记为
  Rust 严格更优雅：Node 的 RST 带「慢客户端未及读走 400 即被 RST 丢弃」的
  竞态，Rust 的 FIN 无此竞态，两侧响应字节均送达。不对齐 RST（向 RST 对齐
  既伤用户也无判分意义）。
- sms 车道同族早退（`channel/sms/admission.rs`）的 CONNECT 零字节关闭由
  #2773 r2 追加的独立钉固定（`connect_pin_is_the_zero_byte_destroy`），本条
  范围只在 user_dialog HTTP store。
