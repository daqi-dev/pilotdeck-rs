## 类别

补登 #2774 的实测仲裁与 #2773 fix-r1 的更正：解析层准入早退的**连接生命周期
记账**。原条目（001）登记了接线与两格金样重放。r1 初稿据 worker 的 Node 实测 +
读码推断登记「不存在 Node FIN 而 Rust RST 的格 → 产品代码零改动」；三家评审
（anthropic + DS + MM）同撞推翻该结论的证据基础：worker 的 Rust 侧探针
（`rust-probe.out`）**没有任何 1 MiB 格**，「Rust FIN」与「不存在分歧格」两条
结论建立在没有实测的格上，且评审轮本机实测看到了相反格。fix-r1 以三组实测
（评审轮 macOS 探针、本车道 macOS 修前/修后矩阵、CI Linux 修前矩阵）重写本条：
修前 Rust 在「带未读体拒绝」格上的关闭类型**时序敏感、平台间不稳定**（同格在
两组 macOS 实测里互相翻转，Linux CI 未触发竞态但同样未接线保证）；fix-r1 补齐
准入早退与守卫 431 两条路径的排空接线（`mark_unread_body_close()`），并把尺子
（`exchange_until_eof`）从「EOF 即 closed」升级为 FIN / RST / StillOpen 三态，
使任何回归到 RST 的关闭在钉子上显式失败。fix-r2（同轮二家评审 anthropic
concurrency#1 P1 / DS sibling#1 P1 / DS boundary#1 P1 续修）继续增补：两条
绑定钉改为确定性 dribble 构造并加 `ServerClose` 尺子自检、负控改 N 跑协议、
范围与平台边界逐线声明（见对应节）。本条不新增判分豁免；未批准，非已接受

`net.Socket`，原始输出 `_tmp/20261026-issue-2773/r1/artifacts/round/
node-arbitration/probe-final.out`，仲裁回执已代贴 #2774 评论，存档副本
`_tmp/20261110-issue-2773-fix-r1/r1/2774-receipt-original.md`）：

- guard-431 格（超预算头 + 末行不完整，中途头内触发）：本车道补测 Node v22.22.0

## Rust 行为

`src/pilotdeck-gateway/src/user_dialog/http_store.rs` 的三条关闭路径：

1. serve 路径（已接线）：`body_pending && Connection: close →
   mark_unread_body_close()`（`http_store.rs:3479` 一带）。
2. **准入早退（r1 初稿漏接线，fix-r1 补齐）**：`parser_admission` 早退
   `return Ok(rejection)` 发生在上述接线之前，是唯一「带未读体关闭却不排空」
   路径——fix-r1 在早退前按同条件补 `mark_unread_body_close()`
   （`http_store.rs:3410` 一带，评审 MM concurrency P1）。
3. **守卫 431 中途头内触发（fix-r1 新发现的第三条，同补齐）**：超预算头
   `header_guard.push` 触发点在头未读完时 break，同样带未读字节关闭——触发点
   补 `mark_unread_body_close()`（`http_store.rs:3099`）。Node 同格 5/5 FIN 实测
   见基线依据。该置位是**无条件的**：即使请求头是 `Connection: keep-alive`，
   超预算头的 431 关闭也走排空（Node 同格立即 FIN）。差异是 ≤100 ms 量级的
   排空等待时延——对齐需读内核接收队列，不可移植，登记为已知呈现差异
   （b 档台账路线，不改产品代码）。

修前实测矩阵对读（关闭类型）：

| 格 | Node | Rust 修前 · 评审轮 macOS | Rust 修前 · 本车道 macOS | Rust 修前 · Linux CI |
|---|---|---|---|---|
| frob + 1 MiB | RST | RST | FIN | FIN |
| header-no-colon + 1 MiB | RST | FIN | RST | FIN |
| 缺 Host + 1 MiB | FIN | RST | FIN | FIN |

原始输出：`r1/macos-prefix-matrix.txt`、`r1/macos-postfix-matrix.txt`（修后
15/16 FIN，唯 header-no-colon-1m 时序格仍偶发 RST，响应字节已送达，Node 同格
也是 RST，非分歧）、`r1/ci-rust-job-round2.log`（CI Linux 修前 16/16 FIN，
run 42802288407 rust job 129782795134，head `3380b02dc` = 修前 + 临时探针，
探针提交已 revert）、汇总 `r1/linux-matrix.md`。

修后：三条已接线路径「先排空再关」，对 `#702` `drain_after_early_close`
（100 ms 静默、1 s 上限）吸收能力以内的未读体（1 MiB dribble ≈ 35 ms，
实测远在内界）FIN 确定；**超出 1 s 排空上限的未读体不保证**——排空有界截断
后的关闭仍可能 RST，与 Node 排空缓冲超限后 RST 同族，未逐格登记。第四条关闭
路径——hyper 原生解析错误（如无冒号头行）触发的连接收尾——**未接线**：Node
同格实测本就是 RST（基线依据「响应字节先完整到达，然后 RST」），Rust 未接线
行为与之不构成 FIN/RST 分歧，不在本条登记。修前 Linux 全 FIN 只说明竞态在
CI 时序下未触发，不构成「不接线也安全」的证明。

**杀灭力边界（fix-r2 追加，评审 anthropic concurrency#1 P1）**：修后侧 FIN
确定，但拆线侧的关闭类型仍由「close 时内核接收队列是否有未读字节」的时序
决定——旧的一发写全构造下，`6/6 KILLED` 是一次性采样，同格在多轮实测里
互翻（见上矩阵三组对读）；修复轮一轮杀灭不足以证明杀灭力稳定。fix-r2 把
两条绑定钉改为 dribble 构造：客户端先收全响应字节，再有界分拍写剩余体
（见「机器判据」），使拆线变异必然吃 RST、修后侧必然 FIN，两侧都确定。
**平台边界**：Linux 修前实测 16/16 FIN——FIN 钉对排空接线在 Linux 时序下
无判别力，本套负控的杀灭力证据只在 macOS 取证（CI 盲区 → #2842）。

## 机器判据

- **尺子（P1-a）**：`http_store_tests.rs` 的 `exchange_until_eof`
  （`:414`）返回 `(Vec<u8>, ServerClose)`，`ServerClose`（`:406`）分
  Fin / Reset / StillOpen 三态——`Ok(Err(ECONNRESET))` 不再计入 closed；调用点
  按 `early_response_raw` 逐格断言 FIN。
- **尺子自检（fix-r2 补，评审 DS sibling#4）**：
  `server_close_ruler_pins_reset_and_still_open` 用本地 listener 直钉两臂——
  `SO_LINGER 0` 关闭 ⇒ `Reset`（不判响应字节：RST 可刷队列，响应形状不是该
  关闭类型的确定性质）、永不关闭 ⇒ `StillOpen`——不依赖任何准入时序，退回旧
  布尔语义（`Ok(Err(_)) => Fin`）时该钉当轮红。
- **dribble 尺子（fix-r2 补，评审 anthropic concurrency#1 P1）**：
  `exchange_dribbled_after_response`——客户端写头 → 先收全响应（负控绑定的
  响应字节断言先过，拆线变异不会把响应字节 RST 刷掉而变成非锚定 panic）→
  有界分拍写剩余体（frob：1 MiB / 32 KiB 拍 / 1 ms 间隔 ≈ 35 ms，远在 1 s
  排空上限内）→ `read_to_end` 三态分类。确定性：排空侧吸收全部拍后 100 ms
  静默 ⇒ FIN；拆线侧在响应后立即关闭，后续拍必然落在关闭后 ⇒ 内核 RST ⇒
  `Reset` ⇒ 绑定断言以锚定消息红。
- Rust 侧永久钉：`user_dialog::http_store::http_store_tests::
  parser_rejection_with_unread_body_delivers_and_closes`（FROB 头声明 1 MiB 体
  不发 → 准入 400 先完整到达，再 dribble 1 MiB ⇒ **FIN**；withheld 体；
  headless 全量 400；CONNECT 0 字节）；守卫 431 边界钉
  `header_guard_beats_hyper_buffer_cap_at_the_boundary`（首写越计数线 6,600
  值字节 + 尾部 9,768 dribble ⇒ 431 + **FIN**）。所有失败点带 `#2774` 标记。
- sms 侧 CONNECT 钉：`channel::sms::tests::connect_pin_is_the_zero_byte_destroy`

  `head_timeout_tests.rs:57-92` 的 189xx 台账，#2773 A2 唯一正本）。
