## 类别

#1022 fix-r2 更正 R2 的预算边界及批准措辞；不修改冻结评分语义。

## 基线依据

TS cc7c4e6 没有 Rust 的 writer 忙等预算。真实 writer 交错与 48 格依据沿 R2；本项不声称 TS 有该超时字段。原始记录索引在 `_tmp/20261026-issue-1022/fix-r2/RESULT.md`。

## Rust 行为

`FactoryOptions.writer_busy_wait_timeout` 只约束前驱 drain 与忙的进程 writer 锁等待。前驱完成后立即保存剩余预算，随后最终 `drained_file_state()` 快照读取不扣此预算。prepare、storage construction、路径解析和单次 OS 文件操作的边界沿 R2；路径解析耗时仍扣进程锁可等待时间，到期仅允许非阻塞尝试。

## 范围

修复完整 snapshot 读取意外扣预算的问题，不新增墙钟总超时承诺；也不允许越过占用中的 writer 锁。

## 机器判据

`runtime::session::factory::tests::writer_busy_budget_excludes_drained_snapshot` 用同步快照内确定性推进虚拟时钟和实际占用 writer 锁，验证快照耗时不扣忙等预算。配对变异 `r2-snapshot-spends-budget` 将扣费移回快照后，绑定该测试专属失败消息。既有 never/timeout/FIFO/cancel 测试继续约束等待终止和排他。

## 批准记录

未批准，非已接受差异。R2 的“AI 代批，待人复核”只表示范围内实现判断，不能代替差异的人批；本更正不增加评分豁免。fix-r2 用户明确要求在移出预算与扩展文档之间二选一，本轮选择移出预算。
