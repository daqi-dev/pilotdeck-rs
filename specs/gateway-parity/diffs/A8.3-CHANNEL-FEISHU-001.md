## Rust 行为

`src/pilotdeck-gateway/src/channel/loader.rs:151` `reject_unimplemented_bundle_channels`：
对 `BUNDLE_CHANNEL_KEYS = ["weixin", "feishu"]` 中未出现在装配方声明的 implemented 列表里的键，
若 `adapters.<key>.enabled` 严格等于 `true`，返回
`Err(ChannelError::Error)`，消息为
`[adapters] channel "feishu" 未迁移到 Rust，需继续使用 TS gateway`。
`IMPLEMENTED_BUNDLE_CHANNEL_KEYS = ["weixin"]`（`src/pilotdeck-gateway/src/native_process/channels.rs:44`）
是本装配真正构造的键集合，故 `weixin` 不拒、`feishu` 拒。

`src/pilotdeck-gateway/src/native_process/assembly.rs:493` 在配置快照读入后、`NativeChannels`
构造前调用该闸门；`Err` 经 `return Err(error.into())` 向上传播出 `assembly::start` →
`native_process::run` → `main`，进程以 exit 1 结束，stderr 由 std 的
`Termination for Result` 按 Debug 打印：`Error: Error("[adapters] channel \"feishu\" 未迁移到 Rust，需继续使用 TS gateway")`。

## 范围

只覆盖「`ChannelAdapterBundle` 键里本装配尚未实现」的键，当前即 `feishu` 一个。`weixin` 已实现
（#1328），不在拒绝范围；loader 表内的 11 个未迁移键仍由 `reject_unmigrated_channels`
（`UNMIGRATED_CHANNEL_KEYS`）负责。`enabled` 判据是严格 `=== true`，与两条 bundle 构造函数的
门一致；生产路径上 `config/snapshot.rs` 的 `bool_field` 会先把 `enabled` 折叠成布尔，故
`enabled: 1` / `"true"` 之类的非布尔拼写在这里读到 `false`、不触发拒绝（与 `qq` / `wecom`
同一既有行为）。#1329 落地时把 `feishu` 加进 `IMPLEMENTED_BUNDLE_CHANNEL_KEYS` 并删掉本条
（按 `diffs/README.md` 的只追加规则，删条目要另开更正条目说明）。
