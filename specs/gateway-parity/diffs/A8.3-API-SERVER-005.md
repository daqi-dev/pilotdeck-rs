## 类别

缺口已修 + 传输层呈现差异（不可避免，继承已有条目）：原缺口是 api-server
车道**没有接** `native_http::node_parser_admission`，与 `native_http.rs`
「每个原生监听器都过同一道闸门」的注释相反；#1683 把调用点接到
`channel/api_server/server.rs::handle` 的最前面，与 webhook 车道
（`channel/webhook/mod.rs:521`）同一入口。接入后仅剩一项 hyper 呈现差异：
解析器裸 400 上 hyper 补 `content-length: 0`，Node 不写长度（与
`A8.4-NATIVE-HTTP-001` 的裸 400 同一类，本条只把适用范围扩到 api-server
车道）。本条不增加判分豁免：新增两格是**收紧**判据，不是放宽。

## 基线依据

固定基线 `cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85`，Node v22.22.0 /
ICU 78.2（本机生成机实测 `node -p 'process.versions.icu'` = `78.2`，与
`oracle.json` 的 `node` / `icu` 字段一致）。

- `src/adapters/channel/api-server/ApiServerChannel.ts:62` 用
  `http.createServer((req, res) => …)` 建监听器（无 options），所以
  解析层准入就是 llhttp / `_http_server.js` 在 handler 之前的判定。
- 裸 socket 探针（真 `ApiServerChannel`，`_tmp/20261107-issue-1683/probe/
  probe-admission.mts`，原始输出 `probe-admission.out`）逐格实测：

  ```text
  FROB /health HTTP/1.1 + Host   → HTTP/1.1 400 Bad Request\r\nConnection: close\r\n\r\n
  GET  /health HTTP/1.1 无 Host  → HTTP/1.1 400 Bad Request\r\nConnection: close\r\n
                                   date: <masked>\r\nTransfer-Encoding: chunked\r\n\r\n0\r\n\r\n
  GET  /health + Host（对照）    → HTTP/1.1 200 OK … {"status":"ok","platform":"api-server"}
  ```

  与 `native-http-basic` 的 `bad-method-foo` / `no-host` 两格同形。
- 生成器侧确认（`probe-set-host.mts` / `probe-set-host.out`）：Node
  `http.request` 的 `method: 'FROB'` 与 `setHost: false` 即可在既有
  `send()` 路径录到上表两行，无需给夹具引入裸 socket 协议。
- 金样格 `unknown-method` / `missing-host` 由
  `src/pilotdeck-gateway/tests/fixtures/api-server-channel/generate.mts`
  在基线上现采，`oracle.json` 记录 `sourceCommit` / `node` / `icu`。

## Rust 行为

`src/pilotdeck-gateway/src/channel/api_server/server.rs` 的 `handle` 现在以

```rust
if let Some(rejection) = crate::native_http::node_parser_admission(&request)? {
    return Ok(rejection);
}
```

开头，位于 `request_keep_alive`、`header_string(headers, "host")` 与
`Url::parse` 之前，且拒绝响应不经 `finish`（`finish` 会给缺 `Date` 的响应
补 `Date`）。因此：

- `FROB` 等不在 `LLHTTP_METHODS` 的方法 → `parser_bad_request()`：
  `400` + `Connection: close` + 无 `Date` + 零字节体；hyper 另补
  `content-length: 0`（本条登记的呈现差异）。
- HTTP/1.1 缺 `Host` → `headless_bad_request()`：`400` + `Connection: close`
  + `Date` + chunked 空体，与 TS 逐头一致。
- 非 ASCII target / 头预算 16384 / target 形态 / CONNECT 零字节关闭：同一
  函数内判定，行为与 native-http / webhook 车道共用一份实现。

## 范围

- 只涉及 api-server 车道的**解析层准入**：方法允许表、target 字节与形态、
  请求头 span 预算、HTTP/1.1 缺 `Host`、CONNECT 零字节关闭。
- 不含路由策略（`/health`、`/v1/models`、`/v1/chat/completions`、CORS、
  auth、body 上限、`requestTimeout`）：这些既有条目
  （`A8.3-API-SERVER-001/002/003/004`）不变。
- 金样只新增两格（`unknown-method` / `missing-host`）钉住本车道最常被误判
  的两条路径；其余解析层格由同一函数的 `native-http-basic` 金样承担，本条
  不复制那些格，也不声称 api-server 车道逐格覆盖了它们。
- 呈现差异只限裸 400 的 `content-length: 0` 一行；状态码、`Connection:
  close`、无 `Date`、零字节体、关闭连接均与 TS 相同。

## 机器判据

- 金样：`tests/fixtures/api-server-channel/oracle.json` 由 15 格增至 **17
  格**，新增 `unknown-method`（`FROB /health`，期望 400 / 只有
  `connection: close`）与 `missing-host`（`setHost: false`，期望 400 /
  `connection: close` + `date` + `transfer-encoding: chunked`）。
- 重放：`channel::api_server::tests::replays_real_ts_api_server_cells` 的
  精确 id 名单同步为 17 项，逐格比较状态、头、体；`ReqSpec` 读
  `setHost`（fail-closed：只接受缺席或布尔），据此决定是否写 `Host:` 行。
- 夹具守卫：`assert_parser_admission_cell_records_its_knob` 钉住两格的旋钮
  （`FROB` 不在 `http.METHODS`、`setHost: false`）与 400，防止金样退化成
  200 对照；`parser_rejections_keep_the_registered_transport_shape` 用原始
  响应字节钉住裸 400 的 `content-length: 0`（重放归一化会掩盖该行）与缺
  Host 400 的 `Date` + chunked。
- 归一化：`actual_headers(actual, parser_admission)` 只在
  `unknown-method` / `missing-host` 两格丢弃 `content-length: 0`（本条与
  `A8.4-NATIVE-HTTP-001` 的呈现差异），其余 15 格与其余头逐字比较——豁免面
  严格等于本条登记的范围，别的格若多出这一行会红（边界评审 r1 P1）。
- 空值 `Host:`（头存在、值为空）不在本条范围：实测 TS 走 handler 崩溃、
  Rust 服务，登记在 `A8.3-API-SERVER-006`。
- 负控：`tests/fixtures/api-server-channel/negative_controls.py` 新增
  `api-server-parser-admission`，把整个调用点替换成 no-op，绑
  `replays_real_ts_api_server_cells` 的
  `#1333 unknown-method request 0: status differs`；原始输出见
  `_tmp/20261107-issue-1683/`。
- 复算命令：

  ```sh
  python3 -I scripts/gateway-parity/check_frozen.py --base origin/main
  ```
