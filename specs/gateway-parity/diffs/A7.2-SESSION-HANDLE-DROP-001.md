## 类别

有意差异：资源确定性（#1010）。Rust 最后一个 handle 克隆消失时自动启动幂等
清理；TS AgentHandle 没有确定性析构。登记待复核，非已接受差异、非评分豁免。

## 基线依据

Node v22.22.0、cc7c4e6，`src/pilotdeck-gateway/tests/fixtures/session-drop-release/`
的真实 TS AgentHandle 五格金样：丢引用并 GC 后 collected=true/onDisposeCalls=0；
显式 dispose 丢 waiter 后 disposed/onDisposeCalls=1；process.exit 前尚未执行
onDispose 时计数 0；进入 release 永久门闩后退出，完成计数 release/close=0/0；
进入 close 永久门闩后退出，完成计数 1/0。后三格 stateAtExit 均为 draining。

TS 没有“进程已退出后再 drop JS 对象”的可执行对应，也没有 Rust writer RAII。
不得从 process-exit 金样推出 TS 会同步关闭 writer 或释放 Rust fence。

## Rust 行为

- 最后一个 LiveSessionHandle 克隆 drop 调用与显式 dispose 共用的幂等入口；
  捕获的 executor 存活时自定义 release/close 恰一次，调用线程无需 ambient runtime。
- captured executor 关闭或任务未首次 poll：DisposeFallback 同步取得 writer guard；
  writer 立即停止新写，独立关闭线程在 close 后释放 file/process fence，项目 lease
  计数由同步 Drop 释放。尚未执行的异步 hook 不保证执行。
- drain 已 disarm 后卡在 release/close await，shutdown 取消时由任务内 guards
  接管；完成的 hook 不重跑，未完成的 hook 不冒充成功。
- PendingSession 取消交接也最终落到相同的 handle Drop；无需重复 writer fallback。
- PreparedResources 与三个 plugin lease 的 Drop 使用捕获的 executor；plugin 的
  异步释放仅在该 executor 仍存活时保证调度，不能声称已关闭 executor 能执行 hook。

## 范围

仅 #1010 的 Drop 资源确定性与同类 off-runtime plugin lease panic 修复。TS Router /
owner shutdown 排队和 GC 时机不在本条新增范围；writer fence 语义不作调整。

## 机器判据

机器判据与每个负控的完整测试名/专属失败消息见
`src/pilotdeck-gateway/tests/fixtures/session-drop-release/negative_controls.py`。
新增真实工厂四格：`dropped_owned_session_shutdown_before_first_poll`、
`dropped_owned_session_shutdown_during_release`、
`dropped_owned_session_shutdown_during_close`、
`dropped_owned_session_after_executor_shutdown_without_runtime`。

`pending_owned_session_after_executor_shutdown_without_runtime`。

`session_lease_drop_without_runtime`、`legacy_lease_drop_without_runtime` 验证。
既有 handle/drop/prepared 用例与 TS ignored 重生成守卫继续覆盖既有矩阵。
