## 类别

传输层呈现差异（待批）：#1339 的 sms channel 自带 webhook 监听器
（hyper 1.x），其应答以语义三元组 `{status, contentType, body}` /
`{closed: true}` 回放比较，原始帧字节（状态行拼写、头名大小写、`Date`
值、头序、`Connection`/`Content-Length` 细节）不逐字节钉死，继承
A8.4-NATIVE-HTTP-001 家族登记过的帧级呈现差异类别。

## 基线依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0 /
ICU 78.2。`_tmp/20261026-issue-1339/probes/sms-edges.out` 保留真 TS
监听器的原始应答字节（如 `HTTP/1.1 200 OK\r\nContent-Type:
text/xml\r\nDate: ...\r\nConnection: close\r\nContent-Length: 59\r\n\r\n<?xml
version="1.0" encoding="UTF-8"?><Response></Response>`）；Node 与
hyper 1.x 的帧细节天然不同（同类先例：A8.4-NATIVE-HTTP-001 / -002）。

## Rust 行为

`src/pilotdeck-gateway/src/channel/sms/mod.rs`：hyper `http1` 服务产出
应答；`tests.rs` 的 `raw_request` 用原始 socket 读全部应答字节，仅归约
出状态码、`content-type` 与 body（连接被销毁时记 `{closed: true}`）与
oracle 比较。body 内容与状态码逐字节比较；头名大小写、`Date` 值等帧级
呈现不在比较范围。

## 范围

仅 sms webhook 监听器的应答呈现层；`TWIML_OK` body、`Not Found`、
`Unauthorized`、`Bad Request` 的 body 与状态码不受本条影响（各有 oracle
cell 钉死）。超过 1 MiB 的连接销毁（零应答字节）两侧一致，不在本条。

## 机器判据

`src/pilotdeck-gateway/src/channel/sms/tests.rs`：oracle 用例
`wrong-path-and-method`、`bad-signature`、`bad-json`、
`content-type-json-charset` 钉状态码 + content-type + body；`payload-too-large`
钉 `{closed: true}`（零应答字节）；负控 `sms-twiml-body` 变异 TWIML body
字节即被 `valid-signature` 用例击落。

## 批准记录

未批准，不增加判分豁免；登记于 #1339 交付评审，由协调者确定按
A8.4-NATIVE-HTTP-001 同类（帧级呈现差异，语义化归约比较）接受或另定
钉死方案。
