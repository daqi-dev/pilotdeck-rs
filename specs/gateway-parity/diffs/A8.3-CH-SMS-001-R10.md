## 类别

更正（覆盖形状被后续轮次改变，非差异变化）：`A8.3-CH-SMS-001-R9.md` 把形状
写死为「65 个 `crate::mutants::on("sms-…")` 编译期开关」「65 个开关完整负控
65/65 KILLED」，并要求 `--check` 打印 `65 switch anchors and bindings checked`。
`#1813` 处理 `#1729` 的四态口径残余同源点后，开关 65 → 66、`--check` 现在打印
`66 switch anchors and bindings checked`。按 `-R9` 字面核对必然判红（

新形状。`-R9` 原字节不动，本目录只新增本文件。

**本件不登记任何 Rust↔TS 偏离；本单改动全在测试侧，产品代码零改动，金样读值不变。**

三列依据（改前 Rust / TS 侧 / 改后 Rust）：

| | |
|---|---|
| 改前 Rust | `sms/tests.rs:1155` / `:1184`（origin/main）`required = false`；重放处 `:2290` / `:2297` `recorded_*_count(step).unwrap_or_default()` → 缺 `count` 读成 0，谓词 `len() as u64 >= count` 即 `>= 0` **恒真**，等待立即满足 |
| TS 侧 | `generate.mts:900` / `:903` `waitUntil(() => record.sends.length >= step.count, …)`；缺 `count` 时比较恒 false → `waitUntil`（`:210`）3 s 超时。实测（Node v22.22.0，从原文抽 `waitUntil` + 两个 arm 跑）：缺 `count` → `rejected: #1339 wait timeout: sends undefined`，3001 ms；`count: 0` → `satisfied`，0 ms |
| 改后 Rust | `sms/tests.rs:1215` / `:1262` `required = true`：缺 `count` → `Err` → panic；重放谓词 `:2390` / `:2397` 未改（行号为含本单提交后的 head `98a710b9`；origin/main 上是 `:2290` / `:2297`），偏离在读取处关闭 |

改后与 TS 是否仍不同：**失败形态不同，但不再假通过**。TS 是等 3 s 后报超时，Rust 是
读录制时就 panic；旧行为（立即满足）与 TS 结论**相反**，那是真偏离，本单把它消掉，
不是新增或接受一条差异。该输入在金样 54 个 `wait-sends` + 21 个 `wait-rpcs` 步里 0 例。

除条数外，`#1813` 还改了两处**绑定形状**，单看条数会漏：

- `sms-oracle-recorded-sends-count` 与 `sms-oracle-recorded-rpcs-count` 各自
  从「一条错型测试」变成「错型 + 缺席两条测试」的列表绑定——因为
  `wait-sends.count` / `wait-rpcs.count` 从可缺字段改成必填字段。
- 新增 `sms-oracle-null-sentinel`（绑
  `null_sentinels_are_absence_for_every_sentinel_field`），把「显式 `null` = 缺席」
  从五个字段各写一遍收敛成一处实现。
