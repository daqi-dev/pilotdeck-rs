## Rust 行为

`background.rs`：`EntryState.persist_seq` 在 entry 锁内按事件分配（`Entry::append`
自增并返回；settle 与 restore 对账各在自身锁内自增一次；dispose 最终写取
`u64::MAX` 永不被丢；start 路径两条直接构造的初始写用 0）。`persist_entry_static`
携带 seq 透传给 `store.write(snapshot, seq)`。
`background_snapshot.rs` `JsonFileBackgroundTaskSnapshotStore` 增加
`accepted: HashMap<taskId, u64>`，`write()` 在 `write_tail` 锁内裁决：
`seq < accepted` 即丢弃返回 `Ok(())`（被更新写取代；`==` 放行保证幂等重试不丢写），
从而把多线程落盘顺序钉回 TS 的串行顺序。此机制不构成新差异（TS 无该窗口可对拍）。
损坏拒绝四路文案：bad JSON
`Background task snapshot {path} is not valid JSON; recovery is required: Invalid JSON: {serde 明细}`
（M1：比 TS 多追 `: Invalid JSON: …` 解析明细）；version-2 与 duplicate-id 与 TS
逐字相同；invalid status 为
`Background task snapshot {path} has invalid task at index 0: status is invalid.`
（M2：TS 作 `has an invalid task at index 0; recovery is required.`，谓语结构与
结尾分句均不同）。M1/M2 为登记保留的文案差异（未批准），行为两侧均 fail-closed。
