## 类别

不可避免的 HTTP/1.1 帧呈现差异：SSE 处理器显式设置
`Connection: keep-alive`，当请求本身带 `Connection: close` 时，Node 保留
处理器的 `keep-alive` 头（随后关闭 socket），hyper 1.7 在连接状态被请求
置为 close 后强制写 `Connection: close`。本条只登记该角落，不请求判分
豁免；金样 SSE cell 使用 keep-alive 请求，不覆盖此格。

## 基线依据

固定基线 `cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85`，Node v22.22.0 /
ICU 78.2。`src/adapters/channel/api-server/ApiServerChannel.ts:303-306`
（以及 `/new` 流式分支的 `:517-519`）在写 SSE 头时显式
`res.setHeader("Connection", "keep-alive")`。Node 的 `ServerResponse`
按该显式头写出，不因请求的 `Connection: close` 改写；连接在响应结束后
仍按请求语义关闭。

实测：金样生成器最初对 SSE 请求发送 `Connection: close`（Node
`http.request` 在 `agent: false` 下的默认行为），TS 返回的头仍是
`connection: keep-alive`。该轮对比的原始输出在
`_tmp/20261026-issue-1333/test-replay-3.log`：Rust 侧为 `close`，期望
（TS oracle）为 `keep-alive`，其余头与体一致。随后生成器把 SSE 请求改为
keep-alive（正常 SSE 客户端行为），`oracle.json` 只保留该形态。

## Rust 行为

`src/pilotdeck-gateway/src/channel/api_server/server.rs::sse_response`
设置 `Connection: keep-alive`，`finish` 对已存在的 `Connection` 不覆盖；
但 hyper 1.7 的 `proto/h1/conn.rs::enforce_version` 在
`KA::Disabled`（请求带 `Connection: close`）时无条件插入
`Connection: close`，公开 API 无法抑制。最终线缆为 `close`，SSE 体、
chunked 帧、`[DONE]`、状态码、`X-Hermes-Session-Id` 均与 TS 一致。

## 范围

仅“SSE 响应 + 请求 `Connection: close`”这一组合（buffered / JSON 响应
本就应随请求关闭，无差异）。keep-alive SSE 请求、所有非 SSE 请求、
OPTIONS/404/鉴权错误、CORS 头、超限体关闭均不受影响。该差异只影响
`Connection` 头的一个取值，不影响流内容或连接最终关闭。

## 机器判据

`src/pilotdeck-gateway/src/channel/api_server/tests.rs::sse_close_request_uses_hyper_close_header`
以 `ReqSpec::post`（`keep_alive: false`，客户端发送 `Connection: close`）
请求 `stream: true`，断言 Rust 返回 `200`、`connection: close`、体含
`data: [DONE]`。金样 `oracle.json` 的 `stream` / `new-command` /
`gateway-missing` SSE 请求均为 `connection: keep-alive`，由
`replays_real_ts_api_server_cells` 逐字节比对（掩码后）。原始 TS/Rust
对比见 `_tmp/20261026-issue-1333/test-replay-3.log`。

## 批准记录

未批准，非已接受差异。本条只登记 hyper 无法经公开 API 消除的帧级差异，
不增加判分豁免；`#1302` 的范围批准与 `#1333` 的任务书均不构成对本差异
的批准。
