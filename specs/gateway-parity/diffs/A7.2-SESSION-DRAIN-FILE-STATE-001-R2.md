## 类别

#1022 fix-r2 对正常清理完成、panic 终止及取消后错误交付的补充；修复自身生命周期保证与实现矛盾。

## 基线依据

cc7c4e6 `src/agent/scope/AgentHandle.ts:235-297` 的真实 `AgentHandle.dispose`，Node v22.22.0 经 `session-disposal-retry/generate.mts` 实测：正常完成、同步 throw、异步 reject、未等待初次 Promise 四格均复用同一 disposal Promise；失败会保留 AggregateError，disposer 只执行一次。金样 `session-disposal-retry/oracle.json` 含源码闭包哈希。TS 没有 Rust future drop、unwind 或 writer lease，本项不把这些机制称为实测对齐。

## Rust 行为

只有正常执行完整清理聚合且 activity 已退出，才可能视为 recreation drain 完成。普通清理 Err 必须被 factory waiter 实际消费后才能跳过；send 成功不足以证明消费。owner 后台 worker 消费该 Err 时继续保留在旧 Record，外层 waiter 真正接收后按错误对象身份清除；较旧 waiter 不能清除后来错误。

panic 只会终止 handle，不表示清理完成。即使没有活动 turn，重试也返回缓存 panic Err，不进入 replacement storage 构造。原 adapter 显式清理完成且实际 writer 租约取得后，独立创建才可继续；不通过忽略 panic 来释放新 writer。

## 范围

R1 的成功重试保留 drain 后 seed 仍有效；普通已交付清理错误后的 factory 重试能力是 Rust 差异。未消费错误的重放只覆盖仍由 owner 保留的会话 Record；显式 close/shutdown 按既有 disposer 结果处理。Rust panic 不自动重跑未知进度的 cleanup hook。

## 机器判据

`factory_tests.rs` 中 `recreation_idle_{guard,dispose}_panic_cannot_skip_drain`、`recreation_{cancelled,unconsumed}_{factory,owner}_error_is_replayed`、`recreation_old_error_waiter_cannot_clear_new_error` 覆盖 panic、两层取消、发送后取消与旧错误确认交错；R1 的 dispose-error/timeout/seed-error/active-turn 重试格保留。新 TS 金样配 `disposal_retry_regenerates_identically` ignored 守卫；对应 `session-factory/negative_controls.py` 的 `r2-*` 变异均绑定完整测试名和专属断言。
