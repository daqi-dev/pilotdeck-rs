## 类别

有意差异：资源确定性（#1010 fix-r2）。补充构造前提、shutdown 终态与错误语义，
并明确 plugin lease 未解决的边界。原条目不改字节；仍未批准、非评分豁免。

## 基线依据

沿用 `src/pilotdeck-gateway/tests/fixtures/session-drop-release/` 的真实 AgentHandle
五格金样及 Node v22.22.0 重生成守卫。TS process-exit 三格只说明退出前的异步截止：
未开始、release 永不完成、close 永不完成；不能推出进程退出后还能返回结果。
Rust runtime 捕获、Mutex poison、任务取消没有可执行的 JS 对应，不称这些格与 TS 对齐。

## Rust 行为

- `LiveSessionHandle::new` 必须在当前 Tokio runtime 内构造；
  `PreparedResources::push` 首次登记同样要求 runtime（后续登记复用捕获的 executor）。
  两 API 的 rustdoc 明确 `# Panics`；不是支持任意同步上下文构造的 API。
- executor 已死或任务未首次 poll，fallback 取得 writer guard 后发布 `Disposed` 与
  `Session lifecycle executor stopped.` 错误；重复 `dispose()` 共用结果。
  `disposal_completed` 保持 false，不把跳过的异步 hook 视为完成。
- drain 已首次 poll 后被 shutdown 取消，返回 `Agent session dispose task cancelled.`；
  真正 unwind 返回 `Agent session dispose task panicked.`。两者都不授予完成资格。
- handle / activity / dispose guard 的 Drop 路径恢复 poisoned mutex 内值后收尾，
  不因已有 poison 再次 panic。此保证不扩张为任意第三方析构 panic 均可恢复。
- **尚未修复**：三个 plugin lease 的 executor 已死时，异步 `release_lease_plugins`
  不会执行，`lease_counts` 可保留，其他存活 runtime 上的 `dispose()` 可一直等待。
  原条目“executor 存活时保证调度”不等于 executor 关闭后保证回收计数。可靠兜底
  必须覆盖异步状态锁争用、显式 release 取消与重复释放、退休 disposal 唤醒；本轮
  未实现，前置于 #1010 生命周期验收 / A7.2 资源释放收尾，不得据本 PR 宣称此边界完成。
