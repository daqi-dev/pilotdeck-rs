## 类别

更正 + 补测边界：R1（`diffs/A7.2-LIVE-DROP-COMPLETION-001-R1.md`）写明「本次没有实测 status 写入失败与 Drop 同拍，不将这一组合记为通过」。本次用 Node v22.22.0 与真实 cc7c4e6 TS 组件实测该组合，把实测结果与 Rust 现有行为的边界写清。原条目与 R1 原字节不动，不增加判分豁免。

## 基线依据

固定 `cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85`，Node v22.22.0。探针 `_tmp/20261106-1219/ts-probe/status-fail-drop.mts` 直接加载真实 `TurnRunner` / `AgentSessionEventRecorder` / `JsonlTranscriptWriter` / `SessionRuntime` / `JsonlSessionPersistence`，只在 `agent_status_message` 这一条 durable 写入上注入 `failureMode: 'propagate'` 的错误（`recording write failed`），并按三种顺序驱动同一个 turn：写盘失败后立刻 `return()`、`return()` 后写盘失败、只失败不 `return()`。原始输出 `_tmp/20261106-1219/ts-probe/status-fail-drop.json`，逐格持久转录 `_tmp/20261106-1219/ts-probe/forward-status_fail_*.jsonl`。

三格结果一致：宿主前缀 `[turn_started, input_accepted, user_prompt_submitted]`；消费者从 `next()` 得到 `agent_status`（失败状态）；`completeTurn` 恰 1 次（`completes: 1`）；持久转录恰 1 条 `turn_result`，`type` 为 `error`（`durableTypes: [turn_started, accepted_input, turn_result]`，`turnResultCount: 1`）；status 写入尝试 2 次（loop 内一次 + catch 的失败状态一次）且都失败（`attempts: 2`）。带 `return()` 的两格不再交付 `turn_failed` / `turn_completed`（`drained` 只剩 `done: true`），但持久 `turn_result` 已落盘；只失败不 `return()` 的一格继续交付 `turn_failed`（`agent_invalid_state` / `recording write failed`）与 `turn_completed`（result `type=error`、`stopReason=model_error`、`turns=0`）。

可重跑：`PDRS_BASELINE=<cc7c4e6 检出> node --experimental-strip-types _tmp/20261106-1219/ts-probe/status-fail-drop.mts <输出目录>`；脚本自身断言 `process.version === 'v22.22.0'`。

## Rust 行为

不变。Rust 的 Drop 取消该 turn 的 async transition；已经进入的 blocking status append 由 worker 跑完（成功或失败）并保留同一 `ActiveTurn` / `RuntimeLease`，但没有消费者时不再启动 catch 的补偿写入，因此「status 写入失败与 Drop 同拍」下持久 `turn_result` 为 0（`forward_tests.rs::forward_status_fail_drop` 实测，见机器判据）。

与上文 TS 实测对照：TS 在该组合下仍留下 1 条 `type=error` 的 `turn_result`（catch 路径在生成器被 `return()` 抢先之前已跑完 `completeTurn`），Rust 为 0。这是本条登记的实际边界。

## 范围

在 A7.2-LIVE-DROP-COMPLETION-001 原范围（complete I/O 挂起期间销毁整个 LiveTurn）之外，追加「status durable 写入失败与 Drop 同拍」。仍不含「取消一个 next 借用」——那必须继续同一 transition。

对齐实现需要为失败路径引入脱离消费者的终结任务（谁持有 slot/lease、错误归属、是否重复写），属于原条目已声明「必须另行定义」的范畴，本次不做，只登记边界。
