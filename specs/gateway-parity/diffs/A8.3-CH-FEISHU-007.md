## 类别

不可避免（基线是未捕获异常，复刻它没有意义）。`/feishu/webhook` 收到
可解析为 JSON `null`（或其它非对象标量）的 body 时，TS `parseInbound`
在 `typeof raw.encrypt` 上抛 `TypeError`，`handleWebhook` 抛出、
`handleHttpRequest` 的 promise 无人 catch（`void handleHttpRequest(...)`），
请求拿不到任何响应、gateway 侧留下 unhandled rejection；Rust 把它当作
无法识别的事件，按忽略分支回 `200 {"ok":true}`。

## 基线依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0。
`src/adapters/channel/feishu/FeishuChannel.ts` `private parseInbound(body: string)`：
`JSON.parse` 在 try 内只兜语法错，随后 `if (typeof raw.encrypt === "string" && this.encryptKey)`
对 `raw === null` 直接抛 `TypeError: Cannot read properties of null`；
`src/gateway/server/GatewayServer.ts:65` `void handleHttpRequest(request, response, options, auth.token, loopback);`
没有 `.catch`。实测入口：向 `/feishu/webhook` POST `null` 即可复现
（无需真实飞书账号；该 cell 不并入金样矩阵，见「机器判据」）。

## Rust 行为

`src/pilotdeck-gateway/src/channel/feishu/parse.rs:50-58`：`parse_json(body)`
成功后取 `string_prop(&raw, "encrypt")`，非对象 body 上取不到属性，
解密门不触发，最终走到 `ParsedEvent::Ignore`；`mod.rs:454` 回
`200 {"ok":true}`。`null` 之外的非对象标量（数字、字符串、`true`）在 TS
同样拿到 `typeof raw.encrypt === "undefined"` 而不抛——**只有 `null`/`undefined`
一档会抛**，其余两侧一致。

## 范围

仅「合法 JSON、但顶层为 `null`」这一格的 HTTP 结果与连接结局。不含：
非法 JSON（两侧都忽略、200）、`encrypt` 解密失败（两侧都 ignore，
Rust 额外记一条 error 日志、文案不同）、`url_verification` / 事件的字段级
语义（金样覆盖）。本条不构成判分豁免；风险面为零（真实 Lark 不发 `null`）。

## 机器判据

- `src/pilotdeck-gateway/src/channel/feishu/tests.rs` 的 `null` body 用例
  钉死 Rust 侧「200 + `{"ok":true}` + 不入站」，防止未来改动把它变成
  500 或挂起；
- 该格**不进**金样矩阵：TS 侧记录它需要捕获 unhandled rejection 或
  socket 超时，属于「基线无响应」，写进 `oracle.json` 只会把不可复现的
  时序固化成期望。生成器在 README 里注明这一格由 Rust 侧组件钉子覆盖。
