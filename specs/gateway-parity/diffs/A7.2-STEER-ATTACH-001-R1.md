## 类别

更正。基础条目 A7.2-STEER-ATTACH-001「范围」一节写「状态门顺序已对齐 TS：先状态后附件」，该措辞过宽：fix-r3 版本的 Rust 把**全部**状态门（含 `current_steer_info` 的 run-ID 门）放在附件拒绝之前，而 TS 只有 admission 两分支先于附件；本次（#1307 fix-r4）把附件拒绝移到 admission 两分支之后、`current_steer_info` 之前，顺序才与 TS 一致。类别本身（未实现 + 显式拒绝）不变。

## 基线依据

固定基线 `cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85`。fix-r4 重读核实：`InProcessGateway.ts:1859-1862` `steerTurn` 先做 `activeTurnRunId` 的 `no_active_turn`（`:1861`）/ `turn_mismatch`（`:1862`）两分支；随后**立即** `:1864-1870` 准备附件（`input.attachments ?? []` + `prepareAttachmentTurn`）；会话/运行资源状态判定在更晚的 `router.steer`（`:1878-1883` → `SessionRouter.ts:307-314` 无 session record 返回 `no_active_turn`，`AgentSession.ts:290-297` 状态非 running / 无 currentTurnId 返回 `no_active_turn`）。即 TS 的顺序是：admission 两分支 → 附件准备 → 资源/会话门。

## Rust 行为

`src/pilotdeck-gateway/src/native_process/methods/steer.rs`（#1307 fix-r4 起）：`handle_steer_turn` 的非空 `attachments` 拒绝位于 admission 两分支（no_active_turn / turn_mismatch）之后、`active_turn_for`（对应 router.steer 侧资源/会话门）之前。fix-r3 版本把 `current_steer_info` 放在附件拒绝之前，错序的可见差异：admission 匹配但 steer 资源未 staged / 槽位 run 不符时，fix-r3 返回 `no_active_turn`，而 TS 会先做附件准备（本切片即先给 `STEER_ATTACHMENTS_UNSUPPORTED`）。

## 范围

仅顺序描述更正；不影响基础条目的其余内容：非空 `attachments` 显式拒绝、`uploadedAttachments` 两侧一致忽略、`cancel_steer` / `submit_turn` 不涉及、#1444 完整合入前置等均不变。

## 机器判据

`src/pilotdeck-gateway/src/native_process/methods/tests.rs::steer_turn_attachments_sit_between_admission_and_resource_gates`：turn_mismatch + 非空 attachments 断言 `turn_mismatch`（admission 分支先于附件）；admission 匹配但无 steer run / 槽位 run 不符 + 非空 attachments 断言域码 `STEER_ATTACHMENTS_UNSUPPORTED`（附件先于资源门）。负控：`_tmp/20261105-issue-1307-fix-r4/`（附件拒绝移回 `current_steer_info` 之后，变异 KILLED）。复算：`cargo test -p pilotdeck-gateway steer`。
