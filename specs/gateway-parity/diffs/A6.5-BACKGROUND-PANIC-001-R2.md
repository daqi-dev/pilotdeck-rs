## 类别

bug 修复（#1233）：原条目登记的 flush 错误契约差异（Rust 吞错返回 ()/Disposed，TS
拒绝并留 draining）已按 #1162-b 对齐消除；本条为对该登记的事实更正，不改其余登记。

## 基线依据

cc7c4e6 `src/task/runtime/BackgroundTaskRuntime.ts:437-450`：dispose 的最终
`store.flush()` 拒绝使共享 disposePromise 拒绝、state 留 "draining"，后续
`dispose()` 复用同一拒绝。Node v22.22.0 实测
`src/pilotdeck-gateway/tests/fixtures/background-persist-restart/oracle.json` 的
dispose-flush-reject 与 dispose-flush-sync-throw 格：outcome
`rejected: #1233 flush refused`、state `draining`、startError
`Background task runtime is draining; refusing a new task.`。原始输出在本轮
工作树 `_tmp/20261026-issue-1233/node/persist-restart-run1.out`（run2/run3 复跑一致）。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/background.rs` `dispose_now()`：最终 flush 经
`tokio::spawn` join，io 错误与 panic payload（`cleanup_task::panic_message`）都转为
`BackgroundTaskError`；失败时 phase 保持 Draining。`Inner::disposed` 为
`watch::Sender<Option<Result<(), Arc<BackgroundTaskError>>>>`：`dispose()` 返回
`Result<(), BackgroundTaskError>`，晚到与二次 dispose 复用 watch 中 memoize 的同一
拒绝；`BackgroundResources::dispose`（RuntimeResources）把该错误映射为
`RuntimeError` 传播（对齐 TS disposeRuntime 的 try/finally 传播）。

## 范围

本条只更正 flush 错误契约。snapshot write panic 仍按原条目（继续余项、终态推进）；
诊断不回放、TS settleEntry write 与 Rust dispose 最终 write 是不同调用点，均不变。
settle 写盘失败仍通知（#1233 D5）、hasDurableOutput 语义（D6）、start 二次
persistEntry（D7）在 `A6.5-BACKGROUND-PERSIST-001-R2.md` 登记，不在本条。

## 机器判据

`tests/background_persist.rs::dispose_flush_failure_stays_draining_and_memoizes_the_rejection`
（拒绝、留 draining、二次 dispose 复用）与
`background_resources_dispose_propagates_the_flush_rejection`（RuntimeError 传播）；
`background/panic_tests.rs` flush 失败族的 phase/结果断言按 mode 分支（同步
throw/poll reject/普通 Err/成功）。`background-panic/negative_controls.py` 的
flush-join / empty-flush-join（吞掉冲刷拒绝）、retain-disposed（丢弃 memoize）、
wake-disposed（不唤醒观察者）为该契约的逐项源码变异负控。
