## 类别

有意改进。TS `terminal()` 先落盘、后 clone/parse，坏 seed 会带着已持久化的 terminal 一起抛错（磁盘被污染、重开同错）；Rust 在 append 前完成同一校验，磁盘保持干净。向安全偏离，不回退。

## 基线依据

cc7c4e6 的 `src/agent/modules/transport/sessionOperationLedger.ts:97-130`（`terminal()`：`:108-125` 先 `await recordSessionEvent(...)` 写盘，`:128` 才 `record.terminal = cloneKnownTerminal(input)`）、`:362-374`（`cloneKnownTerminal`）、`:386-389`（`cloneSeedState` = `serializeAgentLoopSeedStateProjection` 后紧跟 `parseAgentLoopSeedStateProjection`，后者对坏 Map 值抛 `Invalid readFileState entry: <path>.`）；`src/agent/modules/checkpoint/seedStateProjection.ts:9-24` 与 `:52-63`（parse 抛错点）。实测（Node v22.22.0 + 基线 tsx 4.22.3，`_tmp/20261026-issue-201/probe-run-2.out` T1）：可序列化但不可解析的 seed 在 TS 下在线抛错但事件已 3 条落盘，重开抛同一错误。金样：`src/pilotdeck-gateway/tests/fixtures/operation-ledger/seed-{invalid-kind,string-mtime,invalid-write}.jsonl` 及 `oracle.json` `seedCases`（生成器 `generate.mts`，两次生成逐字节一致）。

## Rust 行为

`src/pilotdeck-gateway/src/storage/ledger.rs:239-244`：`terminal()` 在 `sink.append`（`:265`）之前完成 `serialize_seed` + `normalize_seed`，坏值在写盘前以 `Invalid sidecar seedState…` / `Invalid readFileState entry: …` 拒绝；`src/pilotdeck-gateway/src/storage/projection.rs:10-16`（serialize 顶层对象检查）与 `:26-98`（normalize 深校验，对齐 TS parse）。重开路径（`ledger.rs:454`）与 TS 一样拒绝坏 seed；仅失败时机提前到写盘前。

## 范围

仅 `agent_loop_operation_terminal` 的 seedState：值可序列化（JSON.stringify 成功）但不可解析（Map 值缺 `mtimeMs`/`kind`、`kind` 非法、`mtimeMs` 非数值、`writeSnapshots` 缺字段等）。TS 侧该 terminal 已持久化，后续每次重开同错；Rust 侧事件不落盘，调用方收到 `LedgerError::Invalid` 后操作保持 incomplete，可重试合法值。对合法 seed 两侧逐字节一致；不改变恢复链对已落盘坏 seed 的拒绝（两侧同拒）。不影响 seed 序列化键序（`seed-order` 金样两侧一致）。

`storage::tests::real_ts_seed_admission_matches_on_disk_and_online`（含 `#201` 标注的写盘/内存断言：TS 落盘 3 条 vs Rust 保持 2 条且恢复 Incomplete）；金样 `seed-{invalid-kind,string-mtime,invalid-write}.jsonl`；`#[ignore]` 重建守卫 `operation_ledger_regenerates_identically`；负控 `tests/fixtures/operation-ledger/negative.py` 变体 M7（把 `normalize_seed` 挪到 append 之后复刻 TS 时机，断言负控失败）。复算：`cargo test -p pilotdeck-gateway --lib storage::`。
