## 类别

未消除的行为偏离（待修）：api-server 车道没有复刻 Node `requestTimeout`
对**请求体读取**的期限。只影响那些**已经进入 body 读取**的请求：TS 侧
300 s 后写 `requestTimeoutResponse` 关闭，Rust 侧该 future 永不结束，
关停时 `stop()` 一并挂起。

## 基线依据

固定基线 `cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85`，Node v22.22.0 /
ICU 78.2。`src/adapters/channel/api-server/ApiServerChannel.ts` 用
`http.createServer(...)` 建监听器，未设置 `server.requestTimeout`，因此
取 Node v22.22.0 的默认 300 s；`connectionsCheckingInterval` 默认 30 s
只是检查周期，不缩短上界。Node `_http_server.js` 到点后写
`requestTimeoutResponse`（51 字节）并关闭 socket。同一条 Node 机制在
webhook 车道已实测留档：`_tmp/20261026-issue-1334/fix-r1/node-probe/probe4.out`
（原始字节与关闭时序）。api-server 车道本身的 TS 侧观测尚未单独做过，
本条按同一 Node 内置机制登记，**判分前需在该车道金样上实测确认**。

## Rust 行为

`src/pilotdeck-gateway/src/channel/api_server/server.rs:479` 的
`read_body` 只做 `body.frame().await` 累积，没有任何 deadline；调用点
`:672` 直接 `.await`。客户端声明 `Content-Length` 后不发完 body 时，该
service future 永不返回，连接任务常驻。`stop()` 在
`server.rs:116` 用 `while tasks.join_next().await.is_some() {}` 排空任务，
因此 `stop()` 不返回。

只有走到 `:672` 的请求会挂：`server.rs:445` 按方法与路径分派，
`POST /v1/chat/completions` 通过鉴权（`:652`）后才开始读 body；其它路由、
方法或鉴权失败的请求在读到 body 之前就应答，`read_body` 也已收字节超过
上限时提前返回 `TooLarge`。本条不覆盖这些提前返回的路径。

## 范围

仅「`POST /v1/chat/completions` 且通过鉴权、已送达请求头与部分 body、
已收字节未超上限、客户端既不发完也不关闭」这一形态。其它路由 / 方法的
请求、鉴权失败的请求、body 已完整送达的请求、以及读 body 途中就超出
大小上限的请求都不在此列：它们要么在 `read_body` 之前应答，要么由
`read_body` 提前返回。`Expect: 100-continue` 的路径同样未单独实测。
webhook 车道（A8.3-ch-webhook，`channel/webhook/mod.rs` 的
`ctx.request_timeout` + `node_request_timeout_response`）已复刻该期限并有
负控 `webhook-body-read-no-timeout`；api-server 车道既无期限也无对照格。
