## 类别

更正（归一化规则陈述与实现不符，非差异变化）：原条目「范围」段把归一化
规则列为「date 掩码、头名小写、删空 `content-length: 0`、chunk 大小
小写」，其中「删空 `content-length: 0`」按字面读是该车道回放统一删的
blanket 规则。#2153（fix-r1，PR #2770 已合）之后该车道实现是**逐字
比较，回放从不删该行**：`module_host/tests.rs::normalize`（:1094）对
`content-length` 头逐字保留（与 #2153 前的无条件删相反），删行只存在于
`module-host-normalize-cl0-off` 突变分支（:1137）——该开关重现修前
的 blanket 删作为负控，证明现行逐字比较有牙齿。原条目登记的
premature-close 残余（解析器代答 400 vs 零字节关闭）与 -R1 的登记
全部不变。

**该误述从未掩盖过真实漂移**：本轮从 oracle 原始 JSON 独立重算
（2026-11-11，脚本与原始输出贴 #2775 fix-r1 RESULT），96 格中裸 400
形状格 1 个（`premature-close`，Node 解析器罐头应答，该 cell 本就是
零字节关闭钉死格、非回放比较格），期望字节含 `content-length: 0` 的格
1 个（`undefbody`，200 金样**自带的**长度行）——`content_length_zero_
compares_verbatim`（:1030）双向钉死：注入 `method-head` 的额外
`content-length: 0` 必须改变归一化字节（未登记方向不得删）、
`undefbody` 自带的 `content-length: 0` 必须在归一化后存活（登记值不得
丢）。#2153 的测量结论（normalize 文档注释）：把旧删行关掉后每格回放
照旧全绿——即该车道从来没有任何格需要删行豁免，blanket 删在回放上
无行可删，误述的实质是账本陈述漂移而非判分缺陷。

## Rust 行为

不变。`src/pilotdeck-gateway/src/module_host.rs` 产品代码零改动；#2153
只改测试侧 `module_host/tests.rs::normalize`：`content-length` 头
逐字比较，删行仅存于 `crate::mutants::on("module-host-normalize-cl0-off")`
突变分支。注意与 api-web / native-http 车道的形态差异：那两车道以
`parser_admission` 标志逐调用豁免（api-web 回放传 `false`、gate 测试传
`true`；native-http 以登记格集 `PARSER_ADMISSION_CELLS` 11/88 豁免），
module-host 无登记格，归一化根本不带豁免参数。

## 范围

仅更正原条目「范围」段的归一化陈述：删空 `content-length: 0` 不是该
车道回放的规则，回放端 94 格该行逐字比较。不新增、不撤销任何对拍
豁免；原条目 premature-close 残余的结论、批准状态不变。api-web 车道
同句误述另登 A8.4-API-WEB-001-R3；native-http 车道的收窄已由
A8.4-NATIVE-HTTP-001-R6 登记，本件是 module-host 车道的对应更正。
