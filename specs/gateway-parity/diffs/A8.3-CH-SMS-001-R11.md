## Rust 行为

产品代码有改动，但不改任何对 TS 对拍的消息字节：`#1790` 只在
`channel/sms/permission.rs` / `mod.rs` 增加 `Drop` 守卫与一处锁拆分
（`permissions` 从 tokio `Mutex<SmsRuntime>` 移到 `SmsShared` 的
`Arc<StdMutex<ImPermissionHelper>>`，`Drop` 不能拿异步锁；加锁顺序只有
`permissions → boundaries`）。正常路径仍是显式复位后 `settle()` 解除武装，
发出的提示、确认与状态文案逐字节不变；变化的只有 panic / 取消 / 超时三条
异常退出路径（以及 `!delivered` 分支，队列为空时与 `releaseAnswer` 逐字节
等价）——从「标志永久残留、该 chat 卡死」变成「按既有的失败/重试语义释放」。
其中「确认已收尾、期间又捕获到新 permission」这一交错的队首提升是本 PR 新增
的恢复语义，单独登记在 `A8.3-CH-SMS-009.md`。`-001` / `-R1`…`-R10` 登记的
差异行为零改动。
