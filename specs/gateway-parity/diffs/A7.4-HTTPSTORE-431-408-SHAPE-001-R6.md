## 类别

差异消除（#1555）：R3 / R4「仍存在」清单里的两条资源上限残差——**值前导 OWS 的 guard raw 上界**
与 **hyper `max_headers(4096)` 字段数兜底**——在本单消除，两条均已进机器判据；同时更正两条
随之改变的资源上界口径（raw 上界现在只作用于仍转发的空白；单 head 从 socket 消耗的字节数
不再有 raw 上界）。R3 / R4 的其余「仍存在」条目不变。**未批准，非已接受差异。**

## Rust 行为

`src/pilotdeck-gateway/src/user_dialog/http_store.rs`（本单 head `bd342f472`）：

- **前导 OWS 不再计入也不再转发**：`HeaderGuard::push_head`（:2481）在 `droppable_ows`
  为真（空白紧跟在字段名后的冒号之后，而不是折叠续行）时，把该字节记进 `dropped` 并直接
  返回，既不 `raw_bytes += 1` 也不交给 hyper；`HeaderGuard::kept_prefix`（:2461）在本读块
  扫描完后把 `dropped` 区间从读块里 memmove 掉，`TimeoutStream::poll_read` 只把保留前缀
  追加进 `ahead`。因此 90,000 B（以及实测的 200,000 B）前导空白既不占 guard 的 raw 上界，
  也不占 `ahead` 与 hyper 的读缓冲，请求到达 handler（405，与 Node 同结局）。
- **折叠续行的空白仍转发、仍计 raw**：`GuardLine::FieldName` 的行首 SP/HTAB 分支
  （:2555）把 `droppable_ows` 置 false，hyper 必须看到该行才能报错，所以这部分字节继续
  计入 `raw_limit`（`header_guard_raw_limit`，:130）。
- **字段数按 Node 的计数预算取值**：`.max_headers(max_header_bytes)`（:3438，默认 16,384 槽）。
  Node 的计数字节是 target + 每个字段 name + value，每个字段名至少占 1 个计数字节，
  所以 Node 合法头的字段数 ≤ 16,382 < 16,384：没有任何 Node 合法头因字段数被拒。
  4,097 个 `a:` 字段与 16,329 个 `a:` 字段（计数字节恰 16,383 的通过边界）都到达 handler，
  16,330 个则落在 Node `>=` 16,384 的红线上，由 guard 写 67 B 431。
- **代价（如实登记，属 P2 量级）**：hyper 1.7.0 的 server 解析在每次 parse 尝试前按
  `h1_max_headers` 预分配两个槽向量（`src/proto/h1/role.rs:148-163`，
  `smallvec![MaybeUninit::uninit(); cap]`），即每 head 解析固定约
  `16,384 × (8 + 32) B ≈ 640 KiB`（`HeaderIndices` 8 B + `httparse::Header` 32 B），
  cap 从 4,096 抬到 16,384 后约增 480 KiB；滴发的头每次重解析都会再分配一次。
  峰值 RSS 的实测与数字见 §机器判据。

## 范围

已消除（两格都进机器判据，与 Node 逐字节同结局）：

1. **90,000 B 值前导 OWS**（R3「guard 的 raw 资源上界」一节）：Node 200 / Rust 431 的差异
   不再存在——Rust 与 Node 一样不计数、不缓冲这些字节，请求到达 handler（405 / 236 B / EOF）。
2. **4,097 个空值小字段**（R3「hyper `max_headers(4096)` 字段数兜底」一节）：Node 200 /
   Rust 123 B 431 的差异不再存在——字段上限由 Node 的 16 KiB 计数预算决定，而不是 parser
   的槽数。

随之更正、仍属差异或仍属有界资源（不据此新增豁免）：

- **raw 上界仍在，只是作用面变窄**：折叠续行的空白仍被转发并计入 `4 × max + 2 × 8 KiB`，
  超过它仍是 67 B 431 早于 Node（Node 该形状 200）。这一条仍是 R3 登记、未批准的差异，
  只是触发形状从「冒号后的前导空白」改为「折叠续行」。
- **单 head 从 socket 消耗的字节数不再有 raw / ahead 上界**：被丢弃的 OWS 既不进 `ahead`
  也不进 hyper 读缓冲，所以一个头可以持续消耗 socket 字节，只受 60 s `headers_timeout`
  与 tokio coop 让出（每任务约 128 次 IO）约束。Node 的 llhttp 同样跳过而不缓冲，语义一致；
  但这是资源边界的变化，登记于此（#1555 评审 P2，两家独立提出）。
- **`max_headers` 的 cap 分配是每 head 解析的固定开销**（见 §Rust 行为末条）。它不再导致
  假 431，但把单次解析的瞬态分配从约 160 KiB 抬到约 640 KiB；滴发的头会重复分配。
- **trailer 段另有 16 KiB 原始字节上限**（#1555 评审 DeepSeek boundary P2 提出，本轮只登记、
  未实测 Node 侧）：hyper 1.7.0 的 chunked 解码对 trailer 用
  `h1_max_header_size.unwrap_or(TRAILER_LIMIT)`，`TRAILER_LIMIT = 16 * 1024`
  （`hyper-1.7.0/src/proto/h1/decode.rs:22-25`、`:181`），超限即 `InvalidData`
  （`:283-291` 的 `put_u8!`）；而 hyper 的 `Builder` 尚未暴露 `h1_max_header_size`
  （同文件 `:24` 的 TODO），所以 `.max_headers(max_header_bytes)` 只对齐请求头的字段
  **数**，管不到 trailer 的**原始字节**。R4:56-57 登记的 Node 口径是 trailer 字段按
  name + value 计入同一 16,384 预算，两者不同口径。本单未新增 trailer 用例，Node 侧
  形状也未实测，故只登记为**待实测的剩余差异**，不据此声称 trailer 已对齐。
- R3 / R4 其余「仍存在」条目不变：shutdown 终止界限、malformed 400 / 414 形状、重复等值
  `Content-Length` 的解析差异、让位族精度损失、`ahead` 的 128 KiB 读前瞻上限。

**转成已接受差异须另走人批程序。**

实测（2026-11-06，macmini-01 · Darwin arm64 · `/usr/bin/time -l` · 每格三轮取最小值；
`summary.json` 的 `provenance` 记录测量时的 HEAD 与 `src_dirty=false`；原始日志与
`summary.json` 见 PR #1576 正文）：

| 模式 | 头形状 | 峰值 RSS 最小值 | 相对 baseline |
|---|---|---|---|
| `baseline` | 单条普通 GET | 24,608,768 B（23.47 MiB） | — |
| `ows-90000` | `X:` 后 90,000 空格 | 24,952,832 B（23.80 MiB） | +344,064 B（+336 KiB） |
| `fields-4097` | 4,097 个 `a:` 空值字段 | 25,214,976 B（24.05 MiB） | +606,208 B（+592 KiB） |
| `fields-max` | 16,329 个 `a:`（计数恰 16,383） | 26,001,408 B（24.80 MiB） | +1,392,640 B（+1.33 MiB） |
| `fields-max-16x` | 同上 16 路并发 | 28,065,792 B（26.77 MiB） | +3,457,024 B（+3.30 MiB） |

读法（避免过度解读）：这是端到端进程峰值，含测试自身的请求构造与连接缓冲，不等于单条
解析路径的分配；上表只用来回答「这个改动有没有把峰值内存推到不可接受的量级」，答案是
没有——最密的合法头（16,329 字段）与 16 路并发都在 30 MiB 以内。90,000 B 前导 OWS 格
只比 baseline 高 336 KiB，与请求本身 90 KB 及其连接缓冲同量级，不随 OWS 字节线性增长，
与「丢弃、不缓冲」的实现一致。源码侧每 parse 约 640 KiB 的槽向量（§Rust 行为末条）在
16 路并发下没有线性叠加到进程峰值（+3.30 MiB ≈ 211 KiB/连接）。三轮样本的抖动见
`summary.json` 的 `samples`（单连接各格 ≤ 16 KiB；16 路并发 ≤ 416 KiB，取最小值以排除
外部内存压力造成的抬升）。同一天在前一个 head 上复跑，各格最小值与上表相差 ≤ 112 KiB。
