## Rust 行为

- `storage/transcript.rs` / `storage/transcript_adapter.rs` 的 fs 调用点按真实边界标注：
  `mkdir`（`private_dirs`）、`open`（`File::open`、`create_temporary`、adapter 的 open）、
  `realpath` / `lstat`（`canonical_transcript_path`）、`rename`、`unlink` 用
  `node_io::path_error`；描述符上的 `read` / `write` / `fsync` / `lseek` / `fstat` 用
  `node_io::descriptor_error`（Node 对描述符错误不带 path）。叙述器改名诊断指向调用方
  要替换的 transcript，不暴露 Rust 兄弟临时文件名；`create_temporary` 的 create 失败
  同样指向目标 transcript。
- `load` 把「打开」与「读取」拆成两段：`File::open` 失败标 `open` + 路径；`read_to_end`
  失败标 `read`、无路径。这样 POSIX 上目录能 open、read 才报 EISDIR 的事实与 Node
  `readFile` 完全同形（`EISDIR: illegal operation on a directory, read`），不会再被误标
  成 `open '<path>'`。size 上限仍取自 `fs::metadata`，该调用失败**不标注**：Node
  `readFile` 没有 stat 边界。
- `storage/mod.rs` 的 `LedgerError::Io` 仍是 `io::Error`（阶段信息在 error 内），
  `Display` 经 `node_io::staged_diagnostic` 渲染 Node 文本；**没有被调用点标注的错误
  保持 Rust 原文**，Display 不猜 syscall。落在线上的只有 message 文本；`code` / `errno` /
  `syscall` / `path` 由 `node_io::lookup` / `os_errno` / `staged_fields` 从同一 error 取，
  `os_errno` 返回**正** errno（Node 的 `errno` 字段是它的负值）。
- `node_io.rs` 新增 `os_errno`（穿透 `Stage`，并沿用 `lookup` 的 `MkdirError` 特例；只查
  最外层包装）、`staged_fields`（syscall + 路径）、`staged_diagnostic`（复用
  `diagnostic_or_unknown`）；`descriptor_error` 与 `path_error` 一样对已标注错误直接
  返回，不二次包裹。
- 三处**刻意不伪装**：`load` 的 `fs::metadata` 失败（Node 无 stat 边界）、`replace_inner`
  的写前复核读（Rust 专有）、`LedgerLock::acquire` 的锁 inode（Rust 专有 fence）。锁
  open 失败改写成无原始 errno 的合成错误并带锁路径，避免上层 `read_file` 把它误归因到
  transcript。
- 未改 JSONL bytes、提交次序、锁语义与重试行为；`LedgerLock` 的 WouldBlock 仍是
  Rust 专有的合成拒绝，不伪装成 Node 错误。

## 范围

仅事件持久化 host IO 错误的诊断形状。实测同场景 Rust 输出：

```text
Store(Io(Custom { kind: AlreadyExists, error: Stage { source: Os { code: 17, ...
  path: Some(".../parent"), syscall: "mkdir" } } }))
display=EEXIST: file already exists, mkdir '.../parent'
```

四格状态 `(0, None)` → `(1, Some(<id>))` → `(1, Some(<id>))` → `(2, Some(<id>))`，
终读 `entries=2`，与 TS 逐格一致（entry id 为各自 fixture 的生成值）。

残留（不在本条消除范围，也未请求豁免）：`path` 是 Rust 锁先 `canonicalize` 后的绝对
路径（macOS 上 `/var` → `/private/var`），TS 打印调用方给出的原样路径；调用方传入相对
路径时两者文本不同。形状（四个字段与 message 模板）一致，只有路径文字可能不同。
