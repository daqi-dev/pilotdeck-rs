## 类别

既有 native isolated profile 单项目准入差异，待复核。本条登记 archive 空字符串 projectKey 在进程 cwd 不等于配置项目或已删除时的错误形状；不放宽项目隔离，不增加判分豁免。

## TS 依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0；`src/cli/createLocalGateway.ts:1184,1205,1223` 的三个 archive callback 使用 `input.projectKey ?? fallbackProjectRoot`，空字符串不是 nullish。

真实 `createLocalGateway` / `InProcessGateway` 实测原件为 `src/pilotdeck-gateway/tests/fixtures/native-archive-cwd/oracle.json`；生成器为同目录 `generate.mts`。manifest/entries/artifact 的 empty-other 三格均为 `PROJECT_NOT_FOUND` / `Unknown projectKey: `，empty-deleted 三格均为 `ENOENT` / `ENOENT: no such file or directory, uv_cwd`。生成器仅复用现有 shallow polling watcher 适配沙箱，不改 archive/registry/storage 代码，不启动 HTTP 服务或调用 provider。

## Rust 行为

`src/pilotdeck-gateway/src/native_process/requests.rs` 保留原有项目 gate：显式 projectKey 必须能按进程 cwd 解析为配置项目，否则返回 `gateway_request_failed` / `The isolated native process serves only its configured project.`。空串在 cwd=project 可通过；cwd=other/deleted 被拒。

本次修复仅在三个 archive RPC 的 projectKey 缺失或 null 时，于 gate 前填入配置项目绝对路径；这十八格以及显式配置项目九格、empty-project 三格已按 TS 行为补回归，不属于此差异。

## 范围

只覆盖 native isolated Requests 的三个 archive RPC、显式空字符串 projectKey、other/deleted 两种 cwd，共六格。不是 SubmitCwdService 的 session override 差异，也不扩大到其他 RPC、通用 dispatch 或相对非空 projectKey。不得据此宣布 A7.2 收尾或实效验收完成。

## 机器判据

`native_process::tests::metadata_cwd::archive_matrix_matches_ts` 驱动三方法 × 四 key 形状 × 三 cwd 共三十六个独立 worker。每格完整比较 result 或 code/message，只有本条六格按明确的 native 准入期望比较，其余三十格比较 TS 原件。输入维度由固定测试名决定并核对金样，防止 deleted 行被改成 project 行而假通过。

`archive_regenerates_identically`（ignored）调用 `regenerates_identically("native-archive-cwd")`，逐字节重生成。`native-archive-cwd/negative_controls.py` 的 `empty-string-defaulted` 与 `isolated-admission-skipped` 绑定实际矩阵及 `#1154 archive configured fallback and explicit key boundary`；其余变异覆盖三个 method、缺失/null 默认及维度完整性。新增文件未提交时遵守 HEAD 守卫，逐变异编译及全套负控须由协调者提交后在宿主运行。

fix-r2 起，`metadata_cwd_tests.rs` 以 `include_str!` 读回本文件，六格准入期望的 code/message 与登记内容不一致时矩阵失败（`ledger-admission-drift` 变异绑定 `#1154 archive admission expectation stays bound to its ledger`）；进程外 pairing 路径的缺失/null projectKey 按 server boot 对齐（`pilotdeck.ts:107-111`，fallbackProjectRoot=PILOT_HOME，填 `metadata.home`），覆盖见 `pairing::tests::archive_nullish_project_key_uses_the_proxy_boot_fallback` 与 `native-archive-cwd/negative_proxy.py`，其六格在无 General 工作区的 home 下为 `SESSION_NOT_FOUND`（实测 `_tmp/20261026-issue-1154/fix-r2/ts-general-absent-probe.log`）。
