## 类别

有意偏离（产品增强：错误不炸进程）。`serverUrl` 配置为**非空但非法**的 URL
（`new URL` 抛 `TypeError: Invalid URL`）时，TS 侧该异常以**未处理拒绝**
浮出（Node ≥15 默认使进程崩溃、零日志行）；Rust 侧把它收敛成一条
`error` 级日志并继续轮询，每 2.5 s 一条。存活语义不同：TS 死、Rust 活。

## 基线依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0 /
ICU 78.2。`src/adapters/channel/bluebubbles/BlueBubblesChannel.ts:92-93`：
`pollMessages()` 在 try **之外**执行 `const base = new URL("/api/v1/message",
this.serverUrl)`（`:93`）——非法基址使该 async 函数的返回 promise 直接
reject；`:74`（`setInterval(() => void this.pollMessages(), POLL_MS)`）与
`:75`（start 的 `void this.pollMessages()`）都 `void` 丢弃返回
值 → 未处理拒绝（Node v22 默认 `--unhandled-rejections=throw`，进程退出，
无通道日志）。`:238-241`：`sendReply` 顶部的 `new URL(...)`（`:241`）同样
在任何 try 之外，异常经 `processMessage` → `dispatchPayload` 浮回
`pollMessages` 的 catch（`:127-130`）记 `bluebubbles: poll error:
TypeError: Invalid URL`——但首次轮询已让进程崩溃，该路径实际不可达。

## Rust 行为

`src/pilotdeck-gateway/src/channel/bluebubbles/mod.rs:327-339`（`poll_messages`）：
`url_with_path` 返回 `Err` 时 `log("error", "bluebubbles: poll error:
TypeError: Invalid URL")` 后 `return`，interval 继续按 2.5 s 重试（每次再
记一条）；`mod.rs:698-706`（`send_reply`）：同样 `Err` 时记
`bluebubbles: send failed: TypeError: Invalid URL` 并 `return false`
（不向上传播、不改回合收尾文案）。两处注释（`:326-327`、`:697-700`）均写明
TS 的浮出位置。缺配置（`serverUrl` 为空串）不走本条：那条是 TS 的
`if (!this.serverUrl || !this.password)` 守卫（`:61-66`），两侧同形（错误
日志 + 不起轮询），由金样 `missing-config` 用例覆盖。

## 范围

仅 `serverUrl` 非空但非法（`url_with_path` 解析失败）时的错误浮出与存活
语义：TS 未处理拒绝（默认崩溃）→ Rust 记日志继续轮询。不覆盖空配置路径
（已对齐、金样覆盖）、不覆盖传输错误与非法 JSON 响应（两侧同为
`catch` + `error` 日志 + 继续轮询，仅日志正文的运行时文本不同，见 RESULT
未覆盖范围）。本条不构成判分豁免。

## 机器判据

- 金样 `tests/fixtures/channel-bluebubbles/` 无本条用例（假服务的
  `serverUrl` 恒为合法环回地址，非法基址无法到达真实路径）；
  `missing-config` 用例只钉空配置守卫。
- 组件钉子 `channel/bluebubbles/tests.rs` 的
  `url_with_path_resolves_against_the_origin` 钉死非法基址的错误串
  `Invalid URL`（Node v22.22.0 实测字面量）。
- 本条的存活语义无判据（无负控、无金样）；若后续要求与 TS 对齐（炸进程或
  上浮），须新增非法 `serverUrl` 用例（TS 侧行为以 Node v22.22.0 实测补
  录）并改本条目。
