## 类别

bug 修复的错误分类更正：原条目记录的 RecorderError::State 已改为统一的存储内容无效错误；保留超限拒绝，不把 TS 的空投影当作可写新日志。

## 基线依据

固定 cc7c4e6，Node v22.22.0 实测 `JsonlSessionEventStore.read→restore→append` 与 `createAgentProjectSessionStorage.restore→AgentSessionEventRecorder.startTurn` 两链：50 MiB + 1 文件返回 `entries=[]`、`transcript_too_large` error 级诊断，**不抛异常**，恢复后 sequence=0，随后写 sequence=1。源码入口为 `src/session/transcript/TranscriptReader.ts:20-30`、`src/session/events/JsonlSessionEventStore.ts:23-26`、`src/session/storage/ProjectSessionStorage.ts:337-347`、`src/agent/session/AgentSessionEventRecorder.ts:137-143`。可重跑探针与原始输出：`_tmp/20261025-issue-587-pkg2-fix-r1/ts-probe.mjs`、`ts-probe.log`。因此 Rust 拒绝不是 TS 的错误形状，不宣称与 TS 一致。

## Rust 行为

`storage/transcript.rs::TranscriptRead::ensure_writable` 共用 `Diagnostic::TRANSCRIPT_TOO_LARGE`，取匹配诊断本身的 message，返回 `LedgerError::Invalid`。三个可写入口统一内容错误：JsonlLedgerStore::open 为 Invalid；SessionStorage::restore 为 AdapterError::Store(Invalid)；PersistenceResources::create_session 为 RecorderError::Store(Invalid)。Store 外层保留各入口类型，底层分类相同；不能把所有 Store 错误视为修复路径即可重试，IO-001 仅涉及 LedgerError::Io。

## 范围

只更正三处可写恢复的诊断选择与错误分类。普通 read 仍返回原诊断；缺失文件、损坏行诊断不被误拒。默认 JsonlTranscriptStore 仍为 TS 式无排他锁低层 store。

## 机器判据

`storage::tests::writable_transcript_checks_the_matching_diagnostic_not_the_first` 覆盖非首位、多诊断、首位、无目标和空诊断。`persistence_oversized_log_never_publishes_a_reset_writer` 对同一真实超限文件断言三入口底层均为 Invalid、message 相同、文件长度不变、失败释放锁；空文件可正常写。既有 `oversized_transcript_cannot_open_as_a_new_session` 保留独立 ledger 入口验证。负控及原始输出见同证据目录的 `mutation-results.json` 与 red/green 日志。
