## 类别

差异消除（连接生命周期）。本条更正 R2 的「shutdown 的偏差」段，并补上 R2
与 R3 初版漏登的 **S1**：`close()` 早于响应头决策时，Rust 仍写
`Connection: close` 并关连接，Node 却继续广告 `Connection: keep-alive` 并在
同一 socket 上服务后续请求。

- **S1（本次补修）**：`close()` 在 handler 内、响应头决策之前触发。Node 仍
  广告 `Connection: keep-alive` + `Keep-Alive: timeout=5`，同 socket 第二请求
  成功；连接在空闲期限到达时关闭（`s1_close_in_handler_before_head`）。
- **S2**：`close()` 落在服务闭包取样之后、响应头离机之前。
- **S3**：响应体仍在刷写时 `close()`。

S2/S3 由 R3 初版修掉；S1 是初版正文写成「差异已消除」时未覆到的残余窗，
本条一并修掉，并把机器判据改成 Node 行为。

## 基线依据

Node v22.22.0 真实 `node:http`（无选项）raw-socket 实测，原始字节在
`src/pilotdeck-gateway/tests/fixtures/user-dialog-http-store/lifecycle-matrix/node-lifecycle-matrix.json`
（生成器同目录 `probe.mjs`）：

- `s1_close_in_handler_before_head`：handler 内 `close()` 后仍回
  `Connection: keep-alive` + `Keep-Alive: timeout=5`，同 socket 第二请求成功；
- `s3_body_flushing_close_reuses_same_socket`：已读响应头、2 MiB body 仍在
  刷写（慢 handler + 慢读者）时 `close()`，body 完整到达，同 socket 第二请求
  得到 404，响应头仍广告 keep-alive，`close()` 回调等到 keep-alive 期限；
- `s3_body_flushing_client_fin`：大 body 刷写中客户端 FIN，Node 不补完 body
  （另一既有差异，不在本条）；
- 在 handler 把整个 2 MiB body 一次性交给内核后，Node 的 `close()` 把连接当
  空闲连接销毁（`_tmp/20261026-issue-702/node/node-fast-buffered.out.txt`）。
  因此「已选 keep-alive 且 body 仍在飞」与「body 已全部离机」必须分开判断。

fix-r1 另用 `_tmp/20261026-issue-702/fix-r1/node-s1-probe.mjs`（Node
v22.22.0，`keepAliveTimeout=1s`、buffer 0）复测 S1：第一次与第二次响应都写
`Connection: keep-alive` + `Keep-Alive: timeout=1`，第二次响应后约 1.0 s
EOF，`close()` 回调随后返回；原始输出同目录 `node-s1-probe.out.txt`。

`src/gateway/user-dialog/HttpGatewayUserDialogStore.ts:232,243` 无选项

## Rust 行为

`src/pilotdeck-gateway/src/user_dialog/http_store.rs`：

- `KeepAliveTimer` 的 `ConnectionLifecycle` 增加 `request_in_flight` 与
  `graceful_shutdown_started`（连同既有
  `advertised_keep_alive` / `close_after_response` / `response_write`）；
- 服务闭包在**同一把 `lifecycle` 锁**内决定并写 keep-alive 广告；请求头一到
  达就置 `request_in_flight`，响应体结束才清掉；
- 连接任务的 shutdown 分支：只要 `close()` 时有请求在飞（S1，即使响应头还没
  决策）或已广告的响应仍在线（S2/S3），**不**调用 hyper 的
  `graceful_shutdown`，让响应按 Node 广告写完、同 socket 继续服务后续请求；
  随后由既有 `KeepAliveTimer` 在空闲期限关闭；
- `close()` 落在空闲连接上时仍走 `graceful_shutdown`，并置
  `graceful_shutdown_started`；与该 close 竞速的响应写 `Connection: close`，
  避免广告后立即关闭；
- 不再因为 shutdown watch 已置位就无条件把在飞响应的广告改成 close；这是
  S1 的根因；
- 下一次请求开始时在同一把锁内清空上一响应的广告状态并重新按 Node 决策；
  若连接是在空闲时被 close（`graceful_shutdown_started`）则写
  `Connection: close`，否则照常广告 keep-alive。

## 范围

仅连接生命周期：`server.close()` 与在飞 / 已广告 / 慢读者响应的交错。请求/
响应字节、状态码、JSON、body 上限、超时数值、HTTP/1.0 与早退 close 的广告
策略均不变。S1/S2/S3 在 `close()` 后都按 Node 保留同 socket 的后续请求，直到
空闲期限；`close()` 在空闲连接上仍立即关闭（#679 的
`close_closes_idle_keep_alive_connections` 语义不变）。HEAD/空 body 视为无
body 需等待。

不在本条范围：响应体仍在刷写时客户端 FIN 的行为。Node v22.22.0 的 2 MiB
慢写 + 首块后 FIN 探针（`lifecycle-matrix` 的 `s3_body_flushing_client_fin`）
只送达首块后 EOF，不补完 body；Rust 的 `half_close(true)` 会写完。该差异
早于 #702，本单不改、不新增豁免，只记录在 fixture README；#699 的小响应
半关闭金样仍必须全绿。

## 机器判据

`src/pilotdeck-gateway/src/user_dialog/http_store_tests.rs`：

- `shutdown_during_inflight_request_does_not_advertise_keep_alive`：S1 正控。
  `BlockingStore` 保证请求在飞且响应头未决策时 `close()` 已启动；断言第一次
  响应 200 + `Connection: keep-alive` + `Keep-Alive: timeout=1`、同 socket 第
  二请求 200 且仍广告 keep-alive、空闲期限后 EOF、`close()` 有界返回。
  **函数名是历史误名**：R2（`A7.4-HTTPSTORE-KEEPALIVE-001-R2:194`）引用它，
  账本冻结字节不可改，所以保留名字；R3 初版只让它当旧偏差的正控，fix-r1 把
  断言更正为 Node 的 S1 字节。冻结账本 `accepted-diffs.md` 未引用该名字。
- `shutdown_during_large_response_reuses_advertised_keep_alive`：40 次全名
  逐次断言。每次放 12 个 ~1.5 MiB dialog（响应 ~18 MiB），读到
  `Connection: keep-alive` 头后 `close()`，慢读 body，再在同一 socket 发
  第二个请求，必须得到 405 且该响应仍写 `Connection: keep-alive`；随后由
  客户端关闭，`close()` 有界返回。修复前（负控同路径）第 0 次迭代第二请求
  即 EOF/ECONNRESET，测试中止；修复后 40/40 通过。
- `keep_alive_close_race_uses_wire_bytes_not_body_completion`：S1/S2/S3 决策
  边界单测——只有请求在飞、尚无广告时 close 也必须延后关闭；只写出 head 时
  close 必须让广告兑现；body 真正写出后才允许按空闲连接关闭；
  `response_finished` 早于字节离机时仍必须延后关闭；空闲 close 的
  `graceful_shutdown_started` 必须对服务闭包可见。
- 既有 `close_closes_idle_keep_alive_connections`、`close_waits_for_in_flight_requests`
  与 `http_10_requests_close_like_node` 仍绿；#699 的 header-lifecycle 金样
  全量回归。
