## 类别

传输层呈现差异（不可避免）：sms 车道 body 读超时（Node `requestTimeout`
等价，300 s）后写出的 408。语义与 TS 一致（状态行 408、`Connection: close`、
零长 body、随后关连接），但线上字节在三个维度上不同：

1. **分帧**：hyper 对未知长度的空 body 一律补
   `Transfer-Encoding: chunked\r\n\r\n0\r\n\r\n`；Node 的
   `_http_server.js` `requestTimeoutResponse` 是 51 字节无帧原文。
2. **头名大小写**：sms 车道用裸 `http1::Builder::new()`（没有
   `title_case_headers(true)`），hyper 写 `connection:` / `transfer-encoding:`
   小写；Node 写 `Connection:`。
3. **隐式 `Date`**：同一裸 builder 没关 `auto_date_header`，hyper 追加一行
   `date:`；Node 这条 canned 408 完全没有 `Date`。

三个维度都来自 hyper 的公开 API 默认值，本仓不提供改写扩展点；webhook 车道
的同类残差另有条目（`A8.3-CH-WEBHOOK-001`），sms 车道此前只有车道级的
`A8.3-CH-SMS-002`（应答整体以语义三元组回放、不逐字节钉死）。#1901 首次把
本车道的 408 逐字节钉死，因此单列本条。

## 基线依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0。

- `src/adapters/channel/sms/SmsChannel.ts:89` 用 `createServer(...)`（无
  options），`requestTimeout` 取 Node 默认 300000 ms，
  `connectionsCheckingInterval` 取默认 30000 ms；文件内无
  `requestTimeout` / `setTimeout` 覆盖。
- Node 原文 51 字节：`HTTP/1.1 408 Request Timeout\r\nConnection: close\r\n\r\n`
  （无 `Content-Length`、无 `Date`、无 `Transfer-Encoding`）。实测探针
  `_tmp/20261026-issue-1334/fix-r1/node-probe/probe4.mjs` / `probe4.out`；
  #1901 复核三种请求头（`Connection: close` / `keep-alive` / 不带头）得到同一
  51 字节（`_tmp/20261106-issue-1901/probe/conn-header.out`）。
- 同字节常量另见 `src/pilotdeck-gateway/src/user_dialog/http_store.rs`
  （`NODE_408_RESPONSE`）。
- 金样 cell `body-read-timeout`（`tests/fixtures/channel-sms/oracle.json`，
  56 格中的第 56 格）在生成宿主机（node v22.22.0 / ICU 78.2）录制，期望值为
  `{"status": 408, "contentType": null, "body": ""}`——金样只记语义三元组，
  不记线上字节。

## Rust 行为

`src/pilotdeck-gateway/src/channel/sms/mod.rs`：

- 读体整段包在 `tokio::time::timeout(shared.request_timeout, body_read)`
  （`:832-845` 一带），到期返回
  `crate::channel::webhook::node_request_timeout_response()`——与 webhook
  车道共用同一个构造器，两条通道的 408 语义不会各自漂移。
- 该响应体是未知长度的空 body，hyper 输出
  `HTTP/1.1 408 Request Timeout\r\nconnection: close\r\ntransfer-encoding:
  chunked\r\ndate: <RFC 7231>\r\n\r\n0\r\n\r\n`（头序见 hyper 1.7 的
  `role.rs`；`date` 值每次不同）。

`src/pilotdeck-gateway/src/channel/sms/tests.rs`：

- `REQUEST_TIMEOUT_408`（`:2272`）是**比较基准**：Node 51 字节 + hyper 的
  chunked 帧（Title-Case、无 `Date`），不是线上原样字节。
- `normalize_wire`（`:2289`）把实际字节的头名折成小写、丢掉 `date` 行，其余
  （状态行、`connection: close` 的值、chunk 帧 `0\r\n\r\n`）逐字比较。

## 范围

仅 sms 车道 `/sms/incoming`（及同端口其它路径）body 读超时的 408，一条响应、
一个场景：客户端声明 `Content-Length` 后不把 body 发完。不影响：

- 超时**触发时机**与关闭路径：另见 `A8.3-CH-SMS-011`；
- 正常完成的应答（200 TWIML / 空 200 / 400 / 401 / 404 / 413）：这些响应由
  静态 body 经 `sized()` 装箱，保留 `content-length` 分帧，55 个既有回放 cell
  逐字节通过。帧级呈现的通用豁免仍以 `A8.3-CH-SMS-002` 为准（该条待批）。
- 请求**头**读没有期限（#1955），与 408 的字节形状无关。

本条不构成判分豁免：把 408 断言改成别的字节仍会按上面的恒等式报错。

## 机器判据

- `src/pilotdeck-gateway/src/channel/sms/tests.rs`
  `replay_body_read_timeout`：回放金样第 56 格（声明 64 字节只发 8 字节、
  保持写侧打开），用注入的 200 ms 期限驱动真实监听，5 s 内 `read_to_end`
  拿到上述字节并要求连接关闭；比较前按 `normalize_wire` 折叠两个已登记维度。
- 同文件 `sms_408_is_node_bytes_plus_hyper_framing`：把 `REQUEST_TIMEOUT_408`
  与 `NODE_408_RESPONSE`（`user_dialog::http_store`，`pub(crate)`）+ 帧化常量
  逐字节对上，防止「Node 408」式文案与字节再次脱节。
- `sms_408_is_node_bytes_plus_hyper_framing` 与
  `body_read_deadline_defaults_to_the_node_request_timeout` 一起钉住 300 s
  默认值与字节恒等式（改值转红）。
- 负控：`src/pilotdeck-gateway/tests/fixtures/channel-sms/negative_controls.py`
  的 `sms-body-read-no-timeout`（去掉期限分支，上面的回放 5 s 后转红）。
- 复算命令：`cargo test --offline --locked -p pilotdeck-gateway --lib --
  channel::sms::`（两台宿主：Linux cb8 / macOS mbp2，均 175 passed）。
