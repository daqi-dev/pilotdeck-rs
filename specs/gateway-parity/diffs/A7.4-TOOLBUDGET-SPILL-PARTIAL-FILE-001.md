## 类别

有意改进（#637 评审 P0-2：半写 spill 文件不得被当作有效落盘结果；fix-r2 追加：
被放弃的在途写与同目标重试并发时不得采纳半写文件；fix-r3 追加：在途等待有界，
超时返回显式错误而非无限等待）。

## TS 依据

node v22.22.0（macOS）实测 `writeTextIfAbsent` 的 `writeFile(path, content,
{ flag: "wx", mode: 0o600, encoding: "utf8" })`（`resources/PilotDeck/src/
context/budget/ToolResultSpillPort.ts:14-23`）：在挂载的 5 MB HFS+ 卷
（hdiutil，写满至剩 36 KiB）上写 50 MB 内容，write 中途 ENOSPC 失败后磁盘
留下 524,288 字节的半写文件；随后对同一路径的第二次 `writeTextIfAbsent`
把 `wx` 的 EEXIST 捕获为 `{ created: false }`，半写文件被当作已存在的有效
spill 静默提供截断内容。原始输出：
`_tmp/20261025-issue-637/fix-r1/ts-midwrite-failure.log`（脚本
`ts-midwrite-failure.mjs` 同目录）。错误消息为
`ENOSPC: no space left on device, write`（无路径，与 Rust 的
`io_error(error, "write", None)` 映射逐字节一致）。

fix-r2 并发场景实测（`_tmp/20261025-issue-637/fix-r2/ts-retry-race.log`，脚本
`ts-retry-race.mjs` 同目录，复刻 `maybeReplaceTextToolResult` 的
writeFile(wx)→copyFile(EXCL)→登记顺序，两腿之间停顿模拟慢设备）：被放弃的写 A
停在两腿之间时重试 B 进入，B 的 `wx` 撞 EEXIST 被捕获为 `created:false`，
B 读半写源拷出**截断 alias**（100000/200001 字节）；此后无论 A 成功（B 的
调用方已拿到截断引用，A 的登记覆盖缓存、多耗一个 alias index）还是 A 失败
（TS 不清理，半写文件留存），B 都已把截断字节当有效结果提供。TS 不产生悬空
引用，但产生截断数据；Rust fix-r1 的清理把后一种情况变成了悬空引用，fix-r2
把两种情况都消除。

## Rust 行为

`runtime/context/tool_budget.rs` 的 `ExclusiveSpill` 守卫（#637 fix-r1）：
独占创建的 spill 文件在两条写腿（`write_text_if_absent` 与
`copy_file_if_absent` 的 `write_all`）之间失败或 panic 展开时，经同一受核
根（`project_files::open_directory_beneath` + `unlink_at`，不跟随被换入的
链接）尽力删除半写文件；删除失败时保持与 TS 相同的半写残留。成功路径字节
与文件名不变；错误消息不变（ENOSPC 对拍见上）。下一次同目标写因此拿到干净
的独占创建并写入完整内容，而不是把截断文件当作已存在。

fix-r2 在此之上加在途串行（`State::in_flight_spills` + `InFlightSpill` +
`ResolveSpill`）：文本路径（`maybe_replace_text_tool_result`）与媒体工件路径
（`persist_artifact`）都以 spill 目标路径登记在途任务，重试在缓存未命中且
在途任务未决时等待其结束（等待在 `spawn_blocking` 内的 Condvar 上，不占
tokio worker）；在途任务成功则重试命中登记（媒体路径由独占创建返回
`created:false` 后正常返回），失败则重试自己重跑完整写入。登记的解除在
blocking 任务的每条退出路径（含 panic 展开）上由 `ResolveSpill` 守卫完成，
被丢弃的调用方不会留下永不释放的票据。

fix-r3（DeepSeek 评审 P2-1）把该等待改为有界：`wait_for_spill` 的 Condvar
等待带 `SPILL_WAIT_TIMEOUT`（30 s，与 `storage/run_registry.rs` 的
`FILE_LOCK_TIMEOUT` 同量级——宿主既有的「等另一个并发文件写者」上限）；超时
后重试得到显式错误（文案写明同一工具结果仍在写盘、未采纳半写文件、未返回
指向它的引用），既不采纳半写文件也不假成功。TS 无此等待（其重试直接撞
EEXIST 采纳半写字节，见上），超时错误因此是本条目登记行为的一部分。

## 范围

仅 spill/alias 写腿中途失败（io 错误或 panic）与「被放弃的在途写 + 同目标
重试并发」这两类错误/并发路径的磁盘残留与采纳行为；目录创建残留、成功路径、
错误消息与文件名均与 TS 一致。alias 目的地半写被删除后，重试的
`copy_file_if_absent` EEXIST 分支本就推进到下一个 index（与 TS
`createReadFileAlias` 循环一致，实测
`_tmp/20261025-issue-637/fix-r1/ts-alias-eexist.log`；该循环无上界也与 TS
`while (true)` 同型，实测 `_tmp/20261025-issue-637/fix-r2/
ts-alias-eexist-loop.log`），不改变可观察返回值。并发同 key/同路径重试如今
串行等待而非竞速采纳（TS 会提供截断字节，见上），是本条目登记的有意改进。
清理尽力而为：若删除失败（如目录被并发替换），落盘状态与 TS 完全相同。

## 机器判据

`src/pilotdeck-gateway/src/runtime/context/tool_budget.rs`：
`spill_write_panic_midway_removes_partial_file`（panic 在两条写腿之间，头
半字节已在盘上，断言文件不存活）、`spill_write_failure_midway_cleans_up_
and_retries`（注入 ENOSPC，断言消息与 TS 实测逐字节一致、文件被清理、重
试写入完整内容）、`spill_alias_panic_midway_removes_partial_file` 与
`spill_alias_failure_midway_cleans_up_and_retries`（fix-r2：同一对检查经
alias 拷贝路径——`copy_file_if_absent` 的 `ExclusiveSpill`——中途 panic 后
断言文件不存在；注入 ENOSPC 后断言 `copyfile '<src>' -> '<dst>'` 错误形状、
文件被清理、重试顺延下一个 index 成功）、`spill_retry_waits_for_abandoned_
inflight_writer` 与 `media_retry_waits_for_abandoned_inflight_writer`
（fix-r2：A 停在两腿之间 → 调用方被丢弃 → 重试 B 进入 → A 失败；断言 B
等待而非完成、最终拿到完整内容与单一 alias）、
`spill_retry_times_out_when_inflight_writer_never_finishes`（fix-r3：A 停在
两腿之间且测试内不放行，重试 B 在有界等待后返回上述显式错误，断言无引用、
无 alias、半写文件保持 100000/200001 字节；测试自身的 5 s 看门狗即负控
锚点——去掉超时则 B 永挂、用例在看门狗内失败）。TS 侧复算：
`_tmp/20261025-issue-637/fix-r1/ts-midwrite-failure.mjs`（hdiutil 5 MB 卷真实
ENOSPC）、`_tmp/20261025-issue-637/fix-r2/ts-retry-race.mjs`（并发截断）。
重跑：
`cargo test -p pilotdeck-gateway --lib 'runtime::context::tool_budget' -- --test-threads=4`。
