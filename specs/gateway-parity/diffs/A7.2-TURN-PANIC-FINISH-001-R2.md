## 类别

更正（原条目两处失实，非取舍变化）：其一，「Rust 行为」末句「turn / admission / fence 在预算内有界释放，永不因挂死的 host future 永久占用」在「append 永不沉降」格不成立——`close_live()` 只置 `closed`，而消费者 `next()`（publish.rs）在 `closed && pending` 时把 pending 快照交给无上界 `wait_for`，pending 仅由 `PublicationWrite::finish` 移除，never-settling append 使 `join!(manage, consume)` 永不返回，与修复前同一挂死（#2498 评审 P0）。其二，「Rust 行为」登记的 `timeout(预算, publisher.finish())` 只包住 drain，durable failure record（`publish_failure` → `host.record_failure().await`，生产 spawn_blocking 无超时）在预算起算之前，record 挂死时预算定时器根本不注册（#2498 评审 P2）。原条目 A7.2-TURN-PANIC-FINISH-001 原字节不动。

## TS 依据

与原条目同一固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85（Node v22.22.0）与同一探针（`_tmp/20261026-issue-2498/ts-probe-2498.mts` → `ts-probe-2498.out`）：append 永不沉降（探针 A）TS 挂死（ended=false / active=true / afterCalled=false）——本更正的消费侧收口仍是登记过的「宁可分叉不挂死」分叉，不新增 TS 行为依据；append 晚沉降（探针 B）两帧照常投递；超时路 `queue.close()` 立即结束 consumer、不等 pending（pump finally 的 `Promise.all` 才等），与本更正「硬关即结束尾随等待」同形。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/turn/submit.rs` manage 臂 worker JoinError 分支（fix-r1 后）：claim 后 `timeout(abort_budget(), async { publish_failure; publisher.finish() })` —— **record 与 drain 共享同一 abort 预算**，超时即无条件 `close_live()`。预算抽为 `abort_budget()`（`Duration::from_millis(host.abort_turn_timeout_ms().max(1_000))`，panic 臂与 timer 路后备两站共用，1s 下限语义不变）。`src/pilotdeck-gateway/src/runtime/turn/publish.rs`：`State` 增 `hard_closed`，`close_live()` 与 `closed` 同步置位（不清 `pending`：executor-drop 观察者与 `finish()` 的 drain 屏障语义不动）；新增 `wait_for_trailing_writes`（写入沉降**或**硬关，先到者胜），仅 `next()` 的尾随等待改走它——硬关后空手返回 `retain_terminal → None`，消费臂随 manage 臂同预算收口；`finish()` 保持纯 `wait_for`（session-end drain 屏障，同 TS `Promise.all`）。预算内沉降帧照常投递；硬关后沉降的 append 仍由 `PublicationWrite::finish` 的 `if !state.closed` 丢弃（durable 已有行、wire 只见流结束），与原条目一致。

## 范围

仅 turn submit 的 worker panic（JoinError）臂与其消费侧尾随等待。timer 接管路径（`6-R1.md`）、pump 正常完成路径不变；`.max(1_000)` 下限覆盖 panic 臂与 timer 后备两站（预算过小的 embedder 配置仍给 in-flight failure appends 一个有界沉降窗）；「append 永不沉降」格 Rust 有界收口 vs TS 挂死、「record 挂死」格同理——均为既有登记的「宁可分叉不挂死」取舍的补全，不据此宣称 #589 或阶段完成。不修改 TS 金样或冻结判分器。
