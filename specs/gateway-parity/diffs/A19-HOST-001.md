## 类别

intent bug ②：用户超时取得收尾权后，最终结果被迟到的 `gateway_submit_failed` 覆盖（超时被记成「提交失败」）。同一收尾缺陷的另一面（intent bug ①：实时流不告知用户已超时）在 D4-B 的同一修复口径内一并登记，不拆两条。#1177 按 D4-B 人批把六格期望逐格登记为批准差异，修复本身在 A7 Rust 宿主实现。

## 基线依据

固定基线 `cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85`（Node v22.22.0）。`src/gateway/client/InProcessGateway.ts` 超时收尾路径：`settleTimeout` 触发后 `enqueueGatewayEvent` 在 registry 拓扑下要等异步 append 完成才入队，而队列在收尾发出后立即同步关闭（`:1216-1227`、`:1432`），实时流收不到任何收尾帧；迟到的 catch 分支 `recordGatewayStatusMessage` 吞错后仍入队 `gateway_submit_failed` 的 status 与 error（`:1384-1439`），registry 最终 result 被 `error:gateway_submit_failed` 覆盖。`src/gateway/run/RunRegistry.ts:184-211` 的 mutationChain 逐次刷新落盘，失败 append 不占 seq。

实测：`scripts/a5-19/six_cells.mts` 六格 × 36 变体 × 模型/工具两阶段 × 5 遍 = 360 观测，全部稳定；原始数据 `docs/experiments/exp014-a52-session-fixtures/results.json`（`summary` 72 行，含 `framesAfterPrefix`、`durableStatuses`、`registryEventsAfterPrefix`、`registryState`、`registryResult`、`droppedEnqueues`）与 `readme.md` 逐项表。二者冲突处以 results.json 为准（如 `catch-status-and-timeout-append-fail` 的 readme 表与实测 events 不一致）。#1177 复算：候选树真实重跑见 `_tmp/20261026-issue-1177/recalc/`，360 次 ts 实测与登记期望逐项相等。

## 范围

六格会话域 timeout-first 收尾的三个登记面：客户端实时流 frames（前缀后）、durable status 序列、registry（events / state / result）。允许差异面：ts-equal 类无；两个 no-registry 类仅 durableStatus；registry 超时收尾 / T 状态写失败 / S(T) 追加失败类为 frames、durableStatus、registry.events、registry.result；E(T) 追加失败类另含 registry.state（running）。`registryRevision`/`lastSeq` 不登记（由 events 序号推导）；`droppedEnqueues` 不是登记面。G 侧写失败（迟到的提交失败自己失败）归入超时收尾类，不新增差异面。非 timeout-first 的 4 个 order 变体、prefix 帧、重连回放、A8 切换、deadline 计分本身不在本条内；本条不豁免任何既有判分规则，也不放宽 phase C 的 deadline ×2——其计分按 D4-B 口径另算。
