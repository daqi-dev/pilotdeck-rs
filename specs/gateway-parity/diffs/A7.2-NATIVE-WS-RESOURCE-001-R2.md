## 类别

更正 R1 中未批准的 1 秒关闭期限候选；原条目与 R1 原字节保留，不修改冻结装置、判分或阈值。

## 基线依据

Node v22.22.0、固定 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85。`native-ws-entry/resources.mts` 的 closeFlush 四格直接使用 GatewayServer 创建的真实 TextWebSocketConnection 与 net.Socket，仅在首个原生写回调设置可释放前驱。真实对端 close / EOF 后，模拟全局 setTimeout/setInterval 推进一小时，已接受的2MiB输出仍待写、未 finish/destroy、server.close 仍等待，socketTimeout=0；显式取消 socket 后 server.close 完成。释放后 close 路径交付完整2MiB数据帧和close1000再finish；EOF路径交付完整帧但写端仍半开，finished=false，探针显式销毁完成清理。有限一小时观测不宣称数学上的永不超时。

原始输出 `_tmp/20261026-issue-749/fix-r3/ts-golden.log`；金样 `src/pilotdeck-gateway/tests/fixtures/native-ws-entry/oracle.json` 的 observations.resources.closeFlush，既有 ignored 重生成守卫逐字核验。

## Rust 行为

关闭冲洗期限 = 30秒调度宽限 + ceil(仍占输出许可的已接受字节 / 1MiB)秒，许可涵盖在写帧和排队帧；最大单连接100MiB+10字节对应131秒。首次正常关闭期限不被EOF/重复关闭延长或缩短；紧急请求过载仍可立即收紧。期限内按FIFO冲洗，已完成写入优先于同时就绪期限。期限到达仍返回错误并回收socket；这不是TS的行为等价声明，也不保证任意慢读端永不被截断。

EOF后Rust排空并主动shutdown，与真实TS保持半开连接有差异；此前完整Writable end/finish金样只证明流的end冲洗语义，不替代真实GatewayServer EOF行为。本轮修复不改变服务器run(stop,budget)的独立drain上限，调用方显式较短drain仍可先结束整个服务。
