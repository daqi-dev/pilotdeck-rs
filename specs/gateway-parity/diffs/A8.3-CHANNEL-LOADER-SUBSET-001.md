## Rust 行为

r1 s1 实测（同上证据）：4 键逐个 `enabled: true` 走真启动入口
（`native_process::assembly::start`）启动 Ok、`<home>/channels/` 不创建、
runtime-status.json 不存在、无任何日志；对照组 telegram 同配置拒绝（错误含键名）、
feishu 同配置启动且 runtime-status.json 出现 feishu 条目。r2 复测（2026-11-08，
基点 f31a2e33a，#1343 合入后）：5 键全量复跑同法探针，行为未变——每键启动 Ok、
`<home>/channels/` 不创建、runtime-status.json 不存在（含 bluebubbles，本键 r1 无
实测、r2 补测；证据 `_tmp/20261108-issue-1853-r2/`）。无 TS 回退路径：
`native_process.rs:39-56` 的 `run` 只装配原生 host 与 WS listener，无任何 TS
gateway 派生。键集实算（基点 f31a2e33a）：`channel/loader.rs:18` 的
`CHANNEL_LOADER_KEYS` 15 键中 10 键在 `UNMIGRATED_CHANNEL_KEYS`（`:46`，启用
即拒，`reject_unmigrated_channels` `:103`）；差集 5 键——`wecomCallback` / `sms` /
`apiServer` / `webhook` / `bluebubbles`——不在拒绝表、不在 `BUNDLE_CHANNEL_KEYS`
（`:127`），原生装配只构造 weixin / feishu（`assembly.rs:1064-1069`、
`native_process/channels.rs:49`）。启用这 5 键中任一键：进程正常启动、日志干净、
该 channel 不工作——与 #1763 修掉的 13 键静默忽略是同一失败模式，换成子集内的
键名，用户感知不到差别，排查会走向账号 / 网络 / token。
