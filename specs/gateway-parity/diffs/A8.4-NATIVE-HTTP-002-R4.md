## Rust 行为

`src/pilotdeck-gateway/src/http_proxy.rs`（引用一律函数名锚点——fix-r2 起
数字行号全部移除，见机器判据末段）：

- `write_pending: Arc<AtomicBool>`（`UpgradeReadGate` 字段，构造于
  `serve_connection_configured`）：`UpgradeReadGate::poll_write` 写出
  `written > 0` 置位；`UpgradeReadGate::poll_flush` 透传 `Ready(Ok(()))`
  清零。写错误与 `poll_shutdown` **有意**不清零（评审 Grok #1）：hyper 两路
  都终结连接（响应 future 出错 / 连接落盘），陈旧旗标对后续请求无可观察
  后果——口径已写进 `poll_flush` 清零处的注释。
- `IdleBody::release`（`Drop` 与 `poll_frame` 末尾各调一次）在帧交出处
  `write_pending.store(true)`：「体已交给 hyper 写缓冲」此前只由
  `in_flight` 槽位表达，现在由 release 置位、drained flush 清零共同表达
  attach 窗口。
- 三个消费者同旗标：镜像清零条件（`poll_read` 清零臂，
  `in_flight == 0 && !write_pending`）；`withholding_mid_stream`
  （谓词 `in_flight > 0 || write_pending`）；stand-by 重臂推迟
  （`poll_read` 重臂消费处的 `!write_pending`）——`rearm` 有变但写侧未
  flush 时不臂，等 flush 后的下一次重臂，正是 T3b「无后续头则无窗口」的
  一格（评审 boundary #1，此前该格会在帧交出 +60 s 网格静默关闭并截断
  尾部）。
- fix-r2（DS concurrency #1，实测升 P1）：`_headerSent` 镜像
  `response_head_written` 的置位从「门成功写出字节」改为「`poll_write` 被
  以非空 buf 调用」（交出口径，T3c）——响应头本身停在 hyper `write_buf`、
  传输层 0 可写空间的格，Node 因 `_headerSent` 已置位而裸 destroy，修前
  Rust 会武装 408 顶掉该从未被接受的响应头。
- 代理 lane `serve_connection_with` 无 headers 超时，首条件
  `headers_timeout.is_some()` 不变，零影响（R3 口径维持）。
