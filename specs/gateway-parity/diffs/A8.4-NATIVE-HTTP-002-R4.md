## 类别

更正 + 收口扩展（#1517 fix-r1，评审 fix-r1 双谱系 DS 四角色 + Grok：P0=0
P1=1 P2=7 P3=5）。R3 的旧结论有三处口径问题，且其「已交出、尾部未 flush」
一行只收口了「尾部已部分落到门」的半边：

1. 范围句失实（评审 sibling #3）：「HTTP / WS 升级前 / SMS 回调 lane 均经
   `serve_connection_native_with_shutdown` → `UpgradeReadGate`，一处修复
   全覆盖」——SMS 回调 lane（`channel/sms/mod.rs`，#1955/#2020 登记件）与
   wecom_callback（`channel/wecom_callback/http.rs`）实为私有 hyper 连接
   （`http1::Builder::header_read_timeout`），不经读门。
2. 机器判据行号/时刻漂移（评审 sibling #4 / boundary #3 / Grok P3-4）：
   `probe_open_with_stuck_tail` 写 `tests.rs:3198`，评审时点实测 3207；
   `poll_flush` 写 `:751-766`，实起于 `:750`；cell 时刻注释 `+88.4 s` /
   `+89.4 s` 未计 `probe_still_open` 内部 60 ms 推进，实为 `+88.5 s` /
   `+89.5 s`。
3. 负控出处标注不实（评审 boundary #2）：`native-http-408-into-unflushed-tail`
   只回退 `_headerSent` 镜像的清除条件，保留 #1517 的 withholding 扩展，
   并非「变异即修复前行为」。

新结论（评审 P1，实测成立）：`write_pending` 只镜像「门自己写出的字节」；
尾部整体停在 hyper 自己的 `write_buf`（释放时 0 可写空间象限——真实形态是
内核发送缓冲满，评审建议的确定性实现是停写传输）时 `in_flight == 0` 且
`write_pending == false`，镜像照清、withholding 无据：后续半头进 hyper 读缓冲，
`mid_message_detect_eof` 停在非空缓冲上不再 poll io，**网格点什么都不发生**；
客户端恢复读后 flush → 解析半头时镜像清零 → 在已完成的 200 之后补写 51 字节
408。修法按评审建议方向：`IdleBody::release` 在帧交出处置位共享旗标
（`Arc<AtomicBool>`），`poll_flush` 返回 `Ready(Ok(()))` 清零，镜像清零 /
`withholding_mid_stream` / stand-by 重臂推迟三个消费者同用一旗标——「写侧
未 flush ⟹ 响应仍在 Node 的 attach 窗口」从「门写过字节」扩为「响应已交给
hyper 写侧且此后无完成的 flush」。

## Rust 行为

`src/pilotdeck-gateway/src/http_proxy.rs`（fix-r1 后行号，后续引用一律以
函数名锚点为准——评审 Grok #4 建议）：

- `write_pending: Arc<AtomicBool>`（`UpgradeReadGate` 字段，`:275`；构造
  `:335`）：`poll_write` 写出 `written > 0` 置位；`poll_flush` 透传
  `Ready(Ok(()))` 清零（`:784` 起）。写错误与 `poll_shutdown` **有意**不清零
  （评审 Grok #1）：hyper 两路都终结连接（响应 future 出错 / 连接落盘），
  陈旧旗标对后续请求无可观察后果——口径已写进 `poll_flush` 清零处的注释。
- `IdleBody::release`（`:1039`）在帧交出处 `write_pending.store(true)`
  （`:1043`）：「体已交给 hyper 写缓冲」此前只由 `in_flight` 槽位表达，现在
  由 release 置位、drained flush 清零共同表达 attach 窗口。
- 三个消费者同旗标：镜像清零条件（`:545`，
  `in_flight == 0 && !write_pending`）；`withholding_mid_stream`
  （`:416-419`，`in_flight > 0 || write_pending`）；stand-by 重臂推迟
  （`:564-565`）——`rearm` 有变但写侧未 flush 时不臂，等 flush 后的下一次
  重臂，正是 T3b「无后续头则无窗口」的一格（评审 boundary #1，此前该格
  会在帧交出 +60 s 网格静默关闭并截断尾部）。
- 代理 lane `serve_connection_with` 无 headers 超时，首条件
  `headers_timeout.is_some()` 不变，零影响（R3 口径维持）。

## 范围

`serve_connection_native_with_shutdown` → `UpgradeReadGate`；SMS 回调 lane
（`channel/sms/mod.rs`，#1955/#2020 登记件）与 wecom_callback

四行之外补 fix-r1 收口的两行：

| 到期时写侧状态 | TS 期望 | 本条处置 |

| 已交出、尾部整体停 hyper 写缓冲（0 可写空间）+ 后续半头 | 裸 destroy（T3a 实测） | **fix-r1 收口**：新 cell + 负控 |
| 已交出、尾部整体停 hyper 写缓冲、无后续头 | 无窗口（T3b 实测） | **fix-r1 收口**：新 cell + 负控 |

单登记，本条不改）；Grok #1 写错误路径（有意不清零，注释已写）；Grok #3
