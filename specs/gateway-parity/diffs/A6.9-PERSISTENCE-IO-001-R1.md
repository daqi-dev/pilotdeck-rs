## 类别

错误对象形状（诊断文本）的**已消除**更正。原条目登记的限制是：Rust 存储 IO 失败直接
`Display` 原生 `io::Error` 文本（`File exists (os error 17)`），没有 Node 的 `code` /
`errno` / `syscall` / `path`。本次在 fs 调用点补上 syscall 与路径，并复用 `node_io`
已实测的 libuv 表渲染，该形状差异消除；状态与重试语义未改。残留一项路径文字差异（见
「范围」），不请求判分豁免。

## Rust 行为

- `storage/transcript.rs` / `storage/transcript_adapter.rs` 的 fs 调用点用
  `node_io::path_error`（`mkdir` / `open` / `stat` / `lstat` / `realpath` / `rename` /
  `unlink`）与 `node_io::descriptor_error`（`write` / `fsync` / `read` / `lseek` /
  `fstat`）标注真实 syscall 与路径；叙述器改名时诊断指向调用方要替换的 transcript，
  不指向 Rust 兄弟临时文件名。
- `storage/mod.rs` 的 `LedgerError::Io` 仍是 `io::Error`（阶段信息在 error 内），
  `Display` 经 `node_io::staged_diagnostic` 渲染 Node 文本；**没有被调用点标注的错误
  保持 Rust 原文**，Display 不猜 syscall。
- `node_io.rs` 新增 `os_errno`（穿透 `Stage` 取原始 errno）、`staged_fields`（syscall +
  路径）、`staged_diagnostic`（复用 `diagnostic_or_unknown`）。
- 未改 JSONL bytes、提交次序、锁语义与重试行为；`LedgerLock` 的 WouldBlock 仍是
  Rust 专有的合成拒绝，不伪装成 Node 错误。

## 范围

仅事件持久化 host IO 错误的诊断形状。实测同场景 Rust 输出：

```text
Store(Io(Custom { kind: AlreadyExists, error: Stage { source: Os { code: 17, ...
  path: Some(".../parent"), syscall: "mkdir" } } }))
display=EEXIST: file already exists, mkdir '.../parent'
```

四格状态 `(0, None)` → `(1, Some(<id>))` → `(1, Some(<id>))` → `(2, Some(<id>))`，
终读 `entries=2`，与 TS 逐格一致（entry id 为各自 fixture 的生成值）。

残留（不在本条消除范围，也未请求豁免）：`path` 是 Rust 锁先 `canonicalize` 后的绝对
路径（macOS 上 `/var` → `/private/var`），TS 打印调用方给出的原样路径；调用方传入相对
路径时两者文本不同。形状（四个字段与 message 模板）一致，只有路径文字可能不同。

## 机器判据

断言首次与中途失败的 `code=EEXIST`、`errno=-17`、`syscall=mkdir`、路径以 `parent`
结尾、`Display` 与 Node message 逐字节相等，并逐格校验序列、末条 id 与终读两条。

在 message 断言处转红；恢复后转绿，红/绿原始输出见 `_tmp/20261106-issue-1554/negative-control.log`。
