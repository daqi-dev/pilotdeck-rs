## 类别

有意改进（**非**「不可避免」：TS `Promise.all` 的时间序首拒在 Rust 可用
completion-race 等价实现——如 `FuturesUnordered` 逐完成取首错——故不是
被迫偏离）。选择 key 字典序首错是刻意换取**确定性测试面**：completion
顺序依赖真实文件系统与调度时序（同一构造两次运行可以报不同 key 的错
误），任何「报哪个错」的断言都不可确定性复算；key 序让 `flush` 的失败
面可以被单线程用例钉死。偏离面仅限「同一 `flush` 内 ≥2 个 key 写失败且
错误文本不同」时**报哪一条错误串**；每个 key 仍全部尝试（`Promise.all`
的这一半语义由既有判据钉死，见「机器判据」），金样不覆盖失败路径。

## TS 依据

固定基线 cc7c4e65（`/home/clawbox-08/ws/pdrs-runner/resources/PilotDeck`，
实测该树 HEAD == cc7c4e65），Node v22.22.0。weixin 侧 `flush` 是共享持久
化直通：`src/cli/ChannelAdapterBundle.ts:117-125`（`hotStartWeixin` 以
`this.state.load/save("weixin", …)` 接 mapper，`flush()` 直通
`this.state.flush()`）→
`src/adapters/channel/protocol/ChannelStatePersistence.ts:56-63`：

```ts
async flush(): Promise<void> {
  for (const [key, timer] of this.pending) { clearTimeout(timer); this.pending.delete(key); }
  const keys = new Set([...this.dirty.keys(), ...this.inFlight.keys()]);
  await Promise.all([...keys].map((key) => this.ensureWrite(key)));
}
```

首拒时间序实测（探针
`_tmp/20261026-issue-1725/fix-r1/probes/p1-weixin-flush-first-rejection.mts`，
原始输出同目录 `.txt`；上一轮 P3 探针
`_tmp/20261111-issue-1725/probes/p3-state-flush.*` 已钉「每个 key 先于任何
拒绝被尝试」）：

- 真类真盘件：两个 key 同一 `flush` 内以不同错误文本失败（`aa` 目标被目
  录占 → rename `EISDIR`；`zz/enoent` 的 tmp 落在缺失子目录 → write
  `ENOENT`），30 轮采样全部报 `zz/enoent` 的 `ENOENT`——时间序首拒（它
  比 rename 少一次 syscall），**不是** key 序首错（`aa` 的 `EISDIR`）。
- 受控时序（真实 `flush` 不动，仅以实例属性遮蔽 `ensureWrite`——上一轮
  P3 探针同法：两 key 以不同错误文本在受控时刻拒绝）：zz 5 ms / aa
  40 ms → 报 `boom-zz`；aa 5 ms / zz 40 ms → 报 `boom-aa`。同 key 序、
  报错随首拒时间翻转，钉死 `Promise.all` 时间序即 `flush` 继承的语义。

## Rust 行为

`src/pilotdeck-gateway/src/channel/weixin/state.rs`（符号锚点，`grep -n`
复算）：`flush` 清 pending 定时器后收集 dirty ∪ in_flight 的 key，
`keys.sort_by(|a, b| a.units().cmp(b.units()))`，`join_all` 并发跑完每个
`ensure_write`，再**按 key 字典序**返回第一个 `Err`。该实现是 Rust 侧唯一
一份 `ChannelStatePersistence`（`native_process/channels.rs` 的
`NativeChannels::flush` 直通它，与 TS `ChannelAdapterBundle` 一个实例服务
全部 channel 同构），故本条覆盖整个 channel bundle 的 flush，不止 weixin
一个 channel key。错误串上溯：`src/pilotdeck-gateway/src/native_process/
assembly.rs` 的 teardown 里 `cleanup_channels.flush().await` 的 `err()` 进入
关闭 outcome 诊断（对用户可见），故「报哪条错误串」是可观察面。

## 范围

仅「同一 `flush` 内 ≥2 个 key 写失败且错误文本不同」时报哪一条错误串。
不涉及：每个 key 是否都被尝试（`Promise.all` 语义，既有判据钉死）、成功
路径字节、防抖/等待/游标语义、写盘 tmp+rename 原子性。金样（replay
oracle 等）不覆盖多 key 失败路径，本偏离不改变任何金样输出；单 key 失败
或错误文本相同的场景与 TS 无差（首拒与 key 序首错是同一条串）。

## 机器判据

- `src/pilotdeck-gateway/src/channel/weixin/tests.rs` 的
  `flush_reports_the_key_order_first_error_when_two_keys_fail_differently`：
  同一 `flush` 两个失败 key、错误文本不同（`a` 目标被目录占 → rename
  `EISDIR`；`z/sub` 的 tmp 落在缺失目录 → write `ENOENT`），断言报 `a`
  的 `EISDIR`（key 序首错）。对应 TS 形态见「TS 依据」第一点：真类同构
  造报时间序首拒 `ENOENT`，即本条登记的偏离本身。
- 负控（`src/pilotdeck-gateway/tests/fixtures/weixin-channel/
  negative_controls.py`）：`flush-error-order-reversed` 把错误选择变异成
  任意序（`outcomes.into_iter().rev()`——取字典序末个失败 key 的错误），
  上述断言 `#1725 the flush error is the key-order first key's EISDIR, per
  A8.3-CH-WEIXIN-FLUSH-001` 转红；真正的「时间序」变异体不可确定性复算
  （completion 顺序时序依赖），正是「类别」节选择 key 序的理由，故以
  确定性任意序替身作杀手。复算锚点：
  `python3 -I src/pilotdeck-gateway/tests/fixtures/weixin-channel/negative_controls.py --check`；
  变异执行走同一脚本指定 `flush-error-order-reversed`。
- 既有判据不动：`flush_attempts_every_dirty_key_before_reporting_the_first_failure`
  （负控 `flush-sequential-short-circuit`）、
  `flush_waiter_observes_the_drainers_failure`（负控
  `flush-waiter-swallows-drainer-failure`）。
