## 类别

更正 R6 的三处事实性错误（#1576 双家审查边界 / sibling P1，评审人独立核验），不改变任何
已登记差异的类别，也不新增判分豁免：R6 把折叠续行残余的 Node 结局写反、把
`fields-max-16x` 的串行测量标成「16 路并发」、§范围 把 raw 上界的残余形状写成只剩折叠
续行而漏掉请求行分隔符。第三条同时补登一个此前未登记的 Node 200 / Rust 431 形状。
**未批准，非已接受差异。**

## 基线依据

Node v22.22.0（macmini-01 · Darwin arm64 · raw socket 直接打 `node:http` 无选项
`createServer`）。本轮新增的三份原始输出随 #1576 fix-r2 证据入库：

- `_tmp/20261106-1576-review/raw/node-obs-fold-probe.out`（探针
  `_tmp/20261106-1576-review/raw/fold-probe`）：**短折叠 / 90,000 空格折叠 / 16,400 B
  折叠全部 47 B `400 Bad Request`**（`{"bytes":47,"why":"EOF"|"error:ECONNRESET"}`，
  hex `485454502f312e312034303020426164...`）；同文件 `leading-ows-90000` 对照格仍为
  200 / 141 B，说明拒绝发生在折叠本身而不是填充量。
- `_tmp/20261106-1576-review/raw/node-reqline-probe.out`：请求行 90,000 空格（target
  前 / target 后两种形状）、短双空格、plain 四格**全部 200 / 141 B**。
- `_tmp/20261106-1576-review/raw/rss-16x-serialized.txt` 与
  `_tmp/20261106-1576-review/raw/tokio-test-current-thread.txt`：`#[tokio::test]`
  无 flavor 时 tokio-macros 2.6.1 `src/entry.rs:84-90,452-456` 选
  `Builder::new_current_thread()`；实测 `fields-max` 单连 14.1 ms、
  `fields-max-16x` 211.2 ms（14.98×，串行下界 16×，真并发应 ≈1×）。

## Rust 行为

`src/pilotdeck-gateway/src/user_dialog/http_store.rs`（#1576 审查 head `37889557e`，
fix-r2 在此基础上改 guard 的 CR 状态与峰值探针的树锁）：

- **折叠续行**仍由 `HeaderGuard` 计入 raw 上界，超过 `4 × max + 2 × 8 KiB` 时写 67 B
  431（`header_guard_raw_cap_uses_node_431_bytes`，形状 `X: a\r\n<90,000 SP>b\r\n`）。
  **Node 对同一形状是 47 B 400，不是 200**：真实残余是「Rust 431 vs Node 400」，两个实现
  都拒绝该畸形头，只是状态码与字节不同；R6 写成「Node 该形状 200」低估了 Node 侧的拒绝。
- **请求行分隔符**（target 前 / 后的空格）同样计入 raw 上界：单测
  `header_guard_replays_node_field_budget` 末段断言
  `GET <4×max+2×8 KiB SP> HTTP/1.1\r\n` 触发 431；而 **Node 对 90,000 空格请求行是 200**
  （`raw/node-reqline-probe.out`）。这是 R6 未登记的 Node 200 / Rust 431 形状，与折叠续行
  同属「guard 仍转发、但不计入 Node 计数字节」的 raw 上界族。
- **进程峰值 RSS 探针** `header_budget_peak_rss` 的 `fields-max-16x` 格不是并发：
  `#[tokio::test]` 默认 current-thread，16 个 client / 连接 task 严格串行；实测墙钟
  211.2 ms ≈ 16 × 14.1 ms。R6 的「16 路并发下没有线性叠加（+3.30 MiB）」只能读作同一
  线程上依次解析 16 次，不能证明多 worker 并发下的上界。

## 范围

只更正 R6 的三处表述，作用面仅限 R6 自身：

1. **折叠续行残余的 Node 结局**：R6 §范围与 §机器判据称「Node 该形状 200」。实测 Node 对
   短折叠 / 90,000 空格折叠 / 16,400 B 折叠**一律 47 B 400**
   （`raw/node-obs-fold-probe.out`）。残余措辞改为「Rust 431 vs Node 400」：Node 是先拒绝
   该畸形头，不是接受后计数；R6 的「已消除」只覆盖前导 OWS，不覆盖折叠形状。
2. **`fields-max-16x` 的并发标签**：R6 峰值内存表「同上 16 路并发」不成立。该格是
   current-thread 运行时里的 16 次串行解析（`raw/rss-16x-serialized.txt`），`+3.30 MiB`
   只能说明 16 次串行解析的进程峰值；多线程 worker 下的叠加上界仍未实测，仍列为待实测。
3. **raw 上界的残余形状清单**：R6 §范围只列折叠续行；同一 PR 的
   `header_guard_replays_node_field_budget` 同时钉住请求行分隔符受 raw 上界约束，而 Node
   对 90,000 空格请求行是 200（`raw/node-reqline-probe.out`）。据此补登一个
   Node 200 / Rust 431 形状：**请求行 target 前 / 后的空格填充超过 raw 上界时 Rust 写
   67 B 431，Node 接受并 200**。该形状未批准，不据此新增任何豁免。

R6 的其余结论不变：前导 OWS 两格已消除、字段数按 Node 计数预算取值、trailer 16 KiB
原始字节上限待实测、每 parse 约 1 MiB 槽向量（`fields-max-16x` 一格按串行解读）。
