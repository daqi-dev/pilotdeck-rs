## 类别

不可避免的宿主注入边界（既有差异）：Rust 的 BuiltinMcpPaths 由宿主提供 Node/Playwright 安装路径，未移植 TS 在每次 browser-use 标记替换时探测安装位置的行为。本条登记 #879 pr3 实测揭示的 cwd 差异，不增加判分豁免。

## 基线依据

固定 cc7c4e6 `src/mcp/runtime/projectMcpSpec.ts:45-54` 的 playwrightMcpEntrypoint 构造候选时无条件调用 process.cwd，`:66-76` 的 browser-use 分支调用该函数。Node v22.22.0 实跑原 patchProjectScopedMcpSpec：绝对 projectRoot + 删除 cwd 仍抛 `ENOENT: no such file or directory, uv_cwd`，cwdReads=1。正常 cwd 结果不受影响。

金样：`src/pilotdeck-gateway/tests/fixtures/metadata-process-cwd/oracle.json` 的 absolute-base-deleted / absolute-path-deleted / browser；生成器调用原函数，未复制 TS 实现。原始 stdout 由执行者保留在 `_tmp/20261026-issue-879/ts-expanded.log`；可按 fixture README 重新取得。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/mcp/registry.rs::patch_project_scoped_mcp_spec` 使用注入的 BuiltinMcpPaths。projectRoot 为绝对路径时，metadata::resolve_process_path 不依赖进程 cwd，browser-use 替换仍成功；相对 projectRoot 在 cwd 删除时返回带 uv_cwd 消息的 io::Error。

## 范围

仅 browser-use、宿主已提供 BuiltinMcpPaths、绝对 projectRoot 且进程 cwd 无法取得。FunASR 及通用 path.resolve 的绝对路径短路与 TS 实测对齐；不为模拟 TS 的额外安装探测而添加 cwd 读取。不改变非 stdio / 非 builtin 早返回，以及其余 #879 包的 cwd 回退。

## 机器判据

`metadata::process_cwd_tests::{absolute_base_deleted,absolute_path_deleted}` 要求 Rust browser-use 成功，同时金样明确保留 TS error；fixture 的 ignored `metadata_process_cwd_regenerates_identically` 保证 TS 记录可重生成。`absolute-path-needs-cwd` / `absolute-base-needs-cwd` 负控锁住公共 resolver 的绝对路径分支；`registry-path-swallow` 锁住相对路径不能吞错。负控只许提交后的 HEAD，由协调者运行 fixture/negative_controls.py。
