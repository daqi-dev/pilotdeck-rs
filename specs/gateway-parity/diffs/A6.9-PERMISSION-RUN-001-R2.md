## 类别

实现修复与剩余端口差异登记；不新增已接受差异或判分豁免。更正 R1 未覆盖的 profile 拒绝层次及 emit 异常边界。

## 基线依据

cc7c4e6 `src/cli/SessionInteractionBundle.ts:117-127` 将 PermissionRuntime 包在 ProfiledPermissionDecisionPort 中，只有真实 gateway answerer 时安装 callback；`src/interaction/ProfiledPermissionDecisionPort.ts:35-48` 只把 ask 交给 policy，保留其他决定。`InteractionPolicy.ts:35-43` 顺序为 disabled、canPrompt=false、无 answerer。

本轮 `src/pilotdeck-gateway/tests/fixtures/interaction-permission/generate.mts` 直接 import 上述真实类并构造 bundle/attach，八例输出保存为同目录 profiles.json；原始证据 `_tmp/20261025-issue-586/pkg2-fix2/ts-probe/`。实测 ordinary canPrompt=false 的底层 deny 保留 `Permission prompt denied because prompts are disabled for this session.`；forced MCP ask 才得到 profile 的 `Prompts are disabled for this session.`。headless ask 得到 `No interaction answerer is available.`；disabled ask 得到 `Interaction is disabled for this profile.`，不能把所有底层 deny 改成这三条短文案。

`src/gateway/permission/createGatewayPermissionHook.ts:158-164` 实测 emit 抛 Error("sink failed") 或字符串均返回 deny/message=`Permission prompt delivery failed: sink failed`；先同步答复 allow 再抛错或返回 false 则保留第一份 allow。原三例 hook 的完整 result/rules 与既有 oracle 一致；补采集在 `ts-probe-2/`，profile 输出与首次采集逐字节一致。

## Rust 行为

`runtime/project/interaction_permission.rs` 的 decide 保留底层上下文与非 ask 决定，仅对 ask 应用 profile policy；request 的防御检查同步短文案。调用方不得对不可提示的决定再创建 lifecycle wait；本包仍不安装 hook。直接 request 且 policy_can_prompt=false 的防御拒绝保留底层 Gateway policy 文案，此路径正常组合先在 decide 拒绝。

emit 返回 false 时优先读取已经同步收到的答复，复现 TS settle 的首响应优先；没有答复才返回 no-sink deny。`synchronous_answer_wins_over_delivery_false` 比较原 allow oracle 并检查完整 remember 规则及 pending 清理。

**剩余差异**：PermissionTurnOptions.emit 仍为 `Fn(JsValue) -> bool`，没有 Result 错误通道；false 映射既有 no-sink deny，Rust panic 继续 unwind，不映射 TS 的 delivery-failed deny。pending 注册由 RequestGuard 在 unwind 时回收，不写 remember 规则。本轮按任务允许的「闭包无错误通道则说明并登记」分支处理，不把 panic 当作可等价捕获的 JS Error，也不宣称该分支逐字一致。

## 范围

仅第二包 permission 决定和请求端口；保留原条目 generation/run 所有权差异。emit 的可恢复错误协议需要后续端口接线确定；本条不是对该差异的批准。第三包负责 extractSessionAllowRules 的提取接线，本轮仅明确 request 的已提取 suggestions 契约。
