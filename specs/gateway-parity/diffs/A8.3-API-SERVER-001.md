## 类别

不可避免的运行时差异（向安全偏离）：`null` 请求体在 TS 基线触发未捕获
`TypeError`，整个 api-server 进程退出；Rust 端口按普通非法请求返回
`400 messages_required`，进程与其它会话继续服务。本条不请求判分豁免，
也不把 `null` 格纳入金样矩阵。

## 基线依据

固定基线 `cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85`，Node v22.22.0 /
ICU 78.2。`src/adapters/channel/api-server/ApiServerChannel.ts:213`
直接读取 `body.messages`，未先判 `body` 是否为对象；`body` 为 JSON
`null` 时抛出 `TypeError: Cannot read properties of null (reading
'messages')`。该异常在 `handleRequest` 的异步链
（`ApiServerChannel.ts:176`）中未被捕获，Node 以 exit 1 终止。

真实 Node 实测：`_tmp/20261026-issue-1333/probe/probe4.out`，原始输出
（节选）：

```text
D oversized: {"closed":true,"len":0,"head":""}
.../ApiServerChannel.ts:213
    const messages = body.messages as Array<{ role: string; content: unknown }> | undefined;
                          ^
TypeError: Cannot read properties of null (reading 'messages')
    at ApiServerChannel.handleChatCompletions (.../ApiServerChannel.ts:213:27)
    ...
Node.js v22.22.0
exit=1
```

同一探针里的 `D oversized` 行属于 A8.3 的另一格（超限体零字节关闭），
与本条无关。`null` 不是 `oracle.json` 的 cell：TS 无法在不崩溃的前提下
产出金样。

## Rust 行为

`src/pilotdeck-gateway/src/channel/api_server/server.rs` 的
`chat_completions` 用 `parse_json` 得到 `JsValue`，再以 `parsed.get("messages")`
读取字段；`JsValue::Null` 没有该字段，落入 `messages_required` 校验，返回
`400`、`event: "api_messages_required"`、`code: "messages_required"`。没有
`unwrap`/索引访问，也没有 panic；请求任务结束后监听器继续接受后续请求。
该路径与 `42`、`"x"` 等非对象 JSON 的处理一致（TS 对它们不抛异常，也走
同一 400）。

## 范围

仅 JSON 字面量 `null`（以及同一字段读取方式会崩溃的同类非对象输入，若
TS 将来扩大）这一格。所有正常对象、数组、缺字段、空消息的校验与状态码
保持金样一致。Rust 的 400 是拒绝非法输入，不是放宽校验；不改变鉴权、
CORS、SSE、超限体、生命周期任何行为。TS 的崩溃不被模拟，也不把进程
退出当作可接受行为。

## 机器判据

`src/pilotdeck-gateway/src/channel/api_server/tests.rs::null_body_is_registered_divergence`
启动真实 Rust 监听器，发送 `null`，断言 `400` 且体含
`"code":"messages_required"`。`oracle.json` 不含 `null` cell；
`replays_real_ts_api_server_cells` 因而不覆盖本条。真实 Node 原始输出见
`_tmp/20261026-issue-1333/probe/probe4.out`，复跑探针
`_tmp/20261026-issue-1333/probe/probe4.mts`（Node v22.22.0，
`PDRS_BASELINE` 指向上述提交）。
