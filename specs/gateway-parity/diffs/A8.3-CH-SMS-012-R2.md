## 类别

更正（判废规程会丢反证 / 缺版本门禁 / 同类清单漏项，非差异变化）：
`A8.3-CH-SMS-012-R1.md`「机器判据」里的判废条款有三处会让审计看不到反证或归属
含糊（#2049 三条，来源是 PR #2029 第六轮 DeepSeek 四角色评审的 P2）：

1. `A8.3-CH-SMS-012-R1.md:127-129` 把 `stop()` 提前 resolve 的成因写成「连接被
   提前关闭**或**端口被别人占了」，并一律判废。端口被占时 `start()` 的 listen
   失败会把 `channel.server` 置空
   （`resources/PilotDeck/src/adapters/channel/sms/SmsChannel.ts:103-106`），首行
   必然缺 `headersTimeout`，已被同一判据的前置条件排除，成因只剩「连接结束了」。
   R1 的判废条件**一条不删、一条不改**（含 `stopResolvedMs < stopCalledMs` 与
   `connectionEndedMs < stopCalledMs`）；本条只补一条留档要求：若该次运行同时
   带有下文定义的**反证签名**，它就是「`stop()` 阻塞到客户端离开」的反证，必须
   连同成因说明一并留档，不得静默重跑把它丢掉。
2. 判废列表没有基线运行时版本项：条目把行号锚与 60 s / 30 s 默认值全钉在 Node
   v22.22.0 / ICU 78.2，产物首行也已记这两个字段，但在别的 Node 上重跑可以满足
   现有全部判废条件，而被当作 v22.22.0 基线的证据采信。
3. 「截至 2026-11-07 的同类清单」（`A8.3-CH-SMS-012-R1.md:86-92`）漏了
   `A8.3-CH-SMS-011.md:29-32` 的「停在**请求头**阶段的连接仍能把任务与 fd
   无限占住」；同一份 R1 的 `:83-85` 已判定该句随 #1955 的 60 s 头读期限失效，
   归属含糊：既说它失效，又不在由 #2021 统一处理的清单里。

本更正只收紧重跑/采信规程与同类清单，不放宽任何判据，不改变四条残差、任何实测
数字或实现行为。

## 基线依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0 / ICU 78.2。

- **端口被占一格（本轮实测，2026-11-07）**：先起 dummy TCP 监听器占住
  `127.0.0.1:18871`（`_tmp/20261107-issue-1955-ledger/evidence/dummy-listener.mjs`），
  再用真实 `SmsChannel` 探针
  `_tmp/20261107-issue-1955/smoke/ts-stop-drain.mjs` 在同一个端口上跑。原始输出
  `_tmp/20261107-issue-1955-ledger/evidence/stop-drain-port-busy.out`（同目录
  `.err` / `.rc`，`rc=0`）：
  - 首行：`{"phase":"started","node":"v22.22.0","icu":"78.2","port":18871}`
    ——**没有** `headersTimeout` / `requestTimeout` / `keepAliveTimeout` 字段；
  - 记录行：`{"scenario":"stop-with-stalled-half-head","stopCalledMs":1002,"stopResolvedMs":1002,"stopWaitedMs":0,...}`
    ——`stop()` 立即 resolve，`stopWaitedMs=0`，且 `afterStopPort` 仍是
    `"accepted"`（端口还在别人手里）；
  - stderr：`[ts] sms: HTTP server failed: Error: listen EADDRINUSE: address already in use 127.0.0.1:18871`。

  即：端口被占的运行**必然**被「`headersTimeout` 不是 60000」这一前置排除，
  不需要、也不应该再在「提前 resolve」的成因里保留它。
- **版本字段的位置**：同一族的正常运行首行都带 `node` / `icu`，例如
  `_tmp/20261107-issue-1955-ledger/evidence/ts-stop-drain-2021.out` 与
  `ts-body-read-timeout.out` 的首行均为 `"node":"v22.22.0","icu":"78.2"`。
- 行号随 Node 版本可变（R1 已述）；本条不引入新的版本假设，只把已有的
  v22.22.0 / 78.2 前提写成可机检的采信条件。

## 机器判据

本条不新增机器可跑用例（R1 已说明「`stop()` 不等连接」目前只有代码结构为据，
测试缺口登记 #2035）；收紧的是**重跑产物的采信条件**，逐条可机械判：

- `python3 -I scripts/gateway-parity/check_frozen.py --base origin/main` 通过
  （只新增文件，不改既有字节）。
- 端口被占一格可复现：起 dummy 监听 → 用同一端口跑
  `PROBE_PORT=<port> PROBE_DEADLINE_MS=5000 node _tmp/20261107-issue-1955/smoke/ts-stop-drain.mjs`
  → 首行必须无 `headersTimeout`，`stopWaitedMs=0`，stderr 含 `EADDRINUSE`。
  本轮原始输出 `_tmp/20261107-issue-1955-ledger/evidence/stop-drain-port-busy.out`
  （dummy 监听器已按精确 pid 停止，未用 `pkill -f`）。
- 版本门禁可核：任何被采信的产物，首行须同时含 `"node":"v22.22.0"` 与
  `"icu":"78.2"`；缺一或不同即作废。
- **反证签名**（本条唯一新增的可机检规则；**不新增、不删除、不修改任何判废
  条件**，R1 的判废与重跑规程原样有效）：
  - 适用对象：stop/drain 族产物——文件名匹配 `ts-stop-drain*`，或记录行
    `scenario` 为 `stop-with-stalled-half-head`。族外产物（`ts-body-read-timeout
    [-gold].out`、`ts-half-head.out`、`ts-zero-and-delayed.out` 等没有 `stop()`
    阶段的探针）只受版本门禁约束，不适用本签名，也不因缺 `stopCalledMs` 等字段
    判废。
  - 前提：已通过 R1 全部判废条件（记录行存在、四个时刻字段为有限数值、
    `headersTimeout == 60000`、`stopResolvedMs ≥ stopCalledMs`、
    `connectionEndedMs ≥ stopCalledMs`、窗口足够）。
  - 判定：`stopResolvedMs + 100 ms ≤ connectionEndedMs` → 该次运行显示 `stop()`
    在连接结束 100 ms 之前就返回，即**反证**「`stop()` 阻塞到客户端离开」。
    两个时刻同为本进程的 `Date.now()`（同一事件循环内先后取戳），loopback 上
    事件投递抖动在个位数毫秒，100 ms 是 10 倍余量；探针在 `STOP_AFTER_MS`
    （1,000 ms）之后的任何真实等待都远大于 100 ms。
  - 处置：带签名的产物须以「复现失败」入档并附成因说明，不得静默重跑后只留新
    产物；不带签名的产物无此要求，判废与否仍只看 R1 的条件。
- 在档产物现核（2026-11-07）：`ts-stop-drain-2021.out` 记录行
  `stopCalledMs=1001`、`stopResolvedMs=connectionEndedMs=199964`、`ended=false`
  → **不带反证签名**（两个时刻同毫秒）。该产物没有记录 `PROBE_DEADLINE_MS`，
  也没有记录连接结束的成因，本条**不作「探针在窗口终点销毁套接字」之类的因果
  断言**，只按落盘字节记观测值。`stop-drain-port-busy.out` 首行无
  `headersTimeout`，在门禁即作废；`ts-stop-drain.out`（`200003 / 200003`）与
  `ts-stop-drain-zero.out`（`30002 / 30002`）同样不带签名。
