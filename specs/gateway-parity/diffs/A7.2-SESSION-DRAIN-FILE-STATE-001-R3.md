## 类别

#1022 fix-r3 补充取消 caller 后的临时 BUSY 失效与 pending 清理错误跨 idle sweep 保留；修复自身生命周期保证。

## 基线依据

沿 R2 的固定 cc7c4e6、Node v22.22.0 真实 AgentHandle 四格金样（`session-disposal-retry/oracle.json`）。本轮重新采集并逐字节一致；错误未消费格仍返回相同 AggregateError。TS 没有 Rust future drop/writer budget/pending token；本项不声称这两条 Rust 组合与 TS Router 端到端一致。

## Rust 行为

owner 读到未消费 `SESSION_WRITER_BUSY` 时，只有前驱已正常完成 recreation drain 才丢弃这个过期错误并继续创建；仍有 activity 或未完成清理时保持原拒绝行为。dispose 清理错误即使已由后台 factory worker 消费，仍须交付外层 caller，不能仅凭 drain 完成清除。idle sweep 跳过所有含 pending error 的 record，显式 close/shutdown 继续用原 disposer 结果返回/聚合错误。

## 范围

补充 R2 的未消费错误交付保证，不改变冻结判分。普通 prepare/setup/读取错误沿 R2 保留，不扩展为自动重试。没有下一 caller 的 pending record 持续保留至显式 close/shutdown，这是避免无接收方吞错的既有策略延伸。

## 机器判据

`factory_tests.rs` 的 `recreation_cancelled_timeout_{retries_after_drain,keeps_active_predecessor}` 验证取消、BUSY、迟到 drain、仍活跃前驱；`recreation_{cancelled,unconsumed}_owner_error_survives_idle_sweep` 验证发送前/后取消、idle 到期和错误交付。`session-factory/negative_controls.py` 的 `r3-owner-replays-drained-busy`、`r3-idle-sweeps-pending-error` 为配对编译期开关负控，完整名与专属断言由执行器绑定。沿用 ignored `disposal_retry_regenerates_identically` 守卫。
