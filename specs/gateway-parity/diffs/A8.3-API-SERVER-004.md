## 类别

传输层呈现差异（不可避免）：api-server 车道复用
`crate::http_proxy::serve_connection_native_with_shutdown` 的 hyper 1.x
HTTP/1.1 编解码器。body 读超时（Node `requestTimeout` 等价，300 s）后写出的
408 在语义上与 TS 一致（状态行 408、`Connection: close`、零长 body、随后关
连接），但 hyper 公开 API 对未知长度的空 body 一律补 chunked 帧，Node 的
`_http_server.js` `requestTimeoutResponse` 是 51 字节无帧原文。hyper 不提供
改写该帧的公开扩展点，属 A8.4-NATIVE-HTTP-001 与 A8.3-CH-WEBHOOK-001 已
登记的同一 hyper-public-API 呈现差异类；本条只把该类的适用范围扩到
api-server 车道。

## 基线依据

固定基线 `cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85`，Node v22.22.0。

- `src/adapters/channel/api-server/ApiServerChannel.ts` 用
  `http.createServer(...)`（无 options，故 `requestTimeout` 取 Node 默认
  300000 ms）；body 未读完时由 Node 回 `requestTimeoutResponse`。
- Node 原文 51 字节：`HTTP/1.1 408 Request Timeout\r\nConnection: close\r\n\r\n`
  （无 `content-length`、无 `date`、无 `Transfer-Encoding`）。本车道实测探针
  `_tmp/20261106-issue-1620/probe/probe-408.mts` / `probe-408.out`
  （真 `ApiServerChannel`，`requestTimeout` 缩短到 800 ms：客户端收到
  `status=408`、`headers={"connection":"close"}`、空 body，socket 上恰
  51 字节 `HTTP/1.1 408 Request Timeout\r\nConnection: close\r\n\r\n`），
  同字节常量见 `src/pilotdeck-gateway/src/user_dialog/http_store.rs` 的
  `NODE_408_RESPONSE`。
- 本车道的 TS 侧实测由金样格 `body-read-timeout` 采集
  （`src/pilotdeck-gateway/tests/fixtures/api-server-channel/generate.mts`，
  `oracle.json` 的 `sourceCommit` / `node` / `icu` 记录基线）。

## Rust 行为

`src/pilotdeck-gateway/src/channel/api_server/server.rs` 的
`chat_completions` 以 `shared.body_read_timeout`（默认 300 s，可注入短值）
为 body 读的唯一 deadline；超时后 `handle` 返回
`crate::channel::webhook::node_request_timeout_response()`，hyper 在写响应时
把未知长度空 body 帧化为 `Transfer-Encoding: chunked\r\n\r\n0\r\n\r\n`。
线上字节因此是
`HTTP/1.1 408 Request Timeout\r\nConnection: close\r\nTransfer-Encoding: chunked\r\n\r\n0\r\n\r\n`，
与 webhook 车道 `WEBHOOK_REQUEST_TIMEOUT_RESPONSE` 同一形态（没有 `Date`：
`handle` 对该响应跳过 `finish`）。

本条只登记「帧化」这一项呈现差异，不含状态码、头名语义、`Connection:
close` 或连接关闭行为上的任何差异；也不含触发时机（Rust 恰在 deadline，
Node 落在 30 s connections-checker 网格，同 A8.3-CH-WEBHOOK-002 的机制）。

## 范围

仅 api-server 车道 `POST /v1/chat/completions` 的 body 读超时 408 的**帧级
呈现**，一条响应、一个场景：客户端声明 `Content-Length` 后不把 body 发完，
超时到期时线上字节。不影响其它响应（JSON / SSE / 404 / 401 等）的帧化，
也不影响判分比较的 status / headers / body 语义。

## 机器判据

- `src/pilotdeck-gateway/src/channel/api_server/tests.rs`
  `partial_body_is_answered_at_the_body_read_deadline`：半截 body + 客户端
  保持 socket → 收到 408、`Connection: close`、空 body，并发 `stop()` 在有界
  时间内返回。该测试按 status / `Connection` / 去帧后的 body 断言，不把
  chunked 帧当成基线字节。
- 金样格 `body-read-timeout`：
  `replays_real_ts_api_server_cells` 断言 TS 侧 `status: 408`、空 body、无
  `error`、`stalledAfter` < 声明长度。
- 负控：`api-server-channel/negative_controls.py` 的
  `api-server-body-read-no-timeout`（去掉期限，上条测试转红）。
