## 类别

按真实 TS 复算修正 #778 默认工厂与数值边界；不登记新的已接受差异，不宣告阶段完成。

## 基线依据

Node v22.22.0、cc7c4e6，`edgeclaw-native-default/observe.mts` 直接导入固定源。43 格配置包含宿主 telemetry、空 rootDir、batch/maxMessageChars 的 0、负数、小数、超大、NaN、正负 Infinity，以及显式 flush batch 覆盖。真实 `service.flush` 与 `repository.listPendingSessionKeys` 分别记录 SQL LIMIT 和 preferred slice 结果。

`core/storage/sqlite.ts:509-540` 的构造顺序经实测：数据库路径为目录时，memory/global 根目录先创建，DB 打开失败后没有 FileMemoryStore 子目录；损坏文件可先打开，FileMemoryStore 子目录先创建，随后 schema 初始化报错。此前仅比较文件内容漏掉了空目录差异；补充逐路径目录金样，不把提前校验损坏文件当成 TS 行为。

## Rust 行为

默认工厂保留 JS 数值，经 service、indexer 到 storage 才按具体操作处理：SQL 绑定原始 number，preferred 选择按 JS slice 截断，`Math.max` 保留 NaN。JS 错误出口移除 Rust 的 `sqlite:` 诊断前缀。provider 的 source 与 retrievalMode 原始选项纳入配置对拍；数据库 connect/initialize 的可观察顺序遵循上述实测。telemetry 表示边界见 A6.6-MEMORY-PROVIDER-OPTIONS-001-R3。

## 范围

本轮不改代际租约或取消协议。同 rootDir 两代并发写 SQLite 的 P2 风险仍待独立确定性交错验证，前置于同根热重载实效验收；保持既有 Node busy_timeout=0 契约。R2 的 D-4 人工验收限制继续有效。

`factory_config_matrix` 比较43格及 provider/目录清单；`heartbeat_batch_numeric_edges` 经真实 service.flush 检查配置与覆盖，再比较 SQL/preferred 两路；`storage_invalid_paths` 直接调用 with_clock 检查损坏文件和目录路径、原始坏库字节。已有 ignored 重生成守卫必须实跑。`negative.py` 声明专属完整测试名及断言，保留晚开 DB 变异并新增提前校验、telemetry 拒绝、数值截断与错误前缀等控制。执行证据及宿主待跑清单见 `_tmp/20261026-issue-778/fix-r1/RESULT.md`。
