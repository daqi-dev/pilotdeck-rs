## 类别

登记更正（差异消除）。原条目 `A8.3-CHANNEL-FEISHU-001` 登记的是「`feishu` 尚未迁移，
启用即被原生启动拒绝」这一临时状态；本 PR（#1329）把 `feishu` 加进
`IMPLEMENTED_BUNDLE_CHANNEL_KEYS` 并真正构造该通道，被登记的状态消失，本条只更正结论与
判据，**不新增任何差异，也不改变任何判定键或阈值**。

## Rust 行为

`src/pilotdeck-gateway/src/native_process/channels.rs:49`
`IMPLEMENTED_BUNDLE_CHANNEL_KEYS = &["feishu", "weixin"]`，`channel/loader.rs:128`
`BUNDLE_CHANNEL_KEYS = &["weixin", "feishu"]`：两表逐键闭合，`loader.rs:153` 的
`reject_unimplemented_bundle_channels` 对表内每个键都视为已实现，不再产生
`[adapters] channel "feishu" 未迁移到 Rust，需继续使用 TS gateway`。
`adapters.feishu.enabled === true` 时装配构造 Feishu 通道并把 `/feishu/webhook` 挂到原生
HTTP 监听器上（`native_process/assembly.rs` 的 `start_with_webhook` →
`native_http::Config.webhook`）；`enabled` 仍走严格布尔门，非布尔拼写照旧折叠为 `false`。

原条目的「机器判据」一节引用过两个已不存在的钉子，更正如下：

- `native_process/channels_tests.rs`：`startup_refuses_unimplemented_feishu` **已删除**，
  同一格由 `startup_builds_the_enabled_feishu_channel` 接替（启用 feishu → 启动成功且
  路由已挂）；`startup_accepts_configs_without_an_unmigrated_channel` 与
  `startup_rejection_reaches_stderr_in_the_debug_form` 仍在，但后者的拒绝样本改用表内
  之外的键。
- `channel/tests.rs`：`implemented_bundle_keys_are_exactly_the_assembled_weixin` 更名为
  `implemented_bundle_keys_are_exactly_the_assembled_bundle_keys`。
- `tests/fixtures/channel-unmigrated-startup/negative_controls.py` 的 FEISHU cell 换成
  BUNDLE 表 cell（把 `feishu` 从 `BUNDLE_CHANNEL_KEYS` 里删掉仍必须被杀），套件本体与
  三条变异仍在。

**给其它车道复算说明的映射**：`A8.3-CHANNEL-{QQ,WECOM,...}-001-R1.md` 等登记件里把
`startup_refuses_unimplemented_feishu` 写成必杀用例的复算命令，自 #1329 起应改读
`startup_builds_the_enabled_feishu_channel`（同一格、反向断言）；这些登记件未在本 PR 内
逐件更正（只追加规则，逐件改属各自车道的更正轮），映射以本条为准。

## 范围

只涵盖 `feishu` 这一个 bundle 键从「拒绝启动」到「构造并启动」的状态更正。`weixin` 不变
（#1328 已实现）；`loader.rs` 的 11 个 `UNMIGRATED_CHANNEL_KEYS` 与
`reject_unmigrated_channels` 不受影响；`enabled` 的严格布尔判据、错误消息文案（其它未实现
键仍用它）与启动失败路径均不变。
