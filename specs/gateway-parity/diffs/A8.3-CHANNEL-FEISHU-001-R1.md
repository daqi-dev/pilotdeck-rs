## Rust 行为

`src/pilotdeck-gateway/src/native_process/channels.rs:49`
`IMPLEMENTED_BUNDLE_CHANNEL_KEYS = &["feishu", "weixin"]`，`channel/loader.rs:128`
`BUNDLE_CHANNEL_KEYS = &["weixin", "feishu"]`：两表逐键闭合，`loader.rs:153` 的
`reject_unimplemented_bundle_channels` 对表内每个键都视为已实现，不再产生
`[adapters] channel "feishu" 未迁移到 Rust，需继续使用 TS gateway`。
`adapters.feishu.enabled === true` 时装配构造 Feishu 通道，生产入口再把 `/feishu/webhook`
的 resolver 挂到原生监听器上（`native_process.rs:43` `assembly::start_with_webhook` →
`:54` `NativeWsServer::with_webhook`；测试门面 `assembly::start` 不传 slot，见下）；
`enabled` 仍走严格布尔门，非布尔拼写照旧折叠为 `false`。

原条目的「机器判据」一节引用过两个已不存在的钉子，更正如下：

- `native_process/channels_tests.rs`：`startup_refuses_unimplemented_feishu` **已删除**，
  同一格由 `startup_builds_the_enabled_feishu_channel` 接替（启用 feishu → 启动成功、无
  拒绝错误）。**该用例的证明范围仅到此**：它走测试门面 `assembly::start`
  （`assembly.rs:139-147`，`#[cfg(test)]` → `start_observed_with_upload_cleanup`
  → `start_impl(..., webhook_slot = None)`，`assembly.rs:181-189`），只断言 `start`
  返回 `Ok`，host 随即关闭。测试路径**根本不建 webhook slot**，因此该用例既不断言
  装配产出了 `/feishu/webhook` 的 resolver（那是生产入口 `start_with_webhook` 的第二
  个返回值），也不发任何 HTTP 请求。「路由行为」由 `native_http` 层的 13 场景金样覆盖；
  装配层把 resolver 交给监听器的那一步（`native_process.rs:43`）目前无断言。
