## 类别

有意改进（向安全偏离）。TS 的 `writeFileSync(path, data, "utf8")` 用默认 flag `w`（O_WRONLY|O_CREAT|O_TRUNC），对目标 inode 不做任何校验：硬链接、FIFO、套接字、设备文件一律照写或照挂；读侧 `readFileSync`/`scandir` 同样在 `existsSync` 校验后按路径跟随任何被换入的链接。Rust 在写侧于打开后、截断前用 `fstat` 复核同一 inode，拒绝共享硬链接（`st_nlink != 1`）与非普通文件，并且打开带 `O_NONBLOCK`，使无读者的 FIFO 立即报错而不是永久阻塞；读侧自 `within()` 校验后改为从固定的 memory 根目录句柄逐级 `NOFOLLOW` 打开（`read_at` / `regular_files_at`），校验与读写针对同一目录对象，竞态换入的链接在校验后不可被跟随。该检查自 #344 起已存在于同族的 `create_new_beneath`（`wx` 排他创建），#597 将其扩展到覆盖写路径，修复轮 2 再扩展到读路径。

## Rust 行为

`src/pilotdeck-gateway/src/project_files.rs`（均为 `#[cfg(unix)]`）：

- 写侧 `overwrite_at`（`:271`）：`openat(O_WRONLY|O_CREAT|O_CLOEXEC|O_NOFOLLOW|O_NONBLOCK, 0o666)` 后 `fstat`，`FileType != RegularFile || st_nlink != 1` 返回 `EACCES`（经 `node_io::path_error` 呈现为 `EACCES: permission denied, open '<path>'`），不截断、不写入。无读者 FIFO 在 `open` 即报 `ENXIO`（`O_NONBLOCK`）。
- 读侧 `read_at`（`:319`）/ `regular_files_at`（`:356`）：自固定根目录句柄逐级 `NOFOLLOW` 打开；链上被换成符号链接时 `leaf_open_error` 以 `statat(SYMLINK_NOFOLLOW)` 确认后按 `NoFollowLoop` 拒绝，消费者映射为 `Invalid("Memory entry not found: <path>")`（fail-closed）；祖先不可达（EACCES/ENOTDIR）按 TS `existsSync` 吞掉化为 ENOENT（无文件）。
- 消费者为 `runtime/memory/edgeclaw/file_memory.rs` 的 `write_bytes`（`:664`，record / project.meta.md / MEMORY.md 全部覆盖写）与读侧 `read_file`（`:611`）/ `read_dir_files`（`:888`）。memory 根本身按信任边界处理：缺失/悬空/指向非目录时读侧按「无文件」（TS existsSync false），不作为竞态拒绝。

## 范围

- 覆盖两种场景：① 正常路径上**预先存在**的硬链接叶（用户自建备份等，TS 会写穿——本条即偏离本体）；② `within()` 校验后竞态换入的硬链接/FIFO/符号链接（TS 同样会写穿/挂起/跟随，属于 #597 要消除的 containment 逃逸：根内硬链接可使写内容落到根外 inode，根内链接可使读越出根外）。
- 写读两侧均在本条范围：写侧拒绝（EACCES/ENXIO）、读侧拒绝（`Memory entry not found`）。读侧同族差异（同一 store 的 `parsed()` / `directory()`，修复轮 2 改造）在此一并登记；A4-FILE-TOCTOU-001 只覆盖 project_files 的读 API，不覆盖 EdgeClaw memory store。
- FIFO：无读者时 Rust 在 `open` 即报 `ENXIO` 而不是阻塞（TS 挂起）；有读者时由 `fstat` 非普通文件检查拒绝（EACCES）。
- 不涉及排他创建（`create_new_beneath`，#344 已有同款检查，本条不重复登记其 `wx` 语义）。
- 错误形状与 TS 不同（TS 成功或挂起或「无文件」，Rust 报 `EACCES ... open` / `ENXIO ... open` / `Memory entry not found`），对上层 `editEntry` 等表现为该 Io/Invalid 错误而非成功。

## 更正（修复轮 3，#597 gate4 P1）

修复轮 3（提交 `5d4ff9d1`）调整了父级路径组件被换成符号链接时的错误形状：

- `:25` 中「链上被换成符号链接时…消费者映射为 `Invalid("Memory entry not found: <path>")`」**仅适用于叶节点**换出的场景（`mutation_race_read_leaf`）。父级路径组件（中间目录）被换成符号链接时，`read_at` 的 `walk_beneath` 返回 `NoFollowLoop`，修复轮 3 显式映射为 `ELOOP`，消费者经 `mutation_error` 呈现为 `Io("ELOOP: too many symbolic links encountered, open '<path>'")`。
- `:31` 的「读侧拒绝（`Memory entry not found`）」限于叶换出场景；父级组件换出为符号链接时，`read_at` 路径报 `ELOOP`（Io 错误，非 Invalid）。注意：`regular_files_at`（directory() 路径）未补同款映射，父级换链仍报 `Invalid("Memory entry not found")`，本更正仅涵盖文件读路径（`read_at`）。
- `:34` 补充：`read_at` 路径父级组件竞态换出时 Rust 报 `ELOOP ... open`。**自环链接**场景下 TS `readFileSync` 同样报 `ELOOP`（一致）；**换入指向有效目录的链接**时 TS 按路径跟随成功读到根外内容——这仍属 §范围② 登记的 containment 偏离（`ELOOP` 为 Rust 选定拒绝形状）。两种子场景行为不同，不能笼统声称「两者已对齐」。
