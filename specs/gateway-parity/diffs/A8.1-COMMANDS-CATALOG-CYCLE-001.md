## 类别

已知未对齐的接口表示边界：既有 `CommandsListResult.value: JsValue` 是树形值，不能承载循环 YAML 对象图。本条只登记事实，不批准行为差异。

## 基线依据

cc7c4e6 `src/gateway/dialog/commands.ts:136-138` 使用 yaml.parse，`:76-81` 返回包含原 metadata 的目录页。Node v22.22.0 实跑真实 `listCommands`：入选的 `self: &x [*x]` metadata 使 list 成功，`metadata.self[0] === metadata.self` 为 true，后续 JSON.stringify 才抛 TypeError。可重生成金样为 `src/pilotdeck-gateway/tests/fixtures/commands-catalog/oracle.json` 的 `selected-cycle`；生成入口在同目录 `generate.mts`。本次原始输出保留于 `_tmp/20261026-issue-887/resume-node.log`。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/plugins/catalog.rs` 在去重、过滤、分页后才将入选 metadata 转成 JsValue；入选循环图返回 `Cyclic alias graph cannot be represented by JsValue`，因此失败阶段早于 TS。被覆盖、被 query 排除或不在当前页的循环图不会令当前目录页失败。

## 范围

仅显式注入 `NativeCommandCatalogProvider` 后入选页中的循环 YAML metadata。默认 gateway dispatch 未接入本 provider。正常树形 metadata 与 Map/Set 的 JSON 投影分别有金样，不能据此声称保留 TS Map/Set 对象身份或全面对齐 TS 内存对象图。解决循环图的阶段差异需要另行确定既有结果接口的对象图表示或批准错误边界，当前未扩展协议。

## 机器判据

`runtime::plugins::catalog::tests::catalog_selected_cycle_boundary` 核对 TS 成功/循环身份/不可序列化三项事实，并验证 Rust 的明确拒绝；这是差异测试，不是对齐通过。`catalog_excluded_cycles` 对拍排除循环图后仍成功的结果；负控 `commands-catalog/negative_controls.py` 的 `selected-cycle` 禁止静默丢弃循环 metadata。运行 `cargo test -p pilotdeck-gateway --lib runtime::plugins::catalog::`；金样重生成守卫为 `catalog_regenerates_identically`（ignored，需要 PDRS_BASELINE 与 Node v22.22.0）。变异编译、击杀与恢复正控待本包提交后由协调者在宿主执行，不能以脚本存在充验收。
