## 类别

宿主相关行为差异（不可避免，未批准）：空 `webhookHost`（`host.is_empty()`）时，
TS 基线的 `listen(port, "")` 在双栈 `::` 上服务，Rust 侧只在宿主未开启
`IPV6_V6ONLY` 时同样拿到双栈；宿主开启 v6only 时回退 `0.0.0.0`，`::1` 不再可达。

## 基线依据

固定基线 `cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85`，Node v22.22.0 / ICU 78.2。
`tests/fixtures/channel-sms/oracle.json` 的 `empty-webhook-host` 用例记录
`sms: Twilio webhook http://:18851/sms/incoming`（Node 侧 host 为空串仍能监听）。
本机实测（`_tmp/20261106-issue-1339-fix-r3/bind-probe.out`）：
`TcpListener::bind(("::", 0))` → `[::]`，127.0.0.1 与 ::1 均可连（该宿主
`net.inet6.ip6.v6only` 未开）；`("[::]", 0)` 与 `("", 0)` 均解析失败。

## Rust 行为

`src/pilotdeck-gateway/src/channel/sms/mod.rs` 的 `bind_dual_stack`：先绑
`("::", port)`；再以 `listener.local_addr()` 的端口试绑 `127.0.0.1`，冲突即
判定双栈并保留该 listener，成功则判定宿主为 IPv6-only，返回 `Err`，调用方
改绑 `("0.0.0.0", port)`。因此 v6only 宿主上本通道只服务 IPv4，而 TS 基线
在 `::` 上同时服务 v6（`::1`）。

## 范围

仅空 `webhookHost` 的监听地址族。显式 `webhookHost`（`127.0.0.1`、域名、
`203.0.113.7` 等）不受影响。55 个 oracle cell 的探针全部走 `127.0.0.1`，
现有对拍看不见 v6 差异，故不改变任何 cell 的判定结论。

## 机器判据

- `bind_dual_stack` 的探测端口取自 `listener.local_addr()`（覆盖
  `webhookPort: 0`：探测 `127.0.0.1:0` 恒成功会把每个临时端口启动都降级成
  IPv4-only）。
- 正控：`cargo test -p pilotdeck-gateway --lib channel::sms` 全绿（含
  `logger_panic_does_not_poison_boundaries` 的 `webhookPort: 0` 路径）。
- 未覆盖：v6only=1 的宿主本机不可复现，需在 `net.ipv6.bindv6only=1` 的机器上
  复跑 `empty_webhook_host` 并观察 `::1` 连接被拒。

## 批准记录

未批准，非已接受差异。若认为该降级不可接受，替代方案是在绑 `::` 之前显式
`setsockopt(IPV6_V6ONLY, 0)`（tokio 1.48 的 `TcpSocket` 无 `set_only_v6`，
需引 `socket2`/`libc` 直接设置）。来源为 #1339 fix-r3 增量评审：Codex P1 #3、
minimax concurrency #2 / boundary #4（P2），等级按「两家不同取高」记 P1 中的
产品侧问题；协调者按修复轮上限 3 的处理规则登记为跟进项，前置于 #1386 的
A8.3 收尾。
