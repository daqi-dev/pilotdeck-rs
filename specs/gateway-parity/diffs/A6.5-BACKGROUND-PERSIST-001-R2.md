`restore: {expectedTotalBytes}` 读盘（不看 persisted 标志）；输出缺失/长度不匹配从
构造函数抛错；`appendOutput` 每次追加后 best-effort `persistEntry`。Node v22.22.0

output from <state>/output/task-printf.log.`、crashed-running 以 unknown 恢复且
输出可读、spill-write-failure 重启抛错、dispose-flush 两格见
`A6.5-BACKGROUND-PANIC-001-R2.md`。原始输出在本轮工作树
`_tmp/20261026-issue-1233/node/persist-restart-run1.out`（run2/run3 复跑一致）。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/background.rs` `restore_snapshots()`：
`restore_task` Err 即 panic（`Background task snapshot restore failed: {error}`），
不再 `continue` 静默丢任务；有 disk_spill_dir 即总是尝试
`OutputStore::restore_from_spill`，Err panic，InvalidData 带原始错误文案，否则
`Could not restore task output from <path>.`。`Inner::append_output`：每次追加后
fire-and-forget `persist_entry_static`（保留 Rust 先 flush 落盘再写快照的次序，
比 TS 不等落盘更严，登记为 D4' 差异）。dispose 冲刷错误拒绝并留 Draining，
`BackgroundResources::dispose` 传播（详见 PANIC-001-R2）。
