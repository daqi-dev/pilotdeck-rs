# A6.5-MCP-PROXY-HTTPS-001 · MCP / 模型代理：https: 代理 URL 退化为直连

**类别**：行为差异（功能缺失）  
**批准状态**：待批（登记于 #576，理由见下）

## TS 基线

`undici` `EnvHttpProxyAgent`（`proxy.ts:131`）接受 `httpsProxy: proxyUrl`，
对 `https:` 代理 URL 建立 TLS 隧道（undici 8.3 ProxyAgent 默认 `proxyTunnel: true`）。

## Rust 现状

`ProxyConfig::new_with_extra`（`src/pilotdeck-gateway/src/runtime/model/http.rs:533`）：

```rust
if proxy.host_str().is_none() || proxy.scheme() != "http" {
    return None;   // https: proxy URL → None → 直连
}
```

`https:` 代理 URL 解析后 scheme 不为 `"http"`，返回 `None`，调用方退化为直连，不报错。

## 差异描述

`https:` 代理 URL 下，TS 建 TLS CONNECT 隧道，Rust 直连目标端点。
无功能错误，目标仍可达，但安全边界与 TS 不同。

## 批准理由

实现 `https:` 代理需引入 TLS CONNECT 双层握手，依赖评估未完成（#576 范围）。
当前直连退化在内网部署中可接受；外部 https-only 代理场景将无法穿透，行为与 TS 不一致。
待后续版本实现后撤销本条。
