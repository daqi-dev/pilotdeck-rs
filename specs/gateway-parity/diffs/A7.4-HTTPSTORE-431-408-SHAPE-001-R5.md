## 类别

差异登记与判据更正（#1277，跟进 #1232 r2 评审剩余 P2）：①登记「让位后单 burst 优先级」——
让位连接上 A（多 token `Transfer-Encoding`）与超限头 B 同一 `write` 时，Rust 先写 A 的已服务
响应再写 B 的 431，Node 只写 431；②更正 R4:139 的 hyper 缓冲界限推导（累计倍增读
122,880 B，不是「约 >123 KiB」，也不是 `hyper_buffer_bytes + 64 KiB`）；③说明

  chunked JSON 与 B = `X-Pad` 超限头（20 KB 与 200 KB 两格）**同一 `write`**。两格均

  `ended:"error:ECONNRESET"` 但 67 字节仍先到（Linux 上 RST 之前排队的数据可读，这也是

- hyper 1.7.0 `src/proto/h1/io.rs`（本地 cargo registry 源码）：`read_head` 循环里
  `parse` 失败且 `read_buf.len() >= strategy.max()`（= `max_buf_size`）才报 too_large，
  **检查只发生在两次读之间**；`ReadStrategy::Adaptive` 读块 8→16→32→64 KiB 倍增、读前
  `reserve(next)` 保证容量。⇒ 单 burst 到达时缓冲可达累计 8+16+32+64 KiB = **122,880 B**

  与 R4:139「raw 约 >123 KiB」均按此更正（评审行 2 的 `90,112 + 64 KiB = 155,648` 同样
  不是正确推导：第三个读块后 len 只有 57,344，第四个 64 KiB 读才把上界推到 122,880）。

## Rust 行为

`src/pilotdeck-gateway/src/user_dialog/http_store.rs`（本轮无产品改动，全部为判据钉住）：

- **让位后单 burst 优先级（实测，R4「让位族」新登记一条）**：fix-r1 让 guard 在 A 的多
  token `Transfer-Encoding` 处让位后，A 与 B 同一 `write` 到达时 hyper 先完整写出 A 的
  已服务响应（195 B 200，本机实测），然后才 dispatch B；B 的 `serve` `header_bytes` 兜底
  经 `force_node_response` 在 hyper 写 B 时替换为精确的 67 B `NODE_431`，随后拒绝 hyper
  的后续编码并关连接——wire = **200 + 67 B 431 + EOF**（262 B，实测两次一致）。Node 的
  parser 在读回调里就销毁 socket，**只有 67 B 431**。两实现的 B 兜底字节一致（20 KB 在
  hyper 缓冲内、200 KB 超限时 Rust 为 hyper 自己的 123 B 形状——后者是 R4 已登记的
  P2-2 差异，不变）；新差异只在**响应优先级**：A 的 200 是否先上线。
- **hyper 缓冲界限（推导更正）**：`hyper_buffer_bytes(16384) = 90,112` 仍是 `max_buf_size`
  本身，但「报 too_large 的 raw 界限」是 cap 检查位置决定的：≤ 90,112 raw 的头总能完整解析
  （到达任意粒度）；(90,112, 122,880] 区间取决于到达粒度是否填满整读块；> 122,880 恒在
  cap 检查处报 hyper 自己的 431。测试用 200 KB 与 R4 口径不变，仅推导更正。
- **零容量 park（判据补强，无差异）**：`limit == 0` 的 park（fix-r1 P2-4）没有在 socket 上
  注册 waker，但 `KeepAliveTimer::wake()` 有五个 in-band 调用点（`begin_shutdown` /
  `request_started` / `response_finished` / `read_activity` / `write_activity`），连接上任何
  写入或生命周期事件都会唤醒已 park 的读；hyper 自身从不以零容量 poll
  （`poll_read_from_io` 每次 reserve ≥ 8 KiB 的自适应块）。

## 范围

让位族单 burst 交错（多 token `Transfer-Encoding`、重复 `Content-Length` 等让位框架之后的
同 `write` 流水线超限头）：仅 step-aside 后的连接，未让位连接上 guard 仍先行 431（R4 M2，
不变）。hyper 缓冲界限更正只改推导文字与测试注释，不改变任何阈值或行为。零容量 park 无
范围变化。**转成已接受差异须另走人批程序。**
