## 类别

#1122 更正取消候选的负控判杀依据，补充显式 dispose reason 的证据范围。原条目及 R1–R3 保持原字节；本条不改变产品行为或冻结判分。

## 基线依据

固定 TS cc7c4e6 / Node v22.22.0，真实采集入口为 `src/pilotdeck-gateway/tests/fixtures/session-factory/{probe,followups,generate}.mts`，金样为同目录 `oracle.json` 的 `cancelledDisposal`。加载暂停时 shutdown 的候选使用 `session_router_shutdown`；正常 recreate 的候选保持 active，没有 dispose reason。`followups.mts::cancellationDisposal` 显式调用真实 AgentHandle.dispose(`session_create_cancelled`)，以 entered/release 门闩验证 maintenance 在 drain 前收到同名 reason，释放 callback 后恰好 dispose 一次。

TS Promise 没有 Rust future drop 的取消操作；不声称 TS Router 自动使用 `session_create_cancelled`。本轮真实 Node 探针输出及重生成结果见 `_tmp/20261026-issue-1122/fix-r3/RESULT.md`。

## Rust 行为

`runtime/session/factory.rs::PendingSession::drop` 在取消 waiter 未接收候选时，仍显式调用 `dispose("session_create_cancelled")`。最后句柄 Drop 的 `agent_handle_dropped` 兜底虽能释放资源，却不能替代这一显式 reason 契约。

`factory_tests.rs::cancelled_recreation_finishes_drain_and_candidate_cleanup` 保留真实取消重建格；候选子格持有 maintenance guard 和观察句柄，防止最后句柄 Drop 掩盖遗漏。观察只等 reason 或该候选清理 future 结束，并用短 sleep 和有界截止；不以整个 runtime 的存活任务数判定候选是否结束。仅测试构建带候选专属完成通知，不改变非测试构建的生命周期。

## 范围

更正取消候选测试与负控绑定，补记 TS/Rust 信号面的适用范围。候选子格验证 PendingSession 交接，不宣称生产未发布候选已经进入 maintenance，也不把 TS 显式调用的 reason 说成 Router 自动取消行为。R3 的 pending 错误保留、writer budget 与其批准状态仍沿用。

## 机器判据

完整测试名 `runtime::session::factory::tests::cancelled_recreation_finishes_drain_and_candidate_cleanup`：`session-factory/negative_controls.py` 的 `drain-cancelled-candidate-not-disposed` 已从旧清理等待消息 `#1022 seed cancelled cleanup bounded wait` 改绑 `#1122 pending candidate explicit disposal reason`；新增的 `drain-cancelled-candidate-wrong-reason` 绑定同一测试与同一等值断言。构造、观察、清理截止及无关 panic 均不得代替此判杀断言。

`cancelled-disposal-regeneration` 改坏 `oracle.json` 的候选状态，绑定 `runtime::session::factory::tests::cancelled_disposal_regenerates_identically` 与 `#280 session-factory/oracle.json differs`。该 ignored 守卫调用真实生成器，逐字节核对既有金样；执行命令与逐格编译、正负控结果见本轮 RESULT。

同一完整测试前缀下，`pending_candidate_observer_missing_reason_fails_by_deadline` 验证 reason 永不出现且清理永不结束时，截止产生指定 `#1122` panic；`r3-candidate-observation-deadline-accepted` 编译期开关负控把截止错误当 None 返回，绑定该测试和 `#1122 missing reason must fail by observation deadline`。`pending_candidate_observer_ignores_unrelated_tasks` 覆盖清理 producer 完成/取消、无关 pending task 仍活跃的两格，不把通道关闭当作 reason 已正确的证据。
