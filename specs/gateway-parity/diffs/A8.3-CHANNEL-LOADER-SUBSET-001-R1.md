- 构造挂载：`src/pilotdeck-gateway/src/native_process/channels.rs:112-126`
  `production_loader_mounts()`——sms / bluebubbles / slack 各自模块的 `register`，

- 生产调用点：同文件 `:349-356` `NativeChannels::create_startup_configured`——
  `load_enabled_channels(config.adapters, {pilotHome: None}, mounts, …)`，
  对齐 TS 不传 options 的形态；构造失败 error-then-continue（`loadEnabledChannels.ts:132-136`），
  报错闭包为 `console_log_line(&mut std::io::stderr(), …)`（stderr，`console.error` 的
  对应面；fix-r2 起为非恐慌写——`eprintln!` 写失败恐慌，而该闭包在 `assembly::start`
  同步段、任何 catch_unwind 之外）。
- 启动接线：`src/pilotdeck-gateway/src/native_process/assembly.rs:1078`
  （Ok(host) 分支内 `startup.extend(channel_assembly.create_startup_configured())`，
  位于 feishu/weixin 之后、`start_channels` 之前，即 TS `createStartupAdapters` 的
  configured 半区排序）。
- 可见性：`assembly.rs:822` 给 `NativeChannelsOptions` 传
  `console_channel_log()`（`channels.rs:66-75` 委托 `write_console_line`：info → stdout，
  warn/error → stderr，两者均非恐慌写），使
  `api-server: listening on …` / `sms: twilio not installed; run npm install twilio`
  / `wecom_callback: corpId, token, and encodingAesKey are required` 等启动行在原生
  进程上可见（#1853 r1 s2 记录的 TS 锚点形态）。
- 终态行为（替换原「Rust 行为」的静默跳过描述）：启用 6 键差集中任一键的配置，
  原生启动构造对应通道并进入 `ChannelServer` 后台启动——runtime-status.json 出现该键
  生命周期条目（`connected` / `<key>: started`）；缺凭证的键（如 sms 无 twilio、slack 无
  bot token、wecomCallback 无 corpId）按 TS 形态打可见错误行、保留 missing-config
  空句柄，进程照常启动；apiServer / webhook 按配置端口真实监听。构造期数值转换抛错
  （如 `extra.port: {toString: null}`，`Number()` 的 toPrimitive 失败抛 `TypeError:
  Cannot convert object to primitive value`）经挂载以 `ChannelError` 传播，loader 逐键
  `console.error` 后继续——该键不进入启动数组、无生命周期条目，后续键照常构造
  （对齐 TS 构造函数抛错形态，fix-r1；fix-r2 起守卫 `number_conversion_error`
  （`js_value.rs:309-312`，委托 `validate_coercion`）与 `Number()` 的 join 语义
  全等：数组元素、嵌套数组与 config merge 安装的原型链 `toString` 同抛 TypeError，
  过深数组抛 `RangeError: Maximum call stack size exceeded`；**已知缺口（r4 评审
  P1，挂起转人工 #2459）**：数组装载原型形态 `{"__proto__":[{"toString":null}]}`
  Rust 现放行、TS 抛 TypeError，实测 `_tmp/20261108-issue-2301/arrayproto/`）。
  未迁 9 键拒绝、
  weixin / feishu 构造、键集计算（`CHANNEL_LOADER_KEYS` 15 − `UNMIGRATED_CHANNEL_KEYS`
  9 loader 键 = 6）均不变。
