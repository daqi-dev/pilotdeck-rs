## 类别

同原条目（`specs/gateway-parity/accepted-diffs.md` 的 `A6.7-HOOK-RESOURCE-001`）：实现限制（固定预算近似 V8 栈）。本更正只修正 JSON.stringify 深度预算的数值与残余差异带；原条目的动态空重复正则预算 `MAX_EMPTY_REPEAT_WORK=2_000_000` 不变，不在本次更正范围。

原条目里被更正的一句是 `- **Rust 行为**：hooks/config.rs::MAX_STRINGIFY_DEPTH=4000 超限抛 RangeError` 中的 **4000**；同时更新原范围句「Rust 首拒到 V8 首拒之间会提前失败」的边界。

## 基线依据

原条目引用的 TS 基线不变：`cc7c4e6` 的 `extension/hooks/config/matchHookCondition.ts` 的 `matchHookCondition` 先 `JSON.stringify` 再 `includes`。新增实测对应实现提交 `3548d79087e49b0f632adf8191c02a599f742668`（位于 `origin/main` 之上），原始输出为 `_tmp/20261026-issue-335-345/depth-probe.out`（探针 `depth-probe.mts`）：

- 环境：Node `v22.22.0`、V8 `12.4.254.21-node.33`、arm64。
- 入口：直接 `JSON.stringify`、真实 `matchHookCondition` +0 帧、真实 `matchHookCondition` +32 帧；每种入口先二分最大成功深度，再采 5000/6000/6500/7000。
- 5000、6000、6500 三入口全部成功；7000 三入口全部 `RangeError: Maximum call stack size exceeded`。
- 二分最大成功深度：direct `6616`、condition0 `6613`、condition32 `6581`。同进程再测各自的 max+1 层又全部成功（`next.ok=true`），说明 V8 首败会随剩余栈/JIT 抖动，不能把某一层当作确定首败；可确认的是 6500 三入口稳定成功、7000 三入口稳定失败。按任务口径记录：首次失败观测在 **6581–6616** 之间抖动，6500 / 7000 是两端锚点。
- 所以原条目「6500 层成功、7000 失败」仍成立；6500 是三种真实入口都稳定成功的最深样本。
- hook 执行入口另测四家：`CommandHookExecutor`、`HttpHookExecutor`、`PromptHookExecutor`、`AgentHookExecutor` 的 `JSON.stringify(options.hookInput)`。四家一致：最大成功深度 `6885`，`6886` 首败；`6500` / `6501` / `6600` / `6800` 均成功，`6900` / `7000` 均失败。原始输出 `_tmp/20261026-issue-335-345/fix-r1/hook-depth-probe.out`（探针 `hook-depth-probe.mjs`，直接 import 基线 `dist/` 的真实执行器）。

## Rust 行为

提交 `3548d79` 的 `hooks/config.rs` 中 `MAX_STRINGIFY_DEPTH` 现为 `const ... = 6500`（原条目写的 4000 已过期）；`check_stringify_depth` 对 `depth > MAX_STRINGIFY_DEPTH`（即 6501 起）返回 `HookConditionError::StackOverflow`，可观察名为 `RangeError`、文案为 `Maximum call stack size exceeded`。hook 执行路径的 `object_stringify_with_bounded_stack` 现调用同一个 `exec::stringify_json_value`，其深度门限也改为 `MAX_STRINGIFY_DEPTH`，不再借用 `js_value::MAX_ARRAY_DEPTH`（2000，回答的是另一个谓词）。`js_value` 的其他调用方未动。本次只改该常量、执行路径门限与边界断言，空重复正则预算未动。

## 范围

- 已对齐：≤6500 的嵌套容器深度，条件三种入口与执行四家入口实测 TS 均成功，Rust 也接受。hook 执行路径不再在 2001 层提前失败。
- 剩余差异：6501 到 TS 首败深度。Rust 从 6501 起固定拒绝；按本机本次实测，条件入口二分最大成功深度最低为 6581，执行四家入口为 6885。即 **6501–6580**（条件入口）与 **6501–6885**（执行入口）未观测到 TS 失败而 Rust 拒绝（保守提前失败）；条件入口的 **6581–6616** 是实测最大成功深度带，同进程对边界 +1 层复测又会成功，TS 首败在此带附近抖动，Rust 在该带内一律拒绝；执行入口在 6885 / 6886 处稳定分界。上述入口在 7000 层均失败，精确首败仍随调用栈、容器形状与 JIT 状态变化。
- 不声称「6501 是 V8 首败」，也不声称所有表达式存在统一 V8 阈值；TS 精确首败随调用栈、容器形状与 JIT 状态变化。该抖动带是残余已知差异，不因本次把 4000 改为 6500 而消失。
- 动态空重复正则的 2M 工作预算及「超限 matcher false」行为不属于本次更正，仍按原条目执行。

- 正向实跑：`_tmp/20261026-issue-335-345/final-tests.log`，`depth_rc=0`，该用例 `ok`。
