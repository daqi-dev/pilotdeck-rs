## 类别

有意改进（既有 Rust 行为补登记）：在成功交付终态且所有 recorder 写入退出后释放活动槽，不再等待消费者额外拉取 EOF。

## 基线依据

固定 cc7c4e6 `src/agent/scope/AgentHandle.ts:72-85` 的 async generator 在 finally 释放 activeRuns。真实探针 `src/pilotdeck-gateway/tests/fixtures/live-recording/generate.mts`，金样 complete-cancel / complete-resubmit 的 `afterWriteActive=1`；只有 return 后 `after.active=0`。原始 Node 输出 `_tmp/20261026-issue-741f/node-final.log`。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/turn/live.rs` 在 terminal settle 后释放 Recording 与 active；保留 EOF 流对象也不阻止下一次 admission。基线 fcc1624f6 已在 finish 后 `active.take()`；本包保留此边界，仅延后至真实 complete I/O 退出。start/accept pending 及任何 blocking write 未返回时绝不提前释放。

## 范围

仅终态交付后、消费者尚未再 next/Drop 的窗口。JS Promise 取消与 Rust 借用 future 取消、JS return 排队与 Rust Drop 析构不是同一 API；12 格对齐的是 I/O 退出前的 slot/lease 保留不变量，不作整个 factory API 等价声明。

## 机器判据

`live_stream_tests.rs::live_recording_complete_cancel` / `live_recording_complete_resubmit`：取消后恢复同一 transition、恰一次 durable write、终态交付即 slot 空、next EOF、以新 turnId 实际启动下一轮。负控 `live-recording/negative.py` 的 `terminal-releases-runner` 必须在 EOF 前真实槽断言失败；不是编译失败。TS 金样由 ignored `live_recording_regenerates_identically` 守护。
