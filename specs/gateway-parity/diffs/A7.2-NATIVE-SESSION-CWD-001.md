## 类别

有意改进（待复核的隔离策略差异）。保留 native isolated profile 的单项目限制；不把会话 override 的保存与项目注册 marker 的路径解析混为一谈。

## TS 依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，`src/cli/ProjectRuntimeRegistry.ts:525` 的 `setSessionCwd` 调用 `sessionOverrides.merge(sessionKey, { cwd })`，原样保存相对字符串 `.`。

Node v22.22.0 真实实测入口：`src/pilotdeck-gateway/tests/fixtures/native-metadata-cwd/generate.mts`；入库原件 `oracle.json` 的 `sessionCwd` 为 `"."`。调用真实 ProjectRuntimeRegistry 与 SessionConfigOverrides，不重写 TS 算法；原始运行输出 `_tmp/20261026-issue-1154/ts-delivery-raw.log`。

## Rust 行为

`src/pilotdeck-gateway/src/native_process/services.rs` 的 `Cwd::set` 只允许相对配置项目解析后仍指向该项目的路径；`.` 返回成功但不创建 session cwd override，换到其他项目返回 `CAPABILITY_UNAVAILABLE`。本单保留这一既有策略。

## 范围

仅原生进程 isolated profile 的 SubmitCwdService；不改变通用 ProjectRuntimeRegistry、executionWorkspace、tools cwd 或会话重载协议。Metadata 的进程 cwd 修复不属于此差异。不据此认定 A7.2 或完整 session cwd 能力完成；完整 override/executionWorkspace 语义须另行设计。

## 机器判据

`native_process::tests::metadata_cwd::matrix_matches_ts` 校验 TS 原件 `sessionCwd`；其八个有界子进程调用真实 native Cwd 服务，检查 `.` 可接受、其他项目仍拒绝。

`native_process::tests::metadata_cwd::regenerates_identically`（ignored）重跑真实 TS 并逐字比较；`tests/fixtures/native-metadata-cwd/negative_controls.py` 的 `raw-session-override` 破坏金样的保存值后必须失败。这项是金样完整性负控；另由 `cwd-refuses-same-project` / `cwd-allows-project-switch` 直接变异产品 Cwd::set，分别绑定上述成功/拒绝断言。`negative_regeneration.py` 将 oracle-node-version 变异绑定实际 ignored 重生成守卫。源文件未提交时遵守 HEAD 守卫，逐变异编译、判杀及恢复由协调者提交后执行。
