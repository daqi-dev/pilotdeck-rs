## 类别

有意范围限定（stub 契约级金样移植，非全等价）。#1344 把 slack channel（`SlackChannel.ts`
+ `SlackSessionMapper.ts` + `slack-render.ts`）移植到原生 #1327 通道协议，真值来源从
「基线实测」降级为「基线源码 + 仓内 stub 契约」：oracle 由 `generate.mts` 驱动基线的真实
TS channel 代码对仓内 7 成员 `@slack/bolt` stub（`bolt-stub.mjs`）录制，不是对真实 Slack
SDK 的测量。本条登记该降级与五项范围限定；**不宣称与 TS 全等价**。

## 基线依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85（只读），Node v22.22.0 / ICU 78.2。
oracle（`src/pilotdeck-gateway/tests/fixtures/channel-slack/oracle.json`，35 用例，29 格
状态×事件×时机矩阵 + 6 补充）由 `tests/fixtures/channel-slack/generate.mts` 以
`--import` 挂载仓内 `@slack/bolt` stub 后运行基线 `src/adapters/channel/SlackChannel.ts`
等真实代码录制；两次运行 deep-equal 才算 PASS（`oracle.json` 头部记录 sourceCommit/
sourceSha256/command/node/icu）。真值来源因此是**基线源码 + 仓内 stub 契约**
（`connections.open` → WS 连接 → `auth.test` → message 帧 → `chat.postMessage` →
close(1000)），不是对真实 SDK 行为的实测——本条即该降级的登记。oracle 生成用
tmp+rename 原子写（S0，与已提交 oracle `cmp` 字节一致）。

## Rust 行为

`src/pilotdeck-gateway/src/channel/slack/`（mod.rs / mapper.rs / render.rs）：按 stub 契约
实现 Socket Mode 客户端（原生 `tokio-tungstenite`，wss 生产 URL / ws 回放 seam）、消息
过滤（bot_id / subtype / 自身消息 / 空 channel / 空文本）、mention strip、线程键、
elicit/permission 决定、`/new` 会话切换、mrkdwn 转换、分块与 `chat.postMessage`。
loader 侧（`channel/loader.rs`）：`slack` 移出 `UNMIGRATED_CHANNEL_KEYS`（12→11，基线已含 #1343 的 bluebubbles 移出），
`slack::register` 提供加载表挂载点——**但生产装配（`native_process/assembly.rs`）尚无
该挂载的接线**：启用 `slack` 的配置当前启动成功但不构造任何 slack 通道。移出表之前
Rust 是拒绝启动、TS 基线是构造 channel，当前状态相对两者都是静默跳过；该缺口属
登记的范围限定（非已接受差异），接线前置于 slack 生产装配跟进单。`rejects_unmigrated_slack`
用例随之删除。

## 范围

登记的范围限定（均为「未覆盖」，非「已接受差异」）：

1. **真值来源降级**（上文）：Rust 侧金样只对 stub 契约负责，真实 Slack SDK 的行为
   （限流、重连退避、`connections.open` 失效轮换、WS ping/pong 细节等）不在判分范围。
2. **SDK 内部行为未覆盖**：`@slack/bolt` 内部（收发队列、`App#message` 匹配层、
   retry 策略）由 stub 契约替代，未逐字节复刻。
3. **无「SDK 未装」状态**：TS 侧 `@slack/bolt` 缺失时的降级/报错路径未移植
   （Rust 侧无动态依赖，该状态不存在）。
4. **无生产装配接线**：`slack::register` 仅由测试驱动（
   `channel::tests::loader_mount_builds_slack_channel`）；生产路径构造属后续装配单元。
5. **TS 侧 oracle 敏感度正控不可行**：要证 oracle 对 TS 侧行为敏感需变异基线
   channel 代码再生成，但基线树只读；变异 stub（`bolt-stub.mjs`）只测桩不测被测代码；
   变异 harness 记录层同理。故 TS 侧敏感度不设正控，改以 Rust 侧 11 个 #996 编译期
   开关的判别力正控（`_tmp/20261108-issue-1344-r4/positived-control.out`）+ 生成器
   双跑 deep-equal + 再生成守卫（`channel_slack_fixture_regenerates_identically`，
   `#[ignore]`）为证据。
6. **failed-open 后 `app` 态分歧**：TS 在 `connections.open` 失败（`new BoltApp` 后
   抛错）保留 `this.app`；Rust 侧 `runtime.app` 只在 WS 连上后赋值，failed-open /
   握手失败时为空。无 socket 即无入站帧，35 格均观测不到；生产装配接线后若引入
   重试/重入（`sendReply` 的 `this.app` 门）即可观测。修法二选一（对齐 TS 的
   `app = Some(LiveApp { sink: None })` 入口赋值，或维持现状），随 slack 生产装配
   接线一并定夺（前置于该节点）。

本条取代 `A8.3-CHANNEL-SLACK-001`（-R1）：slack 移出拒绝表后，「启用即拒绝」的差异
描述作废；本条登记的是移植后的范围限定。
