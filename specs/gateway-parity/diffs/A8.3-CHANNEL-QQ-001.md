## Rust 行为

`src/pilotdeck-gateway/src/channel/loader.rs:46-60`（`UNMIGRATED_CHANNEL_KEYS` 13 键表）
与 `loader.rs:104-119`（`reject_unmigrated_channels`，供生产装配单元启动时调用的单一 seam；当前全仓尚无生产调用点）：
`qq` 键 `enabled` **严格等于布尔 `true`** → `Err(ChannelError::Error)`，错误文本（`loader.rs:114`）为
`Error: [adapters] channel "qq" 未迁移到 Rust，需继续使用 TS gateway`。判据在
`loader.rs:77` `STRICT_TRUE_CHANNEL_KEYS` 与 `loader.rs:83-89` `rejects_enabled`：`qq` / `wecom`
走 `matches!(cfg.get("enabled"), Some(JsValue::Bool(true)))`，其余 11 键走 `js_truthy`——与
TS 两条不同的门一一对应（见「TS 依据」）。该键不在
`CHANNEL_LOADER_KEYS`（loader.rs:18-34）里，判断看配置对象自身的键，不能只遍历 loader
表（否则漏判）。seam 不收 mounts、不收 console 回调，拒绝发生在任何 adapter 构造或
console_error 之前。启动装配接线属独立单元，本条登记 seam 行为。

**seam 入参是层间约定，不是用户配置原文**（#1579 r2 评审实测，2026-11-06）：`config/snapshot.rs`
在生成 gateway 快照时已把 `adapters.<key>.enabled` 一律收敛成严格布尔——`qq()`
（`snapshot.rs:1429-1436`）与 `platform()`（`snapshot.rs:1354-1361`）都写
`JsValue::Bool(bool_field(...))`——`platform()` 的键表在 `adapters()` 装配处
（`snapshot.rs:1306-1323`），共 **16** 键：11 个未迁 loader 键 + `wecom` + `wecomCallback` /
`sms` / `apiServer` / `webhook`；`qq` 走 `qq()`，`weixin` / `feishu` 另走 `enabled_only()`
（`:1344-1353`）/ `feishu()`。而 `bool_field`（`snapshot.rs:282-284`）是
`v.as_bool().unwrap_or(fallback)`：配置里 `enabled: 1` / `"true"` / `[]` / `{}` 到不了 seam，
在快照层就变成 `false`。所以本条的「严格 `true` / JS 真值」两条门只在调用方直接把**原始配置
`JsValue`** 递给 `reject_unmigrated_channels` 时才可区分。**TS 侧也在解析层收敛**（#1579 r5 评审实测，2026-11-06；更正 r4 的推断）：
`loadPilotConfig` → `parseAdaptersConfig`（`src/pilot/config/parseGatewayConfig.ts:56-96`）先用
`booleanField`（`:170-172`，`typeof === "boolean" ? v : false`）把 `qq`（`parseQQ`，`:153`）、
`wecom` 与其余 11 键（`PLATFORM_KEYS`，`:71-78`）的 `enabled` 一律收敛成布尔，之后才交给
`createStartupAdapters(snapshot.config)`（`src/cli/pilotdeck.ts:215`）与 `loadEnabledChannels`
（`ChannelAdapterBundle.ts:82`）。端到端探针 `_tmp/20261106-1579-review2/lang-probe/probe-e2e.mjs`
（同一 Node / 同一基线，13 键 × 9 值，输出 `probe-e2e.out`）两列对照：

```
qq       enabled=true -> raw: CONSTRUCTED | e2e: CONSTRUCTED (parsed.enabled=true)
qq       enabled=1    -> raw: skipped     | e2e: skipped (parsed.enabled=false)
telegram enabled=true -> raw: ATTEMPTED   | e2e: ATTEMPTED (parsed.enabled=true)
telegram enabled=1    -> raw: ATTEMPTED   | e2e: skipped (parsed.enabled=false)
```

即 `probe.out` 里 11 键 `enabled: 1` → ATTEMPTED 的分工只在**函数层直接喂原始对象**时成立；
经真实配置解析层，13 键的非布尔 `enabled`（`1` / `-1` / `"true"` / `"1"` / `[]` / `{}` / `""` /
`null`）一律变 `false`，TS 全部跳过、gateway 正常启动。Rust 快照层 `bool_field` 与 TS
`booleanField` 同构，所以**快照入参下两侧对 13 键一致**：`enabled: true` 时 TS 装载/构造而
Rust 拒绝启动（#1302 B 的有意差异——喊出来，不静默丢 channel）；其余取值两侧都跳过。r4 曾据
函数层实测推断「11 键在 TS 下 `enabled: 1` 会装载、快照入参下 Rust 静默跳过」，该推断不成立，
按本节实测更正。装配单元尚未落地（seam 无生产调用点），落地时须在这里写明入参是原始配置还是
快照：原始配置下两条门按原样生效；快照下两条门对真实配置文件不可区分，但 seam 仍保留它们以对齐
TS 函数层，测试与负控直接构造原始 `JsValue`，验的是 seam 契约本身。

## 范围

配置键 `qq` 的 `enabled` 为布尔 `true` 时拒绝 seam 返回 `Err`（装配接线落地后即原生 gateway 拒绝启动）；多键同时启用按
`UNMIGRATED_CHANNEL_KEYS` 声明顺序报第一个命中键（qq 在 wecom 之前、11 个表内键之后）。
`enabled` 为非布尔真值（`1`、`-1`、`"true"`、`"1"`、`[]`、`{}`）时**不拒**——与 TS 的 `!== true` 一致；
`enabled` 为假值或键缺省无影响；已迁子集 6 键（weixin、feishu、apiServer、webhook、
wecomCallback、sms）不受影响；未启用任何 channel 的默认配置行为不变。qq 迁移单 #1332
落地后本条随之失效，届时以更正条目或新条目处理。
