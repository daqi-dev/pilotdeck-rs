## 类别

更正（登记与实测对齐）：#1365（19ca8ad9）及其 fix-r1 更正 R4 两处已漂移的登记，
补齐 R4 留给后续轮的 panic 路径判据，并按实测更正探针能力的表述、把不可判杀的单删
释放写登记为等效变异。

① 探针语义（更正 R4 的因果推断）：R4「Rust 行为」登记「守卫 settle 写入**前**记
`closing-settled`」；19ca8ad9 把记录点移到 `send_replace` 之后，fix-r1 把
`Ticket::drop` 的 `ticket-released` 同型后移。记录点的前后只固定探针与写入的**先后
顺序**，不固定写入**是否发生**——探针在同一分支内无条件记录，删掉写入它照常触发，
事件序列照常保绿。因此「探针见证写入」不成立；写入缺失只能靠成对变异（两写者全删）
或另有可观察差异的绑定判杀。

② 等效变异登记（实测）：`ticket-release-write-removed`（删 `Ticket::drop` 的
`self.done.send_replace(true)`）语义上等价——sender 本来就在 `Drop` 体结束时被丢弃，
`Ticket::enter` 的 `let _ = self.previous.wait_for(|done| *done).await` 对
`Ok(true)` 与通道关闭的 `Err(RecvError)` 一视同仁，排队 close 同样被唤醒并排空；
`ticket-released` 探针又无条件记录，事件序列不变。评审轮独立负控与 fix-r2 全量重跑
均为 `SURVIVED`，故不再计入必须判杀集合，改为在装置内 `EQUIVALENT` 注册表显式登记
（含理由、绑定测试与实测路径），运行时要求该行仍然 `SURVIVED`；若将来被杀死，装置
报 `INVALID` 并提示转回必须判杀集合（判据不随行消失）。

③ 变异项数与 panic 判据：R4「机器判据」登记「增至九项」，但 19ca8ad9 已加第十项
且该项单删实测杀不死（见 ①），fix-r1 重设为成对变异并新增三项，共十三行：十二行
必须 `KILLED`，一行（`ticket-release-write-removed`）登记为等效变异。R4「批准记录」
中登记为跟进的 panic 路径（r3 评审 P2）由 fix-r1 补齐行为测试与可编译变异。

Rust 对外行为不变（判据补强与登记更正；`Ticket::drop` 内 `#[cfg(test)]` 探针的记录
时机后移、以及 `owner.rs` / 测试文档注释的措辞更正都不改变任何产品行为）。

## Rust 行为

一处实现事实、两处更正与一处能力边界。① 探针位置：`ClosingGuard::drop` 先
`self.settle.send_replace(Some(outcome))` 再 `#[cfg(test)]` 记 `closing-settled`；
`Ticket::drop` 先 `self.done.send_replace(true)` 再记 `ticket-released`——位置只决定
事件序列里探针与写入的先后，不构成写入的见证（见「类别」①）。② 守卫 settle 写的
判杀：close 任务成功路径上的守卫写在同一个 poll 内被外层 `Completion::finish` 补发
同值（守卫 drop 与 finish 之间无 await 点，current_thread 测试运行时上无第三方可
观察间隙），故「单删守卫写」实测等价；写入的可观察效果是它**先于票释放的顺序**
（`settle-after-release` 由事件序列判杀），以及两写者全删后 close 必以 `wait_result`
的 lifecycle-stopped 替身拒绝（成对变异判杀）。③ serial ticket 释放写不可见证：
`Ticket::enter` 是 `let _ = self.previous.wait_for(|done| *done).await;`，sender
无论如何都在 `Drop` 结束时被丢弃——写 `true` 得 `Ok(true)`、不写得 `Err(RecvError)`，
两者都被 `let _` 丢弃，排队 close 行为相同；`ticket-released` 探针无条件记录，删写后
事件序列也不变。故该行是实测等价变异，按「类别」② 登记，不宣称为已覆盖的判据。
④ panic/abort 路径（fix-r1 补判据，行为未变）：close 任务 panic 时无 outcome 暂存，
守卫只释放 ticket，外层 `Completion::drop` 在释放之后以 dropped error
（"Session close task was dropped or panicked before completion."）结算条目；abort 与
panic 共用该 `Completion::drop` 机制，且 owner 公共 API 不暴露 close 任务句柄、无法
从外部触发 abort（读码推断，未实测）。
