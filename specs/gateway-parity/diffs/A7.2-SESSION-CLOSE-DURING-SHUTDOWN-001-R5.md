## Rust 行为

两处登记更正。① settle 写入语义（19ca8ad9 + fix-r1）：`ClosingGuard::drop` 先
`self.settle.send_replace(Some(outcome))` 再 `#[cfg(test)]` 记 `closing-settled`；
`Ticket::drop` 先 `self.done.send_replace(true)` 再记 `ticket-released`——两个探针都
绑定在写入之后，删除对应写入时探针不再单独保绿。close 任务的 settle 写在成功
路径上被外层 `Completion::finish` 在同一 poll 内补发同值（守卫 drop 与 finish
之间无 await 点，current_thread 测试运行时上无第三方可观察间隙），故「单删守卫
写入」是实测等价变异；守卫写的可观测效果是其**先于票释放的顺序**，由
`settle-after-release` 的事件序列断言判杀。② panic/abort 路径（fix-r1 补判据，
行为未变）：close 任务 panic 时无 outcome 暂存，守卫只释放 ticket，外层
`Completion::drop` 在释放之后以 dropped error
（"Session close task was dropped or panicked before completion."）结算条目；
abort 与 panic 共用该 `Completion::drop` 机制，且 owner 公共 API 不暴露 close 任务
句柄、无法从外部触发 abort（读码推断，未实测）。
