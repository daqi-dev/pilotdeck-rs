## 类别

有意改进（范围暂缓，非缺陷）。2026-11-05 人定「只做核心 agent 功能，always-on 等增值模块暂缓，不阻塞核心路径」（人令原文与转述见 #1475；`state/decisions-20261105-1313-rescope.md` 记录同一句）；决策卡选项 A 采纳：always-on 三方法不迁移，Rust 侧如实拒绝而不静默、不回 TS 兜底。

## 基线依据

TS 基线 cc7c4e6（`resources/PilotDeck` @ `cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85`）：

- `src/gateway/client/InProcessGateway.ts:2992-3014`（`alwaysOnApply` 2992–2997 / `alwaysOnAbort` 2999–3008 / `alwaysOnRerunPlan` 3010–3014）：`alwaysOnApply` / `alwaysOnAbort` / `alwaysOnRerunPlan` 在缺 `alwaysOnControl` 时对**合法对象参数**不抛错，返回**成功结果对象**，payload 内 `error: { code: "not_configured", message: "Always-On … is not configured on this gateway." }`（`alwaysOnAbort` 另带 `aborted: false` 与回填的 `sessionKey`）。边界：`alwaysOnAbort` 会读 `input.sessionKey`，参数为 `null` / 缺省时在该行抛 `TypeError`，由 WS 层转成 `ok:false` + `gateway_request_failed`（`GatewayWsConnection.ts:246-256`），不走 `not_configured` 分支；`alwaysOnApply` / `alwaysOnRerunPlan` 不读参数，任何参数形状都返回结果对象。
- `src/gateway/server/GatewayWsConnection.ts:558-571`：WS dispatch 在网关没有对应方法时同样 `resolve` 一个 `not_configured` 结果对象（`"Always-On apply not available"` 等），**不是**请求级错误。
- `src/always-on/runtime/createApplyHandler.ts:142-173`：自动化装配的 fallback control 并非空壳——`applyCycle` 会按已有 work cycle / workspace 真正执行（可能成功，也可能返回 `not_configured` / `project_not_found` 等具体错误码），而 `abortRun` / `rerunPlan` 恒返回 `not_configured`（文案为「requires an enabled Always-On runtime.」）。所以「已配置」有两种：注入 fallback（只有 apply 可能真跑）与接入 manager/runtime（三项都可真跑）。
- `src/gateway/client/InProcessGateway.ts:2123-2126`：describe 的 capabilities 只在 `options.alwaysOnControl` 存在时才列出这三个方法。
- `src/cli/createLocalGateway.ts:552,1565`：本地网关只把 `alwaysOnControl` 当可选注入（经 `setAlwaysOnControl` 更新），自身不构造 always-on 运行时；`src/cli/ProjectAutomationBundle.ts:364` 的自动化装配则会注入 manager 或 fallback control，因此 TS 运行时可能真的**广告并服务**这三个方法。
- 同一事实在 `specs/gateway-coverage/coverage-manifest.json` 的 `always_on_apply/abort/rerun_plan` 条目有源码锚点登记：`branches.unconfigured[0].summary` 写明「缺 alwaysOnControl 时返回携带 error.code=not_configured 的结果对象，WS 仍为 ok:true」。这些条目是**读码登记**（`scenario_ids.driver` 为 `NONE`，未跑场景驱动），本条同样按读码结论登记，不声称有真实 TS 运行金样。

## Rust 行为

`src/pilotdeck-gateway/src/native_process/methods/always_on.rs:13-46`：三个 wire 方法名照常注册进 A7 method 注册表（`METHODS`），但处理器 `Requests::always_on_request` 在任何参数校验之前直接返回 `RequestError { code: "CAPABILITY_UNAVAILABLE" }`，message 沿用 TS 的 `Always-On <apply|abort|rerun> is not configured on this gateway.`。没有成功的返回路径，也没有转发给 TS 的兜底。

`src/pilotdeck-gateway/src/native_process/requests.rs:154-220`：describe 的 capabilities 固定表**不含**这三个方法，因此 Rust 不会声称可用；宿主能力子集守卫 `assert_ts_capability_subset` 只约束「Rust ⊆ TS」，挡不住多报，故由组件测试单独钉住「不得广告」。

## 范围

只影响 always-on 三个 WS 方法（`always_on_apply` / `always_on_abort` / `always_on_rerun_plan`）及其 describe 广告位。不影响 A7 其余 47 项、不影响 HTTP 同域入口（另见 `A7.8-HTTP-USER-DIALOG-STORE-001`）、不影响 cron / SOP 家族。Rust 没有「已配置 always-on」这一状态，三个方法对**任何参数形状**都恒定返回 `CAPABILITY_UNAVAILABLE`；TS 侧的行为随「未注入控制 / 注入 fallback / 接入运行时」三态与参数形状变化，故差异逐场景列出。

| 场景 | TS 表现 | Rust 表现 | 用户感知 |
|---|---|---|---|
| describe，本地网关未注入 always-on 控制 | capabilities 不含这三项（`InProcessGateway.ts:2123-2126`） | capabilities 不含这三项（`requests.rs:154-220`） | 一致：客户端看不到这三个入口 |
| describe，TS 自动化装配已注入 control（fallback 或运行时） | capabilities 含这三项 | 仍不含 | 使用自动化装配的客户端在 Rust 下看不到 always-on 入口（能力发现层少三项，属暂缓的一部分） |
| 调用三方法，本地网关无控制，参数是合法对象 | 成功响应（`ok:true`），payload `error.code="not_configured"`，message 为「… is not configured on this gateway.」 | 请求级失败（`ok:false`），`CAPABILITY_UNAVAILABLE`，同一句 message | 同为「不能用」，但响应封套不同：TS 在成功封套里给 payload 错误码，Rust 用请求级错误码。依赖 `error.code=="not_configured"` 判断的分支在 Rust 下拿不到该码；具体 UI 呈现（行内提示 / 弹层）未实测，本条不作断言 |
| 调用 `always_on_abort`，无控制，参数为 `null` / 缺省 | 读 `input.sessionKey` 抛 `TypeError` → `ok:false` + `gateway_request_failed` | 仍 `CAPABILITY_UNAVAILABLE` | 两边都失败但错误码与文案不同；按 `gateway_request_failed` 分支处理的客户端在 Rust 下拿不到该码 |
| 调用三方法，TS 自动化装配注入 fallback control | describe 已广告；`apply` 按已有 work cycle / workspace 真跑（成功或 `project_not_found` 等具体错误码）；`abort` / `rerun` 恒返回 `not_configured`（「requires an enabled Always-On runtime.」） | 三项一律拒绝 | fallback 场景下 Rust 比 TS 少了 apply 的真实执行能力，abort/rerun 同为不可用但错误码与文案不同 |
| 调用三方法，TS 已接入 AlwaysOnManager / runtime | 三项真正执行并返回结果 | 仍拒绝 | 功能不可用（暂缓本体的用户可感知代价） |
