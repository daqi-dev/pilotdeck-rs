## 类别

更正（003 的「Rust 行为」段已过时）。003 的类别结论**不变**：`stop` 不等待
在途回合（TS 同形，#1353 收口 drain 契约）。过时的是 003 对 Rust 侧 stop 的
描述：它写 stop 在 `poll_abort.send(true)` 之后「随即返回 `Ok(())`」；#2285 ③
落地后，stop 还会取出 interval driver 任务的 `JoinHandle`，先 `abort()` 再以
`DRIVER_STOP`（20 s）有界 reaping，并新增两条 `error` 日志路径。本件按
`diffs/README.md` 更正规则新增，003 原文不动、不回写。

## 基线依据

003 的 TS 依据继续有效（cc7c4e6
`src/adapters/channel/bluebubbles/BlueBubblesChannel.ts:79-88`：stop 的全部
动作是 `logger.info` → `running = false` → `pollAbort.abort()` →
`clearInterval`；`:74` 以 `void` 丢弃轮询返回值，TS 无句柄可等待）。补充：
Rust 侧的有界 reaping 是**超出 TS 的收口**而非 TS 行为——TS `clearInterval`
同步移除定时器、无可观察的等待；本件登记的依据是 #2285 fix-r1 评审
sibling #1（`_tmp/20261026-issue-2285/fix-r1/review.md`）对 003 与
`mod.rs:876-890` 现实现相反的指出。

## Rust 行为

`src/pilotdeck-gateway/src/channel/bluebubbles/mod.rs:862-895`
（`BlueBubblesHandle::stop`）：`log("info", …)` → `running.store(false)` →
`poll_abort.send(true)` → 取 `driver` 句柄并 `driver.abort()`，随后
`tokio::time::timeout(DRIVER_STOP, driver).await`（`DRIVER_STOP = 20 s`，
`mod.rs:56-59`）：reaping 得 `JoinError` 且 `is_panic()` → `error` 日志
`bluebubbles: poll driver task failed: …`；20 s 内未退出 → `error` 日志
`bluebubbles: poll driver task did not exit after stop`；正常退出无日志。
三条路径之后返回 `Ok(())`——在途回合仍不被等待（003 类别不变），其回复仍
被 `send_reply` 的 `running` 闸门拦下（`mod.rs:707-710`，003 判据继续
有效）。

## 范围

仅更正 003 的「Rust 行为」描述并登记两条新日志路径；003 的类别（stop 不
drain）、TS 依据、金样判据不变。`DRIVER_STOP`（20 s）与测试外层
`DEADLINE` 同值，「did not exit after stop」分支在金样中先被外层超时截断、
不可观测（评审 boundary #4，P3，不在本件收口）。panic 若发生在 per-tick
轮询任务（非 driver 任务本身），仍无日志——见 007。

## 机器判据

- 003 的判据全部继续有效：金样 `stop-drains-inflight-turn`、组件钉
  `send_reply_after_stop_is_gated_by_running`、负控
  `send-reply-running-gate-removed`。
- 新增的 abort/reaping 与两条日志分支**无专属判据**：删掉 abort/reap 块后
  watch 信号仍使 driver 退出、轮询照样停止，行为测试不转红；panic 日志分支
  的触发需要 driver 任务本身 panic，测试装置无法在不改产品码的前提下确定
  性构造。登记为已知覆盖缺口（#2285 fix-r1 评审 boundary #3，P2 跟进候选）；
  行为面（stop 返回 `Ok`、停后服务端计数停增）由
  `poll_task_panic_does_not_stop_the_driver` 的末段给出**弱判据**——该窗口
  不能探测幸存 driver：`running === false` 使其后任何 `poll_messages` 在发
  GET 前返回，计数无论 driver 存活与否都不再增长（#2285 r2 评审
  concurrency#2 收口，镜像措辞与 tests.rs / fixture README 同步）。
