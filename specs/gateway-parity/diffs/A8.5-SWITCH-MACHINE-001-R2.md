登记的两处缺口——R1 更正已指出但按授权轮次停在前置之外：死亡行军的

future 被 drop 的路径连标记都不留）。基线依据、差异格、豁免口径不变
（S4/finish 的 once-only 与 owner 界本就是 #1353 已登记差异的 Rust 侧
实现细节，本轮是补齐其失败语义，不新增差异格）。

## Rust 行为

在原条目行为之上，两处变更（#2363 协调者授权，2026-11-09）：

- `src/pilotdeck-gateway/src/native_process/switch_wiring.rs`
  `finish_after_halt`：`phased.finish()` 由裸 await 改为共享 owner 尺度
  deadline（`tokio::time::timeout_at`，`drain_budget + BACKSTOP_SLACK_MS`，
  与 close join 同一个界——S4 半段不再重新起一个全尺度界：挂起 close 后
  接挂起 finish 的最坏情况也只等一个 owner 尺度即退出；deadline 不进
  时钟的溢出/换算带按 #1949 弃权口径退回无界 await）。超时上报
  "owner finish: exceeded the halt owner bound" 计入 walk 的失败聚合、
  walk 照常返回——不再阻断进程退出（此前该半段无界，host teardown 挂起
  则进程不退出）。
- `src/pilotdeck-gateway/src/native_ws.rs` `PhasedInner::finish`：
  `host.shutdown(...)` 的 `?` 早退改为折进 `finished` 记录（shutdown 错误
  优先级最高，保持第一次调用者的上报文案不变；变化在第二次调用不再
  整段重跑）；新增 `finish_started` 进行中标记，拿锁后看到标记而无
  verdict 的复访得到 Err("native WS owner finish was interrupted") 并
  记录（第一次被 drop 的路径此前会重发 close 帧/abort/host shutdown，
  最坏多耗一个 drain_budget）。锁串行化保证 started&&!finished 只可能
  是「前一次被 drop」，无「运行中被误判中断」格。
