## 类别

不可避免（本包限定范围下保留的既有运行时差异）：Node `process.cwd()` 有进程级缓存；Rust `std::env::current_dir()` 每次读取系统 cwd。本条不认可该限制为最终行为，不增加判分豁免。

## 基线依据

cc7c4e6 的 `src/session/filesystem/FileHistoryStore.ts:134` / `:238` 分别在 `trackEdit` / `markEditCommitted` 中执行 `path.resolve(filePath)`，发生在任何状态变更或无 snapshot 早退之前。

Node v22.22.0 原入口 12 格实测：冷缓存相对路径、cwd 已删除时报 `ENOENT: no such file or directory, uv_cwd`，状态与 transcript 不变；绝对路径即使 cwd 已删除也成功，cwdReads=0。先成功读取 cwd、随后删除该空目录，再传 `../files/./nested/../tracked.txt` 时，Node 使用缓存的 cwd，track / mark 均成功处理同一临时根内仍存活的文件。

金样与生成器：`src/pilotdeck-gateway/tests/fixtures/file-history-cwd/{oracle.json,generate.mts}`（含固定基线与源码 SHA256）。原始输出：wt-879 的 `_tmp/20261026-issue-879/node-probe.log`；协调者交接时保全此证据。

## Rust 行为

`src/pilotdeck-gateway/src/storage/file_history.rs::resolve_node_path` 在相对路径上实时查询 cwd，失败以既有 `FileHistoryError::Fs` 返回 Node/libuv 消息；`track_edit`、`mark_edit_committed` 在改状态或早退之前传播错误。绝对路径仍直接词法归一化。

暖缓存场景中 Rust 仍无法恢复旧 cwd；本包将原来错误的 `/` 回退改为显式错误，并保持操作前状态。缓存差异在本包之前已存在，**暖缓存失败输出并非保持不变**。本包不新增跨调用缓存、不修改其他路径入口。现有 FileHistoryError 接口只承载消息，不新增 TS Error 的 name/code/syscall 字段。

## 范围

仅 file_history 两个直接入口的相对路径、已有 Node cwd 缓存且真实 cwd 被删除的组合。健康 cwd、冷缓存错误和绝对路径 10 格按真实 TS 结果验收。stats、metadata:342、projector 两处属于 #879 后续独立包；本条不能证明 A7 接线已完成。

## 机器判据

`storage::file_history::cwd_tests::{track_relative_warmed_deleted,mark_relative_warmed_deleted}` 明确核对 TS 成功金样，同时要求 Rust 返回对应冷缓存金样的 uv_cwd 消息及操作前状态。其余十格逐项比较 outcome/message、备份与状态。

fixture 的 `negative_controls.py` 绑定点名测试与专属失败消息；`cwd-root-fallback` 包含暖缓存格。运行要求提交后默认 HEAD 守卫和调用方传入 CARGO_TARGET_DIR；正控、运行时判杀、恢复通过分别留原始日志。ignored `file_history_cwd_regenerates_identically` 要求重新执行 Node 生成器后 oracle 字节一致。
