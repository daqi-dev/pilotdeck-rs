## 类别

接口语义差异（待批）：#1327 的 `ChannelHandle::stop(&str)` 必须携带理由
字符串，TS 的 `stop(reason?: string)` 可无参调用；TS 缺省时以
`reason ?? "no reason"` 记日志，Rust 侧「未给理由」这一输入形态不可
表达，由调用方（oracle 回放 harness）在 TS 无理由时传 `"no reason"`
复刻同一日志字节。

## TS 依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85。
`SmsChannel.ts:110-111`：`stop: async (reason?: string) => {
this.logger?.info?.(\`sms: stopping (${reason ?? "no reason"})\`) ... }`。
oracle 金样各用例的 `sms: stopping (no reason)` 行即 TS 无参 stop 的
实测输出（Node v22.22.0 / ICU 78.2 生成）。

## Rust 行为

`src/pilotdeck-gateway/src/channel/sms/mod.rs` `SmsHandle::stop(&self,
reason: &str)` 按收到的理由原样记录 `sms: stopping ({reason})`；
`stop` 后监听关闭、重复 stop 仅再打日志的行为与 TS 一致。缺省语义不可
表达：协议上没有「未给理由」，调用方需自行传 `"no reason"`（回放
harness 已如此，注释在 `stop()` 内）。

## 范围

仅 stop 入参形态；日志字节、监听关闭时序、no-op handle 的无 stopping
日志行为不受影响。`stop-during-turn` 的排空语义（turn 挂起时 stop 仍
完成）不在本条。

## 机器判据

`src/pilotdeck-gateway/src/channel/sms/tests.rs`：oracle 用例
`stop-during-turn` 钉 `sms: stopping (drain)` / `(no reason)` /
`(cleanup)` 三行日志；负控 `sms-stop-log-reason` 变异理由文本即被该
用例击落。
