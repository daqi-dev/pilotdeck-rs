## 类别

bug 修复（安全，向安全偏离）。`PILOTDECK_DUMP_REQUEST=1` 的 dump 正文含完整用户对话，TS 用毫秒时间戳做文件名并经 `writeFileSync`（默认 flag `w`，O_WRONLY|O_CREAT|O_TRUNC）写入共享临时目录：同毫秒并发请求互相截断覆盖 dump（数据丢失），毫秒可预测的文件名 + 跟随符号链接的截断打开允许共享目录上的其他用户用预置 symlink 覆盖任意可写目标（数据破坏），默认 umask（实测 0644）让 dump 全局可读（内容泄露）。三条均属 CLAUDE.md「什么算 bug」第 ③ 条安全问题，按「默认修」授权修复；与 TS 的一致性让位于安全，故登记本条。不能因 TS 同样有此写法而忽略（任务 #621 明确）。

## TS 依据

cc7c4e6 的 `src/model/streaming/streamModel.ts`：

- `:196-203`（OpenAI 路径）与 `:395-401`（Google 路径）：`if (process.env.PILOTDECK_DUMP_REQUEST === "1")` 后 `path.join(os.tmpdir(), \`pilotdeck_request_${Date.now()}.json\`)` + `fs.writeFileSync(dumpPath, JSON.stringify(body, null, 2))`。
- `os.tmpdir()` 在 macOS 返回用户私有 `$TMPDIR`，在 Linux 常为共享 `/tmp`；文件名只有毫秒时间戳，`writeFileSync` 跟随既有符号链接、截断既有文件、按 umask 建权限。
- Rust 侧最小实测（darwin，探针与原始输出见本树 `_tmp/20261025-issue-621-provider-tail/scratch/probe-output.txt`）：`File::create` 对 symlink 目标截断改写（受害者数据丢失）；同名二次 `File::create` 截断前次内容；默认 mode 0644；对照 `create_new`（O_CREAT|O_EXCL）对 symlink 与既有文件均报 `AlreadyExists` 且不触碰目标，`mode(0o600)` 得 600。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/model/http.rs` 的 `dump_request_to_file` / `write_dump_exclusively`：

- 目录改为 `std::env::temp_dir()`（对齐 TS `os.tmpdir()`，修正此前硬编码 `/tmp` 与 TS 落点不一致的偏离）。
- 文件名 `pilotdeck_request_<毫秒>_<pid>_<进程内单调序号>.json`：进程内单调序号保证并发唯一，跨进程 pid 不同；TS 只有毫秒时间戳。
- 创建用 `OpenOptions::write(true).create_new(true)`（O_CREAT|O_EXCL，unix 下 `mode(0o600)`）：拒绝跟随预置 symlink、拒绝截断既有文件；`AlreadyExists` 换下一候选名（最多 8 个）而不是截断。
- 触发条件、目录、日志行（`[model-debug] Request dumped to <path> (model=<model>)`）与 TS 一致；Google 路径本轮才接上（TS `:395-401`），model 取自 canonical 请求而非 URL 之外的信息。
- 残余已知项（不在本条修复）：dump 在 async 路径上同步 `std::fs` 写 + `println!`，阻塞 tokio worker（旧评审 P3，debug 门控下影响有限，未修）；写中途失败可能留下部分文件（TS `writeFileSync` 同样可能）。

## 范围

仅 `PILOTDECK_DUMP_REQUEST=1` 的调试 dump（OpenAI 与 Google 两条 provider 发送路径）；正常请求路径、请求正文内容、错误形状均不受影响。偏离点：① 文件名多出 pid 与序号（TS 只有毫秒时间戳）；② 独占创建拒绝而非跟随/截断（TS `writeFileSync` 跟随并截断）；③ 权限 0600（TS 按 umask，共享 `/tmp` 下实测 0644）。文件内容（pretty-print JSON）与触发语义（严格 `=== "1"`）与 TS 一致。
