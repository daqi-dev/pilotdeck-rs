## Rust 行为

`src/pilotdeck-gateway/src/native_process/methods/steer.rs`（#1444 起）：
`handle_steer_turn` 在 admission 两分支之后以 `steer_attachments` 归一
入参——nullish 缺省、数组、以及一切 falsy 非空值（`""`/`0`/`NaN`/`false`）
与字符串（单字符格全被 composer 跳过）归为空集，对象仅当其 `length` 为
数值 0 时折空（fix-r1，对齐前门 `attachments.length === 0` 对原值的取值，
b1/b2；`{length:2}`/`{length:"0"}`/`{}` 不折），真值不可迭代值
（`1`/`true`/`{}` 等）报 `gateway_request_failed` + `"attachments is not
iterable"`；空集走内联原样构造（text 块嵌入原始 wire `message`，含 a11/
a16/a17 原值格，与 A7.2-STEER-INPUT-001 的 message 无残差结论保持一致），
非空集调用 `submit_services.prepare_attachment_turn`（#1321 提交通机制：
profile 校验 → 字符串 message 守卫 → 阻塞线程 compose），`type:"text"`
的合成结果按 TS `:1873-1875` 包 text 块、其余原样取 `content`；
`allowedReadFiles` 从合成返回值派生（缺键 = 空表）。`uploadedAttachments`
仍不读（两侧一致忽略）。

残差 1-5（产品分歧，均只在**非空 attachments** 格触发；空集格不受影
响）；残差 6 的触发形为非数组拼写（submit 前门，主消息车道）；残差 7
为测试守卫夹具局限（非 TS/Rust 产品行为分歧，与 attachments 输入域无
关），另列于清单末项：

1. **非字符串 message + 非空 attachments**（fix-r8 按分支分述，评审
   MM boundary#1 + DS boundary#2/#4，probe6 d3-d6 补格）：Rust 走
   `prepare_attachment_turn` 的字符串 message 守卫，报
   `gateway_submit_failed` + `"message must be a string."`；TS 无守卫，
   按 compose 是否产出附件块分两支：
   - **blocks 路径**（有可合成元素或 path note，读
     `input.message.length`，composer `:75`）：`null`/缺席在取
     `.length` 处即抛 TypeError、不得 accepted——与 Rust 同败不同
     形，登记为错误形状子残差（null 形 fix-r7 probe6 d1 实测；缺席
     格同抛点，未单独实测）；取得到 `.length` 且 `> 0` 的真值
     `.length` 形对象（`{length:2}`，d4）门槛放行、message 块以
     原值（对象）保留；取 `.length` 不抛而 `> 0` 不成立的值
     （数值/布尔——`.length` 取值为 undefined，probe a12 与 fix-r6
     probe5 c5：content 仅附件块；零长度 `[]`，d6——空数组属非字符串，
     归本残差）message 块不产、不报错。零长度串 `""` 是**字符串**
     （d5），不属本残差——两侧一致：TS blocks 路径零长度不产 message
     块，Rust 守卫放行（只拒非字符串）、composer 空串不产 message 块，
     两侧 content 均仅附件块（fix-r9 更正，评审 DS boundary#2 + MM
     boundary#1 取高；Rust 侧钉格见
     `steer_turn_message_cells_keep_the_raw_block_and_the_submit_guard`
     的 `""` 格）。
   - **plain 路径**（元素全被跳过、无 path note，不读 `.length`、
     原值嵌入，composer `:67`）：非字符串值原值嵌入 text 块，实测
     数值（元素 `[{}]`/`[1]`/`["x"]` 三格，fix-r6 probe5 c1-c3）、
     `null`（fix-r7 probe6 d2，text:null）、缺席（fix-r8 probe6 d3，
     text 键缺失——undefined 原值嵌入后 JSON 序列化丢键）。
   `{path:5}` 元素的 TypeError 与 message 类型无关（probe3 与 probe5
   c4 同抛），属残差 4 的 TS 抛格，不在此列。空集格（a11/a16/a17）
   两侧一致原值嵌入，无残差。
2. **原生隔离 profile 不合法 + 非空 attachments**：Rust 因复用 submit 的
   `validate_profile` 前门报 `CAPABILITY_UNAVAILABLE`（如 home 配置了
   plugins/skills/MCP）；TS steerTurn 无 profile 概念，照常合成。无附件
   格 Rust 走内联路径、不查 profile，与 TS 一致。
3. **`[null]` 元素（真数组、元素为 null）**（fix-r1，probe e1）：TS 在
   composer 首趟 `collectRegisteredAttachmentReadFiles` 读 `attachment.path`
   即抛 `TypeError: Cannot read properties of null (reading 'path')`；Rust
   的字段访问对 null 元素返回 None、静默跳过，accepted 且投递 plain
   turn。同族 `[1]`/`["x"]`/`[{}]` 三格两侧同形跳过（probe e2-e4，无
   残差，钉格 `steer_turn_skips_non_object_attachment_elements`）。

前两残差同根：复用 submit 同一机制的类型/能力边界。若要消除，需给 steer
单独开不带守卫的 compose 入口（拆 `prepare_attachment_turn` 的包装层），
收益仅 a12 单格，随本条登记待裁。

4. **`{path:5}`（truthy 非字符串 path，fix-r3，probe3）**：TS 在 compose
   的 pdf else-if 读 `attachment.path.toLowerCase()` 即抛 TypeError；Rust
   的 path 匹配只认 `JsValue::String`，非字符串 path 折
   `(String::new(), None)` 静默跳过，accepted 且投递 plain turn。钉格
   `steer_turn_skips_mistyped_attachment_fields_and_keeps_the_plain_turn`
   （methods/tests.rs，三格共测）。
5. **`{type:"text",content:5}`（truthy 非字符串 content，fix-r3，
   probe3）**：TS 原值嵌入 `{type:"text",text:5}` 块；Rust 的 content
   取值 `text_field` 只产 JsString，数值 content 落 None、块不产，
   accepted 且投递 plain turn（同上钉格）。`{type:5}` 格两侧同形
   （Rust 非字符串 type 取缺省 ""，分支全不中），无残差，同钉格。
6. **submit 前门非数组折空 vs TS 展开抛错（fix-r3，probe4；`runtime/
   turn/submit_host.rs` prepare 的 `attachments` 折空臂）**：Rust 一切非
   数组折空表、turn 照常合成；TS 前门 `InProcessGateway.ts:1480` 的展开
   只折 nullish，不可迭代拼写抛 TypeError、被 pump catch（:1708）折成
   `gateway_submit_failed` 错误事件。nullish/字符串格两侧同形无残差。
   钉格 `submit_front_door_folds_non_array_attachments_to_an_empty_table`
   （submit_host_tests.rs，七格：1/0/false/""/"ab"/{length:0}/null）。

残差 6 **选登记不对齐**的依据：（1）TS 侧非设计边界而是展开引擎伪
影——错误落 `gateway_submit_failed` 内部失败桶（userHint「check the
gateway logs」、recoverable:false），复刻 V8 报错文本会把事故固化成设
计；（2）submit 前门是主消息车道，对齐把原生端今日「折空继续」的输入域
改成硬失败，超出 #1444（steer 车道）范围，账本对这类分歧的既有处理
（残差 1/2/3）正是登记待裁；（3）抛错点不可精确复刻——TS 在租约解析
之后抛（pump 内 session.submit 之前），Rust prepare 的折空臂在租约登记
之前，带租约格（uploadedAttachments 非空 + attachments 非数组）对齐将
泄漏租约释放，需先重排 prepare 生命周期。

7. **〔测试守卫夹具局限，非产品分歧〕FifoUnstrand 守卫 unlink 失败
   （非 ENOENT）→ 后到读者永久停泊**
   （fix-r8 登记，fifo_probe_r8 实测，原始输出
   `_tmp/20261115-2800-fixr8/fifo_probe_r8.{out,err}`，评审 DS
   conc-r2#1 + MM sibling#3/conc#1）：守卫 drop 的救援 open 成功而
   `remove_file` 失败（非 ENOENT）时 FIFO 路径残留、无写端，后到的阻塞
   `open(O_RDONLY)` 永久停泊；该格内测试的 runtime teardown 等待
   已启动的阻塞任务、整二进制挂死（只留 trace，不解停泊）。实测
   两格：目录顶掉 FIFO 路径（fix-r6 probe(4) 形态复跑）证 unlink
   失败分支确实走记录（stderr 见 open+unlink 两条失败记录）、路径
   仍在；父目录去写权限保住 FIFO（EACCES）证后到读者停泊（Drop
   记录走非 panic 写，30s 看门狗超时格，无写端 FIFO 永久停泊）。
   **属测试守卫（FifoUnstrand）夹具局限，非 TS/Rust 产品行为分歧**
   ——守卫只为 `steer_turn_profile_gate_does_not_block_the_serial_host_executor`
   的失约会合兜底，产品代码无此路径；`mem::forget(
   rescue)` 不是缓解（泄漏的 O_RDWR 句柄只把停泊从 open 挪到
   read），不试。停泊转红（改守卫结构）不做，登记待裁。

## 范围

仅 `steer_turn` 的 `attachments` 输入域。基础条目的「未实现 + 显式拒绝」
关闭；`uploadedAttachments` 两侧一致忽略不变；非数组拼写按 composer 自身
边界对齐（`""`/`0`/`false`/`NaN`/非空字符串 → 无附件 turn，对象带数值
0 的 `length` → 无附件 turn（fix-r1，b1/b2），`1`/`true`/`{}`/
`{length:2}`/`{length:"0"}` 等 → TypeError）；真数组的非对象元素按
composer 每趟跳过（e2-e4 对齐，e1 `[null]` 为残差 3）；顺序（-R1）
不变；`cancel_steer`、`submit_turn`、message 原值格（A7.2-STEER-INPUT-001）
不涉及；itemId 强转族不涉及（其 #1444 后收敛点状态与再评估车道见
A7.2-STEER-INPUT-001-R1）。fix-r3 追加的 submit 前门差异属残差 6，见
残差清单。
