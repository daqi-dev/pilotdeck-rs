## 类别

合入登记 + 残差登记。#1444 把 `steer_turn` 的非空 `attachments` 完整合入
content（复用 #1321 的 `prepare_attachment_turn` 提交通机制），基础条目
「未实现 + 显式拒绝」就此关闭、更正为已对齐。合入同时带出两个新的
**残差**（复用 submit 同一机制的类型/能力边界，见 §Rust 行为），按探针
实测登记于此；fix-r1 追加对象 `length === 0` 前门格的对齐与元素级残差 3。

## Rust 行为

`src/pilotdeck-gateway/src/native_process/methods/steer.rs`（#1444 起）：
`handle_steer_turn` 在 admission 两分支之后以 `steer_attachments` 归一
入参——nullish 缺省、数组、以及一切 falsy 非空值（`""`/`0`/`NaN`/`false`）
与字符串（单字符格全被 composer 跳过）归为空集，对象仅当其 `length` 为
数值 0 时折空（fix-r1，对齐前门 `attachments.length === 0` 对原值的取值，
b1/b2；`{length:2}`/`{length:"0"}`/`{}` 不折），真值不可迭代值
（`1`/`true`/`{}` 等）报 `gateway_request_failed` + `"attachments is not
iterable"`；空集走内联原样构造（text 块嵌入原始 wire `message`，含 a11/
a16/a17 原值格，与 A7.2-STEER-INPUT-001 的 message 无残差结论保持一致），
非空集调用 `submit_services.prepare_attachment_turn`（#1321 提交通机制：
profile 校验 → 字符串 message 守卫 → 阻塞线程 compose），`type:"text"`
的合成结果按 TS `:1873-1875` 包 text 块、其余原样取 `content`；
`allowedReadFiles` 从合成返回值派生（缺键 = 空表）。`uploadedAttachments`
仍不读（两侧一致忽略）。

残差（均只在**非空 attachments** 格触发；空集格不受影响）：

1. **非字符串 message + 非空 attachments**：Rust 走
   `prepare_attachment_turn` 的字符串 message 守卫，报
   `gateway_submit_failed` + `"message must be a string."`；TS 无守卫、
   compose 的 blocks 路径自行丢弃非字符串 message 块（probe a12，
   accepted 且 content 仅附件块）。空集格（a11/a16/a17）两侧一致原值
   嵌入，无残差。
2. **原生隔离 profile 不合法 + 非空 attachments**：Rust 因复用 submit 的
   `validate_profile` 前门报 `CAPABILITY_UNAVAILABLE`（如 home 配置了
   plugins/skills/MCP）；TS steerTurn 无 profile 概念，照常合成。无附件
   格 Rust 走内联路径、不查 profile，与 TS 一致。
3. **`[null]` 元素（真数组、元素为 null）**（fix-r1，probe e1）：TS 在
   composer 首趟 `collectRegisteredAttachmentReadFiles` 读 `attachment.path`
   即抛 `TypeError: Cannot read properties of null (reading 'path')`；Rust
   的字段访问对 null 元素返回 None、静默跳过，accepted 且投递 plain
   turn。同族 `[1]`/`["x"]`/`[{}]` 三格两侧同形跳过（probe e2-e4，无
   残差，钉格 `steer_turn_skips_non_object_attachment_elements`）。

前两残差同根：复用 submit 同一机制的类型/能力边界。若要消除，需给 steer
单独开不带守卫的 compose 入口（拆 `prepare_attachment_turn` 的包装层），
收益仅 a12 单格，随本条登记待裁。

## 范围

仅 `steer_turn` 的 `attachments` 输入域。基础条目的「未实现 + 显式拒绝」
关闭；`uploadedAttachments` 两侧一致忽略不变；非数组拼写按 composer 自身
边界对齐（`""`/`0`/`false`/`NaN`/非空字符串 → 无附件 turn，对象带数值
0 的 `length` → 无附件 turn（fix-r1，b1/b2），`1`/`true`/`{}`/
`{length:2}`/`{length:"0"}` 等 → TypeError）；真数组的非对象元素按
composer 每趟跳过（e2-e4 对齐，e1 `[null]` 为残差 3）；顺序（-R1）
不变；`cancel_steer`、`submit_turn`、message 原值格（A7.2-STEER-INPUT-001）
不涉及；itemId 强转族不涉及（其 #1444 后收敛点状态与再评估车道见
A7.2-STEER-INPUT-001-R1）。

## 机器判据

`src/pilotdeck-gateway/src/native_process/methods/tests.rs`：

- `steer_turn_merges_attachments_into_content`：无活跃 turn 各附件形输入
  断言 `no_active_turn`（顺序）；活跃 turn 下非空 `attachments` 断言
  accepted + 投递 content 为 message 块 + 附件块（probe a13）、
  `allowedReadFiles` 空表；非空 `uploadedAttachments` 断言 accepted（TS
  忽略语义）。
- `steer_turn_attachments_sit_between_admission_and_resource_gates`：
  无 admission / turn_mismatch + `attachments:1` 断言 `no_active_turn` /
  `turn_mismatch`（probe a14/a15）；admission 匹配但无 steer run / 槽位
  run 不符 + `attachments:1` 断言 `gateway_request_failed` +
  `"attachments is not iterable"`；合法附件 + 无匹配 steer run 断言
  `no_active_turn`（compose 先于资源门）。
- `steer_turn_non_array_attachments_follow_the_composer_boundary`：
  `""`/`0`/`NaN`/`false`/`"ab"`/`null` 六格断言 accepted + 投递 plain
  turn（各用独立 itemId——邮箱 claim 门去重，A7.2-STEER-INPUT-001 差异
  6）；`1`/`true`/`{}` 三格断言 TypeError 文本 + `gateway_request_failed`
  且不入队。
- `steer_turn_object_attachments_follow_the_length_zero_front_door`
  （fix-r1）：`{length:0}`/`{0:{…},length:0}` 两格断言 accepted + 投递
  plain turn（probe b1/b2）；`{length:2}`/`{length:"0"}` 两格断言
  TypeError 文本 + `gateway_request_failed` 且不入队（b3/b4）。
- `steer_turn_skips_non_object_attachment_elements`（fix-r1）：
  `[null]`/`[1]`/`["x"]`/`[{}]` 四格断言 accepted + 投递 plain turn
  （probe e1-e4；e1 即残差 3 的 Rust 侧形状钉格，e2-e4 为对齐格）。
- `steer_turn_message_cells_keep_the_raw_block_and_the_submit_guard`：
  message `5`/`null`/缺席（无附件）三格断言 text 块原值嵌入（probe
  a11/a16/a17）；message `5` + 非空 attachments 断言
  `gateway_submit_failed` + `"message must be a string."`（残差 1，probe
  a12 的 TS 形为 accepted）。
- `steer_turn_registers_leased_attachment_paths`：租约注册附件断言三块
  content（message 块 + `<attachment path>` 内联块 + 会话注记块，注记
  全文钉格）与 `allowedReadFiles == [路径]`（probe a18）。
- `steer_turn_attachments_reuse_the_profile_capability_gate`：home 配置
  plugin 后，无附件断言 accepted（内联路径不查 profile）、非空附件断言
  `CAPABILITY_UNAVAILABLE`（残差 2）。
- `steer_turn_profile_gate_does_not_block_the_serial_host_executor`
  （fix-r1）：home `pilotdeck.yaml` 换成 FIFO 后，非空附件的 steer 在
  config 加载停泊期间探针（FIFO rendezvous 后 10ms sleep）仍能完成——
  profile 门的 FS 扫（MCP 配置加载、四个 plugins/skills `read_dir`、项目
  config 全量加载）经 `assembly.rs` `validate_profile_inner` 的
  `spawn_blocking` 跑在阻塞池（评审 MM concurrency #2）；释放后请求
  accepted 且 content 为 message + 附件块。
- `steer_turn_uploads_never_reach_the_canonical_message`（#1307 既有）：
  `uploadedAttachments` 不进 content、`allowedReadFiles` 空表。
