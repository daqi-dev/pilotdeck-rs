## 类别

更正（差异消除 + 「现状」陈述失效，非差异变化）：#2499（#2026 决策 B）
把 012 登记的四条残差中的 **1 / 2 修除**——sms 车道请求头读期限到期时
现在写 Node 的 51 字节 `408 Request Timeout` + `Connection: close`
原始字节直上 socket，锚点与落点对齐 Node 的首字节锚 / 连接建立锚 +
30 s connections-checker 网格。012「类别」节的核心前提「本单在连接上装了
`.timer(..).header_read_timeout(60 s)`、没有把车道迁到仓内已有 Node 口径
实现」已被 #2499 推翻：车道现在拥有读侧（`HeadersTimeoutGate`），正是
012 自己点名的那条 native 车道对齐方案（`http_proxy.rs` 的
`UpgradeReadGate` / `NODE_HEADERS_TIMEOUT_408` / `grid_anchor`）。四条
残差的现状：

1. **线上字节**（012 残差 1）：**已消除**。到期写 `NODE_408_RESPONSE`
   （`user_dialog/http_store.rs`，与 012 基线依据引的是同一条 Node
   `requestTimeoutResponse` 常量）原始 51 字节，不经 hyper 响应路径
   ——无帧化、无 header 改写、无 `Date`。金样新增两格
   （`headers-timeout-first-byte` 18859 / `headers-timeout-connect-anchor`
   18860，期望均 `{"status":408,"contentType":null,"body":""}`）在基线上
   真录制钉住字节；Rust 重放逐字节断言（不经归一化）。
2. **触发时刻与起算点**（012 残差 2）：**已消除**。锚点规则对齐：有首
   字节锚首字节（任何一次读到字节且当前头未开始即锚定该头自身——
   首头也不例外，实测 120,008 ms 形状由此而来）、无字节锚连接建立
   （90004 形状）；落点 = 网格上首个**严格大于** deadline 的点（恰落
   网格点取后继，整除进一）。残留的毫秒级确定性差（Node tick 抖动
   双峰）改由 **`A8.3-CH-SMS-017` 残差 1** 登记。
3. **空闲 keep-alive**（012 残差 3）：**重读**。修前头期限到期一律
   零字节关；修后**首个**零字节头与 Node 一样得 408，已 served 连接上
   的零字节 follow-up 头才静默关——仍由本车道自己的 60 s 头期限兜底
   （Node `keepAliveTimeout` 5–6 s + 两个 keep-alive 头），登记迁移到
   **`A8.3-CH-SMS-017` 残差 2**。
4. **`stop()` 期间的半截请求头**（012 残差 4）：**重读**。#2499 同时
   把「stop 解除在途连接的头期限」对齐 Node 的 `httpServerPreClose`
   清 checker——drain 中连接不再由头期限退休；012 残差 4 的「Rust 的
   socket 在 stop() 返回后至多再活 60 s」这句的**机制**已失效（退休
   来源从 60 s 头期限变为 014 登记的 60 s drain 上限 abort），结果量级
   与 Node 的「活到客户端离开」之差不变，按 `A8.3-CH-SMS-014` /
   `-R1`（决策 C）读。

012-R1 至 R4 链上与残差 1 / 2 相关的「现状」句（R1 的 hyper 零字节
关、R4 的「残差 1 / 2 / 3 不受影响，维持原判」收尾句）随本条失效；
