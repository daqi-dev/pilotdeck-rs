## 类别

凡目标序与 TS 停机组合根相左之处按矩阵断言表锁 Rust 行为，本条集中登记

被既有连接无限阻塞）同由该已批条目承接。D7/D8（双 owner、新握手无前置）
在本嵌入里没有第二个进程可比对（切换即本进程退出，新握手属下一个 owner
进程），不在此登记；D9（closing 期 webhook 退化 static）行为未改，不属
本条。超时值与谓词、close 帧内容、杀灭口径等取值依据见
`_tmp/20261108-issue-1353-r1/plan.md` 决策卡 DC-1…DC-5（AI 代批，待人复核）。

## Rust 行为

`src/pilotdeck-gateway/src/switch.rs` 的状态机（`SwitchMachine::run`
`src/switch.rs:354`，序 Steady→StopAutomation→StopAccepting→Flush→
StopOwner→Recover，任一步失败进 Halted）驱动生产面
`src/native_process/switch_wiring.rs`，由信号触发
（`src/native_process.rs:94-139`；phased run/面/机器在信号等待**之前**
构造，稳态接纳自启动即服务，信号只触发切换）：

- D1+D2：每个面经 `bounded()`（`src/switch.rs:385`）有界执行，超时与
  拒绝都停切换（Halted）并报该面自己的失败，不进 flush/停 owner；谓词
  `BoundedTimeout`（`src/switch.rs:79`，上限 `TIMEOUT_CAP_MS=300_000`
  `:42`，0/负/NaN/无穷/溢出显式拒绝）；机器层面的 entry/owner backstop
  为内部预算加 `BACKSTOP_SLACK_MS=10_000`（`:47`，`backstop_from_millis`
  `:123`、`SwitchTimeouts::production` `:265`）——预算封顶后 slack 仍
  叠加其上，backstop 永不与该面自己的 deadline 同时触发。嵌入特例
  （登记为「死亡行军」）：本嵌入的切换就是进程停机——SIGTERM 必须终结
  进程，矩阵 A2 的「保留可服务性」在进程退出语义下不可达，故 Halted 后
  `finish_after_halt`（`src/native_process/switch_wiring.rs:131`）仍走完
  剩余出口（封接纳、drain、S4 半段；channel close join 以 entries 同尺
  度有界等待，悬挂的 channel stop 不阻止进程终结），进程以非零码退出，
  机器错误为主、teardown 错误附后（`src/native_process.rs:126-139`）。
- D4：S4 边界 `PhasedInner::finish` 先向全部存量 WS 发
  `close(1001, "server switching")`（`src/native_ws.rs:405-414`，
  `CLOSE_FRAME_WINDOW` 2s `:445`），close 帧发出后连接不再分发
  （transport 的 close_notice 分支），再 abort、再 host shutdown。
  仅切换路径（`run_phased`）：普通 `run()` 调用方保持 #1353 之前的
  abort 行为（见「范围」）。
- D5：S1 停 cron 前先关管理面——`cron_request` 路由缝查询切换闸
  （`src/native_process/methods/cron.rs:68-78`），S1 后六个管理方法报
  `SWITCH_IN_PROGRESS`「switch in progress: cron management is closed」；
  闸以 manager 身份登记（`src/switch.rs:429-454`，未配置 `cron:` 段的
  None 永不关闭，requireCron 形状不变）。
- D6：`RecordingCronGateway`（`src/switch.rs:527`）包住生产 cron 网关，
  abort 拒绝被收集为失败面，S1 面的 stop 连同 abort 失败一起报告，不吞。
- D10：`AdmissionGate::seal`（`src/native_process/switch_wiring.rs:81`）把
  channel server close 的同步前缀（closing 翻转 + running-handle 认领）
  与 native WS listener 停止触发放在同一同步点，seal 返回后两个入口都
  拒新，无 closing 窗口。
- A10 尾格：`finish_stop`（`src/channel/server.rs:470-478`）在
  `closing=true` 下的失败 stop 不再把 handle 回填进 `running`（closing
  外的独立 stop 保留 TS 回填行为）。

## 范围

仅 `--native` 入口的信号停机路径（SIGTERM/SIGINT）。S2 的既有连接语义
（旧 WS 继续服务、有界 drain、到期 abort 不假称排空成功）沿用已接受的
`A7.2-NATIVE-WS-DRAIN-001-R1`，本条不重复、不修改；cron 族实现
（`runtime/cron/*`）未改，闸在路由缝；always-on drain 语义（#2260 三支
二分）不在本条；E5 background 的 S1–S3 接纳格与杀灭口径待 #2251，不宣称
覆盖。本条不作为对拍豁免：上述差异只在切换路径生效，稳态字节与已冻结
判分不变。A10 尾格的 TS 侧行为目前是矩阵的源码推导格，#2251 实测若推翻
「closing 后回填」，本条该点按只追加规则新增更正条目复核。
