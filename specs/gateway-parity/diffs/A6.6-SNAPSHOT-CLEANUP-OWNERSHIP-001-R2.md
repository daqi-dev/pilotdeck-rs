## 类别

对既有登记条目的更正（协议整体替换）：R1 的「创建时取身份 + 私有墓地删除」仍属「在共享发布路径上判归属后删/还」，本轮按协调者指令换为「私有暂存 + 一次原子 rename 发布」，共享路径上不再存在任何归属判断。

## 基线依据

原条目 `A6.6-SNAPSHOT-CLEANUP-OWNERSHIP-001` 与其 R1（原字节冻结）。TS 基线不变（cc7c4e6 `src/storage/workspaceSnapshot.ts`）。本轮新增实测（Node v22.22.0，`_tmp/20261026-issue-293/fix-r2/probe-c.out`）：① 预置非空 partition（含 `keep.txt`、无 marker）时 TS capture 照常提交，`keep.txt` 存活、manifest/`_COMMITTED` 落位——「目标已存在」按覆盖语义处理；② `rename(dir, 非空已存在 dir)` 为 ENOTEMPTY（errno=66）；③ `rename(dir, 空已存在 dir)` 原子替换成功；④ `rename(file, 已存在 file)` 覆盖；⑤ `rename(file, 已存在 dir)` 为 EISDIR。probe-b（`_tmp/20261026-issue-293/probe-b-concurrent.out`）对 TS catch 块无条件 `unlink` 的实证继续有效。方案选择：不采用 `renameat2(RENAME_NOREPLACE)` 等价物（macOS `renamex_np(RENAME_EXCL)`）——它使「目标已存在」直接失败，与实测的 TS 覆盖语义相反；不采用「版本目录 + 指针文件」——它改变 `workspaces/<w>/sessions/<s>/snapshots/<sha>/` 的在盘布局，破坏 TS provider 互读与已冻结的 oracle 树。采用：空闲/空目录目标一次 `rename(2)`（内核级原子），占用目标退化为 TS 自身的逐文件 rename 原语（实测语义）。

## Rust 行为

`src/pilotdeck-gateway/src/storage/workspace_snapshot.rs`：capture 在 marker 早退检查之后派生 `<snapshot_root>/.staging/<uuid>/`，`commit`（函数名锚点）按序写 `_COMMITTED`（先）与 `manifest.json`（最后）到暂存目录，随后 `publish_staging`（函数名锚点）一次 `fs::rename(staging, partition)` 发布；ENOTEMPTY/EEXIST（实测的 dir-onto-dir errno）时退化为本轮暂存内文件的逐文件 rename——`_COMMITTED` 先、manifest 最后，故中断的发布永不留下「无 marker 的 manifest」，残留是 `_COMMITTED` 而非 manifest（见范围）。失败臂 `failure_cleanup`（函数名锚点）只 `remove_dir_all(本轮 staging)` 并尽力 `rmdir(.staging)`，永不触碰已发布路径；`OwnedFile`/`owned_file`/`write_file_identified`/`remove_if_owned`/墓地（`graveyard_name`）全部删除。`walk_manifests` 的根级 `.staging` 跳过（递归层不跳）。成功路径发布后同样尽力移除本轮 staging 与空父目录。NUL 检查保持：失败臂的 `validate_nul_path(partition)` 在 mkdir 与 marker 之前，`nul-capture-root` oracle 拒绝形状不变。

## 范围

结构消除：R1 条目登记的全部四个窗口（rename 后取身份、check-then-unlink、墓地还回竞态、`write_file_identified` 句柄释放后的 inode 复用）随归属判断本身删除而不复存在；`.tmp-grave-*` 滞留物不再产生。仍开放并登记的偏离：① 根级 `list()`/`get()` 忽略 `.staging`——TS 的 walk 无私有暂存区，会读到 `partition/.tmp-*/manifest.json` 中途态（读码 `workspaceSnapshot.ts:152-158`，读码推断未实测）；② fallback 逐文件发布 marker 在先：发布中断于两次 rename 之间时残留已发布的 `_COMMITTED` 而无 manifest，下一轮早退报 Committed（TS 先写 manifest、catch 里删它，不留 marker）；③ staging 清理为尽力而为：残留空 `.staging` 目录属泄漏非不一致；④ 占用目标的 fallback 逐文件覆盖窗口本身与 TS 相同（非原子，last-writer-wins，实测覆盖语义）。`_FAILED.json` 写入顺序不变。
