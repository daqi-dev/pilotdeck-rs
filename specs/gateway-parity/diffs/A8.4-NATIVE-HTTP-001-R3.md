## Rust 行为

`src/pilotdeck-gateway/src/native_http/tests.rs`（test-only；产品代码
`http_proxy.rs` 本两轮零改动）：

- 6 s 空闲关闭族窗口收紧为 (5.99, 6.09] s 共六格：随本 PR 首笔（r1）三格
  `idle_state_no_request_stays_open` / `handler_execution_blocks_idle_close` /
  `pipelined_request_during_body`（probe 5_400/700 → 5_930/40）；随 fix-r1
  三格 `served_follow_up_head_silent_ends_at_idle_close` /
  `in_flight_request_disarms_rearmed_timeout` / `held_response_gets_no_headers_timeout`
  （尾窗 200 ms → 40 ms，消息加「not any later」）。九格共用命名常量
  `IDLE_CLOSE_PROBE_ADVANCE`（+5.93 s 探活推进，探活点 = 该常量 +
  `probe_still_open` 内部 `IDLE_CLOSE_HELPER_ADVANCE_MS` 60 ms = +5.99 s）
  / `IDLE_CLOSE_TAIL_WINDOW`（40 ms 尾窗，晚关上界 = 40 + eof helper
  内部同一 60 ms = 6.09 s）；fix-r2 起同刻格
  `idle_deadline_and_client_close_same_instant_resolve_ok` 的半关瞬时与
  越界步也收编——派生常量 `IDLE_CLOSE_PROBE_INSTANT`（=
  `IDLE_CLOSE_PROBE_ADVANCE` + 60 ms helper 推进 = +5.99 s）与
  `IDLE_CLOSE_RACE_STEP`（20 ms，独立于窗口常量：同刻竞态语义，非探针
  窗口），6 s 族全部裸字面量收编（防漂移；评审 simplify #4——700/200 ms
  宽尾窗正是字面量彼此无关联的漂移产物）。
- 新格 `client_close_during_held_body_resolves_without_timer`（矩阵
  S4×E5，`#1250` fix-r1 遗留子格）：持体期（`held_body("part1-", "part2",
  release)`）客户端半关后放行持体，连接 future 裸 `task.await` 解出
  `Ok`、全程零 `advance()`；可读半关客户端收到补完的保留体
  （`…part2\r\n0\r\n\r\n`）再 EOF。
- **字节层分歧（本条目的登记主体）**：同格交错下 Node 在 FIN 同刻截断
  响应（保留体不送达，见上探针），本车道把保留体补完给仍在读的半关对端
  再 EOF；两家在连接 future 结果层一致（`Ok`、不挂、无残留计时——新格
  锚定的就是这一层）。产品侧是否复刻 Node 的 FIN 同刻截断属产品代码
  改动，**另单跟进**，不在本 PR（只改测试文件）范围（另见已开跟进
  #2380，其覆盖范围不因本条目改变）。

## 机器判据

`src/pilotdeck-gateway/src/native_http/tests.rs`：

- 六格窗口收紧 (5.99, 6.09] s（测试名见「Rust 行为」），窗口由命名常量
  可复算：探活点 = `IDLE_CLOSE_PROBE_ADVANCE` + `probe_still_open` 内部
  `IDLE_CLOSE_HELPER_ADVANCE_MS`（5_930 + 60 = 5_990 ms），晚关上界 =
  `IDLE_CLOSE_TAIL_WINDOW` + `eof_after_idle_close` 内部同一 60 ms
  （40 + 60 = 探活点后 100 ms，即 6.090 s）；写法与 #1250
  fix-r1 已收紧的 `keep_alive_idle_close_lands_at_six_seconds` /
  `idle_close_waits_for_streaming_body` / `idle_close_refreshes_on_read_segments`
  同款；`native-http-idle-close-buffer-half`（500 ms buffer，关闭 5.5 s）
  绑 `keep_alive_idle_close_lands_at_six_seconds` 的 +5.99 s 仍开探针
  （001-R2 已登记），六格的探针对同回退同样失败。
- 新格 `client_close_during_held_body_resolves_without_timer`：对齐格，
  无专属 mutant，与 001-R2 的 `idle_deadline_and_client_close_same_instant_resolve_ok`
  同口径——本格对 `native-http-inflight-body-off` mutant 不判杀（恒绿：
  槽位回归在本格不可观测，连接 future 经对端 EOF 结束，与计数无关，
  per-connection `in_flight` Arc 随 task 消亡；读码推断，标注见测试 doc
  comment），「体结束释放槽位」的专属判杀格是绑该 mutant 的
  `negative_controls.py:78` 条目所指 S4×E3/E4 格
  `idle_close_waits_for_streaming_body`。本轮不新增 `negative_controls.py`
  条目（处置表限定「仅改常量与消息」），37 条既有锚与本 PR 消息改动
  零交集（anchor 双跑 diff 为空，见 #1366 fix-r1 RESULT）。
- 复算命令：`cargo test -p pilotdeck-gateway --lib native_http`（六格 +
  新格逐名 ok）；`python3 -I
  src/pilotdeck-gateway/tests/fixtures/native-http-basic/negative_controls.py
  --check`（37 锚）。
