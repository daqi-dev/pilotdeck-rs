## 类别

行为差异（语义细节）

## 基线依据

`proxy.ts:122-145`：`applyGlobalProxy` 捕获所有异常（`catch { // best effort }`），若 `EnvHttpProxyAgent` 构造失败则返回 `undefined`，全局 dispatcher 保持 undici 默认（带长超时参数的直连 agent）。不可解析或不支持的代理 URL 静默退化，仍使用 `createLongTimeoutOptions` 的全局 dispatcher。

## Rust 行为

`ProxyConfig::new_with_extra`（`src/pilotdeck-gateway/src/runtime/model/http.rs:532`）：

```rust
let proxy = url::Url::parse(proxy_url).ok()?;   // 解析失败 → None
if proxy.host_str().is_none() || proxy.scheme() != "http" {
    return None;   // 不支持的 scheme → None
}
```

返回 `None` 时 `ProxyConnect` 使用 `proxy: None` 直连，超时参数沿用 `https_connector` 的 10 s `connect_timeout`。

## 范围

语义对齐：两者均静默退化为直连。细节差异：TS 退化路径仍通过 `EnvHttpProxyAgent`（带长超时），Rust 退化路径使用原生 hyper connector（10 s connect timeout）。对于代理 URL 不可达场景，超时行为略有不同，属可接受偏差。
