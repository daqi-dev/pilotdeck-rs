# A6.5-MCP-PROXY-FALLBACK-001 · MCP / 模型代理：不可解析 / 不支持 URL 退化为直连

**类别**：行为差异（语义细节）  
**批准状态**：待批（登记于 #576，理由见下）

## TS 基线

`proxy.ts:122-145`：`applyGlobalProxy` 捕获所有异常（`catch { // best effort }`），
若 `EnvHttpProxyAgent` 构造失败则返回 `undefined`，全局 dispatcher 保持 undici 默认
（带长超时参数的直连 agent）。TS 对任何不可解析或不支持的代理 URL 均静默退化，
但仍安装了带 `createLongTimeoutOptions` 的全局 dispatcher。

## Rust 现状

`ProxyConfig::new_with_extra`（`src/pilotdeck-gateway/src/runtime/model/http.rs:532`）：

```rust
let proxy = url::Url::parse(proxy_url).ok()?;   // 解析失败 → None
if proxy.host_str().is_none() || proxy.scheme() != "http" {
    return None;   // 不支持的 scheme → None
}
```

`None` 时 `ProxyConnect` 使用 `proxy: None`，即直连，超时参数沿用 `https_connector` 的
10 s `connect_timeout`；TS 的 `UNDICI_TRANSPORT_TIMEOUT_MS`（600 s）长超时 agent
不适用（该值专用于已建立连接上的读写，不是 connect timeout，语义不同）。

## 差异描述

语义对齐：两者均静默退化为直连。细节差异：TS 退化路径仍通过 `EnvHttpProxyAgent`
（带长超时 dispatcher），Rust 退化路径使用原生 hyper connector（10 s connect timeout）。
对于代理 URL 不可达场景，超时行为略有不同，属可接受偏差。

## 批准理由

直连退化行为与 TS 语义一致（静默、不中断连接）。
超时细节差异不影响正确性，登记备查，不阻塞合并。
