## Rust 行为

NOT_RUN —— 本切片不判 Rust、不跑 Rust retirement 轮（它是本切片之后的单）。本条目只登记 Rust 轮**必须**满足的对照判据与独立装置；Rust retirement 轮必须显式运行本装置（判据未接进冻结装置 `session_domain.py`，见「已知边界」③），否则该轮不得宣称覆盖本判据。不得据本条宣称退役达成。

## 范围

判定对象 = 一轮或多轮 retirement 轮的 `driver/methods.json`（逐方法 outcome）+ `driver/frames.jsonl`（线缆）。规则（实现于 `scripts/retirement-outcome-parity/check_outcome_parity.py`）：

- **P1 COVERAGE**：执行集必须等于登记的 101 方法集（金样），缺一 / 多一即 FAIL（点名方法）；`timeout` outcome 不计入已执行且本身即 FAIL；方法名重复即 FAIL。
- **P2 SHAPE**：每方法 `shape` 必须等于金样（`submit_turn` = `stream`，其余 100 = `request`）。
- **P3 OUTCOME**：每方法 `outcome` 必须等于金样（77 ok / 24 error），**不接受任何「可用率」折算**。
- **P4 ERRORCODE**：每个 error 方法 `errorCode` 必须与金样逐字相等（大小写敏感）；ok 方法不得带 `errorCode`。15 种码的具体归属全部登记进金样，不按种类近似。
- **P5 UNAVAILABLE-SET（本单核心，闭环 F5 / DS-P0-1）**：`errorCode == CAPABILITY_UNAVAILABLE` 的方法集合必须**恰好**等于基线依据所列 6 个；集合外任何方法答 unavailable 即 FAIL（点名），6 个之内任何一个答非 unavailable 也 FAIL。**99/101 unavailable 必须 FAIL**——「全量才 FAIL」的旧 `UNIFORM_UNAVAILABLE` 语义不得作为 Rust 轮判据（负控 N10 是该语义的死亡证明：该形状下旧规则一条都不触发，本判据 P5 触发）。
- **P6 WIRE-CODE（闭环 F7）**：每个 error 方法必须有同 id 的 `response` 帧且 `ok is false`、`error.code` == `outcome.errorCode`、`error.message` 非空；每个 ok 的 request 方法必须有同 id 的 `response` 且 `ok is true`、不得带**非 null** 的 `error`（`"error": null` 与缺省等同无 error——serde 未 skip 成功响应时常见，判成「携带 error」会对合法 Rust 轮假 FAIL；**除 null / 缺省之外的任何值都算携带 error**，包括 `error: String` 的 `"boom"`、`error: Vec` 的 `[]`、`0`、`true`——「不是 dict 就当没有」会把线缆异常放成假 PASS）；`stream` 且 ok 必须有同 id 的 `final: true` 事件帧且 `events >= 1`。缺帧 / 码不一致一律 FAIL（点名方法 + 双方码），不设「仅建议」档。三条加严：① **同一 id 出现多条 `response` 帧即 FAIL**（与 send 侧「一个方法多条 send 帧」对称）：重放/重试重复落盘不得被 last-wins 掩盖成「先错码后对码」的假 PASS；② **`stream` 且 ok 的方法若同 id 另有一条 `response` 帧，该 response 必须 `ok is true` 且无 `error`**——事件侧有 `final: true` 不能豁免一条自相矛盾的错误 response（否则错误响应被静默忽略成假 PASS）；③ **同一请求 id 被多个方法当作 send id 即 FAIL**（点名方法与共用方）——否则一个方法的成功 response 可被另一个方法借用通过 P6，响应无法归属单一方法。
- **P7 ROUND-STABILITY**：同一轮次集合内每方法 `(outcome, errorCode)` 必须逐轮相同；任何轮间漂移 FAIL（点名方法 + 漂移轮次）。基线依据：TS 5 轮零漂移。报告显式给出 `p7Rounds` / `p7Evaluated`：**只跑 1 轮时 P7 是空判**（每方法只有一项），`status: PASS` 不得被引用为「跨轮稳定已核」。
- **P8 FAIL-CLOSED**：缺 `methods.json` / `frames.jsonl`、JSON 解析失败、方法行缺 `method`/`outcome`/`shape` 字段、未知 `outcome` 值、金样条目数 ≠ 101、金样 unavailable 集与登记 6 个不符 → 一律非 PASS（rc 1 或 2），禁止静默跳过。另四条入口 fail-closed（rc 2，不当 PASS）：方法行 `errorCode` 非字符串（否则 P7 稳定性集合抛 `TypeError` traceback）、`events` 非整数（否则 JSON `true` 被当成 1）、**轮次目录重名**（P7 以目录名为键，重名会静默合并两个轮次，跨轮漂移检测被架空）、`methods.json` / `frames.jsonl` / 金样**非法 UTF-8**（`UnicodeDecodeError` 不属于 `OSError`，不显式接住会 traceback 成 rc1「判据 FAIL」）。另加一条**跨登记表一致性**（rc 2）：金样的 `(method, shape)` 集合必须与冻结 fixture `scripts/gateway-parity/fixtures/retirement-methods.json` 逐条相同——本装置的金样是第 5 份「101 方法」登记表，不与冻结四源交叉校验时，任一边单独漂移都会让 P1 的期望集失效（漏跑新方法时 missing=∅ 仍 PASS，即假 PASS；反向漂移则假 FAIL）。`emit` 生成侧同样核。

**阈值**：**0 处不一致**。不设百分比阈值、不设「允许 N 个方法退化」、不设 per-method 白名单。唯一「看起来像豁免」的东西是 6 个 gated unavailable 行：它们**不是豁免而是登记值**（基线在无凭据配置下就是如此答，P5 对它们两个方向都判）。

**容差（明确不比较，逐条理由）**：

- `elapsedMs` —— 纯计时；TS 5 轮 95/101 方法跨轮变动（其余 6 个亚毫秒方法恰好恒定），计时不是行为判据。
- `error.message` 文本 —— 含轮次绝对路径（`skill_read` 即证）与 provider 措辞；只要求非空（P6）。**残余登记**：Rust 轮可以码对而文案不同仍 PASS，文案对齐不在本切片。
- `events` 计数 / `lastEventType` —— 只要求 stream ok 有 `final: true` 帧且 `events >= 1`；不锁定帧数。

## 已知边界

① 上述 `error.message` 文案与 `events` 帧数不比较（码对文案不同仍 PASS），文案对齐不在本切片；② 判据只覆盖**单轮内**的方法级行为，不覆盖 hostAudit / entryInventory / 网络面（那两面归 #1478）；③ 判据**尚未接进冻结装置**（`session_domain.py`），Rust retirement 轮必须显式运行 `scripts/retirement-outcome-parity/check_outcome_parity.py`，否则该轮不得宣称覆盖本判据——接进冻结装置需走冻结程序另立条目（若协调者认为必须接进才算生效，见 `_tmp/20261106-issue-1477/r1/decision.md` 的范围与代价记录）；④ P6 的 error 分支要求同 id 的 `response` 帧，比冻结装置 `EVIDENCE_BACKING` 对 stream error 的「任意 receive 帧」语义更严（`session_domain.py:1987-1994`）：Rust driver 若把 `stream` 形状的错误只落 event 帧、不写 response，本判据会判 FAIL——方向是响亮失败而非假 PASS；是否放宽需另立更正件，不在本切片改判据。

负控执行器**第一件事**是失效同输出目录的旧 `summary.json`（含残留 `*.tmp`）：下游以「`summary.json` 存在」为跑完证据，任何早退路径（缺 `-I`、checker 导入失败、参数拼错 / 缺值 / 多余 token、缺文件、解析失败、preflight 非 0）都不得把上一轮的 PASS 留在盘上。因此这段写在**模块体最前面**，早于 `-I` 断言、早于 `load_checker()`、早于 pycache 前缀设置，且只依赖 `os` / `sys`；它只在 `__main__` 下执行（被 import 时不得拿宿主 `sys.argv` 去删任何东西）。输出目录只从**显式** `--output` 取（解析器 `allow_abbrev=False`，选项名精确匹配，解析前即可无歧义取值）：不按「哪些 token 可能是位置参数」猜候选——未知选项带不带值在解析前不可判定，猜错就删到别人的证据（误删同样算丢数据）；**没写 `--output` 就一个都不删**（`--` 之后的 `--output` 按 argparse 语义只是位置参数，执行器无位置参数、命令直接 rc=2，此时不删）。**帮助路径同样失效**：命令里显式点了输出目录，之后无论是跑、是 `-h` / `-hh`、还是 argparse 报错，那个目录的旧 PASS 都已报废——「跳过帮助」等于把「哪些形状算帮助」再猜一遍，而猜错的方向永远是留旧 PASS 冒充本轮。重复写多次时**每个非空值都失效**且**逐个都试一遍再退出**（前一个目录不可删不短路后面的；argparse 只有最后一个生效，但这条命令终究没跑完，多失效一个自己点过名的目录代价远小于留下旧 PASS）。值 = **紧跟** `--output` 的那个 token；它若不是值，就算这次 `--output` 缺值、**不再向后找**（`--output --data DIR` 里的 DIR 属于 `--data`，argparse 在第一个 `--output` 上就报错）。三种 token 不是值：① 本解析器认识的选项拼写（`allow_abbrev=False`，精确匹配）；② **3.12 与 3.14 都判成选项**的形状——`-` 后是 `-` 或字母、且不含空格（`-hh` / `-h=x` / `-x` / `--he` / `-e5` / `--1`），两版实测 `--output <token>` 都报 `expected one argument`，当值只会去失效一个同名目录；③ 空 token。两版**结论相反**的只有「`-` 后紧跟数字或点」这一小撮（`-1x` / `-1e3` / `-1_000`：3.12 当选项、3.14 当值），一律按值——漏收的方向是留旧 PASS 冒充本轮，误删只是少一份可复算的旧结果，代价不对称。已知选项不当值但要重新按 token 处理一遍（`--output --output=DIR` 仍收集 DIR）。空值（`--output=` / `--output ''`）不失效且判参数错误 rc=2——`Path('')` 就是当前工作目录，否则会删掉调用者 CWD 里的 `summary.json` 再把变异轮写进去。失效只删本执行器自己的产物名（`summary.json`、`summary.json.tmp`、`summary.json.<pid>.tmp`），`summary.json.backup` 之类的既有文件与**存活 pid** 的 tmp 不删（并发互斥残余见跟进单）。前置自检除逐轮外还跑一次**跨轮合并**（`check --round round-01 --round round-02`），否则 N11 的「跨轮漂移」归因无法排除参考轮对本身已漂移（单轮 P7 是空判）。两个入口成对设 `sys.pycache_prefix` + `sys.dont_write_bytecode`（同族 `scripts/gateway-parity/*`、`scripts/parity/*` 口径）：只挡写不挡读时，负控经 `spec_from_file_location` 再加载 checker 可能执行陈旧 `.pyc`（PEP 552 unchecked-hash），KILLED 归因就不再是「跑当前源码」；无可写临时目录时回退到**核实不存在**、名字带 16 位随机字节的目录（固定的 `.no-pycache-<pid>` 可预测，等于给 unchecked-hash pyc 留了可投毒位置），**启动依赖不得先于旧结果失效**。入口级失败一律 **rc=2**（输入或环境不可用，不是判据 FAIL）：缺 `-I`、checker 缺失 / 不可读 / **加载期任何异常**（含 `SyntaxError`）、pycache 前缀候选耗尽、`emit`
