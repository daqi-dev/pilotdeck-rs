## 类别

运行时 API 映射差异的范围补充。原条目只覆盖 complete I/O；同一 Drop 所有权规则也适用于新增 wire status 持久化。原条目结论不变，不增加判分豁免。

## 基线依据

cc7c4e6 的 TurnRunner.ts:332-336 等待 status callback。真实 TS TurnRunner 探针见 `src/pilotdeck-gateway/tests/fixtures/turn-runner/generate.mts` 的 status_drop，原始输出 `_tmp/20261026-issue-741h/ts-verified-complete.log`，金样 `turn-runner/oracle.json` 的 forward/status_drop。

实测：status writer 挂起时 next 与 return 都未完成；放行后该 next 得到 agent_status，写入恰一次，return 随后关闭 loop。JS return 不能取消排在它前面的 next。

## Rust 行为

Drop 整个 LiveTurn 取消 async transition 和 status 完成反馈；已进入 blocking append 的 worker 保留同一 ActiveTurn 与 RuntimeLease，直至 I/O 退出。没有消费者，不再交付 status。取消 next 的借用则保留原 transition 和 payload，恢复后只写一次。

## 范围

补充 status I/O 成功写入期间的 owner Drop。本次没有实测 status 写入失败与 Drop 同拍，不将这一组合记为通过。其余 complete、EOF、预取消范围沿用原条目；不改变 StreamIntegrity。

## 机器判据

`src/pilotdeck-gateway/src/runtime/turn/forward_tests.rs` 的 forward_status_drop / forward_status_cancel 检查 pending gate、两次 waiter 取消、真实 slot/lease 及一次写入；ignored runner_regenerates_identically 逐字节重生成整个 turn-runner 金样。forward_negative.py 绑定 worker ownership 与 pending payload 变异；运行时负控待提交后宿主执行，不能将静态锚点审计计为运行时 RED。
