## 类别

#886 额外损坏压缩载荷探测发现的 legacy SSE 握手错误差异，未批准，非已接受差异。

## 基线依据

固定 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85、Node v22.22.0、SDK 1.29.0。
真实 SSEClientTransport.start 收到 Content-Encoding: gzip 且载荷为 invalid compressed body，
立即拒绝 Error / SSE error: TypeError: terminated: incorrect header check。
金样为 tests/fixtures/mcp-http-encoding/oracle.json 的 legacy-start/corrupt；
原始输出 `_tmp/20261026-issue-886/node-golden-expanded.log`。

## Rust 行为

共享 #867 decoder 把 codec 错误映射为 BodyFailure::Terminated，不保留 codec cause。
既有 legacy_stream 忽略 read_events=false，未收到 endpoint 的 start 保持未 settle，
外层 event_source 进入既有重连逻辑。该行为不是已对齐。

## 范围

仅本地真实 socket 的 legacy SSE 初次 endpoint 前损坏 gzip 载荷。
普通合法 gzip/br、多层、五层边界、六层上限、未知编码不属于此差异，均严格对拍。
不推断其他压缩器、截断程度、任意传输失败或已建立会话的结果。

## 机器判据

runtime::mcp::http::encoding_tests::mcp_legacy_corrupt_gap_is_observed 重放同一 wire 字节；
在 read_events 返回后用 oneshot.try_recv 确认 start 尚未 settle，打印 TS/Rust 差异。
无 sleep；10 s watchdog 保证测试结束。该诊断的绿不计入 TS 对齐格数。
完整范围 77 格中 76 对齐、此格未对齐，不能称损坏载荷全通过。

## 批准记录

未批准，非已接受差异，前置于 legacy SSE 损坏压缩体范围验收。
本任务要求 #867 复用仅变可见性/导出，不修改其语义；修复须另核共享错误信息与 legacy
生命周期，并回归 #867 金样。此处登记缺口供协调者跟进，不新增判分豁免、不关闭阶段。
