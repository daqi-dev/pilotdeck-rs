## 类别

更正（登记失实，差异本身不变）：原条目「范围」节写「差异只在同一非字符串键的第二次及以后重连……首调（无状态）语义两侧一致」，与仓内录制的 TS 金样相反——金样里 `submit_turn` 已经按原始值 `5` 落过 binding，因此**第一次** `reconnect_interaction(5)` 即返回 `reconnected`。原条目「Rust 行为」节把规则位置写成请求适配器；#1632 包 B 第 8 项把该规则下沉到 runtime 端口，位置随之改变（行为不变）。原条目文件原字节不动。

## 基线依据

TS 基线 `cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85`（Node v22.22.0），与原条目一致。反证取自仓内录制金样 `src/pilotdeck-gateway/tests/fixtures/connection-context/oracle.json`：

- 场景 `session-key-5`（`oracle.json:7073`）：`hello`（`clientName:"sdk"`）→ `submit_turn {"sessionKey":5,"projectKey":"p"}` → `reconnect_interaction {"sessionKey":5}`；
- 该次重连的录制帧（`oracle.json:7296`，同形重复于 `:7403`）：

```json
{"type":"response","id":"reconnect_interaction","ok":true,"result":{"outcome":"reconnected","binding":{"connectionId":"@connection-19","generation":19},"requests":[]}}
```

即 TS 在**首调**就把 `5` 当成已有 owner：`bindings.set(5, …)` 已在 `submit_turn` 侧发生（与原条目引用的 `InteractionReconnect.ts:94-111` 普通 `Map` 一致）。

## Rust 行为

不变（`no_pending` / `stale_binding`），但规则位置改了：`src/pilotdeck-gateway/src/runtime/interaction/reconnect.rs:137` 的 `InteractionReconnectPort::reconnect_unkeyed` 决定非字符串 owner 的 miss 形状（`previous` 有值 → `stale_binding`，否则 `no_pending`，均不建状态），`src/pilotdeck-gateway/src/runtime/interaction/coordinator.rs:89` 同层转发；`src/pilotdeck-gateway/src/native_process/methods/interaction.rs:94` 只把 owner 映射进端口并转换错误类型，不再决定 miss 长什么样。原因同原条目：交互端口用 `JsString` 建模 TS 的 `string` 键域，非字符串键无表示。

## 范围

仅 `reconnect_interaction` 且 sessionKey 为非字符串（null/undefined 已由连接层 `?? ""` 折叠为空串）。更正后的范围：**每一次**非字符串 owner 的重连都与 TS 分歧，包含首调——只要 TS 侧在该键上已存过 binding（如先 `submit_turn {"sessionKey":5}` 再重连），TS 返回 `reconnected`（或 generation 不变时的 `stale_binding`），Rust 恒 `no_pending`/`stale_binding`。只有「TS 侧从未见过该非字符串键」的那一格两侧才同为 fresh-owner 语义。字符串 sessionKey（包括空串）完全一致。

原条目对兄弟分支的结论（`elicitation_respond` / `permission_decide` 无此差异，理由是「TS 的 `Map.get(SameValueZero)` 对非字符串键恒 miss」）与本条新证实的事实**方向相反**：SameValueZero 用原始值比较，`5` 与 `5` 相等，只要 TS 在该键上存过值就会命中，不会「恒 miss」。该兄弟结论未经 TS 探针复算，本条不代为改判；缺口记入 #1465，待该轮以 `elicitation_respond {"sessionKey":5}` / `permission_decide {"sessionKey":5}` 的录制帧定形。

旁注（不改变本条判定）：连接层回放看不见这条分歧——`src/pilotdeck-gateway/src/runtime/connection/tests.rs:162`、`:215` 的 Gateway 替身用 `property_text(&params,"sessionKey")` 以 JSON 文本落键（行为=TS），真端口不参与回放；该夹具真实性缺口登记在 #1465。
