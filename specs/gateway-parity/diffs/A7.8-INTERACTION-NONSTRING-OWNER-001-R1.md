## 类别

更正（登记失实，差异本身不变）：原条目「范围」节写「差异只在同一非字符串键的第二次及以后重连……首调（无状态）语义两侧一致」，与仓内录制的 TS 金样相反——金样里 `submit_turn` 已经按原始值 `5` 落过 binding，因此**第一次** `reconnect_interaction(5)` 即返回 `reconnected`。原条目「Rust 行为」节把规则位置写成请求适配器；#1632 包 B 第 8 项把该规则下沉到 runtime 端口，位置随之改变（行为不变）。原条目文件原字节不动。

## 基线依据

TS 基线 `cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85`（Node v22.22.0），与原条目一致。反证取自仓内录制金样 `src/pilotdeck-gateway/tests/fixtures/connection-context/oracle.json`：

- 场景 `session-key-5`（`oracle.json:7073`）：`hello`（`clientName:"sdk"`）→ `submit_turn {"sessionKey":5,"projectKey":"p"}` → `reconnect_interaction {"sessionKey":5}`；
- 该次重连的录制帧（`oracle.json:7296`，同形重复于 `:7403`）：

```json
{"type":"response","id":"reconnect_interaction","ok":true,"result":{"outcome":"reconnected","binding":{"connectionId":"@connection-19","generation":19},"requests":[]}}
```

即 TS 在**首调**就把 `5` 当成已有 owner：`bindings.set(5, …)` 已在 `submit_turn` 侧发生（与原条目引用的 `InteractionReconnect.ts:94-111` 普通 `Map` 一致）。

## Rust 行为

不变（`no_pending` / `stale_binding`），但规则位置改了：`src/pilotdeck-gateway/src/runtime/interaction/reconnect.rs:137` 的 `InteractionReconnectPort::reconnect_unkeyed` 决定非字符串 owner 的 miss 形状（`previous` 有值 → `stale_binding`，否则 `no_pending`，均不建状态），`src/pilotdeck-gateway/src/runtime/interaction/coordinator.rs:89` 同层转发；`src/pilotdeck-gateway/src/native_process/methods/interaction.rs:94` 只把 owner 映射进端口并转换错误类型，不再决定 miss 长什么样。原因同原条目：交互端口用 `JsString` 建模 TS 的 `string` 键域，非字符串键无表示。

## 范围

仅 `reconnect_interaction` 且 sessionKey 为非字符串。

> **2026-11-06 追加更正（#1632 包 B r8 评审）**：本节原写「null/undefined 已由连接层 `?? ""` 折叠为空串」，并据此把 null 排除在分歧之外——**只对 reconnect 侧成立**。submit_turn 侧 Rust 曾把非字符串键折叠成空串 owner 并在共享端口落 binding：`submit_turn {"sessionKey":null}` 之后 `reconnect_interaction {"sessionKey":null}`（连接层折成 `""`）会命中该 binding，答 `reconnected`/`stale_binding`；而 TS 把 binding 存在原始键 `null` 下，`""` 查不到，金样 `session-key-null` 答 `no_pending`。这是未登记的反向分歧。包 B 已把 submit 侧改为「非字符串键不落 binding」（空串仍是真实 owner），`session-key-null` 那一格（重连答 `no_pending`）两侧一致，并已作为可执行断言纳入金样用例。范围因此收紧为：**已录制的那一格在 reconnect 侧**。

同一处改动还有一条**未录制的代价**，一并登记（r9 concurrency P1）：Rust 的端口键域是 `JsString`，不落 binding 等于**该 owner 在 Rust 侧没有任何 per-owner 状态**，于是 `interaction_reconnect_required` 闸门对非字符串键永不触发——TS 把 binding 存在原始键下，第二个连接用同一原始键、不同 binding 再 `submit_turn` 会被拒。改前 Rust 因误用 `""` 桶而「碰巧」与 TS 同答案，改后放行。用「可表示的影子键」补回这条状态属结构性改造（端口键域放宽到 `JsValue`），不在 #1632 范围，缺口记 #1723；当前行为由 `runtime::turn::admission::tests::a_non_string_owner_does_not_gate_a_second_connection` 钉住，不让它只活在散文里。同一函数里按 owner 键的 `dialog_project_keys` 表原先把非字符串键也折进 `""` 桶（该表当前**无读取方**，`dialog_project_key()` 无调用点），已按同一键域规则改为非字符串键不落桶。同文件另有两处 `string(field(input,"sessionKey"))` 折叠（`compact_command` 交给 `router.compact`、`set_sdk_config` 交给 `port.set`）暂不改：这两个端口全仓只有测试实现（`SubmitCompactionRouter` / `SubmitSdkSessionConfig` 无生产实现），不落任何跨会话共享状态，改动只会动测试替身的行为；清理与接上生产实现时的复核一并记 #1723。

同一条键域规则在别处还有若干**既有**折叠，本 PR 不改、也不声称已对齐（r11 GLM sibling P1、r14 GLM sibling P2：**本条不写数量、不声称穷举**，理由是这条清单已经因为「只数到 N 处」被评审纠正过两次）。已知各格：`runtime/turn/submit.rs` 的 `RunRef.session_key = string(field(&input,"sessionKey"))`（turn 骨干状态——run registry、lease 表、replay 缓冲、事件协调器——都按它键，非字符串键因此落 `""` 桶）、`runtime/replacement.rs` 的 `replace_last_turn` / `finalize_last_turn_replacement` 同款折叠（reservations / pending 按 `""` 桶互相占位）、`runtime/turn/read.rs` 的 `read_session_messages` 用 `.and_then(JsValue::as_string).cloned().unwrap_or_default()` 把非字符串/缺失键折成 `""` 再拿去 `snapshot(...)`（直接消费原始方法输入，`methods/history.rs` 原样透传 params）。复核用 `grep -rn 'unwrap_or_default()' src/pilotdeck-gateway/src/runtime` 与 `grep -rn 'field(&input, *"sessionKey")\|get("sessionKey")' src/pilotdeck-gateway/src` 现场重数，不要相信本文的数字。全部都在本 PR 之前就存在，改法是把 per-owner 状态改成原始值键域（同「消除分歧」一样属结构性改造），已记 #1723，前置于 #1316 关闭。

同一键域上还有一批**丢弃/拒绝**点（r13 GLM sibling P1、r13 MiniMax sibling P2；行为不变，只更正注释与登记）。**注释只改了一处**：`runtime/turn/gateway.rs` 的 `abort_on_close` 原写「TS 用严格 Map 键，非字符串值不可能命中活会话」——与本文件上面证实的「SameValueZero 比原始值、存过即命中」相反——已改成「Rust 侧键域所限；TS 是否同样 miss 未定」，并指向 #1465。同文件的 `disconnect`（`sessionKey must be a string.`）本就没有键域注释，本 PR **不改它的文案也不加注释**，只在这里登记它是同一形态的拒绝点，不把它写成「已加免责注释」。**同一形态的点本条不声称穷举**：`grep -n 'sessionKey must be a string' src/pilotdeck-gateway/src` 与 `grep -rn 'string(&params, "sessionKey")' src/pilotdeck-gateway/src` 可随时重新枚举，本次所见还含 `native_process/methods/{steer,active_turn,runs,session_dir}.rs`（经 `methods/mod.rs` 的 `string()` 助手产出同款文案），均为本 PR 之前的既有行为。TS 的 abort/disconnect/steer/hook 半边行为待 #1465 以录制帧定形（本 PR 的 oracle 只覆盖 reconnect），登记归 #1723。

更正后的范围：分歧只出现在**能原样过线到网关**的非字符串原始键上，即 number 与 bool（`5` / `true` / `0` / `false`）：只要 TS 侧在该原始键上已存过 binding（先 `submit_turn {"sessionKey":5}` 再重连），TS 返回 `reconnected`（generation 不变时 `stale_binding`），Rust 恒 `no_pending`/`stale_binding`，且**首调**即分歧；TS 侧从未见过该键时两侧同为 fresh-owner 语义。

另有两类非字符串键按同一逻辑两侧**一致**，不属本条范围（r10 boundary P1：把它们算进「每一次都分歧」会让读者去修已经对齐的格子）：

- `null` / `undefined`：连接层把 reconnect 的 `sessionKey` 折成 `""`（`params.sessionKey ?? ""`），而 submit 侧把 binding 存在原始 `null` 下，`""` 查不到，TS 答 `no_pending`（金样 `session-key-null`）；包 B 之后 Rust 同样不为非字符串键落 binding，两侧一致。
- 对象 / 数组键：TS 的 `Map` 按引用比较，WS 每帧重新解析出的对象必是新引用，`get` 恒 miss；Rust 侧键域不含非字符串，同样 miss。

字符串 sessionKey（包括空串）完全一致。

原条目对兄弟分支的结论（`elicitation_respond` / `permission_decide` 无此差异，理由是「TS 的 `Map.get(SameValueZero)` 对非字符串键恒 miss」）与本条新证实的事实**方向相反**：SameValueZero 用原始值比较，`5` 与 `5` 相等，只要 TS 在该键上存过值就会命中，不会「恒 miss」。该兄弟结论未经 TS 探针复算，本条不代为改判；缺口记入 #1465，待该轮以「TS 在该非字符串键上存过 pending 后再查」的录制帧定形。

同一份夹具里确有一帧 `permission_decide` 的非字符串请求，但它**定不了**这件事：`session-key-5` 场景的 pending 权限项 `requestId` 是 `fixture-permission`（`oracle.json:7294` 的 `permission_changed` 载荷），而该请求送的是 `{"sessionKey":5,"requestId":"control"}`（`:7098`），TS 仍答 `{"accepted":true}`（`:7350`，`framesText` 见 `:7404`）。即 `accepted` 是连接层对「收到并排队」的应答，不是「命中 pending 并投递」的信号——拿它判兄弟分支命中与否会得出与 reconnect 半边相反的结论。该字段语义与 Rust `delivered` 是否同义一并留给 #1465。

旁注（不改变本条判定）：连接层回放看不见这条分歧——`src/pilotdeck-gateway/src/runtime/connection/tests.rs` 的 Gateway 替身（`authed_as_client` 构造的那个 `Gateway` 桩）用 `property_text(&params,"sessionKey")` 以 JSON 文本落键（行为=TS），真端口不参与回放；该夹具真实性缺口登记在 #1465。

「null 被折叠」这条排除本身也有可执行钉子：连接层用例 `runtime::connection::tests::interaction_inputs_reach_the_gateway_through_the_connection` 对同一份录制金样的 `session-key-null` 场景分别钉住 `reconnect_interaction` 折成 `""`、`submit_turn` 与 `permission_decide` 原样转发 `null`。只钉 reconnect 半边会让「到处折叠」的回归判绿，从而把本条范围悄悄扩大。
