## 范围

更正统一规约六点（基础条目第 1 项内；第 3 项 ② 的「端口互斥、EADDRINUSE 假红的机检
字样与上限同彼」与 ④ 的引用，所指一律为本 R1 更正后的版本）。其余条款不变：ls-remote
远端真值与格式判据、一次性 detached worktree、`--exact` 命令形态与取数正则、三条已知
假绿的堵法、EADDRINUSE 假红连续 2 次作废、第 2 项人工核对、第 3 项 ①③④⑤⑦、
`mergeCommit` 落点与作废、装配认定。**装置现状如实登记：① 的租约装置与 ② 的字面串
锚点自检均为「规约要求、装置待落地」（见「机器判据」），落地前不得当作已存在判据引用。**

① **运行前 per-port flock 租约**。该轮 worktree 核完 `HEAD` / `status --porcelain`
之后、第一条用例命令之前，对 18990 与 18991 各取一次宿主机 per-port flock 租约，
#1510 形态：租约文件放固定绝对路径的 0700 uid 属主目录下（不经 `$TMPDIR`——不同
TMPDIR 的并行副本会租到不同文件、互斥静默失效），按端口一文件，绝不 unlink；
`flock LOCK_EX|LOCK_NB`；EACCES/EAGAIN/EWOULDBLOCK = 已被持有，其它 errno 一律
如实上抛（环境故障不得伪装成端口忙）。**持有期为该次核验会话全程**：从首条用例命令起
（含 EADDRINUSE 假红后的整轮重跑）到最后一条用例命令返回（含其进程内 teardown 探针
完成）止；进程退出即释放，不留 stale。取不到租约：视同该端口被占用，按 ⑤ 有界等待或
换宿主处置、按假红计一次（同受 2 次上限），不得绕过租约继续。

交错覆盖面（issue #2344 交错 A / B / C 的评估，如实登记）：

- **A（同宿主另一会话跑全量 lib 套件先占端口）**：租约只约束**同样取租约**的一方；
  全量 lib 套件与 wecom 负控矩阵当前不取租约（不归本条目管辖），对它们的兜底仍是
  机检字样 + ④ lsof + ⑤ 等待/记账。租约当下买到的是「两次都按本 R1 执行的核验之间」
  的互斥，并作为后续套件采纳的锚点（列入待落地跟进）。
- **B（teardown 竞态：`listener.stop()` 已释放、teardown 探针重绑前，外部用例绑上
  同端口并持有）**：合作方在整个核验窗口（含探针期）进不来，B 对合作方关闭；不合作方
  直接 bind、不查租约，仍可达。`listener teardown` panic 不在豁免内、一律按取数
  判据判不过的判定**保留**（fail-closed：那正是用例要钉的行为，不得因端口疑点洗成
  假红）；本 R1 只补一条留档：该时点立即跑一次 lsof（按 ④ 读法）快照入档，供人工
  回滚决策看到「端口被外部占用」的证据——不改变判分。
- **C（两棵树的 wecom 负控矩阵同宿主并行互撞）**：矩阵脚本不在本 R1 管辖（其
  `.negative-source.lock` 按树隔离、不跨树）；矩阵侧采纳租约属后续单。

② **三条字面串锚点存在性自检**。判读任何一轮输出**之前**，先在该 worktree 上做三条
字面串的锚点存在性自检：`#1336 stalled listen`；`Error: listen EADDRINUSE: address
already in use 0.0.0.0:18990` / `…18991` 的拼出机制（`ListenError::from_bind` 的
`EADDRINUSE: address already in use` 分支与 `Error: listen {described} 0.0.0.0:{port}`
格式）；`listener teardown`。任一缺失 = 代码已漂移、机检字样不可信，**本轮作废**
（不得进入判读、不得按通过或失败记账），留档缺失项后按作废转人工口径处理。落地方向：
复用 / 扩展 `tests/fixtures/wecom-callback/negative_controls.py --check` 的锚点自检
机制；按内容匹配、不按行号（行号漂移正是本条要防的）。今日该 `--check` 只覆盖变异行
锚点、不含这三条——**规约要求、装置待落地**。

③ **删可杀路径，只留等待换宿主**。统一规约中「占用者仅当能证明是本核验自己派生并
登记过 pid 的残留进程……（用例启动时把子进程 pid 写入该轮留档；处置前
`ps -o pid,lstart,command -p <pid>` 核对命令行与启动时间吻合）才可按 pid 停掉」整段
作废。占用处置只剩两条：**等待其释放（受 ⑤ 上限）或换宿主**；不得按 pid 停掉任何
进程。依据：两条用例不派生子进程、绑定在测试二进制自身进程内（「Rust 行为」段实核），
可杀前提不存在；pid 归属核对附带的 lstart 时区比对、ps 与 kill 之间的 pid 复用窗口、
kill 退出码与释放确认（r22 #3 / #5、r22b 第二条）随可杀路径一并消解。执行者对**仍在
跑**的本会话调用（自己起的 cargo 进程树）的处置属会话内运行管理，不属本规约的端口
处置路径；调用退出后残留的任何占用者一律按上述两条处置（fail-closed：宁可烧 2 次
上限转人工，不冒误杀他方进程的不可逆风险）。

④ **lsof 退出码映射**。判前 lsof（命令不变：`lsof -nP -iTCP:18990 -iTCP:18991
-sTCP:LISTEN`）的读法改为**只认已列出的匹配行**：非 0 退出码但已列出匹配行 → 按已列
输出判（本机实测：该命令形态下单端口被监听时退出码即 1 且已列 2 行，退出码不区分
「无匹配」与「有匹配」）；0 匹配行（无论退出码）→ 记一行「lsof 无匹配/工具错误不明」
并按 EADDRINUSE 假红计一次（同受 2 次上限）。原「1 = 无匹配；>1 = 工具错误，转人工」
作废：本机 lsof 只观察到 0 / 1 两态、「>1」是死分支，且工具错误与无匹配无法靠退出码
区分——统一按假红计，fail-closed。

⑤ **等待上限与记账**。「等待其释放」= 有界等待：最多 60 s、每 2 s 轮询一次 lsof，
占用消失即继续；超时按 EADDRINUSE 假红计一次（同受 2 次上限）。起止 UTC 时刻与起、
止两次 lsof 快照（原始输出与退出码）留档。

⑥ **留档枚举与引用同步**。第 3 项 ⑥ 的每轮留档枚举补：每轮 lsof 原始输出与退出码
（预检 + 占用处置 / 等待路径上的每次快照）、⑤ 的等待起止与快照；B 路径上的
`listener teardown` 时点快照（① 交错 B）。r22 #3 的「登记 pid」留档项随 ③ 删除可杀
路径而不复存在（无 pid 登记义务）；第 3 项 ②④ 对统一规约的引用所指为本 R1 更正后
版本（①–⑥）。
