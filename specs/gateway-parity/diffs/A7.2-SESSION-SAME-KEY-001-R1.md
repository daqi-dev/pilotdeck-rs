## 类别

机器判据更正；有意差异「同 key 创建串行复用」仍未批准。原条目把 `same-key-concurrent` 负控作为整个串行复用行为的证据，但该变异仅将新记录 `dirty: false` 改为 `true`，不能单独证明排队或缓存返回路径受保护。

## 基线依据

固定 cc7c4e6、Node v22.22.0；`session-factory/probe.mts` 重新实跑 `same-key-concurrent` 与 `same-key-cached`，归一结果逐字段等于原 `oracle.json`。并发首次创建仍为两次准备、后一次 publication 拒绝；已发布缓存仍返回相同 handle。原始证据：`_tmp/20261026-issue-745/fix-r4/ts-probe/raw/`，比较输出 `ts-comparison.log`。

## Rust 行为

沿用 SessionOwner 的 per-key ticket 排队与缓存返回：同 key 第二次调用复用已发布 handle，只构建一次。此次不改产品排队与缓存逻辑，只更正负控证据。新变异直接使 `create_active` 的缓存返回条件为 false，强制再创建；不再以 dirty 标记变异代称缓存跳过。

## 范围

同 owner、同 key 的首次并发创建与随后缓存命中。新变异验证缓存返回对两种调用时序的作用，不独立证明 ticket 等待本身；dirty 变异继续保留为新记录缓存有效性检查。重建并发仍见 RECREATE-DRAIN 条目。

## 机器判据

完整测试前缀 `runtime::session::factory::tests::`，夹具目录 `src/pilotdeck-gateway/tests/fixtures/session-factory/`：

- `same_key_concurrent` ↔ `negative_controls.py` 的 `same-key-concurrent-skip-cache`，专属失败消息 `#745 same-key-concurrent conclusion`。
- `same_key_cached` ↔ `same-key-cached-skip-cache`，专属失败消息 `#745 same-key-cached conclusion`。
- 原 `same-key-concurrent` / `same-key-cached` 仅称 dirty 缓存负控，不再作为本条主要负控。

复算：提交后设置 README 中的 target/baseline，执行 `negative_controls.py OUT same-key-concurrent-skip-cache same-key-cached-skip-cache`；每项正控→变异编译→被点名用例失败→还原复跑，二者均须 KILLED。本机已实跑 concurrent 样本；其余宿主结果由协调者补齐，不以静态审计替代判杀。
