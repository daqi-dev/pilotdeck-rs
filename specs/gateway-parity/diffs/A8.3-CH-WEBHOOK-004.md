## 类别

传输层呈现差异（待批）：webhook 通道自己的监听器（`WebhookChannel` 的
`node:http` server，Rust 侧 `src/pilotdeck-gateway/src/channel/webhook/mod.rs`
的 hyper 1.7.0 `http1::Builder` 连接）对 **HTTP/1.0** 请求回显
`HTTP/1.0` 状态行，而 Node v22.22.0 恒回显 `HTTP/1.1`。这是
A8.4-NATIVE-HTTP-001 第 4 项的同一 hyper 行为，但那份登记的「范围」明确
只覆盖 opt-in `NativeWsServer` 的非升级分支、不含各组件车道；webhook 车道
的 1.0 一格此前没有登记，本 PR (#1684) 补上后按既有惯例单列一条。

本通道的其余 1.0 语义（`Connection: close`、无 framing 的 close 定界体、
发完即关）Rust 与 Node 逐字节一致，不在本条豁免范围内，由钉死测试逐项
比对。

## 基线依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0 /
ICU 78.2。TS 侧 `src/adapters/channel/webhook/WebhookChannel.ts` 用真实
`node:http` 监听（`/health` 走 `sendJson`，`:122-124`），没有对 1.0 做
任何处理器级分支：版本处理全部在 `_http_server.js` 里。

实测（探针 `_tmp/20261106-issue-1696-1684/probe-http10.mts`，原始输出
`probe-http10.out`，基线提交 / 源闭包 SHA-256 与 node / icu 都在输出头部）：

```
health-1.0-plain        HTTP/1.1 200 OK   Content-Type / Date / Connection: close   closed=true
health-1.0-keepalive    HTTP/1.1 200 OK   Content-Type / Date / Connection: close   closed=true
                        （请求带 Connection: keep-alive，Node 仍回 close 且关闭）
404-1.0-keepalive       HTTP/1.1 404 Not Found   Date / Connection: close           closed=true
webhook-1.0-keepalive   HTTP/1.1 200 OK   Content-Type / Date / Connection: close   closed=true
health-1.1-keepalive    （对照）Connection: keep-alive + Keep-Alive: timeout=5 + Content-Length: 36，
                        同一 socket 第二请求有应答
```

金样 cell `webhook-channel/oracle.json` 的 `http10` 一格即
`GET /health HTTP/1.0` + `Connection: keep-alive`，录制到的响应为
`HTTP/1.1 200 OK` / `content-type` / `date` / `connection: close`、
body `{"status":"ok","platform":"webhook"}`、无 `content-length`，
由 `generate.mts` 在基线上实跑生成（#1684 实施，重生成守卫通过；生成器
stdout 打印 `#1334 webhook-channel: 20 cases`，落盘为 `oracle.json` 的
`expectedCaseCount: 20`）。

## Rust 行为

`src/pilotdeck-gateway/src/channel/webhook/mod.rs` 的 `handle_request` 记下
请求版本，路由后过 `finalize`：请求是 HTTP/1.0 时把响应版本置
`hyper::Version::HTTP_10`，hyper 1.7.0 的 `proto/h1/conn.rs` 因此写
`HTTP/1.0` 状态行（`enforce_version` 对 1.0 请求无条件改写，公开 API 无
扩展点）。同一分支把响应体包成未知长度（`Unsized`），让 1.0 连接按
close 定界写体，不补 `content-length`——与 Node 的线上字节一致。

实测（钉死测试 `channel::webhook::tests::http10_request_closes_the_connection`，
逐 socket 读取直到 EOF 或 10 s 截止）：

```
HTTP/1.0 200 OK
Content-Type: application/json
Date: <masked>
Connection: close

{"status":"ok","platform":"webhook"}
（closed=true）
```

即除状态行外，头集合、framing 与体字节都与 Node 录制一致。

## 机器判据

`src/pilotdeck-gateway/src/channel/webhook/tests.rs`：

- `http10_request_closes_the_connection`：从 oracle 的 `http10` 案取请求字节与
  options 起真实通道，断言状态行为 hyper 的 `HTTP/1.0 200 OK`（本条豁免项）、
  连接在响应后关闭（`closed=true`），并把归一化后的头集合与 body 与录制值
  逐字节比对（`content-length` 缺失、`connection: close`、体字节）；
- `replay_cases_cover_exactly_the_oracle`：回放列表 + 钉死列表与 oracle 的
  20 案集合相等（新增或漏案即红）；
- ignored `webhook_channel_regenerates_identically` 在固定基线上重生成完整金样；
- `negative_controls.py` 的 `webhook-http10-finalize-off`（去掉 1.0 版本钉，
  连接不再关闭）与 `webhook-http10-framing-off`（保留已知长度体，1.0 响应
  多出 `content-length`）各自绑定上述断言，正控 / 变异 / 复原三态实测
  KILLED（原始日志 `_tmp/20261106-issue-1696-1684/negctl/webhook-r1/`）。
