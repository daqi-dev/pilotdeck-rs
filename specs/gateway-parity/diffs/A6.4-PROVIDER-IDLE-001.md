## 类别

不可避免的当前实现时机差异（#411）：undici fast timer 的进程内相位和调度历史未被 Rust 的单次 read_frame 时长参数携带。记录观察范围，不批准错误文案豁免，不改变冻结评分语义。

## 基线依据

固定 cc7c4e6，`src/model/streaming/streamModel.ts` 的 `withIdleTimeout` 使用 Node 原生 setTimeout，`src/cli/proxy.ts` 安装 undici bodyTimeout=600000。Node v22.22.0 + undici 8.3.0 的真实 TCP 探针复用 #396 原件，可移植入口为 `src/pilotdeck-gateway/tests/fixtures/provider-http-boundaries/probe.mts` / `measure.mjs`。

本次 `_tmp/20261026-issue-411/tcp-summary.json`（逐条原始 `tcp-gap-*-run-*.jsonl`）：body=5000、idle=body+{0,100,300,500,700,900,1100}ms，各 3 次；前三组全部 idle，后四组全部 body。实际 body 约 5496–5510ms。`timer-ticks.jsonl` 调用已安装 undici 的真实 timer 实现并控制 tick：调度间隔 499ms，5000ms 在第11 tick（fastNow=5489）回调。样本分布不能外推成全局胜负保证。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/model/http.rs::read_frame` 继续用严格 `<` 判 body 比剩余 idle 短；相等由 idle 赢。idle 比 body 仅多 100/300ms 时，Rust 会选 body（TypeError/terminated），本次 TS 样本选 idle（Stream idle timeout）。不加入固定 499/1000ms 补偿，因为它无法表达共享 timer 池相位与实际事件循环延迟。

## 范围

Provider 流无后续 body 字节、自定义 stream idle 与 body timeout 近平局的窗口，默认配置数值相等不进入这一自定义窗口。稳定对拍输入选 idle=body 或 idle≥body+1000ms；这是本 fixture 的输入约束，非生产调度保证。对拍中的等时格通过测试接口重置已销毁 dispatcher 的 fast-timer 状态，冷时钟与热池观察分开记录。

## 机器判据

`src/pilotdeck-gateway/tests/provider_http_boundaries.rs::timer_contract_matches_node_outside_near_tie` 用真实 TCP 回放等时/1100ms间隔，逐字校验 TS 错误消息；`zero_idle_fallback_and_cancel_match_node` 覆盖无限 body 的 idle/父取消终止。`fixtures/provider-http-boundaries/generate.mts` 生成稳定金样，ignored `provider_http_boundaries_regenerate_identically` 逐字重生成；`negative_controls.py` 的 tie-body-first / shorter-body-ignored 绑定本单消息。完整命令、原始证据与未完成负控项见该 fixture README 和 `_tmp/20261026-issue-411/RESULT.md`。
