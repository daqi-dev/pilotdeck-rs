## 类别

headers 后父取消生命周期（行为缺陷候选）。原条目结论不变；R1 只记录 #752 第一包
（ERROR-CLASS）带来的 Rust `name` 快照变化，并把叠加原因写明。不把本类差异视为
已修复，也不增加判分豁免。

## 基线依据

同原条目：固定基线 OpenBMB/PilotDeck@cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，
Node v22.22.0；`src/tool/builtin/web/urlFetcher.ts:167-169` 与
`src/network/fetch.ts:94-96`。TS 金样仍为
`src/pilotdeck-gateway/tests/fixtures/network-timing/oracle.json`。

## Rust 行为

`runtime/tools/builtin/web/network.rs::read_body_inner` 继续与父取消竞争，未改。
`runtime/tools/builtin/web/fetcher.rs` 的 `FetchError::Other` 现在保留 TS
`Error.name`；因此本类 5 格的 Rust `name` 从 `null` 变为 `NetworkFetchError`
（Rust 侧实际抛出的是 `network_error()` / `abort_error()`）：

- `web_fetch/body/fulfilled/parent-first`
- `web_fetch/body/fulfilled/tie-parent-first`
- `web_fetch/body/rejected/parent-first`
- `web_fetch/body/rejected/tie-parent-first`
- `web_fetch/body/idle/parent-first`

`known_differences.json` 的 `rust` 快照已同步。原条目逐格表的 `name=null` 行是
登记时快照，以本 R1 与 json 为准。未来若对齐 headers 后取消语义，这些格应按 TS
转为成功或 `TypeError: terminated`，而不是保留 `NetworkFetchError`。

## 范围

5 格不变，仍全部 ignore；差异原因是 headers 后父取消生命周期，而不是 `name`。
本 R1 只覆盖上述 5 格的 `name` 字段；`message`/`delivery`/`content`/`calls`/`retries`
仍按原条目保留差异。pr2a 的 POST-HEADERS-PARENT-002（6 格 background）与 pr2b 的
-003（4 格 mcp/hooks）未被 #752 改动，不在本 R1 范围。

## 机器判据

`tests/network_timing.rs` 的 `known_differences_remain_exact_and_ignored` 逐格重放
`known_differences.json` 的 Rust 当前值；本类 5 格仍严格断言 TS 原值且保持 ignore，
显式 `--ignored` 时仍在完整 observable 断言处失败。默认运行
`171 passed; 0 failed; 22 ignored`。#752 的错误类型修复与负控见
`A6.4-NETWORK-TIMING-ERROR-CLASS-001-R1.md`；复算：

```sh
CARGO_TARGET_DIR="$PWD/_build/cargo-target" cargo test --offline \
  --manifest-path src/Cargo.toml -p pilotdeck-gateway --test network_timing -- --test-threads=1
```
