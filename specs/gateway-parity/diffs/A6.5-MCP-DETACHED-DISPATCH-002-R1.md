## 类别

fix-r3 评审修复（#1114），并更正 -002 登记的「GET 字节级落线残余差异」。
评审 P1 两项：(1) 进程级 panic hook 观测改为 spawn 余段的 `JoinHandle`
（`JoinError::is_panic`），hook 及其恢复锁序、并发生成死锁类一并消失；
(2) GET 交换判据闭合到请求行（区分零字节 / 部分行 / 完整行）。判据修正
后以形状对齐的 TS 探针 C 复测：-002 的残余差异登记不成立——其证据是形状
错配的（探针 B 的 mock 202 保活 = 池化形态；Rust 测试刻意 `Connection:
close` = 新连接形态）。形状对齐后：池化形态 TS 50/50 落线（Rust 同样
落线），新连接形态 TS 50/50 零字节（Rust 同样零字节）——两侧派发与字节
交付一致。残余差异更正为一条更窄的记录：新连接形态下 abort 拆除与内核
完成 TCP 握手的先后（TS 总是先完成握手再拆；Rust 是亚毫秒内核竞态，测试
以同步屏障消除），GET 派发本身（connect 先于 close 发起）两侧一致。

## 基线依据

固定基线 `/Users/da/ws/pilotdeck-rs/resources/PilotDeck`（Node v22.22.0、
SDK 1.29.0），真实 `McpClient` + 原始 TCP 服务器，单进程时钟。探针 C
（`_tmp/20261026-issue-1114/fix-r3/probe/probe_get_close_fresh.mjs`，50 轮 ×
pooled / fresh / fresh-inflight 三模式，原始输出 `probe_get_close_fresh.out`）：

- pooled（所有 POST 响应不带 `Connection: close`，GET 复用池化 socket）：
  lineOk=50/50，EOF 晚于 close() 返回 0.2–2.7ms——undici 对空闲池化 socket
  同步写入，close 不吞请求行（与 -002 引用的探针 B 一致，形状本就相同）。
- fresh（initialize 200 与 202 均带 `Connection: close`，GET 必须自开连接）：
  lineOk=0/50，GET 连接被 accept 但交付 0 字节（connections 形如
  `["POST","0bytes(0)"]`）——abort 落在 connect 在途时同样撤回请求。
- fresh-inflight（同 fresh，close 前 100ms）：lineOk=50/50（窗口 B 对照）。

## Rust 行为

产品源码非测试路径零变更（`detach` 的 `#[cfg(not(test))]` 分支与 fix-r1
逐字节相同）；全部改动为测试侧（`http.rs` 的 cfg(test) 段与
`http_encoding_tests.rs`）：

- panic 观测（`http.rs` cfg(test)）：`detach` 在 spawn 余段时把
  `JoinHandle<()>` 存入 thread-local `DETACHED_TASKS`，包装任务以
  `let _ = continuation.await;` 抹平输出类型；首询 Ready 的余段二次 poll
  在任务内 panic，由被等待的 handle 以 `JoinError::is_panic` 呈现。进程级
  `PanicRecorder`、其互斥锁、恢复锁序与并发生成回归测试全部删除——死锁
  类不存在，无需再护。
- 请求行判据（`http_encoding_tests.rs`）：`read_request_line` 只读到首个
  CRLF，`Delivered::{Eof, Partial, Line}` 区分零字节 / 部分行 / 完整行并
  保留原始字节。`dispatch_get_connects_before_close`（新连接形态）断言
  交付为零字节——与探针 C fresh 模式一致；其服务端 accept 观测依赖内核
  完成 TCP 握手先于客户端拆除，实测（探针 D，2000 轮 × 两模式）立即拆除
  仅 1.0–5.9% 握手完成（随机器负载浮动）、拆除前 ≥200µs 后 1999–2000/
  2000，测试在 send 与 close 之间以
  同步 `std::thread::sleep(200ms)` 为屏障：不让出 runtime（spawn 余段仍
  未被 poll，close 仍严格先于它），只给内核留出握手时间。
- 池化形态（新用例 `dispatch_get_line_lands_before_close`，
  `pooled_line_server` 每 POST 应保活 202）：断言 GET 请求行落线——这是
  原始 CI 偶发（mcp_proxy 的 mock 服务器保活连接）的形态，也是 TS 保证
  落线的形态（探针 C pooled 50/50）。

## 范围

更正 -002 的残余差异登记：字节级落线差异不成立（两形态两侧均一致），
更正后的残余仅为新连接形态下握手完成与拆除先后的亚毫秒竞态，不改变
「GET 于 close 前已派发」的交换语义。`dispatch` 的 abort 门、
`DETACHED_DISPATCHES` 计数、wire.rs 与产品行为（非测试编译）均未改动。
stdio 队列语义、窗口 B（在途 abort 后的落线，探针 C fresh-inflight
50/50）不变。本条目只覆盖 fix-r3 的评审修复与判据闭合；机器判据为
7 用例 / 6 变异（hook 变异随其观测机制删除，新增 dispatch-abort-never-wins
保护零字节判据）。
