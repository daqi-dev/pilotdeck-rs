## 基线依据

固定基线 `OpenBMB/PilotDeck@cc7c4e6`：`src/agent/modules/transport/agentLoopSidecarClient.ts:662` 使用 `if (message.final)`，普通事件分支在第 680 行才进入 `readAgentEvent`。Node 探针从已核对 Git blob 的原文件 AST 提取这个唯一谓词，以及原 `readAgentEvent`/`asRecord`，实跑 14 组真值/假值，原始输出见 `_tmp/20261025-issue-589-combined-fix-r3/ts-final-probe.log`，可复现脚本为同目录 `ts-final-probe.cjs`。

边界限制：同一客户端第 566 行已先做 `validateModuleMessage`，`src/agent/modules/protocol.ts:334` 要求 final 为 boolean。探针同时执行真实 wire 校验，证实非布尔 final 被拒绝。因此本记录只断言嵌入回调采用 TS 分流谓词的真值语义，**不声称 TS 完整 wire 执行接受字符串/数字 final**。`readAgentEvent` 对 null payload 的真实错误仍是 `Sidecar event payload is not an AgentEvent.`；fix-r2 的非 final payload 收紧及其未批准状态不变。

## Rust 行为

`runtime/turn/live.rs::StreamHandler::event` 对嵌入回调使用现有 JS 真值函数：`"true"`、`1`、对象、数组等进入 final 分支，由 inner handler 应用且不作为普通 AgentEvent 转发；false、0、NaN、空字符串、null、undefined 保持普通 payload 校验。协议解码和 execute response 的严格布尔检查不变。

`HostHandler::validate_event` 返回随队列项持有的 `EventGuard`。校验成功后队列限流、执行返回、future 被丢弃、未 poll 回调取消等路径都会释放自己的预留槽；正常应用把槽移交到转发 future，继续由 done sender 的 Drop 唤醒后继。inner handler 的 guard 同样保留到应用结束。

评审原文中的“取消后普通事件 aborted=true”并不可达：`host/execution.rs::validate_event` 对非 final 始终返回 false，只有不完整 compaction final 才返回 true，而 final 不调用生命周期预留。此次确定性复现的是普通事件通过校验后 **整个执行 future 被 abort/drop** 的真实弃队路径，不扩大为任意单条中间事件跳过后仍维持全链顺序的承诺。

`runtime/cleanup_task.rs` 共用完成守卫支持保留原错误类型；ProjectRuntime、provider retirement、plugin refresh/dispose 同步接入。被 runtime 丢弃的任务返回稳定可观察错误，不伪报资源已清理成功；ProjectRuntime 未执行清理时仍是 Retired。

## 机器判据

- `live_stream_tests.rs::aborted_execution_releases_validated_wire_reservations`：实际 HostClient 读取并校验三条排队事件，模块交付先被预留阻塞，drop run 后模块、后续 wire 与 final 进展且预留队列为空；删掉释放的负控必须超时。
- `discarded_event_guards_release_only_their_own_reservation`：不删除其他队列项，未 poll 的应用回调也释放移交的槽。
- `embedded_final_uses_js_truthiness`：真值 final 的缺失/null/原始值/对象 payload，以及假值 final 的拒绝和对象转发；严格 true 与“字段存在即 final”两种变异均转红。
