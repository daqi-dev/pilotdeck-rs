## 类别

## Rust 行为

字段改名 `FactoryOptions.writer_busy_wait_timeout`，全仓调用点同步，#589 接线使用新名。它限制前驱 drain 与忙的进程锁等待，不是 factory.create 的墙钟总截止。prepare、storage construction、canonicalization、单次 LedgerLock 文件打开/锁尝试排除在可取消等待之外；路径解析耗时仍扣掉进程锁可等待时间。已耗尽时只允许一次非阻塞尝试：空闲成功、忙立即 SESSION_WRITER_BUSY。

未过期的申请直接调用 Tokio `lock_owned`，使用 FIFO 队列；过期才 `try_lock_owned`。原报告声称 try 必然绕 FIFO 属读码推断，本轮未证明原版饥饿；Tokio 的 try 与等待共用 semaphore，因此不把该推断写成已复现缺陷。

## 基线依据

Rust 专有，TS 无 fence，沿既有 writer-fence 决策卡。既有真实 TS writer 交错与 48 格已由 `session-factory/generate.mts` 在 Node v22.22.0 / cc7c4e6 重采，`_tmp/20261026-issue-1022/ts-generation.log`。

## 范围

前驱 drain 与进程 writer 锁的等待；慢文件系统操作不承诺墙钟总截止。跨进程排他仍由既有 LedgerLock 执行。

## 机器判据

`runtime::session::factory::tests::writer_waiters_are_fifo_and_cancellation_safe` 显式 poll A/B/C 竞争、排队取消、永不释放到期；`writer_busy_budget_excludes_path_resolution` 以可控 resolver + 虚拟时钟验证慢路径排除、到期空闲与忙两格。既有 exhausted-budget / external-ledger / alias / timeout 测试继续覆盖实际锁。

负控：`writer-unexpired-try-only`、`writer-wait-never-times-out`、`writer-resolution-charged-as-total`、`writer-expired-budget-skips-try`。源码须等于 HEAD；编译和判杀由提交后的协调者补齐，不把 audit 当判杀。
