## 类别

更正（原条目第 5 项 keep-alive 空闲超时「未收敛」已由 #1250 收敛，且
矩阵化探针补齐三点语义登记）：原条目登记 Rust 恰 5 s 关闭、Node 实测
~6 s 的 ~1 s 差异。#1250 以真实 `GatewayServer` 探针（Node v22.22.0，
`_tmp/20261026-issue-1250/probes/`：S1–S5 状态 × E1–E5 事件矩阵）钉死
Node 的空闲计时语义后按实测复刻，三处偏离全部收敛：

1. **有效超时 6 s**：`keepAliveTimeout` 5000 + 固定 `keepAliveTimeoutBuffer`
   1000（hook 内直读真实 server 实例；S5：应答后 quiet+5749 ms 关闭，
   末段 dribble +6006 ms，S3：TIMEOUT 事件恰 +6000 ms）。响应头仍广告
   `Keep-Alive: timeout=5`（裸值，原第 4 项不变）。
2. **装定点是响应 finish，不是 handler 返回**：handler 挂 8 s 不关（S3）；
   响应头 + 一帧在途、8 s 无写不关（S4a）；`socket TIMEOUT` 事件只在
   finish 后 6 s 出现。在途状态（含流式响应体）保持到体完成。
3. **读分段刷新 deadline**：响应完成后有效请求头分段逐段刷新（dribble
   实测每段 +6 s 重臂；半到头活过原 deadline；无效方法前缀 `x` 被 llhttp
   立即裸 400 关闭，与 keep-alive 计时无关）。

另登记一处**范围外未收敛**新差异（探针 `node-headers-timeout.out`）：
首请求头不完整时 Node 的 `headersTimeout`（60 s）写 51 字节
`HTTP/1.1 408 Request Timeout\r\nConnection: close\r\n\r\n` 并关闭；原生
监听器无 headersTimeout，半头连接无限等待。该差异属解析层时序，归
A8.4-NATIVE-HTTP-002 一族处理，本条仅登记不复刻。

## Rust 行为

`src/pilotdeck-gateway/src/http_proxy.rs`（native 路径；
`serve_connection_with` 代理路径 stop=None 依旧无空闲关闭，字节不变）：

- `NODE_KEEP_ALIVE_TIMEOUT` 5 s 保持裸值（广告头仍由 `native_http.rs`
  `Keep-Alive: timeout=5` 供给，未改），新增
  `NODE_KEEP_ALIVE_TIMEOUT_BUFFER` 1 s：空闲 deadline = 最后活动
  + 6 s。
- 在途持有改为响应体完成：service 闭包把 `InFlightRequest` guard 与
  activity 发送端挂进 `IdleBody` 包装（poll_frame 见端即释放并刷
  activity，Drop 兜底），handler 出错路径立即释放；`size_hint` 委托内体
  （裸 400/431 的 exact-0 帧型不变，依赖 Cargo 新增直依赖
  `http-body = "=1.1.0"`，版本与锁内既有值一致）。停机路径
  `idle_now`（in_flight==0）因此涵盖体传输中——与 TS 停机不抢在途体的
  行为一致，原条目登记不变。
- 读分段刷新：`UpgradeReadGate::poll_read` 成功读到字节即发布 activity
  （读即 Node socket activity）；写活动不必单独 hook：体传输期计时本来
  不在岗，装定点是体完成。
- 解析层（`native_http.rs` 路由、头预算、方法表）与默认代理路径零改动。
