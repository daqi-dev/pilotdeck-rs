## 类别

不可避免（传输层缺失，非判分口径改动）。feishu 车道只移植了
`connectionMode: "webhook"` 的入站路径：Lark 官方 `@larksuiteoapi/node-sdk`
的 `WSClient`（长连接订阅）没有 Rust 等价实现，`app_id`/`app_secret`
齐全且 `connectionMode` 为默认 `"stream"` 时，Rust 侧只打 TS 的
「stream 启动失败、回落 webhook-only」告警，不建立任何 WS 订阅。

## 基线依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0。
`src/adapters/channel/feishu/FeishuChannel.ts:183`
`this.connectionMode = options.connectionMode ?? "stream"`；
`:212-262` stream 分支创建 `new sdk.WSClient({...})` 并注册
`im.message.receive_v1` 处理器，注册失败才走 `:213-218` 的回落告警；
`:242` 同一告警文案。TS 默认配置（不写 `connectionMode`）即走 WS，
webhook 路由交给 `GatewayServer` 的 `/feishu/webhook`（`:436-460`
`handleWebhook`），两条入站互不排斥。

## Rust 行为

`src/pilotdeck-gateway/src/channel/feishu/mod.rs:383-390`：`connection_mode
== "stream"` 时只 `log("warn", "feishu: stream mode failed to start; falling
back to webhook-only …")`，不构造 WS 客户端、不订阅事件；`:391-399` 的
webhook 分支才是真正就绪的分支。`FeishuOptions::connection_mode`
（`mod.rs:72-73`、`:117-118`）保留该字段只为复刻这条告警与配置解析，
不驱动任何传输。因此默认配置下 Lark 控制台推送的「长连接」事件永远
收不到，只有把回调地址指到 `/feishu/webhook` 才有入站。

## 范围

仅 feishu 入站传输：Lark WS 长连接订阅缺失，以及由此产生的默认配置
行为差异（TS 默认 stream 可用 → Rust 默认 stream 不可用、必须显式
`connectionMode: webhook`）。不覆盖出站（Lark HTTP API 走
`client.rs`，两种模式共用，已对齐）、不改 webhook 路由语义、不改金样
矩阵（`tests/fixtures/channel-feishu/` 的金样一律以 `connectionMode:
"webhook"` 构造，见该目录 README）。本条不构成判分豁免。

## 机器判据

- `src/pilotdeck-gateway/src/channel/feishu/tests.rs` 的重放用例以
  webhook 模式构造通道并逐格比对 `/feishu/webhook` 的状态码与正文，
  钉死已移植分支。
- 无 WS 分支判据：没有 Rust 实现可测，负控也不能覆盖。补齐 WS 传输
  时必须新增订阅/重连/去重用例，并把本条目改为「已对齐」或新增更正
  条目。
