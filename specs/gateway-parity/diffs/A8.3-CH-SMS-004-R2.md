## 类别

更正（判据登记措辞，非差异变化）：`A8.3-CH-SMS-004-R1`「机器判据」节
两条与实现不符。

1. 「其余记录字段逐字节比较」——重放比较的是解析后的 JSON 快照
   （两侧均为 `serde_json::Value`），对象键序与序列化空白不参与，只有
   字段值参与。
2. 「记录的 `expected` 不参与比较」——`port-busy-preflight` 的
   `expected` 在正常轮确实不比，但 `sms-port-preflight` 负控轮里
   `replay_named("port-busy-preflight")` 的 `connect` 步会把
   `expected.responses` 当前缀比较，它正是该负控的落点。

`-R1` 原字节不动，本条按实测更正（#1339 fix-r3 评审 Codex P2 #3、
minimax concurrency #2 / boundary #7，等级取高 P2）。

## 机器判据

`src/pilotdeck-gateway/src/channel/sms/tests.rs`：55 个 oracle 用例中
54 个有 `replay_cases!` 重放 cell，在注入 mock `SmsGateway` 下回放，
并与 `oracle.json` 的 `expected` 做解析后 JSON 值比较
（`negative_assert_eq!` 作用于 `serde_json::Value`，键序与空白不参与）。
`expected.rpcs` 同样按解析后的值比较。第 55 个 `port-busy-preflight`
无重放 cell，其 `expected.responses` 只在 `sms-port-preflight` 负控轮经
`connect` 步的前缀断言比较（期望 `{"refused":true}`）；
`every_oracle_case_has_a_replay_cell` 机检用例名集合，`REPLAY_CELL_NAMES`
由 `replay_cases!` 宏发射，与 cell 定义同源。
