## 类别

有意改进（向安全偏离）。TS `ProjectFileService` 的写路径只做词法边界检查（`resolveSafeWriting` 没有任何 `realpathSync`），根内预置的目录符号链接会把写入带到工作区之外；读路径是 `realpathSync` 校验 → `statSync` → 按路径 `readFileSync` 的三段序列，校验与读取之间被换入的链接会被跟随，读到根外内容。Rust 侧在 realpath 闸门放行后改走 A4-FILE-TOCTOU-001 的 `NOFOLLOW` 描述符走查：读按句柄读、写按根句柄逐级 `mkdirat` + `overwrite_at`、目录枚举按句柄 `getdents` + 相对 `statat`，任何在校验后被换入的链接都 fail-closed 为 403 `workspace_boundary`；写叶节点另按 A6.6-EDGECLAW-WRITE-INODE-001 复核 inode（非普通文件或 `st_nlink != 1` 拒绝）。根内**既有的**普通链接仍被 `realpathSync` 先行解析，因此金样 `files-read-symlink`（`inside-link -> aaa.txt`）字节不变。

## 基线依据

cc7c4e6 的 `src/adapters/web/projectFiles.ts`（Node v22.22.0）：

- `:194` `writeFile`：`resolveSafeWriting` → `mkdir(dirname, {recursive:true})` → `writeFile`。
- `:238` `resolveSafeWriting`：只做 `isAbsolute` / `normalize` 前缀 `..` / `resolve` / `isInsideRoot` 四步词法检查，**不调用 `realpathSync`**（对比 `:209` `resolveSafe` 在 `:221` 用 `realpathSync` 解析已存在的目标）。
- `:153` `readFile`：`resolveSafe`（`:155` `statSync` 跟随链接）→ `:173` / `:183` `readFileSync(path)` 按路径重新打开。
- `:114` `readTree`：`stat` → `:120` `readdir(withFileTypes)`，随后逐项 `stat`（跟随链接，只取 `size`/`modifiedAt`）。

三种逃逸形态在 TS 侧均为确定性成功：根内目录链接 `out-link -> ../outside` 上写 `out-link/escaped.txt` 落到根外；读竞态窗口内把叶节点换成指向根外的链接后读到根外内容；目录枚举同理。`..` 与绝对路径两种形态 TS 与 Rust 都已在词法闸门拒绝（`WorkspaceBoundaryError` → 403），不属本条偏离。

## Rust 行为

`src/pilotdeck-gateway/src/api_web/files.rs`（描述符路径均 `#[cfg(unix)]`，非 Unix 保留原按路径形态）：

- 开关：`ProjectFileService::nofollow`（`:50`，`:63`）= `!mutants::on("api-web-nofollow-off")`，`armed()`（`:388`）= Unix 且开关未关；`beneath`（`:374`）在闸门放行且 `strip_prefix(root)` 成功时才给出根内相对路径，否则回落到按路径形态（`api-web-boundary-off` 负控因此仍在旧形态上被 `files-tree-escape` 杀死）。
- 写定位 `resolve_safe_writing`（`:435`）：词法闸门之后用 `canonical_prefix`（`:488`）解析**最深的已存在祖先**并把尚未创建的尾部接回，再做根内判定。因此根内既有链接仍按 TS 语义写穿（金样外由两条 counter-probe 钉住），落点越界的链接在写之前就 403；开关关闭时该方法退化为纯词法，负控可复现原逃逸。
- 读 `read_bytes`（`:306`）→ `read_beneath`：`project_files::open_beneath(root, canonical)` 自 `/` 逐级 `NOFOLLOW` 打开（叶 `O_RDONLY|O_CLOEXEC|O_NOFOLLOW|O_NONBLOCK`），再从句柄 `read_to_end`。
- 写 `write_bytes`（`:330`）→ `write_beneath`（`:346`）：根句柄 + `create_directories_at`（逐级 `openat`/`mkdirat`，`NOFOLLOW`）+ `overwrite_at`（打开后 `fstat`，`FileType != RegularFile || st_nlink != 1` → `EACCES`，随后 `set_len(0)` 再写）。
- 枚举 `tree_rows`（`:219`）→ `rows_beneath`（`:257`）：`open_beneath` 拿目录句柄，`rustix::fs::Dir::read_from` 迭代（跳过 getdents 的 `.`/`..`），类型取目录项 `d_type`（`Unknown` 回落 `statat(SYMLINK_NOFOLLOW)`），`size`/`modifiedAt` 用同一句柄上的 `statat`（相对解析，跟随链接，与 TS `stat` 同语义）。
- 拒绝形状 `refusal`（`:395`）：`nofollow_loop` 或 `ELOOP` → `FilesError::Workspace { raw }`（403 `workspace_boundary`，`raw` 为用户原始输入）；其余错误保留 Node 诊断（`mkdir` / `open` / `read` / `scandir`）。

## 范围

- 写侧：① 根内预置目录符号链接（`out-link/escaped.txt`，TS 确定性写出根外）；② `realpath`/词法闸门放行后、写入前被换入的链接（TS 同样写穿）。两种都从「成功写根外」变为 403。根内链接（文件叶或目录）**不在**本条偏离内：`canonical_prefix` 先解析既有前缀，写仍落到链接目标，与 TS 一致。
- 悬空链接叶：TS `writeFileSync` 会跟随并在链接目标处创建文件（可指向根外），Rust 以 403 拒绝（描述符 `NOFOLLOW` 打开）；属本条安全偏离。
- 读侧：③ `resolveSafe` 通过后叶节点或中间目录被换入链接（TS 读到根外内容），Rust 403。
- 枚举侧：④ 目录在校验后换入链接（TS 列出根外目录），Rust 403。
- 词法闸门已覆盖的 `..` 与绝对路径不在本条：两者 TS 与 Rust 行为一致（403），只作为回归探针留在测试里。
- 写叶 inode 复核（非普通文件 / `nlink != 1` → `EACCES: permission denied, open '<path>'` 500）是 A6.6-EDGECLAW-WRITE-INODE-001 在 api-web 侧的同款扩展，本条一并登记：TS 会写穿硬链接、对 FIFO 挂起。
- 不在范围：`readTree` 逐项 `stat` 仍跟随链接（与 TS `stat` 一致，只泄漏根外文件的 `size`/`modifiedAt`，内容不经此路径）；项目根本身缺失/悬空时的 `new()` 词法兜底不变（写路径遇根缺失时按 TS `mkdir(dirname, {recursive:true})` 递归建根再钉住，见 `write_creates_a_missing_project_root`）。

## 机器判据

- `src/pilotdeck-gateway/src/api_web/tests.rs` 六条探针（三种写侧形态、两种读侧形态、一种枚举侧形态各一条）：
  - `write_rejects_a_symlink_that_leaves_the_root`（`:779`）：断言根外 `escaped.txt` 不存在且得到 `Workspace { raw: "out-link/escaped.txt" }`。
  - `write_rejects_dotdot_that_leaves_the_root`（`:812`）、`write_rejects_an_absolute_path`（`:841`）：词法闸门回归，根外哨兵字节不变。
  - `write_rejects_a_component_swapped_inside_the_window`（`:870`）：`test_hook` 在 `resolve_safe_writing` 之后、写之前把 `swap/` 换成指向根外的链接。
  - `write_rejects_a_root_swapped_for_a_link`（`:911`）：`test_hook` 在写之前把项目根整目录改名走、换成指向根外的链接，断言写不落到根外且得到 `Workspace { raw: "raced.txt" }`。
  - `read_rejects_a_file_swapped_inside_the_window`（`:1010`）：`test_hook` 在 `stat` 通过后把叶节点换成指向根外的链接，断言不得返回根外内容。
  - `read_tree_rejects_a_directory_swapped_inside_the_window`（`:977`）：`test_hook` 新增的 `tree` 相位在 realpath 闸门之后、钉住枚举之前把被列目录换成指向根外的链接，断言得到 `Workspace { raw: "listing" }` 且不列出根外条目。
  - 既有 `read_rejects_a_symlink_that_leaves_the_root`（`:702`）继续钉住 `resolveSafe` 的 realpath 闸门。
- 三条 counter-probe 证明没有过度拒绝（TS 同款行为）：`write_follows_a_link_that_stays_inside_the_root`（`:1049`，根内文件链接照写穿且链接本身不被替换）、`write_creates_below_a_directory_link_that_stays_inside_the_root`（`:1084`，根内目录链接下照建新文件）、`write_creates_a_missing_project_root`（`:951`，根不存在时按 TS 递归建根）。三者不绑负控开关：开关关闭时按路径写同样跟随链接或同样建根，故恒绿。
- 负控：`tests/fixtures/api-web/negative_controls.py` 的 `api-web-nofollow-off`（第 7 个开关，绑 FILES）——打开后上述五条写/读/枚举加固探针必须同时变红（KILLED）。
- 金样：79 格 api-web replay 全绿（`api_web::` 共 95 passed / 1 ignored），`files-read-symlink` 仍回 `path: aaa.txt` + `YWxwaGEK`，`files-write-nested`（`deep/dir/n.txt`）仍成功，证明加固未改正常路径字节。
