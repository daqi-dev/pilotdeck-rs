## 类别

bug 修复（防御性加固）：结构非法或不支持的代理配置明确拒绝连接。启动时 URL 合法、仅 userinfo 解码失败保留 TS 的直连行为；不能把两类安装失败混同。

## 基线依据

TS `src/cli/proxy.ts:52-85,93-103,122-145`（cc7c4e6）。`_tmp/20261025-issue-676/ts-wire/invalid-reload/`、`unsupported-reload/`、`bad-userinfo-reload/`、`invalid-path-reload/`、`invalid-query-reload/`、`invalid-fragment-reload/` 实测仍用旧代理；`invalid-startup/`、`unsupported-startup/` 实测仍能直连；`invalid-env-config-fallback/` 实测 config 补装成功。

fix-r1 以 Node v22.22.0 重新调用上述真实 TS 入口和 `McpClient`：`user%ZZ` config startup、`user:%FF` env startup 均安装失败后直连成功，代理连接收据为 0，原 35-case oracle 的这两例没错，不改旧金样。四协议 HTTP/HTTPS/SOCKS5/socks 的截断转义、非十六进制、非法/截断 UTF-8、代理项混合来源共 61 例金样见 `src/pilotdeck-gateway/tests/fixtures/mcp-proxy-schemes/userinfo-oracle.json`；两次复采逐字节一致。原始 Node 输出与目标/代理收据：`_tmp/20261025-issue-676/fix-r1/ts-userinfo-final-{1,2}/`，两例目录分别为 `http-invalid-escape`、`http-invalid-utf8`。空 username 跳过 password 解码（包括 `:%FF`），仍可安装代理；转义后的合法 `%25ZZ` 不应被误拒绝。

## Rust 行为

`runtime/model/http.rs::ProxyConfig::from_settings_lookup` 通过 `ProxyParseError` 区分结构错误与 userinfo 解码失败：

- 结构非法：URL 无法解析、无 host、协议不在 `http/https/socks5/socks` 内；HTTP(S) 非根 path、非空 query/fragment。即使还含非法 userinfo，也优先归结构错误。connector 返回配置错误，NO_PROXY 的 127.0.0.1 也不连接。
- 合法 URL 仅 userinfo 失败：startup（env 或 config）恢复直连；坏 env 后有效 config 可以补装；无有效补装时，尝试过的非空 env/config 必须都只是 userinfo 错误才直连，任一结构错误仍 fail-closed。最后这条是上述防御性差异的混合来源边界，不宣称 TS 会拒绝。
- reload：所有安装失败仍明确拒绝，包括 userinfo；TS 此时保留旧代理，Rust 沿用已登记差异。空配置 reload 仍可主动取消代理。

合法编码、空 username、有效 env 优先、有效 config 补装的选择与本次 TS 实测一致；原始输出同上。

## 范围

MCP、model、count、hook 共享。Rust 不引入全局可变安装状态。reload 安装失败与首次结构非法配置明确失败属于本轮授权的防御性差异；startup userinfo-only 失败不在“非法配置 fail-closed”范围内。MCP streamable 公开错误仍为握手 fetch failed；具体配置错误 cause 由共享层单测验证。
