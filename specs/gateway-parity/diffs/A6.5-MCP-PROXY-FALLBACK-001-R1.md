## 类别

bug 修复（防御性加固）：代理配置失败明确拒绝连接，不能静默直连。

## 基线依据

TS `src/cli/proxy.ts:52-85,93-103,122-145`（cc7c4e6）。`_tmp/20261025-issue-676/ts-wire/invalid-reload/`、`unsupported-reload/`、`bad-userinfo-reload/`、`invalid-path-reload/`、`invalid-query-reload/`、`invalid-fragment-reload/` 实测仍用旧代理；`invalid-startup/`、`unsupported-startup/` 实测仍能直连；`invalid-env-config-fallback/` 实测 config 补装成功。

## Rust 行为

`runtime/model/http.rs::ProxyConfig::from_settings_lookup` 区分未配置与安装失败，后者保留失败状态，connector 返回配置错误，即使目标是 NO_PROXY 的127.0.0.1也不建立连接。startup 非法 env + 有效 config 补装与 TS 一致；空配置仍可主动取消代理。

## 范围

MCP、model、count、hook 共享。与 TS 保留旧 dispatcher 不同，Rust 不引入全局可变安装状态，而在 reload 非法时明确失败；首次非法配置也明确失败。这两处是本轮授权的防御性差异，不宣称完全等同 TS。MCP streamable 公开错误仍为握手 fetch failed；具体配置错误 cause 由共享层单测验证。

## 机器判据

`tests/mcp_proxy_schemes.rs::replays_ts_proxy_schemes`（22场景）；`runtime/model/http.rs` 代理来源/非法URL/无直连/超时单测；`runtime/model/proxy_socks.rs` 协议应答单测。真实TS两次复采一致；负控删协议支持、恢复非法直连、禁用config补装及协议校验/默认端口变异均须测试转红并逐字节还原，原始证据 `_tmp/20261025-issue-676/negative-controls.json`。定向测试与全量lib/fmt/clippy/frozen结果见 `_tmp/20261025-issue-676/RESULT.md`。
