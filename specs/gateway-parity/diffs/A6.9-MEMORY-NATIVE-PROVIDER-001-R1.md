## 类别

## 基线依据

cc7c4e6 `src/context/memory/createEdgeClawMemoryProviderFromConfig.ts:45-75`：缺少配置、disabled 或非 edgeclaw 返回 undefined；启用 edgeclaw 时构造 EdgeClawMemoryService 和 EdgeClawMemoryProvider。启用默认 service 的行为为读码推断，未实测：其构造器读取宿主 OpenClaw 配置及凭据，不在本包隔离探针中运行。

直接 import 基线的实测沿用 `_tmp/20261025-issue-587-pkg1/evidence/ts-probe.mjs` 与 `_tmp/20261025-issue-587-pkg1/evidence/06-ts-probe-final.log`：missing/disabled 不创建；unsupported 经生产规范化产生 fatal；注入 native provider 可被会话 context 调用，dispose 恰调用一次 close。注入成功仍不代表默认原生 service 已移植。

## Rust 行为

注入式 provider 已真实接线：`runtime/project/memory_bundle.rs` 的 `MemoryBundleFamilySource` 先取 `providerFactory`，缺失时取 deprecated `createProvider`，两者都进入 `ProjectMemoryBundle` 的 stage 并发布 `Resource::Memory` / `MemoryService` / `MemoryManagement`；`ContextStorageResources::create_session` 经 `Resource::Memory` 消费该 resolver。

默认 EdgeClaw 原生 provider 没有移植：`runtime/memory/mod.rs` 的 `MemoryBundleError::NativeProviderNotPorted` 仍是默认分支的返回值；启用 `edgeclaw` 且未注入 factory 时 stage 明确失败、不发布 generation。`memory_bundle.rs` 的模块注释仍把未移植归给 #587，归属以本条为准；该错误与注释由 #751 / #778 承接删除。

## 范围

- 「范围」原句：「完整网关入口组装尚无非测试 create_session 调用者，不能将组合 API 验证写成入口已启用或关闭 #587。」
- 「批准记录」原句：「#587 及完整生产入口验收保持未完成。」

更正后：

1. 「组合 API 验证不等于生产入口已启用」这一判据保留；但生产入口的验收归属改为 #590，不再记在 #587 名下。
2. 默认 EdgeClaw 原生 provider 的移植由 #751 承接，已拆成 #758–#778；默认分支接线与收尾见 #778（A6.6-edgeclaw-21）。在这条线合入前，默认分支继续显式返回 `NativeProviderNotPorted`，本条不批准该能力缺失。
3. #587 按自身代码交付关单（注入式接线、snapshot/recorder、事件落盘与重启回读），不再以「完整生产入口验收未完成」为由保持未完成。
4. 适用范围仅限本账本条目与 #587 / #590 / #751 之间的验收归属；不改测试期望，不改任何代码，不扩大 A6.6 验收范围。判分语义不变：仍不增加任何判分豁免，默认分支改回空成功仍须转红。
