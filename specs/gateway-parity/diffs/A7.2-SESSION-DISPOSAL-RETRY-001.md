## 类别

有意差异：宿主重试策略（#1020）。owner 已选 `previous` 后同 key dispose 完成的窗口，Rust 重试一次；TS 无任何重试。未批准，非已接受差异。

## 基线依据

Node v22.22.0、cc7c4e6 的 `session-stale-handoff/oracle.json`（4 格）与既有
`session-factory/oracle.json`：

- `router-disposed-previous` / `router-disposed-second-dirty`：TS
  `SessionRouter.getOrCreateActive`（SessionRouter.ts:135-143）直接把
  `cached.handle.session` 交给 `recreateSession`，无状态过滤、无重试；dispose
  完成后第二次、第三次 `getOrCreate` 均以 `Session projection driver is
  disposed.` 拒绝，再 markSessionDirty 仍拒绝，registry 不变。
- `direct-recreate-disposed` / `session-factory` 的 `recreate-disposed`：直接
  factory 层同样拒绝，错误无 code、无 causes。
- `router-prepare-disposal` / `session-factory` 的 `prepareDisposal`
  （MATRIX_DISPOSE_PREPARE）：dispose 在替代 prepare 的 refresh 里完成后，
  prepare 后的 `snapshotForRuntimeReload` 拒绝（SessionProjectionDriver.ts:227）。

## Rust 行为

- 选择时已 Disposed（初始 Disposed）：#745 r1 的选择过滤不把死 handle 交给
  factory，`previous=None`，一次 create 成功（本条把该行为从代码事实升级为
  显式登记；TS 在同格上反复拒绝）。
- 选择与 factory 接管之间 dispose 完成（同 key dispose 刚完成）：factory 在
  prepare 之前捕获 `state==Disposed && !retains_recreation_source()`，post-prepare
  `recreation_snapshot` 拒绝时给 previous 打 `recreation_stale_handoff` 标记并
  原样返回 TS 错误；owner 识别被标记的失败，**重跑一次**同步选择（死 handle
  不再入选 → `previous=None` → fresh resume），setup、dirty 清位、publication 与
  单次成功路径完全一致，对外仍是一个 get_or_create 操作。
- prepare 期间 dispose 完成：入口时 handle 尚未 Disposed，不打标记，错误原样
  上抛，与 TS 逐字一致（`recreate_snapshot_rejects_disposal_during_prepare` 钉住）。
- 重试上限 1 次；重试后仍失败则把该次 factory 错误原样上抛，不包裹。
- 直接 `factory.create(ctx, Some(previous))` 调用方不受影响：错误仍是
  `Session projection driver is disposed.`，无 code（oracle 钉死）。

## 范围

仅 owner 的 stale-handoff 窗口与初始 Disposed 选择过滤。TS 的 Router 端到端
（close/shutdown 排队、markAllDirty 等其余行为）不在本条内；writer fence 与
同 key 排队差异另归既有登记。

## 机器判据

`factory_tests.rs`：`recreate_retries_stale_disposed_handoff`（PublishGate
create 侧门闩确定性复现窗口）、`recreate_after_completed_disposal_resumes_without_previous`、
`stale_handoff_retry_is_limited_to_one`（fake factory，第 3 次成功防突变死循环）、
既有 `recreate_snapshot_rejects_disposal_during_prepare`（prepare 窗口不重试回归）、
`stale_handoff_matches_ts`（新金样四格）。fix-r1 起补 setup(previous) 契约（失败尝试
不到 setup、成功重试 fresh setup 恰一次）与第二次错误 message/code/causes 完整形状；
fix-r2 起 setup 事件带尝试序号，两家顺序断言
`ordered("setup.fresh.2","evict.dirty-recreate")` 钉死成功重试/替代的 setup 先于
publication。生成器侧另有 ignored 守卫 `stale_handoff_regenerates_identically`
（逐字节复算）与 `stale_handoff_preserves_unrelated_out_files`（fix-r2，既存 OUT
内容逐字节保留）。负控（session-factory/negative_controls.py，总数见其 README）：
#1020 原始 4 项 `1020-stale-mark-removed`、`1020-stale-retry-removed`、
`1020-stale-retry-unlimited`（三个 `#[cfg(test)] option_env!` 编译期开关）与
`1020-stale-fixture-regeneration` 金样防漂移；fix-r1 增 4 项
`1020-generator-missing-out`、`1020-generator-work-dirs-kept`、
`1020-setup-passes-stale-previous`、`1020-second-error-flattened`；fix-r2 增 3 项
`1020-generator-deletes-unrelated-out`、`1020-publication-before-setup`、
`1020-publication-before-setup-completed`。
