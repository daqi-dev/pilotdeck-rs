## 类别

不可避免（既有同步端口契约的表示边界）。`CronAgentGateway::submit_turn` 的端口
契约（#1326 落定、`native_process/assembly/cron.rs` 的
`NativeCronGatewayBody` 实现）是：turn 展开后才同步返回，事件流在端口边界被
`drain_turn` 折叠——首个 `error` 事件折为 `Err`（原 code 透传），其余事件不表
面化。TS `CronFire` 逐事件消费的四个观测面在该契约下不可表示，本条登记损失
面；不重开端口（重开须把 `submit_turn` 改为流式，属跨族契约改动，另立决策）。

## TS 依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0 / ICU 78.2。
`src/cron/runtime/CronFire.ts:95-140`：`for await (const event of
this.deps.gateway.submitTurn(...))` 逐事件——① `:105`
`store.appendRunEvent(runId, event)` 每个事件落 run 事件流；② `:106` +
`:205-216` `forwardTurnEvent` → `onTurnEvent`（吞错只 warn）；③ `:108-110`
`assistant_text_delta` 累积 `assistantText`，`deliverResult`（`:217-240`）的
completed 臂送 `assistantText.trim()`，为空才走 fallback
「定时任务已完成，但没有返回内容。」；④ `:111-127`
`elicitation_request`/`permission_request` 事件 → `failed` +
`cron_interaction_required` + `abortTurn("system:interaction_required")` 吞错；
`:128-140` `error` 事件分级（`turn_timeout`→`cron_run_timeout` 且
`forcedFailure` 闩锁，`agent_aborted`→`aborted`，其他 code→`failed` 透传）。
另有 `onPhaseEvent` 两点（`:96-104` cron_started、`:181-190`
cron_completed/cron_failed）。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/cron/fire.rs` 的 `run_task`：`submit_turn`
同步返回，`Err` 的 code 即折叠面携带的唯一信号（`assembly/cron.rs::failed_turn`
选首个 `error` 事件，code 原样透传）。因此：① run 事件流无逐事件记录，
run-history 只有 `appendRun` 的单条终态记录（`:221-251`）；② `assistantText`
恒为空，completed 臂的 `deliverResult`（`:301-330`）恒走 fallback
「定时任务已完成，但没有返回内容。」——TS 在有 assistant 文本时递送该文本，
Rust 侧永不可能；③ `elicitation_request`/`permission_request` 不是 `error`
事件，drain 继续，turn 按网关侧实际终态收场（典型为 `timeoutMs` 到点 →
`turn_timeout` → `failed`/`cron_run_timeout`），不产生 TS 的
`cron_interaction_required` 及其伴随 abortTurn；④ `onPhaseEvent` /
`onTurnEvent` 两个可选依赖无落点，不存在（fire deps 无此字段）。错误分级
（`turn_timeout`→`cron_run_timeout`、`agent_aborted`→`aborted`、其他透传、
无 code→`cron_run_failed`）与 `forcedFailure` 闩锁的可见效果（首个 error 定
终态）在折叠面上等价保留。

⑤ `onResultDelivery` 回调本身未接线（#2295 fix-r1 登记，**非表示边界、可实
现的接线缺口**，与①-④的「不可避免」不同类）：`CronFireDeps.on_result_delivery`
字段与 `deliver_result` 的调用链路已实现（fire.rs），但 `CronManagerOptions`
无 `on_result_delivery` 字段、`bind_agent_gateway` 写死 `None`
（manager.rs）、`assembly/cron.rs::build` 无注入点，native assembly 恒为
`None`。TS 侧是四条完整链路：`pilotdeck.ts:88`（onCronResultDelivery）→
`ProjectAutomationBundle.ts:313` → `CronManager.ts:198` → `CronRuntime.ts:136`
→ `CronFire.ts:228`（`deliverCronResult`）；Rust 各 IM 频道已实现
`deliver_cron_result`，但生产路径上无调用者，生产上 cron 结果不向任何频道递
送。测试以闭包直注 deps（scheduler_tests 的 fire_harness），故 oracle/探针
覆盖不到该缺口。跟进 #1826 族（频道递送接线）。

## 范围

cron fire 的结果递送与事件观测面：run-history 事件流形状、completed 递送
文本、interaction_required 分类、onPhaseEvent/onTurnEvent 回调，以及⑤的
onResultDelivery 接线缺口（可实现面，跟进 #1826 族，非端口契约限制）。不在
本条：
`appendRun` 终态记录形状、错误分级 code 映射、once 删除 / cron 重排的
post-run 更新、stopRequested 覆写 outcome——这些与 TS 一致（金样
`tests/fixtures/cron-scheduler/oracle.json` 逐格覆盖，oracle 的 observations
记录 gateway 调用序列与 tasks.json / run-history 终态，两侧可比面就是这些）。
管理面（create/update/delete）与调度面（见 A8.3-CRON-SCHED-SERIAL-001）不受
本条影响。

## 机器判据

`src/pilotdeck-gateway/src/runtime/cron/scheduler_tests.rs`（fire 面）：
`turn_errors_classify_by_code`（折叠面携带的 code 分级三级钉死）+
`codeless_rejection_folds_to_cron_run_failed`（seam 抛出折 `cron_run_failed`，
失败臂递送文本为 error message 而非 fallback）+
`stale_claim_aborts_without_record` / `stale_post_run_update_keeps_the_task` +
`stop_requested_overrides_the_outcome` +
`append_run_failure_warns_and_continues` / `delivery_failure_warns` /
`post_run_update_failure_warns`（三处 finally 容错）。金样重放
`scheduler_replays_the_ts_gold`（含 `due-once-fires` 等 10 格，oracle 由真 TS
`generate.mts` 生成，`cron_scheduler_oracle_regenerates_identically` 重生成
守卫钉 oracle 字节）。本条登记的不可表示面无 Rust 断言可写（不存在的行为），
其「不产生」由 deps 形状静态保证（`CronFireDeps` 无 on_phase_event /
on_turn_event 字段，`deliver_result` 的 completed 臂常量空串）。
