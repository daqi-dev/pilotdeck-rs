## 类别

基线 bug：丢数据。更正原条目把独立 fence 预算描述为默认 close_timeout，以及决策卡引用缺少 state/ 前缀的问题。

## 基线依据

Node v22.22.0、cc7c4e6：session-factory/oracle.json 的 writerInterleavings、fenceMatrix 保留真实 TS 输出。prepareDisposal 由真实 factory 的第二次 prepare refresh 钩子 dispose 旧会话得到：prepare 后取 snapshot 拒绝 Session projection driver is disposed.；本轮 Rust 对齐该结果，不登记快照取早差异。

## Rust 行为

FactoryOptions.writer_fence_timeout 由宿主显式提供，定义为旧 writer drain 加租约等待的总预算，storage 构建耗时不计入。不再隐式取 Limits::default().close_timeout；#589 接线须按宿主的实际取消/关闭策略配置，可复用 POST_CANCEL_EXIT_TIMEOUT。超时 SESSION_WRITER_BUSY、不发布候选、不强收旧租约的语义不变。

48 格同形观测逐字段比较：普通格在 load/publish 边界旧 handle 已 disposed、inFlight=0、oldPending=false；never 格在 fence 截止前为 draining/1/true、不能进入 load，最终 first/second 返回 SESSION_WRITER_BUSY。这些是 WRITER-FENCE 修复丢数据的用户可感知差异。

## 范围

仅 ProjectSessionFactory 的排他 writer 生命周期。close 钩子 panic 时局部 guard 释放本方租约；生产 open_locked 所有权复用仍须前置于 #589 接线解决。硬链接别名沿用存储层既有限制。

## 机器判据

factory_tests.rs 的 fence_* 全48格、writer_fence_uses_configured_budget、writer_close_panic_releases_lease、writer_rollback_close_panic_releases_lease、recreate_snapshot_rejects_disposal_during_prepare。negative_controls.py 逐项绑定完整测试与专属消息；新增TS字段沿用 ignored regenerates_identically 重采守卫。
