## 类别

bug 修复：拒绝用超限日志的空投影创建可写 recorder，避免向原日志追加从 1 重开的序列。

## 基线依据

cc7c4e6 `src/session/transcript/TranscriptReader.ts:15-29` 返回空 entries 与 transcript_too_large；`src/session/events/JsonlSessionEventStore.ts:24-26` 透传；SessionRuntime.restore 接受空数组。直接 import 探针在 50 MiB + 1 的稀疏文件上实际 read→restore→append 后 sequence=1，见 `src/pilotdeck-gateway/tests/fixtures/project-persistence/probe.mjs` 与同目录 oracle.json 的 oversizedCodes/oversizedSequence。原始输出 `_tmp/20261025-issue-587-pkg2/ts-probe-6.log`。

## Rust 行为

`runtime/project/persistence.rs` 的 create_session 在构造可写 recorder 前检查 transcript_too_large，返回 RecorderError::State，保持原文件不变；复用 `storage/transcript.rs` JsonlLedgerStore::open 的既有保护模式。同类 `storage/transcript_adapter.rs` SessionStorage::restore 也以 AdapterError::Store 拒绝该诊断。普通损坏行仍保留诊断并恢复完整记录。

## 范围

新 project persistence 会话组合入口与现有 SessionStorage::restore 可写恢复入口；底层 TranscriptStore/read_transcript、adapter 的独立 read 方法保持原有诊断行为。不是对所有读取错误的静默忽略，也不宣称整个 gateway 已使用本入口。

## 机器判据

`persistence_oversized_log_never_publishes_a_reset_writer`：超限拒绝、文件长度不变、空日志仍可写；分别删除两处守卫的负控必须失败。运行 `cargo test -p pilotdeck-gateway --lib persistence_`。金样 probe 独立运行 TS。

## 批准记录

未批准，非已接受差异。属于范围内可撤回 bug 修复候选，不扩大冻结判分豁免；合并前由协调者按项目程序处理。
