## 类别

更正（判据缺失已修复）：r3 评审（P1）发现 fix-r2 登记的核心不变量 settle-before-release
（R3「Rust 行为」第二点）没有任何会变红的机器判据——删除 owner.rs 两处
`settle.send_replace` 或把结算移到 serial ticket 释放之后，现有测试与全部负控仍绿，
窗口②（ticket 释放→条目结算之间同 key 创建发布 record、`shutdown()` 的 skip 漏排空）
会静默回归。由 #1245 fix-r3 修复并登记：结构化（ticket 移入结算守卫）+ test-only 顺序
探针 + 专用负控变异。Rust 对外行为不变（同一不变量的加固与判据补强）。

## TS 依据

无新增 TS 行为声明。R3 已登记的三份真实路由探针（`close-during-shutdown.out`、
`close-first-same-tick.out`、`skip-only-closing-key.out`，Node v22.22.0）继续适用；
本轮读码复核基线 `cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85` 的
`src/gateway/SessionRouter.ts:132-133`：`getOrCreateActive` 在检查 cached record 之前
先 `if (closing) await closing;`，条目由 `finishEviction` 在结算后移除，故 TS 不存在
「record 发布于条目未结算窗口」，无需新探针复现窗口本身（窗口在两段无 await 同步
代码之间，R3 已登记无法确定性复现；本轮判据断言的是任务内 settle 与 ticket 释放的
先后顺序，非窗口交错）。

## Rust 行为

#1245 fix-r3，`runtime/session/owner.rs`：close 任务与 idle sweep 任务把 serial
ticket 的所有权移入新守卫 `ClosingGuard`——任务体只 `closing.settle(outcome)` 暂存
结果；`ClosingGuard::drop` 在释放 ticket（`exclusive = None`）之前写入该 key 的
closing 条目，结算与释放成为同一个 drop 序列，调用点层面不再存在可错排的两条语句
（正常返回路径的「ticket 已释放 ⇒ 该 key 的 closing 条目已结算」不变量由结构保证，
与 fix-r2 的行为等价）。panic/abort 路径行为不变：无 outcome 暂存时守卫只释放
ticket，外层 `Completion` 守卫照旧在其后以 dropped error 结算条目（r3 评审 P2
登记的 panic-only 残留窗口维持原状、非回归，跟进处理）。测试侧新增
`#[cfg(test)]` thread_local 顺序探针 `settle_order`：守卫 settle 写入前记
`closing-settled`、`Ticket::drop` 记 `ticket-released`，两条记录点都在同步执行
路径内，其先后顺序可被确定性断言（评审建议①与②的结合）。

## 范围

`owner.rs` 的 close 任务体与 idle sweep 任务体两处（settle 调用改为守卫暂存）及
`Ticket`/`ClosingGuard`/`settle_order` 定义区；`owner_tests.rs` 新增两个顺序测试。
`shutdown()` 的 drain spawn、skip 判据、`cleanup_task.rs` 的 `Completion` 守卫、
A7.2-SESSION-RECREATE-DRAIN-001 的重建串行差异均不动。R1/R2/R3 的其余结论不变；
R3「Rust 行为」第二点所述不变量在本轮获得机器判据，panic 路径的限制按 r3 评审 P2
另行跟进。

## 机器判据

owner 级新增两个确定性单测（`runtime::session::owner::tests`，current_thread、
无 sleep）：`close_settles_its_closing_entry_before_releasing_the_ticket` 与
`idle_sweep_settles_its_closing_entry_before_releasing_the_ticket`——各自在夹具创建
完成后清空探针，断言 close/idle 任务的探针事件序列恰为
`["closing-settled", "ticket-released"]`（专属失败消息）。负控
`negative_close_shutdown.py` 增至九项（+`settle-after-release`：把
`ClosingGuard::drop` 里的 `self.exclusive = None;` 移到 settle 写入之前，即窗口②
回归，绑上述两个测试，须按各自专属消息 KILLED）；`negative.py` 的
`close-without-ticket-serialization` 锚随守卫化跟改（变异语义不变：close 任务
不等待/不持有 ticket，仍绑 `close_waits_for_prior_same_key_close_to_drain` 第二相
的既有 marker）。顺序探针为 thread_local，cargo test 并行线程间互不可见；夹具
创建任务的 ticket 释放在其最后一个 poll 的同步段内完成，先于被唤醒的公开 future
复跑，故测试窗口内事件序列不含杂项。
