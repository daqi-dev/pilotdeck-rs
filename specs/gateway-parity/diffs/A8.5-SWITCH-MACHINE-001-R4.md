## 机器判据

更正后的 R2 复算命令（工作目录一律 workspace 根 `src/`，须设**绝对路径
且不得位于 `src/` 内**的 CARGO_TARGET_DIR——fixture 的 cargo 子进程以
仓库根为 cwd（`negative_controls.py:182`），相对值会被两道命令解析到
两个 target 树（外层复算自 `src/` 起跑解析到 `src/<值>`，fixture 子
进程解析到 `<根>/<值>`，各编译一份）；本夹具自身不扫 `src/` 的未跟踪
产物（主流程只 preflight / record_sources / verify_unchanged /
enforce_denominator，`_assert_input_areas` 仅经 `mutating_sources` /
`build_snapshot` → `_assert_product_pristine` 到达，negative_process.py
排除表只排 `src/target/**`、`src/*/target/**`），但 `src/` 内残留会让
同树后续源码替换型负控当 build input 拒跑整树（DS fix7
concurrency#2，P2-b 判 P1 当轮补；fix7b boundary#1 更正先前「本夹具
拒跑整树」论据失实——本夹具不执行该守卫，此为核实后的正确后果）；
两条命令同一 shell 一次复现；循环体 `|| exit 1` 聚合失败——`for`
复合命令的退出码只取末次迭代，无聚合则中途红被末次绿吞、按 rc 判收
即假 PASS（DS fix7 concurrency#1+boundary#1 两家同撞，P2-b 判 P1
当轮补；循环与 fixture 两条命令须以 `&&` 串联成一个复合命令——
`( for …; do …; done ) && python3 …`，或整段落入 `set -e` 脚本：
`|| exit 1` 若只落在 `( … )` 子 shell 内，循环红仅终止子 shell、
fixture 仍执行，末次 rc 归 fixture（绿），复现本段所防的按 rc 判收
假 PASS（DS fix7c concurrency#1，P1 本轮引入当轮修）；接入管道会被
末段 rc 吞、交互 shell 顶层 `exit 1` 直接终止会话，故宜整段落脚本
执行（fix7b concurrency#2 / boundary#4）；单测逐名过滤（过滤名为 `--` 前的单名
位置参数）、`--exact` 在 `--` 后逐名一跑，零匹配退出 0 不得充数——
六条 cargo 复算记录各须附 `1 passed` 原始输出，`0 passed 0 failed` 与
`0 passed 0 failed; 1 ignored` 均不得充数（六个循环名中两个不在本
夹具 switches 表：`a_hung_channel_and_a_hung_owner_finish_share_one
_owner_bound` 与 `a_maximal_drain_budget_walks_to_completion`，改名
或 `#[ignore]` 时循环仍逐名 rc=0，唯逐条 `1 passed` 记录可拦——DS
fix7b boundary#2；与 R3 复算段逐条附 `passed` 计数同款口径）：

`for t in a_hung_host_teardown_exceeds_the_halt_owner_bound
an_erroring_owner_finish_is_recorded_for_the_revisit
an_interrupted_owner_finish_is_not_rerun_by_the_revisit
a_hung_channel_stop_exceeds_the_halt_close_bound
a_hung_channel_and_a_hung_owner_finish_share_one_owner_bound
a_maximal_drain_budget_walks_to_completion; do cargo test --offline
--locked -p pilotdeck-gateway --lib --features pdrs-mutants
native_process::switch_wiring_tests::$t -- --exact || exit 1; done` 与
`python3 -I pilotdeck-gateway/tests/fixtures/switch-state-machine/negative_controls.py
<输出目录>`（表按当前源态全跑：R2 时 10 行，今 13 行——3 行新增属
R3 承接，全表由本条实测跑过；输出目录须为不存在的路径，fixture
`mkdir(exist_ok=False)`，重跑沿用旧目录直接抛错；且不得位于 `src/`
内——工作目录是 `src/`，相对值会落在 `src/` 内且按设计留残留（每次
复算新建目录），正是上文 build input 拒跑机制，与 CARGO_TARGET_DIR
同口径（DS fix7c concurrency#2））。
