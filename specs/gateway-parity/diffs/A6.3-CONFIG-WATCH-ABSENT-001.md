## TS 依据

`pilot/config/PilotConfigStore.ts:103-140`（`startWatching`；回退与空 catch 在 `:123-130`）：`watchedPath = existsSync(path) ? path : dirname(path)` 只回退一级；`fs.watch(watchedPath, scheduleReload)` 抛错被空 `catch {}` 吞掉。被监视路径不存在、父目录不可读（`chmod 000` 等，`fs.watch` 抛 EACCES）时，**该路径没有任何监视器且基线永不重试**，只剩手动 reload。固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85。

真实数据复算（#2209 登记单，Node v22.22.0 / ICU 78.2，macOS 宿主，对只读基线 dist 编译版实跑）：原始输出 `_tmp/20261026-issue-2209/ts-probe-a3.log`（复算脚本同目录 `ts-probe-a3.mjs`）。配置缺失 + 父目录 chmod 000：`existsSync(cfg)` 为 false（stat EACCES），watchedPath 回退一级到父目录，`fs.watch(父目录)` 抛 EACCES、被空 catch 吞；父目录恢复可读并写入配置后等待 3 s **无任何自动 reload**（version 不变），手动 `reload()` 正常（version+1）。翻转另一侧（父目录可读）：watch 建立在父目录上，写入配置后约 154ms（debounce 150ms）reload 事件送达。

## Rust 行为

`config/store.rs` 的 `WatchedPath::new`（探测失败保留路径自 #1792 r1、main 已在；#1987 A3 / PR #2089 补钉子测试与负控行，`new` 的分支结构在 #2089 head `1c3ca8d51` 与 main 相同，均经 `git show` 逐行现核）。按路径本体 stat 的结果分两条可达路径：

- 路径本体 stat `NotFound`（路径真实缺失）→ 回退父目录（同基线一级回退）：父目录 stat 也 `NotFound` → 同基线跳过该路径；父目录 stat 失败但非 `NotFound`（EACCES/EMFILE/EIO）→ `Err(_) => Self::probing(parent, target)`——保留父目录与 target、模式未知。该臂以路径本体 stat 得 `NotFound` 为前提，#2089 的钉子测试经注入 stat 失败（`arm_read_failures`）到达，真实世界对应启动瞬态失败。
- 路径本体 stat 失败但非 `NotFound`——本条登记场景（配置缺失且父目录 `chmod 000`）即落此臂：stat 该路径直接 EACCES（TS 侧 `existsSync` 同因 EACCES 得 false，`_tmp/20261026-issue-2209/ts-probe-a3.log` 实测）→ `Err(_) => Self::probing(path, None)`——保留被监视路径本身、target=None、模式未知。

两形状 `changed()` 均 every tick 重探直至分类成功，恢复后按 D8 首完整拍必报、补报期间错过的变更：`probing(parent, target)` 形状含 target 创建与兄弟条目变更（路径为父目录）；`probing(path, None)` 形状路径即 target、含其创建，无兄弟观测（基线同形状无监视器，两侧一致）。启动探测失败期间（模式未知）不可观测：兄弟条目变更不报，恢复后首完整拍补报。

## 范围

启动（或 watch 建立）时被监视路径不存在、且父目录不可读的形状。基线：该路径无监视器、无自动 reload、永不重试——用户感知：父目录权限恢复后配置改动**永不自动生效**（需手动重载或重启）；Rust：保留该路径（`probing`、模式未知，两条可达路径见 Rust 行为段），恢复后自动补报。父目录可读的正常回退路径两侧一致（watch 父目录、事件/采样驱动 reload），不属本条。不影响手动 reload、判分语义、阈值与场景集。
