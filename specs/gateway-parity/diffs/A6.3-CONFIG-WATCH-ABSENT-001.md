## 类别

## TS 依据

`pilot/config/PilotConfigStore.ts:103-140`（`startWatching`；回退与空 catch 在 `:123-130`）：`watchedPath = existsSync(path) ? path : dirname(path)` 只回退一级；`fs.watch(watchedPath, scheduleReload)` 抛错被空 `catch {}` 吞掉。被监视路径不存在、父目录不可读（`chmod 000` 等，`fs.watch` 抛 EACCES）时，**该路径没有任何监视器且基线永不重试**，只剩手动 reload。固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85。

真实数据复算（#2209 登记单，Node v22.22.0 / ICU 78.2，macOS 宿主，对只读基线 dist 编译版实跑）：原始输出 `_tmp/20261026-issue-2209/ts-probe-a3.log`（复算脚本同目录 `ts-probe-a3.mjs`）。配置缺失 + 父目录 chmod 000：`existsSync(cfg)` 为 false（stat EACCES），watchedPath 回退一级到父目录，`fs.watch(父目录)` 抛 EACCES、被空 catch 吞；父目录恢复可读并写入配置后等待 3 s **无任何自动 reload**（version 不变），手动 `reload()` 正常（version+1）。翻转另一侧（父目录可读）：watch 建立在父目录上，写入配置后约 154ms（debounce 150ms）reload 事件送达。

## Rust 行为

`config/store.rs` 的 `WatchedPath::new`（#1987 A3，PR #2089）：被监视路径 `NotFound` 时回退父目录（同基线一级回退）；父目录 stat 失败但非 `NotFound`（EACCES/EMFILE/EIO）时 `Err(_) => Self::probing(parent, target)`——保留父目录与 target、模式未知；`changed()` 每 tick 重探直至分类成功，恢复后按 D8 首完整拍必报（补报期间错过的变更，含 target 创建与兄弟条目变更）。启动探测失败期间（模式未知）不可观测：兄弟条目变更不报，恢复后首完整拍补报。

## 范围

启动（或 watch 建立）时被监视路径不存在、且父目录不可读的形状。基线：该路径无监视器、无自动 reload、永不重试——用户感知：父目录权限恢复后配置改动**永不自动生效**（需手动重载或重启）；Rust：保留父目录、恢复后自动补报。父目录可读的正常回退路径两侧一致（watch 父目录、事件/采样驱动 reload），不属本条。不影响手动 reload、判分语义、阈值与场景集。
