## 机器判据

除以下更正外同原条目；Rust 22 格测试名不变：
`runtime::model::stats::cwd_tests::{relative,empty,absolute,tilde,tilde_child,unset,empty_home_tilde,empty_home_unset,empty_home_child,file_path,disabled}_{normal,deleted}_cwd`。

1. **每格 collector / runtime 两个独立子进程（44 receipts）**：原条目「逐一比对 collector 与 runtime 两个入口」现由每格两个 bounded test worker 落实——collector 与 `RouterRuntime::with_deps` 分别在独立子进程、独立临时 root / cwd / home 中运行，父进程分别校验退出状态与唯一 receipt，共 22 格 × 2 = 44 个 receipt。runtime 入口经 test-only 访问器读取 runtime 自己持有的 collector 实际选中的 `jsonl_path`，不从 collector 副作用或测试预计算的期望路径取值。

2. **负控 12 → 13 项，新增 `runtime-home`**：`src/pilotdeck-gateway/tests/fixtures/stats-cwd/negative_controls.py` 的 `MUTATIONS` 由 12 项增至 13 项。新增 `runtime-home` 把 router 传给 collector 的 home 改成 `/wrong`，要求除 `disabled-*`（读 home 前返回）与 `file-path-*`（使用 `config.filePath`）外的 18 格全部以 `#879 stats cwd runtime matrix:` 专属消息转红。`absolute-guard` 因裸 `~` 在 `stats.rs::default_pilot_home` 提前返回、结构上到不了 `expanded.is_absolute()`，fix-r1 起改为「声明的四格中至少一格命中专属消息」即算杀；其余 12 项仍要求声明的每一格命中，失败在无消息 panic 上不算杀。`cwd-fallback` 仍须让对应矩阵断言转红。

3. **kill 判定改读 libtest `failures:` 清单**：不再依赖 `... FAILED` 与测试名相邻（`--nocapture` 下 receipt 可能把 FAILED 挤到下一行）；执行器从 libtest 的 `failures:` 测试清单读取失败格，再要求该格出现 collector / runtime 的专属矩阵消息。无关 panic、编译失败与超时都不算杀，分别记 INVALID。

4. **执行器逐项汇总**：每个变异体依次做 positive → 应用变异 → negative → 恢复 positive，逐项记 KILLED / SURVIVED / INVALID 并输出汇总，任一非 KILLED 即非零退出，不在首个失败处中止；锚点过期直接失败退出，不记为 SURVIVED。脚本要求调用方设置 `CARGO_TARGET_DIR`，默认用 `mutating_sources` 锁定 HEAD（`NEGATIVE_BASELINE` 仅供提交前同字节临时基线样本），源码未提交就拒跑，不建影子仓库或第二份构建目录。
