## 类别

**本轮有意未对齐**（`stop()` 期间 Twilio client 的可用窗口差异）：sms 车道
`stop()` 把 `runtime.client` 置空的**时刻**比 TS 早一整段「排水窗口」。

依据是 `A8.3-CH-SMS-012` 残差 4 已登记的 detach 语义：Rust `SmsHandle::stop()`
只停 accept 循环、**不等** detach 的连接任务；TS `server.close()` 的 callback
要等所有连接结束才 resolve。两侧 `stop()` 的收尾动作相同（置空 client），但
它们相对「连接寿命」的位置不同，于是产生本条：Rust 在本车道**已经停止服务**
的那一刻就清掉 client，TS 要等排水结束。Rust 侧没有「服务器已停、连接还在
排水、client 仍可用」这段窗口，所以这不是漏写一行，而是残差 4 的直接后果；
本轮不改 `stop()` 的 detach 语义（那是决策单 #2026 的选项 C），因此登记。

  `_tmp/20261107-issue-1955-prereq/smoke/ts-stop-client-timing-r2.out`

  三个格点把这条顺序钉死。

## Rust 行为

`src/pilotdeck-gateway/src/channel/sms/mod.rs`：

- `SmsHandle::stop()`（`:337-373`）：`shutdown.send(true)` → `server.task.await`
  （只等 accept 循环）→ 立刻 `shared.runtime.lock().await.client = None`
  （`:371`）。detach 的连接任务不参与这条等待，所以 client 的置空时刻与
  它们是否还在跑无关。
- `send_reply()`（`:1208-1216`）：`runtime.client` 为 `None` 时直接 `return
  false`，与 TS `SmsChannel.ts:302` 同一判据，因此测试可以用它当黑盒读数。
- 配对用例
  `src/pilotdeck-gateway/src/channel/sms/head_timeout_tests.rs:379`
  `stop_returns_before_the_detached_connection_ends`：注入 30 s 头读期限 →
  起一条半截头连接 → `stop()` 必须在 1 s 内返回（`STOP_RETURN_LIMIT`）→
  返回后该通道自己的 detach 连接计数（`SmsShared::live_connections`，
  `#[cfg(test)]` 字段）仍 ≥ 1、连接在 500 ms 内既无字节也无 EOF →
  `send_reply` 已返回 `false`（stop 前置的同一调用返回 `true`，所以这条观察
  不是空断言）。
- 变异开关 `sms-stop-waits-for-connections`（`mod.rs:361-369` 的
  `#[cfg(test)]` 分支）把 `stop()` 改成等全部 detach 连接结束再置空 client，
  即 TS 的「排完再清」形状；该形状下载荷用例必须撞上 1 s 上界而转红。

## 范围

只影响 `SmsHandle::stop()` 返回到最后一条 detach 连接结束之间的这段窗口：

| 场景 | TS | Rust |
| --- | --- | --- |
| stop 已调用、连接仍在排水，`sendReply` | 返回 `true`，消息真的发出（实测 `sends=2`） | 返回 `false`，消息被丢弃（client 已 `None`） |
| stop resolve 时 client | 已 `null`（实测 `clientPresent=false`） | 早已 `None`（早一整段窗口） |
| stop 期间新连接 | `ECONNREFUSED`（`ts-stop-drain.out` 实测） | 同样拒绝 |

用户可感知差异：**只有「停止过程中恰好产生一条回复」时**，TS 还能把它发出去，
Rust 会丢掉。正常停机窗口内（无半截头连接）这段窗口是毫秒级；有半截头连接时
TS 的窗口可以无限长（Node `httpServerPreClose` 清掉 checker，半截头连接不再
到期），Rust 的窗口固定为「accept 循环结束后立即」——按 `A8.3-CH-SMS-012`
残差 4 的取舍，Rust 不承担排水，因此也不保留排水期的 client。

不在本条范围：`request_timeout` / `headers_timeout` 的取值与线上字节
（`A8.3-CH-SMS-010` / `-012`）、`stop()` 的 reason 默认值
（`A8.3-CH-SMS-004` 族）、`stop()` 期间已经进入 handler 的请求本身（它们各自
继续跑，只是回复发不出去）。

  `cargo test -p pilotdeck-gateway --lib channel::sms::head_timeout_tests::stop_returns_before_the_detached_connection_ends`
