## 类别

兼容性更正：同一 native host 现在按请求选择独立项目，退役原条目及 R1 中单项目全局 admission 导致的 archive 空串六格差异。原条目、R1、冻结 oracle 和判分规则均保留原字节。进程外 pairing 的 nullish General fallback 不受影响。

## 基线依据

固定 TS cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85、Node v22.22.0。已有 `tests/fixtures/native-archive-cwd/oracle.json` 的 36 个原始观察包含：空串/other 三格为 PROJECT_NOT_FOUND 与 `Unknown projectKey: `；空串/deleted 三格为 ENOENT 与 `ENOENT: no such file or directory, uv_cwd`。三个 callback 使用 `input.projectKey ?? fallbackProjectRoot`，空串保留给 path.resolve；registered project resolver 负责归属校验，而非限制所有请求为启动时项目。

## Rust 行为

每个请求 clone 不可变 options.project view；只按 UTF-16 词法解析身份，绝不以 runtime registry 可 stage 作为授权。archive 仍由既有 registered-project resolver 拒绝未登记目录，nullish fallback 和原参数顺序保留。scope 的 process cwd 失败使用既有 cwd_error 映射。已存在或创建中的同名 session 属另一项目时，按独立项目隔离差异拒绝，不能执行到旧项目。

## 范围

此更正仅撤销原单项目 admission 在 36 格矩阵中的六格覆写，恢复直接比较固定 TS 原始 oracle；不改 Metadata marker 规则、archive 内容格式、pairing fallback、会话权限、所有权或冻结标准。`active_turn_snapshot` 的空流与路径选择测试验证词法 root，而非把无资源的空流返回误作 registered-project 授权。

## 机器判据

`native_process::tests::metadata_cwd::archive_matrix_matches_ts` 仍为 36 个子进程，逐字比较全部原 oracle；R1 的旧行仅作不可修改的历史登记检查，不再替换预期。`isolated-admission-skipped` 保留槽名、原测试与 nonce，注错目标改为真实 archive registered-project admission，原未知项目格必须杀死；`request-project-base` 保留五格、测试与 nonce，以 scope 选中的真实路径杀死错误 project-base；`submit-project-base` 将相同错误基点注在 workspace 身份规范化之前，避免规范化后绝对路径使旧注错成为等价空操作。没有删除 control、缩减分母或放宽失败判据。作者仅完成源码/standalone rustfmt/patch 格式检查，Rust 与真实变异仍待协调者 mbp2 验证，不登记已通过。
