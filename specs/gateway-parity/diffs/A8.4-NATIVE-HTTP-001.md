## 类别

传输层差异（已接受）：#1209 为原生监听器的非升级 HTTP 分支
（`/health`、回环 `/auth/local-token`、静态回退、最终 404）引入 hyper 1.7.0
作为 HTTP/1.1 编解码器后，无法经 hyper 公开 API 消除的帧级/头级呈现差异
（下列基线依据中 4 项）。金样矩阵内（88 cell）路由语义（状态码、
content-type、体字节、连接关闭与否）与 TS 一致（date 掩码与已登记帧级
呈现差异归一化后字节一致；原始字节在上述 4 项呈现上不同）；矩阵外的
解析层差异（target 字符集及头预算边界残余）另立 A8.4-NATIVE-HTTP-002
登记，不在本条。
Node 的 keep-alive 空闲超时**未收敛**（原第 5 项，见"基线依据"与
"Rust 行为"）：Rust 复刻 `keepAliveTimeout` 本身、恰 5 s 关闭，Node 实测
~6 s（5 s + 固定 1 s `keepAliveTimeoutBuffer`，有效 socket 超时 6000 ms），
行为对齐见 #1250（A8.5 切换默认路由前复核）。未修改冻结尺子或默认代理
路径（`native_process.rs` 与 `serve_connection_with` 的代理字节不变）。

## 基线依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0。
真实金样 `src/pilotdeck-gateway/tests/fixtures/native-http-basic/oracle.json`
（88 cell，四服务器 a/b/c/d，date 掩码后的原始响应字节）：

1. 头名大小写：TS 混合——`GatewayServer.ts:96` 源码字面 `content-type`
   小写，Node 自动头 `Date`/`Connection`/`Keep-Alive`/`Transfer-Encoding`
   大写；hyper 头统一 Title-Case（`content-type` → `Content-Type`），
   差异收敛到每个响应恰一处。
2. chunk 大小十六进制：Node 小写（`b`），hyper `encode.rs` 的 `{:X}`
   大写（`B`），无扩展点。
3. 裸 400（llhttp 方法表/target 形态/非字母 scheme 拒绝）：TS 无
   content-length，hyper 对已知长度空体自动补 `content-length: 0`。
4. HTTP/1.0 状态行：Node 恒回显 `HTTP/1.1`，hyper 回显 `HTTP/1.0`
   （HTTP/1.0 客户端不进金样矩阵，`http10_close_delimited_response`
   钉死测试记录在案）。

（第 5 项 keep-alive 空闲超时差异未收敛，fix-r3 曾误记"已消除"：Node 实际
生效的是 `_http_server` 的 `socket.setTimeout(keepAliveTimeout +
keepAliveTimeoutBuffer)`，Node v22.22.0 实测 `keepAliveTimeout` 5000、
`keepAliveTimeoutBuffer` 固定 1000（有效 6000 ms；本机只读复核
`_tmp/20261026-issue-1209/fix-r4/node-keepalive-probe.out`），探针
`probe-fixr3-a.out` A 实测无停机时 +6007 ms 关闭；hyper 无内建空闲超时，
端口在连接层按"最后一次请求 parse/应答完成活动 + 5 s"重臂式 deadline
自行关闭，恰 5 s、早于 Node 约 1 s。行为对齐（有效超时复刻与 5–6 s
窗口断言）见 #1250；该差异属时序而非帧级呈现，不影响上述 4 项。）

回放比较对两侧统一归一化（date 掩码、头名小写、删 `content-length: 0`、
chunk 大小小写；状态行不折叠）；归一化会折叠的每个维度（状态行、
Date 缺席、HEAD 无帧、Title-Case、大写 chunk、`Content-Length: 0`）
都有钉死测试锁住 hyper 实际字节，金样矩阵内新增未登记差异会被逐
cell 回放击落。

## Rust 行为

`src/pilotdeck-gateway/src/native_http.rs`（`http_proxy::serve_connection_native_with_shutdown`，
`title_case_headers(true)` + `auto_date_header(false)` + `max_headers(16384)`，
与代理路径共享私有 helper）：llhttp 方法表（Node `http.METHODS` 正本）、
target 字节/形态、scheme 纯字母检测在 handler 层复刻裸 400 + 关连接；
`Connection: close` 与 HTTP/1.0 请求按 Node v22 应答 `Connection: close`、
无 Keep-Alive、应答后关连接；WHATWG URL 规范化（绝对形式保留
`//` 路径）为静态层的穿越防线，`path.resolve` 折叠 + contains 守卫 +
根词法规范化为纵深防御；Node 式头序（content-type、Date、
Connection: keep-alive、Keep-Alive: timeout=5）、未知长度流式体恒
chunked、HEAD 无帧。CONNECT 以 handler Err 实现零字节销毁，等价 TS 的
`socket.destroy()`。

停机与空闲关闭按 Node 实测复刻（探针 `probe-fixr1.out` B、
`probe-fixr2.out` D、`probe-fixr3-a.out` A/D、`probe-fixr3-b.out` B1）：

- `server.close()` 停机瞬间空闲的已服务连接立即关闭（hyper
  `graceful_shutdown()` 等价）；从未发字节的连接不关（close() 只等它，
  有界 runner 以 drain 错误呈现该无限等待）。
- 停机后才到达的请求、停机时在途的请求照常应答 200 +
  `Connection: keep-alive`，连接不因停机或应答完成而关闭，由 5 s
  keep-alive 空闲超时统一收口，`run()` 在收口后 `Ok(())`。
- 5 s keep-alive 空闲超时与停机无关地始终在岗：deadline 为最后一次
  请求 parse/应答完成活动 + 5 s，逐活动重臂；请求在途时不触发。端口
  在恰好 5 s 关闭，Node 实测 ~6 s（5 s + 固定 1 s
  `keepAliveTimeoutBuffer`）；该 ~1 s 差异未收敛，对齐见 #1250。

## 范围

仅 opt-in 的 `NativeWsServer` 非升级分支（`with_static_root` 配置静态根；
生产默认无静态根、恒回环，`bind` 签名不变）。不含 `/api/web/`、approvals、
module-host（A8.4 后续包），不改默认代理路由。上述 4 项差异仅指明呈现层，
不作为对拍豁免：任何新的未登记差异会先被钉死测试或逐 cell 回放击落。
