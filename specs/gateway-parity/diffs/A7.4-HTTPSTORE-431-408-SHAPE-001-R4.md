## 类别

差异消除（body `requestTimeout` 408 的字节形状；请求 body 期间流水线进来的下一个请求头、
分块 body、trailer 的 431 形状与优先级），并登记剩余差异。R3「仍存在」清单的第 1 条
（body 408 经 hyper 写出）与第 2 条（流水线超限头走 `serve` 兜底的 hyper 形状）在本单消除；
其余条目不变。本条目是 R3 的事实更新，**未批准，非已接受差异**。

实测要点（每 cell 记状态行、头、体、字节数、hex、连接结局、耗时、handler 调用数）：

- **M1 body 超时**：头完整、body 未收完、默认 300 s `requestTimeout` → **300,019 ms
  （首跑）/ 300,022 ms（复跑）收到 51 B `HTTP/1.1 408 Request Timeout\r\nConnection:
  close\r\n\r\n`，随后 EOF**，处理函数从未被调用（put/list 均 0）。与 #699 短配置探针
  （`short-body-timeout` 308 ms、51 B）互证：字节常量与超时配置无关。
- **M2 body 期间流水线超限头**：第一个请求 body 相位把下一个请求头（计数 16,384+）写进
  同一 socket。Node 的 parser 在 body 读回调里就看到这些字节，**在 in-flight 响应到达
  socket 之前**写 67 B 431 并关连接——`single-burst` / `body-late` / `with-body` /
  `chunked-pipelined-oversized-body-late` / `chunkext-pipelined-oversized-body-late`
  （chunk 扩展不遮蔽）全部 **67 B only**（list 处理函数被调用 1 次但响应 1 从未上线）；
  唯一例外 `after-response`（响应 1 已经 flush 之后才写入超限头）是 262 B =
  200 OK + 67 B 431，EOF。
- **trailer**：`chunked-oversized-trailer` → 67 B 431 + EOF；trailer 字段与头字段共享同一
  per-message `maxHeaderSize` 预算。
- **M3 负控**：`pipelined-under-limit-body-late` / `chunked-pipelined-under-limit-body-late`
  → 449 B = 200 OK + 400 `invalid_json`，连接保持打开；`large-body-served-and-
  connection-reusable`（40 KB body）→ 400 + 后续 200，连接可复用。
- **重复 `Content-Length`（等值两次）**：Node parser 自答 47 B
  `HTTP/1.1 400 Bad Request\r\nConnection: close\r\n\r\n` 并关连接（llhttp 拒绝重复
  CL）；hyper（`role.rs` 只拒绝不等值）会正常服务。这是解析器差异，本单不消除，只钉住
  Rust 兜底的字节。

## Rust 行为

`src/pilotdeck-gateway/src/user_dialog/http_store.rs`：

- `serve` 的两处 `empty_response`（:3544 `header_bytes` 431 兜底、:3604 body
  `requestTimeout` 408）不再让 hyper 自行编码：`KeepAliveTimer::force_node_response`
  （:2036）把 Node 常量字节挂到连接（`forced_response` :1968），
  `TimeoutStream::poll_write`（:3026）在 hyper 的第一个字节之前
  `take_forced_response()`，把 51 / 67 B 写进 socket，随后以 `BrokenPipe` 拒绝 hyper 的
  全部后续写入——hyper 的 123 B 形状（`content-length: 0` / `date` / 小写头名）不再上
  线。占位响应继续流经 service（其 `Connection: close` 让 keep-alive 广告保持惰性），
  与 #699 头相位的 `raw_response` 机制同一族、同一任务写。
- `HeaderGuard`（:2227）从「只在请求头相位扫描」扩为全连接扫描：`BodyFraming`（:2272）
  重放 `Content-Length` 与单 token `chunked`（数据块、`;ext` 扩展、`ChunkEnd`、terminal
  chunk 之后的 trailer 段），body 字节既不计入 `maxHeaderSize` 账本也不计入 raw 上界；
  每个消息边界 `begin_next_head`（:2359）重置 per-message 预算与框架记账（Node 的
  `header_nread_` 是 per message）；trailer 字段按头字段计数（`trailer` 标志）；
  `begin`（:2386）不再在 `Request` 相位把 guard 关掉。
- `TimeoutStream::poll_read`（:2865）读前瞻循环：Node 的 parser 在读回调里扫描每个到达
  字节，所以一次 poll_read 持续排空 socket 直到读尽或 `READ_AHEAD_BYTES`（:109，
  128 KiB）为止；hyper 还没要的字节存在 `ahead`（:2758），EOF 用 `ahead_eof`（:2762）
  锁存、等字节交齐后才浮出（半关闭 47 B 400 的判定随之搬进该循环，行为不变）。
- guard 无法重放的框架（重复 `Content-Length`、多 token `Transfer-Encoding`、畸形
  chunk-size 行）`active = false` 让位：hyper 仍解析该请求，`serve` 的 `header_bytes`
  兜底经 `force_node_response` 仍答 Node 的 67 B 431。

## 范围

已消除（逐字节，探针 cell 见 §基线依据）：

1. body `requestTimeout` 408 → Node 51 B（M1），计时仍为 Rust 300 s 整点（Node 受
   30 s checker 量化到 300–330 s，R3 已登记的计时差异不变）。
2. body 期间流水线超限头 → 在 hyper 能答 in-flight 请求之前只写 67 B 431（M2，五个
   cell：single-burst / body-late / with-body / chunked / chunk-ext）。
3. 响应 1 已 flush 之后的超限头 → 200 + 67 B 431（after-response，两实现一致）。
4. `maxHeaderSize` per-message 预算：前一消息的 head 与 body 消耗不带入下一消息
   （M3 负控与 `begin_next_head`）。
5. 40 KB body 正常服务、连接可复用；chunk 扩展不遮蔽流水线头；trailer 字段计入本消息
   预算（M2/M3）。
6. 重复等值 `Content-Length`：guard 让位后 serve 兜底答 67 B 431（Node 是 47 B 400，
   见「仍存在」）。

仍存在、如实登记（不据此新增豁免）：

- **shutdown 终止界限**：`server.close()` 后 body 在途，Node 挂起 0 B，Rust 仍写 408 再
  关——但字节已从 hyper 123 B 变为 Node 51 B
  （`shutdown_with_partial_body_finishes_at_request_timeout` 现在逐字节断言）；终止界限
  差异本身仍是 R3 登记的差异。
- **guard 的资源上界族**：raw 上界（R3 已登记）不变；`ahead` 读前瞻缓冲上限
  `READ_AHEAD_BYTES`（128 KiB）与 `HEADER_GUARD_BUFFER_BYTES`（8 KiB 读块）同族——
  能触发任一判定（16,384 计数或 raw 上界）的头都落在 128 KiB 之内，cap 只对不可
  trip 的超量字节（如前导空白）生效，park 等待 hyper 消费而非丢字节。
- **hyper `max_headers(4096)` 字段数兜底**、**malformed 400 / 414 形状**（R3 已登记，
  另案拆包）。
- **重复等值 `Content-Length` 的解析差异**：hyper 服务该请求（200），Node 自答 47 B
  400 并关连接；本单只对齐兜底 431 的字节，总行为差异登记在案（探针
  `dup-cl-pipelined-oversized-body-late`）。
