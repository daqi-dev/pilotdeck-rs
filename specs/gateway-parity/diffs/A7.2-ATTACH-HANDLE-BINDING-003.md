## 类别

不可避免（安全加固）。本条目是 `A7.2-ATTACH-HANDLE-BINDING-002` 只收口租约条目那一处之后，把同一加族打开推广到租约外三个读路径兄弟位（#2098）：`verified()` 的附件叶摘要读、`read_at` 的 `metadata.json` 读、composer 的租约条目读。TS 基线三处同形挂起/无上限读，Rust「立即拒绝」是登记的安全加固分叉，不改变冻结判据。fix-r3 条B 另在同条目登记一条**正常路径** TS 可观察分叉（`create` 写侧记录上限，见「Rust 行为」fix-r3 条B 与「范围」），随本 PR 评审。

## 基线依据

固定 cc7c4e6。TS 侧对应实现：`src/gateway/client/UploadStore.ts` 的 `verifyAttachments`（`sha256File` 读到 EOF）与 `readAt`（`readFile` 读到 EOF）、`GatewayAttachmentTurnComposer.ts` 的附件 lease 路径 stat/open（裸 open）。协调者 2026-11-11 darwin / node v22.22.0 实测（任务书 §1）：三处同格——附件叶换成 FIFO 后 `sha256File`/`readFile` 阻塞超 3 秒（进程随之不退）；换成指向 `/dev/zero` 的符号链接后 3 秒读 2.7 GB 仍无 EOF；稀疏放大后 3 秒读 7.5 GB 仍无 EOF。与 `_tmp/20261107-issue-1887/lease-open-probe/` 对租约条目位实测的同一族脸面（该次 `probe.rs`：裸 `File::open` FIFO 3 秒不返回、`/dev/zero` 链接读 64 MiB 无 EOF）。写侧（`UploadStore.ts` 的 create/mutate 落盘）无记录大小上限、超界 manifest 照写并读回（fix-r3 轮登记口径，提交 55ca8053a：协调者实测 `validateManifest` 无 `name` 长度/记录大小上限、`readFile` 任意大小读回、幂等回放与并发计数都走 listing）；既有 oracle 只把 `UPLOAD_TASK_TOO_LARGE` 钉在 `Upload task exceeds its byte limit.`（`src/pilotdeck-gateway/tests/fixtures/upload/oracle.json:3058-3059`）。fix-r3 条B 的写侧上限据此登记为正常路径分叉。

## Rust 行为

- 共用一个 helper（不三处各写一份）：`upload/mod.rs` 的 `open_lease_entry` 改名并改签名为 `pub(crate) fn open_artifact_guarded(path) -> io::Result<File>`（Unix `O_NOFOLLOW | O_NONBLOCK`；非 Unix 保留裸 `File::open` + 源码注释写明诚实残余，与租约侧 `cfg(not(unix))` 同形）。`.custom_flags(libc::O_NOFOLLOW | libc::O_NONBLOCK);` 在 `upload/mod.rs` 仍恰出现一次（既有 `lease-link-*` 负控行锚点不破）。
- S1 `verified()`（`upload/mod.rs`）：附件叶经加族打开；句柄 `fstat` 的类型项与长度相等项（`info.len() ==` 记录 `bytes`）都在句柄上；`hash_file`（读 EOF，无上限）删除，摘要改 `hash_file_exact(&mut file, 记录 bytes)`（定长 + 恰好结尾，复用 #1889 的 helper，语义未改）。
- S2 `read_at()`（`upload/mod.rs`）：`metadata.json` 经加族打开；句柄 `fstat` 非（普通文件或目录）→ `PROJECT_PATH_FORBIDDEN` + `Upload metadata path became a non-regular file after validation.`（沿用本函数「became a symlink after validation」同族文案）；新增 `MAX_METADATA_JSON_BYTES = 64 MiB`（依据：metadata.json 由本网关独写、合法记录远低于此界，只为堵稀疏对抗文件）；`read_to_end` → 新 helper `read_exact_file`（读恰好 `fstat` 长度且随后必须 EOF，仿 `hash_file_exact` 写法）。既有 dev/ino 身份项、`symlink_metadata` 前置、`handle_path` 包含项全保留。
- S3 composer（`native_process/services.rs`）：租约条目经 `crate::upload::open_artifact_guarded` 打开，open 错误（含 ELOOP）沿用既有 not-found 诊断分支（continue）；句柄 `fstat` 非（普通文件或目录）→ not-found 诊断（不读、不注册）；读侧不动（`read_bounded` + `len() > limit` 已有界）。
- 目录豁口（三处类型项一致）：判式是 `!is_file() && !is_dir()`——目录的读按 Node 的 `EISDIR … read` 描述符读形状立刻失败（TS parity #656/#1462 既有测试钉住该形状），既非本项要堵的 FIFO 等待、也非设备的无上限流。
- fix-r2 条2：`verified()` 与 `lease_link_content_matches` 的摘要读加绝对上限 `MAX_ATTACHMENT_READ_BYTES = 1 GiB`（取值依据：对齐写侧 `options.max_file_bytes` 默认——网关自己写的附件不超过它，超界记录只能是伪造或外部写入），超限按既有 `ATTACHMENT_TAMPERED` 族拒绝。用户可感知差异：`bytes` 超界的记录从「按记录 bytes 读满再比对」变为立即完整性失败，正常附件不受影响。
- fix-r2 条3：`cleanup_expired_leases` 的 `lease.json` 读（同源第四读位）收口为 `open_artifact_guarded` + 句柄项（非 file/dir 视为过期、按坏记录口径跳过）+ `read_exact_file`（`MAX_METADATA_JSON_BYTES` 界），同 `read_at` 形。
- fix-r2 条4（选型 b，oracle 复算收窄）：`list_in_project` 对读加固自身的脸面（类型项、读界、精确读两项）改为按清扫（`sweep`）的 `skip_record` 口径跳过；TS 自身会产生的拒绝（身份不符、逃逸符号链接、JSON 解析失败）与 #1494 族（换链/句柄身份/句柄逃逸）仍严格传播——oracle `metadata-identity`#3、`metadata-symlink`#4 钉住 `create` 在这两种兄弟记录下必须失败（`upload_create_still_fails_on_a_tampered_sibling_record` 同口径）。判据：写侧单帧可达 ~100 MiB 记录 JSON（`name`/`relativePath` 无长度项）而读界 64 MiB，选 a（写侧加界）改正常写路径、选 c（抬读界）放大攻击面且负控难钉「恰好超界」；b 不改变既有合法记录语义（ blanket 跳过被 oracle 复算抓回后收窄），且有 `list-strict-error-restored` 负控行钉住。
- fix-r2 P2a：`read_exact_file`/`hash_file_exact` 合并为 `read_exact_chunks` 流式引擎（digest 版与字节版共用同一边界语义，负控各钉一边）；`read_at` 新增 `BeforeRead` 测试窗口（类型项/长度项之后的精确读窗口，`BetweenWalkAndCanonicalize` 同例），使精确读项有确定性杀点。
- fix-r3 条A（#1494 DS boundary#1，读句柄项单因子）：`read-at-handle-check-dropped` 收窄为单因子变异（old 锚只删句柄包含项、new 为空串），新测试 `upload_read_at_metadata_hardlinked_through_a_swapped_id_dir_is_rejected`——`<id>` 目录在 canonicalize→open 窗口换成指向上传根外 holder 的符号链接、目录内 `metadata.json` 为批准 inode 的硬链接（实测 `_tmp/20261026-issue-2098/fix-r3/probe-handle-alias/probe.out`：`O_NOFOLLOW` 只护末段、open 成功、dev/ino 相同、`readlink /proc/self/fd/N` 答根外路径），唯一拒绝项是句柄路径包含检查（`PROJECT_PATH_FORBIDDEN` + `Upload metadata handle leaves the upload directory.`）；原 ELOOP 形测试保留为产品测试，open 守卫由 `read-at-open-nofollow-dropped` 钉。
- fix-r3 条B（评审 MM boundary#1 + DS boundary#4 两家独立；**正常路径 TS 可观察分叉**，类别：安全加固、非对抗性，依据：`validate_manifest` 只限文件 bytes 不限记录自身 JSON——`name` 无长度项，单帧可达 ~100 MiB 而读界 64 MiB）：`create` 在落盘前对序列化记录 JSON 行长做写侧上限——`line.len() > MAX_METADATA_JSON_BYTES`（64 MiB，与读侧同一常量、单一来源，含尾 `\n` 写盘字节 = `line.len()`，「写得出=读得回」恒成立）即以 `UPLOAD_TASK_TOO_LARGE` + `Upload manifest record exceeds the supported size.`（写侧自己的新文案）拒绝、零落盘。TS 基线无此拒绝、该 manifest 照写并读回（见「基线依据」）——同码异消息的正常路径分叉在此登记。恰好 64 MiB 的记录保持「可写、可读回」、超一字节即拒（`upload_create_refuses_a_manifest_record_past_the_write_cap`；负控行 `create-record-cap-dropped`）；list 的 skip 分支保留（只守外部来源记录）。
- fix-r3 条C（DS boundary#2，P2a）：第四读位（`cleanup_expired_leases` 的 `lease.json` 读）的专属负控行 `cleanup-lease-entry-open-dropped`——变异体把读闭包退回 pre-fix `fs::read` 形（裸 open，FIFO 上阻塞），由 `upload_lease_cleanup_does_not_wait_on_a_fifo_lease_entry` 的 2 s 看门狗专属 panic 文案杀。
- fix-r3 条D（DS boundary#3，P2a）：`unreadable_record_face` 的 `""` 面（精确读两项的合成 io 错，无 errno 可镜像，故 wire code 为空）只为读加固自身的脸面存在；JSON 解析失败同是空码但必须保持严格传播（TS 自己的 `JSON.parse` 同样让 listing 失败）。新测试 `upload_create_still_fails_on_a_malformed_json_sibling_record`（真实截断 JSON 兄弟记录走真实 list 路径，`create` 仍失败：code 空、parser 消息含 `at byte`）+ 放宽变异行 `unreadable-face-empty-code-loosened`（`"" => matches!(...)` 宽化为 `"" => true`）。

## 范围

只影响本地可写工程 `.tmp/chat-uploads` / `.tmp/chat-upload-leases` 的对抗性换链（FIFO / 设备链接 / 稀疏放大 / 同 inode 追加），以及「Rust 行为」fix-r3 条B 登记的一处正常路径分叉：`create` 对记录 JSON >64 MiB 的 manifest 新增 `UPLOAD_TASK_TOO_LARGE` 拒绝（TS 无对应——TS 侧照写并读回；复用既有码、新文案 `Upload manifest record exceeds the supported size.`，oracle 只把该码钉在 `Upload task exceeds its byte limit.`）。除该分叉外，正常路径（普通文件）可观察行为、既有错误码与 TS 可观察形状不变；`hash_file` 无产品调用点后删除。

本条目登记的行为分叉：三处兄弟位的 open 在**打开本身**拒绝窗口内换入的符号链接（ELOOP），而不是跟随它再由打开后绑定项回答。该分叉按协调者 2026-11-11 裁定（fix-r1，提交 68bc6f39b，决策卡 `_tmp/20261111-issue-2098/ruling-card-draft.md`）落地：六条 #1468/#1494 窗口测试的夹具与断言改形——四条身份形（`upload_read_at_record_renamed_after_open_is_rejected`、`multi_step_swap_across_all_windows_is_not_found`、`rename_after_open_is_not_found`、`upload_store_root_swapped_outside_project_is_not_a_second_home`）的窗口换入从符号链接改为指向上传目录/租约根外普通文件的硬链接（硬链是普通文件，加族 open 成功并落在外部 inode 上，与「链接被跟随」同构，只有 open 不再 ELOOP；`upload_store_root` 的 store-root 符号链接是被测主体，保留）；两条包含性形（`upload_read_at_metadata_swapped_between_canonicalize_and_open_is_rejected`、`upload_read_at_forged_record_cannot_reach_the_lease`）保留符号链接换入、断言改为 ELOOP 期望。fix-r2（MM sibling#3，探针 `_tmp/20261111-issue-2098/fix-r2/probe-rename-getpath.{py,rs}` 实测：POSIX rename 同 inode 两名是成功空操作；`F_GETPATH` 回答打开时用的名字、真换名后保持陈旧）再把三条带「改名盖叶」的测试改为真换名——换名对象与 leaf 不同 inode：`rename_after_open_is_not_found` 的拒绝项随之从句柄绑定项移到复验身份项（路径 stat 与句柄 fstat 不同对象），`approved-identity-dropped` 行改绑 `multi_step_swap_across_all_windows_is_not_found`（该变异体在新 `rename_after_open` 形状下存活）。外部字节仍从不进管线（拒绝只是提前或换个项）。两条 r1 死行重锚：`read-at-check-before-open` 为完整 pre-fix 形状（同一变异同时退回裸 `File::open`，使被突变项重新可达）；`read-at-handle-check-dropped` 于 fix-r3 条A 收窄为单因子（只钉句柄包含项：old 锚只删句柄包含项、new 为空串，见「Rust 行为」fix-r3 条A）。`content-open-failure-diagnosed` 锚随 callee 改写（既往口径，行名与所钉测试不变）。

仍余的窗口（本条目不放宽也不宣称关闭）：(1) 非 Unix 无 `O_NOFOLLOW`/`O_NONBLOCK`，换链被跟随、FIFO 仍阻塞（诚实残余，同租约侧）；(2) `open` 自身解析一次路径，调用方身份/内容项不再解析第二次（同 -002 口径）；(3) T2「打开后换路径」仍由 -002 登记的句柄绑定与残余清单拥有，本条目不动；(4) composer 读侧 `read_bounded` 的界不因本条目改变；(5) 记录附件 `path` 无包含性检查（本条目未引入也未收紧，MM concurrency#2）：伪造 `metadata.json` 的 `attachments[].path` 指向工程外文件并配上该文件的 bytes/sha256，verified 与租约 hard_link 全过，工程外字节经租约被内联——加族 open 只拒链接、不拒绝对路径；(6) `MAX_METADATA_JSON_BYTES` 是逐叶上限，无每工程/每调用聚合预算（本条目未引入，MM concurrency#3）：预置 N 个 64 MiB 稀疏记录叶即可让一次 `create`（listing）或周期清扫做 N×64 MiB 量级的读；(7) verify 侧（`verified` 的合并判式）类型项与长度项在读**非零**记录时重合——`info.len() != expected_bytes` 先拒，类型项不可单独证伪；零字节记录面（bytes=0 + 空摘要 + 无 writer FIFO 的 `O_NONBLOCK` 读返回 0）理论上可单独隔离类型项，未设行，按残余登记（fix-r2 P2a 如实口径）；(8) 写侧越界面——fix-r3 条B 只收 `create` 一侧，恰好 64 MiB 的合法记录仍可经后续 `mutate`→`write`（progress/complete 路径，`write` 无自己的上限）增长越过读界，成为本网关自己写下、自己 `read_at` 拒绝的记录（`mutate` 闸内重读失败被缓存进 uploadId 队列、清扫对不可读记录只 skip、listing 跳过使其移出幂等回放与并发计数）。该残余在 fix-r3 落地时已在源码注释登记（`upload/mod.rs` create 写侧上限注释末句），由协调者跟进单承接（#2976 同族；评审 2026-11-13 concurrency#1 / boundary#2、2026-11-14 regate MM concurrency#1 同题）。
