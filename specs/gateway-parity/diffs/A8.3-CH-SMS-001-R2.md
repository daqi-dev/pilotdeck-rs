## 类别

更正（判据登记措辞与覆盖形状，非差异变化）：`A8.3-CH-SMS-001-R1`
「机器判据」节有两条失实。

1. 「全部 55 个 oracle cell 每次运行都与 `oracle.json` 记录逐字节比较
   （正控）」——只有 54 个 cell 有重放表项；第 55 个
   `port-busy-preflight` 没有重放 cell，只为 `port_busy_preflight_fails_fast`
   提供被占端口。
2. 「逐字节比较」——重放比较的是解析后的 JSON 快照：两侧都是
   `serde_json::Value`，对象键序与序列化空白不参与比较，只有字段值参与。

`-R1` 原字节不动，本条按实测更正。同 A8.3-CH-SMS-004-R1 的同一形状
（#1339 fix-r3 评审 minimax sibling #1 / concurrency #2 / boundary #7，
Codex P2 #3，等级取高 P2）。

## 机器判据

`src/pilotdeck-gateway/src/channel/sms/tests.rs`：

- 55 个 oracle 用例中 54 个有 `replay_cases!` 重放 cell，每次运行都在
  注入 mock `SmsGateway` 下回放，并与 `oracle.json` 的 `expected` 做
  **解析后 JSON 值**比较（`negative_assert_eq!` 作用于
  `serde_json::Value`；键序与空白不参与，字段值逐字段比较）。响应按
  字节比较不成立，也不存在该判据。
- 第 55 个 `port-busy-preflight` 无重放 cell。它的 `expected` 在正常轮
  不被比较，但**并非任何轮次都不被比较**：`sms-port-preflight` 负控轮里
  `ensure_replay_port_free` 被关掉，`replay_named("port-busy-preflight")`
  的 `connect` 步由 `assert_responses_so_far` 按前缀比较，命中的正是该
  `expected.responses`（oracle 期望 `{"refused":true}`）。该轮次因此是
  这个 case 唯一被比较的地方，不能按「死重量」清空。
- 用例名集合由 `every_oracle_case_has_a_replay_cell` 机检：oracle 用例名
  == `REPLAY_CELL_NAMES` ∪ {`port-busy-preflight`}。`REPLAY_CELL_NAMES`
  由 `replay_cases!` 宏自身发射，与 cell 定义同源，不会各自漂移。
