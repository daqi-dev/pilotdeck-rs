## 类别

#1022 drain 期间保存的 checkpoint 丢失修复。保留 prepare 后的 recreate eligibility 检查，成功 drain 后再取最终 file_state 给新 HostToolCheckpoint 与 saved_files；消息、序号仍只从 storage.restore 恢复，不拿旧快照覆盖耐久状态。

## 基线依据

固定 TS cc7c4e6 / Node v22.22.0 实测：`session-factory/followups.mts` 用真实 stdio sidecar 与工具 gate，捕获时只有 seed.txt，drain 的 finally 保存后含 during.txt。金样 `oracle.json.followups`，原件 `_tmp/20261026-issue-1022/ts-followups/followups-raw.json`。TS ProjectSessionFactory.ts:170,188 提前捕获并沿用旧 fileState 的 factory 层结论是**读码推断，未独立实测整个真实 factory 与 stdio 组合**；不把底层 checkpoint 实测扩大成整个组合实测。

## Rust 行为

`runtime/session/factory.rs` 在成功 `previous.dispose` 后刷新 seed；`handle.rs::drained_file_state` 使用保留的 reload source。刷新失败先释放 prepared resources 再返回原错误，未创建 storage。

## 范围

只调整已允许重建的旧 session 在 drain 中保存的 file_state；完成前已 disposed 的旧 handle 仍拒绝重建，耐久消息仍从存储恢复。

## 机器判据

完整前缀 `runtime::session::factory::tests::`：`recreation_uses_file_state_saved_during_drain` 对照 TS 真实 drained.readFileState，经过生产 OwnedTurn::drop、SessionSubmission 活动归还和真实 factory recreate，验证新 seed 和工具 checkpoint 均保留读权限。测试使用确定性 started-turn 注入，不宣称完整模型 transport 验收。`cancelled_recreation_finishes_drain_and_candidate_cleanup` 验证取消 caller 后 owned 创建与候选清理；`failed_drained_seed_releases_prepared_resources` 验证最终 seed 读取失败的回滚；既有 never/timeout 格仍不得发布新 writer。

负控 `drain-file-state-not-refreshed`、`drain-turn-drop-seed-removed`、`drain-cancelled-candidate-not-disposed`，另 `followups-regeneration` 绑定 ignored `followups_regenerates_identically`，真实重采金样。提交后再编译与执行变异；当前不绕 HEAD 守卫。
