## 类别

双侧同状、无行动（登记类）。`/api/web/.../files/write` 的请求体在
**两侧**都没有字节上限：TS `readJsonBody` 逐 chunk 无界拼接后
`JSON.parse`，Rust `read_json_body` 同形；Node `IncomingMessage` 在
该路由无 body 上限。这不是 parity 偏差——两侧现状一致，本条登记
「无预算」这一事实本身，避免后续单侧加固悄悄制造新的对外错误形状
差异。#2354 把写路由挂上生产监听器后该事实首次在生产 HTTP 面成立，
故在此登记。

## TS 依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0。
TS `adapters/web/httpRouter.ts:132` `readJsonBody`：`for await (… of
request)` 逐 chunk `chunks.push` 后 `Buffer.concat` 全量拼接，
无 Content-Length 门、无累计上限。无界的同形先例已原文登记于
A8.3-WECOM-CALLBACK-BODY-LIMIT-001:17-18（TS `readBody` 同样无上限）。

## Rust 行为

`src/pilotdeck-gateway/src/api_web.rs:349` `read_json_body`：
`while let Some(frame) = body.frame().await` 逐帧
`bytes.extend_from_slice`，无预算门；读满后
`String::from_utf8_lossy` 一份、`parse_json` 一份，峰值内存约
2× 请求体。`/feishu/webhook` 的 `serve_with_body` 体读取
（`native_http.rs:173`）同形。持有有效 bearer 的客户端可用数 GiB
的 `Content-Length` 或 chunked 慢速发送把进程 RSS 推到 OOM——
与 TS 基线行为一致，因此不判 parity 偏差。

## 范围

仅 `/api/web/` 路由组的请求体预算（写路由实际读取体；tree/read/
projects 分支不读体）。**若未来任一侧单侧加预算**：Rust 单侧按
module-host 公网面先例（`INPUT_BUDGET` = 32 MiB，超限
`ReadError::OverBudget` → 413，`src/pilotdeck-gateway/src/
module_host.rs:87`/`:433`）将制造 TS 侧仍读满的对外错误形状差异，
属对齐决策——要么双侧同步加（产品变更），要么按有意硬化登记为
已接受差异；本条不构成任何一侧的授权或豁免。

## 机器判据

双侧同状，无单侧断言可钉。锚点为本条文件；任何一侧新增预算时，
该侧的既有 replay/钉死测试（api-web 79 格金样、`read_json_body`
调用路径）会出现未登记差异而变红，届时须新增 `<ID>-R<n>.md`
更正本条并按「范围」节的口径处理对齐。复算入口：
`cargo test -p pilotdeck-gateway --lib api_web`。
