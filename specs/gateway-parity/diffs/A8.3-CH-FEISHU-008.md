## 类别

不可避免（共享交互 helper 未移植）。TS 的飞书通道把 gateway 的
`elicitation_request` / `permission_request` 变成飞书消息发给用户，再把
用户在同一个 chat 里的下一条文本当成答复交回 gateway；Rust 侧的通道编排
（`InteractionPort` 的十六个方法、`answer_pending_elicitation` /
`answer_pending_permission`、待答期间的入站分流）都已就位，但
**生产装配传入的是 `no_interaction()`**：`elicitation_pending` /
`permission_pending` 恒为 `false`，capture 返回空，因此飞书用户既看不到
问题也交不回答复。

## 基线依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0。
`src/adapters/channel/feishu/FeishuChannel.ts:337-429`：
`elicitation.capture(...)` 取出问题并用 `send` 发到同一 chat，
`permissions.capture(...)` 同理（含 `permissionMode` 与 `requestId` 的去重、
多问题排队、答复确认文案）；两处都在入站消息进入 gateway 之前判定，
所以「待答时用户的下一条消息是答复，不是新 turn」。
helper 本体在 `src/adapters/channel/protocol/`（`ImElicitationHelper` /
`ImPermissionHelper`），由 wecom-callback 与 feishu 共用。

## Rust 行为

`src/pilotdeck-gateway/src/native_process/channels.rs:284`
（`make_feishu_with`）固定传 `crate::channel::feishu::no_interaction()`；
`src/pilotdeck-gateway/src/channel/im_interaction.rs` 的 `NoInteraction`
实现即「恒无待答」：`elicitation_capture` 返回 `String::new()`、
`permission_capture` 返回 `None`、`*_pending` 恒 `false`。
通道侧分支已按 TS 接好：`channel/feishu/mod.rs` 的
`process_inbound_messages` 先查 `elicitation_pending` / `permission_pending`
再决定是答复还是新 turn，`try_handle_pending_interaction` 负责权限答复的
`permission_answering` 记账与并发占用，`answer_pending_*` 复刻确认文案与
排队。但这些分支在生产装配下永远走不到（`NoInteraction` 恒无待答），
它们本身也没有组件钉子——现阶段没有任何用例驱动过这条路径。

## 范围

仅生产装配的交互 helper：飞书侧的提问投递、答复捕获、答复确认与排队，
以及因此产生的行为差异——需要权限确认或 elicitation 的 turn 在飞书侧
既没有提示也不会被答复（该 turn 在 gateway 自己的超时/中止路径结束，
而不是被用户答复推进）。不覆盖通道侧编排（已接好但无判据，见下）、不覆盖
wecom-callback 的同名缺口（其车道另登记）。本条不构成判分豁免。

## 机器判据

- 生产实现为零：`NoInteraction` 让两条 `*_pending` 恒为 `false`，
  `process_inbound_messages` 因此总是走 gateway 分支，可判据的只有
  「装配确实使用 NoInteraction」（`make_feishu_with` 的构造点）。
- 通道侧交互分支无判据：金样矩阵、组件钉子与负控矩阵都不驱动
  `elicitation_pending` / `permission_pending` 为真的路径。移植共享
  helper 时必须同时补 (a) 脚本化 `InteractionPort` fake 驱动的编排钉子
  （待答文本走 answer 而非 submit、确认文案、`permission_answering` 的
  占用与释放），(b) 真实装配路径「发出问题 → 用户答复 → turn 继续」的
  回环用例，并把本条目改为已对齐。
