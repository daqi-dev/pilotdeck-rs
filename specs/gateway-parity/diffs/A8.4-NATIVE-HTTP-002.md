## 类别

解析层差异（已接受，原生监听器 opt-in 期间）：#1209 fix-r1 对齐 scheme
纯字母、非 ASCII target 字节、方法表后，fix-r2 实测 Node v22.22.0 的真实
上限语义并按其复刻：头数上限不存在（钉死 16384 为解析分配上界，先于
预算永不生效），单"行"上限实为报文级 URL span + 全部头名 span + 全部
头值 span 的累计预算（分隔符与 CRLF 不计；头值前导 OWS 跳过、**尾随
OWS 计入**——fix-r3 探针 `probe-fixr3-c.out` C1 修正 fix-r2 的"OWS 不计"
表述），恰达 16384 即触发罐装 431（含边界，非超过）。仍无法经 hyper
公开 API 消除的差异剩 1 类（请求 target 字符集），另有预算复刻的 4 个
边界残余（fragment 剥离、OWS 填充下 hyper 读缓冲 408 KiB 上限先行、
头值尾随 OWS 被 httparse 折叠后少计、绝对形式空路径 target 重渲染多计
1 字节）。差异只影响金样矩阵之外的输入（矩阵内 88 cell 归一化后路由
语义一致，见 A8.4-NATIVE-HTTP-001），已按当前 Rust 行为钉死，不构成
对拍豁免。

## 基线依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0，
真实 `GatewayServer.ts` 原始 socket 探针（#1209 fix-r2/fix-r3 证据目录
`_tmp/20261026-issue-1209/fix-r2/probe/`、
`_tmp/20261026-issue-1209/fix-r3/probe/`，`probe-fixr2.out`、
`probe-fixr2-b2.out`、`probe-fixr2-c2.out`、`rust-residual-probe.out`、
`probe-fixr3-c.out`、`probe-fixr3-c3.out`）与 Node 源码语义
（`node_http_parser.cc` `TrackHeader`：`on_url`/`on_header_field`/
`on_header_value` 按 span 长度累加，达 `max_http_header_size`（默认
16 KiB，node_options.h）即 HPE_HEADER_OVERFLOW）：

1. 头数：2049/2500/8000 个 `a: b` 小头均 200（8000 头时 tracked 16020，
   尚未触预算）；Node `maxHeadersCount` 为 null，无头数上限。
2. 报文级预算：单头 `x:` 值 16362（tracked 16383）→ 200，16363（tracked
   16384）→ 431（含边界；`probe-fixr2-b2.out` 与 `probe-fixr3-c.out` C1
   双侧复核）；头名长度等量计入（name-4-value-16360 → 431、
   name-1-value-16360 → 200，`probe-fixr3-c.out` C2）；URL span 同界
   （`/health?x=` + 16360 → 200、+ 16361 → 431；20 KiB URL → 431）。
   431 为罐装字节 `HTTP/1.1 431 Request Header Fields Too Large\r\n
   Connection: close\r\n\r\n`，无 Date、无 body，连接关闭（C 段）。
3. OWS 计法（`probe-fixr3-c.out` C1）：头值**尾随** OWS 计入（16350 值 +
   13 空格 → tracked 16384 → 431；+ 12 空格 → 200；16349 + 14 空格 →
   431），**前导** OWS 跳过（13 空格 + 16362 值 → 200）。分隔符与 CRLF
   不计。
4. 头数上界（`probe-fixr3-c.out` C4）：1 字节头名 + 空值的 `a:` 小头，
   16363 个（tracked 20+16363=16383）→ 200，16364 个（tracked 16384）→
   431——可服务头数的真实上界，也是计数上限 16384 的取值依据。
5. 绝对形式空路径 target（`probe-fixr3-c3.out`）：`GET http://h HTTP/1.1`
   的 URL span 为线上 8 字节（`http://h`），value-16361 时 tracked 16383
   → 正常 404 路由应答。
6. 预算先于分发表、后于 target 文法：20 KiB CONNECT authority → 431
   （预算在 CONNECT 销毁之前判定）；20 KiB authority-form（非 CONNECT）与
   20 KiB 非字母 scheme absolute-form → 裸 400（文法错误先于预算）
   （`probe-fixr2-e.out`）。

## 已复刻项（不属本条残余）

scheme 必须全 ASCII 字母、非 ASCII target 字节裸 400（fix-r1，handler 层
复刻）；`max_headers(16384)`——空值小头每个只占 1 个预算字节（头名），
实测可服务上界 16363（第 4 点），计数上限 16384 是不先于预算生效的最小
取值，只为约束 hyper 单次解析的 smallvec 分配（压到 3000 会使 TS 服务
的 8000 头请求 431，负控 `native-http-header-cap-low` 钉死）；报文级
span 预算在 handler 复刻（`tracked_header_bytes`：`uri().to_string()` +
头名 + 头值，达 16384 → 罐装 431，含边界），预算判定置于 CONNECT 销毁
之前、target 文法之后，次序按第 6 点实测。

## Rust 行为

`src/pilotdeck-gateway/src/http_proxy.rs`：`http1::Builder` 设
`max_headers(16384)`。`src/pilotdeck-gateway/src/native_http.rs`：scheme、
target 字节、span 预算在 handler 层复刻。残余差异的当前行为（均已双侧
实测）：`?x=<` → 400（TS 200）；16400 字节 fragment target → 200（TS
431，`http::Uri` 剥离 fragment 致 tracked 少计）；500 KiB OWS 单头 →
hyper 读缓冲（约 408 KiB）先行报"message head is too large"回 431（TS
200，Node 不计 OWS，500 KiB 空格单头实测 200）；头值尾随 OWS 预算等值
但 httparse 折叠尾随 OWS 后 Rust 少计（16350 值 + 13 空格：Rust 200 /
TS 431，`probe-fixr3-c.out` C1 与 `header_budget_431s_like_ts` 钉死）；
绝对形式空路径 target `http://h` 的 URL span 线上 8 字节，Rust 侧
`uri().to_string()` 重渲染为 `http://h/`（9 字节）多计 1 字节（value-
16361：Rust 431 / TS 404，`probe-fixr3-c3.out` 钉死）。

## 范围

仅 opt-in 的 `NativeWsServer` 非升级分支解析层；不改默认代理路由
（`serve_connection_with` 不设 `max_headers`，代理字节不变）。差异只
影响金样矩阵外输入；若后续版本对齐（如 hyper 暴露字符集/尺寸配置），
需同步更新钉死测试与本条，金样矩阵本身不含这些 cell。同源 sibling
`A7.4-HTTPSTORE-431-408-SHAPE-001-R3`（`user_dialog/http_store.rs`）对
Node 预算采用按头行字节的另一口径，属该条自身登记；本条的 span 口径
（头名/头值/URL span 累加、分隔符与 CRLF 不计）由 fix-r3 探针逐项钉死
（头名差 3 字节改变结果、8000 小头 tracked 16020 在预算内），两条登记
以各自探针为准，本轮不改 A7.4。
