## 类别

解析层差异（未批准，非已接受差异；待批）：#1209 fix-r1 对齐 scheme 纯字母、
非 ASCII target 字节、方法表后，fix-r2 实测 Node v22.22.0 的真实上限语义并
按其复刻：头数上限不存在（钉死 16384 为解析分配上界，先于预算永不生效），
单"行"上限实为报文级 URL span + 全部头名 span + 全部头值 span 的累计预算
（分隔符、OWS、CRLF 不计），≥16384 触发罐装 431。仍无法经 hyper 公开 API
消除的差异剩 1 类（请求 target 字符集），另有预算复刻的两个边界残余
（fragment 剥离、OWS 填充下 hyper 读缓冲 408 KiB 上限先行）。差异只影响
金样矩阵之外的输入（矩阵内 88 cell 归一化后路由语义一致，见
A8.4-NATIVE-HTTP-001），已按当前 Rust 行为钉死，不构成对拍豁免。

## 基线依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0，
真实 `GatewayServer.ts` 原始 socket 探针（#1209 fix-r2 证据目录
`_tmp/20261026-issue-1209/fix-r2/probe/`，`probe-fixr2.out`、
`probe-fixr2-b2.out`、`probe-fixr2-c2.out`、`rust-residual-probe.out`）
与 Node 源码语义（`node_http_parser.cc` `TrackHeader`：`on_url`/`on_header_
field`/`on_header_value` 按 span 长度累加，≥`max_http_header_size`
（默认 16 KiB，node_options.h）即 HPE_HEADER_OVERFLOW）：

1. 头数：2049/2500/8000 个 `a: b` 小头均 200（8000 头时 tracked 16020，
   尚未触预算）；Node `maxHeadersCount` 为 null，无头数上限。
2. 报文级预算：单头 `x:` 值 16362（tracked 16383）→ 200，16363（tracked
   16384）→ 431（`probe-fixr2-b2.out` 精确边界；`probe-fixr2.out` B 的
   value-16350→200 / value-16372→431、URL-16350（tracked 16373）→200 /
   URL-16371→431 同界）；头名长度等量计入（name-12-value-16372 与
   name-1-value-16372 均 431）。431 为罐装字节
   `HTTP/1.1 431 Request Header Fields Too Large\r\nConnection: close\r\n
   \r\n`，无 Date、无 body，连接关闭（C 段）。
3. 预算先于分发表、后于 target 文法：20 KiB CONNECT authority → 431
   （预算在 CONNECT 销毁之前判定）；20 KiB authority-form（非 CONNECT）与
   20 KiB 非字母 scheme absolute-form → 裸 400（文法错误先于预算）
   （`probe-fixr2-e.out`）。

## 已复刻项（不属本条残余）

scheme 必须全 ASCII 字母、非 ASCII target 字节裸 400（fix-r1，handler 层
复刻）；`max_headers(16384)`——头名至少占 1 个预算字节，故任何可服务请求
至多约 16377 个头，计数上限 16384 先于预算永不生效，只为约束 hyper 单次
解析的 smallvec 分配；报文级 span 预算在 handler 复刻（`tracked_header_
bytes`：`uri().to_string()` + 头名 + 头值，≥16384 → 罐装 431），预算判定
置于 CONNECT 销毁之前、target 文法之后，次序按第 3 点实测。

## Rust 行为

`src/pilotdeck-gateway/src/http_proxy.rs`：`http1::Builder` 设
`max_headers(16384)`。`src/pilotdeck-gateway/src/native_http.rs`：scheme、
target 字节、span 预算在 handler 层复刻。残余差异的当前行为（均已双侧实
测）：`?x=<` → 400（TS 200）；16400 字节 fragment target → 200（TS 431，
`http::Uri` 剥离 fragment 致 tracked 少计）；500 KiB OWS 单头 → hyper
读缓冲（约 408 KiB）先行报"message head is too large"回 431（TS 200，
Node 不计 OWS，500 KiB 空格单头实测 200）。

## 范围

仅 opt-in 的 `NativeWsServer` 非升级分支解析层；不改默认代理路由
（`serve_connection_with` 不设 `max_headers`，代理字节不变）。差异只
影响金样矩阵外输入；若后续版本对齐（如 hyper 暴露字符集/尺寸配置），
需同步更新钉死测试与本条，金样矩阵本身不含这些 cell。
