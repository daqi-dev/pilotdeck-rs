## 类别

解析层差异（未批准，待批）：#1209 fix-r1 将原生监听器非升级分支能对齐
llhttp 的解析规则对齐后（scheme 纯字母、非 ASCII target 字节、方法表、
头数上限），仍无法经 hyper 公开 API 消除的解析层差异，共 2 类：请求
target 字符集、请求头/URI 尺寸上限。两类差异只影响金样矩阵之外的输入
（矩阵内 88 cell 路由语义逐字节一致，见 A8.4-NATIVE-HTTP-001），已按
当前 Rust 行为钉死，不构成对拍豁免。

## 基线依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0，
真实 `GatewayServer.ts` 原始 socket 探针（#1209 fix-r1 证据目录
`_tmp/20261026-issue-1209/fix-r1/probe/probe-fixr1.out`，C 段）：

1. target 字符集：llhttp 接受 `<`、`>`、反引号（`GET /health?x=<`、
   `GET /a<b>` 均 200），`http::Uri` 拒绝这些字节，hyper 在连接层
   直接 400（未到 handler）。
2. 尺寸上限：Node v22.22.0 无头数上限（`maxHeadersCount` 为 null，
   8000 个 2 字节名小头通过），实际约束是请求行+头名+头值合计约
   16384 字节（观测通过上限 16307、失败下限 16391），20 KiB 单头与
   20 KiB URI 均 431。hyper `max_buf_size` 默认约 408 KiB、URI 上限
   65534，20 KiB 头与 20 KiB URI 均 200。

已对齐项（不属本条差异）：scheme 必须全 ASCII 字母（`a1://`、`ab+c://`
双裸 400）、非 ASCII target 字节裸 400、`max_headers(2048)`（hyper 默认
100 会 431 请求 TS 服务的 2001 小头请求；2048 为缓冲分配开销与覆盖
范围之间的折中，llhttp 实际无上限）。

## Rust 行为

`src/pilotdeck-gateway/src/http_proxy.rs`：`http1::Builder` 设
`max_headers(2048)`；`http::Uri` 解析失败时 hyper 连接层回 400 并关
连接，handler 不可见。`src/pilotdeck-gateway/src/native_http.rs`：
scheme 纯字母、target 字节（authority 与 path-and-query 两部分）在
handler 层复刻 llhttp 裸 400。两类残余差异的当前行为由钉死测试断言：
`?x=<` → 400（TS 200）、20 KiB 头/URI → 200（TS 431）。

## 范围

仅 opt-in 的 `NativeWsServer` 非升级分支解析层；不改默认代理路由
（`serve_connection_with` 不设 `max_headers`，代理字节不变）。差异只
影响金样矩阵外输入；若后续版本对齐（如 hyper 暴露字符集/尺寸配置），
需同步更新钉死测试与本条，金样矩阵本身不含这些 cell。

## 机器判据

`src/pilotdeck-gateway/src/native_http/tests.rs`：
`angle_bracket_target_stays_pinned` 钉死 `?x=<` 的 hyper 400；
`parse_size_limits_stay_pinned` 钉死 20 KiB 头/URI 的 200；
`header_counts_within_ts_bounds_stay_served` 钉死 150 小头 200。
`negative_controls.py` 的 `native-http-header-count-off` 开关绑定
150 小头测试（关掉 `max_headers(2048)` 后 hyper 默认 100 会 431）。
TS 侧行为依据为 fix-r1 探针输出（证据目录，不进提交）。
