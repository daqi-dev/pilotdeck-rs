## 类别

bug 修复：强制 persistence 既有「同路径单活跃 writer」契约，防止独立序列缓存向同一日志写出重复 sequence。

## 基线依据

cc7c4e6 `src/session/persistence/JsonlSessionPersistence.ts:20-38` 无排他锁。本轮 Node v22.22.0 直接 import JsonlSessionEventStore，同一路径各 restore 一次后依次 append，实测两个成功写入的 sequence 为 `[1,1]`、parentEntryId 为 `[null,null]`；原始输出 `_tmp/20261025-issue-587-pkg2-fix-r1/ts-probe.log`，探针同目录 `ts-probe.mjs`。

## Rust 行为

PersistenceResources::create_session 在 read/restore 之前调用 JsonlTranscriptStore::open_locked，复用 JsonlLedgerStore 的 LedgerLock::acquire：解析 canonical path，再独占稳定的 `<path>.lock` inode；竞争返回 RecorderError::Store(LedgerError::Io(WouldBlock))，不会发布第二个 writer。锁存在 store 内，随最后一个持有它的 recorder/writer/SessionRecording 释放；不能只依赖 SessionRecording 的 Drop。失败恢复自动释放锁，锁文件保留供后续竞争复用。

## 范围

同进程共享 project resource、跨 project generation 及使用该锁协议的 Rust 进程；与 JsonlLedgerStore 互斥。None 的 memory-only recorder 不加锁，不同路径可并存。create_session 现在会创建缺失的父目录和私有 .lock 文件，并把 canonical path 用于读写与诊断消息（别名路径可能被规范化）。叶软链接若目标不存在则返回 Io(NotFound)，不允许借别名获取第二把锁；普通缺失文件仍可创建。普通 JsonlTranscriptStore::new、自带 TranscriptStore 的 adapter、TS writer 不参与此锁，不承诺对其排他；硬链接别名和外部移动/删除/替换锁文件或路径不受保护。沿用 A6.2-TRANSCRIPT-LOCK-001 的切换约束：先停旧 writer、不对 transcript 建硬链接。本入口另要求 writer 存活时不替换路径，此项不借用旧条目批准。

## 机器判据

`persistence_concurrent_open_publishes_exactly_one_writer` 真线程 Barrier 并发打开，只发布一个 writer，失败为 WouldBlock；释放后恢复真实日志。`persistence_writer_lock_spans_generations_aliases_and_writer_clones` 覆盖缺失文件、字面别名、Unix 软链接、实际 generation 切换、ledger 双向互斥、SessionRecording 丢弃后 clone 继续持锁和写入，最后释放后从已有 sequence 恢复。`persistence_dangling_symlink_cannot_acquire_a_separate_writer_lock` 覆盖叶链接目标缺失时的明确拒绝，以及目标建好后的争用和释放恢复。既有 session 隔离、memory-only、restore 失败和 ledger lock 测试一并回归。行为负控丢弃 owner 后锁断言失败，原始输出见本轮 `mutation-results.json` 及 red/green 日志。
