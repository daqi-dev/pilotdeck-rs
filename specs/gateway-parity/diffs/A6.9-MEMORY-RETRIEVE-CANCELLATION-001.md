## 类别

运行机制差异：Rust 超时后释放 retrieve future；TS 通过 AbortSignal 请求取消，但 Promise.race 不释放底层尚未完成的 Promise。属于已有 memory builder 在本包首次接到资源组合时显现的边界，未改冻结尺子。

## 基线依据

cc7c4e6 `src/context/memory/MemoryAttachmentBuilder.ts:27-88` 使用 AbortController 与 Promise.race。直接 import 实测见 `_tmp/20261025-issue-587-pkg1/ts-probe.mjs`、`06-ts-probe-final.log` 的 `provider-ignores-abort`：超时返回空 attachments 和 warning，signal 已 aborted；释放忽略取消的 provider 后它仍完成。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/context/memory.rs` 的 `build` 在 timeout 分支取消实际输入 signal，然后 drop 未完成的 retrieve future。diagnostic 和附件结果与该 TS 探针相同；若 provider 自己另起后台任务，drop future 不承诺终止其独立任务。

## 范围

只涉及 resolver 的异步工作寿命；默认 30000ms、规范化覆盖值、project_root、错误 warning 与外部取消的可观察结果由资源到会话调用链检验。没有把停止任意外部 provider 副作用列为保证。

## 机器判据

`src/pilotdeck-gateway/src/runtime/project/factory_memory_tests.rs` 的 `context_memory_default_and_normalized_override_timeout_cancel_and_drop_retrieve` 同时断言 deadline 前未取消、到点已取消、pending future 已 drop、无成功 attachment 且有 warning；parent abort 和成功提前完成分别有测试。命令与变异负控在 `_tmp/20261025-issue-587-pkg1/RESULT.md`。
