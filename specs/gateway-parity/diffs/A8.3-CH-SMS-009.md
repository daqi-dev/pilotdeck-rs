## 类别

bug 修复（有意偏离 TS 基线的失败路径早退语义）：`#1790`。sms permission 的
`release_answer`（TS `releaseAnswer` 的同形移植）在「确认消息未送达 /
panic / 取消 / 超时」时若 `pending` 里还有一条新捕获的 permission，会走
`confirm_answer` 的 `pending` 早退分支，`answering` 从此永久残留：该 chat
之后的每条消息在 `begin_answer` 都落到 `BeginAnswer::None` 被静默丢弃，
网关也一直在等那条从未展示给用户的 permission。Rust 侧在异常退出（Drop
守卫）与 `!delivered` 分支改走 `recover_answer`：先按原语义调
`release_answer`，仍残留时把 `pending` 队首提升为 `next_prompt` 并置
`retry_prompt_pending`，下一条消息重发提示。队列为空时两函数行为完全相同，
普通路径的消息字节零改动。

## 基线依据

固定基线 `cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85`，Node v22.22.0 / ICU 78.2。
TS 侧 sms permission helper 的源码不在本仓（`#1339` 只带了对拍 oracle 与
探测记录），因此「TS 在等价交错下是否同样早退」未实测：可从 Rust 侧
`src/pilotdeck-gateway/src/channel/sms/permission.rs` 的 `release_answer` /
`confirm_answer` 逐行镜像关系推断（两者注释均标明对应 TS
`releaseAnswer` / `confirmAnswer`），但本条不把推断当实测。若后续拿到 TS
源码实测同样残留，本条就从「偏离基线」降级为「修掉基线同病」，其余文字
不变。

## Rust 行为

`src/pilotdeck-gateway/src/channel/sms/permission.rs` 的
`ImPermissionHelper::recover_answer`（`release_answer` + 队首提升）由
`PromptGuard::drop`（panic / 取消 / 超时）与
`src/pilotdeck-gateway/src/channel/sms/mod.rs` 的 `deliver_answer`
`!delivered` 分支调用。正常返回、状态文案分支、错误返回
（`fail_answer`）仍走各自原有的显式复位，不经过 `recover_answer`。
`A8.3-CH-SMS-001-R11` / `-008-R8` 只登记负控开关形状（66 → 69），与本条
分开；本条不改变任何 oracle cell 的期望字节。

## 范围

仅限「一次 answer 已进入收尾、`answering` 仍持有，期间又有新 permission
被 `capture` 入队」这一个交错：确认消息发送 panic / 任务取消 / 调用方超时 /
`send_reply` 返回 false 四条退出。用户可见差异只有一种：修复前 chat 永久
卡死不响应，修复后下一条消息重发那条排队中的提示。`pending` 为空的失败
路径逐字节不变（oracle cell `permission-confirmation-send-fail` 钉死）。

## 机器判据

`src/pilotdeck-gateway/src/channel/sms/tests.rs`：
`a_permission_captured_during_the_confirmation_send_is_not_dropped`（panic）、
`an_undelivered_confirmation_does_not_lock_the_chat`（`!delivered`）、
`a_panicking_confirmation_send_does_not_lock_the_chat`、
`cancelled_confirmation_send_does_not_lock_the_chat`、
`timed_out_confirmation_send_does_not_lock_the_chat`。负控
`sms-permission-prompt-guard-off`（`channel-sms/negative_controls.py`）把
`PromptGuard::drop` 变成空操作后，位于 Drop 路径的四条（两条 panic、取消、
超时）全部变红（`_tmp/20261106-issue-1790/negctl-1790-rebase-pack/`）。
`!delivered` 与队首提升尾巴不在 Drop 路径上，二者**没有专属变异开关**，
目前只由上述回归用例守住（跟进单 #1905 负责补 `sms-permission-recover-off`）；
`--check` 的 69 条绑定自检只覆盖锚点/绑定形状，不覆盖该分支的语义。
