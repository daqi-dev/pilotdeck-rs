## 类别

不可避免（宿主系统 TZ 数据源约束；失败形态是有意选择的 fail-closed）。#1324
的 once 调度解析沿用既有分层：规则 = Node v22.22.0 V8 日期解析器端口
（`pilotdeck-transport::parse_node22_date_with_local`），无时区后缀的本地墙钟
串的本地规则 = 进程 TZ 的系统 TZif（`resolve_local` → 与已上线
`get_current_time` 工具同一通路）。TS 基线里 Node 日期解析自带 ICU-local，
本地墙钟串永远可解析；Rust 侧当进程 TZ 在宿主 zoneinfo 树不可解析（同
A8.3-CRON-TZ-ALIAS-001 的数据缺口：legacy 别名进程 TZ + 缺 backward 链接的
宿主，或 `TZ` 指向不存在的 zone 名）时构造失败。该缺口在既有「不内嵌 tzdata
规则」约束下无法消除；对缺口的行为选择——失败时 fail-closed 返回 `undefined`
而不是抛错或猜一个时刻——是有意为之，与 `system_clock.rs` 头注既有立场一致。

## 基线依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0 / ICU 78.2。
`src/cron/runtime/CronSchedule.ts:20-35`（`computeNextRunAt` 的 once 臂把
`runAt` 交给 `new Date(runAt)`，无后缀串按进程 TZ 的本地墙钟解析，Node 内置
ICU-local 使其在任何 `TZ` 下都不失败）、`src/scheduler/utils/parseDate.ts` 同
通路。实测原件（cb8，Node v22.22.0 / ICU 78.2）：`TZ=UTC0` 下
`new Date('2026-03-05T09:30:00').toISOString()` 为
`2026-03-05T09:30:00.000Z`（探针与原始输出在 #1324 fix-r1 轮目录
`_tmp/20261026-issue-1324/fix-r1/probe/once-local-wall.*`；一行复现：
`TZ=UTC0 node -e "console.log(new Date('2026-03-05T09:30:00').toISOString())"`）。
macOS 系统 zoneinfo 树含 backward 链接，常见 legacy 进程 TZ 不触发；`TZ` 为
记录名单外任意串时两侧都走各自的后备（Node 静默当 UTC，Rust fail-closed，
见下）。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/cron/schedule.rs` 的
`once_computed_run_at`：`parse_node22_date_with_local(run_at, &resolve_local)`
在 `runAt` 是无时区后缀的本地墙钟串且进程 TZ 的系统 TZif 不可解析时返回
`Err`，映射为 `Ok(ComputedRunAt::Undefined)`，即 `computeNextRunAt` 层的
`undefined`。`resolve_local`（`src/pilotdeck-transport/src/system_clock.rs`）
与 `ZonedPartsResolver` 共用 `timezone_tzif`（先精确后大小写不敏感匹配、
canonicalize 防逃逸），系统数据版本由宿主决定。带时区后缀（`Z` /
`±HH:MM`）的 `runAt` 与日期 only 串（按 UTC）不受本条影响——这两类不查
进程 TZ，与 TS 逐格一致（金样在
`tests/fixtures/cron-schedule/oracle.json` 的 once 格）。

## 范围

#1324 新增的未接线调度计算组件（接线在 #1325），差异表现：进程 TZ 在宿主上
不可解析时，once 任务的 `computeNextRunAt` 返回 `undefined`（TS 算出日期）；
接线后表现为该任务不被调度，不是错误、不静默换时区。接线前置约束（#1325，
与 A8.3-CRON-TZ-ALIAS-001 同一条）：`ComputedRunAt::Undefined` 同时承载
「`runAt` 串不可解析 / 366 天内永不匹配 / 宿主缺 tzdata」三种来源，调用方
不得把它当作「无后续运行」落盘终止任务，否则换宿主装上 tzdata 后任务不会
恢复。宿主相关：同一台机器装上 tzdata-legacy（或 macOS + 常见 TZ）即与 TS
一致。不属于本条：`runAt` 串本身的 V8 解析语义（与 TS 逐格一致，金样
`once/*` 格）；进程 TZ 是 legacy 别名 zone 时的规则数值（同
A8.3-CRON-TZ-ALIAS-001 的版本漂移保留子集，本条不宣称）。

## 机器判据

`src/pilotdeck-gateway/src/runtime/cron/schedule_tests.rs`：
`once_local_wall_unresolvable_fails_closed`（注入恒 `Err` 的 local 解析器，
钉死「进程 TZ 解析失败 → `Undefined`」的 fail-closed 分支本身，不依赖宿主
缺 zone 文件）。金样的 once 格只带宿主无关的 `runAt`（Z-/offset 后缀、
date-only、非法串），不依赖进程 TZ，故金侧重放不钉本条；解析成功侧
（`resolve_local` → TZif）由 `pilotdeck-transport` 的
`system_clock.rs` 测试钉死（含 `parse_node22_date_with_local` 的本地墙钟
用例）。
`tests/fixtures/cron-schedule/negative_controls.py` 的
`once-local-wall-guessed-utc` 行负控钉死该分支（把 `Err` 猜成 epoch 0 的
变体必须被上述测试按专用消息杀掉）。宿主相关的原始证据为 cb8 一次性探针
（上列 fix-r1 轮目录原件），无自动化复跑；换宿主重跑该一行复现即可。
`regenerates_identically("cron-schedule")` ignored 守卫重生成完整金样。
