## 类别

修正 R2 的默认工厂 telemetry 契约。carrier 表示差异延续原条目；不增加判分豁免。

## 基线依据

cc7c4e6 的 `src/context/memory/createEdgeClawMemoryProviderFromConfig.ts:65` 将宿主 telemetry 交给 service runtime，并在同文件 provider 构造时透传。Node v22.22.0 的真实源探针现以 `src/telemetry/collector.ts` 创建禁用外发、隔离 pilotHome 的宿主客户端；`edgeclaw-native-default/oracle.json` 的 `host-telemetry` 格记录成功构造。原始输出见 `_tmp/20261026-issue-778/fix-r1/generate-runtime.log`。

## Rust 行为

`runtime/memory/edgeclaw/factory.rs` 对 `MemoryTelemetry` 调用已移植的接口。其它 opaque `TelemetryClient` 没有可调用的 Rust vtable，默认工厂按本轮任务授权降级为无原生遥测，仍发布 memory、maintenance、management，不再返回空消息 `JS_HOST_REQUIRED`。carrier 与注入工厂仍保留原对象。

## 范围

仅更正 R2 的“其他不支持的对象显式返回宿主边界错误”。未知 opaque 客户端的事件转发没有实现，不能把成功构造解释为这些事件与 TS 对齐；`MemoryTelemetry` 的已有 M21 遥测回放继续适用。

## 机器判据

`factory_config_matrix` 回放真实宿主客户端格；`memory_native_default`、项目工厂的 `memory_native_default_publishes_three_handles` 携带 opaque 宿主对象且不注入工厂；前者以 `native-opaque-telemetry-rejected` 负控绑定专属失败消息。可调用 wrapper 的事件由原 M21 / E2E 回归守护。

## 批准记录

本轮 #778 fix-r1 用户明确允许“无法适配时降级为无遥测而非失败”，据此执行。未修改冻结判分语义，不增加机器判据豁免；原条目的其它批准状态不变。
