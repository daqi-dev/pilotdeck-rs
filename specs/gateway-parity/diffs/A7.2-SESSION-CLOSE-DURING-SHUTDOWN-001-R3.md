## 类别

更正（缺陷已修复）：R2 交付后的 r2 评审发现两处未闭合缺口，由 #1245 fix-r2 修复
并登记——① `shutdown()` drain 清单对「有未结算 closing 条目的 key」的 skip 只有
单 key 用例，`continue` 回归为 `break`（其余 record 不再排空、record 永久滞留
`state.records`）时现有测试与负控全绿；② shutdown 的 per-key drain 是裸
`tokio::spawn`（R2 已登记的 panic 限制），且 close/idle 任务在**释放同 key
serial ticket 之后**才结算自己的 closing 条目，该窗口内排队的同 key
`get_or_create` 可发布新 record，随后的 `shutdown()` 会因条目未结算而 skip 该 key，
新 record 既不进 drain 清单也无人 dispose（泄漏，concurrency/boundary 评审各判
P2）。本条登记修复与机器判据。

  仅一次 dispose，`evict:a:closed`——Rust 加强用例第一相的 TS 依据。
- `close-during-creation.out`（close 落在创建在途、record 未发布时）：TS close
  立即 fulfilled（else 分支 `await undefined`），创建随后照常发布、record 存活到

  A7.2-SESSION-RECREATE-DRAIN-001 的已登记有意差异，加强用例第二相断言的是
  该差异的 Rust 行为，非 TS 行为。

  「record 发布于条目未结算窗口」；Rust 修复恢复同一不变量（见下），无需 TS 探针
  复现窗口本身。

## Rust 行为

#1245 fix-r2，`runtime/session/owner.rs` 三处：

- **drain 守卫**：per-key drain 改走 `cleanup_task::spawn_with_error`（与
  close/idle/shutdown 外层同一完成守卫），结果经 `wait_result(drain_done.subscribe())`
  收进聚合。drain panic 时守卫以 dropped error 结算该 key 的 closing 条目：聚合仍
  拒绝（含该错误），后续 record-less `close(key)` 视条目已结算、落回
  shutdown 分支答 Ok（= TS 关停后 `await undefined` fulfilled）。R2 登记的
  「panic 后 close 答 lifecycle-stopped」限制随之闭合。
- **settle-before-release**：close 任务与 idle sweep 任务在自己的 closing 条目
  结算后**才**释放同 key serial ticket（结算调用移入持有 ticket 的任务体内）。
  由此「ticket 已释放 ⇒ 该 key 的 closing 条目已结算」，排在 ticket 后的
  `get_or_create` 发布的新 record 不可能落在「条目未结算」窗口内，`shutdown()`
  的 skip 不再可能因此漏排空该 record。该交错窗口位于两段无 await 代码之间
  （ticket Drop 与 Completion::finish），仅多线程抢占可触发，无法确定性复现；
  修复为不变量收紧，由既有 D1/D2/C1/B2/B4 全窗口用例回归。
- `unsettled_closing` 注释改写为登记新不变量；`shutdown()` 的 skip 分支本身
  （fix-r1）不变。
