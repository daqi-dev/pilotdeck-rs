## 类别

不可避免（已退役）。原条目登记的是「重复 sequence 组里出现含孤代理的 createdAt 时拒绝并要宿主作答」这一实现限制；#132 把该排序切到 vendored `compare_utf16_preserving_surrogates` 后，本机即可给出 Node 的顺序，拒绝分支整体删除。本更正登记差异退役与判据替换，不改变原条目其它结论。

## 基线依据

原条目的运行时前提仍成立并已用真实入口复核：`resources/PilotDeck/src/session/transcript/TranscriptReader.ts` 对相同 sequence 用 `left.createdAt.localeCompare(right.createdAt)` 升序。本单新增真实 TS 金样 `src/pilotdeck-gateway/tests/fixtures/transcript-collation/oracle.json`，由 Node v22.22.0 / ICU 78.2 直接调用基线 `readTranscript` 生成（生成器 `generate.mts` 内 `assert.equal(process.version, 'v22.22.0')` 与 `assert.equal(process.versions.icu, '78.2')`），记录两组同 sequence 输入的真实 `entries`，按码位写：`U+10000 → U+D800 → U+E000 → U+FFFD`，以及 `U+D800 → U+D801 → U+DC00`（U+E000 是不可见的私用区码位，成对比较见 `tests/fixtures/transcript-collation/README.md`）。

## Rust 行为

`src/pilotdeck-gateway/src/storage/transcript.rs::load` 删除了 `ties` 组上的孤代理预检与 `Transcript timestamp collation requires the Node host for unpaired surrogates.` 错误；重复 sequence 的 `createdAt` 比较改调 `compare_utf16_preserving_surrogates`，孤代理按 ICU4C 的 implicit-weight 公式直接参与比较，结果与上述真实 TS 顺序逐字节一致。

## 范围

原条目的差异范围——重复 sequence 组内、`createdAt` 含孤立 UTF-16 的时间戳排序——整体退役，包括原先「比实际比较边界更宽的整组预检」这一过度拒绝形态。未覆盖：仍直接调用 `collator.compare_utf16(...)` 的其它排序点（`skills/`、`runtime/tools/registry.rs`、`runtime/plugins/contributions.rs`、`runtime/context/cache.rs`、`runtime/model/stats.rs` 等）不属本条目，已由 #132 的跟进单登记、前置于 A8 退役 TS gateway；archive 与 snapshot 两处独立边界另见各自更正。
