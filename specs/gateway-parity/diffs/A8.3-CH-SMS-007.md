## 类别

运行时容错差异（待批）：#1339 的 sms channel webhook 收到 body 为 JSON
字面 `null` 的请求时，TS 侧 `params.Body`（无签名）或
`Object.keys(null)`（带 `X-Twilio-Signature` 且配置了 authToken）抛
`TypeError`，该异常在异步监听路径上无 try/catch：真实进程按 Node 22
`unhandledRejection` 默认行为终止，且应答从未写出（连接悬挂至客户端
放弃）。Rust 侧同一异常被连接任务包含：先经 `record_unhandled` 回调
上报同一消息文本，再销毁连接（零应答字节），进程与其余连接不受影响。

## 基线依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0 /
ICU 78.2。`_tmp/20261026-issue-1339/fix-r1/probes/null-body.out` 实测
（真实 TS 闭包 + 原生监听器，原始 socket 探针）：body `null` 无签名 →
1.5s 内零应答字节（超时销毁）、`unhandled:
["TypeError: Cannot read properties of null (reading 'Body')"]`；
`null-body-signed.out`：body `null` 带
`X-Twilio-Signature: bogus` → 同样零应答字节、`unhandled:
["TypeError: Cannot convert undefined or null to object"]`。两分支
`SmsChannel.ts` 均无 try/catch（派发路径同 A8.3-CH-SMS-001 的
`body.trim` 一族）。

## Rust 行为

`src/pilotdeck-gateway/src/channel/sms/mod.rs` `handle_request`：JSON
解析结果为 `JsValue::Null` 时，按「带签名且配置 authToken」与否选择
上述两消息文本之一，经 `report_unhandled` 上报后返回
`Err(DestroyConnection)`——hyper 连接任务收到后销毁流，零应答字节，
进程继续服务。消息文本与 TS 探针逐字节相同；生产挂载
（`register`）当前 `record_unhandled` 为 `None`（静默丢弃，见
A8.3-CH-SMS-004）。

## 范围

仅 JSON 字面 `null` body（带 / 不带签名两分支）；非字符串对象 `Body`
（`body.trim` 一族）在 A8.3-CH-SMS-001，截断 body 的 400 在
`A8.3-CH-SMS-002` 家族的 oracle cell `body-truncated`，均不在本条。
两侧共同点（零应答字节）一致，差异只在进程存活与连接销毁时机
（TS 悬挂、Rust 立即销毁）。

## 机器判据

`src/pilotdeck-gateway/src/channel/sms/tests.rs` 专属测试
`json_null_body_is_unhandled_destroy`（不走 oracle 重放——TS 侧悬挂
连接依赖探针超时销毁，生成器记录形态不确定）：两分支原始 socket
请求断言响应 `{closed: true}` 且 `unhandled` 记录上述两消息文本
（各自专属断言消息）；负控 `sms-json-null-body` 关掉 Null 分支的
销毁（落回 200 TWIML）即被该测试击落（KILLED，锚点
`#1339 json null without signature must destroy the connection`）。
