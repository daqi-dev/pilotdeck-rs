## 类别

bug 修复：补齐原条目所述「新同 session run 关闭旧绑定」缺失的清理屏障。不属于新的 TS 差异，也不改变原条目的 per-run runtime 策略。

## 基线依据

cc7c4e6 `src/cli/SessionInteractionBundle.ts:136-169` 每 session 构造一个 `HookRuntime`，`src/gateway/SessionRouter.ts:126-180` 按 session key 缓存同一 session；同 key 重提交复用原 runtime，不产生 per-run 替换。真实探针 `src/pilotdeck-gateway/tests/fixtures/interaction-hooks/replacement-probe.mts`（oracle：`replacement-oracle.json`）实测：旧 callback pending 时新 hook item 仍并发启动；drop 消费者流不 dispose；旧 runtime `draining` 时另建 replacement runtime 可先完成。探针 commit 与源文件 SHA256 在 oracle 内；运行命令见同目录 README。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/project/interaction_hooks.rs`：`State.draining` 由 `Vec<Arc<Run>>` 改为按 session key 的 `Vec<(JsString, Arc<Run>)>`；同 key 绑定顶替旧身份后保留旧 `Run`；`TurnHooks::wait_barrier`（`wait_ready` 公开）等待本 key 所有旧 run 的 `wait_closed`，本绑定取消/被顶替即返回 stale，成功项移除、失败项保留；`dispatch` 入口先等屏障，生产装配 `src/pilotdeck-gateway/src/runtime/turn/interaction.rs:159-168` 在 hooks 绑定后、steer 绑定前 `await wait_ready()`。旧 run 已在 `Run::close` 中取消，其 dispatch job 退出是等待的终止条件；旧 cleanup 失败成为只阻塞该 key 的失败屏障。不同 key 互不阻塞。

## 范围

仅 `Resource::InteractionHooks` 的同 generation 同 session key 生产绑定与 dispatch 路径；不改变底层 `HookRuntime`/`LifecycleRuntime`、`InteractionPermission` 或 `InteractionEvents` 的同步替换语义，也不把该屏障归因给 TS。原条目关于 per-run runtime 丢弃跨 turn pending、opaque receipt、generation 关闭的结论不变。

## 机器判据

`runtime/project/interaction_hooks/tests.rs`：`same_key_rebind_waits_for_old_cleanup_before_new_hook_runs`（基线红灯：新 hook 在旧 cleanup 前启动）、`dropped_stream_then_same_key_rebind_waits_for_old_cleanup`、`same_key_rebind_after_cleanup_dispatches_immediately`、`canceled_predecessor_releases_same_key_barrier`、`superseded_replacement_cancel_terminates_never_finishing_predecessor`（前驱永不完成时新绑定取消可终止等待）、`failed_cleanup_blocks_same_key_only`、`replacement_ts_oracle_records_unserialized_same_key_overlap`。负控：去掉 dispatch 屏障、去掉生产 `wait_ready`、失败 cleanup 不保留屏障、把按 key 过滤改成全局。复算：`cd src && cargo test -p pilotdeck-gateway --lib interaction_hooks::tests -- --nocapture`；TS 复算命令见 fixture README。
