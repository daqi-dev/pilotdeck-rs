## 类别

有意改进（防资源放大，#1011 fix-r1 / opus r1 P2）：Rust 对投影检查点读取加
transcript 同源大小上限；TS 读取无上限。

## 基线依据

cc7c4e6 的
`src/session/projection/checkpoint/JsonFileSessionProjectionCheckpointStore.ts`
（read 实测）：`load` 为 `const raw = await readFile(this.options.path, "utf8");`
后 `JSON.parse(raw)`，无 `stat`/大小检查；仅 ENOENT 静默、其余错误经
`onError` 报告后返回 `undefined`。transcript 侧读取上限为
`readTranscript(path, { maxBytes })` 默认 50 MiB（Rust 侧对应
`storage/transcript.rs` 的 `MAX_BYTES`，与 TS 金样
`sparse_transcript_read_limit_diagnostics_match_real_ts` 对齐）。

## Rust 行为

`runtime/session/projection_cache.rs`
`FileProjectionCheckpointStore::load`（#1011 fix-r1 起）：读取前先
`std::fs::metadata(&self.0).ok()?.len()`，超过
`crate::storage::TRANSCRIPT_MAX_BYTES`（即 transcript 50 MiB 常量的复用再导出）
即 `return None`（视为缺失），由 `ProjectionCache::restore` 走日志重放；
不整文件读入、不解析。边界语义与 transcript 读取一致（`len > max` 才超限，
恰好等于不超限；小于上限的合法文件照常加载）。`save` 路径不变
（写入内容仍由投影计算决定）。

## 范围

仅 `<transcript>.jsonl.projections.json` 的读取侧。超限文件不被删除（下次
`save` 的原子替换会覆盖）；行为差异表现为：超限检查点在 TS 会全量分配并解析
（随后校验失败回退重放或 hydrate 出错状态），在 Rust 直接按缺失处理重放。
不影响其余检查点格式/校验/水位语义，也不影响 50 MiB 以内的任何读写。

## 机器判据

`runtime/session/projection_cache_tests.rs`：

`oversized-checkpoint-accepted`（去掉大小分支后超限文件被解析，
断言 `#1011 oversized checkpoint is treated as missing` 失败）。

`cargo test --offline -p pilotdeck-gateway --lib
runtime::session::factory::projection_cache_tests::oversized_checkpoint_is_missing -- --exact`。
