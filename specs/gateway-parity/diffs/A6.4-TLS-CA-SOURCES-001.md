## 基线依据

cc7c4e6、macOS Homebrew Node v22.22.0。真实入口与源码闭包哈希见
`src/pilotdeck-gateway/tests/fixtures/private-ca/generate.mts`、`oracle.json`；每格原始 stdout/stderr 在同目录 `<mode>-<mismatch>.json`。
MCP `McpClient.ts`、hook `HttpHookExecutor.ts`、model `streamModel.ts`、count `TokenAccountingRuntime.ts` 均直接 import，count 的 local fallback 不算 HTTPS 成功。

实测：NODE_EXTRA_CA_CERTS 支持 PEM bundle，首错前有效证书保留；无关 CA、缺失文件、畸形首项及主机名不匹配失败。
本机 Node 默认读取显式 SSL_CERT_FILE（ssl-unflagged / system-off 正控），并读取 OpenSSL hash 命名的 SSL_CERT_DIR（dir-unflagged 正控、dir-plain 负控）。
强制 --use-bundled-ca 后 SSL_CERT_FILE 不再有效，即使同时加 --use-system-ca（forced-bundled / bundled-system）。因此不能把 system-flag 成功错误归因于读取 macOS 钥匙串。
系统原生库没有安装临时 CA，故无原生库正控；未查看或修改库内容，不能宣称已验证库内 CA 的接受行为。

## Rust 行为

`runtime/model/http/tls.rs`（相对 `src/pilotdeck-gateway/src/`）在原 bundled Mozilla roots 上加 NODE_EXTRA_CA_CERTS 和显式 SSL_CERT_FILE，保留标准 rustls 链及名称校验，所有 HTTP 客户端及 HTTPS 代理共用。

剩余差异：
1. 不读取 SSL_CERT_DIR。OpenSSL hash 目录的匹配规则不是“信任目录内所有 PEM”，本包不以粗略枚举扩大信任；system-dir / dir-unflagged 的匹配主机名格 Node 成功、Rust 失败。可将所需 CA bundle 指向 NODE_EXTRA_CA_CERTS 或 SSL_CERT_FILE。
2. 不模拟 Node CLI / NODE_OPTIONS 的 bundled、openssl、system 开关，亦不读取宿主默认 OpenSSL 路径或原生系统信任库。forced-bundled / bundled-system 的显式文件格 Node 失败、Rust 成功；这是带 Node 专属参数的启动语义差异，不是 hostname 绕过。
3. NODE_EXTRA_CA_CERTS 在 Node 进程启动时读取；Rust 第一次默认连接器构造时快照。之后的文件变化都不重载。Node 启动后改环境无效（late-env）；首次客户端 import 前将原为空的 extra 文件填入正确 CA，Node 仍失败、Rust 成功（early-file），直接证明该快照时机差异。Rust 安全产品 API 不修改进程环境，未用 unsafe 制造 late-env。
4. 两边 bundled 根数据版本不同（Node 构建数据与 webpki-roots 1.0.9），本地私有 CA 试验不能证明公开根集合逐字相同。
