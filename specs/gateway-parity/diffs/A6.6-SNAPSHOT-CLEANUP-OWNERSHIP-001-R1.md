## 类别

对既有登记条目的更正（数据安全加固的协议升级）：原条目登记的「rename 后 stat 共享路径 + check-then-unlink」协议仍留有三个可被并发交错利用的窗口，本次修复改为「创建时取身份 + 私有墓地删除」。

## 基线依据

原条目 `A6.6-SNAPSHOT-CLEANUP-OWNERSHIP-001`（`specs/gateway-parity/diffs/A6.6-SNAPSHOT-CLEANUP-OWNERSHIP-001.md`，原字节冻结）以 probe-b（`_tmp/20261026-issue-293/probe-b-concurrent.out`）实证 TS 的无条件 `unlink` 删除并发轮提交。TS 基线不变（cc7c4e6 `src/storage/workspaceSnapshot.ts:260-280`）；本更正只针对 Rust 侧防护协议的形状，TS 侧交错期望为读码推断（TS 无钩子无法确定性停在 rename 与 unlink 之间；无条件 unlink 语义由 probe-b 实证）。

## Rust 行为

`src/pilotdeck-gateway/src/storage/workspace_snapshot.rs`：① 身份在创建时从本轮持有的句柄取得——manifest 与 `_COMMITTED` 均经 `write_file_identified`（:1634-1646，fstat）在临时文件上取 dev/ino，rename 保留身份后登记（`commit` :1049-1067，`atomic_marker` :1312-1331 返回 rename 前身份）；不再 stat 共享路径。② 删除经 `remove_if_owned`（:982-1003）：先把共享路径 rename 进本轮私有墓地（`.tmp-grave-{pid}-{counter}`，同目录同文件系统），在墓地重验身份，匹配才删；他人文件在路径已空时 rename 还回。③ `#[doc(hidden)]` 确定性钩子（`SnapshotRoundStage`/`SnapshotRoundHook` :616-639，`new_with_hook` :693-699；生产 `new` 不装钩子）在 rename 与身份登记之间、committed 之后、清理前、删除前四个点驱动交错测试，取代 mtime 推断。

## 范围

消除的窗口：rename 后取身份（Codex P0-2）、check-then-unlink（Codex P0-3）。仍开放并登记的残余：① 墓地还回与新一轮占用竞态——他人文件滞留 `.tmp-grave-*`（还回前路径已被占则新文件留守，last-writer-wins 同任意 rename 覆盖）；② 本轮覆盖并发轮已提交 manifest 后失败：本轮按身份删自己的 manifest，留下 `_COMMITTED` 无 manifest（TS 同样丢 manifest，R2 删除路径本身正确；marker 早退读侧由此返回不存在的 manifest 路径）；③ inode 复用需要的时间窗与轮次在该协议外；④ 并发 `list()` 仍可能读到中途态（TS 同样，读码 `workspaceSnapshot.ts:152-158`）。uuid 临时目录仍无条件 `remove_dir_all`。`_FAILED.json` 写入顺序不变。

`src/pilotdeck-gateway/tests/workspace_snapshot.rs`：`concurrent_failure_cleanup_keeps_other_rounds_commit`（`BeforeFailureCleanup` 钩子阻塞至 R1 同步提交完成，生存断言 + 第三轮早退）；`failing_round_keeps_manifest_renamed_over_by_concurrent_round`（`AfterManifestRename` 钩子在窗口内 rename 外来 manifest，断言其存活）；`committed_marker_ownership_survives_concurrent_overwrite`（`AfterCommittedMarker` 钩子 rename 外来 `_COMMITTED` 并以只读临时目录触发失败，断言外来 marker 存活、自己的 manifest 仍删除）；`owned_delete_window_cannot_hit_a_concurrent_publish`（`BeforeOwnedUnlink` 钩子在删除窗口内 rename 外来文件，断言其存活）。负控 `tests/fixtures/workspace-snapshot-gate/negative_controls.py`：`cleanup-unconditional-delete`、`cleanup-no-ownership-check`、`ownership-capture-after-rename`、`ownership-committed-capture-after-rename`、`cleanup-unlink-by-shared-path` 要求 KILLED。复算：`cargo test -p pilotdeck-gateway --locked --offline --test workspace_snapshot` 与 `--lib snapshot`。
