## TS 依据

固定 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85（fix-r1 更正笔误：原写作 `…d41c…`，正确值见 `tests/baseline_provenance.rs:14`），Node v22.22.0，真实 `SessionRouter` + 真实 `asAgentHandle` 会话（dispose 可门控/可拒绝，与 mcp-gateway 金样 fixture 同款）。探针 `_tmp/20261026-issue-1245/probe/close-during-shutdown.mts` / `close-during-shutdown.out`，probe1–11，按「状态 × 事件 × 时机」矩阵覆盖 else 分支（`SessionRouter.ts:327-338` `await this.closingSessions.get(sessionKey)`）的全部窗口：

- A1 同 tick（驱逐未登记，pending creations 仍 drain）：close(key) 与 close(unknown) 均 fulfilled（probe1）。
- A2 驱逐 mid-flight 且 dispose 失败：close 拒绝并透传**该 key 自己的** `Failed to dispose agent handle.`；同窗口 dispose 成功的 key（A2b）与无关 key（A3）、从未存在的 key（A4）均 fulfilled（probe2）。
- A5 驱逐已结算（失败或成功，`finishEviction` 已删条目）：fulfilled（probe3/probe4）。A6 shutdown 完全结束后：fulfilled（probe3）。
- B1 无 shutdown 的普通 close（dispose 失败）：拒绝 per-key（probe5，即 #1215 金样 close-fault 行）。
- B2 同 key close#2 在 close#1 驱逐 mid-flight 时：拒绝 per-key（probe6）；close#1 结算后 close#2 fulfilled（probe7）。
- B4 close 在 idle 驱逐 mid-flight 时：拒绝 per-key（probe8，`sweepIdle` 的 `beginEviction` 同样登记 `closingSessions`）。
- C1 close#1 mid-flight → `shutdown()` → 同 key close#2：close#2 拒绝 per-key、close#1 拒绝 per-key、shutdown 聚合含该错误（probe9 成败两臂 probe10）。

机制注解（读码，行为以探针原始输出为准）：`beginEviction` 在任务启动时登记 `closingSessions`，`finishEviction` 在结算后删除；`shutdown()` 同步清空 `sessions` 后，close 一律落入 else 分支。`close` 从不返回 shutdown 聚合，聚合只是 `shutdown()` 自己的答案。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/session/owner.rs` 以 `State.closings`（`HashMap<JsString, watch::Receiver<Option<RuntimeResult>>>`，TS `closingSessions` 的对等物）对齐 else 分支：close 任务的完成 watch 在 **call 时**（ticket/track 同段）登记，idle sweep 驱逐在 sweep 锁内登记，shutdown 的每个 drain 在 spawn 前登记。`close()` 依次：查未结算的 closing 条目（`unsettled_closing`：`borrow().is_none()` 才算在飞，已结算视同不存在 → Ok）→ `state.shutdown` 已置位 → Ok（TS：sessions 已清空，else 分支 await `undefined`）→ 原驱逐路径。`shutdown()` 的每个 drain 发布自己的 per-key 结果；close/shutdown/idle 三处登记统一，故 A1–A6、B2/B3/B4、C1 全窗口与 TS 一致：mid-flight 透传该 key 自己的驱逐结果（失败的 dispose 经 #1011 `LiveSessionHandle` 聚合为 `Failed to dispose agent handle.`），未登记/已结算/未知 key fulfilled，`Failed to shut down all agent sessions.` 只由 `shutdown()` 产生。旧 `wait_result(shutdown)` 短路分支已删除。dirty_recreate 不经登记（TS `beginEviction` 同样不登记，不登记）。条目不在任务体内删除，`track()` 顺手 prune 已结算条目；任务 panic 时 `spawn_with_error` 的 Completion 守卫保证 watch 必定结算，不会以陈旧结果服务后来的 close。

## 范围

`runtime/session/owner.rs` 的 `close`/`sweep_idle`/`shutdown` 三处登记与 `close` 的分支语义；`#1215` 的 `runtime/mcp/gateway.rs` close 透传不变（消息语义已随 owner 对齐）。原条目「后续接线 PR 若在 shutdown 期间路由四控制方法，应以本条差异为准评估」的警示随差异闭合失效。B2/B4/C1 是同一 TS else 分支的兄弟窗口，一并实测（probe6/8/9/10）一并实现，避免「半套机制」；`#1215` 金样 53 行不含 shutdown 格，重放不受影响。`close_project`/`replacement`/turn 路径对 `close` 的既有调用语义不变（成功臂不变，失败臂从聚合改为 per-key 的场景只在 shutdown 进行中的窗口内）。
