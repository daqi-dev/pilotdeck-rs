## 类别

不可避免（本单元范围外的装配面待补）：cron 结果投递入口未随 channel 移植。

## 基线依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0 / ICU 78.2。
`src/adapters/channel/protocol/types.ts:28-32` 的 `ChannelAdapter` 把
`deliverCronResult?(delivery: CronResultDelivery): Promise<boolean> | boolean`
声明为**可选**成员（问号即「渠道可以不实现」）；
`src/adapters/channel/wecom-callback/WeComCallbackChannel.ts:148` 为
wecom-callback 实现了它，转发到共享 helper
`src/adapters/channel/protocol/ImCronDelivery.ts:17-27` 的
`deliverChatCronResult`：先按 `originChannelKey` 过滤（存在且不等于本渠道
即返回 false），再用 `<channelKey>:chat=` 前缀 + `^(.+):(general|s_[0-9a-fA-F-]{36})$`
后缀从 `originSessionKey ?? sessionKey` 解析 chatId，最后经 `sendReply` 发文本，
返回值是「`sendReply` 的返回值 !== false」。

## Rust 行为

`src/pilotdeck-gateway/src/channel/protocol.rs:93-99` 的 `ChannelAdapter` 只声明
`channel_key()` 与 `start()`，没有 cron 投递成员；
`src/pilotdeck-gateway/src/channel/wecom_callback/mod.rs` 也没有对应实现。
全仓 grep `CronResultDelivery` / `deliver_cron` 零命中——cron 类型属于
`channel/` 之外的依赖面（计划 §1 明确不移植共享 IM helper 的内部实现），
当前 Rust 侧没有任何渠道能接收 cron 结果。

## 范围

只影响 cron 结果回投（定时任务把结果送回发起会话的渠道）。入站 HTTP 面、
回合提交、回复发送、生命周期 start/stop/drain 全部不受影响；22 个 TS 金样
case 没有 cron 投递场景，本项不改变任何已被金样钉死的 cell。
待 cron 装配（A8.5 接线或 cron 单元）在 `ChannelAdapter` 上补可选成员时关闭本条。

## 机器判据

`src/pilotdeck-gateway/tests/fixtures/wecom-callback/oracle.json`（22 case，
`expectedCaseCount: 22`）由 `channel_matches_real_ts` 逐格回放比对 TS 记录；
组件 pin（`decrypt_matches_the_recorded_envelope`、`signature_sort_uses_utf16_code_units`
等）各钉死一处 TS 行为。本项没有正向输出可对，只能给静态证据：
`grep -rn "CronResultDelivery\|deliver_cron" src/pilotdeck-gateway/src/` 零命中；
`negative_controls.py` 的 9 个变异不覆盖本项。
