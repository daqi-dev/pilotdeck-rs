## Rust 行为

`src/pilotdeck-gateway/src/channel/loader.rs:106`（`reject_unmigrated_channels`）行为不变：
`signal` 键 `enabled` 为真值 → `Err(ChannelError::Error)`，错误文本为
`Error: [adapters] channel "signal" 未迁移到 Rust，需继续使用 TS gateway`。

变化在装配：`src/pilotdeck-gateway/src/native_process/assembly.rs:493-509` 在读取配置快照
之后、构造 `NativeChannels`（同文件 `:510`）之前调用该 seam；`Err` 经 `return
Err(error.into())` 向上传播出 `assembly::start` → `native_process::run` → `main`，原生进程
启动失败并以非零码退出（exit 1）。**stderr 的实际形态是 Debug，不是 Display**：`main` 返回
`Result<(), ProxyError>`，std 的 `Termination for Result` 打 `Error: {e:?}`，而 `ChannelError`
的 `Debug` 是派生实现，故实测一行为
`Error: Error("[adapters] channel \"signal\" 未迁移到 Rust，需继续使用 TS gateway")`
（比 `Display` 的 `Error: …` 多一层 `Error(...)` 且引号转义；最小实测与原始输出见 #1763 的 PR，
用例 `startup_rejection_reaches_stderr_in_the_debug_form` 钉住该形态）。拒绝仍发生在任何
adapter 构造或 `console.error` 之前。同处另有 `loader.rs:153`
`reject_unimplemented_bundle_channels` 覆盖 `weixin` / `feishu` 两个不在本拒绝表内的 bundle
键（#1694 §7；`feishu` 的拒绝另见 `A8.3-CHANNEL-FEISHU-001.md`）。

## 范围

更正两处措辞：本条不再是「seam 已就绪、装配待落地」，而是「原生启动路径上已生效」——
启用 `signal` 的配置在原生 gateway 启动时被拒绝，不静默忽略、不降级为不启用、不回落 TS
gateway。判定键集合（`UNMIGRATED_CHANNEL_KEYS` 13 键）、`enabled` 真值判据（本键属
`loadEnabledChannels` 表内 11 键，seam 层走 JS 真值；**生产路径上 `config/snapshot.rs`
的 `bool_field` 先把 `enabled` 折叠成严格布尔**，故 `signal: {{enabled: 1}}` / `"true"` / `[]`
这类非布尔拼写在生产装配里读到 `false`、不触发拒绝——这是配置快照层的既有行为，非本闸门引入，
用例 `startup_folds_non_boolean_enabled_spellings` 钉住它）、多键命中顺序（`UNMIGRATED_CHANNEL_KEYS`
声明顺序报第一个）与「未启用任何 channel 的默认配置行为不变」均沿用原条目。`signal`
迁移单落地后本条仍以更正条目或新条目处理。
