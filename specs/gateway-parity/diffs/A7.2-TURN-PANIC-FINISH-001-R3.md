## 类别

更正（原条目「Rust 行为」两处失实，非取舍变化）：其一，R2 登记的「record 与 drain 共享同一 abort 预算」引入第三格未登记——record 在预算之后才沉降时，预算随 record 一起耗尽，两条终态帧（failure status 帧 + error 帧）根本不入队（`gateway_event` 只在 `record_failure().await.is_ok()` 之后调用），Rust 丢弃帧而有界收口；TS 同形是共享无界链、帧在 record 沉降后照常投递（#2498 fix-r2 评审 P1-b）。其二，R2「范围」登记「timer 接管路径（`6-R1.md`）……不变」在 fix-r2 后不再成立——timer 胜者的 durable record（`submit.rs` timer 臂 `record_failure`）原先无界，挂死时 manage 臂停在 settlement 与 `close_live` 之前，与 panic 臂修复前同形挂死；fix-r2 给它与 panic 臂同式的 abort 预算（#2498 fix-r2 评审 P1-c）。原条目 A7.2-TURN-PANIC-FINISH-001 与 R2 原字节不动。

## TS 依据

与原条目同一固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85（Node v22.22.0）。探针 C（`_tmp/20261026-issue-2498/fix-r2/ts-probe-2498-r2.mts` → `ts-probe-2498-r2.out`）：panic 臂 record 慢沉降（300ms，append 不设闸）。record 进行中（150ms 采样）`delivered=2`（turn_started / input_accepted）；record 沉降后 `delivered=4`（agent_status + error 均投递）、`ended=true`、`active=false`、`afterCalled=true`——TS 无预算、record 与 append 共享同一条无界等待链（record → enqueue → `Promise.all` → `queue.close`），wire 帧照常投递、turn 干净收口。timer 臂探针 D（fix-r3 补测，`_tmp/20261026-issue-2498/fix-r3/ts-probe-2498-r3.mts` → `ts-probe-2498-r3.out`；同基线同接线，`timeoutMs=100` + record 慢沉降 300ms、真 setTimeout）：record 进行中 `delivered=2`、`ended=false`；record 沉降后 `ended=true`、`active=false`、`afterCalled=true`、durable appends=4（agent_status + error 在 record 沉降后照常 append）——turn 收口等 record（`settleTimeout` await record，pump finally await 该 settlement；R2 时为读码，本探针实测同一条无界等待链）。timer 臂 wire 侧与 record 快慢无关：`settleTimeout` 的 `queue.close()` 先于 append→enqueue 竞速关闸，终态帧不上 wire（金样 `timeout-active` 同形：visible=[turn_started, input_accepted] 而 registryCalls 含 agent_status / error 两 append），即 timer 臂「帧照常投递」只成立于 durable 侧。**结论：TS 共享**，故 Rust 保持共享预算 + 本件登记第三格分叉（预算耗尽弃的是 await：wire 侧终态帧不入队，durable record 不弃、由 `spawn_blocking` 迟到落盘，详「Rust 行为」；宁可丢帧不挂死），不改 Rust。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/turn/submit.rs`（fix-r2 后）：panic 臂不变（R2 登记）。timer 臂 timer 胜者（`owns_terminal`）的 record 与两条终态帧改包进 `timeout(abort_budget(), async { record_failure; 两条 gateway_event })`——与 panic 臂同式同预算（`abort_budget()`，`max(1_000ms)` 下限），预算内沉降照常入队；预算耗尽丢弃的是 await 的未来（JoinHandle）：`gateway_event` 只在 `record_failure().await.is_ok()` 之后调用，超时即不再被调用，wire 侧两条终态帧不入队。durable record 不随预算放弃——生产 `record_failure`（`native_process/services.rs`）是 `spawn_blocking`（同 R2 登记：派发后不可取消），超时只丢 await，durable 写仍会执行、可能晚于预算 / `close_live()` 迟到落盘（或随 recorder 关闭失败）；wire 侧丢帧与 durable 侧迟写分列登记，不是一回事。settlement 发送与 `close_live()` 保持在预算外原位（worker 侧不额外等待、close 语义不动）。第三格（慢 record）：预算先于 record 耗尽 → 帧不入队 → 硬关收口（wire 无帧）；TS 侧 panic 臂 wire 帧照投（探针 C）、timer 臂 wire 两侧同弃（`queue.close()` 竞速，探针 D + 金样 `timeout-active`）、durable append 在 record 晚沉降后照常落——分叉点仅此一格（wire 分叉只在 panic 臂，durable 分叉两臂同形），格 1/2（预算内 Ok/Err）与既有登记一致。

## 范围

仅 turn submit 的 timer 胜者 record 有界化与共享预算第三格登记。timer 接管路径的其余部分（认领、reject_pending、session abort、settlement、close 语义、flush_wait 后备）不变（`6-R1.md` 登记）；pump 正常完成路径不变；panic 臂不变（R2 登记）。「慢 record 丢帧」为既有「宁可分叉不挂死」取舍在共享预算下的自然推论，与 6-R1、R2 同族，不据此宣称 #589 或阶段完成。不修改 TS 金样或冻结判分器。
