## 类别

已知未收敛差异：#1071 显式原生进程继承 Rust host 的清理失败策略；未批准，不能计作 TS 对齐。

## 基线依据

固定 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0。`native-process/generate.mts` 调用真实 `PilotDeckServerShutdownBundle`：`oracle.json` 的 `observations.reject` 记录多错聚合，`observations.cancel` 记录自动化停止失败后仍执行后续清理。其生成守卫为 `native_process::tests::regenerates_identically`。

本轮另将真实 `createShutdownAndExit` 与 bundle 组合：请求退出码 0，automation.stop 抛 `Error('cancelled')`，其余清理完成后 exit callback 仍收到 0，Promise 保留该错误。原始脚本及输出：`_tmp/20261026-issue-1071/ts-shutdown-error.mts`、`ts-shutdown-error.log`。这是实际 TS 组件组合探针，未启动完整 TS CLI；完整 CLI 的 `process.exit` 行为此处仅按源码定位，不冒充进程实测。

## Rust 行为与范围

`native_process/assembly.rs` 的 cleanup 顺序调用 session factory dispose 和 project dispose，即使前者失败也调用后者；二者同时失败时只返回首错。既有 `runtime/turn/gateway.rs` 同样保留 owner/cleanup 的首错。`native_process::run` 将该错误作为 main 的 Result 返回，因此信号启动的失败清理会非零退出，与 TS 上述 callback 结果不同。

只适用于显式 `--native`；默认 A4 不变。socket/业务前驱不完成时的有界 drain 沿用 `A7.2-NATIVE-WS-DRAIN-001`，本条不重复修改其语义。

## 判据与批准状态

TS 组件金样、Rust 既有 `native_ws::tests::{host_cleanup_runs_after_session_failure,host_cleanup_is_bounded}` 与新真实进程 `never` 格分别验证组件失败继续清理及明确超时。尚未对新生产装配注入 session/project 双错误，不能宣称多错行为逐格对齐。

未批准，待人复核；保留差异以防虚报通过，不放宽冻结阈值或 native 格验收条件。完整 CLI 清理失败对拍及聚合策略收敛前，#1071 不能据本条标全通过。
