## 类别

更正（归一化规则陈述与实现不符，非差异变化）：原条目「范围」段把归一化
规则列为「date 掩码、头名小写、删空 `content-length: 0`、chunk 大小
小写」，其中「删空 `content-length: 0`」按字面读是该车道回放统一删的
blanket 规则。#2153（fix-r1，PR #2770 已合）之后该车道实现是**逐调用
豁免**：共享件 `tests/common/replay_normalize.rs` 的 `normalize` 以
`parser_admission: bool` 参数收窄删行，api-web 侧唯一包装
`api_web/tests.rs::normalize`（:2410）把该参数透传，**79 格金样回放
（:454-455）全部传 `false`——回放从不删该行**；传 `true` 的只有
#1765/#2354 的解析层准入 gate 测试（`gate_bad_method_is_parser_bare_400`
:739、`gate_non_ascii_target_is_parser_bare_400` :796——裸 400 上
hyper 补的 `content-length: 0` 是已登记差异，gate 比较需要豁免该行）。
原条目两项 500 残余、HTTP/1.0 继承差异与 -R1/-R2 的登记全部不变。

**该误述从未改变任何判分结论**：本轮从 oracle 原始 JSON 独立重算
（2026-11-11，脚本与原始输出贴 #2775 fix-r1 RESULT），79 格中裸解析器
400 格 **0** 个、期望字节含 `content-length: 0` 的格 **0** 个、含任意
`content-length` 头的格 **0** 个——blanket 删在该车道的回放上本来就
无行可删，#2153 收窄前后 79 格全绿一致。误述的实质是账本陈述漂移：
读者按原句会把「删 cl0」当成该车道回放的现行规则，而把它当成豁免依据
或移植范本时，会复刻一个已不存在的 blanket 删（恰是 #2776/#2789 在
native-http 车道收窄掉的形状）。

## 范围

车道回放的统一规则，而是 gate 测试逐调用豁免、回放端 79 格逐字比较。
不新增、不撤销任何对拍豁免；原条目两项 500 残余与 HTTP/1.0 状态行
继承差异的结论、批准状态不变。module-host 车道同句误述另登
A8.4-MODULE-HOST-001-R2；native-http 车道的收窄已由
A8.4-NATIVE-HTTP-001-R6 登记（登记格集 11/88），本件是 api-web 车道
