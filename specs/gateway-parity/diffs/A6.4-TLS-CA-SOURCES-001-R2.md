## 基线依据

原文基线写「cc7c4e6、macOS Homebrew Node v22.22.0」；`-R1` 已登记项目基线
Node v22.22.0 / ICU 78.2 源码构建（`resources/PilotDeck cc7c4e65`）在同样两格上的
相反实测。两份事实并存，本轮不再重测：

| 格 | 冻结账本（Homebrew） | 项目基线（源码构建） | 原始证据 |
|---|---|---|---|
| `dir-unflagged`（默认模式 + `SSL_CERT_DIR` 指向 c_rehash hash 目录） | 四客户端全 **true** | 四客户端全 **false** | 源码构建：`_tmp/20261105-archive-wt-1162/20261105-issue-1162/r1/tls.log` |
| `early-file`（启动时 extra 文件为空、首个客户端前写入） | 四客户端全 **false** | 四客户端全 **true** | 同上 |

源码构建这一组内部自洽，且符合 Node 文档语义：默认用 bundled CA，只有 `--use-openssl-ca`
才走 OpenSSL store（`r1/tls-flags.log`：`openssl-dir` success、`openssl-plain`
`non_blocking_error`）。Homebrew 那台把默认模式也接上了 OpenSSL 默认路径。

**裁决**：采纳冻结账本口径。理由是选项 1 **零改尺子**——`tests/fixtures/private-ca/oracle.json`
的 `dir-unflagged` / `early-file` 期望值一字不动，`private_ca` 60 格在测试当前口径下全绿，
本单内可闭环；选项 2 要改 **8 格**期望（判分语义变更），须另走一次明确授权：两格已登记的
差异（`dir-unflagged` mismatch=false 全 `true`→全 `false`、`early-file` mismatch=false 全
`false`→全 `true`）+ 六格 Homebrew-only（`ssl-unflagged` / `system-flag` / `system-env` /
`system-dir` / `system-off` / `system-options` 的 mismatch=false，冻结全 `true`、源码构建
全 `false`）。两个 mode 的 mismatch=true 格两侧都是全 `false`，不受影响。六格实测见
`_tmp/20261106-1552/option2-facts.md`（mbp2 / darwin arm64；其中 `system-dir` 在 Linux 上
走 OpenSSL 默认路径会读 `SSL_CERT_DIR`，与 darwin 的 Keychain 路径不同，该项跨平台不齐）。

「全绿」的准确含义（防误读为「60 格全部匹配冻结账本原值」）：60 格 = **56 格计入对齐**
（其中 50 格匹配冻结 `oracle.json` 期望，6 格匹配基线实测的 `openssl-cases.json` 期望，
即 `--use-openssl-ca` 三模式 × 2）+ **4 格按注册差异记、不计入对齐**。四格里
`dir-unflagged` 的 mismatch=false 格冻结期望本就是全 `true`（测试的改写是空操作）；
`early-file` 的 **mismatch=false 1 格**才是靠测试运行时（`private_ca.rs:356-366` 的
`difference && !mismatch` 守卫）把期望改写为 Rust 实测值 `true` 后通过——该格上 Rust
对齐的是源码构建基线、不是本轮采纳的冻结账本口径；两个 mode 的 mismatch=true 格都按
冻结原值（全 `false`）直接通过，两侧一致。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/model/http/tls.rs`（origin/main `6f7522f05`，#1552 / PR #1647 落地）：

- `client_config` `:14-18`：`OnceLock` 一次性快照（首个默认连接器构造时读环境）。
- `CaMode` `:24-40`：`Default` / `Openssl` / `Bundled`；`ca_mode` `:42-52` 从 `NODE_OPTIONS` 分词，
  `--use-bundled-ca` 优先于 `--use-openssl-ca`，缺省 `Default`。
- `roots_from` `:67-96`：先铺 bundled Mozilla 根；`if mode != CaMode::Bundled`（`:78`）时才
  读显式 `SSL_CERT_FILE`（`:79-81`）与 OpenSSL hash 命名的 `SSL_CERT_DIR`（`:82-89`，
  按路径列表逐个调 `load_hash_dir`）；`NODE_EXTRA_CA_CERTS` 在所有模式追加（`:91-93`）。
- `load_hash_dir` `:223`：只认 `<8 位小写十六进制>.<0-9>` 形状的条目。

**因此**：`CaMode::Default`（Rust 未识别到 `--use-openssl-ca` / `--use-bundled-ca` 时）
会读 `SSL_CERT_FILE` 与 `SSL_CERT_DIR`。按冻结账本口径这与 Homebrew Node 对齐；按项目基线口径这是**扩大信任集合**
（两个来源各有一批 CA 是基线不信任的，见「范围」）。

## 范围

同原文：MCP HTTPS、HTTP hook HTTPS、模型 HTTP、token count、HTTPS 代理。不新增 ca 配置项、
不新增关闭证书校验开关、不读宿主原生信任库。

**本轮新增登记（安全相关放宽，未消除）**：默认模式（`CaMode::Default`——Rust 的 `ca_mode`
只识别 `--use-openssl-ca` / `--use-bundled-ca`，其余旗标组合都落在这里）下，`roots_from`
在 bundled 根之外读**两个显式来源**——`SSL_CERT_FILE`
（`:79-81`）与 OpenSSL hash 命名的 `SSL_CERT_DIR`（`:82-89`）；项目基线的源码构建 Node
在同样条件下**两个都不读**，握手失败。实测的相反格（均为 mismatch=false、每组 4 个客户端）：
目录来源 `dir-unflagged`（源码构建全 `false`、Rust 全 `true`）；文件来源 `ssl-unflagged`
（只设 `SSL_CERT_FILE`、不加任何旗标，同向）；另有五格 `system-*` 同向——`system-flag`
（`--use-system-ca`）、`system-env`（`NODE_USE_SYSTEM_CA=1`）、`system-options`
（`NODE_OPTIONS=--use-system-ca`）、`system-off`（`NODE_USE_SYSTEM_CA=0`）四格由
`SSL_CERT_FILE` 驱动，`system-dir`（`NODE_USE_SYSTEM_CA=1` + `SSL_CERT_FILE`=空文件 +
`SSL_CERT_DIR`=c_rehash 目录）由目录驱动，合计**六格**（冻结 Homebrew 账本全 `true`，
源码构建全 `false`，见上文复算表）。共同机制：Rust 的 `ca_mode`（`tls.rs:42-52`）**只认
`--use-openssl-ca` / `--use-bundled-ca`**，上述系统 CA 旗标（含显式设为 `0`）一律按
`CaMode::Default` 处理，于是照样读两个来源；源码构建基线在这六种组合下都不读。家族内
`system-extra`（`NODE_EXTRA_CA_CERTS`，两侧全 `true`）与 `system-empty`（两侧全 `false`）
**不属于**这六格；这六格的 mismatch=true 格两侧同为全 `false`（冻结 oracle 的 28 个
mismatch=true 格期望也全为 `false`）。夹具条件见
`tests/fixtures/private-ca/generate.mts:65-76`。就用户影响而言，值得记住的是这一方向：
**基线拒绝的内部/自签站点，Rust 可能接受**——同一审计口径下 Rust 信任的 CA 更多。

**「多信任」只限定在上述两个显式来源与已实测条件上，不等于任意条件下整体信任集合是基线的
超集**：bundled 根集合两侧未证同源（原条目已记）；Rust 还会跳过超过 8 MiB 的 CA bundle
（`-R1.md`「残余差异」与 `tls.rs` 的 `MAX_CA_FILE_BYTES`，注释自述「trust set is *smaller*
than Node's」），Node 无对应上限——即存在 Rust **少**信任的反方向情形。因此本条不宣称
「Rust 的信任集合 ⊇ 基线的信任集合」。

这是选项 1 的已知代价，登记为独立跟进单 **#1865**（label `P2-跟进`，**前置于 A6.4 差异族
收尾节点**；该单覆盖 `SSL_CERT_FILE` 与 `SSL_CERT_DIR` 两个来源）。本更正不宣称该放宽已
闭合或已批准为永久行为。

`--use-openssl-ca` 下保留 bundled 根的超集问题、hash 名未校验、`SSL_CERT_FILE` 列表语义、
冲突旗标四条残余仍按 `-R1` 与 #1654 处理，与本条不重叠。
