## 类别

有意改进（安全，向安全方向偏离）。工具结果落盘目录在 TMPDIR/TMP/TEMP 都未设置时落在 `/tmp/pilotdeck-tool-results`，Linux 下 `/tmp` 是本机所有用户共享；文件名可预测（`<session>/<turn>/<call>.txt`）。TS 用 `mkdir(..., {recursive:true})` 加 `writeFile(..., {mode:0o600})`，既不核对既有目录的属主，也让最终打开跟随符号链接、截断既有文件；本机其他用户可以先占目录或预置符号链接，把工具输出写进别处、截断别的文件（数据破坏），或借着别人的目录读走工具输出（内容泄露）。Rust 改为逐级 0700 创建、从 `pilotdeck-tool-results` 起核对属主与目录类型、文件 `O_NOFOLLOW` 打开；不符合就拒写并报错。行为只在「遭遇恶意预置」时与 TS 不同：TS 写到别处，Rust 什么都不写。正常写入的路径名、文件名、内容与 0600 不变。

## TS 依据

cc7c4e6 的 `src/gateway/client/GatewayToolResultArtifactStore.ts`：

- `:32`：`this.rootDir = resolve(options.rootDir ?? resolve(tmpdir(), "pilotdeck-tool-results"))`；`os.tmpdir()` 在 macOS 通常是用户私有的 `$TMPDIR`，在 Linux 常为共享的 `/tmp`。
- `:34-36`：默认 `createDirectory` 为 `await mkdir(path, { recursive: true })`，沿用进程 umask 建目录；`recursive` 对已存在的路径只做存在性判断，不核对它是目录、符号链接还是别人的目录。
- `:37`：默认 `writeText` 为 `writeFile(path, text, { mode: 0o600 })`。Node 的 `writeFile` 默认 flag 是 `w`（`O_WRONLY|O_CREAT|O_TRUNC`），会跟随最终组件的符号链接并截断目标；`mode` 只在新建文件时生效。
- `:40-50`：`persist` 先 `void this.write(...)` 再 `return path`，落盘是 fire-and-forget，路径先交给调用方。
- `:52-59`：`write` 的 `try/catch` 吞掉建目录与写文件的所有错误（注释说明这是 advisory host preview，不得影响工具完成）。

因此 TS 在共享临时目录上遇到预置目录/符号链接时会照写：根级符号链接把整棵树写进链接目标，最终文件符号链接截断链接目标，他人属主的目录让工具输出落到对方可读的位置。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/turn/projector.rs`：

- `:287-334` `create_directory_private`（unix）：不再用 `create_dir_all`，改为按路径组件逐级创建；缺失的一级用 `DirBuilder::mode(0o700)` 建目录，并显式 `set_permissions(0o700)` 覆盖 umask。走到名为 `pilotdeck-tool-results` 的组件后打开 `guarded`，该级及其下每一级（无论新建还是已存在）都用 `symlink_metadata`（不跟随符号链接）取元数据并核对。`/tmp` 这类 tmpdir 本身在 `guarded` 打开前，只保证权限/存在，不做属主核对（与任务要求一致；macOS 上 `/tmp` 本身是指向 `/private/tmp` 的符号链接，也不能被拒绝）。
- `:341-377` `verify_private_directory`：`file_type().is_symlink()` → `PermissionDenied`；`!is_dir()` → `NotADirectory`；`metadata.uid() != rustix::process::geteuid().as_raw()` → `PermissionDenied`（含双方 uid 的错误文本）。抽成纯函数 `(path, metadata, expected_uid)` 是为了让属主分支能用合成的 uid 测试——非 root 无法 `chown` 出别人的目录。
- `:384-398` `write_private`（unix）：`OpenOptions::write+create+truncate+mode(0o600)+custom_flags(libc::O_NOFOLLOW)`（`OpenOptionsExt`，安全 API，无 `unsafe`）；最终组件是符号链接时 `open` 直接失败。
- `:240-270` `persist`：沿用调用方现有的错误处理路径。写任务仍投递到 detached writer，钩子返回的 `io::Error` 只让该次写静默结束（不 panic、不中断回合）；队列仍接受时 `persist` 照旧返回路径（TS 也是先返回路径再写、`catch` 吞错），队列被拒（writer 已死）时返回 `None`。所以对外可见行为不变：恶意预置时模型仍可能拿到一个「路径存在但文件没写成」的结果，与 TS 的 advisory 契约一致；区别只在磁盘上——Rust 不写、不跟随，TS 写到别处。非 unix 分支保持 `create_dir_all`/`fs::write` 不变。

## 范围

只覆盖默认根目录所在的共享临时目录场景（`pilotdeck-tool-results` 这一级及其下各级）。正常情况完全不变：目录名、`<session>/<turn>/<call>.txt` 文件名、落盘内容、阈值、0600 文件权限都与 TS 相同；新目录为 0700（TS 按 umask，共享 `/tmp` 下常为 0755）。偏离只发生在恶意预置时：

- 根级或中间级符号链接：TS 跟随并写进链接目标；Rust 报错，链接目标不出现任何文件。
- 最终文件符号链接：TS 截断/覆盖链接目标；Rust `O_NOFOLLOW` 打开失败，目标内容不变。
- 属主不是当前 euid 的目录：TS 照写（内容可被目录所有者读取）；Rust 拒写。
- 同名的普通文件占位：TS `mkdir` 报错但 `catch` 吞掉；Rust 同样报错不写（`NotADirectory`）。

显式传入的自定义 `rootDir` 若路径组件里不含 `pilotdeck-tool-results`，只按 0700 创建、不做属主核对；这不在本条默认共享 `/tmp` 的威胁范围内（根由调用方自己选择）。
