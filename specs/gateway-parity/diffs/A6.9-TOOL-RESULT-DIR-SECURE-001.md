## 类别

有意改进（安全，向安全方向偏离）。工具结果落盘目录在 TMPDIR/TMP/TEMP 都未设置时落在 `/tmp/pilotdeck-tool-results`，Linux 下 `/tmp` 是本机所有用户共享；文件名可预测（`<session>/<turn>/<call>.txt`）。TS 用 `mkdir(..., {recursive:true})` 加 `writeFile(..., {mode:0o600})`，既不核对既有目录的属主，也让最终打开跟随符号链接、截断既有文件；本机其他用户可以先占目录或预置符号链接，把工具输出写进别处、截断别的文件（数据破坏），或借着别人的目录读走工具输出（内容泄露）。Rust 改为 `openat`/`mkdirat` 逐级创建、从 `root_dir` 起核对属主与目录类型、逐级 `fchmod 0700`、文件相对父目录 fd 用 `O_NOFOLLOW` 打开；不符合就拒写并报错。行为只在「遭遇恶意预置」或 session/turn 路径段含 `..` 时与 TS 不同：TS 写到别处，Rust 什么都不写。正常写入的路径名、文件名、内容与 0600 不变。

## TS 依据

cc7c4e6 的 `src/gateway/client/GatewayToolResultArtifactStore.ts`：

- `:32`：`this.rootDir = resolve(options.rootDir ?? resolve(tmpdir(), "pilotdeck-tool-results"))`；`os.tmpdir()` 在 macOS 通常是用户私有的 `$TMPDIR`，在 Linux 常为共享的 `/tmp`。
- `:34-36`：默认 `createDirectory` 为 `await mkdir(path, { recursive: true })`，沿用进程 umask 建目录；`recursive` 对已存在的路径只做存在性判断，不核对它是目录、符号链接还是别人的目录。
- `:37`：默认 `writeText` 为 `writeFile(path, text, { mode: 0o600 })`。Node 的 `writeFile` 默认 flag 是 `w`（`O_WRONLY|O_CREAT|O_TRUNC`），会跟随最终组件的符号链接并截断目标；`mode` 只在新建文件时生效。
- `:40-50`：`persist` 先 `void this.write(...)` 再 `return path`，落盘是 fire-and-forget，路径先交给调用方。
- `:52-59`：`write` 的 `try/catch` 吞掉建目录与写文件的所有错误（注释说明这是 advisory host preview，不得影响工具完成）。
- `:62-64`：`safePathPart` 只保留 `[A-Za-z0-9_.-]`，把 `/` 换成 `-`，因此单个路径段可以是 `.` 或 `..`，但不可能含有分隔符。

路径字段的来源（同一基线）：

- `src/agent/protocol/events.ts:42`：`{ type: "tool_result"; sessionId: string; turnId: string; result: PilotDeckToolResult }` 只是普通 `string`，无格式约束。
- `src/gateway/client/GatewayAgentEventProjector.ts:146-150`：把 `event.sessionId`、`event.turnId`、`event.result.toolCallId` 原样交给 `persist`。
- `src/gateway/server/GatewayWsConnection.ts:124-136`：`submit_turn` 从客户端 `frame.params` 取 `sessionKey` 并把整个 params 展开成 `GatewaySubmitTurnInput`，不校验字符串形状；`src/gateway/Gateway.ts:80` 用它作 `sessionId`。
- `src/gateway/client/InProcessGateway.ts:903`：`const runId = input.runId ?? this.uuid()`；`:1255` 把 `runId` 当 `turnId` 发出。客户端可在 `submit_turn` 的 params 里自带 `runId`。
- `toolCallId` 来自工具结果本身（提供方/工具运行器给的 id），同样是未经形状约束的字符串；`safePathPart` 允许 `.`。

所以 `sessionId`/`turnId` 为 `..` 在 TS 侧可达（客户端可控），而 `"../.."` 会被 `safePathPart` 变成单段 `..-..`，无害。TS 遇到 `..` 会 `path.resolve` 把 `pilotdeck-tool-results` 这一级消掉，照写到共享 tmpdir 的别处。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/turn/projector.rs`：

- `:281-321` `persist`：`root = resolve_lexically(self.root_dir)`；`directory`/`path` 仍按 TS `path.resolve` 词法归一化。随后检查 `path.strip_prefix(&root)`：失败（`..` 把某一级弹出根外）就返回 `Ok(None)`——既不排队、也不把路径交给调用方，且不抛错（与「写入没能入队」同一分支）；工具结果本身仍照常投影，只是 `resultPath` 为 `undefined`，根外不出现文件（fail-closed；TS 会照写到根外并返回根外路径）。通过检查后行为不变：advisory 写投递到 detached writer，队列接受时照旧先返回路径；writer 内的错误只让该次写静默结束（`persist` 不抛、不 panic、不中断回合）。
- `:106-133` `ArtifactIo`：默认 `new()` 用 `Secure`（fd 相对、见下）；`with_io` 保留 TS `createDirectory`/`writeText` 注入点（测试与非 unix 主机），hook 收到的仍是最终路径/目录路径。
- `:351-403` `write_artifact_secure`（unix）：`base = root.parent()`（默认即 tmpdir，macOS 的 `/tmp` 符号链接在这一层由 `File::open` 跟随，属既有行为）；`base` 允许多级自定义 root，先 `create_dir_all(base)` 再固定 `base_fd`。逐级创建复用 `crate::project_files::create_directories_at`（`project_files.rs:138-180`，`openat`/`mkdirat` 全部相对固定父 fd、每级 `O_NOFOLLOW|O_DIRECTORY`、`mkdirat` 的 `EEXIST` 在 `:153-158` 被当作「已存在」继续打开，正好覆盖并发创建）。之后从 `base_fd` 起把 `root` 及其下每级（root/session/turn）用 `O_RDONLY|O_DIRECTORY|O_CLOEXEC|O_NOFOLLOW` 重新 `openat`，对 fd 取 `metadata`（`fstat`，不再按路径名）交 `verify_private_directory` 核对，再 `fchmod 0700`：既补上 umask 对 mkdir/open mode 的遮蔽，也把旧版本按 umask 留下的 0755 既有层级收紧。最终文件用 `openat(父 fd, "<call>.txt", O_WRONLY|O_CREAT|O_TRUNC|O_CLOEXEC|O_NONBLOCK|O_NOFOLLOW, 0600)` 打开，`fstat` 必须是普通文件（`O_NONBLOCK` 防竞态换入的 FIFO 挂住 writer），再写内容。中间级在「核对之后、打开之前」被换掉也无法把写重定向：后续打开都相对已固定的父 fd。writer 内仍保留自己的根外检查（`refused_artifact_path`）作为纵深防御。
- `:431-467` `verify_private_directory`：`file_type().is_symlink()` → `PermissionDenied`；`!is_dir()` → `NotADirectory`；`metadata.uid() != rustix::process::geteuid().as_raw()` → `PermissionDenied`（含双方 uid 的错误文本）。抽成纯函数 `(path, metadata, expected_uid)` 是为了让属主分支能用合成的 uid 测试——非 root 无法 `chown` 出别人的目录。
- `:415-424` `refused_artifact_path`：writer 内根外路径的 `PermissionDenied` 错误（advisory 写失败被吞掉，不改变 `persist` 返回值）。
- 非 unix 分支保持 `create_dir_all`/`fs::write` 不变；除 `..` 的根内检查外，安全加固只在 unix 生效。

## 范围

只覆盖 `root_dir` 及其下各级；默认根位于共享临时目录（Linux `/tmp`），`root_dir` 的父目录（tmpdir 本身）不做属主核对。正常情况完全不变：目录名、`<session>/<turn>/<call>.txt` 文件名、落盘内容、阈值、0600 文件权限都与 TS 相同；新目录为 0700（TS 按 umask，共享 `/tmp` 下常为 0755）。偏离只发生在恶意/异常输入时：

- 根级或中间级符号链接：TS 跟随并写进链接目标；Rust 拒写，链接目标不出现任何文件（`create_directories_at` 的 `O_NOFOLLOW` 打开失败）。
- 最终文件符号链接：TS 截断/覆盖链接目标；Rust `O_NOFOLLOW` 打开失败，目标内容不变。
- 属主不是当前 euid 的目录：TS 照写（内容可被目录所有者读取）；Rust 拒写。
- 同名的普通文件占位：TS `mkdir` 报错但 `catch` 吞掉；Rust 同样报错不写（`NotADirectory`）。
- **`..` 逃逸**：`sessionId` 或 `turnId` 恰为 `..` 时，`resolve_lexically` 会把 `pilotdeck-tool-results`（或更上一层）消掉，最终路径落到共享 tmpdir 里、不再有任何属主/符号链接核对。TS 照写到根外并返回根外路径；Rust 在 `persist` 里 `strip_prefix(root)` 失败即拒写：不排队、不返回路径、也不抛错，该 `tool_result` 事件照常投影（`resultPath` 缺省，其余 preview/行数/字节数不变），根外不出现文件。这是本条目唯一一处**会改变 `persist` 返回值**的偏离（TS 返回根外路径，Rust 返回 `None`）；方向是更安全，且不再像 fix-r1 那样因 `Err` 丢掉整个投影。`sessionId`/`turnId` 为 `.` 的归一化、以及 `"../.."` 被 `safePathPart` 折叠成单段 `..-..` 的行为不受影响。
- 既有目录权限：新版本把 `root_dir` 及其下既有层级也 `fchmod 0700`；TS 保留旧权限（常为 0755）。收紧只发生在属主已是当前 euid 的层，外来属主仍直接拒写。
- 并发创建：两个同用户写方同时首次建同一级时，后到的 `EEXIST` 按「已存在」继续（与 TS `mkdir recursive` 一致；不使用会直接报错的裸 `create_dir`）。
- 显式传入的自定义 `rootDir`：保护起点改为 `rootDir` 本身（不再靠路径组件名 `pilotdeck-tool-results` 判断），因此自定义根也会核属主/类型并收紧为 0700；默认根的行为与旧描述相同。
