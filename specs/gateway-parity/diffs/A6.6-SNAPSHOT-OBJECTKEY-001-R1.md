## 类别

对既有登记条目的更正（安全加固范围扩大）：原条目登记的词法前缀检查不防符号链接，本次修复把边界检查移到打开操作本身。

## 基线依据

原条目 `A6.6-SNAPSHOT-OBJECTKEY-001`（`specs/gateway-parity/diffs/A6.6-SNAPSHOT-OBJECTKEY-001.md`，原字节冻结）只覆盖 `../` 与绝对路径越界（Node v22.22.0 实测 `_tmp/20261026-issue-293/probe-a-objectkey.out`）。TS 基线不变：cc7c4e6 `src/storage/workspaceSnapshot.ts:128-131` 对 `objectKey` 无任何校验，`resolve(config.snapshotRoot, entry.objectKey)` 后 `readFile` 会跟随符号链接读出根外内容——原条目的越界实测即由此产生，链接场景是同一基线行为的子集（读码，未单独另测 TS）。

## Rust 行为

`src/pilotdeck-gateway/src/storage/workspace_snapshot.rs` 的 `restore_units`（:493-497 调用点）：词法前缀检查（`units_within` :1442-1450，与目标侧共用，保留 TS 的 `//` 拼写）之后，不再用 `fs::read` 直接读共享路径，而是 `read_object_within_root`（:1490-1539，unix）——从快照根目录句柄开始逐组件 `openat`（`O_NOFOLLOW`，中间组件 `+DIRECTORY`，末级 `+NONBLOCK` 防 FIFO 挂起），任一组件是符号链接（ELOOP，或 ENOTDIR + 对固定父目录的 `statat(SYMLINK_NOFOLLOW)` 证明）一律返回 `ObjectKeyEscape`；非 Normal 组件也拒绝（防御）。非 unix 平台保留实测的 Node 读形状（`fs::read` 回退，:1543-1550，未实测）。

## 范围

词法检查与受约束打开合并后的直接结论：指向根外、根内、悬空的链接组件均拒绝（保守：链接的真实目标不是 key 自己的路径）；快照根本身按部署配置路径打开（与其它 snapshot 操作同样跟随根路径的解析，这是配置根而非攻击者输入）。根恰为 `/` 时 TS 的 `destination + sep` 也是 `//` 前缀（Node v22.22.0 实测 `_tmp/20261026-issue-293/fix-r1/probe-root-prefix.out`），根内 key 全部词法越界——Rust 保持一致，不修。`entry.path` 侧、list/get 原样返回不变。
