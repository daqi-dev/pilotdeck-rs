## 类别

更正（Rust 侧已随 #2026 决策 C 对齐大半，非陈述错误）：`A8.3-CH-SMS-013`
登记的核心差异——「Rust 的 `stop()` 在停止服务那一刻就清 client，没有
『服务器已停、连接还在排水、client 仍可用』这段窗口」——**已被 #2026 决策 C
消掉**：`SmsHandle::stop()` 现在 drain 在途连接（上限 60 s，见
`A8.3-CH-SMS-014`），client 的置空移到 drain 之后，与 TS 的
`server.close()` 回调顺序一致。

收窄后只剩一条派生残差：**上限截断时**，Rust 在 `stop()` 返回（60 s 上限到
点）时即清 client，而 TS 的 `stop()` 仍阻塞在 close 回调、client 继续可用
（直至客户端自己离开）。这条残差登记在 `A8.3-CH-SMS-014` 残差 4，本条只做
指向。013 范围表里「stop 已调用、连接仍在排水，`sendReply`：TS true /
Rust false」一格对未截断路径已不成立，对截断路径维持。

## Rust 行为

`src/pilotdeck-gateway/src/channel/sms/mod.rs`（#2026，基于 5c694ee6e）：
`stop()` 的收尾顺序为 `shutdown.send(true)` → `server.task.await`
（**含 drain**）→ 置空 `runtime.client`。与 013 登记的旧实现
（`stop()` 只 await accept 循环、立即清 client）相比，client 置空推迟到
drain 之后；截断路径上推迟到 60 s 上限。

013「Rust 行为」节引用的配对用例 `stop_returns_before_the_detached_connection_ends`
与变异开关 `sms-stop-waits-for-connections` 已随实现更替：用例改名为
`stop_drains_a_half_sent_header_once_the_header_timeout_fires`（断言随之反
转），开关换成 `sms-stop-no-drain`（回到 #2026 前 detach 形状）与
`sms-stop-drain-unbounded`（回到 TS 无界形状），负控行同步登记在
`tests/fixtures/channel-sms-head-timeout/negative_controls.py`。

## 范围

只更正 013 的 Rust 侧行为与机器判据。013 的 TS 侧实测（三格点时序）与
`send_reply` / `sendReply` 同判据的黑盒读法不变。未截断路径的窗口差异已消
除；截断路径的窗口差异（`stop()` 返回时刻 client 已清 vs TS 仍可用）读
`A8.3-CH-SMS-014` 残差 4。`stop()` 的 reason 默认值、头/体读期限取值不在
本条范围。

## 机器判据

与 `A8.3-CH-SMS-014`「机器判据」同一组，本条只指向：

  的三格断言：drain 中 `send_reply` `true`（本条核心，替代 013 的
  `stop_returns_before_the_detached_connection_ends`）；返回后 `false`；
  返回后 EOF 已 pending。

- TS 侧复算命令不变：`PROBE_PORT=18784 node _tmp/20261107-issue-1955-prereq/smoke/ts-stop-client-timing.mjs`
  （须复现 `duringDrain.clientPresent=true` /
