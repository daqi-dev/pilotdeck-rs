## 类别

同刻注册序与完成/idle 超时优先级（行为缺陷候选）。原条目结论不变；R1 只记录
#752 第一包（ERROR-CLASS）带来的 Rust `name` 快照变化，并把叠加原因写明。
不把本类差异视为已修复，也不增加判分豁免。

## 基线依据

同原条目：固定基线 OpenBMB/PilotDeck@cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，
Node v22.22.0；`src/tool/builtin/web/urlFetcher.ts:153-169` 与
`src/network/fetch.ts:64-96`。TS 金样仍为
`src/pilotdeck-gateway/tests/fixtures/network-timing/oracle.json`。

## Rust 行为

同刻判定（`runtime/network.rs::exchange` / `body_frame_with_abort` 的
`parent_first=false`）未改。`runtime/tools/builtin/web/fetcher.rs` 的
`FetchError::Other` 现在保留 TS `Error.name`；因此本类中两个 web_fetch 抛出格的
Rust `name` 从 `null` 变为 `NetworkFetchError`：

- `web_fetch/headers/rejected/tie-parent-first`
- `web_fetch/redirect-hop/rejected/tie-parent-first`

其余四格（两个 web_fetch 成功格、两个 fetch_redirect body idle 格）的 Rust 值不变。
`known_differences.json` 的 `rust` 快照已同步，原条目的逐格表是登记时快照，
其 `name=null` 行以本 R1 与 json 为准。

## 范围

6 格不变（pr1 的 web_fetch 4 + fetch_redirect 2），仍全部 ignore；差异的原因是
同刻注册序/完成源，而不是 `name`。本 R1 只覆盖上述两个 web_fetch 格的 `name` 字段；
`message`/`delivery`/`content`/`calls`/`retries` 仍按原条目保留差异。
pr2b 新增的 19 格 PARENT-TIE-002 未被 #752 改动，不在本 R1 范围。

## 机器判据

`tests/network_timing.rs` 的 `known_differences_remain_exact_and_ignored` 逐格重放
`known_differences.json` 的 Rust 当前值；本类 6 格仍严格断言 TS 原值且保持 ignore，
显式 `--ignored` 时仍在完整 observable 断言处失败。默认运行
`171 passed; 0 failed; 22 ignored`。#752 的错误类型修复与负控见
`A6.4-NETWORK-TIMING-ERROR-CLASS-001-R1.md`；复算：

  --manifest-path src/Cargo.toml -p pilotdeck-gateway --test network_timing -- --test-threads=1
