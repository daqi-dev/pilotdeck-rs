## 类别

不可避免（安全加固）。TS 基线的 `UploadStore.readAt`（`UploadStore.ts:370-392`）与附件 composer（`GatewayAttachmentTurnComposer.ts:125-151`）都是「canonicalize → 前缀检查 → open」序列；同形竞态在 TS 上同样能读出项目外字节（node v22.22.0 实测，见 `_tmp/20261106-issue-1468-1494/ts-probe/`）。Rust 端口把批准对象绑定到已打开句柄并新增两条拒绝，这不是对齐 TS 而是对抗性收紧，故记录新增的偏离文案与拒绝面，不改变冻结判据。

## 基线依据

固定 cc7c4e6：`src/gateway/client/UploadStore.ts:370-392` 的 `readAt` 在 realpath 与前缀检查之后重新 `readFile(metadataPath)`；`GatewayAttachmentTurnComposer.ts:125-151` 的附件解析对 lease 路径做 stat/open。真实实测：Node v22.22.0 探针 `_tmp/20261106-issue-1468-1494/ts-probe/read_at_toctou_probe.mjs` 在 canonicalize 后把 `metadata.json` 换成指向项目外的 symlink，TS 读回外部记录（原始输出同目录 `probe.out`）。macOS `fcntl(F_GETPATH)` 的硬链接/rename 语义探针在同目录 `probe/`。不是只读码推断。

## Rust 行为

`native_process/services.rs`：open 前用 `fs::symlink_metadata`（不跟随叶链接）记录批准对象身份，open 后用平台句柄路径（`handle_path.rs`：macOS F_GETPATH / Linux `/proc/self/fd`）做「租约根 ∪ canonical upload-store 根」双根包含性检查，并把句柄 fstat 与批准身份按 `(dev, inode)` 绑定。`upload/mod.rs` 的 `read_at` 同样增加 open 前身份与句柄包含性/身份比对。新增的拒绝形状 TS 无对应：`Upload metadata path became a symlink after validation.`、`Upload metadata handle leaves the upload directory.`、`Upload metadata handle names a different file than the one validated.`，以及附件 lease 的 not-found 诊断（`attachment lease path became a symlink after validation` 等）。

`upload/mod.rs` 的 lease 获取（`acquire_attachment_lease`）另加两道：(1) `verified` 在每个附件**同一次打开**的句柄上记录 `(dev, inode)`，`fs::hard_link` 建链后用 `symlink_metadata` 读**链接本身**比对，不一致或不是普通文件即 `ATTACHMENT_TAMPERED`／`Attachment artifact changed between verification and lease acquisition.`——这是 TS 完全没有的拒绝面（TS 只按路径建链）；(2) 非 Unix 无跨平台文件身份，该比对跳过并在源码注释写明，Unix 是出货目标。

两个「合法家」根（`.tmp/chat-uploads` 与 `.tmp/chat-upload-leases`）共用 `canonical_home`：根本身是符号链接（即便指向工程内子树）一律不是家，再由 canonical 前缀判包含性。TS 没有「家」的概念，这条同样是 Rust 侧的收紧。

## 范围

只影响本地可写项目 `.tmp/chat-uploads` / `.tmp/chat-upload-leases` 的对抗性换链与 rename；正常路径、既有错误码与 TS 可观察形状不变。非 Unix 无跨平台文件身份，句柄路径是唯一不查路径的步骤，残余窗口已在源码注释如实记录。租约根内开 turn 之前预置的硬链接不在本序列范围（#1468 跟进项）。
