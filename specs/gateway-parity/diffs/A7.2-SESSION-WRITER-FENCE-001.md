## 类别

基线 bug：丢数据（意向书「什么算 bug」第①条）。

## 基线依据

Node v22.22.0 运行固定 cc7c4e6 的 ProjectSessionFactory / AgentHandle。session-factory/oracle.json 的 writerInterleavings 两时序均重复 sequence，resume 报 sequence_not_increasing；保留 tsDefect=true。新增 fenceMatrix 48 格原始探针显示 TS 允许旧 writer 尚未释放时读取/发布候选。

## Rust 行为

同一 canonical transcript 路径以进程租约和既有 LedgerLock 排他；recreate 先中止并 dispose，等待最长复用 Limits.close_timeout 的1秒预算。load 前取得租约，从磁盘恢复序号；超时返回 SESSION_WRITER_BUSY，不发布候选、不强收旧租约。关闭后同 owner 可重试 resume。 实现：src/pilotdeck-gateway/src/runtime/session/factory.rs、owner.rs。

## 范围

ProjectSessionFactory 的初建、重建和关闭；TS 原始损坏不作为 Rust 安全目标。其他产品入口尚未宣称迁移完成。文件锁新增 .lock 为同一安全修复的一部分；锁文件不删除，避免锁inode分裂。

## 机器判据

recreate_running_before_read / recreate_running_after_publish_resume / writer_fence_timeout_then_owner_resume / writer_lease_excludes_second_factory_and_alias / 48个 fence_* 用例。负控 writer-lease-removed、writer-drain-wait-removed、writer-timeout-candidate 等完整绑定在 negative_controls.py。 测试前缀 runtime::session::factory::tests::；夹具目录 src/pilotdeck-gateway/tests/fixtures/session-factory/。
