## 基线依据

cc7c4e6 `src/cli/ProjectSessionRuntimeBundle.ts:216-226,374-392` 在 session 组合时取得项目与 contribution 租约；`src/agent/modules/transport/sidecarTurnComposition.ts:65-97` 按真实 ports 绑定。`sidecarDefaultModuleDispatcher.ts:394-436` 按模块存在性广告，实际 manifest 48 金样由仓内 `tests/fixtures/host-manifest/generate.mts` 直接 import 采集，与既有 oracle 字节一致，证据 `_tmp/20261025-issue-589-consume/ts-manifest/`。

TS `agentLoopSidecarClient.ts:379-399` 在唯一 generator pump 读取 host event buffer，含 500ms pump；`:1504-1536` 还做 timeline/subagent 状态投影。TS recorder (`SteerMailbox.ts:180-190`) 无明确 I/O deadline。

## Rust 行为

`runtime/turn/live.rs` 的 `with_interaction` 在每轮 request identity 已解析后调用宿主 factory，`runtime/turn/interaction.rs` 从该租约独立探测四资源并绑定，profile 覆写为该 generation 的 profile。新轮可用新 generation，旧轮持有旧租约直到清理结束。缺失 recorder 时拒绝装配，不将外围 timeout 当作实际 I/O 截止保证。

host events 在 callback 边界 drain，完整性观察同步完成；wire 接收时预留交付顺序，避免后到模块 callback 的 host events 越过已收到但未应用的 wire lifecycle。无独立 500ms pump；本包不提供 TS 的 host timeline/subagent 派生投影。后台直接写缓冲且没有后续 callback 的即时发布与该投影留后续包，不能据此声称完整 TS 对拍通过。

fix-r2 补记（未批准，非已接受差异）：`StreamHandler::event` 的非 final 嵌入回调在调用 inner 和发布前，拒绝缺失、undefined、null、标量及数组 payload，返回 Protocol / `Sidecar event payload is not an AgentEvent.`。cc7c4e6 `src/agent/modules/transport/agentLoopSidecarClient.ts:1310-1317,1739-1743` 的 `readAgentEvent` / `asRecord` 对这些输入实际返回同一错误；线缆路径先在 `src/agent/modules/protocol.ts:330-335` 返回 `MISSING_EVENT_FIELD` / `Event sequence, final, and payload are required.`，Rust `protocol/module.rs` 已作相同形状检查。`host/execution.rs` 的身份错误文案属于后续 type/session/turn 检查，非这些输入的实际 wire 错误，本轮不改。与此不同，TS `src/agent/modules/events/hostAgentEventBridge.ts:35-49` 的 emitter 本身不校验、原样调用 event 模块且吞掉调用失败；因此嵌入回调新增拒绝相对于该 bridge 是显式收紧，不能视为已批准的全路径等价。此 guard 仅管非 final 对象形状，type/session/turn 由既有 receive/inner 合同负责；final 仍交 inner，payload 不直接转发。Node 原函数实测（逐文件比对基线 git blob、AST 提取未导出的准入函数）见 `_tmp/20261025-issue-589-combined-fix-r2/ts-payload-probe.cjs` 与 `ts-payload-final.log`；首轮 `01-ts-payload.log` 的 wire fixture 缺 eventType，不作为 wire payload 证据。
