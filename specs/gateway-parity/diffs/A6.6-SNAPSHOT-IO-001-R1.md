## 类别

对既有登记条目的更正（实现限制的回退形状描述已过期）：表外 errno 的 `_FAILED.json.error` 回退不再是 `io::Error::to_string()` 的 Rust Display 文案，而是空串（host boundary）。

## 基线依据

原条目 `A6.6-SNAPSHOT-IO-001`（`specs/gateway-parity/accepted-diffs.md:142-149`，原字节冻结）的「Rust 行为」仍写「表外回退 `io::Error::to_string()`，可能写入与 TS 不同的 `_FAILED.json.error`」。cc7c4e6 `src/storage/workspaceSnapshot.ts:260-279` 的基线行为不变：实际 Error.message 写入失败标记；本更正只针对 Rust 侧表外回退的形状，不涉及 TS 基线。

## Rust 行为

`src/pilotdeck-gateway/src/storage/workspace_snapshot.rs`：`io_error`（:1600-1609）与 `two_path_message` 的表外 errno 回退，以及 `random_uuid` 失败臂（:850、:1323）统一走 `host_boundary_io()`（:1614-1619）——`WorkspaceSnapshotError::Io { code: None, message: String::new() }`。`runtime/snapshot.rs` 的 `project_error` 对 `code: None` 按 `NODE_IO_REQUIRED` 处理，空消息不再把 Rust Display 写上协议线（node_io.rs 的既有约定：表外 errno 属宿主边界）。

## 范围

仅表外 errno 的回退形状与 uuid 随机失败（TS 不会失败）臂；已测量表内 errno 的文案、成功路径、JSON 语法错误行为不变。对捕获结果的影响：失败标记的 `error` 字段为空串，`list()` 读 marker 时不解读该字段（读码 `read_failure_message` :1336-1340 只原样返回字符串，空串与缺失在投影侧同样呈现）；投影错误路径表现为 `NODE_IO_REQUIRED` 宿主边界而非带文案的 Error。与旧登记的差异：旧文本描述的「Rust Display 可能写入 marker」已不成立，读旧尺子者应以本条为准。

## 机器判据

`src/pilotdeck-gateway/src/storage/workspace_snapshot.rs` 内部测试 `io_error`/`two_path_message` 表外 errno 断言 `code: None` 与空消息；`tests/fixtures/workspace-snapshot-gate/negative_controls.py` 的 `IO_ERROR_ARM`、`TWO_PATH_ARM`、`UUID_DISPLAY` 变异（把空消息换回 Rust Display）要求 KILLED。复算：`cargo test -p pilotdeck-gateway --locked --offline --lib snapshot`。
