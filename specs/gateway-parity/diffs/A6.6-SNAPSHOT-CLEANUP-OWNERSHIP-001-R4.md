## 类别

对既有登记条目的更正：R3/R4 引入的「manifest 实际可读」早退判定使用阻塞式
`fs::read`，r5 评审 P0（两家复核之一点名、另一家复核确认修法）——无写端 FIFO 的
`manifest.json`（或持续打开不 EOF 的写端）会阻塞 open/read，`capture_once` 永不返回，
同 key follower 永等 Condvar；`list()` 的 walk 对 FIFO manifest 同样阻塞。按协调者
fix-r5 指定修法修复。

## 基线依据

原条目 `A6.6-SNAPSHOT-CLEANUP-OWNERSHIP-001` 及其 R1、R2、R3（原字节冻结）。TS 基线
不变（cc7c4e6 `src/storage/workspaceSnapshot.ts`）。本轮新增实测（Node v22.22.0，
`_tmp/20261026-issue-293/fix-r5/probe/node-fifo-probe.out`）：`fs.promises.readFile` 对
① 无写端 FIFO、② 写端持续打开不写数据的 FIFO，均 3 s 期限内不返回且进程不退出——
TS 的 `list()`（readFile manifest）与 capture 失败腿的 `_FAILED.json` 读取
（workspaceSnapshot.ts:366-373）在 FIFO 上同样挂起；TS capture 早退本身不读 manifest
（R3 已登记「TS 只看 marker」，读码推断），故早退 manifest 读的挂起是 Rust 侧 R3/R4
新增读侧的缺陷，非 TS 行为。既有 oracle 钉死行为继续有效：场景 `manifest-read-dir`
（`tests/fixtures/workspace-snapshot/oracle.json`）——TS `list()` 对指向目录的符号链接
manifest 是跟随打开、read 阶段报 `EISDIR: illegal operation on a directory, read`。

## Rust 行为

`src/pilotdeck-gateway/src/storage/workspace_snapshot.rs`：新增
`read_snapshot_bytes`（函数名锚点，unix/非 unix 两半），复用
`storage/file_history.rs:732-750` 私有备份守卫的形状——`OpenOptions` +
`custom_flags(libc::O_NONBLOCK)` 打开，对**同一 fd** `metadata()` 取类型（fstat，无
TOCTOU）再读。既非普通文件也非目录 → 不读，直接 EPERM（file_history 拒绝写穿的同一
errno，node_io 表内 `EPERM: operation not permitted, open '<path>'`）；目录放行到
read，保留 Node 自己的读阶段 EISDIR；符号链接照常跟随（与 oracle `manifest-read-dir`
一致——这也是不采用 file_history 的 O_NOFOLLOW 的原因：O_NOFOLLOW 会让该钉死场景
报 ELOOP）。三个调用点共用：`capture_once` 早退提交判定（非普通文件 / 打开失败 /
读失败 → 视为未提交，重新捕获发布）、`walk_manifests`（`list()`/`get()`/`restore()`
的 manifest 读）、`read_failure_message`（`_FAILED.json` 读：任何读失败本就无 error，
FIFO 亦然，早退 Failed + `error: None`）。与 R3 已登记的「对象读 O_NOFOLLOW 组件
游走」不冲突：那是 objectKey 逃逸防护，manifest 读跟随链接是 oracle 钉死行为。

## 范围

新增登记偏离（TS 侧行为为挂起，实测见基线依据）：① `list()`/`get()`/`restore()` 的
walk 遇 FIFO/套接字/设备 manifest → 立即 `Io{EPERM}` 失败，不挂起（设备文件原
`fs::read` 可能成功返回空内容再报 JSON 语法错误，现一律 EPERM；oracle 语料无设备
manifest 场景，读码推断）；② capture 失败腿遇 FIFO `_FAILED.json` → Failed 且
`error: None`，不挂起。早退提交判定对 FIFO manifest 的行为不是对 TS 的偏离（TS 根本
不读），是 R3/R4 已登记偏离的读侧形状修正：FIFO 属「读失败」→ 未提交 → 重发。
R1 登记的 `.tmp-grave-*` 残余、R3 登记的崩溃遗留 `.staging/<uuid>` 无回收、`.staging`
父目录常驻均不变。`scan_visit` 只对普通文件调 `store_file`（FIFO 不产生 entry），
`read_object_within_root` 已有 NONBLOCK（R1），均不在本轮范围。
