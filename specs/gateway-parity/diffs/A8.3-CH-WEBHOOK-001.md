## 类别

传输层呈现差异（不可避免）：webhook 车道复用
`crate::http_proxy::serve_connection_native_with_shutdown` 的 hyper 1.x
HTTP/1.1 编解码器。body 读超时（Node `requestTimeout` 等价，300 s）后写出的
408 在语义上与 TS 一致（状态行 408、`Connection: close`、零长 body、随后关
连接），但 hyper 公开 API 对未知长度的空 body 一律补 chunked 帧，Node 的
`_http_server.js` `requestTimeoutResponse` 是 51 字节无帧原文。hyper 不提供
改写该帧的公开扩展点，属 A8.4-NATIVE-HTTP-001 已登记的同一
hyper-public-API 呈现差异类。

## 基线依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0。

- `src/adapters/channel/webhook/WebhookChannel.ts:84` 用
  `http.createServer(...)`（无 options，故 `requestTimeout` 取 Node 默认
  300000 ms）；`handleRequest` 的 body 读未完成时由 Node 在 30 s
  connections-checker 网格上回 `requestTimeoutResponse`。
- Node 原文 51 字节：`HTTP/1.1 408 Request Timeout\r\nConnection: close\r\n\r\n`
  （无 `content-length`、无 `date`、无 `Transfer-Encoding`）。真实实测探针
  `_tmp/20261026-issue-1334/fix-r1/node-probe/probe4.mjs` /
  `probe4.out`（本树内，原始输出：
  `"HTTP/1.1 408 Request Timeout\r\nConnection: close\r\n\r\n"`，客户端在
  +518 ms 收到后连接关闭）。同字节常量另见
  `src/pilotdeck-gateway/src/user_dialog/http_store.rs:85`
  （`NODE_408_RESPONSE`，fixture
  `tests/fixtures/user-dialog-http-store/header-lifecycle/node-408.bin`）。

## Rust 行为

`src/pilotdeck-gateway/src/channel/webhook/mod.rs` 的 `read_request_body`
以 `DEFAULT_REQUEST_TIMEOUT`（300 s，可注入短值）为唯一 deadline；超时后
经 handler 返回 408，hyper 在写响应时把未知长度空 body 帧化为
`Transfer-Encoding: chunked\r\n\r\n0\r\n\r\n`，实际线上字节为
`HTTP/1.1 408 Request Timeout\r\nConnection: close\r\nTransfer-Encoding:
chunked\r\n\r\n0\r\n\r\n`（`WEBHOOK_REQUEST_TIMEOUT_RESPONSE`，
`src/pilotdeck-gateway/src/channel/webhook/tests.rs`）。

`webhook_408_is_node_bytes_plus_hyper_framing` 断言上式恒等：Rust 字节 =
Node 的 51 字节去掉结尾 CRLF + hyper chunked 帧。即本条只登记"帧化"这一项
呈现差异，不含状态码、头名语义或连接关闭行为上的任何差异。

## 范围

仅 webhook 车道（`/webhooks/:name` 的 body 读）超时 408 的**帧级呈现**，
一条响应、一个场景：客户端声明 `Content-Length` 后不把 body 发完，超时到期
时线上字节。不影响：

- 超时**触发时机**（Rust 恰在 deadline，Node 落在 30 s connections-checker
  网格）——该时序残差单独登记在 `A8.3-CH-WEBHOOK-002`（本车道条目；机制与
  同族实测见那里引用的 `A7.4-HTTPSTORE-431-408-SHAPE-001-R3`/`-R4` 与
  `A8.4-NATIVE-HTTP-002-R2`）；
- 字面量 JSON `null` body 的挂起——实测 TS 基线同样挂住（Node
  `requestTimeout` 只覆盖未读完的 body，4 字节 `null` 已读完），Rust 的
  `std::future::pending()` 是等价复刻，不是偏离，因此**不是本条差异**；
  登记见跟进单 #1557，实测见
  `_tmp/20261105-issue-1534/ts-probe/`；
- 金样 19 场景矩阵的归一化（该矩阵不含 408 格，见
  `src/pilotdeck-gateway/tests/fixtures/webhook-channel/README.md`）。

本条不构成判分豁免：修正该 408 的字节断言仍会按上面的恒等式报错。

## 机器判据

- `src/pilotdeck-gateway/src/channel/webhook/tests.rs`
  `shutdown_with_partial_body_finishes_at_request_timeout`：半截 body +
  客户端保持 socket → 收到上述字节、连接关闭、并发 `stop()` 在有界时间内
  返回。
- 同文件 `webhook_408_is_node_bytes_plus_hyper_framing`：把钉死字节与
  `NODE_408_RESPONSE`（`user_dialog::http_store`，`pub(crate)`）+ 帧化常量
  逐字节对上，防止"Node 408"式文案与字节再次脱节。
- 负控：`src/pilotdeck-gateway/tests/fixtures/webhook-channel/
  negative_controls.py` 的 `webhook-body-read-no-timeout`（去掉 body 读
  deadline，上条测试转红）。
