## 类别

bug 修复：LLM 已发送响应头后，TS 的配置超时失效，持续拖延的响应体可使 memory 调用无法按配置的截止时间结束。Rust 把同一单次截止时间保留到响应体读完。

## 基线依据

固定 cc7c4e6 的 `src/context/memory/edgeclaw-memory-core/src/core/skills/llm-extraction.ts:2340-2359` 在 fetch 返回头时撤销 timer；`response.text()` / `response.json()` 位于此 timer 之外。Node v22.22.0 直接 import 的真实探针在 `src/pilotdeck-gateway/tests/fixtures/edgeclaw-llm/{observe,stub}.mts`。

`oracle.json` 中 `body-hang-{chat,responses}-{200,503}` 四格均记录已收到头、timer cleared、跨过配置截止后仍 pending；探针随后主动关闭本地连接。该有限观测不声称证明无限壁钟等待，证明的是配置的单次截止失效。原始运行记录见 `_tmp/20261026-issue-763/ts-generate-7.log`。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/memory/edgeclaw/llm/transport.rs` 在每个 attempt 开始时计算截止，headers 与 body 复用该截止。默认/非有限数取 30000 ms，<=0 不设请求截止；正数依 Node timer 规则归一化。成功响应 body 读取仍在 retry/fallback 外；错误状态 body 读取在 retry 内。

超时文案保持 `<label> request timed out after <ms>ms`。该文案不匹配 TS 的 `/timeout/i`，所以不自行增加重试；chat 的错误响应 body 超时仍可去 response_format 回退一次。丢弃在途 future 释放请求和响应体，没有额外 detached task。

## 范围

仅 A6.6 EdgeClaw 结构化 LLM 调用的单次响应体截止；不修改共享 model/http.rs，不改变其它模型调用、重试状态码、退避、重定向、JSON 解析或输出提取。成功 body 不因本差异进入重试。
