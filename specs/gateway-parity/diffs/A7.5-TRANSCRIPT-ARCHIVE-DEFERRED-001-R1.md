## 类别

更正（移植收口，撤回原条目的现状态登记）。#2622 把 export / restore_session_transcript
两个 delegate 从 TS 基线移植进 Rust 网关并翻牌（撤 `NOT_ADVERTISED` 例外、capabilities
表加名），原条目三场景表（describe 少名、export 恒 `CAPABILITY_UNAVAILABLE`、restore
恒 `CAPABILITY_UNAVAILABLE`）所述分歧全部消除。原条目对 2026-11-09 时点（路由在、
处理器恒拒绝、不广告）仍准确，其历史登记与「有意改进（范围暂缓）」定性不撤；本条登记
翻牌后的现状，及移植实现相对 TS 的残余结构性差异（见「Rust 行为」末列）。

## Rust 行为

`native_process/methods/transcript_archive.rs`（#2622 新增；export delegate
`export_session_transcript`、restore delegate `restore_session_transcript`）：
守卫次序照 TS——export 为 projectKey → sessionKey →
hasActiveTurn（SESSION_BUSY）→ `transcript_missing`（SESSION_NOT_FOUND）→ error 诊断
（SESSION_TRANSCRIPT_INVALID）→ 投影 → validate；restore 为 busy 门（`hasActiveTurn ||
current_handle`，对照 TS `hasActiveTurn || hasSession`）→ `restoring_session_keys`
（SESSION_RESTORE_CONFLICT）→ 对 wire 上的 raw archive 先 validate（字节量检查走
`js_value::json_stringify` 共享口径：超 2000 容器报 V8 RangeError，与 TS
`Buffer.byteLength(JSON.stringify(...))` 抛出面同域）→ transcript
fence 下 exists 检查（SESSION_RESTORE_CONFLICT）→ 临时 JSONL + rename，返回
`{sessionKey, importedMessages}`。`methods/history.rs:40-41` 路由真实现（原
`unavailable()` 桩删除）；`capabilities.rs:100-101` 表行 `session_transcript_archive`
promise 两方法，`NOT_ADVERTISED` 例外删除，describe 广告该名。

残余结构性差异（照实登记，均非判分豁免）：

- R8：TS 对 external store 无 `replaceTranscript` 的会话答 `SESSION_RESTORE_UNSUPPORTED`
  （createLocalGateway.ts:1332-1334）；Rust 的目标存储恒为 JSONL 写入器，sibling-temp
  rename 即原子 replace，该拒绝分支结构性不可达（仓内无生产 store 不支持 replace）。
- R11（同进程严格化）：TS 的 `restoringSessionKeys.has`（:1321）与集合 add
  （:1338）之间含 await，两个并发 restore 都可能过检后写（manifest 已登记的
  last-rename-wins）；Rust 把 exists 检查与写入收进 per-transcript fence
  （`transcript_archive.rs` restore 路径起的 `transcript_locks::acquire`），并发第二个
  restore 见 R7 冲突——严格化，非放宽。**限定**：该 fence 是进程内互斥；跨进程段
  只有 ledger lease，而 exists 检查在 lease 之前（DS r2 concurrency P2 登记，
  两 gateway 进程共享同一 home 时窗口仍在），跨进程语义与 TS 同为 last-wins——
  **仅 lease 已释放的路径**：lease 被另一进程的 restore 持有时（R13 同一
  `cold_write_lease` 探测撞 `WouldBlock`）答 `SESSION_BUSY` 而非等待重试，写不落盘
  （TS 无跨进程锁，两侧 replace 都落地、后 rename 者胜、两侧都答 ok；fail-closed
  可重试，无数据损失——DS r4 concurrency P2 补登）。
- R12：TS Promise 必 settle、finally 清集合（:1366-1367）；Rust 把集合 add/remove 放进
  持有 fence 的阻塞任务内（`restoring_session_keys` add/remove），请求取消
  （future drop）不把 key 残留在集合。
- R13：hydration 窗口（会话工厂 restore→publish）内 TS `hasSession` 已真 →
  SESSION_BUSY；Rust 以 `cold_write_lease` 探测同一窗口（restore delegate 内），取不到 lease 答
  同一 SESSION_BUSY 文案（不是 rename 家族的 writer-busy 域码）。
- R10 形状：TS temp 写/replace 抛原样穿出（`:1363-1364` 清临时后重抛，raw fs 错误包
  gateway_request_failed）；Rust 侧 #1873 已把 lease 的 busy 与 fs 错误分开
  （`cold_write_lease` 返回 `Result`，本 PR 调用点加 `?`），不可写 chat 目录的 EACCES
  在 lease 阶段穿出为 gateway_request_failed，与 TS 的错误域码一致；文案为 Rust 侧
  锁文件的 io 文本（`Could not open session ledger lock …: Permission denied`——
  fence inode 是 Rust-only，刻意不渲染成 Node uv 形，transcript.rs
  `LedgerLock::acquire` 既有设计），直测钉住；busy（写者互斥 / WouldBlock）仍答
  SESSION_BUSY。原基线上「EACCES→None 降级答 SESSION_BUSY」的差异随 #1873 消除
  （本 PR rebase 到 main 后生效）。
- E6：`SESSION_TRANSCRIPT_EMPTY` 不可达——validate 的 message-count 臂先应答 0 消息
  （源 :1177-1181 次序，`export.empty-text` oracle 行钉住）；`transcript_archive.rs`
  的该分支仅作形状保真保留。
- 渲染边界（#2622 fix-r1，DS boundary P1 仲裁实测后修）：非串值的 portable 文本走
  `JSON.stringify(value, null, 2)` 形 pretty 渲染，显式栈不逐层耗本地栈帧（递归形在
  cb8 实测 `fatal runtime error: stack overflow` 退出 134，进程 abort 属 P0 已修）。
  两处边界：① 2000 容器共享深度界（#1550 家族，`js_value.rs` `MAX_ARRAY_DEPTH`
  同族既定预算）——**不是** V8 的真实抛点，后者形状依赖（账本已人批登记：数组实测
  2398 层成功、对象 1888 层抛 `RangeError`，见 accepted-diffs.md A6-JSVALUE-DEPTH-001
  的 #539 更正与 2026-10-23 人批记录）；约 1888–1999 深对象带 TS 抛→catch→
  `String(value)` 回退而 Rust 照常 pretty，约 2000–2398 深数组带 TS 照常 pretty 而
  Rust 走回退，两段倒挂均为该已登记同族差异，本条不新开豁免。② 渲染输出超 V8
  `String::kMaxLength`（`(1<<29)-24`，**UTF-16 码元**——fix-r4 更正：V8 该常量按
  码元计，此前本条按「字节」表述并据此称对齐，实际字节口径会让 CJK 渲染至多早
  1.5× 回退，属真错位，DS r4 boundary P1 已修：预算按码元累计）走与深度界同一
  `String(value)` 回退——该边界与 TS catch 语义对齐（V8 stringify 对超长输出抛
  可捕获 RangeError，helper catch 后同样回退）。直测钉住（深链照常渲染 / 宽深
  ASCII 载荷走回退 / 190M CJK 码元带内照常 pretty——`cjk_pretty_render_is_budgeted_
  in_utf16_units`），负控 `export-pretty-budget-omitted` 判杀。
