## 类别

bug 修复：异常 loop result 不得使 runner 所有的 turn 永久打开；维持已有 session 身份保护并将错误转成持久化失败终态。本条登记差异，不增加判分豁免。

## 基线依据

固定基线 cc7c4e6，`src/agent/session/AgentSessionEventRecorder.ts:478` 先比较 completedTurnId 与 result.turnId；startTurn 会清空 completedTurnId。真实 `TurnRunner.ts:414,426-439` 探针表明：result=42 或 [] 时静默去重，没有 turn_result；若已有 step，则也无 step_completed，但仍 yield 原 turn_completed。sessionId=other、turnId=t 时按 other 写成功终态，未校验原 session。null 与 turnId=other 则进入 catch，用原身份完成错误终态，Rust 对齐这两类，不列为差异。

原值与源码闭包哈希：`src/pilotdeck-gateway/tests/fixtures/turn-runner/oracle.json` 的 `invalid-result-{number,array,session}-{idle,step}` 六格。Node 22.22.0 原始输出：本树 `_tmp/20261026-issue-741c/fix-r1/ts-final.log` 与 `ts-final/oracle.json`。探针真实调用 recorder.recordModelRequest 打开 step，未用 Rust 结果生成期望。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/turn/runner.rs::complete` 对这些 result 调用 fail，使用 runner 所有的 session/turn、agent_invalid_state 与 `Turn result identity mismatch.`，先关闭 step（failed），写入一个 error turn_result，再产生 agent_status / turn_failed / turn_completed。recorder 移除该 turn，runner 标 Completed。I/O 本身持续失败仍返回原错误，不伪造持久化成功。

## 范围

本包独立 TurnRunner 的 Accepted→Complete 边界；低层 Recorder::complete_turn 保留既有 TS 兼容行为。对象缺 sessionId/turnId 或非字符串身份等既有拒绝路径也改为失败终态；本条六格量化范围仅为数字 42、空数组与仅 sessionId 不符。LiveSessionAdapter 接线与 pr4 不在本轮范围。

## 机器判据

`runner_tests.rs::runner_invalid_result_{number,array,session}_{idle,step}` 从 TS 金样读取原始 result，显式断言 Rust 差异：error 终态、原 session/turn、唯一 turn_result、step 关闭、recorder 拒绝后续模型请求、lease 释放；不冒充逐字节 TS 对齐。turnId 不符与 null 的四格逐字节对齐真实 TS JSONL 和 runner 事件。

负控 `runner_negative.py` 的 invalid-result-early-return / invalid-result-error-shape / catch-complete / catch-terminal-mark，以及 identity-guard / identity-turn-guard 必须运行时 RED，恢复后 PASS。重生成守卫 `runner_regenerates_identically` 覆盖完整 fixture；命令与原始输出在同证据目录 RESULT.md。
