## 基线与层次

`tests/fixtures/edgeclaw-same-root-generation/` 的 `observe.mts` 与 `lifecycle.mts` 在 Node v22.22.0、cc7c4e6 上实跑：

- `serial` 直接操作真实 MemoryRepository；Rust 同形执行 SQLite 读写/关闭/重开后比较整组输出。
- `threaded` 使用 worker 持 SQLite 写锁。`repository-open-while-write` 只代表 repository 构造；真实 service 的 `service-stage-while-write` 还写 workspaceDir，会立即 `database is locked`。更正 R4 把前者泛称 bundle stage 的说法。
- `lifecycle` 使用真实 ProjectRuntimeRegistry acquire/invalidate/resolve/release、真实 ProjectMemoryBundle 与默认 factory/service/provider。只替换无关资源族和离线 LLM transport。输出记录租约数、前驱是否 pending、同 DB 身份、新 stage 覆盖 workspaceDir sentinel、新旧 L0 行、flush stats/indexed、retrieve diagnostics/route、旧句柄关闭与新句柄继续读写。

native memory bundle 没有等 flush/retrieve 的租约。租约属于 registry。`disposing` 格指最后租约释放已进入 resource owner 的异步 dispose gate；gate 放行后才调用真实 native bundle.dispose。不能将测试 gate 描述为 native close 等旧 LLM。TS 的 Promise 不能取消，取消格取消观察者；Rust 对应丢弃等待者，保留内部 cleanup/continuation。

## 矩阵与结束条件

`staged / disposing × flush / retrieve × successor stage / first-write` 共 8 格。staged 格 retire 后旧代仍持真实 lease；disposing 格已释放最后 lease、资源释放停在 gate。所有格先等真实 LLM transport entered，新代发布后再恢复旧请求。

另有 `never-flush-write`、`never-retrieve-write`：直到新代完成前都不放行前驱，并检查前驱未完成；随后放行仅用于清理。`cancelled-retrieve-write` 取消 signal 和观察者；`cancelled-release-flush-write` 取消最后租约释放的等待者，仍观测真实旧 runtime 完成 cleanup。异步 gate 10 秒上限；SQLite writer/竞争通知 5 秒上限，前置条件未达记 INVALID，不能算击杀。

## Rust 修复与读路径

共享注册表回收无 strong owner 的 Weak，保留存活锁身份。除 conn()/close() 外，storage 最后 owner 的隐式 SQLite close/WAL checkpoint 也必须在进程锁下执行；锁 poison 不使析构二次 panic。

同进程读也经过共享锁，等待旧写提交后才返回，必须读到提交后的值。R4 的“无行或新值”表述撤销；worker-thread 控制的 WAL 快照读不是 Rust 同进程读的期望。`accessors::read_workspace` 的独立只读探测仍不在此进程锁范围；它按既有契约吞读错误，本轮不改该路径。
