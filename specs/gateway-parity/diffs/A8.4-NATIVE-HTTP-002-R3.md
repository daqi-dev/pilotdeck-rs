## 类别

更正（#1517 收口 R2 登记的 `_headerSent` 复刻口径）。R2「到期时在飞响应已写出
其头（`_headerSent`）则裸 destroy、无 408」的「在飞」由 `in_flight` 槽位代理：
`IdleBody::poll_frame` 返回 `Ready(None)`——体已交给 hyper 写缓冲——即递减，
早于字节落 socket。Node 的 `_httpMessage` 解绑在响应 `finish`，而 `finish`
需要 flush：发送缓冲未排空时 `_headerSent` 仍真、`socketOnError` 仍走裸
destroy。后果（fix 前码，#1517 矩阵第 4 行）：响应已交出、尾部未 flush 时
到期 → 镜像已清零 → 51 字节 408 排进未落线的尾部**前面**（读门
`poll_write` 的 timeout_408 分支先推 408、拒 hyper 字节），客户端按
`Content-Length` 分帧时多 51 字节且体被截断。同源还有一条 R2 未覆盖的读侧
缝隙：镜像清零的同一刻半头字节放行进 hyper 读缓冲，`mid_message_detect_eof`
（hyper `conn.rs`）停在非空缓冲上不再 poll io，停泊的 headers deadline
无 poll 可触发——网格点**什么都不发生**（fix 前 cell 实测：连接不关闭、
尾部靠客户端排空速率滴流）。修法两处共一条不变式（写侧未 flush ⟹
`response_head_written` 保持置位）：① `UpgradeReadGate` 增 `write_pending`
标记，`poll_write` 写出置位、`poll_flush` 返回 `Ready(Ok(()))` 清零，镜像
清零条件收窄为「`in_flight == 0` 且写侧已 flush」；②
`withholding_mid_stream` 同窗延长（`in_flight > 0 || write_pending`），
半头在尾部未 flush 期间继续 withheld 门侧——deadline 保持可 poll。放行与
hyper 自身的 `Reading::Init` 转换同刻发生（`try_keep_alive` → `idle()` 在
io flush 完成后），状态机两侧一致。

## Rust 行为

`src/pilotdeck-gateway/src/http_proxy.rs`（fix 后行号）：

- `UpgradeReadGate` 增 `write_pending: bool`（`:269`，构造置 false）：
  `poll_write` 成功写出 `written > 0` 时与 `response_head_written` 一并置位
  （`:742-743`）；`poll_flush` 透传结果为 `Ready(Ok(()))` 时清零（`:751-766`）
  ——hyper `io.rs` 的 `Buffered::poll_flush` 只在自身 write_buf 排干后才调
  io 层 flush，门侧 `Ready(Ok(()))` 恰是「排干完成」这一转换（其
  `try_keep_alive` → `idle()` → `Reading::Init` 同刻发生）。
- 镜像清零（`:525-528`）：`in_flight == 0 && !write_pending`（变异口
  `native-http-408-into-unflushed-tail` 退回仅看 `in_flight`——fix 前行为）。
  到期检查（`:582`）沿用现有 `response_head_written` 分支：标记在 → 静默
  关闭（与 `probe-g2/c2` 同形），无需第二处到期判断。
- `withholding_mid_stream`（`:405-408`）：`in_flight > 0 || write_pending`
  ——尾部未 flush 期间半头继续 withheld 门侧，读门的 poll 链
  （`poll_read_keep_alive` → `mid_message_detect_eof`：读缓冲空 →
  `force_io_read`）保持可达，停泊的 deadline 在网格点可触发。
- 代理 lane `serve_connection_with` 无 headers 超时，字节不变；本条修复
  对其零影响（`withholding_mid_stream` 首条件 `headers_timeout.is_some()`）。
