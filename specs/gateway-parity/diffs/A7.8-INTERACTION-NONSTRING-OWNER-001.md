## 类别

不可避免（建模域差异；带后果说明，见范围）。

## 基线依据

TS 基线 cc7c4e6：`src/interaction/InteractionReconnect.ts:94-111`
`createNativeInteractionReconnectPort` 的 `pending`/`bindings`/`lastBindings`
是普通 JS `Map`，`reconnect(ownerId, ...)` 不校验 ownerId 类型；
`src/gateway/server/GatewayWsConnection.ts:470-481` 的 `reconnect_interaction`
分发只做 `params.sessionKey ?? ""`。因此非字符串 sessionKey（如数字 5）是合法
Map 键：首次重连按「新 owner」走（no_pending / 带 previous 则 stale_binding），
且 `bindings.set(5, next)` 会持久化，使同一非字符串键的后续重连看到
`current`/`last`（同 binding → reconnected；generation 不增 → stale_binding）。

## Rust 行为

`src/pilotdeck-gateway/src/native_process/methods/interaction.rs`
`reconnect_interaction`：sessionKey 非字符串时按「恒 fresh owner」模拟——
无 previous → `{outcome:"no_pending", binding:next}`；有 truthy previous →
`{outcome:"stale_binding"}`；不落任何状态。原因：交互端口
（`runtime/interaction/`，前序 issue 移植）用 `JsString` 建模 TS 的 `string`
键域，全部 bucket/binding 状态以 JsString 为键，非字符串键无表示。
elicitation_respond / permission_decide 无此差异：TS 的 Map.get(SameValueZero)
对非字符串键恒 miss，Rust 按 `as_string` 失败直接 `{delivered:false}`，行为一致。

## 范围

仅 `reconnect_interaction` 且 sessionKey 为非字符串（null/undefined 已由连接层
`?? ""` 折叠为合法空串）。差异只在「同一非字符串键的第二次及以后重连」：
TS 会因已存 binding 返回 reconnected/stale_binding，Rust 恒 no_pending。首调
（无状态）语义两侧一致。字符串 sessionKey（包括空串）完全一致。

## 机器判据

`src/pilotdeck-gateway/src/native_process/methods/interaction.rs::tests::reconnect_interaction_non_string_session_key_stays_fresh`
（钉住首调语义）。重复非字符串键的 TS 行为以 Node v22.22.0 实测
（RESULT.md 附录）为准记录；Rust 侧不为其建立测试（该行为是差异本身）。
