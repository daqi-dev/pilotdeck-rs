## 类别

有意改进（人定）：一轮结束时未处理完的 hook / 交互 / steer / permission 事项继续丢弃、不跨轮延续，但 Rust 额外发出用户可见的「上一轮有 N 个待处理项已作废」提示。丢弃行为本身不变；本条只登记提示形状与出口，不声称 TS 有同等提示。

## 基线依据

固定基线 `OpenBMB/PilotDeck@cc7c4e6`。真实探针 `src/pilotdeck-gateway/tests/fixtures/interaction-discard/discard-probe.mts` 直接 import 基线源码，`baseline_source_guard` 核验 commit 与 11 个源文件 SHA256；输出 `oracle.json`，两次生成逐字节一致（sha256 `5cff8ff5f2f5afb34798b28f375cd8d4f6ba78c88f33e0fe23003ef4d92ee776`，证据 `_tmp/20261025-issue-686/ts-probe/fixture-run{1,2}.json`）。

- hooks：TS session-scoped `HookRuntime`/`AsyncHookRegistry`；第一轮 async pending `command:1` 在第二轮后仍可 `complete`/`collect`，两轮 dispatch 事件只有 `started/response`，`noticeEvents=[]`。轮结束不丢弃、也无提示。
- steer：`TurnRunner.ts:160-171,408,423` 在 close 时把未 ack 项逐个映射为 `steer_unapplied {sessionId,turnId,itemId,reason:"turn_ended"}`，先于 `turn_completed`；探针 `steer.noticeEvents` 恰一条 `steer_unapplied`。这是逐项提示，不是本条的聚合 count 提示。
- permission：`GatewayPermissionBus.denySession` 在 turn 结束时把 pending 逐个 deny；探针 `pendingBeforeClose=1`、`pendingAfterClose=0`，dispatch 事件只有 `started/response`，`noticeEvents=[]`。
- elicitation/user-dialog：`GatewayElicitationBus.rejectSession` 逐个 reject；`pendingBeforeClose=1`、`pendingAfterClose=0`，bus 无事件通道、`noticeEvents=[]`。本生产装配 `runtime/turn/interaction.rs:203-204` 明确不安装 elicitation 端口。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/project/interaction_notice.rs` 定义 `DiscardSource`、`DiscardNotice` 与固定形状。每个来源在自己的 close/替换屏障处记录，且在 `done`/cleanup 完成前入队，保证下一轮 `wait_ready` 之后可取：

- `interaction_hooks.rs`：`Run::close` 返回本次关闭观察到的 `pending.len()`；同 key 顶替、`TurnHooks::close`、generation close 三处记录 `source=hooks`。
- `interaction_steer.rs`：cleanup 成功 close 且 `discarded` 非空时记录 `source=steer`，数量为 discarded 长度（覆盖 abort 落在 drain 与 apply 之间、A6.9-STEER-RUN-002 的丢弃）。
- `interaction_permission.rs`：`Run::close` 返回本次排空的 pending request 数；同 key 顶替、`TurnHooks` 配对关闭、generation close 三处记录 `source=permission`。
- 交互/elicitation：本装配不安装端口，不产生该来源；`DiscardSource::Interaction` 仅为将来接线保留，生产不记录。

出口一：`DiscardNotice::log()` 在丢弃发生时立即向 stderr 写一行 JSON（gateway 无 tracing subscriber）。出口二：`InteractionEvents` 的 `TurnEvents::queue_notices` 把同一 session 的 notice 暂存；下一次 `InteractionTurn::bind` 在所有 predecessor 屏障之后取出，`TurnEvents::emit` 在 `turn_started` 之后追加 `warning` AgentEvent（projector 已有 `warning → agent_status(detail)` 映射），因此下一轮用户可见。通知一次性，`turn_started` 后清空。

锁定形状（字段顺序即断言顺序）：

```json
{"event":"interaction_pending_discarded","source":"hooks","count":2,"sessionId":"s","runId":"old-run"}
```

```json
{"type":"warning","sessionId":"<下一轮 session>","turnId":"<下一轮 turn>","code":"interaction_pending_discarded","message":"Previous turn had 2 pending hooks item(s) discarded.","metadata":{"source":"hooks","count":2,"sessionId":"s","runId":"old-run"}}
```

`source` 取值 `hooks | interaction | steer | permission`；`count` 为本次丢弃数；`runId` 为丢弃发生的上一轮 run（gateway 的 `runId` 缺省等于 `turnId`，`runtime/turn/live.rs:790-791`）。

## 范围
