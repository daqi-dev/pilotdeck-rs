## 类别

缺口已修 + 传输层呈现差异（不可避免，继承已有条目）：原缺口是 user_dialog
HTTP store 的自有监听器**没有接** `native_http::node_parser_admission`——与
`native_http.rs`「每个此类监听器都必须调用它」的规则相反（该注释 #1683 r3
起列出实际调用点并注明未接线车道，#2152 前包含 user_dialog / sms，fix-r1 已
同步）。缺口在位时 `FROB` 落到方法表的 405、无 Host 的 HTTP/1.1 请求被放行
直达 handler。#2152 把调用点接到 `user_dialog/http_store.rs` serve 闭包的最
前面（keep-alive / shutdown 生命周期之前）；与 sms / api-server 两车道的差别
是超预算 431 的处理：本车道把它改写成 #1232 已登记的
`force_node_response(NODE_431_RESPONSE)` canned Node 字节，hyper 自有的
431 编码（小写头名 + `content-length: 0`）不出线。本条不增加判分豁免：
新增两格是**收紧**判据。补登依据：该接线与两格此前只在代码注释 / fixture
README / `_tmp/` RESULT 中自我披露，账本无条目，仓内读者会得出「该区域无
已知差异」的假象（同 `accepted-diffs.md`
A7.2-ZERO-RETENTION-TIMER-001 补登依据的口径，评审 #2152 fix-r1 P1 点名）。

## 基线依据

固定基线 `cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85`，Node v22.22.0（本轮
复核 `node --version` 为 v22.22.0）。

- `src/gateway/user-dialog/HttpGatewayUserDialogStore.ts:236` 用
  `http.createServer(...)`（无 options）建监听器，解析层准入即 llhttp /
  `_http_server.js` 在 handler 之前的判定，与 webhook / api-server / sms
  车道同一裸 `createServer` 家族。
- 金样两格 `unknown-method`（`FROB /v1/gateway-user-dialog-store/clear`）
  与 `missing-host`（`GET` 同路径 + `setHost: false`，线上无 `Host` 行）由
  `src/pilotdeck-gateway/tests/fixtures/user-dialog-http-store/generate.mts`
  （`:742-746`，`rawHttp` 经 Node `http.request` 的 `method` / `setHost`
  旋钮录制）在基线上对真 store 监听器实跑录制，`oracle.json` 的
  `socketRequests` 由 18 格增至 20 格（两格为第 19 / 20 格），期望均为
  `{"status":400,"contentType":null,"body":""}`。`setHost` 旋钮沿用
  api-server 车道 #1683 的先例（`A8.3-API-SERVER-005` 基线依据的
  `probe-set-host.mts` / `probe-set-host.out` 证实 Node `http.request`
  即可录到两形态，无需裸 socket 协议）。
- 两拒绝的线上头形状与 `A8.3-API-SERVER-005` 基线依据的裸 socket 探针
  同形（同一无 options `createServer` 家族）：裸 400 无 `Date`、
  `Connection: close`、零字节体；headless 400 自带 `Date` + chunked 空体
  （读码 + 家族先例推断，本车道未另做裸 socket 探针）。

## Rust 行为

`src/pilotdeck-gateway/src/user_dialog/http_store.rs:3377-3401`（serve 闭包
入口，在 `keep_alive_advertisement` / shutdown / keep-alive 生命周期之前）：

```rust
if let Some(rejection) =
    crate::native_http::node_parser_admission(&request)?
{
    if rejection.status() == StatusCode::REQUEST_HEADER_FIELDS_TOO_LARGE {
        timer.force_node_response(NODE_431_RESPONSE);
    }
    return Ok(rejection);
}
```

- 闭包错误类型由 `Infallible` 改为 `io::Error`：闸门的 `Err`（CONNECT 的
  零字节断连）经 hyper 既有的连接中止路径出线（不写任何字节，同其它原生
  车道）。
- 431 分支经 `force_node_response(NODE_431_RESPONSE)` 出本车道 #1232 的
  canned Node 字节（与 `serve` 的 backstop 同一机制——guard 追不了的
  framing，如重复 `Content-Length`、多 token `Transfer-Encoding`，两条入口
  必须出同一 Node 字节）；拒绝响应自带 `Connection: close`，keep-alive
  advertisement 对其不生效。
- headless 400（缺 Host）沿用 `native_http::headless_bad_request()`：
  `400` + `Connection: close` + `Date` + chunked 空体，与 api-server 车道
  （`A8.3-API-SERVER-005`）逐头一致。

## 范围

- 只涉及 user_dialog HTTP store 自有 HTTP 监听器的**解析层准入**：方法
  允许表、target 字节与形态、请求头 span 预算、HTTP/1.1 缺 `Host`、
  CONNECT 零字节关闭。不含方法表 / body 上限 / 鉴权次序 / 超时 / keep-alive
  等既有登记（`A7.4-HTTPSTORE-*` 各条不变）；431 / 408 字节形状仍以
  `A7.4-HTTPSTORE-431-408-SHAPE-001` 链的登记为准，本条不扩大其豁免面
  （闸门 431 落进该链已登记的 Node 字节口径，不新立形状）。
- 两格重放按语义三元组（status / contentType / body）比较，不比较原始
  字节；线上形状钉（兄弟车道 API-SERVER-005「重放归一化会掩盖该行，故用
  原始响应字节钉」的口径）本车道**没有**等价物——已知偏差见「机器判据」，
  评审已点名，协调者另处置。本条因此不声称两格的字节级一致。

## 机器判据

- 金样：`tests/fixtures/user-dialog-http-store/oracle.json` 的
  `socketRequests` 20 格（18→20），新增 `unknown-method` / `missing-host`
  两格；README 记录更新后的 `sha256(oracle.json)` 与条数。
- 重放：`src/pilotdeck-gateway/tests/user_dialog_http_store.rs`
  `socket_requests_match_typescript_framing`（`:1073`）逐格比较状态 /
  content-type / body；`missing-host` 走 `raw_hostless_exchange` 裸 socket
  （hyper client 会自加 `Host`，正是该格不能带的头；读侧带 5 s 上限，
  fix-r1），hyper 路径同样 5 s 上限（fix-r2）；`setHost` 读取 fail-closed
  （`recorded_set_host`，`:1205`，只接受缺席或布尔）。
- 旋钮钉：`socket_requests_pin_their_parser_admission_knobs`（`:1175`）钉
  `unknown-method` 的 `method == "FROB"`（Node `http.METHODS` 之外的
  token）与 `missing-host` 的 `setHost == false`，防 cell 退化成被准入的
  请求后与自己的 400 假过；`socket_request_set_host_refuses_a_non_boolean`
  （`:1218`，`should_panic`，fix-r1 补）钉 fail-closed 读取本身。
- 负控：本车道无 #2152 专属变异开关 / 调用点替换负控（评审 fix-r1 P2 已
  点名：闸门可被整段删掉而无测试变红，协调者另处置）；既有
  `negative_controls_1232.py`（431/408 字节形状族）不覆盖本接线。
- 已知偏差（不在本条范围，登记防「无差异」假象）：①两格重放只比语义
  三元组，裸 400 的 `content-length: 0`、headless 400 的 `date` /
  `transfer-encoding` 等线上形状无本车道字节钉（评审 fix-r1 P2，另处置）；
  ②闸门 431 的 `force_node_response(NODE_431_RESPONSE)` 分支无专属测试，
  默认限额下 `HeaderGuard` 通常先答，该分支可达性未证明（评审 fix-r1 P2，
  另处置）；③CONNECT（闸门 `Err` → 零字节关闭）只有读码，无实跑格。
- 回归（本补登轮实测，cb8，本轮证据
  `_tmp/20261026-issue-2152/fix-r1/v-user-dialog.out`）：
  `cargo test --offline --locked -p pilotdeck-gateway --test
  user_dialog_http_store` → **9 passed / 0 failed**，含上述三个准入相关
  测试。
- 复算命令：`cargo test --offline --locked -p pilotdeck-gateway --test
