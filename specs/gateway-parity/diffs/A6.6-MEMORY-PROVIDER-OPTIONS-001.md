## 类别

不可避免（类型表示差异）。当前生产组合路径的可观察行为与 TS 一致；差异集中在 Rust 尚无对应运行时设施的 `logger`/`telemetry` 表示，以及 `modelConfig` 只保留 memory factory 实际读取的字段。

## 基线依据

cc7c4e6 的 TS：

- `src/cli/ProjectMemoryBundle.ts:30-34` 定义 `ProjectMemoryBundleOptions`；`:57-59` 把**完整 options** 交给 `providerFactory`，`:61` 把去掉两个 factory 的 `input` 交给 `createProvider`。
- `src/context/memory/createEdgeClawMemoryProviderFromConfig.ts:25-40` 列出 9 个字段；`:42-76` 只读取 `config`、`projectRoot`、`modelConfig`、`agentModel`、`logger`、`now`、`telemetry`；`:91-98` 只读 `modelConfig.providers[id]` 的 `protocol`/`url`/`apiKey`。
- `src/cli/ProjectRuntimeResourcesBundle.ts:387-395` 生产组合实际传入 `config`、`modelConfig`、`agentModel`、`projectRoot`、`now`、`telemetry`、`providerFactory`，**不传 `logger`**。
- `src/pilot/config/types.ts:113-132` 定义 `PilotMemoryConfig`/`PilotMemoryScheduleConfig`；`src/model/protocol/canonical.ts:357-379` 定义 `ProviderConfig`/`ModelConfig`；`src/telemetry/types.ts:139-153` 定义可调用的 `TelemetryClient`。
- 真实 TS 入口：`src/pilotdeck-gateway/tests/fixtures/memory/generate.mts` 在固定基线 `cc7c4e6` 上生成入库金样 `src/pilotdeck-gateway/tests/fixtures/memory/oracle.json`（记录 `sourceCommit` 与三个源文件的 `sourceSha256`）。`bundleCases` 的 `factory-options-full` / `native-options-full` 记录 `config` 全部 11 个字段、`modelConfig.providers.test.{protocol,url,apiKey}`、`hasNow`/`hasTelemetry`；`factory-throws-structured` 记录 `DialogGatewayError`/`FACTORY_FAILED`/`requires_host`。

## Rust 行为

- `src/pilotdeck-gateway/src/runtime/memory/mod.rs:157-171` `MemoryConfig` 承载 `PilotMemoryConfig` 全部 11 个字段（`schedule` 3 个子字段在 `:143-148`）；`:197-205` `MemoryModelProvider` 只承载 `providers[id].protocol/url/api_key`，`:207-210` `MemoryModelConfig` 是 id→provider 映射。
- 字符串字段是载体，不是解释后的 Rust `String`：`provider`/`root_dir`/`model`/`api_type`/`schedule.reasoningMode`/`providers[*].{protocol,url,apiKey}` 均存 `JsString`。`runtime/project/memory_bundle.rs:231` 的 `js_text()` 只克隆 UTF-16 单元，不再 `to_utf8().ok()`；含孤立代理项的合法 JS 字符串（如 `"test/mem\uD800"`、`rootDir` 同理）原样到达 provider factory，不再变 `None`/`""`。这是与 TS 对齐，不是差异。
- `mod.rs:212-240` `ProjectMemoryBundleOptions` 含 `project_root`、`config`、`model_config`、`agent_model`、`now`、`telemetry`、两个 factory；`:251-261` `NativeMemoryProviderOptions` 含前六项、不含 factory。
- `runtime/project/memory_bundle.rs:91-104` 从快照填 `config`/`model_config`/`agent_model`/`now: Some(context.clock())`/`telemetry: context.telemetry()`；`runtime/project/factory.rs` 把 `ProjectResourcesOptions.telemetry` 原对象存入 generation slot，`StageContext::telemetry()` 再取出。
- `TelemetryClient = Arc<dyn Any + Send + Sync>`（`runtime/project.rs:27`）：只透传、不调用方法、不定义事件形状。`now` 为 `Arc<dyn Fn() -> SystemTime + Send + Sync>`，对应 TS `() => Date` 的时刻语义。
- 未建模 `logger`：Rust 无 logger seam，且生产组合本来不传；`modelConfig` 其余字段不被 memory factory 读取，故不复制。
- 错误边界见 `mod.rs:340-374`、`:723-735`、`runtime/project.rs:34-53`：`RuntimeJsError` 保留 `name/code/JsString message/requires_host`，`RuntimeError.message` 仍是 lossy 显示串；`From<RuntimeError> for MemoryProviderError` 复原，最终 `MemoryProjectionError` 可读四项。

## 范围

仅 `ProjectMemoryBundleOptions` 的 carrier 与错误边界：`config` 全字段、`modelConfig` 的 3 个消费字段、`agentModel`、`projectRoot`、`now`、opaque `telemetry`、两个 provider 注入点，以及 `MemoryProviderError`→`RuntimeError`→最终投影的形状保留。不包含：EdgeClaw provider 业务逻辑（#587）、`logger` 实现、telemetry 事件、`ProviderConfig` 其余字段、A8 生产适配接线。
