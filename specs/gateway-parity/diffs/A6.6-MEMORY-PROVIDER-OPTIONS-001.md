## 类别

不可避免（类型表示差异）。当前生产组合路径的可观察行为与 TS 一致；差异集中在 Rust 尚无对应运行时设施的 `logger`/`telemetry` 表示，以及 `modelConfig` 只保留 memory factory 实际读取的字段。

## 基线依据

cc7c4e6 的 TS：

- `src/cli/ProjectMemoryBundle.ts:30-34` 定义 `ProjectMemoryBundleOptions`；`:57-59` 把**完整 options** 交给 `providerFactory`，`:61` 把去掉两个 factory 的 `input` 交给 `createProvider`。
- `src/context/memory/createEdgeClawMemoryProviderFromConfig.ts:25-40` 列出 9 个字段；`:42-76` 只读取 `config`、`projectRoot`、`modelConfig`、`agentModel`、`logger`、`now`、`telemetry`；`:91-98` 只读 `modelConfig.providers[id]` 的 `protocol`/`url`/`apiKey`。
- `src/cli/ProjectRuntimeResourcesBundle.ts:387-395` 生产组合实际传入 `config`、`modelConfig`、`agentModel`、`projectRoot`、`now`、`telemetry`、`providerFactory`，**不传 `logger`**。
- `src/pilot/config/types.ts:113-132` 定义 `PilotMemoryConfig`/`PilotMemoryScheduleConfig`；`src/model/protocol/canonical.ts:357-379` 定义 `ProviderConfig`/`ModelConfig`；`src/telemetry/types.ts:139-153` 定义可调用的 `TelemetryClient`。
- 真实 TS 入口 `_tmp/20261025-issue-636/ts-probe.mts`：`ProjectMemoryBundle` 与 `createLocalGateway().memoryList` 两侧都拿到 `config`/`modelConfig`/`agentModel`/`projectRoot`/`now`/`telemetry`（`telemetrySameObject: true` 于直接 bundle，gateway 为宿主默认 telemetry），工厂抛出的 `DialogGatewayError`/`FACTORY_FAILED`/含 `0xD800` 的 message 在两侧都 `sameObject: true`（原始输出 `ts-probe.raw.txt`）。

## Rust 行为

- `src/pilotdeck-gateway/src/runtime/memory/mod.rs:153-171` `MemoryConfig` 承载 `PilotMemoryConfig` 全部 11 个字段（`schedule` 3 个子字段在 `:143-148`）；`:193-205` `MemoryModelConfig` 只承载 `providers[id].protocol/url/api_key`。
- `mod.rs:207-235` `ProjectMemoryBundleOptions` 含 `project_root`、`config`、`model_config`、`agent_model`、`now`、`telemetry`、两个 factory；`:246-256` `NativeMemoryProviderOptions` 含前六项、不含 factory。
- `runtime/project/memory_bundle.rs:91-104` 从快照填 `config`/`model_config`/`agent_model`/`now: Some(context.clock())`/`telemetry: context.telemetry()`；`runtime/project/factory.rs` 把 `ProjectResourcesOptions.telemetry` 原对象存入 generation slot，`StageContext::telemetry()` 再取出。
- `TelemetryClient = Arc<dyn Any + Send + Sync>`（`runtime/project.rs:27`）：只透传、不调用方法、不定义事件形状。`now` 为 `Arc<dyn Fn() -> SystemTime + Send + Sync>`，对应 TS `() => Date` 的时刻语义。
- 未建模 `logger`：Rust 无 logger seam，且生产组合本来不传；`modelConfig` 其余字段不被 memory factory 读取，故不复制。
- 错误边界见 `mod.rs:299-374`、`runtime/project.rs:34-53`：`RuntimeJsError` 保留 `name/code/JsString message/requires_host`，`RuntimeError.message` 仍是 lossy 显示串；`From<RuntimeError> for MemoryProviderError` 复原，最终 `MemoryProjectionError` 可读四项。

## 范围

仅 `ProjectMemoryBundleOptions` 的 carrier 与错误边界：`config` 全字段、`modelConfig` 的 3 个消费字段、`agentModel`、`projectRoot`、`now`、opaque `telemetry`、两个 provider 注入点，以及 `MemoryProviderError`→`RuntimeError`→最终投影的形状保留。不包含：EdgeClaw provider 业务逻辑（#587）、`logger` 实现、telemetry 事件、`ProviderConfig` 其余字段、A8 生产适配接线。

## 机器判据

- Rust 正向：`src/runtime/project/factory_tests.rs:2863` `memory_factory_injects_provider_and_publishes_three_handles`（完整 config、modelConfig、固定 clock、telemetry 对象 downcast）；`:3108` `memory_legacy_create_provider_stages_when_provider_factory_is_absent`（旧注入点同样收到 modelConfig/now/telemetry）。
- Rust 结构化错误：`:3027` `memory_factory_error_keeps_js_shape_and_registered_owner`、`:3290` `memory_registry_stages_injected_provider_and_does_not_publish_failures`、`src/runtime/memory/mod.rs:966` `runtime_error_keeps_factory_error_shape`、`tests/memory.rs:936` `runtime_stage_error_reaches_memory_projection`（真实 `MemoryProjection` 消费者）。
- TS 金样：`_tmp/20261025-issue-636/ts-probe.mts`，原始输出 `ts-probe.raw.txt`；message 的 UTF-16 单元为 `[102,97,99,116,111,114,121,32,98,111,111,109,32,55296]`。
