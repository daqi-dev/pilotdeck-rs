## 类别

fix-r1 评审修复（#1114）。两处：P0——`detach` 对首询即 Ready 的 continuation
无条件 spawn，已完成 future 被二次 poll 触发 panic（`async fn resumed after
completion`）；P1——请求 POST 的内联首询把发送前缀推进了 `timeout` 起算之后，
与 TS 不符（探针 A：TS 超时预算包含 send 预处理），按「范围收窄优先」恢复
后台发送。另登记一项残余差异：紧邻 close 的交错下 GET 请求行的字节级落线
（探针 B：TS 200/200 落线，Rust 仅保证进入 network exchange）。

## TS 依据

固定基线 `/Users/da/ws/pilotdeck-rs/resources/PilotDeck`（Node v22.22.0、
SDK 1.29.0）：

- `node_modules/@modelcontextprotocol/sdk/dist/esm/shared/protocol.js:718`：
  `_setupTimeout` 在 `:743 transport.send` 之前武装——send 自身的预处理
  （`streamableHttp.js:303` JSON.stringify 等）落在请求超时预算内。实测
  `_tmp/20261026-issue-1114/fix-r1/probe/probe_request_timeout_start.mjs`
  （transport.send 前缀 150ms、请求超时 50ms）：sync/async 两种前缀模式均
  `REJECTED McpError -32001 Request timed out`（`.sync.out` / `.async.out`）。
- `_tmp/20261026-issue-1114/fix-r1/probe/probe_get_close.mjs`（200 轮 ×
  immediate/inflight 两模式，真实 mock 服务器 + 原始 `http.jsonl`）：
  immediate（start 后无宏任务轮次即 close）GET 行 200/200 落线，inflight
  同样 200/200——undici 对空闲池化 socket 同步写入，close 不吞请求行。

## Rust 行为

- P0 修复（`runtime/mcp/http.rs:1491`）：`detach` 内联首询返回 `Pending` 才
  `tokio::spawn` 余段；`Ready` 的 continuation 就地完成（原 detached 丢弃
  语义），不再 spawn——poll 已完成的 async block 会 panic。修前路径：legacy
  无 endpoint 的 `send_detached` 首询即 `Err(not_connected)` 即 Ready，旧代码
  无条件 spawn，spawn 余段首询即 panic（修前失败输出见
  `fix-r1/manual-mutants/detach-unconditional-spawn.run.stdout`）。
- 范围收窄（`runtime/mcp/wire.rs:527`）：请求 POST 恢复裸 `tokio::spawn`
  （内联首询会把 stringify/建帧推进 `timeout` 武装之后）。保留 `detach` 的
  仅剩两类调用点：initialized GET（http.rs:1353，close 可整吞的发送）与
  `send_detached`（wire.rs:456，超时 cancel 与回复——TS 调用点同步发起、
  无 deadline 交互）。
- 残余差异：hyper 旧客户端的连接驱动任务需要调度轮次才能写字节；close 落在
  `detach` 返回之后、spawn 余段首次调度之前时，Rust 保证 GET 已过
  `network_fetch_continuing_with` 的 abort 门（服务端观察到 GET 自己的 TCP
  连接），但其后的在途 abort（窗口 B）可先杀掉写入，请求行可能不落线。
  TS（undici 池化 socket 同步写）在该交错下 200/200 落线。按「不硬改」，
  不重写发送路径，登记为本差异。

## 范围

仅 fix-r1 两处行为变更与其残余差异的登记：Ready continuation 不再 spawn；
请求 POST 回退后台发送。窗口 B（exchange 已在途后的 abort 行为）不变；
stdio 队列语义不变；`dispatch` 计数、`DETACHED_DISPATCHES`、abort 门本身
均未改动。GET 字节级落线差异仅存在于上述窄交错（close 先于余段首调度），
探针 B 的 inflight 模式与既有回放测试不受影响。
