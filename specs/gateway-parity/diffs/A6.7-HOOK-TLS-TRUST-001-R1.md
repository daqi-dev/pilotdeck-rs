## 类别

原条目为未实现（信任源 / 代理）。本更正只登记原条目中「不走 TS 的代理 dispatcher」的**局部消除状态**；信任源部分原样有效。

## TS 依据

cc7c4e6 的 `cli/pilotdeck.ts:28` 安装 `cli/proxy.ts` 的全局 undici 代理 dispatcher（`EnvHttpProxyAgent` / `ProxyAgent`），进程内所有走 undici 的出站请求（hook、model、count、Google SDK）都经它。本条只记录 Rust 各调用点接入共享代理连接器的状态，不扩大一致性结论。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/model/http.rs` 的共享 `proxy_https_connector`（`ProxyConfig::from_settings(None)` 读环境代理，含 NO_PROXY 与 HTTP CONNECT 代理认证；`127.0.0.1`/`localhost` 默认直连）当前接入的调用点：

- hook：`runtime/hooks/exec.rs` 的 `HttpHookExecutor::with_config`（已在 main）。
- model：`runtime/model/http.rs` 的 `HyperModelTransport`（`new`/`with_roots`，已在 main）。
- count：`runtime/model/count_http.rs` 的 `HyperCountTransport::from_config`（本条所属 PR 接入；此前直连 `https_connector`）。

原条目「不走代理」对受支持的 HTTP 代理在上述三类调用点上过期。

## 范围

- 仅环境变量来源（`PILOTDECK_PROXY`/`https_proxy`/`HTTP_PROXY` 族 + `no_proxy`）的 `http:` 代理；`pilotdeck.yaml` 的 `proxy` 配置仍未接入 hook / model / count 构造点（MCP 客户端除外）。
- 仍未消除、不得据此宣称完成的：webpki 信任根不读 `NODE_EXTRA_CA_CERTS`；`https:` / `socks:` 代理不支持（直连回退，机制见 A6.5-MCP-PROXY-HTTPS-001 / SOCKS-001 / FALLBACK-001）；`runtime/…/user_dialog/http_store.rs` 的 store 客户端仍直连（未接入共享连接器，非本条范围）；代理分支 `ProxyConfig::tunnel` 的 TCP connect 无独立 10 s 期限（直连分支有），只受外层交换超时兜底，为独立未完项。
- 不宣称「all HTTP transports 已对齐」：上表即全部接入点。

## 机器判据

- 共享连接器证据（既有）：`src/pilotdeck-gateway/tests/mcp_proxy.rs::replays_ts_mcp_http_proxy_scenarios`（CONNECT、NO_PROXY、认证与失败路径）、`runtime/model/http.rs::proxy_tests`（代理来源优先级与匹配规则）。
- count 调用点证据（本条所属 PR）：`src/pilotdeck-gateway/tests/model_stream.rs::count_transport_speaks_https_with_the_shared_connector`（本地自签 CA 下 https count 成功、无 CA 时 `fetch failed`，连接器共享自 model 传输）；`tests/token_count_http.rs`、`tests/token_accounting.rs` 回归。
- count 调用点环境代理端到端（fix-r1 轮补，#621 R6）：`src/pilotdeck-gateway/tests/count_proxy.rs::count_transport_uses_environment_proxy`（子进程设 `HTTP_PROXY`，经真实脚本 CONNECT 代理打到本地 target：成功计数 + 真实 POST 正文与 Anthropic 头穿透隧道、代理 URL 凭据作 Basic 认证、407 → `fetch failed` 且零目标流量、`NO_PROXY` 直连零 CONNECT、重定向逐跳重估 bypass——首跳 `0.0.0.0` 走隧道、重定向到 `127.0.0.1` 直连）。TLS 目标经隧道的场景未在此重复（CONNECT 机制与 model/hook 共享，见 `tests/mcp_proxy.rs` 的 https 场景）。
- hook / model 调用点的端到端代理回放尚未新增（count 已有，见上），不冒充完成该覆盖；count 经 `https:` 代理目标的端到端回放同样未单列。
