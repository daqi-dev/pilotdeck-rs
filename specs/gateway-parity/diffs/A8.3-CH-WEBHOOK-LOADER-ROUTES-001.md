## 类别

固定 TS 基线缺陷修复候选；仅显式配置 `adapters.webhook.extra.routes` 的原生 Server。没有 routes 仍保持旧的空路由与 404；secret、HMAC 校验、路由内部行为不变。

## 基线依据

`OpenBMB/PilotDeck@cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85` 的 `loadEnabledChannels.ts` 只向 WebhookChannel 传 port/secret，漏传 routes。固定 Node22.22.0/ICU78.2 的真实 HTTP 采集表明，同一个 main 路由及正确 HMAC：经生产 loader 得到 routes=[]、404、submit=0；直接构造适配器得到 routes=[main]、200、submit=1。

复算脚本及原始结果：`src/pilotdeck-gateway/tests/fixtures/native-channel-lifecycle/webhook-loader-capture.mjs`、`webhook-loader-oracle.json`。原件 SHA256 `4014cd7ebc9b25ef7e96438c20fa76792b9d471980caca707154c92f3118c30f`。旧 Rust r34 实际 Server 同样 404/零模型请求，失败保留于 mbp2 `channels/_tmp/20261110-webhook-actual-r34-first-failure/`。

## Rust 行为

`channel/loader.rs` 仅在 routes 非 undefined 时透传；新增测试验证显式 routes 和 absent shape。非冻结 `native-channel-lifecycle/http-process.mjs` 使用同一实际 HTTP 入站/A7/出站/公开 reload/停机判据复验修复；新候选运行结果尚待补充。

## 范围

仅原生 Server 的 Webhook loader 显式 routes 配置分支；缺省路由、鉴权和签名、其他渠道及正式验收分母不变。

## 机器判据

固定 TS 生产 loader 的原始 404 与直接构造的 200 必须分别保留。Rust 必须在同一 routes 配置下真实完成 HTTP 入站、A7 模型消费、公开重载和停机；未配置 routes 仍返回 404，错误 HMAC 仍拒绝。实际新版本结果未闭合前不得按该条标通过。
