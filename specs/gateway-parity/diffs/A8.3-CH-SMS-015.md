## 类别

传输层呈现差异（待批）：sms 通道自己的监听器（`SmsChannel` 的
`node:http` server，Rust 侧 `src/pilotdeck-gateway/src/channel/sms/mod.rs`
的 hyper 1.7.0 `http1::Builder` 连接）对 **HTTP/1.0** 请求回显
`HTTP/1.0` 状态行，而 Node v22.22.0 恒回显 `HTTP/1.1`。这是
A8.4-NATIVE-HTTP-001 第 4 项的同一 hyper 行为，webhook 车道的同形差异已按
既有惯例单列 `A8.3-CH-WEBHOOK-004`；sms 车道的 1.0 一格由本条（#1913）
补上。`A8.3-CH-WEBHOOK-004`「范围」车道表 sms 行写的「无登记、未实测：
见 #1913」自本条起有了登记（正本字节不动，读法以本条为准）。

本通道的其余 1.0 语义（`Connection: close`、无 framing 的 close 定界体、
发完即关）Rust 与 Node 逐字节一致，不在本条豁免范围内，由钉死测试逐项
比对。

## 基线依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0 /
ICU 78.2。TS 侧 `src/adapters/channel/sms/SmsChannel.ts` 用真实
`node:http` 监听（`createServer` `:89`，`/sms/incoming` 表单 POST 走 200
空 TWIML），没有对 1.0 做任何处理器级分支：版本处理全部在
`_http_server.js` 里。

实测（探针 `_tmp/20261108-sms-residual/probe-sms-http10.mts`，原始输出
`probe-sms-http10.out`，基线提交 / 源闭包 SHA-256 与 node / icu 都在输出
头部）：

```
form-1.0-plain        HTTP/1.1 200 OK   Content-Type / Date / Connection: close   closed=true（无 content-length）
form-1.0-keepalive    HTTP/1.1 200 OK   Content-Type / Date / Connection: close   closed=true
                      （请求带 Connection: keep-alive，Node 仍回 close 且关闭）
404-1.0-keepalive     HTTP/1.1 404 Not Found   Date / Connection: close          closed=true
form-1.1-keepalive    （对照）Connection: keep-alive + Keep-Alive: timeout=5 + Content-Length: 59，
                      同一 socket 第二请求有应答
```

（200 的 body 为 59 字节空 TWIML
`<?xml version="1.0" encoding="UTF-8"?><Response></Response>`。）

金样 cell `channel-sms/oracle.json` 的 `http10` 一格（第 57 格，port
18856）即 `POST /sms/incoming HTTP/1.0` + `Connection: keep-alive`，录制
响应 status 200 / contentType `text/xml` / 空 TWIML 体，由 `generate.mts`
在基线上实跑生成（#1913 实施；生成器 stdout 打印 `#1339 recorded
http10`，落盘 `expectedCaseCount: 57`，重生成守卫通过）。oracle 只记
{status, contentType, body}（+closed/refused），不记状态行与帧化——状态行
与 close 定界由钉死测试单独比对（同 WEBHOOK-004 的处理）。

## Rust 行为

`src/pilotdeck-gateway/src/channel/sms/mod.rs` 的 `handle_request` 记下
请求版本，路由后过 `finalize`（路由拆出 `route_request`，`finalize` 只在
`handle_request` 出口作用一次，404 分支同样过它）：请求是 HTTP/1.0 时把
响应版本置 `hyper::Version::HTTP_10`，hyper 1.7.0 的 `proto/h1/conn.rs`
因此写 `HTTP/1.0` 状态行（`enforce_version` 对 1.0 请求无条件改写，公开
API 无扩展点）。同一分支把响应体包成未知长度（`Unsized`），让 1.0 连接
按 close 定界写体，不补 `content-length`——与 Node 的线上字节一致。

实测（钉死测试 `channel::sms::tests::http10_request_closes_the_connection`，
`raw_until_close` 读原始线到 EOF，5 s `bounded` 界）：

```
HTTP/1.0 200 OK
Content-Type: text/xml
Date: <masked>
Connection: close

<?xml version="1.0" encoding="UTF-8"?><Response></Response>
（closed=true；head 无 content-length / transfer-encoding）
```

即除状态行外，头集合、帧化与体字节都与 Node 录制一致。

## 范围

仅 sms 通道自有监听器的非升级响应（金样 `http10` cell 这一条请求形态：
`POST /sms/incoming`，HTTP/1.0，请求带 `Connection: keep-alive`；404 分支
同过 `finalize`，探针 404-1.0-keepalive 格同形）。其余车道的 1.0 状态行
归属照 `A8.3-CH-WEBHOOK-004`「范围」车道表，其中 sms 行（「无登记、
未实测：见 #1913」）自本条起改为指向本条，其余各行维持原判。不改变归一
化规则，也不豁免 WebSocket 升级分支（本通道无升级分支）。HTTP/1.0 客户端
此前不进 sms 金样矩阵，本 PR 之后 `http10` 一格进入矩阵：重放格比对
oracle 所记全部字段（status / contentType / body，加 closed），状态行与
帧化由钉死测试单独比对（状态行按本条豁免，其余逐字节）。

## 机器判据

`src/pilotdeck-gateway/src/channel/sms/tests.rs`：

- 重放格 `http10`（`replay_cases!`）：录制步是 1.0 keep-alive 请求，
  `raw_request` 只在连接关闭时返回——丢失 `finalize`（socket 挂着等
  keep-alive）在 5 s `bounded` 界上超时转红；
- `http10_request_closes_the_connection`：从 oracle 的 `http10` 案取
  `build_raw` 字节与录制 options（端口换 18904，重放格自有 18856）起真实
  通道，断言状态行为 hyper 的 `HTTP/1.0 200 OK`（本条豁免项）、head 无
  `content-length` / `transfer-encoding`（close 定界）、head 无
  `connection` 头（1.0 语义下 close 为默认，hyper 1.7 的 1.0 分支只关
  keep-alive 不补写；Node 侧有 `Connection: close`，属 `A8.3-CH-SMS-002`
  车道级帧级呈现家族，#2257 fix-r1 实测钉住）、连接关闭、
  body 与 TWIML_OK 逐字节相等；
- `EXPECTED_CASE_COUNT = 57` 两侧（tests.rs / generate.mts）一致，与
  oracle 的 57 案 / `every_oracle_case_has_a_replay_cell` 名集相等；
- ignored `channel_sms_fixture_regenerates_identically` 在固定基线上
  重生成完整金样、与在库 fixture 逐字节相同（本轮实跑 PASS）；
- `negative_controls.py` 的 `sms-oracle-recorded-version` 行（开关表
  72→73，绑 `recorded_version_rejects_wrong_type`，锚「#1913 rejects
  version type drift」）正控 / 变异 / 复原三态实测 KILLED（原始输出
  `_tmp/20261108-sms-residual/negctl-sc/`）；
- 与 webhook 车道的差异：webhook 另有 `webhook-http10-finalize-off` /
  `webhook-http10-framing-off` 两个生产码变异开关，sms 本批未加同类
  开关——`finalize` 与帧化的回归钉靠上述重放格 + 钉死测试的普通断言，
  无变异负控（任务书 #1913 范围如此，读账者须知）；
- 回归：`channel::sms` 全子集 229 tests / 226 passed / 0 failed /
  3 ignored（`_tmp/20261108-sms-residual/sc-sms-subset.out`）。
