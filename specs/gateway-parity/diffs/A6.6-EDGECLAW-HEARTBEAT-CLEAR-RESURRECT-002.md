## 类别

bug 修复（有意偏离 TS 基线）。`A6.6-EDGECLAW-HEARTBEAT-CLEAR-RESURRECT-001` 修复了
classify/createNote await 窗口内的「文件复活」，但复查只做一次且落在 await 之后，且依赖
SQLite 可读。#917 fix-r1（评审修复轮）补齐三个残留面：① `selectIndexProject` await 窗口
与同一轮后续候选（第二轮复查之前）仍会复活；② `clearSession` 后紧跟 `close()` 时 L0 查
询报 `database is not open`，按 -001 的 fail-open 臂被当作「未清除」，已清候选照样写盘；
③ 非 `Closed` 的 L0 读错误也被 fail-open 吞掉。三者都与 `clearSession` 自身语义相悖
（intent ②）并构成隐私偏离（intent ③）。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/memory/edgeclaw/heartbeat/indexer.rs`：

- `:312-319` 每会话在 `list_unindexed_l0_by_session` 之前读 `session_clear_generation`
  作基线；
- `:1138-1152` persist 循环前经 `session_cleared`（`:1688-1707`）复查：代际标记不等于
  基线 → 已清除；否则回查 L0 行是否仍在；`Err(StorageError::Closed)` → 未清除（fail
  open，仅此一臂，保住 close 各格字节行为）；其余错误 → 传播（fail closed，诚实报错而
  不是静默复活）；
- `:1167-1195` 每个候选：`route_general_candidate` 的 select await 在锁外；随后
  `snapshot_operation_scope()`（`storage/snapshots.rs:438`，workspace+global 快照锁，
  `clearSession` 走 `storage/entries.rs:401` 的同一 `snapshot_operation`）拿住后先在锁
  内复查代际标记，再 `BeforePersistCommit`（`:143`，Rust 专属测试缝）→ meta 物化 →
  `upsert_candidate`，段内无 await——复查与写入和 `clearSession` 互斥；
- 标记实现在 `file_memory.rs:407-418,547`：进程内单调计数 per session，仅
  `clear_session_memory_data`（`entries.rs:412-415`，删除任何数据之前 bump）递增，
  `clear(current_project)` / `clear(all)` 不递增（保住
  `matrix-general-select-clearProject` 金格逐字节一致），`close()` 后仍可读。
