## 类别

bounded-work

## 基线依据

SkillManager.scan 对每个含 SKILL.md 的目录调 buildSkillScanFolder，计数循环在 `src/extension/skills/SkillManager.ts:674-692`：`fs.readdir(dir, { recursive: true })` 后逐条 `fs.stat`，`isFile()` 才计数。TS 实现对该循环无总工作量上限。

基线：`OpenBMB/PilotDeck@cc7c4e65`，出处 `src/extension/skills/SkillManager.ts:674-692`。

## Rust 行为

Rust 实现对累计 listed 条目总数设上限 **8,388,608**（产品常量 `TREE_FILES_CAP`，`src/pilotdeck-gateway/src/skills/import.rs`）。每次 `listed.push(path)` 后检查 `listed.len() > cap`，超限返回 `SkillError::manager("tree_files_limit_exceeded", ...)`，经 `scan_folder` 的 `?` 传播，scan 整体失败、不返回部分 folders。遍历本身保持 main 的形状：判目录 stat、读目录、最终计数三处都用拼接出的完整未规范化路径，不 canonicalize、不 openat、不按 `(dev,ino)` 去重或缓存子树（与 TS 逐值一致的来源，见设计 v3 `_tmp/20261023-issue-595-tree-files/v3/design.md` §3.1）。

测试经参数 `tree_files_capped(dir, cap)` 与内部 `scan_capped(input, cap)` 传小值覆盖边界和 scan 整体拒绝，不用全局 override；公开 `scan` 固定传 `TREE_FILES_CAP`。

## 范围

- 上限之内的树与 TS 逐值一致（金样与停止点测试见机器判据，全部入库机检）。
- 超限的有限树与 TS 做不完的输入：TS 侧返回真实计数或不返回，Rust 显式报错——**向安全偏离**。双自指链接（self-2）TS 侧 300 s 墙钟被 SIGKILL（exit 137，RSS 2.52 GB 仍在涨）、带 cap 的 Rust 在上限处报错（cap=8,388,608 时 163.6 s、峰值 RSS 2.34 GB），均为设计阶段同机实测，原始输出在 `_tmp/20261023-issue-595-tree-files/probes/out/`；仓库内不重放该量级输入，上限行为以小 cap 边界测试覆盖。
- 上限取值 8,388,608 是 **Rust 侧产品资源策略**（决策卡 `_tmp/20261023-loop/card-595-limit.md`，AI 代批待人复核），不承诺覆盖「TS 能完成的输入」：同为无环宽树，TS 吞吐相差约 3 倍（alias-3000x1000 约 26,774 条/s 对 #547 留存 wide-100k 约 76,139 条/s，设计 v3 §3.2），单一树形无法外推 TS 能力上界，超限的有限树会整体报错。

## 机器判据

本更正更新原条目的测试观测单位、负控变异、scan/低 fd 回归和设计验收对账；原条目关于旧 NC-3 及原计划完成程度的描述以此处为准。产品 cap 与未批准状态不变。

测试：`cargo test -p pilotdeck-gateway --lib skills::import::tests`（macOS 为 10 个默认测试 + 1 个 `#[ignore]` 再生测试，含一个低 fd 子进程入口；Linux 不编译 macOS 金样回放）。

金样（真实 TS `SkillManager.scan` 的 `folders[0]` 产出，`tests/fixtures/skills-tree-files/`；生成器 `generate.mts` 带 baseline commit 与源码 SHA-256 溯源守卫，每例跑两次并要求序列化一致）：

- `oracle.json` 5 例（可移植，CI 可跑），`tree_files_matches_ts_baseline` 逐值回放：dag-10 1025/3130、linear-20 21/78、hops-20 2/61、deep-300 2/63、alias-10x5 67/223。这些形状最深跟随 22 个链接（hops-20），距 macOS 32 / Linux 40 均有 ≥10 余量；本机经 `/private/tmp` 前缀（少一个符号链接）复测同值。
- `oracle-macos.json` 5 例（`tree_files_matches_ts_baseline_macos`，`#[cfg(target_os = "macos")]`，夹具与回放都在字面 `/tmp` 下）：dag-15 32769/98362（最深 31 链接，差 1 到界）、dag-16 1/58 与 dag-20 1/58（第 16 层 stat ELOOP，只剩根 SKILL.md）、mutual 65/282、self-1 64/2016（ELOOP 截断落在真实文件之间，故对前缀敏感）。ELOOP 截断类不进默认 oracle 是既有尺子（`tests/fixtures/skills/README.md`）。

上限边界与停止点：

- `tree_files_respects_cap_133`：133 条目在 cap=133 成功返回。
- `tree_files_exceeds_cap_132`：134 条目在 cap=132 报 `tree_files_limit_exceeded`。
- `tree_files_wide_dir_stops_listing_at_cap`：5001 条目平铺宽目录在 cap=100，经 `ReadDir::inspect` 上的 cfg(test) 线程局部钩子记录迭代器产出次数，断言恰在第 cap+1=101 项停止消费；单目录先 collect 再逐项检查会被观测为 5001 项。
- `tree_files_accumulates_cap_across_directories`：5 个子目录各 30 文件共 156 条目在 cap=100 报错，断言第 101 条停止——上限跨目录累计，不按目录单独计。
- `scan_propagates_tree_files_limit_without_partial_folders`：小 cap 走 scan 整体流程，分别验证子文件夹超限丢弃前序 folders、根文件夹超限传播；公开入口使用同一实现并传生产 cap。
- `tree_files_deep_tree_with_low_fd_limit`：deep-300 子进程在实际 `RLIMIT_NOFILE=16` 下与真实 TS oracle 逐值比较；父进程 20 s 期限，超时 kill + wait；`tree_files_low_fd_child` 为该子进程入口。
- `tree_files_fixture_regenerates_identically_from_ts`：`#[ignore]`，需 `PDRS_BASELINE`，从真实 TS 再生两个 oracle 文件逐字节一致。

负控（`python3 src/pilotdeck-gateway/tests/fixtures/skills-tree-files/negative.py`，仅在隔离源码副本变异 `import.rs`，每项 baseline 绿 → 变异红 → 恢复绿；共用本树既有 target，不改工作树源码；SIGINT/SIGTERM 与超时均回收子进程和副本；NC-5/NC-7 需 macOS）：

- NC-1 `no-cap`：移除 `listed.len() > cap` 检查 → `tree_files_exceeds_cap_132` 转红。
- NC-2 `boundary`：`>` 改 `>=` → `tree_files_respects_cap_133` 转红。
- NC-3 `collect-first`：还原为每目录先 `collect::<Vec<_>>()`、随后逐项检查，cap 检查位置不动 → ReadDir 消费数断言 5001 ≠ 101 转红。
- NC-4 `per-dir-count`：改为每目录单独计数 → 跨目录累计测试不再报错，转红。
- NC-5 `canonicalize-root`：遍历前先 canonicalize 根（丢 `/tmp` 前缀符号链接，腾出 1 个 ELOOP 预算）→ macOS 金样 dag-16 得 65537 ≠ 1，转红。

- NC-6 `inode-dedup`：已见 `(dev,ino)` 目录不再下降 → 可移植 DAG 金样少计，转红。
- NC-7 `inode-subtree-cache`：按 `(dev,ino)` 缓存完整子树结果 → macOS mutual 金样因路径上下文丢失而转红。
- NC-8 `retain-parent-handles`：深树下降期间保留父目录 `ReadDir` → fd=16 子进程耗尽句柄，目标测试转红。
- NC-9 `swallow-scan-limit`：`scan_folder` 吞超限错误返回 0/0 → scan 整体拒绝断言转红。
