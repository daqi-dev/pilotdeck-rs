## 类别

bug 修复：阻止旧轮异步写入污染新轮。授权表隔离是本包的绑定要求，不宣称 TS 存在跨轮授权缺陷。

## 基线依据

cc7c4e6 `AgentSession.ts:93,234-258` 复用 session mailbox；`SteerMailbox` 只用 turnId 验证。真实 `tests/fixtures/interaction-steer/probe.mts` 的 difference：旧 insert 等待 recorder 时 finish/start 同 ID，旧 enqueue accepted，新轮 drain 得到旧消息。`oracle.json` 记录源码 SHA256 和实际结果。

## Rust 行为

`runtime/project/interaction_steer.rs` 使用 opaque session/run 身份；取消 monitor 与 mutation admission 共用 State 锁，检查与 mailbox 入队之间不允许 close 越过；close 后异步返回再次检查，成功 close/finish 前禁止重新 start，清理失败保持可观察并禁止复用。同 generation 内同 session key 的新绑定会顶替旧身份，但旧 run 的清理屏障按 key 保留；生产装配等全部旧 run 成功 close/finish 后才 start，新 mailbox 不与旧 discard / admitted durable apply 并发写 recorder。dispose 超时、丢弃流或连续替换未启动的绑定均不移除屏障；失败屏障只阻止对应 session key，其他 key 可继续。每轮授权 pending 表独立。旧句柄、未知/不匹配 applied item 返回 HostError；TS 的 ID-only 部分路径返回 reason 或静默 no-op，错误形式也属本差异。旧 generation 在 lease drain 前仍可服务自己的旧轮，不能访问新代。当前轮取消后的 drain 按 mailbox 实际状态返回 messages/closed，不把 abort 收尾转换成 HostError；已过 durable 成功边界的消息在原 run 上继续 grant/ack，不再作为 discarded 退回。这两项与真实 TS `cancel-probe.mts` / `cancel-oracle.json` 一致，不新增差异。cleanup 任务在已关停 runtime 上被丢弃或 panic 时写入可观察错误，禁止复用失败 run，不让 dispose 永久等待 None；宿主 recorder 必须自行保证有界。

## 范围

仅 factory 发布的 steer 生产绑定；不改变底层 `runtime/steer.rs` 的既有 TS 对拍语义。`host/modules/turn.rs` 的 `Handler::persist_and_apply_steer` / `apply_steer_authorization` 同属 ID-only TS 对拍适配器，不得用于生产接线；生产入口仅为 `TurnSteer::persist_and_apply`。重复 close 的清理恰一次，成功 discarded 列表只交付一次，错误可重复观察。

## 机器判据

`runtime/project/interaction_steer/tests.rs` 覆盖真实 TS trace、旧 insert、旧 run/session/generation、取消与持久化交错、失败不 ack/授权、清理失败和空 paths 不继承旧 grants；`factory_tests.rs` 覆盖两种 builder 顺序、rollback 和 registry lease drain。新增确定性 check→serialize 钩子迫使取消 monitor 竞争 State 锁；去掉该锁的负控必在 `closed != blocked` 断言失败。另测已关停 runtime、未首 poll 任务丢弃、真实 mutex poison 与 hooks 嵌套 cleanup panic。复算命令见 fixture README。
