## 类别

有意未收口（TS 同形）。seen 集合是**通道 epoch 内**的去重：`start()` 每次
都清空 seen 集合，所以 restart（新 epoch）后同 guid 行会在通道层再次派发。
「同 guid 不重执行」的会话级保证由上游 A7 接纳器（#1738 的活跃 chat 守卫与
其后续幂等）负责，通道层如实转发，与 TS 形状相同。

## 基线依据

固定基线 cc7c4e653b15c8b2cec7bcf2d15d41d69396ae85，Node v22.22.0 /
ICU 78.2。`src/adapters/channel/bluebubbles/BlueBubblesChannel.ts:70`：
`start()` 无条件 `this.seenGuids.clear()`；`:118-119`：
`if (guid && this.seenGuids.has(guid)) continue; if (guid)
this.seenGuids.add(guid);`——仅同一 `start()` 周期内的重复 guid 被去重，
`start()` 清空后旧 guid 立即重新可派发。

## Rust 行为

`src/pilotdeck-gateway/src/channel/bluebubbles/mod.rs:260-267`：`start()`
每次自建新 epoch（新 watch abort），`state.seen_guids.clear()` 并重播种
`last_timestamp`、置 `running = true`；`mod.rs:404-410`：
`!guid.is_empty() && !state.seen_guids.insert(...)` 是同一 epoch 内的
去重闸（负控 `seen-dedupe-removed` 钉死）。金样的 `restart-clears-guids`
用例（新实例 + 新 start）记录同 guid 行两次派发，与 TS 实测同形。

## 范围

仅「跨 start/restart 的 guid 去重」：TS 与 Rust 都不做，上游 A7 负责幂等
（通道层重派发后是否重执行由接纳器/回合侧决定，不在本车道）。
不覆盖单 epoch 内去重（已对齐：金样 `duplicate-guid-never-re-executes`
+ 负控 `seen-dedupe-removed`）。若上游落地跨 epoch 去重，本条目改为
已对齐并补「restart 后同 guid 不二次派发」用例。本条不构成判分豁免。

## 机器判据

- 金样用例 `restart-clears-guids` / `duplicate-guid-never-re-executes`
  （`tests/fixtures/channel-bluebubbles/oracle.json`）逐格比对 TS：前者
  记录两次派发、后者记录一次。
- 负控 `tests/fixtures/channel-bluebubbles/negative_controls.py` 的
  `seen-dedupe-removed`：摘掉 seen 闸门 → duplicate-guid 用例必须转红。
- 跨 epoch 去重为零实现、无判据（上游属 A7）；补齐时须新增用例并改本
  条目。
