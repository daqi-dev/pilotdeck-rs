## 重登记理由与范围

**缺陷**：C（`scripts/native-witness/collect.py`）与 N（`scripts/gateway-parity/native_evidence.py`）都把**所有** WS 信封（含 `final:true`）折进 `observation['frames']`。于是每个流都多出一个人造终态帧、空流多出一个 fallback 帧，72 个 native case 与已登记的 in-process 期望系统性不符。这不是 Rust 与 TS 的差异，是**观测投影**的差异。

**改法**：两侧保留原始信封，把「什么是一条 in-process yield」收进唯一的纯函数 `project_envelopes(request_id, envelopes)`：

- `final:false` 的 `event` 才是一条 yield，进 `frames`，逐条保留（**不按内容去重**）；
- 恰好一条末尾 `final:true` 承载派生终态，**不进** `frames`；
- 终态必须等于 `lastError ?? lastCompleted ?? WS_TERMINAL_FALLBACK`，不等即 `need` 失败（不静默通过）；比较用 `same_json` **按 JSON 类型**判定，`true` 不与 `1` 相等（见下「评审 P0」）；
- 信封身份（`type == 'event'`、`id == requestId`）与序号（`seq == 下标`）由同一函数校验，C 与 N 不再各写一份规则。

依据：TS `resources/PilotDeck/.../GatewayWsConnection.ts:157-169`、Rust `src/pilotdeck-gateway/src/runtime/connection/mod.rs:386-408`。

## 判分语义未改

阈值（k、m）、分母、场景集（72 case）、已登记的 in-process 期望值、归一化与聚合方式全部未动。本单只改「信封 → in-process 帧」这一步投影，让两侧对同一个流说同一句话。`specs/gateway-parity/accepted-diffs.md`、`diffs/` 均未改动（本单不产生新的 TS-vs-Rust 差异；残留真实差异归 #1367）。

## 评审 P0 与修法（Codex 实测）

Codex 用合成审计实测发现：终态派生校验原先写作 `terminal == expected`，而 Python 里 `True == 1`，于是把终态里的 JSON `true` 改成 `1` 后伪造终态仍被接受（合成审计仍报 72/72）。修法为新增 `same_json`：布尔只与布尔相等、数字按值比较、字典键集合与列表长度逐层比较（自带栈迭代，不递归）。补两处钉子：`test_safety.py` 的 `test_terminal_types_are_not_coerced`（fallback 顶层 `recoverable=1` 拒、嵌套 `retryable=1` 拒、`inputTokens:'3'` 拒、`inputTokens: 3.0` 收）与数据级负控 `native-terminal-type-drift`（改前该负控 PASS 假绿）。该负控挑「终态事件里真含 JSON 布尔」的那个请求施加漂移，否则以 `CONTROL_PRECONDITION` 明确失败而不是空转。

## 评审 r2 追加（GLM 静态）：同类未同步

GLM r2 指出同一函数族里 `need(observation == original, ...)`（观测与留存原件的全量一致性）仍是裸 `==`，与已修的终态问题同类。已改为 `same_json`。**实测边界**：记录侧唯一的 JSON 布尔是 `registry.applicable`，把它漂成 `0` 会先被 `OBSERVATION_STRUCTURE` 结构守卫拦下（实测 `rule=OBSERVATION_STRUCTURE`），因此这里没有可构造的数据级负控，`same_json` 属纵深防御；同一类的实证钉子仍是终态侧 `native-terminal-type-drift` 与 `WsProjection.test_terminal_types_are_not_coerced`。同理，`native-terminal-type-drift` 只能钉住 fallback 分支（合成采集的登记期望帧里没有任何 JSON 布尔，而那是本单不得改动的判分输入），`lastError ?? lastCompleted` 分支由上述单测钉住。

**未纳入本单（同类但属既有面，登记为缺口转跟进）**：`native_evidence.py` 的 `execWitness`/`networkWitness`/`transcriptWitness` 回放一致性比较、`scripts/gateway-parity/compare.py` 的 `metadata != row['wire']` 等同型比较仍用裸 `==`/`!=`。

## 被暴露的假 PASS 洞（属于本单范围）

`src/pilotdeck-gateway/tests/fixtures/native-session-e2e/mock_gateway.py` 原先在帧序列之后发一条 `{'type':'turn_started','event':'completed'}` 当终态，注释还写着「像真网关的 finish 帧」；真实 TS/Rust 从不发这种帧。它与旧投影**共犯同一个错**，所以端到端测试一直是绿的。修正后实测：**新投影 + 旧夹具**必红（`#1140 terminal envelope must repeat lastError ?? lastCompleted`），**新投影 + 新夹具** 32/32 绿。即修正不是放宽标准，而是把一个假 PASS 洞焊死。
