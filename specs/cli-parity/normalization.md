# CLI D0-pr1 比较口径（未冻结）

本文件先于实现登记。仅用于首批离线定标，不批准任何 Rust 行为差异。

1. **stdout / stderr 不归一化**：保存原始 bytes，包括换行、ANSI、空白、错误文本；每路内部顺序精确比较。另存双 pipe 的采集事件，合并相邻同流 read 后比较流名与 bytes；不比较 read 分块大小、采集时钟。这个事件序列是观察到的跨流顺序，不能证明内核 write 的全序；首批期望至多一路非空。未来混合输出须扩展记录装置，不能用本轮覆盖声明替代。
2. **退出码精确比较**：信号产生的负值保留，超时/截断/采集或清理失败属于装置错误，不能因两侧相同而 PASS。
3. **完整落盘**：对唯一可写 runtime 的初始及最终树逐项记录相对路径、类型、mode，普通文件的长度和 SHA-256、软链接的目标。含空目录、隐藏文件；不跟随软链接。初始树必须与场景 fixture 一致，最终树重新从原件读取，拒绝与缓存 manifest 不符。增加/删除/内容/类型/权限/链接变化都比较；不只比较预期文件。mtime/ctime/atime、inode、uid/gid 不属于本轮内容契约，不参与比较。特殊节点、越界链接、硬链接一律拒绝。
4. **路径不替换**：两次 TS 与可选 Rust 均顺序复用同一个 runtime 绝对路径，结束后移至各自证据目录，每次恢复初始树。不同 runtime 路径的证据不能互比。没有 UUID、时间、警告、错误、版本文本的替换或过滤。
5. **观测元数据**：PID、wall clock、耗时、源 HEAD/二进制哈希用于 provenance 与完整性检查，不当产品相等字段；每一侧仍须有清理成功、OS 隔离预检通过、有效进程树记录。运行命令、环境、stdin、场景集合、fixture、装置/spec 哈希必须绑定一致。

6. **TS 侧运行时警告**（2026-10-17 真实定标后补登，AI 代批，待人复核）：首轮真实 TS 运行发现每个场景 stderr 都以 Node 22 自带的 `(node:<PID>) ExperimentalWarning: SQLite is an experimental feature…` 两行开头，PID 每次不同。它来自 Node 运行时、不是 PilotDeck 产品输出，Rust 实现也不应复刻。处理方式是**不产生而非过滤**：TS 侧以 `node --disable-warning=ExperimentalWarning` 启动，只关闭 ExperimentalWarning 这一类运行时警告；产品自身经 `process.emitWarning` 发出的其它类型警告与全部 stdout/stderr 字节照旧原样比较，第 4 条「不替换、不过滤」对产品输出不变。

TS 自比必须先过场景独立预期及证据完整性检查，再比较两次原件。任一缺失场景、额外场景、缺失原件、模式不符或未运行都不能 PASS。运行器不提供放宽/忽略参数。
