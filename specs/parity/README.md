> **这是阶段 C 的尺子规约。** 2026-10-14 起草（一、二、四节来自人已拍的板；**三节的 S 集合规则是 AI 起草**），**待人过目后冻结**，sha256 记在 `FROZEN.md`。

## 一、比什么

Rust sidecar 对 **TS sidecar**（不对 native），走基线 `resources/PilotDeck` @ `cc7c4e6` 的上游装置 `tools/agent-loop-parity/`（`--surface gateway`），用 **G03 v1 通道拆分比较器**（`scripts/parity/g03_compare.py`，回捞自旧执行，见 `docs/research/003_prior-attempt/`）判。比三样：语义事件流、落盘、发给模型的请求体。

## 二、尺子本身必须先过的四项对照（缺一项，尺子不可用）

1. **TS sidecar 自比**：同一基线连跑 k 遍，统计每个场景被判一致的遍数。
2. **逐条规则的负向对照**：比较器每放宽一处，各配一对注入了对应差异的 trace，断言是**那条规则**判它不一致。
3. **两侧同坏**：两边都空、两边都报同样的错，必须判不一致。
4. **独立审查**：两条不同谱系的模型各审一遍，收敛到无 P0/P1/P2。

## 三、阈值怎么定（程序冻结，数字待定）

- **k = 5**，事先定死，不中途加跑。**不许重跑挽救**：一轮里出现 BLOCKED（环境失败）就整轮作废重来，**不算「原版不稳定」**。
- 术语：「TS 自比」= TS sidecar 第 i 遍对第 j 遍（**不是** native 对 sidecar）。
- **m 只能由 TS sidecar 自比的数据定**，规则：取 TS 自比里「k 遍全一致」的场景集合 S；对 S 里的场景，Rust 要 k 遍全一致才算 PASS；对 S 以外（原版自己就不稳定）的场景，进 `accepted-diffs.md` 登记成「原版不稳定」，**不计入分子也不计入分母**，单列报告。⚠️ 这会让 `.42cog/intent.md` 的分母从 53 变成 53 − |原版不稳定|，**待人拍板**。
- **S 有下限**：|S| < 45 就停下交人，不往下走——防止负载或环境把分母合法地做小（评审 A+B）。S 以外的每个场景，**逐个**由人批准排除。
- ⛔ **定 k、m 时不许看任何 Rust 的运行结果。** Issue #1 不跑 Rust。
