## 类别

bug（per-session 目录回收时机），登记为已接受差异（人批记录见「批准记录」）。基线的 `close()`
当下即删 per-session 临时目录；端口等迟到握手落地 / 握手超时之后的 detached cleanup 才删，
极端情况下（运行时在清理跑完前被拆除）残留。修复（`close()` 即删）属产品判断，#1751 人拍选项 A
暂不执行，留作后续可选优化单。

本条与 `specs/gateway-parity/diffs/A6.5-MCP-SESSION-DIR-LIFETIME-001`（及其更正 `-R1`）为
**同 ID 跨套登记**：同一差异在 gateway-parity 账本与本（阶段 C parity）账本各一条，事实同源
（同一组探针与实测），本条按本套口径书写。

## 基线依据

固定基线 `resources/PilotDeck`（cc7c4e65，Node v22.22.0，`@modelcontextprotocol/sdk` 1.29.0）。
`src/mcp/client/McpClient.ts:361-377` 的 `close()`：`await this.client?.close()` 后置
`status = "idle"`，随后同步 `rmSync(this.perSessionDir, { recursive: true, force: true })`——
删除是 `close()` 的同步步骤，返回前必然完成。

实测（真 TS 探针 `_tmp/20261106-issue-401/probe/probe-dispose-inflight.mts`：`slow-mcp-server.mjs`
把 `initialize` 延迟 3 s，握手在飞时调 `close()`，`PILOTDECK_SESSION_TMPDIR` 指到临时目录；原始输出
`_tmp/20261106-issue-401/probe/probe-dispose-inflight.out`，原样重跑
`_tmp/20261106-1751-1754-diff/ts-probe-dispose-inflight.out`，Node v22.22.0）：

```text
close() returned in ms = 1
dir exists after close = false
child alive after close= true
PROBE RESULT = {"closeMs":1,"closeWaitedForHandshake":false,"dirRemovedAtClose":true,"childAliveAtClose":true}
```

即 TS 在 `close()` 当下就删目录（`dirRemovedAtClose:true` 一行）。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/mcp/client.rs`（行号按 2026-11-07 origin/main 现核）：`close()`
（`:1245`）置 `epoch += 1`、清 `list_tools_cache`、`retire_connection()` 后，只对**当时已登记**且
`wait_on_close` 的清理 `await_cleanup`（`:1267`）；`spawn_cleanup`（`:603`）才把「关连接 + 删目录」
登记进 `State.cleanups`。在飞握手的目录此时尚未登记（`PerSessionDirectory` 还在 `run_connect`
局部，构造于 `:903`）：等握手落定、走到 `:957` 的 `state.epoch != epoch` 分支才
`state.spawn_cleanup(… dir.remove() …)`；握手超时路径（`:912-930`）同理把目录交给 detached cleanup
（`DEFAULT_HANDSHAKE_TIMEOUT_MS = 10_000`，`:94`）。

实测（探针 `probe_1751_close_during_inflight_handshake_keeps_session_dir`，源码
`_tmp/20261106-1751-1754-diff/rust-probe.patch`，命令
`cargo test --offline -p pilotdeck-gateway --test mcp_client probe_1751 -- --nocapture --test-threads=1`，
原始输出 `_tmp/20261106-1751-1754-diff/rust-probe.log`）：`close()` 0 ms 返回时
`dir_exists_after_close = true`、500 ms 后仍 true；放行被闸住的 `initialize` 后迟到握手被判
`aborted`，目录才由 detached cleanup 删除（`dir_exists_after_gate_opened = false`）。

「目录最终会被删」在正常收尾（运行时存活到 detached cleanup 跑完）时成立；运行时在清理跑完前
被拆除则清理任务被 drop，目录残留在 `$TMPDIR`（未实测，见「机器判据」缺口 ③）。

## 范围

仅 stdio 传输 per-session 临时目录（`--user-data-dir=` 临时目录）在 `close()` 期间的寿命，可观察差异
一处：`close()` 返回那一刻目录是否存在（基线 false、端口 true）。**status 走向不在本条**：
`close()` 之后基线被迟到握手抬回 `ready`、端口保持 `idle` / `aborted`，已由本账本第 4 条
`handshakeClose`（郑达奇 2026-10-21 已批）登记，本条不重复主张。不含：目录内容与命名规则、
`reconnect` 路径旧目录回收、子进程回收时机（含「删目录与关子进程先后」的取舍）、握手中断后的
重连语义。

## 机器判据

- TS 金样：`_tmp/20261106-issue-401/probe/probe-dispose-inflight.mts` 与 `.out`（Node v22.22.0，
  关键行 `dirRemovedAtClose:true`）；原样重跑 `_tmp/20261106-1751-1754-diff/ts-probe-dispose-inflight.out`。
- Rust 复算：`_tmp/20261106-1751-1754-diff/rust-probe.log`（原件只读；复算另存新文件名，
  `rust-probe.patch` 只 apply 到一次性树；该日志 1751/1754 两探针输出混排，按
  `dir_exists_*` / `session_dir` 与 `depth=` 内容区分，不按行序切）。
- origin/main 耐用用例：`tests/mcp_client.rs::timed_out_handshake_keeps_its_directory_until_late_close_then_removes_it`
  （`:899`，正常已连接收尾时目录已删）、`registry_dispose_joins_retired_directory_after_cancelled_close`
  （`:1087`）、`dispose_during_an_in_flight_handshake_removes_the_session_directory`（`:1774`，PR #1782
  合入：`McpRuntime::stop()` 不栅栏在飞握手 + 迟到握手落定后 detached cleanup 最终删目录）。
  缺口：① 在飞握手时 `close()` 返回目录仍在的正控、③ 运行时先拆 → 目录残留（未实测），均仍缺，
  须另开跟进单（前置于 A6.5 批次复核）；对 `dispose()` 返回时的目录状态不立断言（返回状态是
  交错不定值，分析见 gateway-parity 同 ID 条目「类别」末段）。
- 本条不改 `score.py` 的场景集合、分母与 `approved_unstable()`（按本目录 README 的阶段 C 分母
  边界，新条目即使记有人批也不自动参与）。
