## 类别

bug 修复（原版缺陷的 Rust 宿主侧修复）。本条不改判分语义、阈值、分母与场景集合，只登记 #6 所述差异在 A7 Rust 宿主上的处置结果。

## 基线依据

`resources/PilotDeck` @ `cc7c4e6`：`src/gateway/client/InProcessGateway.ts:1385-1436`（先发超时取消再等持久化）、`:1727-1750`（catch 只看 fence current，未排除 `timedOut`）、`:1824-1848`（timeout 路径不等 pump 即完成 fence）。
#6 的实测原件 `_tmp/20261025-issue-19/delivery/`（`repro-counts.json`、`diag-hold` / `diag-after`、`natural-failure-wire-analysis.json`）：受控交错下两侧都多写 1 条 `gateway_submit_failed`，fence 完成后两侧都是 0；真实流程 TS 0/10、Rust 1/10。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/turn/submit.rs`：新增 `TerminalClaim`（`AtomicBool` 的 first-writer-wins 认领），deadline 分支与 pump 失败路径共享一次认领；只有胜者写 durable 终态、发终态事件，deadline 分支无论是否胜出都在 settlement 之后关闭 live 投递。`pump` 侧顺序显式为「pump 退出 → 检查 `timed_out` → 检查 completion fence → 取 claim → 写 durable」。`trip_failure_guard` 的 `run_policy_stopped` 终态同样过 claim。改后：timeout 接管之后不再额外登记 `gateway_submit_failed`。

## 范围

仅 Rust 宿主侧的终态写者归属（`turn_timeout` / `gateway_submit_failed` / `run_policy_stopped`）。场景 `deadline`、`deadline_during_tool` 的判分口径、分母、阈值、比较器均不变；TS 基线侧原版缺陷（`InProcessGateway.ts:1727` 的 catch 未排除 `timedOut`）不修，属既定差异。

## 机器判据

`src/pilotdeck-gateway/src/runtime/turn/submit_tests.rs` 的 `timeout_takeover_writes_exactly_one_terminal`，两格确定性交错：`timeout-durable-blocked-behind-catch`（`failureGate` 卡住 timeout 的 durable 写）、`catch-after-fence-complete`（`pumpErrorGate` 卡住 pump error 到 fence 完成之后），两格都断言 durable 终态**恰好一行**、wire 上无外来终态码。
负控：只把 `submit.rs` 回退到 `origin/main`（测试保留），同一命令必须红；实测 `writers [2]`、durable `["gateway_submit_failed", "turn_timeout"]`、rc=101，原件 `_tmp/20261106-issue-727/red-1.log` 与可复现脚本 `_tmp/20261106-issue-727/negctl.sh`。
复算：`python3 -I scripts/parity/check_frozen.py --base origin/main`。
