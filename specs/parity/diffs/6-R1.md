## 类别

bug 修复（原版缺陷的 Rust 宿主侧修复）。本条不改判分语义、阈值、分母与场景集合，只登记 #6 所述差异在 A7 Rust 宿主上的处置结果。

## 基线依据

`resources/PilotDeck` @ `cc7c4e6`：`src/gateway/client/InProcessGateway.ts:1385-1436`（先发超时取消再等持久化）、`:1727-1750`（catch 只看 fence current，未排除 `timedOut`）、`:1824-1848`（timeout 路径不等 pump 即完成 fence）。
#6 的实测原件 `_tmp/20261025-issue-19/delivery/`（`repro-counts.json`、`diag-hold` / `diag-after`、`natural-failure-wire-analysis.json`）：受控交错下两侧都多写 1 条 `gateway_submit_failed`，fence 完成后两侧都是 0；真实流程 TS 0/10、Rust 1/10。

## Rust 行为

`src/pilotdeck-gateway/src/runtime/turn/submit.rs`：新增 `TerminalClaim`（`AtomicBool` 的 first-writer-wins 认领），deadline 分支与 pump 失败路径共享一次认领；只有胜者写 durable 终态并发终态事件。`pump` 侧顺序显式为「pump 退出 → 检查 `timed_out` → 检查 completion fence → 取 claim → 写 durable」。`trip_failure_guard` 的 `run_policy_stopped` 终态同样过 claim。改后：timeout 接管之后不再额外登记 `gateway_submit_failed`。

live 投递的关闭按胜者分叉：deadline 胜出时，settlement 之后立即 `close_live()`（幂等、不等 worker）；deadline 输给 pump 时不抢关——pump 已入队的终态帧若在此刻关闭会被 `PublicationWrite::finish` 丢弃，故由 pump 的 worker 在 `finish()` 之后关闭，另挂一个脱离的兜底任务：worker 报告冲刷完成即退出，超时**或** worker 先死（发送端被丢弃也算未冲刷）则 `close_live()` 硬关，保证 host future 挂死时 turn / admission / fence 不被永久占用。兜底预算取 `abort_turn_timeout_ms` 且下限 1 s，避免 1 ms 的 drain 预算把胜者的末帧切掉。

## 范围

仅 Rust 宿主侧的终态写者归属（`turn_timeout` / `gateway_submit_failed` / `run_policy_stopped`）。场景 `deadline`、`deadline_during_tool` 的判分口径、分母、阈值、比较器均不变；TS 基线侧原版缺陷（`InProcessGateway.ts:1727` 的 catch 未排除 `timedOut`）不修，属既定差异。

认领带来的第二种形状：同一 tick 内 pump 先认领时，Rust 不再写 `turn_timeout` durable 行、也不再发超时终态帧，该 turn 以 pump 的 `gateway_submit_failed` 为唯一终态；TS 基线无认领，timeout 路径照常发超时事件。该形状在 #19 原件（`diag-hold` / `diag-after`、`natural-failure-wire-analysis.json`）中未出现——那里 timeout 都先认领，两侧都以 `turn_timeout` 收尾——故不影响这两个场景的既有判分；将来若在真实场景出现，按新差异条目另行登记，不在本条预设豁免。
