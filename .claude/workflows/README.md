# .claude/workflows — 动态编排

> 能力弹性化的第三处落点。**能力编排**——把一个或多个 Skill 与 CLI 组合起来，发挥更大的专业能力。
> 前两种（主从 Skill / 管道式调用）路线是你事先写好的；**动态编排不一样——路线是当场写出来的。**

分工要看清：**脚本管分几段、每段派几条、什么时候收；模型管每一条具体怎么干。**

⚠️ 这里的文件名与语法是**具体工具的约定**，不是通用规范。换一个框架，位置就变。
要记的是这套分工，不是这几个名字。

## 现成的

| 文件 | 干什么 |
|---|---|
| `pdrs-review.js` | **多视角自检**——几个互相对抗的视角同时审，按 P0–P3 收成修复清单 |

## 多视角自检：为什么有效

**它真正管用的不是「自检」，是「多视角」。**

自检不是再读一遍——再读一遍，AI 只会再一次确认自己是对的。
有效的自检，是把它**分裂成几个互不相同、互相对抗的视角同时审**。
**视角越分化，越能逼出单一视角视而不见的问题。**

挑视角的判据只有一条：**彼此越不像越好**。三个都懂行的人审出来的东西高度重合，等于只审了一遍。

## 分级修复：给无限评审一个出口

多视角一开，它能一轮轮挑下去——什么时候算完？

按风险与紧迫程度定级，**P0 最高，P3 最低**。收工判据：

> **P0 / P1 / P2 修复为零，P3 酌情处理。**

到这条线就停，不再开下一轮。修复原则一旦定好，「无限评审」的循环就有了出口。

## 自己加编排时

一份最小的编排脚本二十来行就够。先想清楚三件事：**分几段 · 每段派几条 · 什么时候收**。
写完先拿一件小事跑一遍——**别第一次就派十条**。
